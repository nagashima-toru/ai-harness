# T-04 vault-spec の archive の説明を配置とスクリプトに合わせる

## 目的
仕様の正本 `docs/vault-spec.md` の archive の説明（1節の表の行と、7節の model_stats の集計対象）を、種別ごとのサブディレクトリの配置と `scripts/archive_plans.sh` に合わせ、移した後はフックの done 判定の対象外になることを明記する。

## 入力
- `docs/vault-spec.md` 1節の表（15行目 `vault/archive/` の行）、7節の model_stats の段落（140行目付近）、12節の done 判定の行
- `scripts/archive_plans.sh`（T-01 の成果物）と T-01 タスク票の「決定済み」
- 計画票 `vault/plans/P-20261003-archive-old-logs.md` の「分割方針」

## 成果物
- `docs/vault-spec.md`（1節の表の1行と7節の1段落を書き換える。1ファイル）

## 受け入れ基準
- 1節の旧い説明が残っていない：`grep -c 'done になった計画一式を月次でまとめる先' docs/vault-spec.md` の出力が `0`
- 1節に配置を書いている：`grep -c 'vault/archive/<年-月>/{plans,tasks,verdicts,log}/' docs/vault-spec.md` の出力が `1` 以上
- スクリプトを名指ししている：`grep -c 'scripts/archive_plans.sh' docs/vault-spec.md` の出力が `1` 以上
- 7節に archive の log を明示して集計する例がある：`grep -c 'model_stats.py vault/archive/\*/log/\*.md' docs/vault-spec.md` の出力が `1` 以上
- 移した後は done 判定の対象外であることを書いている：`grep -c 'agent_write_guard.py の done 判定の対象外' docs/vault-spec.md` の出力が `1` 以上
- 見出しの数が変わらない：`grep -c '^## ' docs/vault-spec.md` の出力が `13`

## 決定済み
- 1節の表の `vault/archive/` の行を、パス列 `` `vault/archive/<年-月>/{plans,tasks,verdicts,log}/` ``、内容列「done かつ PR がマージ済みの計画一式の移動先。`vault/` と同じ種別ごとのサブディレクトリに置き、`<年-月>` は計画 ID の日付部分から決める。移動は人が `scripts/archive_plans.sh --apply` で行う（手順は `docs/runbook.md` 5節）。移した後のファイルは agent_write_guard.py の done 判定の対象外」に置き換える。表の列数（2列）は変えない
- 7節の model_stats の段落の「`vault/archive/` 配下の log は既定の対象に含めず、引数で明示的に渡した時だけ集計する。」の後ろに、例として `python3 scripts/model_stats.py vault/archive/*/log/*.md` を足す（log のファイル名が `<計画ID>.md` のまま残るので計画 ID が取れる旨も一言）
- 12節（agent_write_guard の判定表）は変えない。対象外であることは1節の行で述べるだけにする
- 他の節は変えない。`docs/runbook.md` は T-03 の成果物なので触らない
- 「agent_write_guard.py の done 判定の対象外」は、この文字列のまま（バッククォートで囲まずに）書く
