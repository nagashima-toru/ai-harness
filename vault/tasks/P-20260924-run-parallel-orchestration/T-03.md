# T-03 マージ・状態遷移（done/blocked）・attempt 更新の逐次処理と回帰確認

## 目的
`run` スキルに、全 verifier 完了後の逐次後処理（PASS 時のマージ・`review→done`・ログ追記・worktree 削除、コンフリクト時の `blocked` 化、FAIL 時の attempt 更新）を追加し、着手可能集合が1件の場合でもフェーズ2までの逐次フローと同じ結果になることを確認する手順を明記する。

## 入力
- `vault/designs/D-003.md`（フェーズ3節。決定済み：「マージは常にオーケストレーターが計画ブランチ上で逐次実行」「コンフリクト時は自己判断で解決せず blocked」）
- `.claude/skills/run/SKILL.md`（T-02 完了後の版。手順6「verdict に従う」・手順7「次へ・完了」）
- `vault/rules/common/git.md`（コンフリクト時に自己判断で解決しない方針）
- `vault/plans/P-20260924-creator-subagent.md` と配下タスク票（フェーズ2までの逐次フローの実例。回帰確認の比較対象）

## 成果物
- `.claude/skills/run/SKILL.md` の手順6「verdict に従う」・手順7「次へ・完了」の書き換え、および回帰確認手順の追記

## 受け入れ基準
- 全 verifier 完了後、タスクを1件ずつ逐次処理する旨が明記されている。確認: `grep -n "逐次" .claude/skills/run/SKILL.md`
- PASS 時に該当 worktree のブランチを `git merge --no-ff` で計画ブランチへ取り込み、成功したら `review→done` にしてログ追記し worktree を削除する手順が明記されている。確認: `grep -n -- "--no-ff" .claude/skills/run/SKILL.md`
- マージでコンフリクトが起きた場合にタスクを `blocked` にし question にコンフリクトの状況を書き、worktree を削除せず残す手順が明記されている。確認: `grep -n "コンフリクト" .claude/skills/run/SKILL.md`
- FAIL の場合は計画ブランチへマージせず、attempt が上限未満なら `doing`（attempt+1）、上限到達なら `blocked` にし、いずれもログに追記する手順が明記されている
- 着手可能集合が1件だけの場合に、計画票・ログ・成果物の最終状態が `P-20260924-creator-subagent` で実施したフェーズ2までの逐次フローと同じ結果になることを確認する手順が明記されている
- `HARNESS_MAX_ATTEMPTS` による attempt 上限判定のロジック自体（既定値・比較条件）が変更されていない。確認: `grep -n "HARNESS_MAX_ATTEMPTS" .claude/skills/run/SKILL.md` の既存記述（既定 3）がそのまま残っていることを確認する

## 決定済み
- worktree を次 attempt で再利用するか、破棄して作り直すかは実装時に決めてよい。選んだ方針を SKILL.md に明記すること
- 複数タスクが PASS した場合のマージ順序は、計画票のタスク表の並び順（上から）で1件ずつ処理する
- FAIL で attempt 上限に達し `blocked` になったタスクの worktree は削除しなくてよい（人が blocked を解消する調査に使える可能性があるため、コンフリクト時の温存方針と揃える）
- コンフリクト解消は自己判断で行わない（`vault/rules/common/git.md` の既存方針を踏襲）。他の並行タスクの処理は止めない
- 回帰確認は「手順を文書として書く」ことが成果物であり、このタスクの中で実際に1タスクの計画を用意して `/run` を通しで実行することまでは必須にしない（実施できるならしてよいが、必須の確認コマンドにはしない）
