# T-01 model_stats.py の集計キーを最後の creator= 付き行（doing→review/doing→blocked）にする

## 目的
creator が `doing→blocked creator=<モデル>` で終わったタスクが、`unknown` ではなくそのモデルに集計されるようにする（issue #97）。集計キーの決め方以外の定義は変えない。

## 入力
- `scripts/model_stats.py`（19行目 `CREATOR_RE`、28〜48行目 `collect()`、51〜68行目 `main()` の集計）
- `docs/vault-spec.md` 7節の集計の定義（139〜148行目あたり）
- `gh issue view 97`

## 成果物
- `scripts/model_stats.py`

## 受け入れ基準
- 構文が正しい。確認：`python3 -m py_compile scripts/model_stats.py` の終了コードが0
- `doing→blocked creator=` で終わるタスクがそのモデルに集計される。確認：先に次の1コマンドでフィクスチャを書き出す。`printf '%s\n' '- 2026-10-03 10:00 T-01 todo→doing attempt=1' '- 2026-10-03 10:05 T-01 doing→blocked attempt=1 creator=haiku 質問' '- 2026-10-03 11:00 T-02 doing→review attempt=1 creator=sonnet' '- 2026-10-03 11:05 T-02 review→doing attempt=2 verifier=sonnet 理由' '- 2026-10-03 11:10 T-02 doing→blocked attempt=2 creator=haiku 質問' '- 2026-10-03 12:00 T-03 doing→review attempt=1 creator=sonnet' '- 2026-10-03 12:05 T-03 review→done attempt=1 verifier=sonnet' '- 2026-10-03 13:00 T-04 doing→review attempt=1' '- 2026-10-03 13:05 T-04 review→done attempt=1' '- 2026-10-03 14:00 T-05 doing→review attempt=1 creator=sonnet' '- 2026-10-03 14:05 T-05 review→doing attempt=2 verifier=sonnet 理由' '- 2026-10-03 14:10 T-05 doing→blocked attempt=2 旧形式' > /tmp/P-20261003-model-stats-blocked-creator-T-01.md`。その後 `python3 scripts/model_stats.py /tmp/P-20261003-model-stats-blocked-creator-T-01.md` の標準出力が、タブ区切りでちょうど次の4行になる：`model	tasks	first_pass_rate	avg_attempt	blocked_rate`／`haiku	2	0.00	1.50	1.00`／`sonnet	2	0.50	1.50	0.50`／`unknown	1	1.00	1.00	0.00`（変更前のコードでは `sonnet	3	0.33	1.67	0.67`／`unknown	2	0.50	1.00	0.50` になる）
- 現在の log に対して壊れない。確認：`python3 scripts/model_stats.py` の終了コードが0で、1行目が `model	tasks	first_pass_rate	avg_attempt	blocked_rate`
- 既存の smoke が通る（既存のフィクスチャは `doing→blocked` で終わらないので期待値は変わらない）。確認：`bash scripts/smoke.sh > /tmp/P-20261003-model-stats-blocked-creator-T-01-smoke.txt 2>&1` の後、`tail -1 /tmp/P-20261003-model-stats-blocked-creator-T-01-smoke.txt` が `smoke: pass=<数> fail=0`
- 集計キー以外の定義は変わっていない。確認：`git diff main -- scripts/model_stats.py` を Read と目視で確認し、変わった行が `collect()` の集計キーを決める部分（`if src == "doing" and dst == "review":` の条件と `t["creator"]` の代入）と、docstring・コメントだけである。`main()` の対象タスク・1回目 PASS・blocked・attempt の判定、`HEADER`、出力形式の行は変わっていない

## 決定済み
- 集計キーに使う行は、遷移が `doing→review` か `doing→blocked` の行だけ。そのうち `creator=` が付いた最後の行の値を集計キーにする
- `creator=` が付いていない `doing→review`／`doing→blocked` 行（既存の古い形式）は読み飛ばす。それより前の `creator=` 付き行の値を残し、`None` で上書きしない。`creator=` 付きの行が1つも無いタスクは今まで通り `unknown`
- `review→done`・`review→doing` などの他の遷移の行に `creator=` があっても集計キーには使わない
- 実装の形の目安：条件を `if src == "doing" and dst in ("review", "blocked"):` にし、`cm` がある時だけ `t["creator"] = cm.group(1)` を代入する。planner はこの形で基準2の期待値を計算した。同じ結果になれば書き方は任せる
- `CREATOR_RE`・`LINE_RE`・`ATTEMPT_RE` の正規表現は変えなくてよい
- `collect()` の docstring や近くのコメントに、集計キーの決め方を書き足してよい（例：`creator は doing→review / doing→blocked のうち最後の creator= 付き行の値`）
- 対象タスク（最後の遷移が `→done`／`→blocked`）、1回目 PASS 率、平均 attempt、blocked 率の分母と分子、出力形式は変えない
- `scripts/smoke.sh` は触らない（T-02 で直す）。`docs/vault-spec.md`・`vault/designs/D-010.md` も触らない（T-03 は spec のみ。D-010 は変更しない）
- 今の `vault/log/*.md` に対する出力は、変更の前後で同じになる（planner が確認済み：`sonnet	36	...`・`unknown	131	...`）。違っても基準3は終了コードと見出し行だけを見る
- フィクスチャを `/tmp` の固定パスに書く。後片付けの `rm` は不要
- コミットは不要（受け入れ基準に無い）
