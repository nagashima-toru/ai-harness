# T-02 agent_write_guard.py (b) でベースブランチと main の直接コミットを拒否する

## 目的
`.claude/hooks/agent_write_guard.py` の判定 (b) を、現在のブランチが `HARNESS_BASE_BRANCH` の値（前後の空白を除いて空なら `main`）か `main` の時に `git commit` を拒否するようにする。未設定なら今の動作（`main` 上だけ拒否）を変えない。

## 入力
- `.claude/hooks/agent_write_guard.py`
- `vault/designs/D-20261010-base-branch-config.md`（「決定事項」と「フェーズ1」の「決定済み」）
- `docs/vault-spec.md` 12節（(b) の判定。このタスクでは変えない）

## 成果物
- `.claude/hooks/agent_write_guard.py`（1ファイル）

## 受け入れ基準
- 拒否するブランチの一覧が値に従う：`env HARNESS_BASE_BRANCH=' develop ' python3 -B -c "__import__('sys').path.insert(0, '.claude/hooks') or print(__import__('agent_write_guard').protected_branches())"` の出力が `['develop', 'main']`
- 未設定・空白だけ・`main` の時は `main` だけ：上と同じ `python3 -B -c ...` を `env -u HARNESS_BASE_BRANCH`、`env HARNESS_BASE_BRANCH='  '`、`env HARNESS_BASE_BRANCH=main` を前に付けて実行した出力がどれも `['main']`
- (b) の判定が一覧を使い、固定の `main` 比較が残っていない：`grep -cF 'in protected_branches()' .claude/hooks/agent_write_guard.py` が `1`、`grep -cF '== "main"' .claude/hooks/agent_write_guard.py` が `0`
- ベースブランチ上の `git commit` を、ブランチ名入りの理由で拒否する：`printf '%s' '{"tool_name":"Bash","tool_input":{"command":"git commit -m x"}}' | env HARNESS_BASE_BRANCH=work/p-20261011-base-branch-env CLAUDE_PROJECT_DIR=/home/user/ai-harness python3 -B .claude/hooks/agent_write_guard.py` の出力に `"permissionDecision": "deny"` と `work/p-20261011-base-branch-env への直接コミットはできません` の両方が含まれる
- 同じコマンドを `env -u HARNESS_BASE_BRANCH CLAUDE_PROJECT_DIR=/home/user/ai-harness` で実行した時は出力が空（そのブランチは `main` でもベースでもないので許可）
- 既定のままの既存動作が変わらない（guard3-b・guard-b2・(i)〜(k) を含む）：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- モジュールの関数として `protected_branches()` を足す。値は `os.environ.get("HARNESS_BASE_BRANCH", "").strip() or "main"` で読み、戻り値はリスト `[<ベース>, "main"]`（ベースが `main` なら `["main"]` の1要素。順序はベースが先）。値の形式は検査しない
- (b) は `branch = current_branch(root)` を取り、`is_git_commit_command(cmd) and branch in protected_branches()` の時に拒否する（`in protected_branches()` の字句で書く）。`current_branch` が None（detached HEAD・非 git）の時は従来どおり素通り
- 拒否メッセージは f 文字列で `f"[agent_write_guard] {branch} への直接コミットはできません。"` から始め、その後ろの「ブランチを切ってください（work/<計画IDの英小文字>）: {cmd[:120]}」は今のまま残す
- モジュール冒頭の docstring と `# (b)` のコメントの「main 上の git commit の拒否」「現在のブランチが main の時」は、「ベースブランチ（HARNESS_BASE_BRANCH、既定 main）か main」の意味に書き換える
- `HARNESS_PUSH_BRANCH` 上の直接コミットは拒否しない（設計の決定事項。フェーズ2でも足さない）
- `_hooklib.py`・`transition.py`・`stop_gate.py`・`diff_gate.py` は変えない
- 受け入れ基準のコマンドは、`/home/user/ai-harness`（メインのチェックアウト。run 中は計画ブランチ `work/p-20261011-base-branch-env` にいる）のブランチを判定に使う。payload に `cwd` を入れないので worktree への委譲は起きず、実行したディレクトリ（creator の worktree）の版のフックが判定する。`python3 -B` は `__pycache__` を作らないため
- `scripts/smoke.sh` はこのタスクでは変えない（develop 上・main 上・work 上のケースは T-06 で足す）
