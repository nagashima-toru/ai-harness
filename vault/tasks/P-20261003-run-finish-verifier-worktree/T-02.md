# T-02 run スキルの verifier の worktree 検証手順を絶対パス方式にし、手順7に引数なし既定を書く

## 目的
`.claude/skills/run/SKILL.md` に残る「verifier が `EnterWorktree` で worktree に入る」前提を、verifier が実際にやっている「worktree の絶対パスに対して `git -C` と絶対パスで検証する」形に書き換える。手順7には vcs_finish.sh が引数なしでも通ることを書く（issue #89）。

## 入力
- `.claude/skills/run/SKILL.md`（45行目＝手順4の段落の末尾の文、49行目＝手順5の2、85行目＝手順7の2つ目の箇条）
- `.claude/agents/verifier.md` の4行目（`tools: Read, Grep, Glob, Bash, Write`。`EnterWorktree` を含まない）
- `scripts/vcs_finish.sh`（T-01 で引数なしの既定値が入る。T-01 の結果を待たずに、下の「決定済み」の文をそのまま書いてよい）

## 成果物
- `.claude/skills/run/SKILL.md`

## 受け入れ基準
- `EnterWorktree` という語が手順5の2の1行だけに残り、その行が「使わない」と書いている。確認：`grep -n 'EnterWorktree' .claude/skills/run/SKILL.md` の出力がちょうど1行で、その行が `2. verifier は` で始まり、`` `EnterWorktree` を使わない``・`git -C <worktree のパス>`・`cd <worktree のパス>` の3つを含む
- 手順4の段落の末尾の文が、絶対パスで検証する前提に書き換わっている。確認：`grep -c -F '手順5で verifier が対象タスクの worktree を絶対パスで検証するため' .claude/skills/run/SKILL.md` が `1`
- 手順7に引数なし既定の1文が足されている。確認：`grep -n -F '既定で使うので非対話で通る' .claude/skills/run/SKILL.md` の出力がちょうど1行で、その行番号が `## 7. 次へ・完了` と `## 8. ハーネス振り返り` の見出しの行番号の間にある（`grep -n '^## ' .claude/skills/run/SKILL.md` と見比べる）

## 決定済み
- 方針（人の代理の設計判断。変えない）：verifier に `EnterWorktree` を持たせない（権限を増やさない）。`.claude/agents/verifier.md` の tools は変えない（このタスクでは触らない。T-04 の担当）
- 45行目：末尾の文「手順5で verifier が対象タスクの worktree に `EnterWorktree` で入るため、コミットされていない変更はその worktree には反映されず verifier から見えない。」を、次の文に置き換える（他の部分は変えない）：
  `手順5で verifier が対象タスクの worktree を絶対パスで検証するため、コミットされていない変更はその worktree には反映されず verifier から見えない。`
- 49行目（手順5の2）を、まるごと次の1行に置き換える：
  `` 2. verifier は `EnterWorktree` を使わない（verifier の tools に無く、権限も増やさない）。渡された worktree のパスに対して、git は `git -C <worktree のパス> ...`、ファイルは `<worktree のパス>/<相対パス>` の絶対パスで読む。作業ディレクトリが要るコマンド（スクリプトの実行など）は、同じ Bash 呼び出しの中で `cd <worktree のパス>` してから実行する。verdict はメインリポジトリ側の `vault/verdicts/<計画ID>/<id>.json` に書く（creator の呼び出しで作られた既存 worktree を再利用し、verifier 自身は新規に worktree を作らない） ``
- 手順7：85行目（「全タスクが `done` になったら、…draft PR にするかは規定しない」）の直後、86行目（`gh`/`glab` コマンドが無い時の箇条）の前に、2スペース字下げの箇条を1行足す。85・86行目は変えない：
  `` - 引数なしの `bash scripts/vcs_finish.sh` は、GitHub なら `gh pr create --fill`、GitLab なら `glab mr create --fill --yes` を既定で使うので非対話で通る。PR/MR のタイトル・本文を整えたい時は引数で渡してよい（引数がある時は既定を付けず、そのまま渡す） ``
  （行頭は2スペース＋`- `）
- 手順1〜8の見出し・番号・他の文は変えない。`docs/vault-spec.md`・`vault/designs/` の `EnterWorktree` の記述は直さない（対象外）
- `.claude/skills/` への creator の書き込みが auto mode などの権限判定で拒否された場合、別の書き方での回避はしない。blocked にし、拒否のメッセージを質問文に書く
