# T-05 docs/runbook.md・docs/decisions.md を新方式に更新し通し確認する

## 目的
`docs/runbook.md` を計画票中心の運用手順（ゴールを入れる・承認する・`/run` を回す・blocked に答え
る・計画単位で archive する）に書き直し、`docs/decisions.md` にキュー廃止と並行セッション対応の決定
を1行追記する。最後に一時ディレクトリへ新規 install して `bash scripts/smoke.sh` が通ることを確認す
る。

## 入力
- `docs/runbook.md`（改訂対象。特に「3. キューを回す」「4. blocked に答えて todo に戻す」「5. 月次で
  done を archive に移す」節）
- `docs/decisions.md`（追記対象。既存の1行1レコードの表形式に従う）
- T-01〜T-04 で確定した新しいディレクトリ構成・`install.sh`・`ai-harness.md`・README/install.md
- `.claude/skills/plan/SKILL.md`・`.claude/skills/run/SKILL.md`

## 成果物
- `docs/runbook.md`、`docs/decisions.md`、`scripts/install.sh`（人の承認により追加：新規installで
  自分自身をコピーしないバグの修正）

## 受け入れ基準
- `grep -c 'vault/todo.md' docs/runbook.md` が0
- runbook の「キューを回す」相当節が `/run-queue` ではなく `/run` を使う手順になっている。確認：`grep -c '/run-queue' docs/runbook.md` が0
- runbook の「blocked に答えて戻す」相当節が計画票のタスク表の該当行を書き換える手順になっている。確認：`grep -c '計画票' docs/runbook.md` が1以上
- runbook の「月次で done を archive に移す」節が計画単位でまとめて移す手順に読み替わっている。確認：`grep -c '計画単位' docs/runbook.md` が1以上
- `docs/decisions.md` に日付付きの1行が追加され、キュー廃止・並行セッション対応の決定に触れている。確認：`grep -c '並行セッション' docs/decisions.md` が1以上
- 一時ディレクトリへ新規 install した上で `bash scripts/smoke.sh` を実行し、`tail -1` に `fail=0` が含まれる。確認：`T=$(mktemp -d); bash scripts/install.sh "$T" >/dev/null && (cd "$T" && bash scripts/smoke.sh) | tail -1`

## 決定済み
- **追記（人の承認）**：`scripts/install.sh` を新規インストールでも自分自身をコピーするよう修正
  する。`copy_if_absent` の呼び出し列（`scripts/smoke.sh`・`rules.sh`・`merge_claude_md.py`・
  `merge_settings_json.py` の直後）に
  `copy_if_absent "$SRC/scripts/install.sh" "$DST/scripts/install.sh"` を追加する。
  `manifest_paths()` には既に列挙済みなので `--update` 側のロジックは変更不要
- runbook の節番号・見出し名は「0. 大きなゴールは先に設計する」〜「7. ハーネス自体の更新を取り込む」の構成を踏襲してよいが、中身は次のとおり書き換える：
  - 「1. ゴールを入れる」は `/plan` がブランチを切り計画票 draft を作る旨に変える
  - 「2. 計画を承認する」は `/plan approve <計画ID>` で frontmatter の `status` を `approved` にする旨に変える（`vault/todo.md` への登録という表現を削除）
  - 「3. キューを回す」は `/run`（対話）・`claude -p "/run"`（無人）に変える
  - 「4. blocked に答えて todo に戻す」は、計画票のタスク表の該当行の `status`・`question`・`attempt` を人が書き換える手順に変える
  - 「5. 月次で done を archive に移す」は、`status: done` の計画票1件ぶん（計画票・配下のタスク票・verdict・ログ）をまとめて `vault/archive/<年-月>/` に `git mv` する手順に読み替える
  - 「6. ルールを足す」「7. ハーネス自体の更新を取り込む」は挙動が変わっていないのでそのまま残してよい
- `docs/decisions.md` に追加する1行の例：`| 2026-09-20 | 計画をまたぐキュー（vault/todo.md）を廃止し、計画票のタスク表が状態を持つ1セッション=1計画=1ブランチ方式にした | 複数のエージェントセッションが別々の計画を同時に進めても状態ファイルが競合しないようにするため |`
- 「`/plan` から `/run` までの1周が通る」という完全な実行確認（`claude -p` の起動）は、コストと前フェーズ（P-021）での既存検証を踏まえ、この計画では自動確認の対象にしない。人が必要と判断すれば承認後に手動で確認する（計画票の「人への質問」参照）
