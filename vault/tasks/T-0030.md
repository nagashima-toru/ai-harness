# T-0030 `vault/rules/common/git.md` に git 運用の方針を書く

## 目的
人が提示した「Git 運用ルール」原案を、このハーネスの用語・プロセス（todo→doing→review→done、verdict PASS が done の条件、1計画=複数タスク＋after 依存）に翻案し、全役割（作成エージェント・verifier・planner）が読む共通ルールとして固定する。以降のタスク（creator 向け手順・フック実装・SKILL 改訂・配布）はこの方針を前提にする契約。

## 決定済み
- このタスクは `vault/rules/` へ書き込む。`doing`/`review` 中は `agent_write_guard.py` が `vault/rules/` への書き込みを拒否するため、人が `HARNESS_ALLOW_RULES_WRITE=T-0030 claude`（または同形の `claude -p`）で起動している前提で進める。Write が deny されたら自分でフックや設定を変えず、status を `blocked` にし question に「`HARNESS_ALLOW_RULES_WRITE=T-0030` を設定して再実行してください」と書く。
- 「ルール」に書く内容は次の7項目（各1〜4行、箇条書きの塊ごとに `**見出し**` を付ける。`creator.md` の書きぶりに合わせる）：
  1. **原則**：git は検証とやり直しの単位である／未コミットの変更を残したままセッションを終えない
  2. **ブランチ**：`main` への直接コミット禁止。ブランチ粒度は「1計画=1ブランチ」（原案の「1タスク=1ブランチ」を読み替える）。名前は `work/p-xxx-<計画タイトルの短い英小文字ハイフン区切りスラッグ>`（例：`work/p-017-claude-md`）。ブランチはマージ後に人が削除する
  3. **コミット**：作成エージェントは作業ステップごとにコミットする（まとめて1コミットにしない）。1コミット=1つの意味のある変更。メッセージ1行目に「何をしたか」を書く（日本語可）。生成物・一時ファイル・認証情報はコミットしない
  4. **完了の定義（二層構造）**：タスクの `done` は従来どおり verdict PASS のみで決まる（変えない）。計画（P-xxx）の完了は別の階層で、その計画の全タスクが `done` になった後、作成エージェントが push して `gh pr create` するところまでを指す。**マージは人が行う**。エージェントは `gh pr merge` を実行しない
  5. **セッション終了時**：未コミットの変更は commit / stash（`git stash push -m "<理由>"`）/ 破棄のいずれかで必ず処理する。破棄手段は `git restore` のみを使う（`settings.json` の deny に `git clean` と `git reset --hard` があるため、それ以外の破棄はできない）。`git restore` で足りない場合（未追跡ファイルなど）は自分で消さず、人に報告して止まる
  6. **禁止**：`main` への直接コミット／`--force` push（`--force-with-lease` を含め、人の指示がない限り行わない）／人の指示のない履歴書き換え（rebase・amend）／未コミット状態でのブランチ切り替え
  7. **例外**：コンフリクト・想定外の差分・判断がつかない変更に遭遇したら、自己判断で処理せず作業を止めて人に報告する（該当タスクを `blocked` にし question に書く）
- 「確認方法」には、人・verifier がこのルールを満たしているか見る観点（例：ブランチが `work/p-xxx-*` か、コミットが作業ステップ単位に分かれているか、`gh pr merge` を実行していないか）を2〜4行で書く。機械的な確認コマンドが無くてもよい
- creator 向けの具体的な手順（いつ切る・いつコミットする・いつ PR を作る）はここには書かない。`vault/rules/creator/git-workflow.md`（T-0031）に書く。ここは全役割向けの方針だけに留める
- `.claude/settings.json`・`agent_write_guard.py`・`stop_gate.py`・`run-queue` の SKILL・`install.sh`・`.gitignore`・README/runbook/decisions.md は変更しない（それぞれ T-0032〜T-0035 の範囲）
- git commit はしない（人が確認してからコミットする）
