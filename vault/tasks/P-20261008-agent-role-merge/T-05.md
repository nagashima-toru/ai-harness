# T-05 docs/vault-spec.md 11節と README.md の拡張ポイントを「標準ルールを同梱しない」形にする

## 目的
`docs/vault-spec.md` 11節と `README.md` の「拡張ポイント（ルール）」節を、T-01〜T-04 の結果に合わせる。ハーネスは標準ルールを同梱せず、planner / creator / verifier の役割定義は `.claude/agents/` にあり、`vault/rules/` は導入先のルール専用であることを書く。

## 入力
- `vault/designs/D-013.md` の「フェーズ4 標準の役割定義をエージェント定義に統合する」
- `docs/vault-spec.md` 11節（`## 11. ルール（`vault/rules/`）` から `## 12.` の手前まで）
- `README.md` の `## 拡張ポイント（ルール）` 節
- `.claude/agents/creator.md`・`.claude/agents/verifier.md`・`.claude/agents/planner.md`（T-01〜T-03 の結果）
- `scripts/install.sh`（T-04 の結果。`RETIRED_RULES` と `--update` の動き）

## 成果物
- `docs/vault-spec.md`（主な成果物。11節だけ）
- `README.md`（拡張ポイント（ルール）の節だけ）

## 受け入れ基準
- 両方のファイルの該当節に「ハーネスは標準ルールを同梱しない」の文があり、役割定義が `.claude/agents/creator.md`・`.claude/agents/verifier.md`・`.claude/agents/planner.md` にあることが書かれている：`grep -n 'ハーネスは標準ルールを同梱しない' docs/vault-spec.md README.md` の出力が各ファイル1行以上で、その行が11節・拡張ポイントの節の中にある（Read で確認）
- 11節と拡張ポイントの節に6本のファイル名が残っていない：`sed -n '/^## 11\./,/^## 12\./p' docs/vault-spec.md | grep -nE 'roles\.md|creator/creator\.md|verifier/verifier\.md|planner/planner\.md|common/git\.md|git-workflow\.md'` の出力が空で、`grep -nE 'roles\.md|creator/creator\.md|verifier/verifier\.md|planner/planner\.md|common/git\.md|git-workflow\.md' README.md` の出力が空
- 11節に、旧版で配った6本は `install.sh --update` が未編集なら削除し、編集済みは残して `note` で案内することが書かれている（Read で `scripts/install.sh` と食い違わないことを確認）
- 見出しの構成が変わっていない：`git diff main -- docs/vault-spec.md README.md | grep -E '^[+-]#'` の出力が空。あわせて `git diff main -- docs/vault-spec.md README.md` の変更箇所が11節と拡張ポイントの節の中だけである（Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 書く文：「ハーネスは標準ルールを同梱しない。」をこの文字列ちょうどで、11節の冒頭の段落と拡張ポイントの節の冒頭の段落にそれぞれ1回書く。続けて「planner / creator / verifier の役割定義は `.claude/agents/creator.md`・`.claude/agents/verifier.md`・`.claude/agents/planner.md` にある」旨と、「コーディングルール・開発標準・方式設計・テスト観点などは導入先で `vault/rules/` に書く」旨を書く
- 11節に足す文：旧版の install で配った6本は、`bash scripts/install.sh --update` がマニフェストのハッシュで未編集と判定したものだけ削除し、編集済みのものは残して `note` の行で案内する。6本のファイル名は列挙しない（受け入れ基準2で検査するため）。「旧版で配った役割定義のルール6本」のように書く
- 11節のディレクトリ構成の図・振り分けの箇条・「ルールと受け入れ基準の関係」・「改ざん防止」の小節は残す。小節の見出しは変えない
- README.md の表・`rules.sh` の箇条・名指し参照の例（`vault/rules/common/naming.md`）・提案ファイル方式の箇条は残す。「導入先で積む拡張の例（ハーネス同梱の標準ルールではない）」の括弧書きは、同梱しないことと矛盾しない形（例：「導入先で書くルールの例」）に直してよい
- 11節の外（例：6節の「`vault/rules/verifier/verifier.md` を根拠とする」）と、README.md の拡張ポイントの節の外は変えない（計画票の「人への質問」1。D-013 フェーズ7で扱う想定）
- `.claude/`・`scripts/`・`docs/install.md`・`vault/rules/` は変えない
