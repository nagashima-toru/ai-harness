# T-03 run スキルの手順1を current_plan.sh 判定に書き換える

## 目的
`.claude/skills/run/SKILL.md` の「## 1. 計画票を見つける」を、`scripts/current_plan.sh` の出力行数（0件／1件／2件以上）で判定する手順に書き換える。

## 入力
- 現在の `.claude/skills/run/SKILL.md`「## 1. 計画票を見つける」節（12〜17行目）
- T-01 の成果物 `scripts/current_plan.sh`（出力仕様：frontmatter の `status` が `approved` の計画票の id を1行1件）

## 成果物
- `.claude/skills/run/SKILL.md`

## 受け入れ基準
- 手順1が `scripts/current_plan.sh` を使う記述になっている。確認：`grep -c 'current_plan.sh' .claude/skills/run/SKILL.md` が1以上
- 0件の場合の既存の案内文言が残っている。確認：`grep -c '承認済みの計画が見つかりません' .claude/skills/run/SKILL.md` が1以上
- 2件以上の場合の既存の案内文言が残っている。確認：`grep -c 'approved な計画票が複数' .claude/skills/run/SKILL.md` が1以上
- 手順1以外の見出し（`## 0.`・`## 2.`〜`## 8.` 等）は変更されていない。確認：`git diff -- .claude/skills/run/SKILL.md > /tmp/P-20260927-current-plan-detector-T-03-diff.txt` を実行した後、`grep -E '^[+-]## ' /tmp/P-20260927-current-plan-detector-T-03-diff.txt` の出力が空

## 決定済み
- 手順1の書き換えは、現在の3ステップ（`vault/plans/*.md` を走査 → 0件なら報告 → 2件以上なら報告）の代わりに、`bash scripts/current_plan.sh` を実行し、出力の行数を数えて分岐する記述にする
- 0件・1件・2件以上それぞれの案内文言（「承認済みの計画が見つかりません。`/plan approve <計画ID>` を実行してください」「approved な計画票が複数あります（異常）。人に確認してください」等）は文言を変えずにそのまま残す
- 1件の場合、出力された1行を計画 ID とし、対応する計画票 `vault/plans/<計画ID>.md` の frontmatter の `id` からその計画票のファイルを特定する（計画 ID とファイル名が一致しない運用は考慮不要。既存の運用では両者を一致させている）
- 手順1以外（`## 0.`・`## 2.`〜`## 8.`・「ハング時の復旧」「注意」等）の見出し文・内容は変更しない
- `scripts/current_plan.sh` の呼び出し例（行数の数え方）を SKILL.md 本文に書く場合、パイプ・`&&`・コマンド置換を多用した複合コマンド例にはしない（`vault/rules/planner/planner.md` の方針を踏まえる。必須ではないが読みやすさを優先してよい）
- T-01 が `done`（`scripts/current_plan.sh` が存在し動作する状態）になってから着手する
