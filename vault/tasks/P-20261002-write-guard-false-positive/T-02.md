# T-02 creator の vault/plans/・vault/log/ 拒否の Bash 判定を analyze_bash_writes に載せ替える

## 目的
creator が Bash で `vault/plans/`・`vault/log/` を読むだけのコマンドが拒否される誤検知（issue #91）を解消する。対象は、grep のパターンにある `git add`、別の場所へのリダイレクト、ヒアドキュメント本文中のパス文字列などを含むコマンド。`targets_creator_denied_paths` の Bash 分岐を、T-01 で作った `analyze_bash_writes` の結果で判定するように変える。計画票・ログへの実際の書き込みは引き続き拒否する。

## 入力
- `.claude/hooks/agent_write_guard.py`（T-01 完了後の版。`analyze_bash_writes`・`targets_creator_denied_paths`）
- `vault/tasks/P-20261002-write-guard-false-positive/T-01.md` の「決定済み」（解析関数の返り値・None の条件）
- `scripts/smoke.sh`：T-01 で足した `(bash-parse)` のブロック

## 成果物
- `.claude/hooks/agent_write_guard.py` の `targets_creator_denied_paths` の Bash 分岐の載せ替えと、`scripts/smoke.sh` への `(bash-parse-creator)` 回帰テストの追加（実装とその回帰テストで1PR分の2ファイル）

## 受け入れ基準
- フックが構文エラー無くコンパイルできる。確認：`python3 -m py_compile .claude/hooks/agent_write_guard.py` の終了コードが 0
- smoke が全件 pass し、NG が無い。確認：`bash scripts/smoke.sh > /tmp/P-20261002-write-guard-false-positive-T-02-smoke.txt 2>&1` の後、`tail -1 /tmp/P-20261002-write-guard-false-positive-T-02-smoke.txt` が `smoke: pass=<N> fail=0`（`<N>` は 397 以上）で、`grep -c '^  NG' /tmp/P-20261002-write-guard-false-positive-T-02-smoke.txt` が `0`
- 「決定済み」の許可ケース5件（現行コードでは拒否される誤検知）が、smoke で許可として通る。確認：同じ出力ファイルに対して `grep -c '^  ok   (bash-parse-creator) .*→ 許可' /tmp/P-20261002-write-guard-false-positive-T-02-smoke.txt` が `5` 以上
- 「決定済み」の拒否ケース7件が、smoke で拒否として通り、reason に creator の拒否文言を含む。確認：同じ出力ファイルに対して `grep -c '^  ok   (bash-parse-creator) .*→ 拒否' /tmp/P-20261002-write-guard-false-positive-T-02-smoke.txt` が `7` 以上
- 既存の smoke ケースを削除・変更していない（追加だけ）。確認：`git diff main --numstat -- scripts/smoke.sh` の2列目（削除行数）が `0`
- `targets_creator_denied_paths` が解析関数を使っている。確認：`grep -n -A 25 'def targets_creator_denied_paths' .claude/hooks/agent_write_guard.py` の出力に `analyze_bash_writes(` を含む行がある

## 決定済み
- **判定**：
  - Write/Edit/MultiEdit/NotebookEdit の分岐は変えない
  - Bash は `analyze_bash_writes(cmd)` が None なら現行の判定（`BASH_WRITE_PATTERNS`＋リダイレクト先＋`vault/(plans|log)/` を含むパスらしいトークン）をそのまま使う
  - リストが返れば、verb を問わずどれかの target が `normalize(target, root)` で `DENIED_FOR_CREATOR`（`vault/plans/`・`vault/log/`）始まりの時だけ True にする
  - `git add vault/plans/...` も従来どおり拒否側（creator は計画票・ログをステージしない。コミットはオーケストレーターの役目）
- `analyze_bash_writes` 自体の挙動を変える必要が出たら、変えずに `blocked` にして question に書く（T-01 の smoke ケースの前提が崩れるため）
- 他の判定（`targets_vault_rules`・`targets_transcript_dir`・`find_done_task_write`・ALLOWED 判定・main 直接コミット拒否）は変えない
- **smoke に足すケース**：T-01 の `(bash-parse)` のブロックの直後に置く
  - 名前は `(bash-parse-creator) <説明> → 許可` / `(bash-parse-creator) <説明> → 拒否` の形にする
  - すべて `"agent_type":"creator"` の Bash で、`run_guard` と 4引数版 `expect_guard` を使う。拒否ケースは4番目の引数に `creator は vault/plans/` を渡す
  - パスは root 相対の `vault/plans/P-X.md`・`vault/log/P-X.md`（計画票が無い計画 ID なので done 判定には当たらない）
  - 許可（5件。いずれも現行コードでは拒否されることを planner が確認済み）：
    1. `grep -n "git add" vault/plans/P-X.md`
    2. `git log -p -- vault/log/P-X.md > /tmp/out.txt`
    3. `cat > /tmp/note.md <<'EOF'`＋改行＋`vault/plans/P-X.md ni git commit`＋改行＋`EOF`
    4. `grep -n "doing->review" vault/log/P-X.md`
    5. `grep -c x vault/plans/P-X.md > /tmp/c.txt`
  - 拒否（7件。現行でも拒否される）：
    1. `echo x >> vault/log/P-X.md`
    2. `printf x | tee -a vault/plans/P-X.md`
    3. `sed -i s/a/b/ vault/plans/P-X.md`
    4. `cp /tmp/a vault/log/P-X.md`
    5. `git add vault/plans/P-X.md`
    6. `echo "$(echo x >> vault/log/P-X.md)"`（コマンド置換：従来判定）
    7. `echo a`＋改行＋`rm vault/log/P-X.md`（改行区切り）
  - `git show HEAD:vault/plans/P-X.md > /tmp/x` は現行でも許可されるため、許可ケースに入れない
- 冒頭 docstring の creator 向け拒否リストの段落に、「Bash は `analyze_bash_writes` で解析できた時は実際の書き込み対象だけで判定する」を1〜2行で足す
- 実装時の注意（T-01 と同じ）：
  - フックは `/tmp/P-20261002-write-guard-false-positive-T-02-guard.py` で編集し、`py_compile` を通してから `cp` で置き換える
  - `scripts/smoke.sh` は Edit/Write ツールで編集する
  - 確認コマンドが拒否される時は `/tmp/P-20261002-write-guard-false-positive-T-02-check.sh` に書いて `bash` で実行する
  - 権限分類器に拒否されたら `blocked` にする
- コミットは受け入れ基準に無いので creator は行わない
