# T-03 agent_write_guard.py で計画票の draft→approved を会話記録の人の発言で裏付け、無ければ拒否する（smoke.sh にテストを足す）

## 目的
計画票の承認（status を approved にする書き込み）を、人が `/plan approve <計画ID>` で指示した時だけ許可する。PreToolUse で Write/Edit/MultiEdit の書き込み後の内容を組み立てて判定し、エージェントの独断の承認を防ぐ（D-010 フェーズ4、決定事項の #75）。

## 入力
- `vault/designs/D-010.md` の決定事項（#75 の承認・会話記録が読めない時の警告）とフェーズ4の決定済み
- `.claude/hooks/agent_write_guard.py`：`main()`（T-02 で足した会話記録の保護判定の直後に置く）、`normalize`、`plan_raw_rows`・`plan_task_status`（frontmatter の読み方の参考）、`delegate_to_worktree`
- `scripts/smoke.sh` の `== agent_write_guard.py ==` 節（`run_guard`・`expect_guard`・`make_plan`）と T-02 で足した `HOME` 差し替えヘルパー

## 成果物
- `.claude/hooks/agent_write_guard.py` の変更と `scripts/smoke.sh` への回帰テスト・会話記録ヘルパー追加（1PR分の関連する2ファイル変更）

## 受け入れ基準
- 会話記録の人の発言に `/plan approve P-TEST` がある時、`agent_type` が空の Write・Edit・MultiEdit による P-TEST の計画票の draft→approved が許可される（スラッシュコマンド形式と文形式の両方）。確認：`bash scripts/smoke.sh` の出力に `ok   (approve-pre)` で始まる該当ケースがあり `NG` が無い
- 会話記録にコマンドが無い時、または `agent_type` が `planner` の時（会話記録に有っても）は拒否され、reason に `/plan approve` を含む。計画 ID が違う（`approve P-OTHER`）発言だけの時も拒否される（同上）
- 同じコマンドが `tool_result`（`message.content` が配列）の行や `isMeta: true` の行にしか無い会話記録では拒否される（同上）
- 会話記録が読めない時（`transcript_path` が無い・ファイルが無い・どの行も JSON でない・人の発言が1件も無い）は拒否せず許可する（同上）
- draft→draft・approved→approved・done→done の編集、承認に当たらない他ファイルへの書き込みは会話記録と無関係に従来どおり許可される（同上）
- `bash scripts/smoke.sh > /tmp/P-20260930-approve-transcript-guard-T-03-smoke.txt 2>&1` の後 `grep -c '^  NG' /tmp/P-20260930-approve-transcript-guard-T-03-smoke.txt` が `0`、`tail -1 /tmp/P-20260930-approve-transcript-guard-T-03-smoke.txt` が `smoke: pass=<N> fail=0`

## 決定済み
- 人の発言とみなすのは、会話記録（JSONL・1行1 JSON）のうち `type` が `user`、`message.content` が文字列、`isMeta` が真でない行だけ。`content` が配列の行（`tool_result` など）は対象外。探す範囲はそのセッションの会話記録全体
- コマンドの一致：人の発言が `<command-name>/plan</command-name>` と `<command-args>approve <計画ID></command-args>` の両方を含む（スラッシュコマンド形式）か、先頭が `/plan approve <計画ID>` である（文形式）。計画 ID は完全一致（`P-TEST` と `P-TEST2` を区別する。`<command-args>` の中身の前後の空白は除いて比べる）
- 「会話記録が読めない」とは、`transcript_path` が無い・ファイルが無い・どの行も JSON として読めない・人の発言が1件も見つからない、のいずれか。この時は拒否せず許可する（警告は T-04 の plan_guard が出す）。読めたうえでコマンドが無い時は拒否する
- 承認の検出：対象が root 相対で `vault/plans/<計画ID>.md`（`^vault/plans/([^/]+)\.md$`）で、書き込み前の frontmatter の status が approved でない（ファイルが無い場合を含む）かつ書き込み後の status が approved であること。frontmatter は先頭の `---` から次の `---` まで、`status:` 行を見る（本文中の `status: approved` は無視する）
- 書き込み後の内容の組み立て：Write は `content`、Edit は現在のファイルに `old_string`→`new_string`（`replace_all` を考慮）を適用したもの、MultiEdit は `edits` を順に適用したもの。比較の相手はディスク上の現在の内容。適用に失敗した（`old_string` が見つからない等）場合は、承認ではないとみなして許可する（Claude Code 側が失敗させる）
- 許可の条件：`agent_type` が空（メインセッション）、かつ会話記録に一致するコマンドがある、または会話記録が読めない。`agent_type` が `planner`・`creator`・`verifier` などの時は、会話記録の内容に関わらず拒否する
- reason の文言は `[agent_write_guard] <計画ID> の承認（status を approved にすること）は、人が /plan approve <計画ID> で指示した時だけ許可されます。` とする
- Bash による書き換えはこのタスクでは検査しない（T-04 の plan_guard が PostToolUse で補う）
- 会話記録の解析関数は `agent_write_guard.py` 内に足す（他フックの import はしない。plan_guard 側には T-04 でコピーする）
- smoke.sh の会話記録ヘルパー：`make_transcript`（引数の行を `/tmp/P-20260930-approve-transcript-guard-transcript.jsonl` に書く固定パス方式）を足し、T-04 でも流用できるようにする。サンプルの行の形は次のとおり
  - 人の発言（スラッシュコマンド）：`{"type":"user","message":{"role":"user","content":"<command-name>/plan</command-name>\n<command-args>approve P-TEST</command-args>"}}`
  - 人の発言（文）：`{"type":"user","message":{"role":"user","content":"/plan approve P-TEST"}}`
  - 人の発言（無関係）：`{"type":"user","message":{"role":"user","content":"こんにちは"}}`
  - ツール結果：`{"type":"user","message":{"role":"user","content":[{"type":"tool_result","content":"/plan approve P-TEST"}]}}`
  - メタ：`{"type":"user","isMeta":true,"message":{"role":"user","content":"/plan approve P-TEST"}}`
  - 「コマンドが無い」ケースのフィクスチャには、必ず「無関係な人の発言」を1件入れる（人の発言が0件だと「読めない」扱いになるため）
- smoke.sh のケース接頭辞は `(approve-pre)`。フックの入力には `transcript_path` と `agent_type`（任意）を含める。既存の `run_guard` は文字列をそのまま渡すので流用できる。後片付けに `rm -rf` は使わない
- worktree 委譲（`delegate_to_worktree`）は既存のまま。委譲後も同じ判定が働く
