# ゴール
README.md を改善する。
(1) 冒頭で「何のためのものか」（実行を安いモデルに任せても成果が安定する汎用タスク実行基盤）を1文程度の位置づけ＋ `docs/vision.md` へのリンクで示す（vision の本文は写さない。`docs/vision.md` が唯一の正本という P-20261010-vision-local-only の決定に従う）。clone → `bash scripts/smoke.sh` → 最初の `/plan <ゴール>` →（自動で /run）→ PR → 人がマージ、までの最小のクイックスタート例を足す。
(2) セットアップ節を短くし、CLAUDE.md へのマーカーブロックのマージの細かい挙動や `install.sh --update` の挙動は `docs/install.md` に寄せてリンクする（`docs/install.md` は変えない）。
(3) 「仕組み」節の ASCII 図を全角文字幅のずれが無い形に直し、「構成」節を表か箇条書きに分けて1行が長すぎないようにする。
既存の情報（コマンド表、/design と /plan の使い分け、拡張ポイント（ルール）節とその表、PR 後に人がマージする説明、構成に挙がっている全ファイル・ディレクトリ名、ライセンス節、docs へのリンク）は失わない。成果物は README.md 1ファイルのみ。

## 分割方針
- 成果物はすべて `README.md` 1ファイルなので、節ごとに4タスクへ分け、`after` で直列にする（同じファイルを並行で変えるとマージが衝突するため）
- T-01：冒頭の位置づけ＋vision へのリンクと、クイックスタート節の新設（見出し構成をここで確定させる）
- T-02：セットアップ節の短縮（clone・smoke のコードブロックはクイックスタートに一本化、細かい挙動は docs/install.md へのリンクに置き換え）
- T-03：仕組み節の図を ASCII だけの図＋番号付き手順に直す
- T-04：構成節を1行1項目の表にし、最後に README 全体で既存情報が残っていることを確かめる
- 各タスクは README の見出し一覧が同じであることと smoke の `(ref-1)` を基準に持つ
