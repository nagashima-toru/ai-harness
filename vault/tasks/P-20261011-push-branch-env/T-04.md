# T-04 決定事項を decisions.md に取り出し設計文書を削除する

## 目的
設計文書 `vault/designs/D-20261010-base-branch-config.md` の決定事項のうち docs に無いものを `docs/decisions.md` に取り出し、最終フェーズが終わって読まれなくなった設計文書を削除する。

## 入力
- `vault/designs/D-20261010-base-branch-config.md`（「決定事項」「今回やらないこと」）
- `docs/decisions.md`（表の書式。直近の行の「何を」の末尾に `（D-20261010-async-agent-wait）` のように設計文書 ID を付けている）
- `docs/vault-spec.md`・`docs/install.md`・`docs/runbook.md`（既に書かれている決定を重ねて書かないため）

## 成果物
- `docs/decisions.md`（主な成果物。行を追記する）
- `vault/designs/D-20261010-base-branch-config.md`（削除）

## 受け入れ基準
- `test ! -e vault/designs/D-20261010-base-branch-config.md` の終了コードが0
- `grep -rn --exclude-dir=.git --exclude-dir=plans --exclude-dir=tasks --exclude-dir=log --exclude-dir=verdicts --exclude-dir=worktrees 'vault/designs/D-20261010-base-branch-config' .` の出力が空
- ``grep -cE '^\| 20[0-9]{2}-[0-9]{2}-[0-9]{2} \| .*(専用の設定ファイルは作らない|`HARNESS_PUSH_BRANCH` 上の直接コミットはフックで拒否しない|`origin/<ベースブランチ>` の fetch はしない|GitLab のターゲットブランチは指定しない).*（D-20261010-base-branch-config） \| .+ \|$' docs/decisions.md`` の出力が `4`
- 追記した行の「なぜ」の列が、設計文書の決定事項の「なぜ」（または「今回やらないこと」の理由）に沿っている（ファイルを読んで確かめる）
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<数> fail=0` の形である

## 決定済み
- 追記は `docs/decisions.md` の表の末尾に、1件1行で4行以上。日付は `TZ=Asia/Tokyo date '+%Y-%m-%d'` の値。「何を」の列の末尾に `（D-20261010-base-branch-config）` を付ける（全角の括弧）。既存の行は変えない
- 必ず入れる4行と、その行の「何を」に入れる文言（この文言をそのまま書く）：
  - 設定は環境変数 `HARNESS_BASE_BRANCH`・`HARNESS_PUSH_BRANCH` で持ち、`専用の設定ファイルは作らない`（なぜ：既存の `HARNESS_MAX_ATTEMPTS` などと同じパターンにそろえ、読む規則（優先順位）を増やさない。人の選択）
  - `` `HARNESS_PUSH_BRANCH` 上の直接コミットはフックで拒否しない ``（フック (b) はベースブランチと `main` だけを拒否する）（なぜ：人の選択。push 先ブランチ上ではそもそも作業しない運用で足りる）
  - `/plan`・`/design` の開始条件はローカルの `<ベースブランチ>` の ref と比べ、`` `origin/<ベースブランチ>` の fetch はしない ``（なぜ：クラウドセッションはベースと同一コミットの指定ブランチ上で始まるので、ローカルの ref と内容が同じなら安全に切れる。違うコミットなら他の作業が乗っている可能性があるので止める）
  - `vcs_finish.sh` の GitLab の経路では `GitLab のターゲットブランチは指定しない`（`--target-branch` を `HARNESS_BASE_BRANCH` で指定しない。glab の既定＝リポジトリの既定ブランチに任せる）（なぜ：設計で対象外にした。必要になれば別途）
- 上の4行の文言は、受け入れ基準の grep に当たるよう、バッククォートの位置も含めてそのまま書く（例：`` `HARNESS_PUSH_BRANCH` 上の直接コミットはフックで拒否しない ``、`` `origin/<ベースブランチ>` の fetch はしない ``）。`docs/decisions.md` は ref-1 の検査対象ではないが、存在しないパスをバッククォートで書かない
- ほかの決定事項（値の空白の扱い・既定値、フック (b) がベースと `main` の両方を拒否、push は毎回で force しない、none は push 先を見ない、ローカルのブランチ名と transition.py は変えない、`env HARNESS_PUSH_BRANCH=…` で渡す、フェーズ分け）は、T-01〜T-03 とフェーズ1の後の `docs/vault-spec.md`・`docs/install.md`・`docs/runbook.md` に書かれていれば追記しない。書かれていないものがあれば同じ書式で追記してよい
- 設計文書の削除は `git rm vault/designs/D-20261010-base-branch-config.md` で行ってよい（`vault/designs/` は差分ゲートの禁止対象ではなく、成果物に宣言してある）
- 受け入れ基準の grep の除外：`plans`・`tasks`・`log`・`verdicts` は計画一式（この計画の計画票・タスク票は設計文書のパスを書いており、run の手順7で PR の前に除去される）、`worktrees` は `.claude/worktrees/` にある他の creator の作業コピー、`.git` は履歴。`docs/decisions.md` の行は `vault/designs/` を付けずに設計文書 ID だけを書く（パスで書くと grep に当たる）
