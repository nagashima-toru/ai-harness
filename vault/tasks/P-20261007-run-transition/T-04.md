## 決定済み
- 呼び出しの文字列は T-01 の早見表の6・7と同じ形を使い、`<補足>` だけを次の文面に置き換えて書く（補足の文面は今の手順書のもの。D-012 の決定済み）。1つの呼び出しは1行に1回だけ書き、同じ補足の呼び出しを2回書かない（基準2・3の数が合うように）
  - review の行・worktree が無い・上限未満：`python3 scripts/transition.py <計画ID> <id> doing --no-model --note "worktree が無いため作り直し"`（review→doing。attempt+1）→ 手順3から creator を呼び直す
  - review の行・worktree が無い・上限：`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --no-model --note "worktree が無いため"`（question は「再開時に記録された worktree が無い（パス）」）
  - doing の行・上限未満：`python3 scripts/transition.py <計画ID> <id> doing --no-model --note "中断から再開"`（doing→doing。attempt+1）→ 手順3から creator を呼び直す
  - doing の行・上限：`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --no-model --note "中断が上限に達した"`（question は「中断が続き attempt が上限に達した」）
  - creator のハング・上限未満：`python3 scripts/transition.py <計画ID> <id> doing --no-model --note "creator呼び出しハングにより再試行"`
  - creator のハング・上限：`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --no-model --note "creator呼び出しハング"`（question は「creator 呼び出しがハングした（応答無し、強制終了で復旧）」）
  - verifier のハングが2回に達した：`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --no-model --note "verifier呼び出しハング"`（review→blocked。question に「verifier 呼び出しがハングした」ことと worktree のパス）
- 上限の判断は run が行う（`--worktree` 無しの transition.py は上限を超える doing を終了コード1で拒否するだけで、blocked には切り替えない）。今の手順書どおり「attempt が上限未満なら doing、達していれば blocked」と書く
- 質問文は Write ツールで一時ファイル（例：`/tmp/<計画ID>-<id>-question.txt`）に書き、`--question-file` で渡す（早見表に書いた規則と同じ）
- review の行の再開：log のその id の最後の記録行（`- <日時> <id> worktree path=<パス> branch=<ブランチ名> plan_head=<sha>`）から worktree・branch・`PLAN_HEAD` を復元し、`git worktree list` にそのパスがあれば手順5へ進む、という今の説明は残す（記録行は transition.py の review・blocked が書く。この記録行の書式を書くのはよい。基準1の grep は `→` を含む遷移行のひな形だけを数える）。記録行が無い review の行は worktree が無い場合と同じに扱う
- doing の行の再開：記録行があり worktree が `git worktree list` に残っていれば、再試行の呼び出しの前に `bash scripts/discard_worktree.sh <パス> <ブランチ名>` で破棄してよい（blocked にする場合は破棄せず残す）。今の「手順6.4.2と同じ」の参照は手順6の番号が変わっているので、「（不採用の worktree の破棄と同じ方法）」のように番号を使わない書き方に直す
- 記録行が無く場所が分からない worktree は自動で削除せず、完了報告に `git worktree list` の出力を添えて人に知らせる、は残す
- 「以下の状態変更は、必ず log に追記してコミットしてから次へ進む」は「状態の変更は transition.py の呼び出しで行う（log の追記とコミットも transition.py が行う）。終了コードが0でなければ早見表の表のとおり」に直す
- 「ハング時の復旧」：応答なしの目安（15分）・TaskStop で止めるのは人や運用者の役目、の説明は残す。creator のハングは「`bash scripts/discard_worktree.sh <worktree> <branch>` で破棄 → 上限未満なら再試行の呼び出し、上限なら blocked の呼び出し」。今の「手順6.3.2の FAIL 再試行パターンと同様の破棄方法」の参照は番号を使わない書き方に直す。verifier のハングは worktree を残し、ハング再試行の回数（attempt とは別）が2回に達したら blocked の呼び出し
- 「いずれの場合も…既存の書式（`- <日時> <id> <遷移> attempt=<n> 補足`）で追記し、補足に「ハング」の語を含める」は「補足（`--note`）に「ハング」の語を含める」に直し、log の行のひな形は消す
- 「無人実行（cron・CI）の場合」の段落は、「log への追記は次回の `/run` のオーケストレーターが再開手順の中で行う」を「次回の `/run` が再開手順の中で transition.py で行う」に直す程度にする。`python3 scripts/run_unattended.py`・`HARNESS_RUN_TIMEOUT`・終了コード124 の説明は変えない
- 「status を」「attempt を +1」の言い回しを手順2の2と「ハング時の復旧」に書かない
- 手順2の3〜6（T-01 で置き換え済み）・手順3〜8・早見表・「回帰確認」・「注意」はこのタスクでは変えない
- 「終了コード」の表（行頭が `| <数字> |` の行）を作らない
- `scripts/smoke.sh`・`scripts/transition.py`・`docs/vault-spec.md`・`.claude/agents/verifier.md` は変えない
