## 決定済み
- `validate_verdict(verdict, expected_task, task_path)`：今の `stop_gate.py` の `validate_verdict` を引数の形・判定・文言を変えずに `_hooklib.py` へ写す（問題の説明のリストを返し、空なら正常）。`H.count_criteria` の呼び出しは同じモジュール内の `count_criteria` にする
- `stop_gate.py`・`plan_guard.py` はこのタスクでは変更しない。`stop_gate.py` の `validate_verdict` の削除と切り替えは T-03 で行う（T-01〜T-03 の間だけ定義が2つあってよい）
- `done_rows_without_pass(root, plan_id, tasks)`：
  - `tasks` は `parse_tasks` の戻り値（dict のリスト）。status が `done` の行だけを、`tasks` の順に検査する。done 以外の行は見ない
  - 戻り値は `[(id, 理由), ...]`（問題の無い行は含めない。全部問題無ければ `[]`）
  - verdict は `os.path.join(root, "vault", "verdicts", plan_id, id + ".json")`、タスク票は `os.path.join(root, "vault", "tasks", plan_id, id + ".md")`
  - 検査の順と理由の文言（最初に当たったもの1つだけを理由にする）：
    1. ファイルが無い → `verdict がありません`
    2. JSON として読めない、または JSON がオブジェクトでない → `verdict を JSON として読めません`
    3. `task` が `<plan_id>/<id>` でない → `verdict の task が <verdict の task の値> です`
    4. `str(verdict の attempt)` がタスク表の attempt の文字列と違う → `verdict の attempt が <verdict の attempt の値> です（タスク表は <タスク表の attempt>）`
    5. `str(result).upper()` が `PASS` でない → `verdict の result が <verdict の result の値> です`
    6. `validate_verdict(verdict, "<plan_id>/<id>", タスク票のパス)` が問題を返す → `verdict の形式が不正です: <問題を "; " でつないだもの>`
  - 例外を外に出さない（読めない時は上の理由にする）。ファイルへの書き込み・標準出力への出力をしない（モジュールの冒頭の方針どおり）
- フックへの組み込み（ブロック理由の文面・検査の位置）は T-03・T-04 で行う。このタスクでは関数だけを足す
- docstring は日本語で、上の仕様（対象・戻り値・理由の順）を短く書く。モジュール冒頭の docstring は変えなくてよい
- フィクスチャ（`vault/tasks/P-20261007-done-verdict-check/fixtures/`）は変更しない。基準3の期待値は、フィクスチャに上の仕様を当てた結果として planner が確かめてある
