## 決定済み
- 小節の見出しは `### worktree への委譲の範囲` とし、`### サンドボックス（OS による書き込みと通信の制限）` の直前（「**フックの共通モジュール**」の段落の後）に置く
- 本文に次の4つの文をそのまま含める（基準2〜5の grep のため。前後に説明を足してよいが、文字列は1回だけ使う）
  - `書き込み対象がすべて委譲先の worktree の中にある時だけ委譲する`
  - `書き込み対象が無い呼び出し（読み取りだけ）は今どおり委譲する`
  - `絶対パスの書き込み対象はメインリポジトリのルート基準でも見る`
  - `` `plan_guard.py`・`stop_gate.py` の委譲は今どおり（書き込み対象を見ない） ``
- 書く内容（T-01 の決定済みと実装に合わせる。食い違えば実装を正とする）
  - 目的：creator が worktree のフックを書き換えても、書き換えたフックが worktree の外（メインリポジトリ・`~/.claude/projects/` など）への書き込みを判定しないようにする。worktree の中の作業は開発中のフックで判定する（D-008 の目的）は保つ
  - 判定は `agent_write_guard.py` の `writes_inside_worktree` が `H.delegate_to_worktree` を呼ぶ前に行う
  - 書き込み対象の求め方：Write 系は `file_path`、Bash は `bash_write_targets` の全ての target（解析できない時は和集合の候補）。`~` は展開し、相対パスは payload の `cwd` を基準にし、`os.path.realpath` で比べる
  - 委譲しない場合：worktree の外のパスが1つでもある（`/dev/null`・`/tmp` を含む）、`legacy-unknown`（対象を特定できない）、`gh api`／`curl` による `vault/rules/` のリモート直叩き
  - `vault/rules/` 拒否では、cwd が worktree の時も root は worktree のルートになるため、絶対パスの書き込み対象はメインリポジトリのルート（`CLAUDE_PROJECT_DIR`、無ければフックのファイルから求めた git のルート）基準でも見る
  - 既知の残り：creator の `vault/plans/`・`vault/log/` 拒否は、worktree から絶対パスでメインリポジトリを指す場合を見ていない（この計画の範囲外）
- 12節の判定表の行・列、ほかの小節の文言は変えない。9節（240行目付近）の stop_gate の判定順の記述も変えない
- `docs/` のほかのファイル・`README.md` は変えない
