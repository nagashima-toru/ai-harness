# T-0011 agent_write_guard.py に doing/review 中の vault/rules/ 書き込み拒否を追加する

## 目的
`doing`/`review` 中のタスクがある間、作成エージェントがタスク中に `vault/rules/` を書き換えて verifier の判定基準を自分で緩めることを、エージェント種別を問わずフックで機械的に防ぐ。

## 入力
- `.claude/hooks/agent_write_guard.py`（現状の ALLOWED 判定・BASH_WRITE_PATTERNS・normalize/deny の実装）
- `.claude/hooks/todo_guard.py`（`raw_rows`/`parse_tasks` の todo.md 解析規則。コピー元）
- `scripts/smoke.sh`（`== agent_write_guard.py ==` 節の既存ケースと `run_guard`/`expect_guard` ヘルパー）
- `docs/vault-spec.md`（「10. Stop フックの判定」「11. todo_guard フックの判定」の書き方。新節はこれに揃える）
- `docs/roadmap-rules-extension.md` の「## ⑥ 改ざん防止フック（agent_write_guard.py 拡張）」節（詳細設計・受け入れ基準の候補・決定済みの参考）

## 成果物
- `.claude/hooks/agent_write_guard.py`（新判定を追加。既存の verifier/planner 向け ALLOWED 判定は変更しない）
- 付随：`scripts/smoke.sh` の `== agent_write_guard.py ==` 節にケース3件追加、`docs/vault-spec.md` に新判定の説明節を1つ追記

## 受け入れ基準
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含み、pass 件数が拡張前より3以上増えている（新規ケース3件分。既存ケースは壊れていない）
- doing 中に `agent_type` 無し（メインエージェント）で `vault/rules/` 配下へ Write すると deny になる（smoke 新規ケース(a)）
- doing/review の行が無い todo.md でメインエージェントが `vault/rules/` 配下へ Write すると allow になる（smoke 新規ケース(b)）
- doing 中に verifier が `vault/verdicts/` へ Write すると従来どおり allow になる（smoke 新規ケース(c)。既存の verifier/planner 向け判定が壊れていないことの確認）
- `docs/vault-spec.md` に新判定の説明節がある（`grep -c 'agent_write_guard' docs/vault-spec.md` が既存の1件より増える）

## 決定済み
- 新判定は「既存の ALLOWED 判定より前」に実行する。verifier・planner が `vault/rules/` に書こうとした場合も doing/review 中ならこの新判定で先に deny されてよい（二重に拒否されても実害は無い）
- todo.md 解析ロジックのコピーは、`todo_guard.py` が `stop_gate.py` から同種のロジックをコピーした前例と同じやり方でよい（import はしない。`raw_rows` 相当の「## タスク」表パースだけをこのファイル内に持てば十分。全カラムの厳密な dict 化までは不要で、status 列を見て doing/review の有無と id を拾えればよい）
- Bash コマンドの書き込み判定は既存の `BASH_WRITE_PATTERNS` をそのまま再利用してよい。対象パスの抽出（リダイレクト先）も既存の正規表現を流用する
- `vault/rules/` 配下かどうかの判定は既存の `normalize()` を使い、`rel.startswith("vault/rules/")` で判定する
- todo.md が存在しない、または「## タスク」表に doing/review の行が無い場合は、この新判定は何もせず既存の ALLOWED 判定（agent_type が ALLOWED に無ければ何もしない）に進む
- reason 文言には「doing/review 中は vault/rules/ を編集できません」と対象タスク ID（複数なら列挙）を含める
- smoke.sh の新規3ケースは既存の `run_guard`/`expect_guard`/`make_todo` ヘルパーを流用し、todo.md の用意には `make_todo` を使ってよい（`make_todo` は id/status/attempt を受け取り単一行の todo.md を作る）
- 対象ツールは Write/Edit/MultiEdit/NotebookEdit（file_path 判定）と Bash（既存パターンの拡張）。他のフック（stop_gate.py・todo_guard.py）は変更しない

## 進捗
- `bash scripts/rules.sh creator` を実行（着手時のルール読み込み手順）。出力は空だったため何もしていない
- `.claude/hooks/agent_write_guard.py` に `active_doing_review_task_ids()`（todo_guard.py の raw_rows と同規則を自己完結でコピー）と `targets_vault_rules()`（Write系はパス判定、Bashは既存BASH_WRITE_PATTERNS一致＋リダイレクト先/`vault/rules/`パス断片の抽出で判定）を追加。`main()` の先頭、既存 ALLOWED 判定より前に新判定を挿入
- `scripts/smoke.sh` に (a)(b)(c) の3ケースを追加（既存 `make_todo`／`run_guard`／`expect_guard` ヘルパーを流用）
- `docs/vault-spec.md` に「## 13. agent_write_guard フックの改ざん防止判定」を新設（表形式）。既存の「### 改ざん防止」小節からもリンク
- 受け入れ基準5件の確認コマンドをすべて実行し通過。`bash scripts/smoke.sh` は pass=40 fail=0（既存37件から+3）、`grep -c 'agent_write_guard' docs/vault-spec.md` は3（既存1件から増加）
