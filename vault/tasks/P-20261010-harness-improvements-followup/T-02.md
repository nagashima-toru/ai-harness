# T-02 agent_write_guard の main 上の git commit の拒否を各部分の先頭だけにし smoke にケースを足す

## 目的
`.claude/hooks/agent_write_guard.py` の判定 (b)（`main` 上の `git commit` の拒否）が、`grep -n "git commit" ...` のような読み取りや引用符の中の文字列まで拒否する誤検知を無くす。コマンドを区切った各部分の先頭が `git commit` の時だけ拒否する。

## 入力
- `.claude/hooks/agent_write_guard.py`（`GIT_COMMIT_PATTERN`・`GIT_PREOPT_COMMIT_PATTERN`・`is_git_commit_command`・冒頭の docstring）
- `scripts/smoke.sh` の `== agent_write_guard.py ==` 節（`(guard3-b)` のケースと、`$GTMP` の `main` のリポジトリの作り方）
- `docs/vault-spec.md` 12節の (b) の行（文書の更新は T-06 が行うので、このタスクでは変えない）

## 成果物
- `.claude/hooks/agent_write_guard.py`（主な成果物）
- `scripts/smoke.sh`（agent_write_guard.py の節のケース）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- 足した7ケース（読み取り・引用符の中は許可、`||`・`|`・`git` のオプションを挟む形は拒否）がすべて通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard-b2-[1-7])'` の出力が `7`
- 今ある (b) のケース（`git commit`・`&&`・`;`・改行・`git -C . commit` の拒否と、work ブランチの許可）が今のまま通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard3-b)'` の出力が `7`
- 文字列の正規表現による判定が無くなっている。確認：`grep -c 'GIT_COMMIT_PATTERN\|GIT_PREOPT_COMMIT_PATTERN' .claude/hooks/agent_write_guard.py` の出力が `0`

## 決定済み
- 判定の手順（`is_git_commit_command(cmd)` の中身を置き換える。関数名は変えない）：
  1. コマンドを先頭から1文字ずつ見て、引用符（`'...'`・`"..."`。`"` の中の `\"` は引用符の終わりにしない）の外にある `&&`・`||`・`;`・`|`・改行で区切る。引用符の中の区切り文字では区切らない
  2. 各部分を `shlex.split` で語に分ける（`ValueError` の時は空白で分ける）。語が無い部分は飛ばす
  3. 先頭の語が `git`（`os.path.basename` が `git` のもの。`/usr/bin/git` も含む）でなければその部分は対象外
  4. 2つ目以降の語のうち `-` で始まるものを `git` のオプションとして読み飛ばす。`-C`・`-c`・`--git-dir`・`--work-tree`・`--namespace`（`=` を含まない形）の時は、その次の語も値として読み飛ばす
  5. 読み飛ばした後の最初の語が `commit` なら True。どの部分も当たらなければ False
- 見ないもの（D-015 の「簡単な判定」の範囲。拒否しない）：`env`・`VAR=値` の前置き、`bash -c "..."` の中、サブシェル `( )`・`$( )`・バッククォートの中、単独の `&`
- `GIT_COMMIT_PATTERN`・`GIT_PREOPT_COMMIT_PATTERN` の定数は消す。`re` の import はほかで使っているので残す。`shlex` を import する
- 冒頭の docstring の (b) の説明と `is_git_commit_command` の docstring を、上の判定（区切った各部分の先頭が `git commit` の時だけ。引用符の中は見ない）に直す
- 拒否の文言（`main への直接コミットはできません…`）、ブランチの判定（`main` の時だけ、取れなければ素通り）、(a)(c) の判定、worktree への委譲は変えない
- 足すケース（`$GTMP` の `main` の上で、今の `(guard3-b)` と同じ呼び方。名前は `(guard-b2-<番号>)` で始め、1ケース1行の `ok`/`NG` を出す）：
  - `(guard-b2-1)` `grep -n "git commit" scripts/smoke.sh` → 許可
  - `(guard-b2-2)` `echo 'a; git commit -m x'` → 許可（引用符の中の区切り）
  - `(guard-b2-3)` `git log --grep commit` → 許可（サブコマンドが commit でない）
  - `(guard-b2-4)` `true || git commit -m x` → 拒否
  - `(guard-b2-5)` `true | git commit -m x` → 拒否
  - `(guard-b2-6)` `git -C /tmp/x commit -m x` → 拒否
  - `(guard-b2-7)` `git -c user.name=a commit -m x` → 拒否
- `(guard3-b)` の今の7ケースは名前・期待値を変えない。名前が `(guard-b2-` で始まるケースは上の7つだけにする
- `docs/vault-spec.md` 12節の更新は T-06 が行う
