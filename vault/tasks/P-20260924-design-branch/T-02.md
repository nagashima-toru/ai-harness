# T-02 design スキルにブランチ作成・コミット・PR 提示手順を追記する

## 目的
`.claude/skills/design/SKILL.md` の手順に、`main` ブランチ確認 → `design/d-xxx` ブランチ作成 →（書
いた後の）コミット → PR 提示までの運用を追記し、「フェーズに分ける」の受け入れ基準の候補の説明に単
体マージでの動作完結保証という基準を明記する。

## 入力
- `.claude/skills/design/SKILL.md`（現状）
- `.claude/skills/plan/SKILL.md`（手順2〜3。`main` 確認 → `work/...` 作成の既存パターン）
- `vault/rules/common/git.md`（ブランチ・コミット・PR 運用の共通ルール）
- 本タスク票の「決定済み」

## 成果物
- `.claude/skills/design/SKILL.md`（この1ファイルのみ）

## 受け入れ基準
- 手順の中に `main` ブランチ確認と `design/d-xxx` ブランチ作成が追加されている。確認コマンド：
  `grep -cF 'design/d-xxx' .claude/skills/design/SKILL.md` の出力が1以上
- 手順5「書く」の後に、設計文書をコミットする手順が追加されている。確認コマンド：
  `grep -cF 'コミットする' .claude/skills/design/SKILL.md` の出力が1以上
- 「提示して止まる」手順に、人が `gh pr create` で PR を作りレビュー後に `main` へマージする運用が
  追記されている。確認コマンド：
  `grep -cF 'gh pr create' .claude/skills/design/SKILL.md` の出力が1以上
- 「フェーズに分ける」の受け入れ基準の候補の説明に、そのフェーズが単体で `main` にマージされてもシ
  ステムが動作する状態を保証する旨が追記されている。確認コマンド：
  `grep -cF '単体で' .claude/skills/design/SKILL.md` の出力が1以上
- 既存の手順見出し語（調査する / 人に聞く / 決定事項を固める / フェーズに分ける / 書く / 提示して止
  まる）がすべて残っている。確認コマンド：
  `for w in 調査する 人に聞く 決定事項を固める フェーズに分ける 書く 提示して止まる; do grep -qF "$w" .claude/skills/design/SKILL.md || echo "missing:$w"; done`
  の出力が空

## 決定済み
- ブランチ作成の追記位置は既存の手順1の前（新しい手順として先頭に挿入し、既存の1〜6を繰り下げてよ
  い）。文言例：「現在のブランチが `main` であることを確認する（`main` でなければブランチを切らず
  『`main` に戻ってから `/design` を実行してください』と伝えて止まる）。`main` なら
  `git checkout -b design/d-xxx` でブランチを作る（`xxx` は採番する D-ID の3桁を小文字化したもの。
  例：D-002 → `design/d-002`）」
- コミット手順の追記位置は既存の手順5「書く」の直後（新しい手順として挿入し、既存の6「提示して止ま
  る」をさらに繰り下げてよい）。文言例：「`vault/designs/D-xxx.md` を git add してコミットする
  （`design/d-xxx` ブランチ上のため `main` 直接コミット拒否には引っかからない）」
- 「提示して止まる」への追記文言例：「人がこの設計文書をレビューし、`gh pr create` で PR を作って
  `main` にマージしてから、フェーズ1のゴール文を `/plan` に渡す運用にする、と伝える」
- 「フェーズに分ける」の`受け入れ基準の候補`説明への追記文言例：「そのフェーズだけが単体で `main`
  にマージされてもシステムが動作する状態を保証する内容にする」
- `planner` サブエージェントは呼ばない、`vault/todo.md` に何も登録しない、といった既存の「注意」節の
  内容は変更しない
- `.claude/skills/plan/SKILL.md` 自体は変更しない（この計画のスコープ外）
