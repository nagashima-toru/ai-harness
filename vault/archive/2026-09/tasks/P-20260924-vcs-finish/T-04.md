# T-04 vault-spec.md の done 定義と設計文書のブランチ・PR 節を vcs_finish.sh 経由の記述に更新する

## 目的
`docs/vault-spec.md` の計画票 `status: done` の定義（4節）と、設計文書のブランチと PR の節（13節）
にある `gh pr create` 前提の記述を、`scripts/vcs_finish.sh` 経由の記述に更新する。

## 入力
- `docs/vault-spec.md` 4節（計画票の形式・`status` の意味の表と本文）、13節「ブランチと PR」
- `vault/tasks/P-20260924-vcs-finish/T-01.md`「決定済み」（`scripts/vcs_finish.sh` の呼び出し方の契約）
- `vault/designs/D-005.md`（決定済み）

## 成果物
- `docs/vault-spec.md` の更新（この1ファイルのみ）

## 受け入れ基準
- `docs/vault-spec.md` に `gh pr create` という文字列が残っていない。確認:
  `grep -c "gh pr create" docs/vault-spec.md` が0
- 4節の `done` の説明に `scripts/vcs_finish.sh` を実行済みという趣旨の記述がある。確認:
  `sed -n '/^## 4\./,/^## 5\./p' docs/vault-spec.md | grep -c "vcs_finish.sh"` が1以上
- 13節の「ブランチと PR」節にも `scripts/vcs_finish.sh` を使う旨の記述がある。確認:
  `grep -n "vcs_finish.sh" docs/vault-spec.md | wc -l | tr -d ' '` が2以上（4節・13節の両方に出現）
- `gh pr merge`（`glab mr merge` に触れる場合も同様）への言及はすべて「実行しない」という文脈に限ら
  れる。確認: `grep -n "gh pr merge\|glab mr merge" docs/vault-spec.md | grep -v "実行しない"` の出力
  が空
- 「マージは人が行う」という既存方針の記述は維持されている。確認:
  `grep -c "マージは人が行う" docs/vault-spec.md` が1以上

## 決定済み
- 4節の表の行「| `done` | 全タスクが `done` になり `gh pr create` 済み |」は「| `done` | 全タスクが
  `done` になり `scripts/vcs_finish.sh` を実行済み |」のように書き換える
- 4節本文「エージェントは `gh pr create` までで `gh pr merge` は実行しない」は、
  「エージェントは `scripts/vcs_finish.sh`（内部で GitHub なら `gh pr create`、GitLab なら
  `glab mr create` を呼ぶ。ホスティング無しなら人へのブランチ引き継ぎ案内を出す）までで、
  `gh pr merge`/`glab mr merge` は実行しない」のように、スクリプト経由である旨と GitLab 相当の禁止も
  明記する
- 13節「ブランチと PR」の「`gh pr create` で PR を作り」は「`scripts/vcs_finish.sh` を実行して PR/MR
  を作り（ホスティング無しの場合は案内を受け取り）」のように書き換える。「`gh pr merge` はエージェン
  トが実行しない」は「`gh pr merge`/`glab mr merge` はエージェントが実行しない」に更新する
- 2節（状態5つの表）には `gh pr create` の直接記述が無いため、修正対象は4節・13節の該当箇所のみでよ
  い
- `HARNESS_VCS_HOST` という環境変数名や `github`/`gitlab`/`none` の値の詳細な説明を vault-spec.md に
  新規で書く必要はない。詳細は `scripts/vcs_finish.sh` 自体に譲り、vault-spec.md では
  「`scripts/vcs_finish.sh` 経由で PR/MR を作成する」という参照に留めてよい
- 章番号・章立ては変えない。既存の章の中に追記・書き換えする形でよい
