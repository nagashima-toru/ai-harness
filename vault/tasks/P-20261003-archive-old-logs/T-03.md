# T-03 runbook 5節の手動手順を archive_plans.sh の手順に置き換える

## 目的
`docs/runbook.md` 5節の手動の `git mv` 手順（計画票と log、タスク票と verdict のディレクトリが同じ `vault/archive/<年-月>/` 直下で名前が衝突する）を、`scripts/archive_plans.sh` を人が実行する手順に置き換える。

## 入力
- `docs/runbook.md` 5節
- `scripts/archive_plans.sh`（T-01 の成果物）と T-01 タスク票の「決定済み」
- 計画票 `vault/plans/P-20261003-archive-old-logs.md` の「分割方針」（配置・誰が実行するか・フックとの関係）

## 成果物
- `docs/runbook.md`（5節だけを書き換える。1ファイル）

## 受け入れ基準
- 旧手順（`date +%Y-%m` を使う `git mv`）が残っていない：`grep -c 'date +%Y-%m' docs/runbook.md` の出力が `0`
- ドライランの手順がある：`grep -c 'bash scripts/archive_plans.sh --dry-run' docs/runbook.md` の出力が `1` 以上
- 実際に移す手順がある：`grep -c 'bash scripts/archive_plans.sh --apply' docs/runbook.md` の出力が `1` 以上
- 4種別の配置を1行ずつ書いている：`grep -c 'vault/archive/<年-月>/\(plans\|tasks\|verdicts\|log\)/' docs/runbook.md` の出力が `4` 以上
- 実行するのが人であることを書いている：`grep -c 'エージェント（creator を含む）は --apply を実行しない' docs/runbook.md` の出力が `1` 以上
- archive の log を明示して集計する例がある：`grep -c 'python3 scripts/model_stats.py vault/archive/\*/log/\*.md' docs/runbook.md` の出力が `1` 以上
- 見出しの数が変わらない：`grep -c '^## ' docs/runbook.md` の出力が `9`

## 決定済み
- 5節の見出し `## 5. 月次で done を archive に移す` はそのまま残す（見出しの数・順序を変えない）
- 書く内容
  - 対象：計画票が `status: done`・タスク表が全行 `done`・PR がマージ済み（`main` に `status: done` の計画票がある）の計画のうち、新しい順に `--keep`（既定5）件を残した、それより古い全部。「新しい」は log の最初の日時行の日時（同じなら計画 ID の文字列順）。現在のブランチの計画は常に残し、5件に数えない。月次でこの手順を実行する
  - 移す前に `bash scripts/archive_plans.sh --list` で移す計画 ID の一覧を確かめられる
  - 配置：4種別を1行ずつ箇条書きにする（`vault/archive/<年-月>/plans/<計画ID>.md`・`vault/archive/<年-月>/tasks/<計画ID>/`・`vault/archive/<年-月>/verdicts/<計画ID>/`・`vault/archive/<年-月>/log/<計画ID>.md`）。`<年-月>` は計画 ID の日付部分から決まる（移した日ではない）。計画 ID を渡さなければ移す対象の全部を、渡せばその ID だけを移す
  - 手順：`bash scripts/archive_plans.sh --dry-run <計画ID> ...`（または `--from-file <path>`）で確かめ、`bash scripts/archive_plans.sh --apply ...` で移し、人が `git commit` する。PR ブランチ（または人が切った作業ブランチ）の上で実行し、`main` へは PR でマージする
  - 人が実行する理由：「エージェント（creator を含む）は --apply を実行しない」の文言を、バッククォートで囲まずにこの文字列のまま書き、続けて理由（creator は `vault/plans/`・`vault/log/` に書き込めず、done のタスク票・verdict の編集も禁止されている。スクリプト経由の移動はフックが見えない経路でその禁止を回避することになる）を書く
  - 安全装置の要約（done・全行 done・`main` で done・log に日時行がある・現在のブランチの計画でない・新しい `--keep` 件に入らない・未コミットの変更が無い・移動先が無い。1件でも外れたら何も移さない。候補が `--keep` 件以下なら何も移さない）
  - 集計：`model_stats.py` の既定は `vault/log/*.md` だけで、archive は `python3 scripts/model_stats.py vault/archive/*/log/*.md` のように明示して渡す
  - 移した後のファイルは `agent_write_guard.py` の done 判定の対象外になること（フックは `vault/tasks/`・`vault/verdicts/` だけを見る）
- 「計画 ID は日付＋スラッグなので再利用の心配が無く、採番の調整は不要」の一文は残してよい
- 5節以外（1〜4節・6節以降）は変えない
- `vault/archive/2026-09/` にある旧形式（`todo.md`・`tasks/T-0024.md` など）はそのままにする旨を1行書いてよい（必須ではない）
