# T-09 archive_plans.sh が mktemp の失敗で中断し、一時ファイルを $TMPDIR の下に作るようにする

## 目的
`scripts/archive_plans.sh` の一時ファイルを `$TMPDIR`（無ければ `/tmp`）の下に作り、サンドボックスの中でも作れるようにする。作れない時は、中断の文言を出してその場で終わる（T-01 の `scripts/smoke.sh` と同じ方針）。これで smoke の archive_plans.sh のケースと、サンドボックスの中での `--list`・`--dry-run` が落ちなくなる。

## 入力
- `scripts/archive_plans.sh`（`"$(mktemp)"` は183行目の `CAND_FILE` の1か所。直後の184行目に `trap 'rm -f "$CAND_FILE"' EXIT`）
- `vault/plans/P-20261009-sandbox-friendly.md` の分割方針（「調べて分かったこと」）
- `vault/tasks/P-20261009-sandbox-friendly/T-01.md` の決定済み（同じ方針の smoke.sh の直し方。参考）

## 成果物
- `scripts/archive_plans.sh`（1ファイル）

## 受け入れ基準
確認コマンドは worktree のルートを作業ディレクトリにして実行する（verifier は `cd <worktree>` してから実行する。archive_plans.sh は作業ディレクトリの `vault/plans/` を読む）。4・5行目は、2・3行目が全部真の時だけ実行する。
- 構文が正しい：`bash -n scripts/archive_plans.sh` の出力が空で終了コードが0
- `mktemp` を直接コマンド置換で呼んでいない：`grep -cF '$(mktemp' scripts/archive_plans.sh` の出力が `0`
- 中断付きの呼び出しと関数がある：`grep -cF 'CAND_FILE="$(archive_plans_tmpfile)" || abort_tmp' scripts/archive_plans.sh` の出力が `1`、`grep -cF 'archive_plans_tmpfile() { mktemp "${TMPDIR:-/tmp}/archive_plans.XXXXXX"; }' scripts/archive_plans.sh` の出力が `1`
- 一時ファイルを作れない時は中断の文言を出す：`env TMPDIR=/nonexistent-p20261009 bash scripts/archive_plans.sh --list 2>&1 | grep -cF 'archive_plans: 一時ファイルを作れません（TMPDIR=/nonexistent-p20261009）。中断します'` の出力が `1`
- 一時ファイルを作れる時は最後まで通る：`bash scripts/archive_plans.sh --list --keep 100000 2>&1 | grep -cx 'archive_plans: 移す計画がありません'` の出力が `1`

## 決定済み
- `export LC_ALL=C`（22行目付近）の直後に、次の2行をこのとおり足す
  - `archive_plans_tmpfile() { mktemp "${TMPDIR:-/tmp}/archive_plans.XXXXXX"; }`
  - `abort_tmp() { echo "archive_plans: 一時ファイルを作れません（TMPDIR=${TMPDIR:-}）。中断します" >&2; exit 2; }`
- 183行目の `CAND_FILE="$(mktemp)"` を `CAND_FILE="$(archive_plans_tmpfile)" || abort_tmp` に置き換える。トップレベルにあるので `exit 2` でスクリプト全体が終わる。`set -e` は `||` の左側では効かないので、`abort_tmp` が必ず呼ばれる。続く `trap 'rm -f "$CAND_FILE"' EXIT` はそのまま残す
- テンプレートの名前は `archive_plans.XXXXXX` に固定する（`$TMPDIR` が未設定の時は `/tmp`）。理由：macOS の `mktemp` はテンプレートを渡さないと `$TMPDIR` を使わず `/var/folders/...` に作ろうとし、サンドボックスの中では `Operation not permitted` で失敗する（計画作成時に確認。今の版はサンドボックスの中で `--list` も通らない）
- `abort_tmp` の前に `mktemp` 自身のエラー（`mktemp: mkstemp failed on ...`）が標準エラーに出てよい（消さない）
- 候補の条件・並べ方・出力の文言・終了コードは変えない。`scripts/smoke.sh`（T-01）・`scripts/install.sh`（T-07）・`scripts/uninstall.sh`（T-08）は変えない
- 受け入れ基準5行目の `--keep 100000` は、候補を全部残す（移す対象を0件にする）ための値。`--list` で移す対象が0件の時は `archive_plans: 移す計画がありません` を標準エラーに出して終了コード0で終わる（計画作成時に、mktemp をテンプレート付きに差し替えて確認した）
- 確認に使うのは `--list` だけ（読み取りだけ）。`--apply` は実行しない（人が手元で実行するもの）。`--dry-run` も確認には使わない
- `/nonexistent-p20261009` は存在しないディレクトリとして使う（作らない）。`env` で始めるのは許可リストの `Bash(env *)` で通すため
- `bash scripts/smoke.sh` の全件の実行は、creator・verifier ともサンドボックスの中で行わない（全件は計画の run の後に人が確かめる）。2・3行目のどれかが偽なら4・5行目は実行せず偽とする
- このファイルの編集は拒否されない見込み（`scripts/` はサンドボックスの書き込み保護の対象外）。拒否された時は、別の手段で書き換えようとせず、拒否の理由を question に書いて `blocked` にする
