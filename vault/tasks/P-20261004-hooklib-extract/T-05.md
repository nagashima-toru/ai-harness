# T-05 smoke.sh に _hooklib の読み込み失敗・worktree の未コミット・__pycache__ のケースを足す

## 目的
T-02〜T-04 で入れた3つの挙動を、smoke の回帰テストとして固定する。
- `_hooklib` が壊れている時の終了コード
- worktree（`.git` がファイル）での未コミット検査
- `__pycache__` を作らないこと

## 入力
- `vault/designs/D-011.md`（フェーズ1の受け入れ基準の候補）
- `vault/tasks/P-20261004-hooklib-extract/T-02.md`〜`T-04.md` の「決定済み」（終了コード・メッセージ・`stop_hook_active` の扱い）
- `scripts/smoke.sh`
  - `expect`（block/allow 判定）と `expect_eq`（1055行目で定義）
  - stop_gate の (f)(g) ケース（未コミット検査）
  - 最終行 `echo "smoke: pass=$PASS_N fail=$FAIL_N"`

## 成果物
- `scripts/smoke.sh`（1ファイル。新しい節 `== _hooklib.py ==` の追加）

## 受け入れ基準
- smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- 壊れた `_hooklib.py` の4ケースが通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (hooklib-broken)'` の出力が `4`
- worktree の未コミット検査の3ケースが通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (stop_gate worktree)'` の出力が `3`
- `__pycache__` のケースが通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (hooklib-pycache)'` の出力が `1`
- 既存のケースを消したり書き換えたりしていない（行の追加だけ）：`git diff main... -- scripts/smoke.sh | grep -c '^-[^-]'` の出力が `0`

## 決定済み
- 追加する場所：最終行 `echo "smoke: pass=$PASS_N fail=$FAIL_N"` の直前に、新しい節 `echo "== _hooklib.py =="` を置き、そこに全ケースをまとめる（`expect_eq` が定義済みの位置で使えるようにするため）。既存の節には手を入れない
- ケース名は次の接頭辞で始める（受け入れ基準の grep が数える）。数はちょうどこの通りにする
  - `(hooklib-broken)` 4件：一時ディレクトリの `.claude/hooks/` に、`$ROOT/.claude/hooks/` の3フック（`agent_write_guard.py`・`plan_guard.py`・`stop_gate.py`）を `cp` で置く。あわせて、構文エラーを入れた `_hooklib.py`（例：`def broken(:` の1行）を書いて、次の終了コードを `expect_eq` で確かめる。どのケースも stdin は `printf` で渡し、`CLAUDE_PROJECT_DIR` は一時ディレクトリにする
    1. `agent_write_guard.py` に `{}` → `2`
    2. `plan_guard.py` に `{}` → `2`
    3. `stop_gate.py` に `{"stop_hook_active":false}` → `2`
    4. `stop_gate.py` に `{"stop_hook_active":true}`（`HARNESS_STRICT_STOP=0` を明示）→ `0`
  - `(stop_gate worktree)` 3件
    - 準備：一時の git リポジトリを作り、空コミットをする（既存の (f) と同じ `-c user.email=... -c user.name=...` の形）。`git worktree add` で worktree を作り、その中に `vault/plans/` を `mkdir -p` する
    - 実行：`CLAUDE_PROJECT_DIR=<worktree>` で `stop_gate.py`（`$STOP_HOOK`）を `$DEFAULT_STDIN` で実行する。payload に `cwd` は入れない（委譲させない）
    1. 準備した worktree の `.git` がファイルである（`expect_eq` で `[ -f "$LEAF/.git" ]` を見る。前提の確認）
    2. worktree に未コミットのファイルを置く → `expect ... block ... "未コミットの変更があります"`
    3. そのファイルを消す → `expect ... allow`
  - `(hooklib-pycache)` 1件
    - 準備：別の一時ディレクトリの `.claude/hooks/` に、`$ROOT/.claude/hooks/*.py`（4ファイル。`__pycache__` は含めない）を `cp` で置く
    - 実行：3フックをそれぞれ1回ずつ実行する（`env -u PYTHONDONTWRITEBYTECODE`、`CLAUDE_PROJECT_DIR` は一時ディレクトリ、stdin は agent_write_guard と plan_guard が `{}`、stop_gate が `{"stop_hook_active":true}`）
    - 確認：その後、一時ディレクトリの `.claude/hooks/__pycache__` が存在しないことを `expect_eq` で確かめる
- 一時ディレクトリは既存のケースと同じく `mktemp -d` で作り、節の最後で `rm -rf` と `git worktree remove -q --force` で片付ける（smoke.sh の中での片付けは既存と同じ書き方でよい）
- 終了コードは `rc=$?` で取り、`expect_eq` に渡す。標準出力・標準エラーは `/dev/null` に捨ててよい
- 既存のケースは消さない・期待値も変えない。既存の行の書き換えもしない（受け入れ基準の `git diff main...` で削除行が0）
- フック・`_hooklib.py`・docs は変更しない。新しいケースが NG になる場合は、フック側の不具合の可能性がある。その時は自分で直さず `blocked` にして、question に状況を書く
- コミットは受け入れ基準に無いので、creator はしない
