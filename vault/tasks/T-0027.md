# T-0027 `.claude/ai-harness.md` 新設とルート `CLAUDE.md` のスタブ化

## 目的
ハーネス共通ルールの本文を `.claude/ai-harness.md` に外出しし、ルートの `CLAUDE.md` をマーカー
付きの4行スタブにする。以降のタスク（merge_claude_md.py、install.sh 組み込み）が依存する形式の
契約をここで固定する。

## 入力
- 現行 `CLAUDE.md`（42行、開始時に読む順／状態遷移／質問のしかた／役割／スキル／フック／禁止の7節）
- `docs/vault-spec.md`（ハーネスの仕様の正本。ai-harness.md 側で参照する記述はそのまま残す）
- ゴールで指定されたマーカー文字列 `<!-- ai-harness:begin v1 -->` / `<!-- ai-harness:end -->`

## 成果物
- `.claude/ai-harness.md`（新規。ハーネス共通ルールの本文）
- `CLAUDE.md`（更新。マーカー+見出し+`@.claude/ai-harness.md` の4行スタブ）

## 受け入れ基準
- `.claude/ai-harness.md` が存在し30行以内である。確認コマンド: `test -f .claude/ai-harness.md && [ "$(wc -l < .claude/ai-harness.md)" -le 30 ] && echo ok`（`ok` が出る）
- `.claude/ai-harness.md` に「開始時に読む順」「状態遷移」「質問のしかた」「禁止」の4見出しが残り、「フック」見出しは無い。確認コマンド: `grep -cE '^## (開始時に読む順|状態遷移|質問のしかた|禁止)' .claude/ai-harness.md`（4）と `grep -c '^## フック' .claude/ai-harness.md`（0）
- ルート `CLAUDE.md` はちょうど4行で、1行目が `<!-- ai-harness:begin v1 -->`、3行目が `@.claude/ai-harness.md`、4行目が `<!-- ai-harness:end -->` である。確認コマンド: `wc -l < CLAUDE.md`（4）、`sed -n '1p' CLAUDE.md`（`<!-- ai-harness:begin v1 -->`）、`sed -n '3p' CLAUDE.md`（`@.claude/ai-harness.md`）、`sed -n '4p' CLAUDE.md`（`<!-- ai-harness:end -->`）
- `CLAUDE.md` の2行目が `# ` で始まる見出し行である。確認コマンド: `sed -n '2p' CLAUDE.md | grep -c '^# '`（1）
- `bash scripts/smoke.sh` が既存ケースのまま pass のみで終わる。確認コマンド: `bash scripts/smoke.sh | tail -1`（`fail=0` を含む）

## 決定済み
- 圧縮方針：「## フック」節（3行）は丸ごと削除する（README・docs/install.md に説明があり、エージェントはブロック時に理由を受け取るため不要、というゴールの決定どおり）。「## 役割」は2行に圧縮する（例：作成エージェント1行、`verifier`/`planner` をまとめて1行）。「## スキル」は1行に圧縮する（3スキル名を矢印等でつなぐ）。冒頭2行・「開始時に読む順」・「状態遷移」・「質問のしかた」・「禁止」は文言をそのまま残してよい（30行に収めるための軽微な言い回し圧縮は可）。
- ルート `CLAUDE.md` は次の4行に完全一致させる（前後に空行を付けない）：
  ```
  <!-- ai-harness:begin v1 -->
  # AI協働ハーネス 共通ルール
  @.claude/ai-harness.md
  <!-- ai-harness:end -->
  ```
  この内容は T-0028 の `merge_claude_md.py` が「src ファイルの全文＝マージするブロック」として読み込む前提になるため、これ以外の空行・コメントを付けない。
- `.claude/` 配下は `scripts/install.sh` の `find . -type f ! -name 'settings.local.json'` ループで自動的に複製対象になるため、`.claude/ai-harness.md` をパス列挙に追加する作業は不要（このタスクでは `install.sh` を変更しない）。
- 30行に収まらない場合は「状態遷移」「役割」の説明文をさらに削ってよいが、4見出し名と本文の要点（doing は常に1件・PASS かつ attempt 一致で done・質問は着手前にまとめる／決定済み優先・done のタスク票と verdict を編集しない・破壊的操作の禁止・todo.md の列順不変）は落とさない。
