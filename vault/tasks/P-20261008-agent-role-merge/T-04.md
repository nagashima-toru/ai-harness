# T-04 install.sh が標準ルール6本を配らず、--update で未編集のものを削除する

## 目的
`scripts/install.sh` が標準ルール6本（`vault/rules/common/roles.md`・`vault/rules/common/git.md`・`vault/rules/creator/creator.md`・`vault/rules/creator/git-workflow.md`・`vault/rules/verifier/verifier.md`・`vault/rules/planner/planner.md`）を複製せず、マニフェストにも記録しないようにする。`--update` では、導入先にある6本のうち既存のマニフェストのハッシュと一致する（未編集の）ものを削除し、編集済みのものは残して `note` の行で案内する。`scripts/uninstall.sh` を合わせ、smoke にケースを足す。

## 入力
- `vault/designs/D-013.md` の「フェーズ4 標準の役割定義をエージェント定義に統合する」（受け入れ基準の候補・決定済み）
- `scripts/install.sh`（`manifest_paths()`・`--update` の python ブロック・vault/ の複製ループ・マニフェストを書く python ブロック）
- `scripts/uninstall.sh`
- `scripts/smoke.sh` の「install.sh のマニフェスト」(h)(i)・「install.sh --update」(j)(k)(l)・「uninstall.sh」(q)〜(u) の節

## 成果物
- `scripts/install.sh`（主な成果物）
- `scripts/uninstall.sh`（コメントと note の文言）
- `scripts/smoke.sh`（ケースの追加と、6本を使っている既存ケースのフィクスチャの差し替え）

## 受け入れ基準
- 既存の smoke と追加したケースが全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- 決定済みの (sr-1)〜(sr-7) のケースが smoke にあり、すべて通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (sr-'` の数が7以上（あわせて Read で、決定済みの7つの観点がケースになっていることを確認）
- smoke は、このリポジトリの6本の有無に左右されない：`grep -nE 'ROOT/vault/rules/(common|creator|verifier|planner)/' scripts/smoke.sh` の出力が空
- 「標準4本」という古い説明が残っていない：`grep -n '標準4本' scripts/install.sh scripts/uninstall.sh scripts/smoke.sh` の出力が空
- `install.sh` の vault/ の複製ループと `manifest_paths()` に6本が無く、6本のパスは `--update` で削除の対象にする一覧（決定済みの `RETIRED_RULES`）にだけある（Read で確認）。`vault/rules/README.md` は今どおり複製とマニフェストの対象に残っている

## 決定済み
- 6本のパスは `install.sh` の中に変数 `RETIRED_RULES`（スペース区切り、リポジトリ相対パス）として固定で持つ。`$SRC` に6本があるかどうかで動きを変えない（人が6本を `git rm` した後も同じ動きにするため）
- 新規の install（`--update` なし）：6本を複製せず、マニフェストにも書かない。導入先に6本が既にあっても触れない（削除も案内もしない）
- `--update`：`RETIRED_RULES` の各パスについて、導入先にファイルがあれば次のとおりにする
  - 既存のマニフェストの `files` にそのパスの記録があり、導入先のファイルの sha256 と一致する → 削除し、`remove <パス>` の行を出す
  - それ以外（記録が無い・一致しない・マニフェスト自体が無い）→ 残し、`note  <パス> は編集されているため残しました。役割定義は .claude/agents/ にあります。不要なら削除してください` の形の行を出す（行頭は既存の note と同じ `note  `）
  - 導入先にファイルが無ければ何も出さない
- `--update` の後に書くマニフェストには6本を入れない（残した編集済みのものは利用者の資産として扱い、`uninstall.sh` の対象から外す）
- 空になった `vault/rules/<役割>/` ディレクトリは消さない（`.gitkeep` は今どおり配る）
- `uninstall.sh` の動き（マニフェストに記録があり未編集のものだけ消す）は変えない。旧版のマニフェスト（6本の記録あり）でも新版（記録なし）でもそのまま正しく動く。変えるのは冒頭のコメントと最後の `note` の文言（「標準4本以外の rules/」→「`vault/rules/` のルール」など、6本が配られなくなったことに合う形）だけ
- smoke に足すケース（名前は `(sr-<番号>)` で始める。expect_eq を使う）：
  - (sr-1) 新規 install で6本がどれも複製されない
  - (sr-2) 新規 install のマニフェストの `files` に6本が無い
  - (sr-3) 旧版の導入先（6本があり、マニフェストにそのハッシュが記録されている）に `--update` すると、未編集のものが削除され `remove <パス>` の行が出る
  - (sr-4) 同じ状況で編集済みの1本は残り、編集した行が保たれ、そのパスを含む `note` の行が出る
  - (sr-5) `--update` 後のマニフェストの `files` に6本が無い
  - (sr-6) 旧版のマニフェスト（6本の記録あり）で `uninstall.sh` を実行すると、未編集の6本は削除され、編集済みの1本と利用者が置いたルール（例：`vault/rules/common/my-rule.md`）は残る
  - (sr-7) 6本が無い導入先（新版の install 直後）で `uninstall.sh` が終了コード0で終わり、利用者が置いたルールは残る
- 旧版の導入先のフィクスチャは、smoke の中で作る。新版で install した後、6本のパスに `printf` で中身を書き、そのハッシュを python3 でマニフェストの `files` に足す。`$ROOT/vault/rules/` の6本を読んだり複製したりしない
- 6本を編集の例に使っている既存のケース（(i)・(k)・(q)）は、フィクスチャのパスを `vault/rules/README.md` に替える。期待値の意味（編集済みは上書き・削除されず、記録は src のハッシュのまま）は変えない。ケース名の中のファイル名（`roles.md`）も合わせて直してよい
- 一時ディレクトリは既存のケースと同じく `mktemp -d` で作り、後片付けも既存のケースと同じ書き方にする
- `scripts/rules.sh`・`vault/rules/`・`docs/` は変えない。`docs/install.md` の記述（標準ルールを複製する）は今回は直さない（計画票の「人への質問」1）
