# T-01 transition.py の done が、同じ組の他タスクのマージ後は計画ブランチを worktree に取り込み終了コード6で再検証に回す

## 目的
並行に作ったタスクのうち別のタスクが先に done になって計画ブランチにマージされていた時、`transition.py` の `--worktree` 付きの done が計画ブランチにマージせず、計画ブランチを worktree に取り込んで verdict を消し、終了コード6で返す（verifier を呼び直させる）。状態は review のままにする。

## 入力
- `scripts/transition.py`（`done_with_worktree`・`merge_branch`・`resume_worktree` の取り込み部分・冒頭の docstring）
- `scripts/smoke.sh`（`(transition-wt)`・`(transition-resume)` のテストと `tw_setup`・`tw_run` などの補助関数）
- `docs/vault-spec.md` 2節（worktree 運用の done・引き継ぎ）、7節（log の書式）
- GitHub Issue #212（本文はこの票の「目的」と「決定済み」に要約してある）

## 成果物
- `scripts/transition.py`（主な成果物。`--worktree` 付きの done に再検証の分岐を足す）
- `scripts/smoke.sh`（`(transition-recheck)` のテストを足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<n> fail=0` の形（fail が 0）である
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-recheck) '` の出力が `6` である（決定済みの 01〜06 のテストがすべて通る）
- `grep -c '6  再検証のため計画ブランチを worktree に取り込んだ' scripts/transition.py` の出力が `1` である（docstring の終了コードの一覧に6がある）

## 決定済み
- 背景（Issue #212）：同じ PLAN_HEAD から分岐した T-02・T-03 を並行に作ると、run の手順4の review と手順5の verifier が両方とも手順6の done より前に行われる。T-02 が先に done になって計画ブランチにマージされても、T-03 の verifier は T-02 の変更を含まない worktree で判定していて、`git grep` で旧名が残っていないかなどリポジトリ全体を見る基準が誤って PASS／FAIL になりうる。`--resume-worktree` の場合は取り込み済みで解決済み
- 方針は案A（done の時点で再検証）。状態（5つ）と遷移表（7つ）は増やさない。新しいのは終了コード6だけ
- 対象は `--worktree` 付きの done（`done_with_worktree`）だけ。`--worktree` 無しの done、review・doing・blocked・`--resume-worktree`・`--keep-attempt` の動きは変えない
- 処理の順：PASS の verdict の検査（今のまま）→ 新規コミットの判定（今のまま）→ 差分ゲート（今のまま）→ 再検証の判定（新規）→ 要らなければ今のままの計画ブランチへのマージと done、要れば下の取り込み
- 再検証の判定：メインの作業ツリー（root）で `git rev-list --count --merges --first-parent <plan-head>..HEAD` が1以上の時に再検証が要るとする。理由：計画ブランチは transition.py の状態のコミット（計画票・log のコミット。マージではない）で毎回進むので、HEAD と plan-head の比較では常に真になる。他タスクの変更は done の `--no-ff` マージでだけ計画ブランチに入る
- 取り込み：H をメインの作業ツリーの `git rev-parse HEAD` とする。H が worktree のブランチの祖先でなければ、worktree の中で `git merge --no-ff H -m "<計画ID>/<id>: 計画ブランチを取り込み"` を行う（`--resume-worktree` と同じ件名）。H が既に祖先ならマージはしない（状態のコミットに失敗した後の呼び直しでも二重に取り込まないため）。`resume_worktree` の取り込みのコードと関数にまとめてよいが、`--resume-worktree` の挙動（終了コード5・標準出力の文面）は変えない
- 取り込みが失敗した時：worktree で `git diff --name-only --diff-filter=U` で衝突ファイルを取り、worktree に MERGE_HEAD があれば `git merge --abort` で中止してから、review→blocked にする（計画票・log をコミット。今の done の blocked と同じ `finish`/`block` の経路でよい）。question は衝突ファイルがあれば `計画ブランチの取り込みで衝突したファイル: <ファイル>, ...`、無ければ `計画ブランチの取り込みに失敗した: <stderr の1行目>`。log の補足は衝突なら `マージコンフリクト`、それ以外は `マージ失敗`。worktree とブランチは残し、終了コード4
- 取り込みが成功した時（またはマージが要らなかった時）：
  - 計画票は変えない（status は review、attempt はそのまま）
  - log に、再開情報の記録行 `- <日時> <id> worktree path=<realpath> branch=<ブランチ> plan_head=<H>` と、遷移行 `- <日時> <id> review→review attempt=<n> 計画ブランチを取り込み再検証` をこの順に同じ日時で書く（`worktree_record` と `transition_line` を使う。モデル（verifier=）は付けない。`--note` があれば補足の後ろに付ける）
  - log だけを件名 `<計画ID>/<id>: review→review` でコミットする（`commit_files`）
  - コミットが成功した後で、メインの作業ツリーの `vault/verdicts/<計画ID>/<id>.json` を消す（古い worktree で判定した PASS で done にできないようにするため。verdict は done のコミットまで未追跡なので git の操作は要らない。ファイルが無ければ何もしない）
  - 標準出力に1行 `<計画ID>/<id>: review→review attempt=<n> 計画ブランチを取り込み再検証 plan_head=<H>` を出し、終了コード6で返す。worktree とブランチは残す
- 2回目の done は run が `--plan-head <H>` で呼ぶ。H..HEAD には状態のコミット（非マージ）しか無いので再検証の判定は偽になり、今のままマージと done に進む。新規コミットの判定（`--no-merges <H>..<branch>`）は creator のコミットが H から届かないので1件以上になり、差分ゲート（H と branch の2点比較）は自タスクの変更だけになる
- docstring：冒頭の docstring の「--worktree の done」の段落に再検証の分岐を書き足し、「終了コード:」の一覧の5の行の後に、行 `    6  再検証のため計画ブランチを worktree に取り込んだ（verifier を呼び直す）` を足す（この文字どおり。先頭は空白4つ、6 の後は空白2つ）
- smoke のテスト：`scripts/smoke.sh` の `(transition-resume)` のテストの後（`# --keep-attempt` の前）に、`expect_eq` を6個足す。名前の先頭はそれぞれ `(transition-recheck) 01`〜`(transition-recheck) 06`（この6個以外に `(transition-recheck)` で始まる名前を作らない）。既存の `tw_setup`・`tw_mod`・`tw_commit`・`tw_verdict`・`tw_run`・`tw_row`・`tw_logtail`・`tw_state` を使ってよい。「他タスクの done」は、計画ブランチ（`work/p-test`）から別のブランチを切ってファイルをコミットし、計画ブランチに戻って `git merge --no-ff` することで作る
  - 01：plan-head の後に他タスクのマージがある状態で PASS の done を呼ぶと、終了コード6・T-01 が `| T-01 | review | 1 |` のまま・他タスクのファイルが worktree にある・verdict ファイルが無い
  - 02：01 の後の log の最後の2行が、記録行（`plan_head=<H>`、H は呼ぶ前の計画ブランチの HEAD）と `T-01 review→review attempt=1 計画ブランチを取り込み再検証` である
  - 03：01 の標準出力が1行で `P-TEST/T-01: review→review attempt=1 計画ブランチを取り込み再検証 plan_head=<H>` である
  - 04：01 の後に PASS の verdict を置き直し、出力の plan_head で done を呼ぶと終了コード0・T-01 が done・計画ブランチに他タスクのファイルと自タスクの変更の両方がある
  - 05：他タスクのマージと自タスクが同じファイル（`src/ok.txt`）を変えていると、終了コード4・T-01 が blocked で question に `src/ok.txt` を含む・worktree に MERGE_HEAD が残らない・worktree が残る
  - 06：plan-head の後の計画ブランチのコミットがマージでない（例：`git commit --allow-empty`）だけなら、再検証に回さず終了コード0で T-01 が done になる
- 既存の `(transition-wt) 14`（計画ブランチ側の非マージのコミットとの衝突）は、マージでないので再検証の対象にならず、今のまま通る
- 確認コマンドの smoke は1分ほどかかる
