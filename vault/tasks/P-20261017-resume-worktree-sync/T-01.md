# T-01 新規コミットの判定で取り込みのマージコミットを数えず、Issue #208 の場面を smoke で確かめる

## 目的
`--resume-worktree` が worktree に計画ブランチを取り込んでできるマージコミットを、review・done の「新規コミットの判定」が creator のコミットとして数えないようにする。あわせて Issue #208 の場面（待機中に他タスクの成果物が計画ブランチに入った後の引き継ぎ）で、worktree に他タスクの変更が入り、出力の `plan_head` で review と done が通ることを smoke で確かめる。

## 入力
- `scripts/transition.py`（`count_new_commits`（429行目付近）・`review_with_worktree`・`done_with_worktree`・`resume_worktree`（706行目付近））
- `scripts/smoke.sh`（`# 26 --resume-worktree` の節（2815行目付近）と、その上の `tw_setup`・`tw_mod`・`tw_commit`・`tw_verdict`・`tw_run`・`tw_row`・`tw_rec` などの補助関数）
- `docs/vault-spec.md` 2節（review・done・引き継ぎの項。読むだけ）
- GitHub Issue #208（要旨は計画票の「分割方針」）

## 成果物
- `scripts/transition.py`（主な成果物。`count_new_commits` の1関数）
- `scripts/smoke.sh`（`(transition-resume)` の検査を 08〜11 の4件足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<数> fail=0` の形で、`fail=0` である
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-resume) [01][0-9] '` の出力が `11` である（既存の 01〜07 と新しい 08〜11 がすべて ok）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-resume) 08 取り込みのマージコミットだけ'` の出力が `1` である（引き継ぎの取り込みのマージコミットしか無い worktree の review が、新規コミット無しの blocked（終了コード 4）になる）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-resume) 1[01] 出力の plan_head'` の出力が `2` である（出力の `plan_head` からの差分が自タスクのファイルだけで、その `plan_head` で review と done が終了コード 0 になる）
- `grep -c 'rev-list.,..--count.,..--no-merges' scripts/transition.py` の出力が `1` である（新規コミットの判定がマージコミットを数えない）
- `git diff --merge-base work/p-20261017-resume-worktree-sync --name-only` の出力に `scripts/transition.py` と `scripts/smoke.sh` の両方の行がある

## 決定済み
- `count_new_commits` の `git rev-list` の行は、次の形にする（引数の順もこのとおり）：`r = run_git(root, "rev-list", "--count", "--no-merges", "%s..%s" % (plan_head, branch))`。ほかの行・エラーメッセージ・question の文面（`worktree に新規コミットが無い（マージ対象の差分が無い）`）・補足（`新規コミット無し`）は変えない。review と done はどちらも `count_new_commits` を使うので、この1行で両方に効く
- `resume_worktree` は変えない。衝突時の終了コード 5（何も変えない）・マージコミットの件名 `<計画ID>/<id>: 計画ブランチを取り込み`・成功時の標準出力の `plan_head=<H>`（状態のコミットの前の HEAD）は今のまま
- creator のマージコミットは数えなくてよい（creator は `git merge` をしない。`.claude/agents/creator.md` の `## git` 節）
- smoke の新しい検査は `(transition-resume) 07` の `expect_eq` の直後、`# 25 pr_body の件名のパターン` の行より前に置く。既存の検査（01〜07 を含む）の名前・期待値は変えない。ラベルは次の文字どおりにする
  - `(transition-resume) 08 取り込みのマージコミットだけの worktree は review で新規コミット無しの終了コード 4`
  - `(transition-resume) 09 待機中に計画ブランチへ入った他タスクのファイルが引き継いだ worktree に入る`
  - `(transition-resume) 10 出力の plan_head から worktree への差分は自タスクのファイルだけ`
  - `(transition-resume) 11 出力の plan_head を使った review と done が終了コード 0 で他タスクのファイルが計画ブランチに残る`
- 08 の手順：`tw_setup todo 0; tw_rec`（creator のコミットも未コミット分も無いまま、記録行のコミットで計画ブランチが worktree の分岐元より進む）→ `tw_run P-TEST T-01 doing --resume-worktree`（終了コード 0。worktree に取り込みのマージコミットができる）→ 標準出力から `plan_head=` の値を取り（`(transition-resume) 05` の前の `sed` と同じ取り方）、`tw_run P-TEST T-01 review --worktree "$TWW" --branch "$TWB" --plan-head <その値>` を実行する。期待値は終了コード `4` で、`tw_row` が `| T-01 | blocked | 1 |` で始まること（両方を1つの `expect_eq` で見る。例：`"4 1"` と `"$TW_RC $(tw_row | grep -c '^| T-01 | blocked | 1 |')"`）。今の transition.py ではここが終了コード 0 になり NG になる
- 09〜11 の手順（Issue #208 の場面）：`tw_setup todo 0; tw_mod; tw_commit`（blocked の前の creator のコミット）→ メインの作業ツリー（`$TWR`）に他タスクの成果物として `src/other.txt` を作ってコミットする（T-01 の「成果物」に宣言されていないファイル。中身は任意）→ `tw_rec` → `tw_run P-TEST T-01 doing --resume-worktree`
  - 09：終了コード `0` で、`$TWW/src/other.txt` がある（例：`"0 yes"`）
  - 10：出力の `plan_head` の値を P2 として、`git -C "$TWR" diff --name-only P2 "$TWB"` の出力が `src/ok.txt` と `vault/tasks/P-TEST/T-01.md` の2行だけ（`src/other.txt` を含まない）。逆向きの差分（他タスクの変更が宣言外の変更に見えること）が無いことをこれで見る
  - 11：`tw_run P-TEST T-01 review --worktree "$TWW" --branch "$TWB" --plan-head P2` が終了コード `0`、続けて `tw_verdict PASS 1` → `tw_run P-TEST T-01 done --worktree "$TWW" --branch "$TWB" --plan-head P2` が終了コード `0` で、計画ブランチ（`$TWR` の HEAD）に `src/other.txt` があり `src/ok.txt` の中身が `changed`（例：`"0 0 yes changed"` を1つの `expect_eq` で見る）
- smoke の一時ファイルは既存の `$TW` 配下を使い、`rm -rf` を足さない
- smoke 全体の実行には数分かかる（タイムアウトは10分を見込む）
