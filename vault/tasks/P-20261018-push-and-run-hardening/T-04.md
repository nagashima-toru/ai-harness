# T-04 計画の差分が `/code-review` を通過する

## 目的
T-01〜T-03 で変えた計画全体の差分を `/code-review` で確かめ、致命的な指摘があれば直す。直した後も計画全体の動作（smoke）が壊れていないことを確かめる。

## 入力
- 計画全体の差分：`git -C <worktree のパス> diff --merge-base <ベースブランチ>`
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節
- T-01〜T-03 のタスク票（`vault/tasks/P-20261018-push-and-run-hardening/`）

## 成果物
- 主な成果物：計画の差分への修正（致命的な指摘が無ければ変更なし）
- 変えてよいファイル（先行タスクの「成果物」の宣言のすべて）：
  - `scripts/vcs_finish.sh`
  - `scripts/smoke.sh`
  - `docs/vault-spec.md`
  - `.claude/skills/run/SKILL.md`
  - `.claude/agents/planner.md`
- `scripts/transition.py`（amend_task.py で追加）

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- 上流あり・先行の push の検査が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (push-9) '` の出力が `1`
- 文書のパス参照が壊れていない：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- transition.py に attempt を変えない記録の経路があり検査が通る：`bash scripts/smoke.sh 2>&1 ／ grep -c '^  ok   (tr-keep-1) '` の出力が `1`

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う
- 古い記述の検索で除外するディレクトリと理由は T-01 と同じ：`vault/`（計画票・タスク票が古い記述を引用している）、`.git`（git の内部）、`worktrees`（メインリポジトリの `.claude/worktrees/` にあるほかの worktree）

- 【人の回答（/plan unblock）】前回の `/code-review` の指摘3点（`.claude/skills/run/SKILL.md` の「Agent 呼び出しがエラーで返った時（手順3・5）」節）への回答は次のとおり。この3点は「致命的な指摘」として、この T-04 の中で直す（`docs/vault-spec.md`・`.claude/skills/run/SKILL.md`・`scripts/transition.py`・`scripts/smoke.sh` を変えてよい）
  1. 増やさない：レート制限（429）・一時的な API エラーで止めた後の再開は、attempt を増やさない
  2. 一時的なエラーだけ：レート制限・一時的な API エラーとして扱う判定語は `429`・`rate_limit`・`overloaded`・`529` に絞り、`API error` は外す。それ以外のエラーは「それ以外のエラー」（回数を数えて上限で blocked）にする
  3. 残す：エラーによる再試行の回数は log に残し、再開しても0に戻らないようにする
- 実現方法（決定済み）：
  - `scripts/transition.py` に `--keep-attempt` を足す。`doing --no-model --keep-attempt --note "<補足>"` は doing→doing で attempt を変えず log に1行足す。`review --no-model --keep-attempt --note "<補足>"`（`--worktree` 無し）は review→review で、status・attempt を変えず log に1行足す。status が合わない時、`--keep-attempt` を `doing`・`review` 以外の遷移や `--worktree` と一緒に指定した時は終了コード1か2で何も変えない。それ以外の遷移の挙動は変えない
  - レート制限で止める時（creator）：`python3 scripts/transition.py <計画ID> <id> doing --no-model --keep-attempt --note "creator呼び出しレート制限で停止"` を呼んでから人に報告して止まる。次回 `/run` の手順2.2で、`doing` の行の最後の log 行の補足が `creator呼び出しレート制限で停止` なら、attempt を増やさず `doing --no-model --keep-attempt --note "レート制限から再開"` を呼んで手順3から creator を呼び直す（`中断から再開` の attempt+1 の経路は通らない）
  - レート制限で止める時（verifier）：review のまま止まる（今までどおり。再開は手順2.2の review の経路で attempt は変わらない）
  - verifier のエラーによる再試行の回数：再試行のたびに `python3 scripts/transition.py <計画ID> <id> review --no-model --keep-attempt --note "verifier呼び出しエラーにより再試行"` で log に1行足し、その id の最後の `doing→review` 行より後ろにある同じ補足の行を数える（メモリ上のカウンタにしない）。2回に達していたら、今までどおり `verifier呼び出しエラー` の補足で blocked にする
  - 補足の新しい文字列 `creator呼び出しレート制限で停止`・`レート制限から再開`・`verifier呼び出しエラーにより再試行` を、`.claude/skills/run/SKILL.md` の新しい節（各1回ずつ）と `docs/vault-spec.md` 7節の補足の一覧（各1回ずつ）に足す。早見表（SKILL.md）には `--keep-attempt` の行を足す
  - smoke に検査 `(tr-keep-1) transition.py --keep-attempt は status・attempt を変えず log に1行足す` を足す（doing と review の両方を確かめる）。既存の検査の期待値は変えない
- 基準5（古い記述の grep）は T-01 の基準と重複するため、`(tr-keep-1)` の検査に差し替えた。古い記述が残っていないことは T-01 の verdict で確認済み

## 進捗
- 読んだルール: vault/rules/common/vision.md
- `/code-review` を1回実行（`git diff --merge-base main`、計画一式4種は除く）。指摘8件。クラッシュ・データ破損・誤った結果に当たる致命的な指摘は0件のため、成果物は変更せず、2回目の実行もしていない
  - push の毎回実行（vcs_finish.sh）、stdout の stderr 化、smoke push-9 の前提、vault-spec の文の重複、SKILL.md のエラー分類・回数管理・stop_gate の扱いは、T-01〜T-03 の「決定済み」で決めた仕様または好み・設計の話で、致命的ではないため直さない
- 確認結果: smoke 末尾 `smoke: pass=576 fail=0`、(push-9) ok 1件、(ref-1) ok 1件、'上流が無' の検索は0件
