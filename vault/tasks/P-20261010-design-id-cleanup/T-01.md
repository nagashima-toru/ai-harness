# T-01 vault-spec の設計文書 ID・ブランチ名・最終フェーズでの削除を新方式にする

## 目的
`docs/vault-spec.md`（仕様の正本）の設計文書の ID を `D-<YYYYMMDD>-<スラッグ>`・ブランチを `design/d-<YYYYMMDD>-<スラッグ>` に変え、設計文書を最終フェーズで削除する運用を13節に定める。

## 入力
- `docs/vault-spec.md` の1節の表（`vault/designs/D-001.md` の行）、3節の表（「設計文書 ID」の行）と箇条書き（「設計文書 ID だけは … 最大値 +1 で採番する」の行）、13節「設計文書（`vault/designs/`）」の全体
- この票の「決定済み」（D-016 の決定事項を転記してある。`vault/designs/D-016.md` は T-06 で消えるので、ここだけを根拠にしてよい）

## 成果物
- `docs/vault-spec.md`（1ファイル）

## 受け入れ基準
- 3節の表に `| 設計文書 ID | `D-<YYYYMMDD>-<スラッグ>` |` で始まる行がある（`grep -nF '| 設計文書 ID | `D-<YYYYMMDD>-<スラッグ>` |' docs/vault-spec.md` が1行出す）
- 13節にブランチ名 `design/d-<YYYYMMDD>-<スラッグ>` が書かれている（`grep -nF 'design/d-<YYYYMMDD>-<スラッグ>' docs/vault-spec.md` が1行以上出し、そのうち1行以上の行番号が `grep -n '^## 13\. ' docs/vault-spec.md` の行番号より大きい）
- 13節に見出し `### 最終フェーズでの削除` があり、その節に「決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する」の文がある（`grep -n '^### 最終フェーズでの削除$' docs/vault-spec.md` が1行、`grep -nF '決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する' docs/vault-spec.md` が1行以上出し、その行番号が見出しの行番号より大きい）
- 旧形式の記述が残っていない（`grep -nE 'D-xxx|d-xxx|vault/designs/D-[0-9]{3}|design/d-[0-9]{3}|最大値 ?\+1|\+ 3桁' docs/vault-spec.md` が何も出さない）
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<N> fail=0` を出す（参照切れ検査 (ref-1) を含む）

## 決定済み
- D-016 の決定事項（転記）：設計文書の ID は `D-<YYYYMMDD>-<スラッグ>`、ブランチは `design/d-<YYYYMMDD>-<スラッグ>`（ID を英小文字にして `design/` を付けたもの）。理由は、設計文書を削除すると「既存の最大値に1を足す」採番が崩れて過去の番号と衝突するため。計画 ID と同じ日付＋スラッグなら状態ファイル無しで重複しない。旧方式の最後の番号は D-016
- D-016 の決定事項（転記）：設計文書は最終フェーズで削除する。`/design` は最終フェーズの受け入れ基準に「決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する」を必ず入れる。理由は、設計文書は全フェーズを `/plan` に渡すまで `main` に要り、最後のフェーズが終われば読まれないため
- スラッグの規則は計画 ID と同じ `[a-z0-9][a-z0-9-]*`。日付は `/design` を実行した日（JST、`TZ=Asia/Tokyo date +%Y%m%d`）。採番は要らない。同じ ID の設計文書か同名のブランチが既にある時はスラッグを変える
- 1節の表の行は、パスを `vault/designs/D-<YYYYMMDD>-<スラッグ>.md` にし、内容の説明に「最終フェーズで削除する（13節）」を足す
- 3節の表の行は `| 設計文書 ID | `D-<YYYYMMDD>-<スラッグ>` | `D-20261010-plan-purge` |` とする（例の値は実在しなくてよい。`vault/` 等で始まらないので参照切れ検査の対象外）。3節の「設計文書 ID だけは … 採番する。欠番は許容、再利用は禁止」の行は、「設計文書 ID も日付とスラッグから作るので採番が要らない（13節）」の趣旨に書き換える
- 13節「ID と採番」：形式・日付・スラッグの規則・衝突時にスラッグを変えることを書く。frontmatter が `id` だけで `status` を持たないことはそのまま残す。13節冒頭の「`/design` スキルが `vault/designs/D-001.md` に書く」は `vault/designs/D-<YYYYMMDD>-<スラッグ>.md` に直す
- 13節「ブランチと PR」：`git checkout -b design/d-<YYYYMMDD>-<スラッグ>` に直し、`xxx` の説明（3桁の小文字化）を消す
- 13節に新しい小見出し `### 最終フェーズでの削除` を「`/plan` との関係」の前か後に足し、次を書く：`/design` は最終フェーズの「受け入れ基準の候補」に「決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する」を必ず入れる／削除は creator がタスクの成果物として行ってよい（成果物に `vault/designs/` を宣言する。`vault/designs/` は差分ゲートの禁止対象ではない）／設計文書を読む他のタスクの後に `after` で依存させて置く／削除までは全フェーズの `/plan` のために `main` に残す
- 旧方式の設計文書について触れる場合は「旧方式（`D-` と3桁の番号）の設計文書は D-016 フェーズ3 で削除した」程度にとどめ、受け入れ基準4の正規表現に当たる書き方（`D-xxx`・`+ 3桁`・`vault/designs/D-` に数字が続くパス・`最大値 +1` など）を使わない
- docs に残る過去の `D-0xx` への言及（例：「D-015 フェーズ2 で廃止」「D-012 フェーズ3」）は書き換えない（D-016 の決定：読み物として残す）
- 参照切れ検査（smoke の refcheck）はバッククォート内の `vault/`・`scripts/`・`docs/`・`.claude/` で始まるパスが実在するかを見る。`<` を含むパスは対象外なので、具体的な設計文書のファイル名（実在しないもの）をバッククォートのパスで書かない
- 1節・3節・13節の上に挙げた箇所以外（計画一式の除去の段落など）は変えない

## 進捗
- 読んだルール: なし（rules.sh creator は出力なし）
- docs/vault-spec.md の1節・3節・13節を決定済みどおり更新、13節に「### 最終フェーズでの削除」を追加
- 受け入れ基準5行すべて確認済み（grep 各条件OK、旧形式grepは出力なし、smoke: pass=478 fail=0）
