# T-06 smoke.sh に番号付き基準・引用符付き status・インデントした行のケースを足す

## 目的
T-01〜T-05 で寛容な側に揃えた3つの規則（番号付きの受け入れ基準を数える・frontmatter の値の引用符を外す・タスク表の行頭の空白を許す）が、フックとスクリプトを実際に動かした時に効いていることを smoke のケースで固定する。

## 入力
- `vault/designs/D-011.md`（フェーズ2の受け入れ基準の候補）
- `scripts/smoke.sh`（使える補助関数：`make_plan`・`make_plan_task`・`write_verdict`・`run_stop`・`run_plan_guard`・`expect`・`expect_eq`・`ar_init`・`ar_plan`・`ar_commit`・`ar_branch`・`ar_run`。変数：`OK_C`・`TMP`・`CURRENT_PLAN_SH`・`AR_OUT`）
- T-01〜T-05・T-08 の成果物（`.claude/hooks/*.py`・`scripts/current_plan.sh`・`scripts/archive_plans.sh`）

## 成果物
- `scripts/smoke.sh`（1ファイル）

## 受け入れ基準
- smoke が全件通り、件数が6件以上増えている：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含み、pass が513以上
- 追加した6ケースがすべて通る：`bash scripts/smoke.sh 2>&1 | grep -c 'ok   (hooklib-rules)'` の出力が `6`
- 既存の行を消していない（期待値の変更なし）：`git diff main -- scripts/smoke.sh | grep -c '^-[^-]'` の出力が `0`
- 追加した6ケースが「決定済み」の表の a〜f と1対1で対応し、それぞれの入力と期待（block/allow・部分文字列・期待値）が表のとおりである（`scripts/smoke.sh` の `(hooklib-rules)` の行を Read で読んで確かめる）

## 決定済み
- 置き場所：`== _hooklib.py ==` 節の最後（`rm -rf "$HLB" "$HPC"` の行）の後、末尾の `echo` と `echo "smoke: pass=..."` の前に、`echo "== hooklib-rules（D-011 フェーズ2） =="` の節を新しく作り、6ケースをまとめて置く。`expect_eq` は1055行目で定義されているので、stop_gate 節など前の方には置かない
- 節の最初で `$TMP` の状態を作り直す：`rm -rf "$TMP/vault/plans" "$TMP/vault/verdicts" "$TMP/vault/tasks"` してから `mkdir -p "$TMP/vault/plans"`。`$TMP` は git リポジトリではないので、stop_gate の未コミット検査には当たらない
- ケース名は必ず `(hooklib-rules) ` で始める（受け入れ基準で grep する）。各ケースは `expect`／`expect_eq` を1回だけ呼ぶ（1ケース = 1件）

| | ケース名（`(hooklib-rules) ` の後ろ） | 入力 | 期待 |
|---|---|---|---|
| a | `stop_gate: 受け入れ基準が番号付きの4行・criteria 4件の PASS → 形式不正にしない` | `make_plan_task T-0001 review 1`。タスク票 `$TMP/vault/tasks/P-TEST/T-0001.md` を printf で作り、「## 受け入れ基準」に `1. 基準1`〜`4. 基準4` の4行、続けて「## 決定済み」に `- x` を置く。`write_verdict T-0001` で task `P-TEST/T-0001`・attempt 1・result PASS・criteria に `$OK_C` を4件・reasons `[]` | `expect ... block "$(run_stop)" "verdict は PASS ですが"`（形式検査を通って「done にする」指示まで進むこと） |
| b | `stop_gate: status: "approved"（引用符付き）の計画票を approved として扱う` | verdict とタスク票を消してから `make_plan "P-TEST" '"approved"' "\| T-0001 \| doing \| 1 \| - \| A \| \|"` | `expect ... block "$(run_stop)" "verdict が無い"` |
| c | `plan_guard: status: "approved"（引用符付き）の計画票を approved として扱う` | `make_plan "P-TEST" '"approved"' "\| T-0001 \| blocked \| 1 \| - \| A \| \|"` | `expect ... block "$(run_plan_guard)" "question 列が空です"` |
| d | `current_plan.sh: id・status が引用符付き → 引用符を外した計画 ID を出す` | `$TMP/vault/plans` を作り直し、`---`／`id: 'P-CUR-Q'`／`status: "approved"`／`---` の計画票を `$TMP/vault/plans/P-CUR-Q.md` に置く | `expect_eq ... "P-CUR-Q" "$(CLAUDE_PROJECT_DIR="$TMP" bash "$CURRENT_PLAN_SH")"` |
| e | `archive_plans.sh: status: "done"（引用符付き）の計画を移す対象にする` | `ar_init ar_quoted` → `ar_plan ar_quoted P-20260101-q '"done"' done "2026-01-01 10:00"` → `ar_commit ar_quoted` → `ar_branch ar_quoted work/p-20260109-cur` → `ar_run ar_quoted --keep 0 --dry-run P-20260101-q` | `expect_eq ... "4" "$(grep -c '^git mv ' "$AR_OUT")"`（既存の (ar-1) と同じ確かめ方） |
| f | `stop_gate: 行頭を半角空白でインデントしたタスク表の doing 行を検査する` | `$TMP/vault/plans`・verdict を作り直し、`make_plan "P-TEST" "approved" "  \| T-0001 \| doing \| 1 \| - \| A \| \|"`（行頭に半角空白2つ） | `expect ... block "$(run_stop)" "verdict が無い"` |

  （表の中の `\|` は表を崩さないためのエスケープ。smoke.sh には `|` で書く）
- 節の最後で `$TMP/vault/plans`・`$TMP/vault/verdicts`・`$TMP/vault/tasks` を作り直しておく（後ろにケースは無いが、他の節と同じ後始末の形にする）
- 既存のケースの削除・期待値の変更はしない。既存のケースが落ちた場合は、自分で直さず blocked にして、落ちたケース名と原因を question に書く（D-011 は寛容側の帰結なら期待値を直してよいとしているが、PR 本文への列挙が要るので人の判断に回す）
- フック・`_hooklib.py`・scripts（smoke.sh 以外）・docs は変更しない
- コミットは受け入れ基準に無いので、creator はしない

- 人の決定による追加（2026-10-05）：T-05 で awk が値の後ろに語が続く行の先頭の語を読むようになり、T-08 で `table_counts` がインデントした行を数えるようになった。受け入れ基準の行数上限を超えない範囲で、`fixtures-comment/`（`status: approved # …`）を `current_plan.sh` が approved と読むこと、インデントした done でない行を `archive_plans.sh` が候補から外すことを、既存の基準のケースに含める形で足す。基準を増やして7行を超える場合は、1つの基準に束ねる
