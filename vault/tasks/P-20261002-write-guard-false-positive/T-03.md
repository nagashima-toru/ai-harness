# T-03 done タスク書き込み拒否の Bash 判定を analyze_bash_writes に載せ替える（#87 の連結を許可）

## 目的
done 遷移の手順で `printf '...' >> vault/log/<計画ID>.md && git add ... vault/verdicts/...` のように連結すると、`is_git_stage_or_commit_only` の除外が効かず拒否される（issue #87 の1例目）。読み取りコマンドの引数やリダイレクト先以外にある done のパス文字列でも拒否される（issue #91）。`find_done_task_write` の Bash 分岐を `analyze_bash_writes` の結果で判定し、`git add`/`git commit` は内容を変えない操作として対象から外す。done のタスク票・verdict の内容を変える書き込みは引き続き拒否する。

## 入力
- `.claude/hooks/agent_write_guard.py`（T-02 完了後の版。`analyze_bash_writes`・`find_done_task_write`・`is_git_stage_or_commit_only`）
- `vault/tasks/P-20261002-write-guard-false-positive/T-01.md` の「決定済み」（verb の種類：`git-add`・`git-commit` と `git-write` の区別）
- `scripts/smoke.sh`：既存の `(done-write)` ケース（`P-FIX` フィクスチャ：T-01=done / T-02=doing / T-03=review）
- `.claude/skills/run/SKILL.md` 手順6.3.4（読むだけ。T-05 で別に直す）

## 成果物
- `.claude/hooks/agent_write_guard.py` の `find_done_task_write` の Bash 分岐の載せ替えと、`scripts/smoke.sh` への `(bash-parse-done)` 回帰テストの追加（実装とその回帰テストで1PR分の2ファイル）

## 決定済み
- **判定**：
  - Write/Edit/MultiEdit/NotebookEdit の分岐は変えない
  - Bash は `analyze_bash_writes(cmd)` が None なら、現行の判定をそのまま使う（`BASH_WRITE_PATTERNS`、`is_git_stage_or_commit_only` による除外、`extract_bash_write_targets`＋パスらしいトークン）
  - リストが返れば、verb が `git-add`・`git-commit` の組を除いた target だけを候補にする（ステージ・コミットはファイル内容を変えないため。issue #84 の方針を引き継ぐ）。`git-write`（`git rm/restore/checkout` 等）は候補に含める
  - 候補を `normalize` して `match_task_or_verdict_path` に当て、計画票で done なら拒否する（既存のループをそのまま使う）
- **#87 の2例目**（`git commit -m "$(cat <<'EOF' … EOF)"`）は許可しない：`$(` を含むので解析不能（None）になり、従来どおり判定する。メッセージに done の verdict パスがあれば拒否される。これは案2を採らない計画の方針どおり（計画票の「分割方針」）。運用は T-05 で run/SKILL.md 6.3.4 に明記する
- 他の判定（`targets_vault_rules`・`targets_transcript_dir`・`targets_creator_denied_paths`・ALLOWED 判定・main 直接コミット拒否）と `analyze_bash_writes` 自体は変えない（main 直接コミット拒否は T-07 で行う）。`analyze_bash_writes` を変える必要が出たら `blocked` にして question に書く
- **smoke に足すケース**：既存の `(done-write)` の最後のケース（`commit メッセージ内のコマンド置換で done のタスク票へ書き込み → 拒否`）の直後に置く。`P-FIX` フィクスチャがまだある位置
  - 名前は `(bash-parse-done) <説明> → 許可` / `(bash-parse-done) <説明> → 拒否` の形にする。#87 の再現ケースだけは説明の先頭を `#87 ` にする（例：`(bash-parse-done) #87 log 追記と done verdict の git add の && 連結 → 許可`）
  - メインセッション（agent_type 無し）の Bash で、`run_guard` と 4引数版 `expect_guard` を使う。拒否ケースは4番目の引数に `done` を渡す
  - `→` は JSON の `→` で書く（既存の issue #54 のケースと同じ）
  - 許可（4件。いずれも現行コードでは拒否されることを planner が確認済み）：
    1. （#87）`printf '%s' "- 2026-10-02 10:00 T-01 review→done attempt=1 verifier=sonnet" >> vault/log/P-FIX.md && git add vault/plans/P-FIX.md vault/log/P-FIX.md vault/verdicts/P-FIX/T-01.json`
    2. `git add vault/verdicts/P-FIX/T-01.json`＋改行＋`git commit -m "P-FIX/T-01: done"`（改行区切り）
    3. `grep -n "vault/tasks/P-FIX/T-01.md" README.md > /tmp/x.txt`
    4. `cat vault/verdicts/P-FIX/T-01.json > /tmp/v.json`
  - 拒否（6件。現行でも拒否される）：
    1. `printf x >> vault/log/P-FIX.md && echo y > vault/verdicts/P-FIX/T-01.json`
    2. `git add x && git rm vault/verdicts/P-FIX/T-01.json`
    3. `git commit -m "$(cat <<'EOF'`＋改行＋`P-FIX/T-01 vault/verdicts/P-FIX/T-01.json`＋改行＋`EOF`＋改行＋`)"`（#87 の2例目。案2不採用のため拒否のまま）
    4. `git restore vault/tasks/P-FIX/T-01.md`
    5. `cp /tmp/y vault/tasks/P-FIX/T-01.md`＋改行＋`git add vault/tasks/P-FIX/T-01.md`
    6. `tee vault/verdicts/P-FIX/T-01.json < /tmp/y`
- 冒頭 docstring の「done タスクへの書き込み拒否」の段落に、「解析できた時は `git add`/`git commit` の対象を除いた実際の書き込み対象で判定する（issue #87）。解析できない形（`$(` 等）は従来の `is_git_stage_or_commit_only` を含む判定に落とす」を数行で足す
- 実装時の注意（T-01 と同じ）：
  - フックは `/tmp/P-20261002-write-guard-false-positive-T-03-guard.py` で編集し、`py_compile` を通してから `cp` で置き換える
  - `scripts/smoke.sh` は Edit/Write ツールで編集する
  - 確認コマンドが拒否される時は `/tmp/P-20261002-write-guard-false-positive-T-03-check.sh` に書いて `bash` で実行する
  - 権限分類器に拒否されたら `blocked` にする
- コミットは受け入れ基準に無いので creator は行わない
