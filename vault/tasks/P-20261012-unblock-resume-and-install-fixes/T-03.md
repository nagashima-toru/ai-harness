# T-03 stop_gate.py の creator 待ちの文言と条件を直す

## 目的
creator の呼び出しが起動通知で返り、完了通知を待つ間の停止で stop_gate がブロックした時に、待っているだけなら問題ないと分かる文言にする。あわせて、その文言を出す条件を「その id の最後の着手（`→doing` の行）より後に記録行が無い」に直し、FAIL の再試行や worktree の引き継ぎの後の待ちでも同じ文言が出るようにする（Issue #191 の3）。

## 入力
- `.claude/hooks/stop_gate.py`（`has_record_line` と、記録行の無い doing のブロック理由）
- `docs/vault-spec.md` 7節（記録行・遷移行の書式）・9節（Stop フックの判定）
- `docs/decisions.md` の 2026-10-10 の行（「`stop_gate.py` の判定は変えず、記録行の無い doing でブロックする時の理由の文面だけを…」）
- `scripts/smoke.sh` の末尾の `(async-wait-1)`〜`(async-wait-3)` のテスト

## 成果物
- `.claude/hooks/stop_gate.py`（主な成果物）
- `scripts/smoke.sh`（テストの変更と追加）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (async-wait-[1-5]) '` の出力が `5`（決定済みのテスト 1〜5 がすべて通る）
- `grep -c '待機中なら問題ありません' .claude/hooks/stop_gate.py` の出力が1以上（ブロック理由の文言）
- `git diff --merge-base work/p-20261012-unblock-resume-and-install-fixes --name-only -- .claude/hooks/stop_gate.py` の出力が `.claude/hooks/stop_gate.py`

## 決定済み
- 判定（block か allow か）は変えない。記録行の無い doing は今までどおりブロックし、変えるのはブロック理由の文言と、その文言を選ぶ条件だけ。「最初からブロックしない」案は採らない（`docs/decisions.md` の 2026-10-10 の行の人の選択「判定は変えず文面だけ」に合わせる）
- 文言を選ぶ条件：status が doing で、verdict が無いか古く、かつ `vault/log/<計画ID>.md` で、その id の `→doing` を含む遷移行（`- <日付> <時刻> <id> <旧>→doing attempt=<n> ...`）のうち最後の行より後ろに、その id の記録行（`- <日時> <id> worktree path=`）が無い時。その id の `→doing` の行が1つも無い時は、今までどおり記録行が1行も無い時とする。log が読めない時は条件に当たるものとする（今の `has_record_line` が False を返すのと同じ扱い）
- 条件に当たる時のブロック理由は、先頭の `[stop_gate] <計画ID>/<id>` の後に、creator の作業中（最後の着手の後に記録行が無い）であることと、`待機中なら問題ありません。` の文をこの文字どおり含め、続けて「creator の完了通知を待っている場合は、そのままターンを終えて通知を待ってください」の旨（`完了通知` の語を含める）と、待っていないなら creator・verifier を実行して verdict を書く旨を書く。条件に当たらない時の理由（`verdict が無い` など）は今のまま変えない
- モジュール先頭の docstring の該当の説明を新しい条件に合わせる
- smoke のテストは、`scripts/smoke.sh` の末尾の `# 記録行の無い doing の block 理由だけ完了通知の案内が付く` のブロック（`(async-wait-1)`〜`(async-wait-3)`）を直し、同じブロックの中に `(async-wait-4)`・`(async-wait-5)` を足す（ほかのタスクが別の場所にテストを足すので、このブロックの外には足さない）。番号ごとに `expect` か `expect_eq` を1つだけ書く：
  - 1：記録行の無い doing・verdict 無し・log 無し → block で、理由に `待機中なら問題ありません` を含む
  - 2：log に記録行だけがある（`→doing` の行が無い）doing・verdict 無し → block で、理由に `verdict が無い` を含み、`待機中なら問題ありません` を含まない
  - 3：review・verdict 無し・log 無し → block で、理由に `verdict が無い` を含み、`待機中なら問題ありません` を含まない
  - 4：log に記録行、その後に `T-0001 review→doing attempt=2` の行がある doing（attempt=2）・verdict 無し → block で、理由に `待機中なら問題ありません` を含む
  - 5：log に `T-0001 todo→doing attempt=1` の行、その後に記録行がある doing・verdict 無し → block で、理由に `待機中なら問題ありません` を含まない
- ほかの既存のテスト（doing・verdict 無しで block になるもの）の期待は変えない（判定を変えないので通るはず）
