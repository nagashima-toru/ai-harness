# T-01 install.sh で vault/log/.gitkeep を配り smoke で検査する

## 目的
導入先に `vault/log/.gitkeep` が配られるようにし、`scripts/purge_plan.sh` が最後の log を `git rm` しても `vault/log/` が git に残るようにする（Issue #205 の本修正）。

## 入力
- `scripts/install.sh`（146〜153行目の vault の複製。151行目の `for f in tasks/.gitkeep plans/.gitkeep verdicts/.gitkeep designs/.gitkeep ...` の列）
- `scripts/smoke.sh`（807行目からの「install.sh の CLAUDE.md 扱い」節。824〜827行目の `(inst-arch)`。`smoke_tmpdir`・`expect_eq` の使い方）
- `vault/log/.gitkeep`（このリポジトリで追跡済みの空ファイル。配る元）

## 成果物
- `scripts/install.sh`（主な成果物。複製リストへの1語の追加）
- `scripts/smoke.sh`（`(inst-log)` の検査4件の追加）

## 受け入れ基準
- `scripts/install.sh` の vault の複製リストに `log/.gitkeep` が `verdicts/.gitkeep` と `designs/.gitkeep` の間に入っている（確認：`grep -c 'verdicts/.gitkeep log/.gitkeep designs/.gitkeep' scripts/install.sh` が `1`）
- smoke に `(inst-log)` の検査が4件あり、すべて ok になる（確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (inst-log) '` が `4`）
- smoke の `(inst-log)` に NG が無い（確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  NG   (inst-log) '` が `0`）
- smoke 全体が通る（確認：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる）
- `vault/log/.gitkeep` がマニフェストの記録対象に加わっていない（確認：`grep -c 'log/.gitkeep' scripts/install.sh` が `1`。追加は151行目の複製リストの1か所だけで、`manifest_paths` には足さない）

## 決定済み
- 追加の位置：151行目の `for f in tasks/.gitkeep plans/.gitkeep verdicts/.gitkeep designs/.gitkeep templates/task.md ...` を `for f in tasks/.gitkeep plans/.gitkeep verdicts/.gitkeep log/.gitkeep designs/.gitkeep templates/task.md ...` にする（`verdicts/.gitkeep` の直後に ` log/.gitkeep` を足す。ほかの語は変えない）
- 扱いは既存の `.gitkeep` と同じ：`copy_if_absent` で配る（無ければ `copy  vault/log/.gitkeep`、あれば `skip  (exists) vault/log/.gitkeep`）。`manifest_paths` には足さない（ほかの `.gitkeep` もマニフェストに載せていない。利用者の資産のディレクトリ `vault/log/` の中身をマニフェストに載せないという既存の方針（smoke の `(h) 利用者の資産は含まれない`）とも合う）。`--update` の時も `copy_if_absent` のループは走るので、既存の導入先に `--update`（または通常の再実行）をすれば配られる
- 147行目の `mkdir -p` の行と、146・148〜150行目のコメントは変えなくてよい。151行目の直前のコメントに `.gitkeep` の説明を足すのは任意だが、`scripts/install.sh` のコメントには `log/.gitkeep` の文字列を書かない（受け入れ基準5で `log/.gitkeep` の行を数えるため。151行目の1行だけが当たるようにする）
- smoke の検査は「install.sh の CLAUDE.md 扱い」節の `(inst-arch)` の行（827行目）の直後、`rm -rf "$ITMP"` の前か後に足す。新しい一時ディレクトリを `smoke_tmpdir` で作り（例：`LGTMP="$(smoke_tmpdir)" || abort_tmp`）、節の最後で既存の節と同じく `rm -rf "$LGTMP"` で片付ける（smoke の中の片付けは既存の書き方に合わせてよい）。検査名と期待値はこの4件（名前の先頭は `(inst-log) ` で、番号は 01〜04）：
  - `(inst-log) 01 新規の install で vault/log/.gitkeep が配られる`：`bash "$ROOT/scripts/install.sh" "$LGTMP"` の後、`$LGTMP/vault/log/.gitkeep` がファイルとしてある
  - `(inst-log) 02 2回目の install で skip  (exists) vault/log/.gitkeep が出る`：同じ導入先への2回目の install の出力（`2>&1`）に、`skip  (exists) vault/log/.gitkeep` に完全一致する行が1行ある
  - `(inst-log) 03 マニフェストの files に vault/log/.gitkeep が無い`：`$LGTMP/.claude/harness-manifest.json` の `files` のキーに `vault/log/.gitkeep` が無い
  - `(inst-log) 04 vault/log/.gitkeep が無い導入先に --update すると配られる`：`$LGTMP/vault/log/.gitkeep` を `rm -f` で消してから（旧版で導入した導入先を模す）`bash "$ROOT/scripts/install.sh" --update "$LGTMP"` を実行し、出力に `copy  vault/log/.gitkeep` に完全一致する行が1行あり、ファイルがある
- smoke の出力の行頭は `expect_eq` が付ける `  ok   ` / `  NG   `（空白2つ・語・空白3つ）。検査名は上の4つをそのまま使う
- `scripts/purge_plan.sh`・`scripts/uninstall.sh`・`docs/install.md` は変えない（purge は `vault/log/.gitkeep` があれば `vault/log/` を消さない。uninstall は vault に触れない。install.md の「空ディレクトリ」の記述は `.gitkeep` があっても誤りではない）
- このリポジトリのほかに vault のディレクトリを配る経路は無い（`designs/.gitkeep` を含む複製リストは `scripts/install.sh` の1か所だけ。planner が `grep -rn 'designs/.gitkeep' scripts .claude docs` で確かめた）
