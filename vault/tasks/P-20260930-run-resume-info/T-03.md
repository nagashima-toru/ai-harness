# T-03 run SKILL.md 手順2.2の review・doing の再開手順を記録行を使う形に書き換える

## 目的
run が中断した後の再開で、review の行は記録行から worktree を復元して検証へ進み、doing の行は中断を1回の試行として数えて creator を呼び直すようにする。無人実行で同じ地点の中断が続いても、上限で blocked になって止まる（D-010 フェーズ6、issue #78）。

## 入力
- `.claude/skills/run/SKILL.md` 手順2.2（「`doing` の行があればそれを続ける…`review` の行があれば手順4へ」）
- 同 SKILL.md 手順3（T-02 で追記した記録行）、手順5、手順6.4.2（FAIL 時の破棄・作り直し）
- `docs/vault-spec.md` 7節（記録行の書式）
- `vault/designs/D-010.md` フェーズ6のゴール文と決定済み

## 成果物
- `.claude/skills/run/SKILL.md` の変更（1ファイル。手順2.2の範囲）

## 受け入れ基準
- 手順2.2に review 行の再開手順がある：その id の最後の記録行（`worktree path=` の行）から worktree のパス・ブランチ名を復元して手順5へ進む。確認：`grep -n '最後の記録行\|最新の記録行' .claude/skills/run/SKILL.md` が手順2.2の行にヒットする
- 手順2.2に、記録された worktree が `git worktree list` に無い場合の手順がある：status を `doing`、attempt を +1 にして作り直す（上限に達していれば blocked）。log の補足に理由を書く（目視で確認）
- 手順2.2に doing 行の再開手順がある：中断を1回の試行として attempt+1 にし、log に `- <日時> <id> doing→doing attempt=<n+1> 中断から再開` を追記して手順3から creator を呼び直す。attempt が上限（`HARNESS_MAX_ATTEMPTS`）に達していれば blocked にする（目視で確認）
- 記録行が無く場所が分からない worktree は自動で削除せず、完了報告に `git worktree list` の出力を添えて人に知らせる旨が書かれている。確認：`grep -n 'git worktree list' .claude/skills/run/SKILL.md` が手順2.2の範囲にもヒットする
- 変更が手順2.2の範囲に収まっている。確認：`git diff -- .claude/skills/run/SKILL.md` の `@@` 行が手順2（`## 2.` から `## 3.` の手前）に収まることを目視で確認する
- `bash scripts/smoke.sh` の最終行が `fail=0` になる

## 決定済み
- 検査対象ファイルの範囲：変更してよいのは `.claude/skills/run/SKILL.md` と、このタスク票自身（`vault/tasks/P-20260930-run-resume-info/T-03.md` の「進捗」）だけ。宣言外ファイルの変更は verifier が `git status --porcelain` で検査する（`vault/log/`・`vault/verdicts/`・計画票は run が更新するので除外）。手順3（T-02 の担当）・「ハング時の復旧」節（F7 で扱う）・`.claude/settings.json`・フックは変更しない
- 再開時に参照するのは、その id の**最後の**記録行
- doing の中断では attempt+1 にする。無人実行のラッパー（F7）が同じ地点でタイムアウトし続けても、上限（`HARNESS_MAX_ATTEMPTS`、既定3）で blocked になって止まるようにするため。log の補足は `中断から再開`
- review で worktree が `git worktree list` に無い時は、doing に戻して attempt+1 で作り直す。ここでも上限に達していれば blocked にする。log は `- <日時> <id> review→doing attempt=<n+1> worktree が無いため作り直し`（上限なら `review→blocked`）。遷移後の状態変更はコミットしてから手順3へ進む
- doing の中断時に残った worktree（記録行が無く、場所が分からないもの）は自動で削除しない。完了報告に `git worktree list` の出力を添えて、人に知らせる。記録行がある doing の worktree（前回の試行のもの）は、手順6.4.2と同じ `bash scripts/discard_worktree.sh <パス> <ブランチ名>` で破棄してから作り直してよい
- 手順2.2の既存の文「`doing` の行があればそれを続ける」は置き換える（`vault/tasks/<計画ID>/<id>.md` の「進捗」を読むのは、creator を呼び直す時に creator 自身が行うので、run 側には残さなくてよい）
- 「ハング時の復旧」節の手順は変えない。stop_gate.py・plan_guard.py は log を読まないので変更しない
