# T-04 scripts/install.sh を更新（新規3ファイルの配布対象追加 + manifest に settings_src を書く）

## 目的
T-01〜T-03 で作った `scripts/uninstall.sh` / `scripts/unmerge_claude_md.py` / `scripts/unmerge_settings_json.py` が、`install.sh`（と `--update`）で他リポジトリへ配布されるようにする。あわせて `uninstall.sh` が settings.json を逆処理できるよう、`.claude/harness-manifest.json` に `settings_src`（インストール時点の ai-harness 側 `.claude/settings.json` の内容）を書く。

## 入力
- `/home/user/ai-harness/scripts/install.sh`（`manifest_paths()`、通常の複製ループ、マニフェスト書き出しの python インラインスクリプト）
- T-01〜T-03 で実際に作られた `scripts/uninstall.sh` / `scripts/unmerge_claude_md.py` / `scripts/unmerge_settings_json.py` のファイル名・パス

## 成果物
- `scripts/install.sh`（1ファイルの更新。新規ファイルは作らない）

## 受け入れ基準
- `manifest_paths()` の列挙（`for p in ...` の一覧、または該当する `find`/追加行）に `scripts/uninstall.sh` `scripts/unmerge_claude_md.py` `scripts/unmerge_settings_json.py` の3つが含まれる。確認：`grep -n 'uninstall.sh\|unmerge_claude_md.py\|unmerge_settings_json.py' scripts/install.sh` に3行以上ヒットする
- 通常の複製ループ（`scripts/rules.sh` などを `copy_if_absent` している箇所）にも同3ファイルの `copy_if_absent` 呼び出しが追加されている。確認：同上の grep 結果に `copy_if_absent` を含む行が3行含まれる
- 一時ディレクトリに `bash scripts/install.sh <tmp>` を実行すると、3ファイルがコピーされる。確認：`test -f <tmp>/scripts/uninstall.sh -a -f <tmp>/scripts/unmerge_claude_md.py -a -f <tmp>/scripts/unmerge_settings_json.py`
- 生成される `.claude/harness-manifest.json` に `settings_src` キーがあり、その値が `install.sh` 実行時点の ai-harness 側 `.claude/settings.json` の内容（`hooks` と `permissions.deny` を含む）と一致する。確認：`python3 -c "import json; m=json.load(open('<tmp>/.claude/harness-manifest.json')); s=json.load(open('.claude/settings.json')); assert m['settings_src']['hooks']==s['hooks'] and m['settings_src']['permissions']['deny']==s['permissions']['deny']"` が例外なく終了する
- `--update` 実行時も `settings_src` が最新の ai-harness 側 `.claude/settings.json` の内容に更新される（`files` の `skip (edited)` 判定とは独立に、常に最新化してよい）。確認：`--update` を実行後、直前の確認コマンドと同じ python チェックが通ること

## 決定済み
- `settings_src` はマニフェスト書き出しの python インラインスクリプト（`MANIFEST_FILE` を書いている箇所）に `files` と並べて追加する。値は `SRC/.claude/settings.json` をそのまま `json.load` した内容でよい（丸ごと保存してよく、`hooks`/`permissions` 以外のキーが将来増えても構わない）
- `settings_src` は `files` のような「編集済みならスキップ」の対象にしない。常に ai-harness 側の最新内容で上書きしてよい（利用者は `settings_src` を直接編集する対象ではなく、`uninstall.sh` が内部で使うためだけの記録なので、据え置く理由が無い）
- 3ファイルの配布は他のスクリプト（`scripts/rules.sh` 等）と同じ扱いで良い。実行権限の付与（`chmod +x`）は不要（`bash scripts/uninstall.sh ...` の形で呼ぶため、既存の `scripts/*.sh` と同様に `+x` は付けていない）
- `docs/install.md` 冒頭の「複製するもの」一覧コメント（`install.sh` 1〜4行目のコメント）は、このタスクでは更新しなくてよい（T-05 で `docs/install.md` 本体を更新する際にまとめて見直す）
