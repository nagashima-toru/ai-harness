# T-04 .claude/agents/planner.md に「成果物」の書き方（変えるファイルをすべてバッククォートのパスで書く）を足す

## 目的
planner の定義に、タスク票の「成果物」には creator が変えるファイルをすべてバッククォートで囲んだリポジトリ相対パスで書くこと、差分ゲート `scripts/diff_gate.py`（T-01）がその宣言で何を違反にするかを書き、planner が宣言漏れ・宣言しても通らないパスの指定をしないようにする（D-012 フェーズ3）。

## 入力
- `vault/designs/D-012.md` の「決定事項」（差分ゲートの行）と「フェーズ3」の決定済み
- `.claude/agents/planner.md`（今の定義）
- `scripts/diff_gate.py`（T-01 の成果物。判定は先頭の docstring）
- `vault/tasks/P-20261007-diff-gate/T-01.md` の「決定済み」（判定の順・常に違反にする4ディレクトリ）

## 成果物
- `.claude/agents/planner.md`（節を1つ足すだけ。このファイルだけ）

## 受け入れ基準
- frontmatter が変わっていない：`head -5 .claude/agents/planner.md` の出力が `---`・`name: planner`・`description: ゴールを受け取り、粒度基準に沿って vault/plans/<計画ID>.md と vault/tasks/<計画ID>/T-01.md を draft として生成する計画エージェント。plan スキルから呼ばれる。`・`tools: Read, Grep, Glob, Bash, Write`・`model: opus` の5行
- 節の見出しが1つある：`grep -c '^## 「成果物」の書き方$' .claude/agents/planner.md` の出力が `1` で、その行番号が `grep -n '^## ' .claude/agents/planner.md` の `## 粒度の基準（必ず守る）` の行と `## 手順` の行の間にある
- 記法が書かれている：`grep -nF 'バッククォートで囲んだリポジトリ相対パス' .claude/agents/planner.md` の出力に、`末尾を `/` にする` を含む行がある
- 常に違反になるディレクトリと宣言すれば変えられるパスが書かれている：``grep -nF '`vault/plans/`・`vault/log/`・`vault/verdicts/`・`vault/rules/`' .claude/agents/planner.md`` の出力が1行以上で、``grep -nF '`.claude/hooks/`・`.claude/settings.json`・`.claude/agents/`' .claude/agents/planner.md`` の出力が1行以上
- 足した節に、決定済みの6項目（記法・`scripts/diff_gate.py` が base の版のタスク票で照らすこと・自分のタスク票は「進捗」だけ許すこと・4ディレクトリは宣言しても違反・`.claude/` の3つは宣言があれば許すこと・「成果物は1つに特定する」は変えないこと）がすべて書かれている（Read で節を読んで確かめる）
- smoke が通る（「参照される scripts の存在チェック」を含む）：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 置き場所：`## 粒度の基準（必ず守る）` の節の後、`## 手順` の前に、見出し `## 「成果物」の書き方` の節を足す。ほかの節・frontmatter は変えない
- 節に書く6項目（箇条書き。文言は下を基本にし、受け入れ基準が grep する字句はこのとおりに使う）：
  1. 「成果物」には、creator が変えるファイルをすべて、バッククォートで囲んだリポジトリ相対パスで書く。ディレクトリは末尾を `/` にする（その配下の変更をすべて許す）。例：`` - `src/foo.py`（1ファイル） ``
  2. 差分ゲート `scripts/diff_gate.py` は、base（計画ブランチ）の版のタスク票の「成果物」節にあるバッククォートの文字列を宣言として読み、creator の作業ブランチのコミット済みの差分と照らし合わせて、宣言外のファイルの変更を違反にする。creator が branch 側で宣言を書き足しても効かない
  3. 自分のタスク票は「## 進捗」節の変更だけを許す（宣言しなくてよい）。受け入れ基準などほかの節の変更は違反になる
  4. `vault/plans/`・`vault/log/`・`vault/verdicts/`・`vault/rules/` 配下は、宣言しても違反になるので成果物にしない（ルール変更は従来どおり提案ファイル `vault/tasks/<計画ID>/<id>-proposal.md` を成果物にする）
  5. `.claude/hooks/`・`.claude/settings.json`・`.claude/agents/` は、宣言があれば変えてよい（宣言が無ければ違反）
  6. 「成果物は1つに特定する」という粒度の基準は変わらない。主な成果物を1つに決めたうえで、付随して変えるファイル（フィクスチャなど）も含めて変えるファイルをすべて列挙する
- 例のパスは `scripts/` で始めない（`.claude/` 配下は smoke の「参照される scripts の存在チェック」の対象で、実在しない `scripts/<名前>.py` を書くと fail する）。`scripts/diff_gate.py` は T-01 で実在するので書いてよい
- 今の run はまだ `diff_gate.py` を呼ばない（D-012 フェーズ5で呼ぶ）。その旨を1文添えてよいが、必須ではない
- `vault/rules/planner/planner.md` は変えない（エージェントは `vault/rules/` に書き込めない。planner への指示はこのファイルに書く）。`vault/templates/task.md`（T-03）・`docs/vault-spec.md`（T-05）・`scripts/` も変えない
