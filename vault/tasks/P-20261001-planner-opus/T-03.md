- モデル名は alias（`opus`・`sonnet`）で書く。バージョン付きの ID は書かない
- `docs/decisions.md` の 2026-09-17 の行は書き換えない（判断の記録として残す）。新しい日付の行を追加し、置き換える旨を書く（これは T-01 の担当。このタスクでは触らない）
- スキルの frontmatter でのモデル指定はしない。本文の注意書きと runbook での運用とする
- creator のモデルは変えない。haiku 等への切り替えは、`model_stats.py` で十分な件数が集まってから、別の計画で行う
- verifier は「実行側」として扱う（人の回答）。`sonnet` のまま
- 書く語は「強いモデル（opus）」を必ず含める。例：「このスキルは考える工程なので、強いモデル（opus）のセッションで実行する」
- 注意書きは A（計画を作る）に限らず `/plan` 全体への注意として冒頭に置く。planner サブエージェントは agents/planner.md の model（T-05 で opus にする）で動くので、ここでは触れない
- モデルの切り替え手順そのものは書かない（運用は runbook.md の T-04 側）
- smoke.sh はこのタスクの基準に含めない（T-05 で流す）
