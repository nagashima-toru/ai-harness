# T-01 agent_write_guard.py の worktree 委譲を書き込み対象がすべて worktree の中にある時だけにする

## 目的
`.claude/hooks/agent_write_guard.py` の `main()` で、`H.delegate_to_worktree` を呼ぶのを、書き込み対象がすべて委譲先の worktree の中にある時（または書き込み対象が無い時）だけにする。worktree の外への書き込みは、メインリポジトリ側のコードで判定する。smoke にケースを足す。

## 入力
- `vault/designs/D-013.md` の「フェーズ6 worktree 委譲の範囲を絞る」（ゴール文・受け入れ基準の候補・決定済み）
- `.claude/hooks/agent_write_guard.py`（`main()`・`resolve_root`・`normalize`・`bash_write_targets`・`targets_vault_rules`・`targets_vault_rules_remote`・`is_under_transcript_dir`）
- `.claude/hooks/_hooklib.py`（`delegate_to_worktree`・`git_toplevel`。読むだけ）
- `scripts/smoke.sh`（`== agent_write_guard.py ==` の節の `(delegate)` の3ケースと、その上の委譲のテストの注記。434行目付近の `expect_guard` の再定義（第4引数で reason の部分文字列を見る形））

## 成果物
- `.claude/hooks/agent_write_guard.py`（主な成果物）
- `scripts/smoke.sh`（`(wds-N)` のケースの追加）

## 受け入れ基準
- worktree の外を書き込み対象に含む呼び出しは、委譲先が常に allow を返す差し替えでも、メインリポジトリ側の判定で拒否される（Write でメインリポジトリの `vault/rules/`・Bash でメインリポジトリの `vault/rules/` の絶対パス・Bash で `~/.claude/projects/`・解析できない Bash で候補にメインリポジトリの `vault/rules/` の絶対パス）：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(wds-[1-4]\) '` の出力が `4`
- 書き込み対象がすべて worktree の中の呼び出し（解析できない Bash で候補が worktree の中だけ）と、書き込み対象が無い呼び出し（読み取りだけの Bash）は、今どおり委譲先の判定が使われる：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(wds-[56]\) '` の出力が `2`
- 既存の委譲のケースが今どおり通る：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(delegate\) '` の出力が `3`
- `main()` で、委譲の判定の関数が `H.delegate_to_worktree` の呼び出しより前にある：`grep -nE 'if writes_inside_worktree\(tool, tool_input, payload\)|H\.delegate_to_worktree\(payload, "agent_write_guard\.py"\)' .claude/hooks/agent_write_guard.py` の出力が2行で、1行目が `writes_inside_worktree`、2行目が `delegate_to_worktree`（計画作成時点は `delegate_to_worktree` の1行だけ）
- 構文が正しい：`python3 -c "import ast; ast.parse(open('.claude/hooks/agent_write_guard.py').read()); print('ok')"` の出力が `ok`
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 委譲の判定はモジュールの関数 `writes_inside_worktree(tool, tool_input, payload)` に置き、`main()` では次の形で呼ぶ（基準4の grep のため、この呼び出しの書き方を変えず、`main()` の中で1回だけ使う）
  ```python
  if writes_inside_worktree(tool, tool_input, payload):
      delegated_stdout = H.delegate_to_worktree(payload, "agent_write_guard.py")
      ...（今の2行をこの if の中に入れる）
  ```
  `tool`・`tool_input` は今 `main()` の委譲の後で求めているので、委譲の前に移す（`root = resolve_root(...)` は委譲の後のままでよい）
- `writes_inside_worktree` の判定（True なら委譲してよい）
  - worktree のルートは `H.git_toplevel(payload["cwd"])`。`cwd` が無い・ルートが求まらない時は True を返す（`delegate_to_worktree` がどのみち委譲しないので、今の動きと同じ）
  - 書き込み対象：Write・Edit・MultiEdit・NotebookEdit は `file_path`（無ければ `notebook_path`）。Bash は `bash_write_targets(cmd, <worktree のルート>)` の全ての target（解析の成否を問わない。解析できない時は和集合の候補）。それ以外のツール（Read・Grep など）は書き込み対象なし
  - 書き込み対象が1つも無ければ True（読み取りだけは今どおり委譲する）
  - target が空文字列（`git commit`・引数の無い `git add` など）は cwd を指すものとして扱う（worktree の中）。ただし verb が `legacy-unknown`（解析できず対象を特定できない）が1つでもあれば False（委譲しない側に倒す）
  - Bash で `targets_vault_rules_remote(cmd)` が真（`gh api`・GitHub への `curl` で `vault/rules/` を指す）なら False（ローカルの worktree の外への書き込みとみなす）
  - パスの比較：`os.path.expanduser` で `~` を展開し、相対パスは payload の `cwd` を基準に結合し、`os.path.realpath` で解決する。worktree のルートも `os.path.realpath` で解決し、一致するか `<ルート>/` で始まる時だけ「中」とする（macOS の `/var` → `/private/var` の食い違いを避ける）
  - `/dev/null`・`/tmp` なども worktree の外として扱う（例外を設けない。委譲しない時はメインリポジトリ側のコードが今どおり判定する）
- `vault/rules/` 拒否の追加（委譲を絞るだけでは基準1の Bash のケースが通らないため。cwd が worktree の時は `resolve_root` が worktree のルートを返し、メインリポジトリの絶対パスが `../...` と正規化されて拒否に当たらない）：`targets_vault_rules` で、絶対パス（`~` 展開後）の書き込み対象は、今の `root` 基準に加えて、メインリポジトリのルート基準でも `normalize(t, <メインのルート>).startswith("vault/rules/")` を見る。メインのルートは `os.environ.get("CLAUDE_PROJECT_DIR")`、無ければ `H.git_toplevel(<このフックのファイルのディレクトリ>)`（`delegate_to_worktree` の `self_root` と同じ求め方）。求まらない時と `root` と同じ時は今の判定だけ。相対パスは今どおり `root` 基準だけで見る。Write・Bash の両方に入れてよい。拒否の文言は変えない
  - creator の `vault/plans/`・`vault/log/` 拒否、done 判定、`ALLOWED` 判定は変えない（同じ穴の対処はこの計画の範囲外）
- `.claude/hooks/_hooklib.py`・`plan_guard.py`・`stop_gate.py` は変えない（D-013 の決定済み）
- worktree の中の判定は今どおり worktree 側のコードが行う。既存の `(delegate)` の3ケース（相対パスの `cp x.txt vault/rules/common/a.md` は worktree の中なので委譲される）の名前・期待値は変えない
- smoke のケース
  - 置き場所：`== plan_guard.py ==` の見出しの直前（`== agent_write_guard.py ==` の節の末尾。434行目付近の `expect_guard` の再定義より後なので、第4引数で reason の部分文字列を見られる）
  - ケース名は `(wds-1)`〜`(wds-6)` で始め、後ろに半角スペースと説明を続ける（基準の grep はこの接頭辞で見る）。増えるのはこの6件だけ
  - 一時リポジトリは既存の `(delegate)` と同じく `mktemp -d` で main を作り、`git init -q -b main`・空コミットの後、`mktemp -d`＋`rmdir` した場所に `git worktree add` する。`mkdir -p "<main>/vault/rules"` を作る。パスは `mktemp -d` の値をそのまま使う（`realpath` で解決しない。`/var` と `/private/var` の食い違いはフックが吸収すること）。後片付けは既存の `(delegate)` と同じ形でよい
  - worktree 側の `.claude/hooks/agent_write_guard.py` は、標準入力を読んで `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow", "permissionDecisionReason": "(wds-stub)"}}` を出す差し替えにする
  - 全ケースで `cwd` は worktree、`CLAUDE_PROJECT_DIR` は main、`_HOOK_DELEGATED` は付けない
  - (wds-1)：Write、`file_path` が `<main>/vault/rules/a.md` → `deny`、部分文字列 `vault/rules/`
  - (wds-2)：Bash `touch <main>/vault/rules/a.md` → `deny`、部分文字列 `vault/rules/`
  - (wds-3)：Bash `touch ~/.claude/projects/x.jsonl`（`~` は JSON の文字列のまま渡す）→ `deny`、部分文字列 `会話記録`
  - (wds-4)：解析できない Bash `echo $(date) > <main>/vault/rules/a.md`（`$(date)` は JSON の文字列のまま渡し、smoke 側のシェルで展開させない）→ `deny`、部分文字列 `vault/rules/`
  - (wds-5)：解析できない Bash `echo $(date) > vault/rules/a.md`（相対パス。候補は worktree の中だけ）→ `allow`、部分文字列 `(wds-stub)`（委譲されたことを reason で確かめる）
  - (wds-6)：読み取りだけの Bash `ls` → `allow`、部分文字列 `(wds-stub)`
- 委譲のテストの注記（347〜351行目の「Write/Edit + 絶対 file_path 方式だと…使わない」）は、(wds-1) で絶対パスの Write を使うので、フックが `realpath` で比べるようになった旨に直してよい（直さなくてもよい）
- 構文の確認は `python3 -m py_compile` ではなく `ast.parse` で行う（サンドボックスの中では `.claude/hooks/__pycache__` に書けず py_compile が失敗するため）
