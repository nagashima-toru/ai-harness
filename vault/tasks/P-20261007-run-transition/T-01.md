## 決定済み
- 早見表の置き場所：0.5節の直後、「## 1. 計画票を見つける」の前。見出しは `## transition.py の呼び出し（早見表）`（番号を付けない）
- 早見表の冒頭に1〜2文で「計画票のタスク表と `vault/log/<計画ID>.md` は transition.py で変える。log の日時・モデルの記録・コミットは transition.py が行う」と書く
- 早見表は `| 場面 | 呼び出し |` の表にし、次の7行をこの文字列のまま（バッククォートで囲んで）書く。1行に呼び出しは1つだけ。プレースホルダは `<計画ID>`・`<id>`・`<worktree>`・`<branch>`・`<PLAN_HEAD>`・`<質問ファイル>`・`<補足>` にそろえる（以降のタスクも同じ文字列を使う）
  1. 着手（手順2。todo→doing。複数 id をカンマでつないで1回）：`python3 scripts/transition.py <計画ID> <id>[,<id>...] doing`
  2. creator の blocked の報告・分岐元の不一致（手順3。doing→blocked）：`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --worktree <worktree> --branch <branch> --plan-head <PLAN_HEAD>`
  3. review にする（手順4。収集コミット・新規コミットの判定・差分ゲート・再開情報の記録行を含む）：`python3 scripts/transition.py <計画ID> <id> review --worktree <worktree> --branch <branch> --plan-head <PLAN_HEAD>`
  4. PASS（手順6。マージ・done・後始末）：`python3 scripts/transition.py <計画ID> <id> done --worktree <worktree> --branch <branch> --plan-head <PLAN_HEAD>`
  5. FAIL（手順6。再試行、上限なら blocked）：`python3 scripts/transition.py <計画ID> <id> doing --worktree <worktree> --branch <branch>`
  6. 中断からの再開・ハング・worktree が無い時の再試行（doing→doing・review→doing）：`python3 scripts/transition.py <計画ID> <id> doing --no-model --note "<補足>"`
  7. 中断・ハング・worktree が無い時の上限での blocked（doing→blocked・review→blocked）：`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --no-model --note "<補足>"`
- 表の行は `| ` で始める（基準2の grep は、行頭が `| ` で `python3 scripts/transition.py <計画ID> ` を含む行を数える）。早見表以外の場所に、行頭が `| ` で transition.py の呼び出しを含む表の行を作らない（手順の中の呼び出しは番号付きの箇条書きか地の文に書く）
- 終了コードの表は `| 終了コード | 次の行動 |` の形で、行は `| 0 |`〜`| 4 |` の5行（行頭は `| <数字> |`）。この形の行は SKILL.md の中でこの表だけにする。内容：
  - 0：遷移した。次の手順へ進む。`--worktree` 無しの呼び出し（着手・再開・ハング・上限での blocked）は成功すると blocked でも 0
  - 1：前提を満たさず何も変えていない。標準エラーの `[transition] ` の理由を添えて人に報告し、そのタスクの処理を止める（計画票や log を Edit・printf で直さない）
  - 2：引数の誤り。早見表の形と見比べて呼び出しを直す
  - 3：差し戻した（creator を呼び直す）。標準出力の1行を完了報告に写し、手順3の1から `PLAN_HEAD` を取り直してその id の creator を呼び直す
  - 4：blocked にした。標準出力の1行を完了報告に写し、その id を終えて次の対象タスクへ進む（worktree は残っている）
- 複数の id の review・done・blocked・doing（`--worktree` 付き）は1回に1 id ずつ、1つの Bash 呼び出しで1回だけ呼び、並行に呼ばない（transition.py がコミットするため）。todo→doing だけは複数 id を1回で呼ぶ。このことを早見表に1文で書く
- `blocked` の質問文は Write ツールで一時ファイル（例：`/tmp/<計画ID>-<id>-question.txt`）に書いて `--question-file` で渡す（言い換えずに書き写すため。引用符の問題とガードの誤検知を避けるため）。このことも早見表に1文で書く
- 手順2の3〜6の置き換え：着手可能集合の選び方（3）と「選べる行が無ければ終わる」（4）は変えない。5・6は「選んだ行の id をカンマでつないで早見表1の呼び出しを1回行う（計画票・log の書き換えとコミットを transition.py が行う。コミットが要る理由：手順3の worktree はコミット済みの HEAD から分岐するため）」の1項目にまとめ、`python3 scripts/transition.py <計画ID> <id>[,<id>...] doing` をこの文字列のまま書く。終了コード1なら人に報告して止める
- 手順2の2（中断からの再開）はこのタスクでは変えない（T-04 で置き換える）
- 0節（現在時刻）：「log の日時は transition.py が実時刻で書くので run は書かない。`TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M'` は verifier が verdict の `checked_at` に使う」という内容に直す
- 0.5節：モデルの記録は transition.py が自動で付ける（`doing→review`・`doing→blocked` は `creator=<モデル>`、`review→done`・`review→doing`・`review→blocked` は `verifier=<モデル>`。値は `.claude/agents/creator.md`・`.claude/agents/verifier.md` の frontmatter の `model`）。再開・ハング・worktree が無い時は `--no-model` を付ける、と書く。smoke の (ms-3) のため `creator=` と `verifier=` の文字列を必ず残す
- 手順3〜8・「ハング時の復旧」・「回帰確認」・「注意」はこのタスクでは変えない（T-02〜T-05 で置き換える）。途中の版では、後ろの手順に手動の書き込みが残るが、transition.py は推奨の経路で手動の書き込みも従来どおり動くので矛盾しない
- 「status を `doing`」「attempt を `1` にする」のような、表を直接書き換える言い回しを新しく書かない（T-05 でファイル全体を検査する）
- `scripts/smoke.sh`・`scripts/transition.py`・`docs/vault-spec.md` は変えない
