# T-01 vault-spec.md の vault/archive/ をバッククォートのパス参照でない書き方にする

## 目的
一括削除（`bash scripts/purge_plan.sh --merged --apply`）で vault/archive/ が無くなった後も、smoke の `(ref-1) 主な文書のバッククォート内のパスがすべて存在する` が `docs/vault-spec.md` を理由に落ちないようにする。`--apply` が vault/archive/ を消すという説明は残す。

## 入力
- `docs/vault-spec.md`（26行目。`purge_plan.sh --merged` の説明の段落）
- `scripts/smoke.sh` の `refcheck`（2471行目付近。バッククォートで囲まれ、`vault/`・`scripts/`・`docs/`・`.claude/` で始まり、`<*{$` と空白を含まない文字列を実在するパスとして検査する）
- `scripts/purge_plan.sh`（`--merged --apply` の動き）

## 成果物
- `docs/vault-spec.md`（1ファイル）

## 受け入れ基準
- `docs/vault-spec.md` にバッククォートで囲んだ `vault/archive/` が無い。確認：`grep -nF '`vault/archive/`' docs/vault-spec.md` が何も出力しない
- `--merged --apply` が vault/archive/ を消す説明が残っている。確認：`grep -cF '`purge_plan.sh --merged --apply` は対象の4種と vault/archive/（旧方式の移動先。中身を問わず丸ごと）を `git rm` し' docs/vault-spec.md` が `1`
- 一括削除した一時 worktree で、smoke の参照切れの検査が `docs/vault-spec.md` の vault/archive/ を報告しない。確認（対象の作業ツリーのルートで、次の単一コマンドを順に実行する）：`mkdir -p /tmp/claude/P-20261010-purge-prereq-T-01`、`git worktree remove --force /tmp/claude/P-20261010-purge-prereq-T-01/wt`（無ければ失敗してよい）、`git worktree prune`、`git worktree add --detach /tmp/claude/P-20261010-purge-prereq-T-01/wt HEAD`、`env -C /tmp/claude/P-20261010-purge-prereq-T-01/wt bash scripts/purge_plan.sh --merged --apply | tail -1` が `vault/archive/` を出し、`bash /tmp/claude/P-20261010-purge-prereq-T-01/wt/scripts/smoke.sh 2>&1 | grep -c 'vault-spec.md:[0-9]*: vault/archive/'` が `0`
- 一括削除していない作業ツリーで smoke が全部通り、参照切れの検査も ok。確認：`bash scripts/smoke.sh 2>&1 | grep -F '(ref-1)'` の行が `ok` で始まり（行頭の空白を除く）、`bash scripts/smoke.sh 2>&1 | tail -1` が `fail=0` を含む

## 決定済み
- 直し方：26行目の `` `vault/archive/`（旧方式の移動先。中身を問わず丸ごと） `` のバッククォートだけを外し、`vault/archive/（旧方式の移動先。中身を問わず丸ごと）` にする。ほかの語・ほかの行は変えない。`refcheck` の除外リストを足す・`vault/archive/<...>` のような雛形の形にする、はしない（smoke.sh はこのタスクの成果物ではない）
- 26行目のほかのバッククォート（`purge_plan.sh --merged --apply`・`git rm`・`docs/runbook.md` など）はそのまま残す。`docs/runbook.md` は実在し続けるので問題ない
- `docs/vault-spec.md` 140行目の `vault/log/` は変えない。一括削除で vault/log/ が無くなるのは `vault/log/.gitkeep` で防ぐ（人が計画ブランチに足す。計画票の「人への質問」の1）。このタスクの受け入れ基準3は vault/archive/ だけを見るので、`.gitkeep` の有無に左右されない
- 受け入れ基準3の「対象の作業ツリー」：creator は自分の worktree のルート、verifier は渡された worktree（`git -C <worktree のパス> worktree ...` の形で実行してよい）。`/tmp/claude/...` に書けない時は、代わりに対象の作業ツリーの `.claude/worktrees/purge-check-T-01`（`.gitignore` 済み）を使ってよい
- 一時 worktree は detached HEAD で作る。一括削除（`git rm`）は一時 worktree の中だけで行い、対象の作業ツリーでは `purge_plan.sh --merged --apply` を実行しない。確認が終わったら `git worktree remove --force /tmp/claude/P-20261010-purge-prereq-T-01/wt` で片づける（`rm -rf` は使わない。親ディレクトリ `/tmp/claude/P-20261010-purge-prereq-T-01` は残してよい）
- 計画時点で一時 worktree の手順を実行した結果：`purge_plan.sh --merged --apply` の最後の行は `vault/archive/`、smoke の ref-1 は `docs/vault-spec.md:26: vault/archive/` を報告していた
