# T-02 smoke の model_stats フィクスチャに doing→blocked creator= で終わるタスクを足す

## 目的
T-01 で広げた集計キー（`doing→blocked creator=<モデル>` で終わるタスクもそのモデルに集計する）の回帰テストを、`scripts/smoke.sh` の model_stats 節に足す（issue #97）。

## 入力
- `scripts/smoke.sh` の `== model_stats.py ==` 節（1377行目付近から、`rm -rf "$MS_DIR"` まで）と、`expect_eq` の定義（1025行目付近）
- T-01 で変更済みの `scripts/model_stats.py`
- `docs/vault-spec.md` 7節の集計の定義

## 成果物
- `scripts/smoke.sh`

## 受け入れ基準
- smoke 全体が通る。確認：`bash scripts/smoke.sh > /tmp/P-20261003-model-stats-blocked-creator-T-02-smoke.txt 2>&1` の後、`tail -1 /tmp/P-20261003-model-stats-blocked-creator-T-02-smoke.txt` が `smoke: pass=<数> fail=0`
- model_stats 節のケースが13件すべて ok になる（既存12件＋新しい ms-5 の1件）。確認：`grep -c '^  ok   (ms-' /tmp/P-20261003-model-stats-blocked-creator-T-02-smoke.txt` が `13`、`grep -c '^  NG   (ms-' /tmp/P-20261003-model-stats-blocked-creator-T-02-smoke.txt` が `0`
- フィクスチャに、`doing→blocked creator=` で終わるタスクが2つある。確認：`grep -c 'T-05 doing→blocked attempt=1 creator=haiku' scripts/smoke.sh` が `1`、`grep -c 'T-06 doing→blocked attempt=2 creator=haiku' scripts/smoke.sh` が `1`
- 期待値の haiku の行が新しい値になっている。確認：`grep -cF 'haiku\t4\t0.00\t1.50\t0.75' scripts/smoke.sh` が `2`（`ms_want` と ms-5 の2か所）
- 変更は model_stats 節の中だけである。確認：`git diff main -- scripts/smoke.sh` を Read と目視で確認し、変わった行がすべて `echo "== model_stats.py =="` の行から `rm -rf "$MS_DIR"` の行までの間にある

## 決定済み
- 既存のフィクスチャ（`P-MS.md` の heredoc）の T-04 の最後の行（`- 2026-10-01 13:10 T-04 review→done attempt=1`）の直後、`MSEOF` の前に、次の6行をこの順で足す。既存の行は変えない
  - `- 2026-10-01 14:00 T-05 todo→doing attempt=1`
  - `- 2026-10-01 14:05 T-05 doing→blocked attempt=1 creator=haiku 質問`
  - `- 2026-10-01 15:00 T-06 todo→doing attempt=1`
  - `- 2026-10-01 15:05 T-06 doing→review attempt=1 creator=sonnet`
  - `- 2026-10-01 15:10 T-06 review→doing attempt=2 verifier=opus 理由`
  - `- 2026-10-01 15:15 T-06 doing→blocked attempt=2 creator=haiku 質問`
- T-06 は「`doing→review` の creator と最後の `doing→blocked` の creator が違う時、最後の `creator=` 付き行（haiku）が勝つ」ことを確かめるためのもの
- `ms_want` の haiku の行を `haiku\t2\t0.00\t1.50\t0.50` から `haiku\t4\t0.00\t1.50\t0.75` に直す。sonnet・unknown の行は変えない（`sonnet\t1\t1.00\t1.00\t0.00`・`unknown\t1\t1.00\t1.00\t0.00` のまま）。planner が T-01 の変更案で計算した値
- ms-5 のケースを1つ足す。(ms-1) の2つの `expect_eq` の直後に置く。形は次のとおり：`expect_eq "(ms-5) doing→blocked creator= で終わるタスクも creator のモデルに集計される（haiku 4件・blocked 率 0.75）" "$(printf 'haiku\t4\t0.00\t1.50\t0.75')" "$(echo "$ms_got" | grep '^haiku')"`
- ms-2 の `grep -v 'creator=haiku'` で作る `P-LIVE.md` は変えない。T-05・T-06 の `creator=haiku` の行が消えても、T-05 は最後が `todo→doing`、T-06 は最後が `review→doing` になり対象外なので、`^haiku` が0件・`^sonnet` が1件の期待値はそのまま通る（planner が確認済み）
- 既存のケースの名前・数・順序は変えない（ms-1〜ms-4 の12件）
- `rm -rf "$MS_DIR"` などの既存の後片付けの行はそのまま残す（新しく `rm -rf` を足さない）
- `scripts/model_stats.py` は触らない（T-01 の成果物）
- コミットは不要（受け入れ基準に無い）
