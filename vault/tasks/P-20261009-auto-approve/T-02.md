# T-02 agent_write_guard.py から承認の判定を削り、_hooklib.py の is_approve_command と smoke のケースを合わせる

## 目的
`/plan` が計画票を自分で approved にする Edit を、`agent_write_guard.py` が会話記録に `/plan approve` が無いことを理由に拒否しないようにする（D-015 フェーズ2 が単独で動くため）。使われなくなる `_hooklib.py` の `is_approve_command` も削る。

## 入力
- `vault/designs/D-015.md` の「決定事項」の表と「フェーズ2」の節（決定済みの「会話記録を読む関数は、ほかに使う所が無くなれば削る」）
- `.claude/hooks/agent_write_guard.py`（`find_plan_approval` と、`main` の中の「# 計画票の承認（draft→approved）は、人が /plan approve <計画ID> で指示した時だけ許可する（D-010 フェーズ4）。」のブロック）
- `.claude/hooks/_hooklib.py`（`is_approve_command`）
- `scripts/smoke.sh` の「# 計画票の承認（draft→approved）の会話記録による裏付け（D-010 フェーズ4 / T-03）。」の節（`(approve-pre)` のケース。計画作成時は605〜670行目）

## 成果物
- `.claude/hooks/agent_write_guard.py`（主な成果物）
- `.claude/hooks/_hooklib.py`（付随。`is_approve_command` の削除だけ）
- `scripts/smoke.sh`（付随。`(approve-pre)` のケースの削除と `(approve-free-N)` のケースの追加だけ）

## 受け入れ基準
- `agent_write_guard.py` に承認の判定が無い。確認：`grep -c "find_plan_approval\|is_approve_command" .claude/hooks/agent_write_guard.py` の出力が `0`
- `_hooklib.py` から `is_approve_command` が消え、unblock の判定が使う2つの関数は残る。確認：`grep -c "def is_approve_command" .claude/hooks/_hooklib.py` の出力が `0`、`grep -c "def human_messages\|def is_unblock_command" .claude/hooks/_hooklib.py` の出力が `2`
- 会話記録に `/plan approve` が無くても、メインセッションの計画票の draft→approved の Edit・MultiEdit・Write は許可される。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (approve-free-'` の出力が `3`
- 旧ケースが残っていない。確認：`bash scripts/smoke.sh 2>&1 | grep -c '(approve-pre)'` の出力が `0`
- unblock の判定の既存ケースは変わらず通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (unblock-pre)'` の出力が `41`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- `agent_write_guard.py` から関数 `find_plan_approval` と、`main` の中のその呼び出しのブロック（コメント2行・`approved_plan = ...` から `deny(deny_reason)` まで）を丸ごと削る。agent_type が planner・creator の時の拒否も一緒に消える（人の回答待ちの既定案。計画票の「人への質問」1）
- 残すもの：unblock の判定（`find_plan_unblocks` とその呼び出し）、`content_after_write`・`apply_edit`・`PLAN_FILE_RE`（unblock の判定が使う）、それ以外の判定（`vault/rules/`・会話記録への書き込みの拒否・done・creator・verifier/planner・main へのコミット）。これらは D-015 フェーズ3 で扱うので変えない
- `main` の中の会話記録への書き込みの拒否のコメント「（解除口は無い。承認判定 T-03 が会話記録を裏付けにするための前提）」は「（解除口は無い。blocked の解除の判定が会話記録を裏付けにするための前提）」にする。`targets_transcript_dir` の docstring の「承認の裏付けにする会話記録」も「blocked の解除の裏付けにする会話記録」にする。処理は変えない
- `_hooklib.py` は `is_approve_command` の関数だけを削る。`human_messages`・`is_unblock_command` は残す（`agent_write_guard.py` の unblock の判定が使う）。`plan_guard.py`・`scripts/` から `is_approve_command` を使う所は無い（T-01 後）
- smoke.sh の直し方
  - 「# 計画票の承認（draft→approved）の会話記録による裏付け（D-010 フェーズ4 / T-03）。」の節の `(approve-pre)` のケース・`expect_ap`・`T_CMD`・`T_CMD_SP`・`T_SENT`・`T_OTHER_ID`・`T_PREFIX_ID`・`T_TOOLRES`・`T_META`・`AP_EDIT`・`AP_MULTI`・`AP_WRITE` を削る
  - 後ろの節が使う定義は残す：`AP_TRANSCRIPT`・`AP_NONEXIST`・`make_transcript`・`T_CHAT`・`TP`（`(unblock-pre)` が `T_CHAT` を使う。T-01 後の plan_guard の節が `AP_REPO` などを使う）。使われなくなった変数が残っても構わないが、`(unblock-pre)` と plan_guard の節のケースが壊れないこと
  - 新しいケースは削った位置に置き、コメントを「# 計画票の承認（draft→approved）は判定しない（D-015 フェーズ2。/plan が自動で承認する）」にする。`make_plan "P-TEST" "draft" "| T-01 | todo | 0 | - | A | |"` と `make_transcript "$T_CHAT"`（`/plan approve` の無い会話記録）の後に、`expect_guard "<名前>" allow "$(run_guard '<payload>')"` で次の3つを書く。payload は `transcript_path` に `$AP_TRANSCRIPT` を入れ、`agent_type` は付けない（メインセッション）
    - `(approve-free-1) /plan approve 無し・メインの Edit で draft→approved → 許可`：`"tool_name":"Edit","tool_input":{"file_path":"vault/plans/P-TEST.md","old_string":"status: draft","new_string":"status: approved"}`
    - `(approve-free-2) /plan approve 無し・メインの MultiEdit で draft→approved → 許可`：edits に `status: draft`→`status: approved` を含む MultiEdit
    - `(approve-free-3) /plan approve 無し・メインの Write で approved の計画票 → 許可`：`"tool_name":"Write","tool_input":{"file_path":"vault/plans/P-TEST.md","content":"---\nid: P-TEST\nstatus: approved\n---\n# ゴール\n"}`
  - `(unblock-pre)` の節（41件）は1文字も変えない
- `docs/vault-spec.md` 12節の承認の行は T-06 が直すので、このタスクでは変えない
