## 決定済み
- `docs/vault-spec.md`：
  - 2節：transition.py の呼び出しの形の説明に `--resume-worktree`（todo→doing、1 id、併用できない引数）を足し、引き継げる時の順序（収集・計画ブランチの取り込み・状態のコミット）と標準出力の `plan_head`（状態のコミットの前の HEAD を `--plan-head` に使う理由）、終了コード5（引き継げない。何も変えていない）を書く。終了コードの列挙に5を足す。`/run` の場面と遷移先の対応の段落に「unblock 後の再着手は `--resume-worktree`」を足す
  - `scripts/amend_task.py` の段落を足す（置き場は5節の差分ゲートの説明の後か、2節の blocked の解除の文の近くのどちらでもよい）。呼び出しの形・拒否の条件・「成果物」への追加の行の形・受け入れ基準の差し替え・log の行・コミットを、T-01 の「決定済み」と実装に合わせて書く
  - 7節：amend の log の行（`- <日時> <id> amend <要約>`。`→` を含まない補足行で集計に使わない）、`--fresh` 付きの解除の行（`... /plan unblock <計画ID> <id> --fresh`）、引き継ぎの遷移行の補足 `worktree を引き継ぎ` を足す
  - 9節：表の「verdict が無い、または task / attempt が不一致」の行の説明を、T-03 の条件（その id の最後の `→doing` の行より後に記録行が無い）と文言（`待機中なら問題ありません` を含む）に合わせる。判定（ブロック）は変わらないことも書く
- `docs/runbook.md` 4節：コマンドの形を `/plan unblock <計画ID> <id> [--fresh] [回答]` にし、既定は再着手で worktree を引き継ぐこと・`--fresh` で破棄して作り直すこと・回答が成果物の追加や受け入れ基準の変更を含む時はエージェントが `scripts/amend_task.py` で直すこと・同じ前提の todo 票にも基準の文字列で探して追記することを書く。今の「エージェントは、回答をタスク票の「決定済み」に追記し、その行を `todo` に戻し…」の文はこの内容に書き換える。「代替手段として人がエディタで直接直す」段落は残す
- `docs/guide.md` の「blocked に答えて再開する」：「すること：」のコマンドを `/plan unblock <計画ID> <id> [--fresh] [回答]` にし、本文に `--fresh` の意味を1文足す。項目の形（`すること：`・`詳しく：` とリンク）は変えない（smoke の `(guide-1)` が検査する）
- `README.md`：スクリプトの表に `scripts/amend_task.py` の行（例：`| \`scripts/amend_task.py\` | タスク票の成果物の追加・受け入れ基準の差し替え |`）を足す。install の `.gitignore` の扱いは README には書かなくてよい
- `docs/decisions.md`：表の末尾に、日付 `2026-10-12`、「何を」の末尾に `（P-20261012-unblock-resume-and-install-fixes）` を付けた行を少なくとも次の3行足す。(a) unblock 後の再着手は既定で blocked の worktree を引き継ぎ、`--fresh` で作り直す。分岐元が古ければ計画ブランチを worktree にマージしてから引き継ぎ、`--plan-head` には状態のコミットの前の HEAD を使う（Issue #190）。(b) unblock での成果物の追加・受け入れ基準の差し替えは `scripts/amend_task.py` で行い、読み替えの注記で済ませない。他の todo 票は回答文のタスク ID ではなく基準の文字列で探す（Issue #189）。(c) stop_gate は判定を変えず（2026-10-10 の行の人の選択を維持）、文言を「待機中なら問題ありません」に寄せ、条件を最後の `→doing` の行より後に記録行が無い時に直す（Issue #191）。必要なら PR テンプレートと `.gitignore` の行を足してもよい。既存の行は書き換えない
- 文書の中で `.claude/` の下の worktrees ディレクトリのパスをバッククォートで囲まない（リポジトリの直下に無いので smoke の `(ref-1)` が NG になる）。`docs/decisions.md` は `(ref-1)` の対象外
