# T-01 vault-spec 7節に creator=/verifier= の補足の書式を追記する

## 目的
log の遷移行に使ったモデルを残す書式の正本を `docs/vault-spec.md` 7節に確定する。SKILL.md（T-03）と model_stats.py（T-02）はこれを参照する。

## 入力
- `docs/vault-spec.md` 7節（ログ）
- `vault/designs/D-010.md` のフェーズ8（ゴール文・決定済み）

## 成果物
- `docs/vault-spec.md`（7節への追記のみ）

## 受け入れ基準
- 7節に、`doing→review`・`doing→blocked` の行の補足へ `creator=<モデル>`、`review→done`・`review→doing`・`review→blocked` の行の補足へ `verifier=<モデル>` を付ける旨と、モデルの値が `.claude/agents/<name>.md` の frontmatter の `model` である旨がある（`grep -n 'creator=' docs/vault-spec.md` と `grep -n 'verifier=' docs/vault-spec.md` がそれぞれヒットする）
- 7節に、行の例（`creator=sonnet` を含む遷移行と `verifier=sonnet` を含む遷移行）が書かれている
- 7節に、`creator=` が無い既存の行は集計で `unknown` として扱う旨がある（`grep -n 'unknown' docs/vault-spec.md` がヒットする）
- 7節に、集計は `scripts/model_stats.py` が行い、遷移行（`→` を含む行）以外は無視する旨と、`vault/archive/` は既定の対象外である旨がある（`grep -n 'model_stats.py' docs/vault-spec.md` がヒットする）
- `docs/vault-spec.md` 以外のファイルが変わっていない（`git status --porcelain` の出力が `docs/vault-spec.md` と、計画票・タスク票・log・verdict 以外を含まない）

## 決定済み
- 記録先は log（verdict ではない）。verdict.json の形式と stop_gate.py は変えない
- 補足の書式は既存の `- <日時> <id> <遷移> attempt=<n> 補足` の補足の先頭に `creator=<モデル>` / `verifier=<モデル>` を置く形にする。複数の補足が続く場合（例：理由要約）はその後ろに空白区切りで書く
- 集計の定義：対象タスク＝`計画ID/id`（計画 ID は log のファイル名から取る）の最後の遷移行が `→done` または `→blocked` のもの。集計キー＝最後の `doing→review` 行の `creator=`（無ければ `unknown`）。1回目 PASS 率＝`review→done attempt=1` で終わった件数 ÷ 対象タスク数。平均 attempt＝最後の遷移行の `attempt=` の平均。blocked 率＝`→blocked` で終わった件数 ÷ 対象タスク数。定義の細部は D-010 フェーズ8 の決定済みと同じ文言で7節に書いてよい
- 遷移行（`<状態>→<状態>` を含む行）以外の行は無視する。`worktree path=...` やハングの補足行も含む
- 出力はタブ区切りで、1行目を見出し `model	tasks	first_pass_rate	avg_attempt	blocked_rate` とする。率は小数2桁
- `vault/archive/` 配下の log は引数で明示的に渡せば集計できる。既定の対象には含めない
- verifier のモデル別の集計は出さない（記録だけしておく）
- 7節の既存の記述（承認・解除・worktree 記録行の書式）は変えない
