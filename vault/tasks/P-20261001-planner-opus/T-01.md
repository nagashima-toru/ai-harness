- 追加行に `planner=opus`・`verifier=sonnet`・`creator=sonnet` が含まれ、2026-09-17 の「verifier / planner の model は sonnet」を置き換える旨を述べている（`grep -n '^| 2026-10-01 .*planner=opus' docs/decisions.md` がヒットし、目視で置き換えの記述を確認）

## 決定済み
- モデル名は alias（`opus`・`sonnet`）で書く。バージョン付きの ID は書かない
- `docs/decisions.md` の 2026-09-17 の行は書き換えない（判断の記録として残す）。新しい日付の行を追加し、置き換える旨を書く
- スキルの frontmatter でのモデル指定はしない。本文の注意書きと runbook での運用とする
- creator のモデルは変えない。haiku 等への切り替えは、`model_stats.py` で十分な件数が集まってから、別の計画で行う
- verifier は「実行側」として扱う（人の回答）。`sonnet` のまま
- 追加行の日付は 2026-10-01。基準の grep もこの日付で固定している。作業日が変わっていたら、`TZ=Asia/Tokyo date '+%Y-%m-%d'` の値で行を書き、基準の日付も合わせてよい
- 「なぜ」には、planner は考える工程なので強いモデルにする、verifier は実行側なので sonnet のまま、creator は `scripts/model_stats.py` の集計結果を見て別の計画で見直す、を書く
- smoke.sh はこのタスクの基準に含めない（T-05 で流す）
