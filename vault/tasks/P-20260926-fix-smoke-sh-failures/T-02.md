# T-02 discard_worktree.sh のパス比較でシンボリックリンクを解決し worktree 削除判定を安定させる

## 目的
`scripts/discard_worktree.sh` が対象パスを `os.path.abspath()` で求めているために、macOS で `git worktree list --porcelain` の出力と文字列が食い違い、本来削除できるはずの worktree を「登録済み worktree ではありません」と誤判定して何も削除しない不具合を直す（issue #59）。

## 入力
- `scripts/discard_worktree.sh`（変更対象。`TARGET_PATH="$(python3 -c "import os,sys;print(os.path.abspath(sys.argv[1]))" "$WORKTREE_ARG")"` の行）
- `scripts/smoke.sh` の `== discard_worktree.sh ==` セクション、特に `(a)` 正常系ケース（`D_A`/`DWMAIN`/`dw_run` まわり）
- T-01 の「入力」に書いた再現手順（同じ macOS の `/var` ↔ `/private/var` シンボリックリンク解決の食い違いが根本原因）

## 成果物
- `scripts/discard_worktree.sh` の修正（1ファイル）

## 受け入れ基準
- `TARGET_PATH` の算出にシンボリックリンク解決（`os.path.realpath`）を使っている。確認コマンド: `grep -n "os.path.realpath" scripts/discard_worktree.sh` の出力が1行以上
- `bash scripts/smoke.sh` を実行した時、`(a) discard_worktree.sh 正常系` を含むテスト名の行が `ok` から始まる。確認コマンド: `bash scripts/smoke.sh`（`== discard_worktree.sh ==` セクション内の `(a)` の行が `ok` で始まることを出力で確認する）
- 同じ実行で `(b)`・`(c)`・`(d)`・`(e)`（`discard_worktree.sh` の他の既存ケース）に新規の `NG` が発生していない。確認コマンド: 同じ出力中、`discard_worktree.sh` セクションの `(b)`〜`(e)` の行がいずれも `ok` で始まることを確認する
- 同じ実行の末尾 `smoke: pass=<N> fail=<M>` の `pass` が着手前HEAD時点の実行結果（152）より1件以上増えている（今回直した1ケース分。他タスクの完了状況によってはさらに増えていてもよい）。確認コマンド: 同じ実行結果の末尾行を読む

## 決定済み
- 修正箇所は `TARGET_PATH` を求める1行のみ。`os.path.abspath(sys.argv[1])` を `os.path.realpath(sys.argv[1])` に変える（またはそれと同等の、シンボリックリンクを解決した絶対パスを返す実装）。それ以外のロジック（ブランチ名の `worktree-agent-` プレフィックス検証、`git worktree list --porcelain` のパース、削除処理）は変更しない
- `git worktree list --porcelain` が返す `worktree <path>` は git 側で解決済み（シンボリックリンクを含まない）パスである前提で比較する。Linux 等シンボリックリンクが絡まない環境では `os.path.realpath()` と `os.path.abspath()` は同じ結果になるため、既存の通っている `(b)`〜`(e)` ケースへの影響は無い前提で進めてよい
- 他タスク（T-01・T-03〜T-05）の成果物ファイルは変更しない（`scripts/discard_worktree.sh` 以外のファイルには触れない）
- コミットの指示は無いので、コミットするかどうかは任意（する場合は `vault/rules/common/git.md` の運用に従う）
