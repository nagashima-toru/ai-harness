# T-02 smoke.sh の agent_write_guard のケースを3つの判定に合わせて消し・足す

## 目的
T-01 で3つの判定（(a) done のタスク票・verdict、(b) main 上の git commit、(c) verifier の書き込み先）と worktree への委譲だけになった `agent_write_guard.py` に合わせて、`scripts/smoke.sh` の削った判定のケースを消し、新しい判定のケースを足して、smoke 全体を `fail=0` にする。

## 入力
- `vault/designs/D-015.md` の「フェーズ3」の受け入れ基準の候補・決定済み
- `.claude/hooks/agent_write_guard.py`（T-01 の後の版。T-01 のタスク票の「決定済み」に判定の仕様がある）
- `scripts/smoke.sh` の `== agent_write_guard.py ==` の節（222〜718行目あたり）と `== bash-write-unify ==` の節（2002行目あたり）

## 成果物
- `scripts/smoke.sh`（1ファイル）

## 受け入れ基準
- smoke 全体が通る。確認：`bash scripts/smoke.sh 2>&1 | tail -1` が `fail=0` を含む
- (a) のケースが4件ある。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard3-a)'` が `4`
- (b) のケースが7件ある。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard3-b)'` が `7`
- (c) のケースが4件ある。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard3-c)'` が `4`
- 削った判定が効かないことのケースが8件ある。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard3-free)'` が `8`
- 削った判定のケースの見出しが残っていない。確認：`grep -cE 'transcript-guard|bash-parse|guard-text|unblock-pre|bash-write-unify|analyze_bash_writes' scripts/smoke.sh` が `0`
- worktree への委譲のケースが新しい規則で7件ある。確認：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \((delegate|wds-[0-9]+)\)'` が `7`

## 決定済み
- 足すケースの名前は `expect_guard` の第1引数を `(guard3-a) `・`(guard3-b) `・`(guard3-c) `・`(guard3-free) ` で始める（この語を書くこと）。置く場所は `== agent_write_guard.py ==` の節の中ならどこでもよい。4引数の `expect_guard`（reason の部分文字列も見る版）は435行目あたりで定義し直されているので、reason を見るケースはその後ろに置く
- (guard3-a) の4件（`make_plan "P-FIX" "approved" "| T-01 | done | 1 | - | done task | |" "| T-02 | doing | 1 | - | doing task | |"` のような計画票を `run_guard` の `$TMP` に置く）：
  1. メインセッションの done のタスク票（`vault/tasks/P-FIX/T-01.md`）への Edit → deny（reason に `done`）
  2. verifier の done の verdict（`vault/verdicts/P-FIX/T-01.json`）への Write → deny（reason に `done`）
  3. メインセッションの doing のタスク票（`vault/tasks/P-FIX/T-02.md`）への Edit → allow
  4. メインセッションの Bash `printf x >> vault/tasks/P-FIX/T-01.md`（done のタスク票）→ allow（Bash は見ない）
- (guard3-b) の7件（今の `GTMP` のように `smoke_tmpdir` で git リポジトリを作り、`CLAUDE_PROJECT_DIR` をそこに向けて呼ぶ）：
  1. main で `git commit -m x` → deny
  2. main で `git add a && git commit -m x` → deny
  3. main で `echo x; git commit -m x` → deny
  4. main で `echo a` と `git commit -m x` の改行区切り → deny
  5. main で `git -C . commit -m x` → deny
  6. `work/p-test` ブランチで `git commit -m x` → allow
  7. detached HEAD（`git -C "$GTMP" checkout -q --detach`）で `git commit -m x` → allow
- (guard3-c) の4件：
  1. verifier の `$TMP/vault/verdicts/P-X/T-01.json` への Write → allow
  2. verifier の `$TMP/README.md` への Write → deny（reason に `verifier`）
  3. verifier の `$TMP/README.md` への Edit → deny
  4. verifier の Bash `echo x > README.md` → allow（verifier の Bash は制限しない）
- (guard3-free) の8件（すべて allow）：
  1. creator の `$TMP/vault/rules/common/a.md` への Write
  2. メインセッションの `$TMP/vault/rules/common/a.md` への Write
  3. creator の Bash `python3 -c "open('vault/rules/a.md','w')"`
  4. メインセッションの Bash `echo x > vault/rules/a.md`
  5. creator の `$TMP/vault/plans/P-X.md` への Write
  6. planner の `$TMP/README.md` への Write
  7. メインセッションの Bash `gh api -X PUT repos/o/r/contents/vault/rules/common/roles.md -f content=Zm9v`
  8. HOME を一時ディレクトリに差し替えて（今の `TG_HOME`・`run_guard_home` の型。名前に `transcript-guard` を含めない）、`$HOME/.claude/projects/x/s.jsonl` への Write
- 消すケース：新しい判定で結果が変わるものはすべて消すか (guard3-*) に置き換える。少なくとも次は消す。gh api・curl の4件、verifier・planner の Bash の書き込み制限のケース（`(issue #54 placeholder)`・`(bash-parse-allowed)` を含む）、`vault/rules/` への Write が拒否される `(a)(b)(g)(h)` のケース、planner の `vault/todo.md` 拒否、verifier の Bash の git commit 拒否、`(bash-parse-main)` の全件（許可のケースは引用符の中の誤検知を許容したので結果が変わる。拒否のケースは (guard3-b) に置き換わる）、creator の `vault/plans/`・`vault/log/` 拒否、`(done-write)` の Bash のケース、`(bash-parse-done)`、`(transcript-guard)`・`(bash-parse)`・`(guard-text heredoc)`・`(guard-text cd)`・`(bash-parse-creator)`・`(unblock-pre)` の節、`== bash-write-unify ==` の節全体（`analyze_bash_writes` が無くなったので動かない）
- 残してよいケース：新しい判定でも結果が変わらないもの（`(done-write)` の Write のケース、`(i)(j)(k)(l)`、`(worktree)`・`(worktree nested)`、`(approve-free-*)` など）。`(c)`（verifier の verdicts への Write）も残してよい。`fail=0` で結果が合っていることを確かめる
- 委譲のケース（基準7。`(delegate)` 3件と `(wds-N)` 4件）：
  - `(delegate)` の3件は残し、ローカル判定の目印を `cp x.txt vault/rules/...` の Bash から、verifier の worktree 内の `README.md` への Write（`{"agent_type":"verifier","tool_name":"Write","tool_input":{"file_path":"<worktree>/README.md"},"cwd":"<worktree>"}`）に替える。期待値は今どおり（差し替えた委譲先が allow → allow、`_HOOK_DELEGATED=1` → ローカルで deny、委譲先が非0で終了 → ローカルで deny）
  - `(wds-N)` は次の4件に置き換える（今の (wds-1)〜(wds-6) は消す）。(wds-1) verifier のメインリポジトリの `README.md`（worktree の外）への Write → 委譲せず deny（reason に `verifier`）。(wds-2) verifier の worktree 内の `README.md` への Write → 委譲され `(wds-stub)`。(wds-3) Bash `ls` → 委譲され `(wds-stub)`。(wds-4) Bash `touch <メインリポジトリ>/x.txt` → 委譲され `(wds-stub)`（Bash は常に委譲する）
- 一時ディレクトリは今の smoke と同じく `smoke_tmpdir` で作る。smoke の中の後片付け（既存の `rm -rf "$GTMP"` など）は今の書き方のままでよい（スクリプトの中で動くので settings.json の deny に当たらない）
- `.claude/hooks/agent_write_guard.py`・`.claude/hooks/_hooklib.py` は変えない（T-01 の成果物）。smoke のケースと食い違ったら、フックではなくケースを T-01 の「決定済み」に合わせる。フックの側に誤りがあると判断した時は blocked にする
- `docs/vault-spec.md` は変えない（T-03 の成果物）
