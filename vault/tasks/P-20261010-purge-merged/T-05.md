# T-05 vault-spec から archive の記述を除き --merged を書く

## 目的
仕様の正本 `docs/vault-spec.md` から archive（`vault/archive/` の行・`archive_plans.sh` の段落・archive の log を集計する例）を除き、`main` にマージ済みの計画一式を一括削除する `purge_plan.sh --merged` を書く。

## 入力
- `vault/designs/D-016.md` の「フェーズ2」
- `docs/vault-spec.md`（1節の表の `vault/archive/` の行とその直後の「archive への移動は…」の段落、1節の `purge_plan.sh` の段落、4節の frontmatter の読み方の段落、7節の `model_stats.py` の段落、10節の「draft・done の計画票と vault/archive/ は検査しない」）
- T-01 で足した `scripts/purge_plan.sh` の `--merged`（冒頭のコメントに使い方・対象の条件・出力がある）

## 成果物
- `docs/vault-spec.md`（1ファイル）

## 受け入れ基準
1. vault-spec に `archive_plans`・`<年-月>`・`archive/*/log` が無い。確認：`grep -nE 'archive_plans|<年-月>|archive/\*/log' docs/vault-spec.md` の出力が空
2. vault-spec で `vault/archive/` が出てくるのは `--merged --apply` の説明の1行だけ（1節の表の行・10節の検査対象外の記述・7節の集計の例は無い）。確認：`grep -n 'vault/archive/' docs/vault-spec.md` の出力が1行で、その行が `purge_plan.sh --merged --apply` を含む
3. 1節に `--merged` の段落があり、使い方・対象の条件・人だけが `--apply` を実行することが書かれている。確認：`grep -c '^`bash scripts/purge_plan.sh --merged (--list|--report|--apply)` は' docs/vault-spec.md` が `1`、`grep -c -e '--merged --apply は人だけが実行する' docs/vault-spec.md` が `1`
4. 4節の frontmatter の読み方の段落が、archive_plans.sh の代わりに purge_plan.sh を挙げている。確認：`grep -c '`scripts/current_plan.sh`・`scripts/purge_plan.sh` も同じ規則で読む' docs/vault-spec.md` が `1`
5. 節の構成が変わっていない。確認：`grep -c '^## ' docs/vault-spec.md` が `13`

## 決定済み
- 1節の表から `| \`vault/archive/<年-月>/{plans,tasks,verdicts,log}/\` | ... |` の行を消し、表の直後の「archive への移動は人が `scripts/archive_plans.sh --apply` で行う…」の段落を丸ごと消す
- 1節の既存の `purge_plan.sh` の段落（「計画一式4種（…）は、run の手順7で PR を作る直前に除去し…」）の直後に、次の段落を新しく足す（受け入れ基準2・3の文字列を含む。言い回しは整えてよいが、`` `bash scripts/purge_plan.sh --merged (--list|--report|--apply)` は `` で行を始めること、`purge_plan.sh --merged --apply` と `vault/archive/` を同じ行に書くこと、`--merged --apply は人だけが実行する` を途中に記号を挟まない連続した文字列で書くこと）：
  - `` `bash scripts/purge_plan.sh --merged (--list|--report|--apply)` は ``、`main` にマージ済みのまま残った計画一式をまとめて扱う。対象は、計画 ID が `P-YYYYMMDD-<slug>` の形・現在のブランチの計画でない・計画票が `status: done`・タスク表が1行以上で全行 `done`・`main` の版の計画票も `status: done`、の全部を満たす計画。`--list` は対象の計画 ID を1行1件で出す。`--report` は log の `→blocked` の行の補足（`<計画ID>/<id>: blocked <補足>`）と verdict の空でない `reasons`（`<計画ID>/<id>: reasons <理由>`）を出す。どちらも何も変えない。`purge_plan.sh --merged --apply` は対象の4種と `vault/archive/`（旧方式の移動先。中身を問わず丸ごと）を `git rm` し、コミットはしない。対象パスに未コミットの変更があれば何も消さずに終了コード1。--merged --apply は人だけが実行する（他の計画の done のタスク票・verdict を消すのは、フックと差分ゲートを通らない経路になるため）。エージェントは --list・--report だけを使う。手順は `docs/runbook.md` 5節
  - この段落は1行（1段落）で書く。受け入れ基準2の「`vault/archive/` が出てくるのは1行だけ」はこの段落の行を指す
- 4節の「`scripts/current_plan.sh`・`scripts/archive_plans.sh` も同じ規則で読む」を「`scripts/current_plan.sh`・`scripts/purge_plan.sh` も同じ規則で読む」に変える（purge_plan.sh の `fm_status` は同じ規則で読む）
- 7節の `model_stats.py` の段落から、「`vault/archive/` 配下の log は既定の対象に含めず、引数で明示的に渡した時だけ集計する（例：…）。」の1文を消す。前後の文は変えない
- 10節の「draft・done の計画票と vault/archive/ は検査しない。」を「draft・done の計画票は検査しない。」にする
- `--merged --apply は人だけが実行する` は vault-spec 全体で1回だけ書く（受け入れ基準3の期待値 `1`）
- 節の追加・削除はしない（`## ` の見出しは2026-10-10 時点で13個）
- `vault/harness-improvements/` の行と記述は変えない（D-016 の決定済み）
- 過去の D-0xx・計画 ID への言及は書き換えない
