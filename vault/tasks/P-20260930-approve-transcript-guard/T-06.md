# T-06 vault-spec.md の7・10・12節に承認の裏付けと会話記録の保護を追記する

## 目的
T-02〜T-05 で入れた挙動（承認の裏付け・会話記録の保護・log の計画単位の行・マージの deny）を、仕様の正本 `docs/vault-spec.md` に書く（D-010 フェーズ4）。

## 入力
- `vault/designs/D-010.md` フェーズ4（決定済み）
- T-02〜T-05 の成果物（`.claude/hooks/agent_write_guard.py`・`.claude/hooks/plan_guard.py`・`.claude/skills/plan/SKILL.md`・`.claude/settings.json`）
- `docs/vault-spec.md` の4節末尾（マージを人が行う記述）・7節・10節・12節

## 成果物
- `docs/vault-spec.md` の変更（1ファイル）

## 受け入れ基準
- 7節に、計画単位の log 行の形 `- <日時> - draft→approved 人の指示: /plan approve <計画ID>`（タスク ID の位置は `-`）が書かれている。確認：`grep -n 'draft→approved 人の指示: /plan approve' docs/vault-spec.md` が7節内の行にヒットする
- 10節に、plan_guard が作業ツリーの計画票を `git show HEAD:` と比べて承認の裏付けを検査し、裏付けが無ければブロックすること、会話記録が読めない時は `additionalContext` で警告することが書かれている。確認：`grep -n 'additionalContext' docs/vault-spec.md` が10節内の行にヒットする
- 12節の判定表に、承認（draft→approved）の裏付け（メインセッションかつ会話記録の人の発言に `/plan approve <計画ID>`、それ以外は拒否、読めない時は許可）と、`~/.claude/projects/` 配下（会話記録）への書き込み拒否の2行が追記されている。確認：`grep -n '~/.claude/projects/' docs/vault-spec.md` が12節内の行にヒットし、`grep -n '/plan approve' docs/vault-spec.md` が12節内の行にヒットする
- 4節のマージの記述に、`gh pr merge`・`glab mr merge`・`claude` が `.claude/settings.json` の deny で止められることが書かれている。確認：`grep -n 'glab mr merge' docs/vault-spec.md` が4節内の行を含む
- 見出し行（`## ` 始まり）を追加・変更・削除していない。確認：`git diff -- docs/vault-spec.md | grep -E '^[+-]#'` の出力が空

## 決定済み
- 12節の表への追記は、既存の2行の後・「上記に該当しない」行の前に置く。表の列構成（状況／判定）は変えない
- 人の発言の定義（`type` が `user`・`message.content` が文字列・`isMeta` が真でない）、コマンドの一致規則（スラッシュコマンド形式と文形式・計画 ID は完全一致）、「読めない」の定義（`transcript_path` 無し・ファイル無し・全行が JSON でない・人の発言が1件も無い）を12節に1か所だけ書き、10節はそれを参照する形にする
- 会話記録の形式が Claude Code の公開仕様ではなく、変わりうること（形式の変化は smoke.sh のサンプルで検知する）を12節に1行書く
- `Bash(claude *)` の deny の理由（入れ子で `claude -p "/plan approve ..."` を起動して子セッションの会話記録に人の発言を偽造するのを防ぐ）を書く
- blocked の解除（`/plan unblock`）と、2節の「`blocked→todo` は人のみ」の記述はここでは変えない（D-010 フェーズ5）
- 記述は実装（T-02〜T-05 の成果物）と食い違わないこと。creator は実際のフックのコードと SKILL.md を読んで書く。食い違いに気づいたら書き換えずに blocked にして question に書く
- 2節・3節・13節など上記以外の節は変えない
