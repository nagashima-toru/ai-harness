# T-05 docs/runbook.md に haiku を試して sonnet と比べる手順を書く

## 目的
`docs/runbook.md` に、`HARNESS_CREATOR_MODEL=haiku` で計画を回し、`scripts/model_stats.py` と `scripts/usage_stats.py` の出力を sonnet の時と比べる手順を書く。

## 入力
- `vault/designs/D-013.md` の「フェーズ3 creator のモデルの切り替えと計測」（ゴール文4・受け入れ基準の候補の5行目・決定済みの「haiku でどの計画を試すかは人が決める」）
- `docs/runbook.md`（0節・1節のモデルの選び方、3節「キューを回す」の無人実行、5節の `model_stats.py` の記述、7節、「困ったとき」）
- `.claude/skills/run/SKILL.md`（T-03 で入った手順3の `HARNESS_CREATOR_MODEL` の扱い）
- `scripts/usage_stats.py`（T-02 の docstring）・`scripts/model_stats.py`（docstring）

## 成果物
- `docs/runbook.md`（1ファイル）

## 受け入れ基準
- 7節と「困ったとき」の間に `## 8. creator のモデルを比べる` の見出しがある：`grep -c '^## 8. creator のモデルを比べる$' docs/runbook.md` の出力が `1`
- 8節に、`HARNESS_CREATOR_MODEL=haiku` を設定して `/run`（対話）か `python3 scripts/run_unattended.py`（無人）で計画を回す手順と、run の中で `echo "${HARNESS_CREATOR_MODEL:-}"` で値が効いていることを確かめられることが書かれている（Read で確認）
- 8節に、計画が終わった後に `python3 scripts/model_stats.py` で haiku と sonnet の行（1回目 PASS 率・平均 attempt・blocked 率・指摘あり率）を比べ、`python3 scripts/usage_stats.py --plan <計画ID>` で haiku の計画と sonnet の計画の creator の行（呼び出し回数・トークン数・所要時間）を比べる手順が、コマンドの形で書かれている（Read で確認）
- 8節に、`usage_stats.py` の model 列は完全なモデル ID で log の alias と表記が違うこと、どの計画で試すかは人が決めること、元に戻すには環境変数を外すことが書かれている（Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 新しい節は `## 8. creator のモデルを比べる` とし、`## 7. ハーネス自体の更新を取り込む` の後、`## 困ったとき` の前に置く。この見出しは文字どおり書く（受け入れ基準1で grep する）
- 環境変数の渡し方の例：対話は `HARNESS_CREATOR_MODEL=haiku claude`（セッションの起動時に設定する。起動後に変えても run の Bash には効かない場合があるので、起動し直す）、無人は `env HARNESS_CREATOR_MODEL=haiku python3 scripts/run_unattended.py`（ラッパーは環境変数を子に引き継ぐ）
- 比べ方の例：`python3 scripts/model_stats.py` の出力で `haiku` と `sonnet` の行を見比べる。`python3 scripts/usage_stats.py --plan <haiku で回した計画ID>` と `python3 scripts/usage_stats.py --plan <sonnet で回した計画ID>` の creator の行を見比べる。archive 済みの計画は5節と同じく log や会話記録を引数で明示する
- 比べる対象は creator だけ。verifier・planner のモデルは変えない（0節・1節の「creator・verifier は sonnet のまま」は、「creator は8節の手順で試せる」旨の一言を添える程度にとどめ、それ以上は変えない）
- haiku が受け付けられない値などで creator の呼び出しが失敗した時は、run が止まって報告する（SKILL.md 手順3）ことを一言書く
- どの計画で試すか・採用するかの判断基準は書かない（人が決める。設計の決定済み）
- 0〜7節の既存の手順と「困ったとき」の表は、上の一言以外は変えない。`scripts/`・`.claude/`・`docs/vault-spec.md` は変えない
