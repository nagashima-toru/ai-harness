# T-01 run スキルにハーネス振り返り手順を追加する

## 目的
`.claude/skills/run/SKILL.md` の手順7（全タスク `done` → PR 作成）の直後に「ハーネス振り返り」手順を追加し、直近の計画実行で気づいたハーネス自体（`.claude/` のスキル・エージェント定義・フック、`vault/rules/`）への構造的な改善点があれば `gh issue create` で起票する仕組みを定義する。

## 入力
- `vault/designs/D-004.md`（決定事項・フェーズ1のゴール文・受け入れ基準の候補・決定済み・今回やらないこと）
- `.claude/skills/run/SKILL.md`（現行の手順7「次へ・完了」の直後に追記する）
- `docs/vault-spec.md` の「11. ルール」「12. agent_write_guard フックの改ざん防止判定」（creator・verifier の書き込み制約の正本。変更しないことを確認するため）

## 成果物
- `.claude/skills/run/SKILL.md`（1ファイル。既存の手順1〜7への追記のみで、削除・書き換えは行わない）

## 受け入れ基準
- `grep -n "ハーネス振り返り" .claude/skills/run/SKILL.md` がヒットし、その行番号が手順7（`## 7. 次へ・完了`）の見出し行の行番号より大きい
- `grep -n "gh issue create" .claude/skills/run/SKILL.md` と `grep -n "フックの誤検知" .claude/skills/run/SKILL.md` が両方ヒットする（「構造的な改善点があれば `gh issue create` で起票し、無ければ何もしない」という条件と、対象の具体例が明記されていることの確認）
- `grep -n "harness-improvements" .claude/skills/run/SKILL.md` がヒットする（`gh issue create` 失敗時に `vault/harness-improvements/<計画ID>.md` へ提案内容を書き残し、成功時はこのファイルを作らないことが明記されていることの確認）
- `grep -n "オーケストレーター" .claude/skills/run/SKILL.md` がヒットし（実施主体の明記）、`git diff main -- .claude/agents/creator.md vault/rules/` の出力が空である（creator・verifier の役割・書き込み制約を変更していないことの確認）
- `git diff main -- .claude/skills/run/SKILL.md | grep -E '^-[^-]'` の出力が空である（既存の手順1〜7・PR 作成手順を削除・書き換えず、追記のみであることの確認）

## 決定済み
- 振り返りの対象は「構造的な問題」（スキル手順の分かりにくさ、フックの誤検知・見落とし、ルール文書の過不足など、繰り返し発生しうる問題）に限定する。軽微な言い回し修正・タイポは対象外と明記する
- 頻度は「あれば書く」。毎回 must にしない。気づきが無ければ何もしない（issue も作らず、ログにも残さない）ことを明記する
- issue のタイトル・本文フォーマットは自由（「気づいたこと」「該当箇所」「提案」が分かる程度であればよい）。新しいテンプレートファイルは作らない
- `vault/harness-improvements/<計画ID>.md` は `gh issue create` 失敗時のみ作成する。issue 化に成功した場合はこのファイルを作らないことを明記する。このファイルはタスクの5状態遷移の対象ではない
- PR 本文には改善提案セクションを追加しない。既存の `gh pr create` 呼び出し手順（手順7の内容）自体は変更しない
- 実施主体は run のオーケストレーター（メインセッション）。`.claude/agents/creator.md`・`vault/rules/creator/`・`vault/rules/verifier/` は変更しない
- 起票された issue の自動トリアージ（ラベル付け・アサイン等）の仕組みは作らない（今回の範囲外）
- git コミットは行わない（この計画の受け入れ基準にコミットは含まれていないため、`vault/rules/common/git.md` の「受け入れ基準に含まれている場合だけ行う」に従う）
