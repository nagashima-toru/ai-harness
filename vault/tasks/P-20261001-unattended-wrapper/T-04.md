# T-04 run SKILL.md「ハング時の復旧」節に無人実行時のラッパーの記述を追記する

## 目的
無人実行ではハングをラッパーが止め、次回の `/run` が再開手順で続きから進むことを run スキルに明記し、人が TaskStop で止める既存の手順と区別する（D-010 フェーズ7、issue #79）。

## 入力
- `.claude/skills/run/SKILL.md`「ハング時の復旧」節（`## 5.` の後ろ、`## 6.` の手前）と手順2.2（フェーズ6で書き換え済みの再開手順）
- `scripts/run_unattended.py`（T-01 の成果物）
- `vault/designs/D-010.md` フェーズ7のゴール文と決定済み

## 成果物
- `.claude/skills/run/SKILL.md` の変更（1ファイル。「ハング時の復旧」節の範囲）

## 受け入れ基準
- 「ハング時の復旧」節に、無人実行（cron・CI）では `scripts/run_unattended.py` がタイムアウトで止める旨がある。確認：`grep -n 'run_unattended.py' .claude/skills/run/SKILL.md` が同節の行にヒットする
- 止められた後は、次回の `/run` が手順2.2の再開手順で続きから再開する旨がある。確認：`grep -n '手順2.2' .claude/skills/run/SKILL.md` が同節の行にもヒットする
- 対話実行では従来どおり人が TaskStop で止め、既存の手順1・2（creator・verifier のハング復旧）が変わっていない。確認：`git diff -- .claude/skills/run/SKILL.md` の削除行（`-` で始まる行、`---` を除く）が無い、または見出し・番号付き手順の行を含まない
- 変更が「ハング時の復旧」節の範囲に収まる。確認：`git diff -- .claude/skills/run/SKILL.md` の `@@` 行が同節（`## ハング時の復旧` から `## 6.` の手前）に収まることを目視で確認する
- `bash scripts/smoke.sh` の最終行が `fail=0` になる

## 決定済み
- 検査対象ファイルの範囲：変更してよいのは `.claude/skills/run/SKILL.md` と、このタスク票自身（`vault/tasks/P-20261001-unattended-wrapper/T-04.md` の「進捗」）だけ。宣言外ファイルの変更は verifier が `git status --porcelain` で検査する（`vault/log/`・`vault/verdicts/`・計画票は run が更新するので除外）。手順2.2・手順3・手順6は変更しない。`docs/runbook.md`・`scripts/run_unattended.py`・フック・`.claude/settings.json` も変更しない
- 追記の位置は同節の既存の段落・手順1・2の後（節の末尾）に、新しい段落として足す。既存の文は削除・書き換えしない
- 書く内容：無人実行（`python3 scripts/run_unattended.py` を cron・CI から呼ぶ場合）では、`HARNESS_RUN_TIMEOUT`（既定 3600 秒）でラッパーがプロセスグループごと止め、終了コード124で終わる。TaskStop を待たない。止められた後の復旧は手順2.2（フェーズ6の再開手順：doing は中断を1回の試行として attempt+1、review は記録行から worktree を復元）が次回の `/run` で行う。同じ地点で止まり続けても `HARNESS_MAX_ATTEMPTS` で blocked になる
- ラッパーは vault のファイルに書かない（log への追記は次回の `/run` のオーケストレーターが再開手順の中で行う）と書く
- 対話実行（人が `/run` を打つ場合）の運用は変えない。「15分」の目安・手順1・2の内容は変えない
- Agent 呼び出しをバックグラウンドで監視する方式は書かない
