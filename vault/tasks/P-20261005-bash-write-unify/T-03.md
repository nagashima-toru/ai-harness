# T-03 done 判定・is_git_commit_command・ALLOWED 判定を bash_write_targets に載せ替える

## 決定済み
- `bash_write_targets(cmd, root)` の仕様・メモ化は T-02 のまま変えない（戻り値 `(parsed, writes)`、解析できない時の kind は `legacy-redirect`・`legacy-write`・`legacy-path`・`legacy-unknown`）。呼び出し回数はメモ化で1回に収める（`main` で1度計算して渡す形に変えなくてよい）。`main` 内で root を変えて呼ばない
- `is_git_commit_command(cmd, root=None)`：`parsed, writes = bash_write_targets(cmd, root)`。`parsed` なら `any(v == "git-commit" for v, _ in writes)`。解析できない時は今どおり `GIT_COMMIT_PATTERN`・`GIT_PREOPT_COMMIT_PATTERN` を `cmd` に当てる（候補パスの抽出ではないので和集合化の対象外。`git -C . commit` は `BASH_WRITE_PATTERNS` に一致しないため、`writes` が空かどうかで判定してはいけない）
- `find_done_task_write` の Bash 分岐
  - 解析できた時：今どおり `git-add`・`git-commit` を除いた空でない target
  - 解析できない時：`writes` が空なら None（書き込み動詞なし）。`is_git_stage_or_commit_only(cmd)` が真なら None（今どおり）。それ以外は全ての空でない target を候補にする
  - 候補ごとに今どおり `normalize(cand.rstrip(")\"'`"), root)` してから `match_task_or_verdict_path`・`plan_task_status` で判定する
- `main` の ALLOWED 判定（verifier・planner の Bash）
  - 解析できた時：今の (1)〜(5) の順のまま、`parsed` の代わりに `bash_write_targets` の `writes` を使う。`cp`/`mv` の宛先を `extract_bash_write_targets(cmd)` で求める箇所は今どおり（解析の呼び直しではないので残してよい）
  - 解析できない時（許可条件は今のものを残し、和集合の全候補にもパスの条件を課す。今より許可が増えないこと）
    - `writes` が空なら許可（書き込み動詞なし。今どおり）
    - 「root の外だけ」の許可：kind が `legacy-write` の候補が1つ以上あり、かつ全ての候補（kind を問わない。`legacy-unknown` の空文字は root の外とみなさない）が root の外なら許可
    - 「ALLOWED 配下へのリダイレクトだけ」の許可：kind が `legacy-redirect` の候補が1つ以上あり、全ての候補が ALLOWED のパス配下で、`cmd` が `DESTRUCTIVE_BASH_PATTERN` に一致しなければ許可
    - どれにも当たらなければ拒否（メッセージは今と同じ）
  - `masked_cmd` と、`main` 内のリダイレクトの正規表現 `re.findall(r">{1,2}...` は不要になるので消す
- 挙動が変わる例（変更前は許可、変更後は拒否）は、少なくともフィクスチャの `change-example`（verifier の `python3 -c "open('vault/tasks/P-FX/T-02.md')" > /tmp/x.txt`）。ALLOWED 判定に和集合の候補を使った帰結で、D-011 の「拒否する側に倒す」に当たる（計画票「人への質問」1）。他にも挙動が変わる形に気づいたら、「進捗」に「変更前→変更後」の形で書く（PR 本文と T-04・T-05 が使う）
- モジュール docstring（20〜22行・32行・43〜44行あたり）の「解析できない形は従来の判定（BASH_WRITE_PATTERNS 等）に落とす」趣旨の文を、「`bash_write_targets` が1度だけ計算し、解析できない時は4通りの従来判定の候補の和集合を返す。各判定はそれをパスで絞り込む」趣旨に直す。`is_git_stage_or_commit_only` の docstring の「従来の判定に進む」は変えなくてよい
- 変えないもの：`analyze_bash_writes`・`extract_bash_write_targets`・`is_git_stage_or_commit_only`・`bash_write_targets`・T-01 のパターン定義・T-02 で書き直した3つの判定、判定の順序・deny のメッセージ
- `scripts/smoke.sh`・`docs/vault-spec.md`・`_hooklib.py`・他のフックは変更しない（smoke は T-04、docs は T-05）
- 既存の smoke が落ちた場合は、smoke.sh を直さず blocked にして、落ちたケース名・変更前と変更後の判定・原因を question に書く（期待値を変えるかは人が決める）
