## 決定済み
- vault-spec の2節、68行付近の「worktree とブランチの検証は …」の箇条の直後に、新しい箇条を1つ足す。書くこと：
  - 呼び出しの形 `bash scripts/add_worktree.sh <PLAN_HEAD>`（この文字どおり）。run のメインの作業ツリーで実行する
  - `<PLAN_HEAD>` を40桁の sha に解決し、`<ルート>/.claude/worktrees/agent-<8桁の16進>` にブランチ `worktree-agent-<同じ8桁>` で `git worktree add` する。今の HEAD と同じかは見ない（起点を明示する）。名前の形は Agent ツールが作るものと同じなので、上の箇条の検証・`scripts/discard_worktree.sh`・`--resume-worktree` の記録行をそのまま使える
  - 標準出力は成功時だけ1行 `path=<realpath> branch=<ブランチ名> plan_head=<sha>`。コミットはしない
  - 終了コードは次の文言をこのまま書く：「終了コードは 0（作った）・1（`<PLAN_HEAD>` を commit に解決できない・git リポジトリの外・名前が5回続けて当たった・`git worktree add` の失敗）・2（引数の誤り）」
  - 作る理由：Agent ツールの worktree 隔離に任せると、`worktree.baseRef` が `head` でも計画ブランチ以外から切られることがあった（Issue #209）
- vault-spec の79行付近の `/run` の箇条の「場面と遷移先の対応」の前か後ろに、「creator の worktree は手順3で `scripts/add_worktree.sh` で作り、パスを prompt で渡す（transition.py は通さない）」の趣旨を1文足す
- `isolation: "worktree"` の語は vault-spec にも decisions にも書かない（T-04 の基準が、この語のある文書を run/SKILL.md の1つだけに限っているため）。Agent ツールの機能は「Agent ツールの worktree 隔離」と書く
- decisions の表の末尾に1行足す。日付の列は `2026-10-21`、「何を」の列に次の文言を含める：「creator の worktree は Agent ツールの worktree 隔離に頼らず、run が `scripts/add_worktree.sh` で作る（Issue #209）（P-20261021-worktree-base-and-criterion-pipe）」。「なぜ」の列は「worktree 隔離の分岐元は実行環境の状態に左右され、計画ブランチ以外から切られて blocked が続いた。起点をスクリプトで明示すれば仕組みで保証でき、名前を Agent ツールと同じ形にすれば既存の検証・破棄・引き継ぎをそのまま使える」の趣旨で書く
- decisions の既存の行（2026-10-12 の `SCRIPTS_FILES`（今ある21本）など）は変えない
- `.claude/settings.json` の `worktree.baseRef` は変えない。docs/install.md の baseRef の説明も変えない（導入先へのマージは続けるため）
