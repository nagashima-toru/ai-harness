# T-0037 `--update` フラグを実装する（未編集は上書き・編集済みはスキップして報告）

## 目的
`scripts/install.sh --update <target-dir>` を実装し、`.claude/harness-manifest.json` と照合して
未編集なファイルは上書き、利用者が編集したファイルはスキップして一覧報告する。上書きしたファイル
のマニフェストの記録も更新する。

## 入力
- T-0036 で追加されたマニフェスト書き込み・対象パス列挙ロジックと `.claude/harness-manifest.json`
  の形式
- `vault/designs/D-001.md`「## フェーズ1」の決定事項（`--update` の挙動、マニフェスト無しの扱い）

## 成果物
- `scripts/install.sh`（変更）

## 受け入れ基準
- install 先の `.claude/hooks/stop_gate.py` を書き換えずに `bash scripts/install.sh --update <dst>`
  を再実行すると、`diff <src>/.claude/hooks/stop_gate.py <dst>/.claude/hooks/stop_gate.py` が差分
  なしで終わる
- install 先の `vault/rules/common/roles.md` に1行足してから `--update` で再 install すると、標準
  出力に `skip (edited)` と `vault/rules/common/roles.md` の両方が含まれ、足した1行が
  `<dst>/vault/rules/common/roles.md` に残っている
- `--update` で上書きされたファイル（例 `docs/vault-spec.md`）について、上書き後のマニフェストの
  ハッシュが dst の実ファイルの現在のハッシュと一致する。確認コマンド:
  `python3 -c "import hashlib,json;m=json.load(open('<dst>/.claude/harness-manifest.json'))['files']['docs/vault-spec.md'];print(m==hashlib.sha256(open('<dst>/docs/vault-spec.md','rb').read()).hexdigest())"`
  が `True`
- マニフェストが存在しない `<dst>`（初回 install を経ずに手動で用意したディレクトリなど）に対して
  `--update` を実行すると、既存ファイルはすべて `skip (edited)` として報告され、上書きされない
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（新規ケース込み）

## 決定済み
- `--update` はフラグ列に追加する（`--no-claude-md` と同じ並び：`<target-dir>` より前に置く）。
  `--update` と `--no-claude-md` は併用できる。usage 文言も更新する
- `--update` 指定時、T-0036 の対象パス列（`.claude/hooks/*.py` 等、決定済みの12種別。
  `scripts/merge_settings_json.py` と `.claude/settings.json` はまだ対象外。T-0039 で追加）の各ファ
  イルについて、ファイル単位で次のように判定する：
  1. dst にファイルが無ければ新規として src からコピーし、マニフェストに追加して
     `copy <path>` を出力する
  2. dst にあり、マニフェストに記録済みのハッシュと dst の現在のハッシュが一致（未編集）すれば
     src の内容で上書きし、マニフェストのハッシュを更新して `update <path>` を出力する
  3. dst にあり、マニフェストが無い、またはハッシュが不一致なら「編集済み」とみなしスキップし、
     `skip (edited) <path>` を出力する（上書きしない。マニフェストの当該ハッシュも書き換えない）
- マニフェストファイル自体（`.claude/harness-manifest.json`）が無いインストール先に `--update` した
  場合：dst に既にあるファイルはすべて「編集済み」とみなし `skip (edited)` で全件報告する。dst に
  無い新規ファイルは通常どおり複製し、その時点のハッシュからマニフェストの記録を作り始める
- 判定はファイル単位で行う（`.claude/hooks/` などディレクトリ単位でまとめて判定しない）
- 出力の書式：新規複製は `copy <path>`、上書きは `update <path>`、スキップは `skip (edited) <path>`
  （既存の `skip  (exists) <path>`＝従来の `copy_if_absent` の出力とは文言を変え、両者を区別できる
  ようにする）
- `--update` を付けない従来の呼び出しは T-0036 の挙動（`copy_if_absent` + マニフェスト記録）のまま
  変更しない

## 進捗
- 読んだルール: roles.md, creator.md
- `scripts/install.sh` に `--update` を実装した。usage を `USAGE` 変数に括り出して
  `[--update] [--no-claude-md] <target-dir>` に更新。`--no-claude-md` と併用できる
- T-0036 の `manifest_paths()` をファイル前方（`copy_if_absent` の直後）へ移動し、更新パスから
  使えるようにした。更新パスは**通常の複製ループより前**に走らせ、そこで処理したパスを
  `HANDLED_LIST` に記録して `copy_if_absent` の対象から外す。こうしないと、更新パスが扱うべき
  ファイルを copy_if_absent が先に触ってしまい判定がずれる
- 判定は決定済みのとおりファイル単位：dst に無い→`copy <path>`／マニフェストのハッシュと dst が
  一致→上書きして `update <path>`／マニフェストが無いか不一致→`skip (edited) <path>`
- スキップしたパスは `SKIPPED_LIST` に記録し、最後のマニフェスト書き込みで**既存の記録を据え置く**
  （今回配っていないため）。それ以外は T-0036 どおり src のハッシュを書く
- 出力の空白は決定済みに合わせ `copy <path>` / `update <path>` / `skip (edited) <path>` の1スペース。
  従来の `skip  (exists) <path>`（2スペース）と区別できる
- 受け入れ基準の確認コマンドを一時ディレクトリで実行し、5件すべて通した
  - 未編集で `--update` → 23件すべて処理、`diff` 差分なし
  - `roles.md` に1行足して `--update` → `skip (edited) vault/rules/common/roles.md`、足した行は残る
  - 上書きされた `docs/vault-spec.md` のマニフェスト＝dst の現在ハッシュ＝True
  - マニフェストを消して `--update` → 既存22件すべて `skip (edited)`、`update` 行は0、ハッシュ不変
  - `bash scripts/smoke.sh | tail -1` → `smoke: pass=77 fail=0`
- `scripts/smoke.sh` に `== install.sh --update ==` 節を追加（7ケース、(j)(k)(l)）。既存ケースは変更なし
- 補足：従来の複製対象に `scripts/install.sh` 自身は入っていなかったため、初回 install 直後の
  `--update` では install.sh だけが `copy` になる（他22件は `update`）。マニフェストの対象パス列
  （T-0036 で確定）に install.sh が含まれているため、`--update` で初めて配られる
