## 目的
作成エージェント（creator）だけに渡す、git 運用の具体的な手順（ブランチ・コミット・PR のタイミングと例外時の振る舞い）を定める。原則の理由は `vault/rules/common/git.md` に譲る。

## ルール
- ブランチを切るタイミング：`/plan` 実行時に人が指示してブランチ（`work/<計画IDの英小文字>`）が作られている。作成エージェントは自分でブランチを切らない・切り替えない
- コミットのタイミング：作業ステップごと（例：タスクの成果物を書いた直後、計画票やタスク票の状態を更新した直後）に、小さくコミットする
- PR を作るタイミング：計画票の全タスクが `done` になった時点で `gh pr create` までを行う。それより前に PR を作らない
- 例外時の振る舞い：`git commit`/`git push` がコンフリクトや拒否で失敗した場合、自己判断で解決しようとせず、対象タスクを `blocked` にし question に状況（コマンドとエラーの要点）を書いて止まる

## 確認方法
- `bash scripts/rules.sh creator` の出力に `vault/rules/creator/git-workflow.md` が含まれるか
- コミットログが作業ステップ単位に分かれているか（`git log --oneline` で1コミット1変更になっているか）
- `main` に直接コミットしていないか
- PR が計画の全タスク完了後にだけ作られているか
