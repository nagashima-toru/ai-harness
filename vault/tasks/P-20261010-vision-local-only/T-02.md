# T-02 install.sh の --no-claude-md の新規作成でもマーカーブロックだけを置く

## 目的
`scripts/install.sh` の `--no-claude-md` で導入先に `CLAUDE.md` が無い時の経路（今は `copy_if_absent "$SRC/CLAUDE.md" "$DST/CLAUDE.md"` で src 全体を複製している）でも、マーカーブロックだけを置くようにし、ハーネス側の `CLAUDE.md` のマーカーの外の行と `docs/vision.md` がどの経路でも導入先に届かないことを smoke で確かめる。

## 入力
- `scripts/install.sh`（冒頭のコメント・`# CLAUDE.md（既定は…）` の節・`vault/rules/` の複製の節）
- `scripts/merge_claude_md.py`（T-01 で `extract_block` が入り、マーカーブロックだけを使うようになった）
- `scripts/smoke.sh` の `== install.sh の CLAUDE.md 扱い ==` 節（`(e)`〜`(g)`）

## 成果物
- `scripts/install.sh`（主な成果物。1ファイル）
- `scripts/smoke.sh`（`== install.sh の CLAUDE.md 扱い ==` 節に `(in-out)` の検査を足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (in-out) '` が `5`
- `bash scripts/smoke.sh 2>&1 | grep -c '^  NG '` が `0`（既存の `(e)` の「--no-claude-md → CLAUDE.md は変更されない」を含め、全検査が通る）
- `grep -n 'copy_if_absent "$SRC/CLAUDE.md"' scripts/install.sh` の出力が空（src の `CLAUDE.md` 全体を複製する経路が残っていない）
- `grep -c 'note  CLAUDE.md は既にあります。.*のマーカーブロック' scripts/install.sh` が `1`（既存の `CLAUDE.md` への案内が、src 全体ではなくマーカーブロックの追記を求める）
- `bash -n scripts/install.sh` が終了コード `0`

## 決定済み
- `--no-claude-md` で `$DST/CLAUDE.md` が無い時は、`python3 "$SRC/scripts/merge_claude_md.py" "$SRC/CLAUDE.md" "$DST/CLAUDE.md"` を呼ぶ（既定の経路と同じ呼び出し。出力は `create <dst>` になり、従来の `copy  CLAUDE.md` から変わってよい）。`$DST/CLAUDE.md` がある時は今どおり何も書かず案内だけを出す
- その案内の文言は `note  CLAUDE.md は既にあります。$SRC/CLAUDE.md のマーカーブロック（<!-- ai-harness:begin v1 --> 〜 <!-- ai-harness:end -->）を追記してください` にする（先頭の `note  CLAUDE.md は既にあります。` は `docs/install.md` が引用しているので変えない）
- 冒頭のコメントの CLAUDE.md の説明（`# 例外は CLAUDE.md で、…`・`# --no-claude-md を付けると…`）に、「src の CLAUDE.md のマーカーブロックだけを使い、マーカーの外の行（ハーネス本体だけが読む `@docs/vision.md` など）は配らない」「--no-claude-md で CLAUDE.md が無い時もマーカーブロックだけを置く」の趣旨を書き、「マーカーブロック」という語を使う
- `vault/rules/` の複製の対象（README と .gitkeep の固定の列挙）と `manifest_paths` は変えない。`docs/vision.md` も配る対象に足さない（今も配っていないことを smoke で確かめるだけ）
- smoke の `(in-out)` は次の5件にする。名前の先頭を `(in-out) ` にし、`expect_eq` を使う。導入先は `smoke_tmpdir` で新しく作る（既存の `$ITMP` とは別。`CLAUDE.md` の無い空のディレクトリから始める）
  1. `(in-out) 既定の install で作った CLAUDE.md に @docs/vision.md の行が無い`（`grep -c '^@docs/vision\.md$'` が `0`）
  2. `(in-out) --no-claude-md で新規に作った CLAUDE.md がマーカーブロックだけになる`（中身が `$ROOT/CLAUDE.md` に `extract_block` を当てた結果と一致する。比較の値は `python3 -c` で `$ROOT/scripts` を import して作ってよい）
  3. `(in-out) --no-claude-md で新規に作った CLAUDE.md に @docs/vision.md の行が無い`
  4. `(in-out) docs/vision.md が配られない`（既定の install 後の導入先で `[ -e <path> ] || [ -L <path> ]` が偽）
  5. `(in-out) vault/rules/common/vision.md が配られない`（同上。壊れたシンボリックリンクも見落とさないよう `-L` も見る）
- 1・3 は `$ROOT/CLAUDE.md` に `@docs/vision.md` が無い今は自明に通る。T-03 で行が足された後に意味を持つ。5 も T-04 の後に意味を持つ
- smoke の既存の検査の名前・期待値は変えない。`rm -rf` を新たに書かない
