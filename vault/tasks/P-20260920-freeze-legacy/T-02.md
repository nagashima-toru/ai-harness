# T-02 scripts/install.sh を新構造に合わせて改訂する

## 目的
`scripts/install.sh` が `vault/todo.md`・`vault/log/queue.md` を生成しないようにし、新方式の空ディレ
クトリ構成（`vault/{plans,tasks,verdicts,log,designs,archive,templates,rules}`）を作るようにする。

## 入力
- `scripts/install.sh`（改訂対象。特に冒頭コメント、`vault/todo.md` 生成部分（128〜147行付近）、
  `for d in tasks plans verdicts log templates archive` の行）
- `vault/designs/D-001.md` の「決定済み」（`scripts/install.sh が作る空ディレクトリは
  vault/{plans,tasks,verdicts,log,designs,archive,templates,rules}。初期状態の計画票は配らない`）
- `docs/vault-spec.md` の「1. ディレクトリ」節
- `scripts/smoke.sh` の `== install.sh の CLAUDE.md 扱い ==`・`== install.sh のマニフェスト ==`・
  `== install.sh --update ==` の各セクション（`vault/todo.md` の実在を前提にした assertion が無いこ
  とを確認済み。変更不要）

## 成果物
- `scripts/install.sh`

## 受け入れ基準
- `vault/todo.md`・`vault/log/queue.md` を生成・言及するコードとコメントが消えている。確認：`grep -c 'todo.md' scripts/install.sh` と `grep -c 'queue\.md' scripts/install.sh` がともに0
- 作成する空ディレクトリの列に `designs` が加わっている。確認：`grep -n 'for d in' scripts/install.sh` の出力に `designs` が含まれる
- 一時ディレクトリに新規 install した直後、`vault/todo.md` も `vault/log/queue.md` も存在しない。確認：`T=$(mktemp -d); bash scripts/install.sh "$T" >/dev/null; test ! -e "$T/vault/todo.md" && test ! -e "$T/vault/log/queue.md" && echo ok`
- 同じ install 先で `vault/{plans,tasks,verdicts,log,designs,archive,templates,rules}` の8ディレクトリが全部存在する。確認：`for d in plans tasks verdicts log designs archive templates rules; do test -d "$T/vault/$d" || echo "missing:$d"; done` が何も出力しない
- `bash scripts/smoke.sh | tail -1` に `fail=0` が含まれる

## 決定済み
- 作る空ディレクトリは `vault/{plans,tasks,verdicts,log,designs,archive,templates,rules}` の8つ。初期状態の計画票・タスク票は配らない（`/plan` が作る）
- `vault/rules/` 配下の複製対象（README・各役割 `.gitkeep`・標準ルール4本）は変更しない
- `manifest_paths` 関数は変更不要（`vault/todo.md`・`vault/log/queue.md` はもともとマニフェスト対象外だったため）
- 冒頭のコメント（使い方・複製するものの説明。1〜14行目付近）も `vault/todo.md` 前提の記述（「空の todo.md」「vault/todo.md が既にあれば残す」等）を新方式の説明に書き換える
- `scripts/smoke.sh` は変更しない（既存テストは `vault/todo.md` の実在を前提にしていないことを確認済み）

## 進捗
- 読んだルール: roles.md, creator.md（既読）
- 冒頭コメント（複製するもの・既存ファイルの扱い）を新方式向けに書き換え（`空の todo.md` の記述削除、
  「状態は `vault/plans/<計画ID>.md` が持つ（キューは無い）」を追加）
- `for d in tasks plans verdicts log templates archive` → `for d in plans tasks verdicts log designs
  archive templates rules` に変更（決定済みの8ディレクトリ、`designs`・`rules` を追加）
- `vault/todo.md`・`vault/log/queue.md` を生成する if ブロック（旧128〜151行）を削除。直後の
  `scripts/smoke.sh` 等の複製コメントに繋げた
- `manifest_paths`・`vault/rules/` 複製対象は決定済みのとおり無変更
- 受け入れ基準の確認コマンドを実行し、5件すべて通した
  - `grep -c 'todo.md'`=0 / `grep -c 'queue\.md'`=0
  - `for d in` 行に `designs` を含む
  - 新規 install 直後に `vault/todo.md`・`vault/log/queue.md` が存在しない → ok
  - `vault/{plans,tasks,verdicts,log,designs,archive,templates,rules}` の8ディレクトリ全部存在
  - `bash scripts/smoke.sh | tail -1` → `smoke: pass=95 fail=0`
