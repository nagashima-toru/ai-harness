# T-02 transition.py に review→done の verdict 検査と creator=/verifier= の自動付与を足す

## 目的
`scripts/transition.py` の review→done を、フェーズ1のフックと同じ条件（attempt が一致する正しい PASS の verdict がある）を満たす時だけ行えるようにし、verdict もコミットに含める。あわせて、遷移行のモデルの記録（`creator=`・`verifier=`）を `.claude/agents/<name>.md` の frontmatter から自動で付ける（D-012 フェーズ2）。

## 入力
- `vault/designs/D-012.md` の「フェーズ2」の決定済み（PASS の verdict の条件・モデルの記録）
- `scripts/transition.py`（T-01 の成果物）
- `.claude/hooks/_hooklib.py`（`done_rows_without_pass`・`frontmatter_value`）
- `docs/vault-spec.md` の7節（「実行したモデルの記録」）
- `vault/tasks/P-20261007-transition-basic/fixtures/try.sh`（確認用のフィクスチャ。T-06〜T-09 の verdict の条件は先頭のコメント）

## 成果物
- `scripts/transition.py`（T-01 で作ったファイルへの追記・変更だけ。ほかのファイルは変えない）

## 受け入れ基準
- 正しい PASS の verdict がある時は done にし verdict もコミットする：`bash vault/tasks/P-20261007-transition-basic/fixtures/try.sh std P-TEST T-06 done` の出力に `exit=0`・`new_commits=1`・`subject=P-TEST/T-06: review→done`・`commit_files=vault/log/P-TEST.md vault/plans/P-TEST.md vault/verdicts/P-TEST/T-06.json `・`plan_guard=allow` の行があり、table 節に `| T-06 | done | 1 | - | F | |`、log の最後の行が `T-06 review→done attempt=1 verifier=fx-verifier-model` で終わる
- PASS の verdict が無ければ拒否する：`try.sh std P-TEST T-09 done`（verdict 無し）／`try.sh std P-TEST T-07 done`（FAIL）／`try.sh std P-TEST T-08 done`（attempt 不一致）／`try.sh std P-TEST T-06,T-09 done` のどれも `exit=1`・`new_commits=0`・`plan_changed=no`・`log_changed=no` で、stderr 節に拒否した id（順に `T-09`・`T-07`・`T-08`・`T-09`）を含む（`try.sh` は1行目と同じパス）
- creator のモデルを付ける：`try.sh std P-TEST T-04 review` の log の最後の行が `T-04 doing→review attempt=1 creator=fx-creator-model` で終わり、`try.sh std P-TEST T-04 blocked --question q` の log の最後の行が `T-04 doing→blocked attempt=1 creator=fx-creator-model` で終わる
- verifier のモデルを付ける：`try.sh std P-TEST T-07 doing` の log の最後の行が `T-07 review→doing attempt=2 verifier=fx-verifier-model` で終わり、`try.sh std P-TEST T-07 blocked --question q` の log の最後の行が `T-07 review→blocked attempt=1 verifier=fx-verifier-model` で終わる
- モデルを付けない場合と補足の位置：`try.sh std P-TEST T-01 doing` の log の最後の行が `T-01 todo→doing attempt=1` で終わり、`try.sh std P-TEST T-04 review --no-model --note 中断から再開` の log の最後の行が `T-04 doing→review attempt=1 中断から再開` で終わり、`try.sh nomodel P-TEST T-04 review` の log の最後の行が `T-04 doing→review attempt=1` で終わり、`try.sh std P-TEST T-04 review --note 補足` の log の最後の行が `T-04 doing→review attempt=1 creator=fx-creator-model 補足` で終わる（いずれも `exit=0`）
- verdict の判定を複製せず `_hooklib.py` の関数を使う：`grep -cE '^def (validate_verdict|done_rows_without_pass)\(' scripts/transition.py` の出力が `0`、`grep -c '_hooklib.done_rows_without_pass(' scripts/transition.py` の出力が `1` 以上
- 既存の smoke が変わらず通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=529 fail=0`

## 決定済み
- T-01 で入れた review→done の暫定の拒否を消し、次の検査に置き換える：遷移する各 id について、タスク表の行（`_hooklib.parse_tasks` の dict）を写して status だけ `done` にしたもののリストを作り、`_hooklib.done_rows_without_pass(root, 計画ID, そのリスト)` を呼ぶ。戻り値が空でなければ、`[(id, 理由), ...]` を標準エラーに `[transition] <計画ID>/<id>: <理由>` の形で1件1行出し、何も変えずに終了コード1
- 複数の id のうち1つでも条件を満たさなければ、全部を変えない（T-01 の all-or-nothing と同じ）
- PASS の条件はフェーズ1と同じ（`done_rows_without_pass` の条件。verdict がある・JSON として読める・`task` が `<計画ID>/<id>`・attempt がタスク表と一致・result が PASS・`validate_verdict` が問題を返さない）。`validate_verdict`・`done_rows_without_pass` を transition.py に複製しない
- review→done のコミットには、計画票・log に加えて、遷移した各 id の `vault/verdicts/<計画ID>/<id>.json` を含める（`git add -- <パス...>` と `git commit ... -- <パス...>` の両方に足す）。run では verdict が未コミットで置かれる（フィクスチャも未追跡で置く）。ほかの id の verdict（未追跡の T-07.json など）はコミットに含めない
- モデルの記録：
  - doing→review・doing→blocked の行に `creator=<モデル>` を付ける
  - review→done・review→doing・review→blocked の行に `verifier=<モデル>` を付ける
  - todo→doing・doing→doing には付けない
  - 値は対象リポジトリ（`git rev-parse --show-toplevel`）の `.claude/agents/creator.md`・`.claude/agents/verifier.md` を読み、`_hooklib.frontmatter_value(text, "model")` で取る。スクリプトの置き場所側の agents ではない（フィクスチャの値は `fx-creator-model`・`fx-verifier-model`）
  - ファイルが無い・読めない・`model` が無い時は付けない（エラーにしない）
  - `--no-model` を指定した時は付けない（中断からの再開・ハング・worktree が無い時の行のため。`docs/vault-spec.md` 7節）
- log の行の形：`- <日時> <id> <旧>→<新> attempt=<n>[ creator=<m> | verifier=<m>][ <補足>]`。モデルが補足より前。補足は `--note` の値だけ（question は log に書かない。question は計画票の question 列にある）
- `--note`・question の `|`→`／`、改行→空白の置き換えは T-01 のまま
- 拒否条件・attempt の規則・終了コード・コミットの仕方など、T-01 で決めたほかの動きは変えない
- `scripts/smoke.sh`・`docs/vault-spec.md`・`.claude/skills/run/SKILL.md`・`.claude/hooks/`・`.claude/agents/` は変えない
- フィクスチャ `try.sh` は成果物ではない。変えない
