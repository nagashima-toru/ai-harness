# T-02 vcs_finish.sh に HARNESS_PR_BODY_FILE と HARNESS_PR_TITLE で本文とタイトルを渡す経路を足す

## 目的
run が作った PR 本文（verifier の指摘の節を含む）を PR/MR に載せられるように、`scripts/vcs_finish.sh` が環境変数 `HARNESS_PR_BODY_FILE`（本文のファイル）と `HARNESS_PR_TITLE` を受け取る経路を足す。未設定の時の動きは変えない。smoke にケースを足す。

## 入力
- `vault/designs/D-013.md` の「フェーズ2 verifier の指摘を見えるようにする」（受け入れ基準の候補・決定済み）
- `scripts/vcs_finish.sh`（`find_plan_body`・github と gitlab の分岐・先頭のコメント）
- `scripts/smoke.sh`（`== vcs_finish.sh ==` の節。`VF_BIN` の `gh`・`glab` のスタブ、`VF_REPO`・`VF_REPO2`、`expect_vf`・`vf_body_check`）

## 成果物
- `scripts/vcs_finish.sh`（主な成果物）
- `scripts/smoke.sh`（`== vcs_finish.sh ==` の節へのケースの追加）

## 受け入れ基準
- GitHub で `HARNESS_PR_BODY_FILE` と `HARNESS_PR_TITLE` が設定され引数が無い時、`gh` に渡る引数が `pr create --title <HARNESS_PR_TITLE> --body-file <HARNESS_PR_BODY_FILE>` だけになる：`bash scripts/smoke.sh 2>&1 | grep -F 'ok   (vf-notes-1)'` の出力が1行
- GitLab で同じ時、`glab` に渡る引数が `mr create --title <HARNESS_PR_TITLE> --description <本文ファイルの中身> --yes` だけになる：`bash scripts/smoke.sh 2>&1 | grep -F 'ok   (vf-notes-2)'` の出力が1行
- `HARNESS_PR_TITLE` が無い時のタイトルが計画 ID になること、引数がある時は環境変数を無視してそのまま渡すこと、本文ファイルが読めない時は `gh` を呼ばずに終了コード2で終わることのケースが通る：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(vf-notes-[3-5]\)'` の出力が `3`
- 環境変数が未設定の時の動きが変わらない（既存のケースが名前を変えずに通る）：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(vcs_finish(-body)?\)'` の出力が `7`
- 先頭のコメントの使い方に `HARNESS_PR_BODY_FILE` と `HARNESS_PR_TITLE` の説明（引数が無い時だけ使う・タイトルの既定）が書かれている（Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 新しい経路を使うのは「引数が無く、かつ `HARNESS_PR_BODY_FILE` が空でない値で設定されている」時だけ。引数がある時は今どおり引数をそのまま渡し、環境変数は見ない。`HARNESS_PR_BODY_FILE` が未設定か空なら今の動き（`find_plan_body` → 無ければ `--fill`）のまま
- `HARNESS_PR_TITLE` は `HARNESS_PR_BODY_FILE` の経路でだけ使う。`HARNESS_PR_BODY_FILE` が無い時に `HARNESS_PR_TITLE` だけ設定されていても無視する（今の動きを変えない）
- タイトル：`HARNESS_PR_TITLE` が空でなければその値。無ければ計画 ID（`find_plan_body` と同じ方法で、現在のブランチ `work/<計画IDの英小文字>` に対応する `vault/plans/<計画ID>.md` を探す。計画 ID の探索部分を関数に切り出してよい）。計画が見つからない時は現在のブランチ名（`git rev-parse --abbrev-ref HEAD`）
- GitHub：`gh pr create --title "<タイトル>" --body-file "<HARNESS_PR_BODY_FILE>"`（ファイルのパスをそのまま渡す）
- GitLab：`glab mr create --title "<タイトル>" --description "<本文ファイルの中身>" --yes`（`glab` に本文ファイルを渡す引数が無いため中身を読んで渡す）
- 本文ファイルが無い・読めない（`[ -r ]` が偽）時は、`git push` の前に標準エラーに `vcs_finish.sh: HARNESS_PR_BODY_FILE が読めません: <パス>` を出し、終了コード2で終わる（`gh`・`glab` を呼ばない）。`none` の経路では本文を使わないので検査しない
- `none` の経路・ホスティングの判定・push の処理・`gh`/`glab` が無い時の127は変えない
- smoke のケース（`== vcs_finish.sh ==` の節の既存のケースの後に置く。名前は `(vf-notes-N)` で始める。既存の `VF_BIN` のスタブと `VF_REC` の記録の仕組みを使う）：
  - 本文ファイルは smoke の一時ディレクトリ（`$TMP` の下）に2行以上の中身で作る
  - (vf-notes-1)：`VF_REPO`（計画の無いリポジトリ）・github・`HARNESS_PR_BODY_FILE` と `HARNESS_PR_TITLE` あり・引数なし → 記録が `pr`・`create`・`--title`・<タイトル>・`--body-file`・<本文ファイルのパス> の6行と一致
  - (vf-notes-2)：`VF_REPO`・gitlab・同じ環境変数 → 記録が `mr`・`create`・`--title`・<タイトル>・`--description`・<本文ファイルの中身（複数行）>・`--yes` と一致
  - (vf-notes-3)：`VF_REPO2`（計画のあるリポジトリ）・github・`HARNESS_PR_BODY_FILE` だけあり → `--title` の次の行が `P-20990101-vf`
  - (vf-notes-4)：`VF_REPO2`・github・`HARNESS_PR_BODY_FILE` あり・引数 `--title T --body B` → 記録が `pr create --title T --body B` の6行（環境変数を無視）
  - (vf-notes-5)：`VF_REPO`・github・存在しないパスの `HARNESS_PR_BODY_FILE` → 終了コード2で、`VF_REC` が作られない
- 既存の7ケース（`(vcs_finish)` 4件・`(vcs_finish-body)` 3件）は変えない。新しいケースの環境変数が既存のケースに漏れないよう、サブシェルの中か `env` で渡す
- `scripts/pr_body.py` は変えない。`docs/`・`.claude/skills/` は変えない（T-04・T-05 で行う）
