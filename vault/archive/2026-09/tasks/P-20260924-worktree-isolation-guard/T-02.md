# T-02 worktree.baseRef を head にし run/SKILL.md 手順3.6を実態に合わせる

## 目的
`isolation: "worktree"` で作られる worktree の起点を、`/run` を実行する全セッションで計画ブランチ（`head`）にする既定設定をリポジトリ側に反映し、実際には存在しない「起点指定フィールド」を前提にしていた `run/SKILL.md` 手順3.6の記述を実態に合わせて書き直す。

## 入力
- `.claude/settings.json`（現状 `worktree` キーは無い。`permissions`・`hooks` の2トップレベルキーのみ）
- `.claude/skills/run/SKILL.md` 手順3.5〜3.6（分岐元の確認方法と、ずれていた場合の対処）
- `scripts/merge_settings_json.py`（`hooks`・`permissions.deny` のみをマージする仕様。`worktree` キーはこのスクリプトの対象外であることの確認用）
- GitHub Issue #20 の「問題2」本文（このタスク票の元になったゴール文に転記済み）

## 成果物
- `.claude/settings.json` と `.claude/skills/run/SKILL.md` の該当箇所（1PR分の関連する2ファイル変更）

## 受け入れ基準
- `.claude/settings.json` のトップレベルに `worktree.baseRef` が `"head"` として追加されている。確認コマンド: `python3 -c "import json;d=json.load(open('.claude/settings.json'));print(d.get('worktree'))"` の出力が `{'baseRef': 'head'}`
- 既存の `permissions`・`hooks` の内容が変わっていない。確認コマンド: `git diff -- .claude/settings.json` の差分が `worktree` キーの追加分のみで、`permissions`/`hooks` 配下に `+`/`-` の行が無い
- `run/SKILL.md` 手順3.6が、存在しない「Agent ツールの起点指定フィールド」を探す記述を削除し、`.claude/settings.json` の `worktree.baseRef: "head"` 設定に依存する旨、それでも分岐元がずれていた場合は自己判断で起点を上書きせず対象タスクを `blocked` にして question に状況を書く方針に更新されている。確認コマンド: `grep -n "起点を指定するフィールド" .claude/skills/run/SKILL.md` が0件、かつ `grep -n "baseRef" .claude/skills/run/SKILL.md` が1件以上
- `bash scripts/smoke.sh` の最終行が `smoke: pass=<N> fail=0` のままである（settings.json 変更による既存テストへの回帰が無い）

## 決定済み
- `worktree.baseRef` の値は `"head"` 固定とする（Issue #20 本文で回避策として使われた値と同じ）。`fresh` 等の他の値は扱わない
- `scripts/merge_settings_json.py` は `hooks`・`permissions.deny` のみをマージする既存仕様のままでよい。`worktree` キーを他リポジトリのインストール先へ伝播させる対応はこのタスクのスコープ外（計画票の「人への質問」に記載済み。別タスク化しない）
- `run/SKILL.md` 手順3.5（`git -C <worktree> merge-base --is-ancestor <PLAN_HEAD> HEAD` で分岐元を確認する記述）はそのまま残してよい。変更するのは手順3.6（ずれていた場合の対処）だけ
- 手順3.6の新しい対処：起点がずれていることを検知した場合、creator 呼び出しを自己判断でやり直す（起点を上書きする）のではなく、対象タスクの計画票の行を `blocked` にし、question に「worktree の分岐元が計画ブランチと一致しない（<確認コマンドの出力要点>）」のように状況を書く、という既存の blocked 運用（`vault/rules/common/roles.md` の「creator → 人」節）と同じ形にする
- コミットは行わない（受け入れ基準にコミットの指示が無いため）

## 進捗
- 読んだルール: vault/rules/common/git.md, vault/rules/common/roles.md, vault/rules/creator/creator.md, vault/rules/creator/git-workflow.md
- `.claude/settings.json` のトップレベルに `worktree": { "baseRef": "head" }` を追加した
- `.claude/skills/run/SKILL.md` 手順3.6を、存在しない「起点を指定するフィールド」を探す記述から、`worktree.baseRef: "head"` に依存する旨、ずれていた場合は自己判断で上書きせず対象タスクを `blocked` にして question に状況を書く方針（`vault/rules/common/roles.md` の「creator → 人」節と同じ運用）に書き換えた
- 確認コマンド実施結果：
  - `python3 -c "import json;d=json.load(open('.claude/settings.json'));print(d.get('worktree'))"` → `{'baseRef': 'head'}`（一致）
  - `git diff -- .claude/settings.json` → `worktree` キー追加の3行のみ（`+`）。`permissions`/`hooks` 配下に差分なし
  - `grep -n "起点を指定するフィールド" .claude/skills/run/SKILL.md` → 0件（exit=1）
  - `grep -n "baseRef" .claude/skills/run/SKILL.md` → 1件（33行目）
  - `bash scripts/smoke.sh` 最終行 → `smoke: pass=113 fail=0`
- コミットは行わない（決定済みの指示どおり）
