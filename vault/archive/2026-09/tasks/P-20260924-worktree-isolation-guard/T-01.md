# T-01 agent_write_guard.py の worktree root 解決と 2>&1 誤検知を修正する

## 目的
`.claude/hooks/agent_write_guard.py` が、worktree 内から呼ばれた場合でもその worktree のルートを基準に正しく相対パスを解決して `vault/verdicts/` 等への正当な書き込みを許可し、`2>&1` のような fd 複製をリダイレクト（書き込み）と誤検知して拒否しないようにする。

## 入力
- `.claude/hooks/agent_write_guard.py`（root 解決は `main()` の `root = os.environ.get("CLAUDE_PROJECT_DIR") or payload.get("cwd") or os.getcwd()` の行、誤検知対象は `BASH_WRITE_PATTERNS` の先頭要素）
- `scripts/smoke.sh`（`== agent_write_guard.py ==` セクション。`run_guard`/`expect_guard` ヘルパーと、末尾近くの main ブランチ判定テスト (i)〜(l) が `git init`/`git worktree` 相当の一時リポジトリを使う実例になっている）
- GitHub Issue #20 の「問題1」本文（このタスク票の元になったゴール文に転記済み）

## 成果物
- `.claude/hooks/agent_write_guard.py` の修正（1ファイル）と、`scripts/smoke.sh` への回帰テストケース追加

## 受け入れ基準
- `agent_write_guard.py` の root 解決が、Write/Edit/MultiEdit/NotebookEdit では対象 `file_path` の親ディレクトリを起点に、Bash では `payload.cwd` を起点に、それぞれ `git rev-parse --show-toplevel` で worktree のルートを優先的に求める（取得できない場合のみ既存の `CLAUDE_PROJECT_DIR → payload.cwd → os.getcwd()` の順にフォールバックする）
- `git worktree add` で作った一時 worktree 内の `vault/verdicts/<id>.json` への Write を、`CLAUDE_PROJECT_DIR` をメインチェックアウト側に向けたまま `agent_type: verifier` で許可することを検証する `scripts/smoke.sh` のテストケースが追加されている
- `BASH_WRITE_PATTERNS` の先頭要素（`>{1,2}` を含む正規表現）が `2>&1` のような `N>&M` 形式の fd 複製を書き込みと誤検知しない。`echo x 2>&1` を含む非書き込みコマンドが verifier/planner の Bash 制限下でも許可されることを検証する `scripts/smoke.sh` のケースが追加されている
- `bash scripts/smoke.sh` を実行した最終行が `smoke: pass=<N> fail=0` で終了コードが0である。確認コマンド: `bash scripts/smoke.sh; echo "rc=$?"` の出力末尾が `smoke: pass=<N> fail=0` と `rc=0`

## 決定済み
- root 解決の実装方針：対象パス（Write系は `file_path`、Bash は `payload.cwd`）から `git rev-parse --show-toplevel` を実行し、成功したらその出力を root として使う。失敗（非0終了・非 git ディレクトリ等）した場合のみ既存の `CLAUDE_PROJECT_DIR → payload.cwd → os.getcwd()` の優先順にフォールバックする。この変更で非 worktree・非 git のケースの挙動を変えないこと
- 誤検知対象の正規表現修正：`BASH_WRITE_PATTERNS` の `r"(^|[^<>])>{1,2}\s*\S"` を、直後に `&` が来る場合（`N>&M` の fd 複製）はリダイレクトとみなさないように変更する（例：`\s*(?!&)\S` のように否定先読みを足す）。`redirect_targets` 抽出用の正規表現 `r">{1,2}\s*([^\s;&|]+)"` は `&` を含む文字クラスの除外で既にこの種のターゲットを拾わない設計なので、変更するとしても後方互換を保つこと
- `rm`/`mv`/`git commit` 等、他の `BASH_WRITE_PATTERNS` の要素・既存の拒否判定（`vault/rules/` 改ざん防止、creator の拒否リスト、main への直接 commit 拒否）は変更しない
- `normalize()` のシグネチャ（`path, root` の2引数）を変える場合は、呼び出し箇所（`targets_vault_rules`・`targets_creator_denied_paths`・`main()` 内）を全て揃えて更新すること
- `git worktree add` は `.claude/settings.json` の `permissions.allow` にある `Bash(git *)` で実行できる。テストは既存の (f)(g)（`stop_gate.py` 向けの一時 git リポジトリ）や (i)〜(l)（`agent_write_guard.py` 向けの `git init`/`checkout -b`）と同じ書き方を踏襲してよい
- コミットは行わない（受け入れ基準にコミットの指示が無いため）。ただし `main` 上で作業する場合は既存のブランチ運用（`vault/rules/common/git.md`）に従うこと
