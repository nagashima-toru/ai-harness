# T-0048 `agent_write_guard.py` の doing/review 判定を計画票ベースに変える

## 目的
`.claude/hooks/agent_write_guard.py` の `active_doing_review_task_ids` を、`vault/todo.md` では
なく「自分のブランチの計画票」（`vault/plans/*.md` のうち `status: approved` の1件）のタスク表か
ら doing/review の id を集める形に変える。`vault/rules/` の改ざん防止判定・
`HARNESS_ALLOW_RULES_WRITE` による解除口・`ALLOWED`（verifier/planner の書き込み先制限）はロジッ
クを変えない。

## 入力
- `.claude/hooks/agent_write_guard.py`（現行）
- `.claude/hooks/plan_guard.py`（T-0046）・`.claude/hooks/stop_gate.py`（T-0047）。計画票を見つけ
  る規則・タスク表を読む規則を同じ形でこのファイル内にコピーする（import はしない。ファイル冒頭の
  docstring に既にその方針が書かれている）
- `docs/vault-spec.md` 12節（agent_write_guard フックの改ざん防止判定）
- `vault/designs/D-001.md`「## フェーズ3」の決定事項（`ALLOWED` は変更しない旨）
- `scripts/smoke.sh` の `== agent_write_guard.py ==` セクションと `make_todo` ヘルパー

## 成果物
- `.claude/hooks/agent_write_guard.py`
- `scripts/smoke.sh` の `== agent_write_guard.py ==` セクション（新形式への書き換え）と、不要になっ
  た `make_todo` ヘルパーの削除

## 受け入れ基準
- `active_doing_review_task_ids` が `vault/plans/` の approved な計画票のタスク表を読む形に変わり、
  `vault/todo.md` への参照が消える。確認：`grep -c 'vault/todo.md' .claude/hooks/agent_write_guard.py`
  が0、`grep -c 'vault/plans' .claude/hooks/agent_write_guard.py` が1以上
- approved な計画票が0件なら改ざん防止判定は素通りする（許可）。2件以上なら**全部の計画票から
  doing/review の id を集めて**判定する（保守的に倒す）。確認：`scripts/smoke.sh` の新規ケース
  （0件→allow、2件以上でどちらかに doing がある状態で `vault/rules/` へ書き込み→deny）が通る
- 既存の `== agent_write_guard.py ==` の全ケース（`ALLOWED` によるパス制限4件、doing 中の
  `vault/rules/` 拒否・doing 無しでの許可・verifier の verdicts/ 書き込み許可の3件、
  `HARNESS_ALLOW_RULES_WRITE` の一致／不一致／非ID値の3件）が `make_plan_task` ベースで全件通る。確
  認：`bash scripts/smoke.sh 2>&1` の `== agent_write_guard.py ==` セクションに `NG` が無い
- `scripts/smoke.sh` から未使用になった `make_todo` ヘルパー定義が削除されている。確認：
  `grep -c '^make_todo()' scripts/smoke.sh` が0
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

## 決定済み
- 計画票を見つける規則・タスク表を読む規則は T-0046／T-0047 と同じにする（`## タスク表` の前方一
  致、データ行の集め方、計画 ID は frontmatter の `id:`、無ければファイル名）
- approved が**0件**の場合は「doing/review の id は無い」として扱う（空リストを返す＝ fail-open）
- approved が**2件以上**の場合は、見つかった全部の計画票から doing/review の id を集めて返す
  （保守的に倒す）。このフックが拒むのは `vault/rules/` への書き込みだけなので、集めすぎても
  過剰に止まることはない。逆に空リストを返すと、壊れている時だけ改ざん防止が黙って無効になる
- 2件以上の時に返す id が計画をまたいで重複しうる点に注意する。`HARNESS_ALLOW_RULES_WRITE` の
  解除判定は「doing/review の ID がすべて含まれる時だけ解除」なので、集めた id 全部が環境変数に
  列挙されていなければ解除されない（保守的側に働く。これで正しい）
- `ALLOWED`（`verifier: vault/verdicts/`、`planner: vault/plans/ と vault/tasks/`）、
  `BASH_WRITE_PATTERNS`、`rules_write_allowed`（`HARNESS_ALLOW_RULES_WRITE` の解除ロジック）、
  `targets_vault_rules` は変更しない。変えるのは `active_doing_review_task_ids` の中身（読む先）と
  ファイル冒頭の docstring の説明文のみ
- docstring の「改ざん防止：…vault/todo.md に doing/review 中のタスクが1件でもあれば…」は「…自分
  のブランチの承認済み計画票のタスク表に doing/review のタスクが1件でもあれば…」に書き換える
- smoke ヘルパーは T-0046／T-0047 と同じ `make_plan_task <id> <status> <attempt>` を使う。このタス
  クの完了時点で `make_todo`（旧 `vault/todo.md` 用）を呼ぶ箇所が smoke.sh 全体から無くなるため、
  ヘルパー定義ごと削除する
- `HARNESS_ALLOW_RULES_WRITE` のテストケース（一致・不一致・`1` のような非ID値）は、doing の id が
  `make_plan_task` で作った計画スコープの id（例：`T-0001`。計画 ID は固定で `P-TEST` を使うため id
  自体の文字列表現は変えない）になる点以外、期待値・比較ロジックは変えない

## 進捗
- 読んだルール: roles.md, creator.md
- `.claude/hooks/agent_write_guard.py`：`active_doing_review_task_ids` を書き換え。
  `plan_id_and_status`／`approved_plans`（plan_guard.py・stop_gate.py と同じ規則）と
  `doing_review_ids_in_plan`（「## タスク表」前方一致以降を読む）を新規追加し、
  `active_doing_review_task_ids` は approved な全計画票から doing/review の id を集めて返す形にした
  （0件→空リスト＝fail-open、2件以上→全部から集める＝保守的）。docstring の説明文を
  「vault/todo.md に doing/review 中のタスクが1件でもあれば」→「自分のブランチの承認済み計画票の
  タスク表に doing/review 中のタスクが1件でもあれば」に書き換え
- `ALLOWED`／`BASH_WRITE_PATTERNS`／`rules_write_allowed`／`targets_vault_rules` は無変更
- `scripts/smoke.sh`：`== agent_write_guard.py ==` セクションの `make_todo` 呼び出しを全部
  `make_plan_task` に置換。新規2ケース (g)（approved 0件→許可）(h)（approved 2件以上でどちらかに
  doing あり→拒否）を追加。未使用になった `make_todo()` ヘルパー定義本体を削除（`make_plan` の
  直前にあった旧定義を除去。呼び出し元がこの時点で smoke.sh 全体から無くなったことを確認済み）
- 受け入れ基準の確認コマンドを実行し、5件すべて通した
  - `grep -c 'vault/todo.md' agent_write_guard.py`=0 / `grep -c 'vault/plans' agent_write_guard.py`=3
  - `== agent_write_guard.py ==` セクション新規2ケース (g)(h) が allow/deny で通る
  - 同セクション全15ケース ok（既存13＋新規2）、NG なし
  - `grep -c '^make_todo()' scripts/smoke.sh`=0
  - `bash scripts/smoke.sh | tail -1` → `smoke: pass=95 fail=0`
