## 決定済み
- 呼び出しの文字列は T-01 の早見表と同じものを使う。早見表そのものは変えない
- 冒頭の「全 verifier の完了を待ち、対象タスクを1件ずつ、計画票のタスク表の上から並んだ順に逐次処理する」は残す（transition.py がコミット・マージするので並行に呼ばない）
- 6.1（verdict がメインリポジトリ側に無い時）：worktree 側の同じ相対パスにあれば `cp <worktree>/vault/verdicts/<計画ID>/<id>.json vault/verdicts/<計画ID>/<id>.json` でコピーすることは残す。log への「verdictをworktree側からコピー」の追記はやめる（計画票の「人への質問」2。コピーした verdict は done のコミットに含まれる）。両方に無ければ検証未完了として人に確認して止めることは残す
- 6.2（`result` と `attempt` を読む。attempt が一致しない verdict は「無い」ものとして止める）は残す。`result` で PASS・FAIL を分ける
- PASS：`python3 scripts/transition.py <計画ID> <id> done --worktree <worktree> --branch <branch> --plan-head <PLAN_HEAD>` を1回呼ぶ、と書く。この1回で、PASS の verdict の確認・新規コミットの判定・差分ゲート・計画ブランチへの `--no-ff` マージ・done とそのコミット（verdict を含む）・worktree とブランチの後始末が行われる、と1〜2文で書く（コマンド名 `git merge` などを手順6に書かない。基準1の grep のため。「マージ」「後始末」という語で書く）
  - 0：done になった。次の対象タスクへ
  - 4：blocked にした（新規コミット無し・宣言外の変更・マージコンフリクトのいずれか。コンフリクトはマージを中止済み）。標準出力の1行を完了報告に写し、worktree は残っている。他の対象タスクの処理は止めず次へ進む
  - 1：何もしていない（PASS の verdict が無い・attempt 不一致など）か、マージ済みだが状態のコミットに失敗した。標準エラーの理由を添えて人に報告し、処理を止める
- コンフリクトは自己判断で解決しない（`vault/rules/common/git.md` の方針）ことを1文残す
- FAIL：`python3 scripts/transition.py <計画ID> <id> doing --worktree <worktree> --branch <branch>` を1回呼ぶ、と書く。上限の判断（attempt+1 が `HARNESS_MAX_ATTEMPTS` 以内なら再試行、超えるなら blocked）は transition.py が行うので、run は attempt を比べない
  - 3：review→doing（attempt+1）にして worktree とブランチを破棄した。手順3の1から PLAN_HEAD を取り直して、その id の creator を呼び直す（verdict の `reasons` を読んで直すのは creator の役目）
  - 4：上限に達したので reasons を question にして blocked にした。worktree は残っている。標準出力の1行を完了報告に写して次へ
  - 1：verdict が FAIL でない・attempt 不一致など。人に報告して止める
- `PLAN_HEAD` は手順3の1で控えた値（中断からの再開では log の記録行から復元した値。手順2の2）を使う、と書く
- 今の6.3.4の「ログ追記・`git add`・`git commit` を別々の Bash 呼び出しで…コマンド置換を使わない（issue #87）」の説明は、手作業のコミットが無くなるので消す
- 「status を」「attempt を +1」「`<日時> <id>`」の言い回し・log の行のひな形を手順6に書かない。`verifier=<モデル>` は transition.py が自動で付けるので手順6には書かない
- 手順6の小見出しの番号（6.1〜6.5 など）は付け直してよい。ほかの節から手順6の番号を参照している箇所（「注意」の「手順6.3.1」、「ハング時の復旧」の「手順6.3.2」・「手順6.4.2」、手順2の2の「手順6.4.2と同じ」など）は、このタスクでは直さなくてよい（T-04・T-05 で直す）
- 「終了コード」の表（行頭が `| <数字> |` の行）を手順6に作らない。箇条書きで書く
- 手順2〜5・7・8・「ハング時の復旧」・「回帰確認」・「注意」・早見表はこのタスクでは変えない
- `scripts/smoke.sh`・`scripts/transition.py`・`docs/vault-spec.md`・`.claude/agents/verifier.md` は変えない
