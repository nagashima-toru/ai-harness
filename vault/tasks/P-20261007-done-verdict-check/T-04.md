# T-04 plan_guard.py で done の行の verdict を検査する

## 目的
PostToolUse の plan_guard でも、承認済み計画票の done の行に attempt が一致する正しい PASS の verdict があるかを検査し、無ければブロックして review に戻すよう指示する。計画票をどう書き換えても「PASS の無い done」が残らないようにする（D-012 フェーズ1）。

## 入力
- `vault/designs/D-012.md` の「フェーズ1」（ゴール文・決定済み）
- `.claude/hooks/plan_guard.py`
- `.claude/hooks/_hooklib.py` の `done_rows_without_pass`（T-01 で追加済み）
- フィクスチャ `vault/tasks/P-20261007-done-verdict-check/fixtures/mixed/`・`fixtures/ok/`（変更しない）

## 成果物
- `.claude/hooks/plan_guard.py`（このファイルだけ）

## 受け入れ基準
- done の行の verdict が正しくないとブロックする（表の上から最初の T-02 で止まる）：`printf '{"hook_event_name":"PostToolUse","tool_name":"Edit"}' | env GIT_DIR=/nonexistent CLAUDE_PROJECT_DIR=vault/tasks/P-20261007-done-verdict-check/fixtures/mixed python3 .claude/hooks/plan_guard.py` の出力が次の1行と完全に一致する
  `{"decision": "block", "reason": "[plan_guard] P-FIX/T-02 は done ですが、attempt=1 の PASS の verdict がありません（verdict がありません）。計画票の T-02 の status を review に戻し、verifier を実行してください。"}`
- done の行に正しい PASS の verdict があれば許可する：`printf '{"hook_event_name":"PostToolUse","tool_name":"Edit"}' | env GIT_DIR=/nonexistent CLAUDE_PROJECT_DIR=vault/tasks/P-20261007-done-verdict-check/fixtures/ok python3 .claude/hooks/plan_guard.py` の出力が空
- 検査を `_hooklib.py` の関数で行い、plan_guard.py に verdict の検査関数を持たない：`grep -c -E '^def (validate_verdict|done_rows_without_pass)\(' .claude/hooks/plan_guard.py` の出力が `0`、かつ `grep -c 'H.done_rows_without_pass(' .claude/hooks/plan_guard.py` の出力が `1`
- 既存の検査が先にブロックする（done の行に verdict の無い「(d) id が重複」が「重複」でブロックされる）ことを含め、既存の smoke が全件通り件数も変わらない：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=519 fail=0`

## 決定済み
- 検査の対象は自分のブランチの approved な計画票（`approved_plans` が1件の時）だけ。draft・done の計画票と `vault/archive/` は見ない（今の `approved_plans` の扱いのまま）
- 検査の位置：`main()` の既存の検査（列数・status・依存・blocked の question・id の重複）の後、最後の `finish()` の直前。既存ケースのブロック理由が先に出るようにする
- `H.done_rows_without_pass(root, plan_id, tasks)` の戻り値が空でなければ、先頭の1件 `(id, 理由)` で `block()` する。文面は次のとおり（`<n>` はタスク表のその行の attempt の文字列そのまま）
  `[plan_guard] <計画ID>/<id> は done ですが、attempt=<n> の PASS の verdict がありません（<理由>）。計画票の <id> の status を review に戻し、verifier を実行してください。`
  - done のタスクの verdict への書き込みは `agent_write_guard.py` が拒否する。そのため、直す手順は「review に戻す → verifier」の順で書く
- ブロックする時は既存の `block()` を使う（承認・解除の裏付けの警告は出さない。JSON は1つだけ。既存の block と同じ扱い）
- 検査の契機は今の PostToolUse の全呼び出し（`Write|Edit|MultiEdit|Bash`）のまま。ツール名・書き込み先で絞らない
- 粒度の検査・承認と解除の裏付けの検査・worktree 委譲は変えない
- モジュール冒頭の docstring の「検出する壊れ方」に1項目（例：`(g) status が done の行に、attempt が一致する正しい PASS の verdict が無い`）を足す
- 確認コマンドの `env GIT_DIR=/nonexistent` は、フィクスチャがリポジトリの中にあるため、承認・解除の裏付けの検査（HEAD との比較）が本物のリポジトリを見ないようにするもの。フック側で GIT_DIR を特別扱いしない
- `.claude/hooks/agent_write_guard.py`・`stop_gate.py`・`_hooklib.py`・`scripts/smoke.sh` は変更しない（smoke の新ケースは T-05）
- フィクスチャは変更しない
