# T-05 install.md のサンドボックスの節に、ハーネス自身を変える作業には向かない旨を足す

## 目的
`docs/install.md` の「サンドボックスを有効にする（任意）」を、ハーネス本体でサンドボックスを使わなくなった後の姿に合わせ、ハーネス自身（`.claude/`）を変える作業には向かない旨を足す（D-015 フェーズ1）。

## 入力
- `vault/designs/D-015.md` の「決定事項」の表（サンドボックスの行）と「フェーズ1」の節
- `docs/install.md` の「## サンドボックスを有効にする（任意）」（計画作成時は156〜198行目）
- T-03 後の `docs/runbook.md`（9節が無い）

## 成果物
- `docs/install.md`（1ファイル）

## 受け入れ基準
- 「サンドボックスを有効にする（任意）」の節の中に、決定済みの文言がある。確認：`sed -n '/^## サンドボックスを有効にする（任意）$/,/^## アンインストール$/p' docs/install.md | grep -c -F 'ハーネス自身（`.claude/`）を変える作業には向かない'` の出力が `1`
- ハーネス本体で有効にしてあるという記述と、runbook の「9. サンドボックスを確かめる」への参照が無い。確認：`grep -c "では有効にしてある\|サンドボックスを確かめる" docs/install.md` の出力が `0`
- 節の見出しと設定例は残る。確認：`grep -c '^## サンドボックスを有効にする（任意）$' docs/install.md` の出力が `1`、`grep -c '"allowUnsandboxedCommands": false' docs/install.md` の出力が `1`
- 見出しの数は変わらない。確認：`grep -c "^## " docs/install.md` の出力が `7`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 節の最初の段落の「ハーネス本体（ai-harness）では有効にしてある。」を「ハーネス本体（ai-harness）では使っていない（理由は `docs/vault-spec.md` 12節の「サンドボックス（使っていない）」）。」にする
- 「**既知の制約**」の箇条書きの先頭に、次の1項目を足す。「ハーネス自身（`.claude/`）を変える作業には向かない」の文言（`.claude/` はバッククォートで囲む）をこのまま項目の書き出しにし、続けて理由を書く
  - 理由の内容：サンドボックスは `.claude/` の下（`settings.json`・`skills/`・`agents/` など）と `.git` への Bash の書き込みを止めるので、ハーネスのフック・スキル・設定を変える計画では、creator の編集・worktree の後始末・PR の作成が詰まる。そうした作業をするリポジトリ（ハーネス本体など）では有効にしない
- 節の末尾近くの「設定はセッションの開始時に読まれるので、足した後は Claude Code を起動し直し、[docs/runbook.md](runbook.md) の「9. サンドボックスを確かめる」の手順で確かめる。」を「設定はセッションの開始時に読まれるので、足した後は Claude Code を起動し直し、`/sandbox` で有効になっていることを確かめる。」にする
- 設定例の JSON、`denyWrite`・`allowedDomains` の説明、ほかの既知の制約、`uninstall.sh` の段落は変えない（導入先で任意に使う手順として残す。D-015 の決定事項）
- 「## サンドボックスを有効にする（任意）」以外の節は変えない
