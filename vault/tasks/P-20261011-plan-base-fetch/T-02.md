# T-02 vault-spec の開始条件の記述を fetch 手順に合わせ、decisions に判断の変更を記録する

## 目的
T-01 で `/plan` 手順A-2・`/design` 手順1 に入れた best-effort の `git fetch origin <ベースブランチ>:<ベースブランチ>` と矛盾する「`origin/<ベース>` の fetch はしない」という記述を `docs/vault-spec.md` から無くし、判断の変更を `docs/decisions.md` に1行記録する（GitHub Issue #175）。

## 入力
- `docs/vault-spec.md` の `HARNESS_PUSH_BRANCH` の段落（「環境変数 `HARNESS_PUSH_BRANCH` は push 先と…」で始まる1行の段落）
- `docs/decisions.md` の表（末尾の行と、「`/plan`・`/design` の開始条件はローカルの `<ベースブランチ>` の ref と比べ、`origin/<ベースブランチ>` の fetch はしない」の行）
- T-01 で変更済みの `.claude/skills/plan/SKILL.md` 手順A-2（文言をそろえるための参照。変更しない）
- このタスク票の「決定済み」（置換・追記する文言はここに確定している）

## 成果物

- `docs/vault-spec.md` に決定済みの置換後の括弧書きがちょうど1回ある。確認：`grep -cF '（開始条件の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を best-effort で1回行い、失敗しても止まらない。比較はローカルの `<ベースブランチ>` の ref と行い、`origin/<ベース>` とは比べない。ローカルにベースブランチが無ければ止まる）' docs/vault-spec.md` の出力が `1`
- `docs/decisions.md` の表の最終行が決定済みの追記行である。確認：`tail -1 docs/decisions.md | grep -cF '| 2026-10-11 | `/plan`・`/design` の開始条件の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を best-effort で1回行う（GitHub Issue #175。'` の出力が `1`
- リポジトリ全体（`vault/`・`.git`・`worktrees` と `docs/decisions.md` を除く）に「fetch はしない」という記述が残っていない。確認：`grep -rnF 'fetch はしない' . --exclude-dir=vault --exclude-dir=.git --exclude-dir=worktrees --exclude=decisions.md` の出力が空
- smoke の参照切れ検査が通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`

## 決定済み
- `docs/vault-spec.md` の置換：`HARNESS_PUSH_BRANCH` の段落にある「（ローカルにベースブランチが無ければ止まる。`origin/<ベース>` の fetch はしない）」を、「（開始条件の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を best-effort で1回行い、失敗しても止まらない。比較はローカルの `<ベースブランチ>` の ref と行い、`origin/<ベース>` とは比べない。ローカルにベースブランチが無ければ止まる）」に置き換える。段落のほかの文言、ほかの段落（`HARNESS_BASE_BRANCH` の段落を含む）は変えない
- `docs/decisions.md` の追記：表の最終行（現在の「runbook はエージェントが内部でやること…」の行）の次に、次の1行（コードブロックの中身。行頭の `|` から行末の `|` まで、先頭の字下げは付けない）を追記する。既存の行（「…`origin/<ベースブランチ>` の fetch はしない（D-20261010-base-branch-config）」の行を含む）は変えない
  ```
  | 2026-10-11 | `/plan`・`/design` の開始条件の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を best-effort で1回行う（GitHub Issue #175。D-20261010-base-branch-config の「fetch はしない」を改める）。比較は引き続きローカルの `<ベースブランチ>` の ref と行う | クラウドセッションではローカルの `<ベースブランチ>` が古いままのことがあり、開始条件で止まっていた。fast-forward できる時だけ進む非破壊の操作で、失敗しても従来の確認に進む。代案（HEAD がベースの子孫かつ fetch した `origin/<ベース>` と一致すれば可）は採らない（人の選択） |
  ```
- 古い記述の確認から除く範囲と理由：`vault/` は計画票・タスク票・log が旧文言を引用するため。`docs/decisions.md` は判断の履歴で、過去の行（D-20261010-base-branch-config の行）は書き換えずに残し、新しい行で改める方針のため。`.git` と `worktrees` はリポジトリの内容ではないため
- `docs/guide.md`・`docs/runbook.md`・`docs/install.md` の開始条件の記述は fetch に触れておらず矛盾しないので変えない（計画時に確認済み）
- `.claude/skills/plan/SKILL.md`・`.claude/skills/design/SKILL.md` は T-01 の成果物なので変えない
