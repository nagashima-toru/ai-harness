# T-05 planner.md の model を opus にし smoke を通す

## 目的
planner サブエージェントの frontmatter の `model` を `opus` にし、creator・verifier が `sonnet` のままであること、既存テストが通ることを確認する（D-010 フェーズ9、#73）。

## 入力
- `.claude/agents/planner.md`（5行目付近の `model: sonnet`）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md`（変更しない）
- `scripts/smoke.sh`

## 成果物
- `.claude/agents/planner.md`（frontmatter の `model` を `opus` に変える）

## 受け入れ基準
- `.claude/agents/planner.md` の frontmatter が `model: opus` である（`grep -n '^model:' .claude/agents/planner.md` の出力が `5:model: opus`）
- `.claude/agents/creator.md` と `.claude/agents/verifier.md` の frontmatter が `model: sonnet` のままである（`grep -n '^model:' .claude/agents/creator.md .claude/agents/verifier.md` が両ファイルとも `model: sonnet` を出力する）
- planner.md の変更が `model` の1行だけである（`git diff -- .claude/agents/planner.md | grep -E '^[+-][^+-]'` の出力が `-model: sonnet` と `+model: opus` の2行だけ）
- `bash scripts/smoke.sh` の最終行が `fail=0` を含む（`bash scripts/smoke.sh > /tmp/P-20261001-planner-opus-T-05.txt` を実行し、`tail -1 /tmp/P-20261001-planner-opus-T-05.txt` で確認する）

## 決定済み
- モデル名は alias（`opus`・`sonnet`）で書く。バージョン付きの ID は書かない
- `docs/decisions.md` の 2026-09-17 の行は書き換えない（判断の記録として残す。新しい行の追加は T-01 で済んでいる）
- スキルの frontmatter でのモデル指定はしない（このタスクでもスキルは触らない）
- creator のモデルは変えない。haiku 等への切り替えは、`model_stats.py` で十分な件数が集まってから、別の計画で行う
- verifier は「実行側」として扱う（人の回答）。`sonnet` のまま
- このタスクは T-01〜T-04 がすべて done になってから単独で動く。smoke.sh が /tmp の固定パスを使うため、他タスクと並行させない
- 1行目の確認は `5:` の行番号まで含めるが、行番号がずれていたら実際の frontmatter の行に合わせてよい（`model: opus` であることが本質）
- planner.md 本文・他の frontmatter キーは変えない
- smoke が既存テストで planner の model を `sonnet` と決め打ちして fail した場合は、blocked にして question に書く（smoke.sh は成果物外なので勝手に直さない）
