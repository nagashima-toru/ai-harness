# ai-harness のビジョン

## 目的
**実行を安いモデルに任せても成果が安定する、汎用のタスク実行基盤をつくる。**

- **安い実行**：設計や計画には強いモデルを使ってよいが、手を動かす実行部分はできるだけ安いモデルで済ませる。より安いモデルでできるなら、そちらを選ぶ。
- **安定**：受け入れ基準を満たす成果が繰り返し出ること。途中で止まらず（ハングや異常終了で止まらない）、放置しても暴走しないこと。
- **汎用**：アプリ開発や定型作業など特定の作業に特化しない。ドメイン向けの特化は導入先で拡張として積む。すべての土台になるもの。

## 原則

### 安定のため
1. **完了かどうかは作った本人に決めさせない**：別コンテキストの検証が PASS しない限り完了にしない。
2. **守らせたい規律はプロンプトに頼らず仕組みで強制する**：フックなどで機械的に止める。
3. **タスクは1コンテキストで終わる小ささに切る**：受け入れ基準は真偽で判定できる文にする。
4. **状態はモデルの記憶ではなくファイルに置く**：いつ中断しても続きから再開できる。
5. **迷ったら推測で進めずに止める**：質問は着手前にまとめて聞き、着手後に迷ったら理由を残して blocked にし人に返す。これは目的の「途中で止まらない」（ハングや異常終了で止まらないこと）とは別の話で、判断に迷った時に安全側で止まるための原則。

### 安い実行のため
6. **考える工程と実行する工程でモデルを分ける**：設計・計画には強いモデル、実行には成果が安定する範囲で最も安いモデルを使う。

### 汎用基盤のため
7. **ハーネス本体はドメイン知識を持たない**：ドメイン特化は導入先のルールやスキルとして積む。
8. **導入先の既存資産を壊さない**。

### 共通
9. **最終決定は人が持つ**：承認・マージ・blocked の解除。
10. **ハーネス自身もこのハーネスで作って検証する**。

## 非ゴール
- **マルチユーザー化・SaaS化・GUI化はしない**：個人の私的ツールとして閉じたままでよい。
- **このリポジトリ自体を特定ドメイン（アプリ開発・定型作業等）に特化したハーネスにはしない**：ドメイン固有の拡張は導入先のリポジトリで行う。
- **Claude Code 以外のランタイムへの対応は現時点では目指さない**。
