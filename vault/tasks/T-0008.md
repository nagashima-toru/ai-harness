# T-0008 run-queue にルール読み込み手順を追加する

## 目的
作成エージェント（run-queue）が着手時に `vault/rules/` のルール（common + creator）を読んでから成果物を作るよう、SKILL.md に手順を追加する。あわせて CLAUDE.md の役割説明にもその旨を1行反映する。

## 入力
- `docs/roadmap-rules-extension.md` の「## ③ 作成エージェントにルールを渡す（run-queue）」節（このタスクの元になったゴール文と候補基準）
- `.claude/skills/run-queue/SKILL.md`（編集対象）
- `CLAUDE.md`（編集対象）
- `docs/vault-spec.md` の「12. ルール」節（`vault/rules/` の仕様。既に確定済み）
- `scripts/rules.sh`（既存。`bash scripts/rules.sh creator` で列挙する）

## 成果物
- `.claude/skills/run-queue/SKILL.md` の更新（「## 2. 作る」への手順追加、「## 注意」への追記、進捗記録手順の追加）
- `CLAUDE.md` の「## 役割」の作成エージェントの行の更新（60行以内を維持）

## 受け入れ基準
- `.claude/skills/run-queue/SKILL.md` の「## 2. 作る」で、手順1の直後（新しい手順2）に `bash scripts/rules.sh creator` を実行して列挙ファイルを読み、以降の成果物作成でそれに従うこと・列挙が空なら何もしないことが書かれている（確認：`sed -n '/^## 2\. 作る/,/^## 3\./p' .claude/skills/run-queue/SKILL.md | sed -n '3p'` の出力に `rules.sh creator` と `空` の両方が含まれる）
- 「## 注意」に、タスク中は `vault/rules/` を編集しない旨（フックで拒否される旨を含む）の行がある（確認：`sed -n '/^## 注意/,$p' .claude/skills/run-queue/SKILL.md | grep -E 'vault/rules/' | grep -c '編集しない'` が1以上）
- SKILL.md のどこかに、進捗へ読んだルールファイル名を書く手順がある（確認：`grep -c '読んだルール' .claude/skills/run-queue/SKILL.md` が1以上）
- `CLAUDE.md` の「## 役割」の作成エージェントの行に `vault/rules/` を読む旨（common, creator を含む）が追記され、`CLAUDE.md` 全体が60行以内（確認：`awk '/^## 役割/{flag=1} flag && /^## / && !/^## 役割/{exit} flag' CLAUDE.md | grep -c 'vault/rules'` が1以上、かつ `wc -l < CLAUDE.md` が60以下）
- `.claude/agents/verifier.md`・`.claude/agents/planner.md`・`.claude/hooks/` 配下・`scripts/install.sh`・`README.md` が変更されていない（確認：`git diff --quiet -- .claude/agents/verifier.md .claude/agents/planner.md .claude/hooks/ scripts/install.sh README.md` の終了コードが0）
- `bash scripts/smoke.sh | tail -1` の出力に `fail=0` が含まれる

## 決定済み
- 挿入位置：「## 2. 作る」の既存手順1はそのまま、直後に新しい手順2として `rules.sh creator` の実行・読み込みを挿入する。既存の手順2〜4（成果物作成／進捗追記／blocked 分岐）は手順3〜5に繰り下げる
- ルールを読むタイミングは「タスク票を読んだ直後（手順1の後）」。セッション開始時（手順0「現在時刻」や手順1「取り出す」）には読まない。開始時の読み物は増やさない
- 「進捗」への記録は「読んだルール: a.md, b.md」のように1行で十分。列挙が空だった（読むルールが無かった）場合はこの行自体を書かなくてよい
- CLAUDE.md の「## 役割」の作成エージェントの行は、既存の文言（「タスクを取り、成果物を作り、状態と log を更新する」）を維持したまま「着手時に `vault/rules/`（common, creator）を読む」旨を追記する。他の見出し・行は変更しない
- CLAUDE.md が60行を超えそうな場合は、今回追記する文を簡潔にして60行以内に収める。他の節の削減はしない
- `.claude/agents/verifier.md`・`.claude/agents/planner.md`・フック（`.claude/hooks/` 配下）・`scripts/install.sh`・`README.md` は一切変更しない
- `vault/rules/` 配下のファイル自体（common/creator ディレクトリの中身）は編集しない。今回のタスクは「読む手順」を文書に追加するだけ
- git のコミットは行わない（受け入れ基準に含まれていないため）

## 進捗
- `.claude/skills/run-queue/SKILL.md` の「## 2. 作る」に手順2として `bash scripts/rules.sh creator` の読み込みと進捗記録を追加し、既存の手順2〜4を3〜5に繰り下げ
- 「## 注意」に「タスク中は vault/rules/ を編集しない（verifier の判定基準を自分で変えないため。フックでも拒否される）」を追加
- `CLAUDE.md` の「## 役割」作成エージェント行に「着手時に vault/rules/（common, creator）を読み」を追記（41行、60行以内）
- 受け入れ基準6件の確認コマンドをすべて実行し通過。verifier.md・planner.md・フック・install.sh・README.md は無変更（`git diff --quiet` rc=0）、`bash scripts/smoke.sh` は pass=37 fail=0
