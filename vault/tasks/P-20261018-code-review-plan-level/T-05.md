## 目的

- T-01〜T-04 の成果物（`.claude/agents/planner.md`・`.claude/agents/creator.md`・`.claude/agents/verifier.md`・`docs/vault-spec.md`・`.claude/skills/run/SKILL.md`）

## 受け入れ基準
- 方針変更の行が1行だけ足されている：`grep -c 'P-20261018-code-review-plan-level' docs/decisions.md` が `1`、かつ `grep -c '2026-10-18' docs/decisions.md` が `1`
- 理由として費用がタスク数に比例することが書かれている：`grep -c 'タスク数に比例' docs/decisions.md` が `1`
- 「レビューを強制しない」の記述が decisions.md の外に残っていない：`grep -rlF --exclude-dir=worktrees 'レビューを強制しない' .claude docs README.md vault/rules vault/templates` の出力が `docs/decisions.md` の1行だけ
- 「導入先の planner ルール」に任せる記述が decisions.md の外に残っていない：`grep -rlF --exclude-dir=worktrees '導入先の planner ルール' .claude docs README.md vault/rules vault/templates` の出力が `docs/decisions.md` の1行だけ

## 決定済み
- `docs/decisions.md` の表の末尾（2026-10-17 の行の直後）に、次の1行をそのまま足す（既存の行は変えない）：
  `| 2026-10-18 | 2026-10-17 の「ハーネスはレビューを強制しない」を置き換え、コードを変更するタスクを含む計画には、planner が全タスクを after に持つ最後のタスク「計画の差分が /code-review を通過する」（計画単位のレビュータスク）を足す。レビューの範囲はベースブランチ（HARNESS_BASE_BRANCH、既定 main）との分岐点からの計画全体の差分で、通常のタスクの受け入れ基準には /code-review の行を入れない（Issue #214 の続き）（P-20261018-code-review-plan-level） | タスク単位のレビューは費用がタスク数に比例し、タスクを小さく切るほど割高になる。計画の最後に1回だけ行えば費用は計画ごとに1回分で済む |`
- 上の行は表の行なので、行頭・行末の `|` を含めてそのまま書く（外側のバッククォートは含めない）
- 日付は計画 ID の日付 `2026-10-18` にする（作業した日の日付にしない）
- 確認の範囲はリポジトリの文書全体（`.claude`・`docs`・`README.md`・`vault/rules`・`vault/templates`）。除外するのは次のもの：

  - `scripts/`（現状これらの語を含まず、smoke の検査文字列は変えないため対象にしない）
