# T-01 agent_write_guard.py で計画票の blocked→他 の書き込みを会話記録の /plan unblock で裏付け、無ければ拒否する（smoke.sh にテストを足す）

## 目的
blocked の解除（タスク表で blocked の行を blocked 以外にすること）を、人が `/plan unblock <計画ID> <id>` で指示した時だけ許可する。PreToolUse で Write/Edit/MultiEdit の書き込み後のタスク表を組み立てて判定し、エージェントの独断の解除を防ぐ（D-010 フェーズ5、決定事項の #75）。

## 入力
- `vault/designs/D-010.md` の決定事項（#75 の承認と解除・会話記録が読めない時の警告）とフェーズ5の決定済み
- `.claude/hooks/agent_write_guard.py`：`main()` の承認判定（`find_plan_approval` の呼び出し）の直後に置く。`plan_raw_rows`・`PLAN_TASK_COLUMNS`・`content_after_write`・`human_messages`・`is_approve_command`・`PLAN_FILE_RE` を再利用する
- `scripts/smoke.sh` の `(approve-pre)` 節（`make_transcript`・`expect_ap`・`run_guard`・`make_plan`・`TG_HOME`）

## 成果物
- `.claude/hooks/agent_write_guard.py` の変更と `scripts/smoke.sh` への回帰テスト追加（1PR分の関連する2ファイル変更）

## 受け入れ基準
- 会話記録の人の発言に `/plan unblock P-TEST T-02`（スラッシュコマンド形式・文形式の両方、後ろに回答が続いてよい）がある時、`agent_type` が空の Edit・Write・MultiEdit による T-02 の blocked→todo が許可され、T-01 の blocked→todo は拒否される。確認：`bash scripts/smoke.sh` の出力に `ok   (unblock-pre)` で始まる該当ケースがあり `NG` が無い
- 会話記録にコマンドが無い時、`agent_type` が空でない時（会話記録に有っても）、計画 ID が違う・タスク ID が違う・前方一致（`T-020`）だけの時は blocked→todo・blocked→doing とも拒否され、reason に `/plan unblock` を含む（同上）
- `tool_result` の行や `isMeta: true` の行にしか無い会話記録では拒否される。会話記録が読めない時（F4 と同じ定義）は拒否せず許可する（同上）
- todo→doing・doing→review・review→done/doing/blocked・doing→blocked などの遷移、blocked→blocked（question の書き換えなど）、blocked 行を含まない計画票の編集は、会話記録と無関係に従来どおり許可される。F4 の `(approve-pre)` のケースも変わらず通る（同上）
- `bash scripts/smoke.sh > /tmp/P-20260930-unblock-transcript-guard-T-01-smoke.txt 2>&1` の後 `grep -c '^  NG' /tmp/P-20260930-unblock-transcript-guard-T-01-smoke.txt` が `0`、`tail -1 /tmp/P-20260930-unblock-transcript-guard-T-01-smoke.txt` が `smoke: pass=<N> fail=0`

## 決定済み
- 一致判定は F4 と同じ規則で、`is_unblock_command(text, plan_id, task_id)` を新規に足す（`is_approve_command` は変えない）。スラッシュコマンド形式は `<command-name>/plan</command-name>` と、`<command-args>` の中身（前後の空白を除く）が `unblock <計画ID> <id>` で始まり、その直後が空白か末尾のもの（後ろに回答が続いてよい）。文形式は先頭が `/plan unblock <計画ID> <id>` で、直後が空白か末尾。計画 ID・タスク ID は完全一致（空白区切りのトークンで比べる。`T-02` と `T-020` を区別する）。回答が複数行でもよい
- 人の発言の定義（`type` が `user`・`content` が文字列・`isMeta` が真でない）と、「会話記録が読めない」の定義は F4 と同じ。読めない時は拒否せず許可する（警告は T-02 の plan_guard が出す）。読めたうえで該当コマンドが無い時は拒否する
- 解除の検出：対象が root 相対で `vault/plans/<計画ID>.md`（`PLAN_FILE_RE`）で、書き込み前のタスク表（`plan_raw_rows`）で status が `blocked` の行のうち、書き込み後のタスク表に同じ id の行があり、その status が `blocked` でないもの。書き込み後の内容は `content_after_write` で組み立てる（Write は `content`、Edit・MultiEdit は現在のファイルに適用。適用に失敗した時は解除ではないとみなして許可する）。ファイルが無い（新規作成）時は解除に当たらない。計画票の status（draft・approved・done）は問わない
- 行が消える（書き込み後に同じ id の行が無い）場合は検査しない（今回は扱わない）。1回の書き込みで複数行が解除される時は、行ごとにコマンドが必要で、1行でも裏付けが無ければ拒否する
- 許可の条件：`agent_type` が空（メインセッション）、かつ会話記録に一致するコマンドがある、または会話記録が読めない。`agent_type` が空でない時（planner・creator・verifier など）は、会話記録の内容に関わらず拒否する
- reason の文言は `[agent_write_guard] <計画ID>/<id> の blocked の解除（status を blocked 以外にすること）は、人が /plan unblock <計画ID> <id> で指示した時だけ許可されます。` とする
- 判定の位置は、承認判定の直後、done タスクへの書き込み拒否の前。Bash による書き換えはこのタスクでは検査しない（T-02 の plan_guard が PostToolUse で補う）
- run の遷移には blocked から出るものが無いので、通常の run はこの検査に引っかからない。解析関数は `agent_write_guard.py` 内に足す（他フックの import はしない。T-02 で plan_guard にコピーする）
- smoke.sh のケース接頭辞は `(unblock-pre)`。フィクスチャは blocked 行を2つ（T-01・T-02）持つ計画票を `make_plan` 相当で作り、会話記録は F4 の `make_transcript` とサンプル行を流用し、`unblock P-TEST T-02` のサンプル行を追加する。「コマンドが無い」ケースには必ず「無関係な人の発言」を1件入れる。後片付けに `rm -rf` は使わない
- 承認済み計画票の差し戻しや、done の行の変更はこのタスクの対象外
