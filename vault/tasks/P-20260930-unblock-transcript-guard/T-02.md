# T-02 plan_guard.py で作業ツリーの計画票を HEAD と比べて blocked の解除の裏付けを検査し smoke.sh にテストを足す

## 目的
PreToolUse では組み立てられない Bash による計画票の書き換え（`sed -i` やリダイレクト）による blocked の解除を、PostToolUse で取りこぼしなく検出する。作業ツリーのタスク表を HEAD の版と比べ、裏付けが無ければブロックして元に戻すよう指示する（D-010 フェーズ5）。

## 入力
- `vault/designs/D-010.md` のフェーズ5の決定済み、フェーズ4の PostToolUse の決定済み
- `.claude/hooks/plan_guard.py`：`newly_approved_plans`・`approval_check`・`human_messages`・`raw_rows`・`main()`（`approval_check` の呼び出しと `finish()`）
- T-01 で `agent_write_guard.py` に足した `is_unblock_command`（規則をコピーする）
- `scripts/smoke.sh` の `(approve-post)` 節（`AP_REPO`・`run_ap_post`・`make_transcript`）

## 成果物
- `.claude/hooks/plan_guard.py` の変更と `scripts/smoke.sh` への回帰テスト追加（1PR分の関連する2ファイル変更）

## 受け入れ基準
- Bash で計画票の blocked 行を todo に書き換え、会話記録に `/plan unblock <計画ID> <id>` が無い時、plan_guard が `{"decision": "block", ...}` を出し、reason に計画 ID・タスク ID・`git restore vault/plans/<計画ID>.md` を含む。確認：`bash scripts/smoke.sh` の出力に `ok   (unblock-post)` で始まる該当ケースがあり `NG` が無い
- 会話記録の人の発言（スラッシュコマンド形式・文形式）に一致する `/plan unblock <計画ID> <id>` がある時は許可される。`tool_result`・`isMeta` の行にしか無い時、計画 ID・タスク ID が違う時、前方一致だけの時はブロックされる（同上）
- 会話記録が読めない時（F4 と同じ定義）はブロックせず、`additionalContext` に解除の裏付けを検査できなかった旨の警告を出す（同上）
- HEAD でも blocked でない行（todo→doing など）、blocked→blocked、HEAD に計画票が無い（未追跡の）場合、非 git ディレクトリでは何も出さない（同上）
- F4 の `(approve-post)` と T-01 の `(unblock-pre)` のケースが変わらず通る。`bash scripts/smoke.sh > /tmp/P-20260930-unblock-transcript-guard-T-02-smoke.txt 2>&1` の後 `grep -c '^  NG' /tmp/P-20260930-unblock-transcript-guard-T-02-smoke.txt` が `0`、`tail -1` が `smoke: pass=<N> fail=0`

## 決定済み
- 一致判定・人の発言の定義・「読めない」の定義は T-01 と同じ。`is_unblock_command` は T-01 の実装を plan_guard.py にコピーする（フック間 import はしない）。`human_messages` は F4 のコピーがすでにある
- 検査の対象：`vault/plans/*.md` すべて（status を問わない）。作業ツリーの版のタスク表（`raw_rows`）で status が `blocked` でない行のうち、`git show HEAD:./vault/plans/<ファイル名>` の版で同じ id の status が `blocked` だったもの。HEAD の取得失敗（HEAD 無し・未追跡）は「blocked の行が無い」として扱い、何もしない。作業ツリーに同じ id の行が無い場合は検査しない。非 git ディレクトリでは何もしない（F4 の `newly_approved_plans` と同じ前提確認）
- 複数行が解除されている時は行ごとに検査し、裏付けの無い最初の1行でブロックする（reason に計画 ID・タスク ID を含める）
- 会話記録が読めない時は、`newly_approved_plans` と同様に警告を集め、承認の警告と合わせて `additionalContext` に1回出す。既存の検査（粒度・依存など）がブロックした時は警告を出さない（F4 の `finish()` の方式を踏襲する）
- ブロックの reason：`[plan_guard] <計画ID>/<id> が blocked から書き換えられていますが、人の /plan unblock <計画ID> <id> の指示が会話記録にありません。git restore vault/plans/<計画ID>.md で元に戻してください（blocked の解除は人が /plan unblock <計画ID> <id> で指示した時だけ行えます）。`
- 同じ解除に何度も当たらないよう、`/plan unblock` は解除の直後にコミットする（T-03 のスキルで手順化）。コミットすると HEAD の版が blocked でなくなり対象外になる
- run の遷移（doing→blocked など）は HEAD で blocked でない行を変えるだけなので当たらない。`plan_guard.py` の他の検査・PostToolUse の出力形式は変えない
- smoke.sh のケース接頭辞は `(unblock-post)`。git フィクスチャは F4 の `AP_REPO` 方式（`/tmp/P-20260930-unblock-transcript-guard-T-02-repo`）を参考にし、HEAD に blocked 行を含む計画票をコミットしてから作業ツリーで書き換える。後片付けに `rm -rf` は使わない
