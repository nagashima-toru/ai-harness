# T-04 smoke の設計文書 ID の例を新形式にし、/design の記述の検査を足す

## 目的
`scripts/smoke.sh` の設計文書 ID・ブランチの例を新形式（`D-<YYYYMMDD>-<スラッグ>`・`design/d-<YYYYMMDD>-<スラッグ>`）にそろえ、`/design` スキルとテンプレートが新形式と最終フェーズの削除を書いていることを smoke で検査する。

## 入力
- `scripts/smoke.sh` の (k)・(l)（286〜290行目付近。`design/d-999`・`vault/designs/D-999.md`）
- `scripts/smoke.sh` の「スキルの記述の検査」（`DESIGN_SKILL` の定義と (run-skill-3) のあたり）
- `scripts/smoke.sh` の参照切れ検査 `refcheck` の除外リスト `excl` と (ref-3) のフィクスチャ（`vault/designs/D-xxx.md` を含む行）
- T-02 で直した `.claude/skills/design/SKILL.md`・`vault/templates/design.md`

## 成果物
- `scripts/smoke.sh`（1ファイル）

## 受け入れ基準
- smoke に旧形式の例が残っていない（`grep -nE 'd-999|D-999|D-xxx|d-xxx' scripts/smoke.sh` が何も出さない）
- smoke を実行すると、新形式のブランチの (k)・(l) と、新しく足した (design-skill-1)・(design-skill-2) の4件が ok になる（`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   (\((k|l)\) design/d-20991231-smoke |\(design-skill-[12]\) )'` が `4` を出す）
- (design-skill-1) は、`.claude/skills/design/SKILL.md` から「決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する」の行を消すと NG になる（creator が一時的に消して smoke を実行し NG を確かめ、元に戻したことを「進捗」に書く。verifier は `grep -n 'design-skill-1' scripts/smoke.sh` で検査の本体を読み、その固定文字列を `grep -F` 等で見ていることを確かめる）
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<N> fail=0` を出す（参照切れ検査 (ref-1)〜(ref-4) を含む）

## 決定済み
- D-016 の決定事項（転記）：設計文書の ID は `D-<YYYYMMDD>-<スラッグ>`、ブランチは `design/d-<YYYYMMDD>-<スラッグ>`。smoke の `design/d-999`・`D-999.md`・`D-xxx.md` を使うテストは新しい形式の例に直すか、形式に依存しないならそのままでよい（通ることが条件）。このタスクでは新しい形式の例に直す
- (k)・(l) の新しいラベルと値：ブランチは `design/d-20991231-smoke`、ファイルは `vault/designs/D-20991231-smoke.md`。ラベルは `(k) design/d-20991231-smoke ブランチで git commit → 許可`・`(l) design/d-20991231-smoke ブランチで vault/designs/D-20991231-smoke.md へ Write → 許可`。判定（allow）とフック（`agent_write_guard.py`）は変えない（フックは ID の形式を見ていない）
- 新しい検査は「スキルの記述の検査」の (run-skill-3) の後に足し、`expect_eq` で ok/NG を比べる既存の型（`rs3` など）に合わせる：
  - `(design-skill-1) design スキルが新しいブランチ名と最終フェーズの削除を書いている`：`$DESIGN_SKILL` が固定文字列 `design/d-<YYYYMMDD>-<スラッグ>` と固定文字列 ``決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する`` の両方を含み（`grep -qF`）、`D-xxx` を含まない時だけ ok
  - `(design-skill-2) design テンプレートの id が新しい形式`：`$ROOT/vault/templates/design.md` に行全体が `id: D-<YYYYMMDD>-<スラッグ>` の行がある時だけ ok（`grep -qxF` など）
- 参照切れ検査の除外リスト `excl` から `"vault/designs/D-xxx.md"` を外す（T-02・T-03 で文書から `D-xxx.md` の参照が消えたため）。(ref-3) のフィクスチャの `printf` の引数から `'`vault/designs/D-xxx.md`'` を外す。(ref-3) のラベルと残りの引数は変えない
- smoke は計画の実ファイル（`vault/plans`・`vault/tasks`・`vault/verdicts`・`vault/log` の下）と `vault/designs/` の実ファイルを読まない（`vault/designs/D-*.md` は T-06 で消える。docs/decisions.md 2026-10-10 の行の方針）
- 受け入れ基準3の一時的な削除の確認は作業ツリーで行い、コミットには含めない（`.claude/skills/design/SKILL.md` は成果物ではないので、変更を残すと差分ゲートで差し戻される）
- インストール先のマニフェストの検査（`vault/designs/` を含む startswith のタプル）と install まわりの検査はディレクトリ名だけを見るので変えない
- ラベルの `D-016`（例：(run-skill-5) の「D-016 の順」）など過去の設計 ID への言及は書き換えない
