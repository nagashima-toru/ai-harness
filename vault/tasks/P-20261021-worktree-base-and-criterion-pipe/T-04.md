# T-04 creator.md の受け渡しと git 節を add_worktree.sh の経路に合わせる

## 目的
Issue #209。run が `scripts/add_worktree.sh` で作った新しい worktree のパスを `作業する worktree: <パス>` で渡すようになった（T-03）ことに合わせ、`.claude/agents/creator.md` の「入力」節と `## git` 節を直す。リポジトリの文書に、creator を worktree 隔離で呼ぶ前提の記述が残らないようにする。

## 入力
- `.claude/agents/creator.md`（「入力」節の `作業する worktree:` の箇条、`## git` 節の「ブランチ」の行）
- `.claude/skills/run/SKILL.md` の手順3の2・6（T-03 の成果物）
- `scripts/add_worktree.sh`（T-02 の成果物）

## 成果物
- `.claude/agents/creator.md`（1ファイル）

## 受け入れ基準
- 追跡しているファイルのうち `.claude/`・`docs/`・`README.md` で `isolation: "worktree"` の語があるのは run/SKILL.md の既知の原因の説明だけ：`git grep -l 'isolation: .worktree.' -- .claude docs README.md` の出力が `.claude/skills/run/SKILL.md` の1行だけ
- `## git` 節に worktree を作る主体と方法がある：`grep -c 'run が .scripts/add_worktree.sh. で計画ブランチ' .claude/agents/creator.md` の出力が `1`
- 「入力」節が新しい worktree の場合を扱う：`grep -c '新しい worktree' .claude/agents/creator.md` の出力が `1` 以上
- 文書のバッククォートのパスがすべて存在する：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<n> fail=0` の形（`<n>` は任意）

## 決定済み
- 「入力」節：prompt の `作業する worktree: <パス>` は、run が `scripts/add_worktree.sh` で計画ブランチから作った新しい worktree か、unblock の後に `--resume-worktree` で引き継いだ前回の worktree のどちらかを指す、と書く（「新しい worktree」の語をこのまま使う）。新しい worktree では「進捗」も成果物もまだ無いので最初から作る。今の箇条（絶対パスで読み書きする・`cd <パス>` してから実行する・その worktree の版のタスク票を読む・ブランチを切り替えず git の操作をしない）は両方に当てはまるので残す。「前回の続きを作る」「計画ブランチの取り込みは transition.py が済ませている」は引き継いだ worktree の場合の説明として残す
- prompt に `作業する worktree:` が無い呼び出し（古い run から呼ばれた時）は、今の作業ディレクトリの worktree で作る、と1文残す
- `## git` 節の「ブランチ」の行：「run が `isolation: "worktree"` で creator 用の worktree を用意する」を「run が `scripts/add_worktree.sh` で計画ブランチ（`PLAN_HEAD`）から creator 用の worktree を作る」に置き換える（この文字どおり）。1ブランチ=1計画・ブランチを切らない・切り替えない、は残す
- creator.md のほかの節（手順・コードレビュー・受け渡し・禁止など）は変えない
- 1つ目の基準の範囲を `.claude/`・`docs/`・`README.md` の追跡ファイルにするのは、creator を呼ぶ手順が書かれる文書がここだけで、`vault/` の計画一式（この計画のタスク票は旧い記述を引用する）は PR の前に除去されるため。`.claude/worktrees/` は追跡外なので `git grep` に出ない
- `.claude/settings.json` の `worktree.baseRef` は変えない（このタスクの成果物ではない）
