# ゴール
GitHub Issue #107 を解決する。#102（計画 P-20261002-verify-cmd-guard-align）の続きとして扱う。planner のルール（`vault/rules/planner/planner.md`）が確認コマンドの代わりの手段として「`/tmp` へリダイレクトしてから別コマンドで読む」形を勧めているが、実運用では verifier が `/tmp` へのリダイレクトを実行できない（agent_write_guard の外の権限判定で止まる）。この記述を、リダイレクトを使わない形（単一の読み取り専用コマンド、または出力を絞るパイプ1段）を勧める記述に最小の変更で直す提案を書く。

## 分割方針
- 人が決めた方針（変えない）：planner の確認コマンドは `/tmp` へのリダイレクトを前提にせず、パイプ（`cmd | tail -1`・`cmd | grep -c`）や単一の読み取り専用コマンドで書く。verifier の `/tmp` 権限を増やす案（issue の提案2つ目）はこの計画に含めない。`.claude/hooks/`・`.claude/settings.json` は触らない（issue #85）。
- T-01 の1タスクだけ。`vault/rules/` には書けないので（`docs/vault-spec.md` 12節「提案ファイル方式」）、成果物は提案ファイル `vault/tasks/P-20261003-planner-no-tmp-redirect/T-01-proposal.md`（`planner.md` の変更後の全文）にする。書き方は `vault/tasks/P-20261003-run-finish-verifier-worktree/T-03-proposal.md` に倣う。実体への反映は人が PR ブランチ上で手で行う。
- 変える行は3行だけ：36行目（代わりの手段の本体）、48行目（ガードの話としては残し、代わりの手段として勧めない旨を1文足す）、60行目（「確認方法」の対応する行。36行目を直すと「事前書き出し＋読み取り」の記述が食い違うため）。置き換え後の文はタスク票の「決定済み」に一字一句で書いてある。
- 36行目はパイプ1段を許す例外を書く。これは33行目の「パイプ…で組み合わせた複合コマンドにしない」と緩く食い違うが、33行目は変えずに36行目で例外として書く（P-20261003-model-stats-blocked-creator の T-02 で、verifier が `bash scripts/smoke.sh 2>&1 | grep -E '^smoke:'` を実行できた実績がある）。
- planner が事前に確かめたこと：置き換え後の3行で現行の全文を組み立て（ファイルには書かず python の標準入力で）、受け入れ基準の各 `grep -c` が期待値（1・0・1・0・1）になり、issue 番号・計画 ID が0件になることを確認した。現行の `planner.md` には issue 番号・計画 ID が無い（`grep -cE` で0）。
- 受け入れ基準の確認コマンドは、すべて単一の読み取り専用コマンド（`diff`・`grep -c`・`grep -n`）。`/tmp` へのリダイレクト・`>` を使う比較・連結は使わない。
