## 決定済み
- 手順7の「全タスクが `done` になったら」の番号付きの手順を次の順に書き直す（番号は振り直してよい。各手順の文字列は下の字面を使う）：
  1. 計画票 frontmatter の `status` を `done` にする（今どおり Edit）
  2. `git add vault/plans/<計画ID>.md` と `git commit -m "<計画ID>: approved→done" -- vault/plans/<計画ID>.md`（今どおり。それぞれ1回の Bash。`(run-skill-1)` が見る字面を変えない）
  3. `python3 scripts/pr_body.py <計画ID>`・`python3 scripts/verdict_notes.py <計画ID>`・`python3 scripts/plan_record.py <計画ID>` を実行し、出力を読む。`plan_record.py` が終了コード0以外なら除去に進まず、標準エラーの内容を添えて人に報告して止まる
  4. 取り出し（次の判断基準。D-016 の決定済みのとおり）：タスク票の「決定済み」の判断・`/plan unblock` の回答・blocked の question のうち、恒久的な仕様や判断でまだ docs に無いものは、`docs/vault-spec.md` などの該当文書か `docs/decisions.md` に追記する（Edit。除去のコミットに含める）。対応しなかった verifier の指摘・残課題は、手順8と同じ `gh api repos/{owner}/{repo}/issues -X POST -f title=<タイトル> -F body=@<本文ファイル> --jq .html_url` で Issue にする。起票に失敗したものは本文の `## 取り出した情報` に「Issue にできなかったもの」として内容を書く。仕様の変更そのものは各タスクで docs に反映済みなので二重に書かない。取り出すものが無ければ何もしない
  5. 本文ファイルを Write ツールで一時ファイル（今どおり `/tmp/<計画ID>-pr-body.md` の例）に書く。中身はこの順：計画 ID の1行、`pr_body.py` の出力、`## verifier の指摘` の見出しと `verdict_notes.py` の出力、`plan_record.py` の出力（`## 計画の記録` から始まる）、`## 取り出した情報` の見出しと、docs に追記した箇所（ファイルと節）と作った Issue の URL の一覧（無ければ「なし」）。出力は言い換えずにそのまま写す。`verdict_notes.py` が終了コード0以外の時の扱い（PR は作り、節に標準エラーを書く）は今どおり
  6. `bash scripts/purge_plan.sh <計画ID>` を実行する。終了コード0以外なら PR を作らず、標準エラーの内容を添えて人に報告して止まる。続けて、取り出しで docs を編集した時はそのファイルを名前で `git add` し（1回の Bash）、`git commit -m "<計画ID>: 計画一式を除去"` を実行する（パスを指定しない。`purge_plan.sh` が stage した削除と、名前で add した docs だけをコミットする。`git add -A`・`git add .` は使わない）
  7. `env HARNESS_PR_BODY_FILE=<本文ファイル> HARNESS_PR_TITLE="<計画ID>: <ゴールの1行目>" bash scripts/vcs_finish.sh`（今どおり。ゴールの1行目は `plan_record.py` の出力の `### ゴール` の最初の行から取る。除去の後は計画票が無いため）
  8. 完了報告に `verdict_notes.py` の出力をそのまま含める（今どおり）。取り出した情報（docs の追記箇所・Issue の URL・Issue にできなかったもの）も含める
- `(run-skill-1)` は手順7の中の最初の `git add vault/plans/<計画ID>.md` と最初の `bash scripts/vcs_finish.sh` の行番号を比べるので、手順7の中で `bash scripts/vcs_finish.sh` の字面を手順7の PR 作成の項より前に書かない（引数なしの経路の説明の段落など、PR 作成の項より後ろはよい）。`bash scripts/purge_plan.sh <計画ID>`・`python3 scripts/plan_record.py <計画ID>`・`git commit -m "<計画ID>: 計画一式を除去"` も、上の順の位置より前に書かない
