# T-02 docs/vault-spec.md の5節・10節に6見出しの検査と「## 進捗」の扱いを書く

## 目的
仕様の正本 `docs/vault-spec.md` を、T-01 で `plan_guard.py` に入れた6見出しの検査と、「## 進捗」の見出しの扱い（planner は見出しだけ書く・creator は無ければ見出しごと足す）にそろえる（Issue #166）。

## 入力
- `docs/vault-spec.md` の「## 5. タスク票」と「## 10. plan_guard フックの判定」
- `.claude/hooks/plan_guard.py`（T-01 で足した `heading_violation` の契機と理由文）
- `scripts/diff_gate.py`（`_split_sections`。見出しを足す時に空行1つが要る理由）
- `scripts/smoke.sh` の `(headings-task)`・`(diff_gate-progress)` のケース

## 成果物
- `docs/vault-spec.md`（1ファイル。5節と10節だけを変える）

## 受け入れ基準
- `grep -c '「## 進捗」は見出しだけを書き、本文は空にする' docs/vault-spec.md` の出力が `1`
- `grep -c '見出しごと末尾に足してから追記する' docs/vault-spec.md` の出力が `1`
- `grep -c '6見出しがそろっていなければブロック' docs/vault-spec.md` の出力が `1`
- 上の3つの文言が、それぞれ「## 5. タスク票」節（前の2つ）と「## 10. plan_guard フックの判定」節（3つ目）の中にある（`grep -n` の行番号が各節の見出し行と次の `## ` 見出し行の間にある）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 5節の「進捗は doing 中に作成エージェントが追記する。」の箇条を書き換え、次の2点を同じ節の箇条として書く。文言はこのとおりの部分文字列を含める
  - planner：「## 進捗」は見出しだけを書き、本文は空にする（見出しを省くと、creator の追記が直前の「決定済み」節の変更と判定され差分ゲートで差し戻される。Issue #166）
  - creator：タスク票に「## 進捗」の見出しが無ければ、既存の行を変えずに、末尾に空行1つを挟んで見出しごと末尾に足してから追記する（空行を挟まないと直前の節の本文が変わったと判定される。`scripts/diff_gate.py` の節の分け方による）
- 10節の粒度の検査の箇条（「タスク票：」「計画票：」の並び）に、次の内容の箇条を1つ足す。文言「6見出しがそろっていなければブロック」をこのとおり含める：タスク票（契機は粒度の検査と同じ draft の計画のタスク票への Write/Edit）は `vault/templates/task.md` の6見出し（`## 目的`・`## 入力`・`## 成果物`・`## 受け入れ基準`・`## 決定済み`・`## 進捗`）を行単位の完全一致で探し、6見出しがそろっていなければブロックして欠けた見出しを示す。順序は検査しない。受け入れ基準の行数の検査より先に行う
- 5節冒頭の「見出しは `目的 / 入力 / 成果物 / 受け入れ基準 / 決定済み / 進捗` の6つで固定。順序も変えない。」は残す（順序は規約として残し、機械の検査は有無だけ、という関係にする）
- 5節・10節以外は変えない。`.claude/skills/plan/SKILL.md` と `vault/templates/task.md` は変えない（検査はフックが担い、テンプレートは既に6見出しを持つため）
- バッククォートで囲むパスは実在するものだけにする（`(ref-1)` が検査する）
- 「成果物のみで他ファイル不変」の確認は書かない（差分ゲートに任せる）
