## 決定済み
- 直す箇所は12節の「### Bash の書き込み対象の解析（issue #91・#87）」小節だけ。12節冒頭の表・他の節は変えない
  - 250行の段落：`analyze_bash_writes` の説明は残し、「解析できない形は従来の判定に落とす（…各判定が従来の正規表現の判定を使う）」を、「`bash_write_targets` が1回のフック呼び出しで1度だけ計算する（同じコマンドはメモ化）。解析できた時は `analyze_bash_writes` の結果、解析できない時は書き込み動詞の正規表現に一致した時だけ、4通りの従来判定の候補の和集合（リダイレクト先・`extract_bash_write_targets` の対象・保護対象パスを含む path-like トークン）を返す。各判定はこの結果をパスで絞り込む」趣旨に直す。語句「`bash_write_targets`」「候補の和集合」「1回のフック呼び出しで1度だけ」をこのとおり書く
  - 保護対象パスの一覧（`vault/rules/`・`vault/plans/`・`vault/log/`・`vault/tasks/`・`vault/verdicts/`・`.claude/projects`）と、候補の末尾の `)`・`"`・`'`・バッククォート・`;` を落とすことを書く
  - 256行（vault/rules・会話記録・creator）：「解析できない時はそれぞれ従来の判定（…）に落とす」を、解析の成否にかかわらず `bash_write_targets` の全ての target をそれぞれのパスで絞り込む趣旨に直す
  - 257行（done 判定）：`git add`・`git commit` だけのコマンドを対象外にする判定（issue #84）が解析できない時も残ることは今のまま書く。候補が和集合になることを足す
  - 258行（ALLOWED 判定）：解析できない時の許可条件を T-03 の「決定済み」どおりに書く（書き込み動詞が無ければ許可／`extract_bash_write_targets` の対象が1つ以上あり、和集合の全候補が repo の外なら許可／リダイレクト先が1つ以上あり、和集合の全候補が `ALLOWED` 配下で破壊的な動詞を含まなければ許可／それ以外は拒否）
  - main 直接コミット拒否（259行）：解析できない時は今どおり正規表現で判定する（和集合の対象外）ことが分かるようにする。中身は変えない
- 「一本化で変わった点」は小節の中に `- 一本化で変わった点（D-011 フェーズ3）：` で始まる箇条書きとして足す。各項目は「<コマンドの形>：変更前は許可→変更後は拒否」の形で書く。少なくとも、verifier・planner の解析できない形のコマンドで、repo の外だけに書き込むのに引数・引用符の中に保護対象パスがあるもの（例：`python3 -c "open('vault/tasks/P/T-01.md')" > /tmp/x.txt`）を書く。T-03 の「進捗」に他の例があれば足す。変わった点が拒否側だけであること（許可が増えた形は無い）も1文で書く
- 「残る弱点」の行（261行）の「従来の判定には … 既知の穴があり」は、和集合の候補でも塞がらない穴なので、「解析できない時の候補には」のように主語だけ合わせて残す
- `_hooklib.py` の段落（263行）は変えない
- `.claude/hooks/agent_write_guard.py`・`scripts/smoke.sh`・`vault/rules/` 配下・他のファイルは変更しない
- コミットは受け入れ基準に無いので、creator はしない
