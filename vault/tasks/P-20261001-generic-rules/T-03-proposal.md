## 目的
作成エージェント（creator）だけに渡す、git 運用の具体的な手順（ブランチ・コミット・PR の役割分担と例外時の振る舞い）を定める。creator は worktree で成果物を作るだけで、コミットの収集・計画ブランチへのマージ・PR 作成はオーケストレーター（run のメインセッション）が行う。原則の理由は `vault/rules/common/git.md` に譲る。

## ルール
- ブランチ：`/plan` が計画ブランチ（`work/<計画IDの英小文字>`）を切り、run が `isolation: "worktree"` で creator 用の worktree を用意する。creator はブランチを切らない・切り替えない
- コミット：creator がコミットするのは、タスク票の受け入れ基準にコミットが書かれている時だけ（受け入れ基準にある時だけ行う）。それ以外の未コミット分は、PASS 後にオーケストレーターが worktree でまとめてコミットし、計画ブランチへ `git merge --no-ff` で取り込む
- 書き込み範囲：creator は計画票のタスク表と `vault/log/<計画ID>.md` に書き込まない（状態更新と log はオーケストレーターの役目）
- PR：全タスクが `done` になった後、オーケストレーターが `bash scripts/vcs_finish.sh` で作る。creator は PR を作らず、`gh pr create` も実行しない。マージは人が行う
- 起点コミット：タスクが `doing` の作業開始時に `git rev-parse --short HEAD` を取り、タスク票の「進捗」の先頭に `起点コミット: <短縮ハッシュ>` の形で1行記録する。verifier はこの起点から `HEAD` までの差分を見て、そのタスクの変更範囲を判断する
- 例外時：受け入れ基準にあるコミットが失敗した場合や、判断が必要になった場合は、自己判断で解決せず、完了報告を `blocked: <質問文>`（状況としてコマンドとエラーの要点を含める）の形にしてオーケストレーターに返す。計画票を `blocked` にするのはオーケストレーターで、マージのコンフリクトもオーケストレーターが扱う

## 確認方法
- `bash scripts/rules.sh creator` の出力に `vault/rules/creator/git-workflow.md` が含まれるか
- creator が新しいブランチを作成・切り替えしていないか（worktree のブランチが run の用意したものか）
- creator のコミットが、受け入れ基準にコミットがあるタスクの分だけか（それ以外は未コミットのままオーケストレーターに渡っているか）
- タスク票の「進捗」の先頭が `起点コミット: <短縮ハッシュ>` になっているか
- `main` に直接コミットしていないか
- PR が全タスク `done` の後に、オーケストレーターの `bash scripts/vcs_finish.sh` でだけ作られているか
