# T-07 docs/vault-spec.md に統一した解析規則を書く

## 目的
T-01〜T-05 で寛容な側に揃えた解析規則（frontmatter の値の引用符を外す・タスク表の行頭の空白を許す・受け入れ基準は `- ` と `数字. ` を数える）を、正本の `docs/vault-spec.md` の該当節に明記する。

## 入力
- `vault/designs/D-011.md`（フェーズ2）
- `docs/vault-spec.md`（4節「計画票の形式」・5節「タスク票」・9節「Stop フックの判定」の verdict が不正の行・12節の「**フックの共通モジュール**」の段落）
- T-01〜T-05・T-08 の成果物（`.claude/hooks/_hooklib.py` の `frontmatter_value`・`parse_tasks`・`count_criteria`、`scripts/current_plan.sh`・`scripts/archive_plans.sh`）

## 成果物
- `docs/vault-spec.md`（1ファイル）

## 受け入れ基準
- 4節に frontmatter の読み方がある：`grep -n '前後の引用符を外して読む' docs/vault-spec.md` と `grep -nF '`scripts/current_plan.sh`・`scripts/archive_plans.sh` も同じ規則で読む' docs/vault-spec.md` の出力の行番号が、どちらも4節の範囲（`grep -n '^## ' docs/vault-spec.md` で見た `## 4.` の行から `## 5.` の行の間）にある
- 4節にタスク表の行の読み方がある：`grep -n 'タスク表の行は行頭の空白を許す' docs/vault-spec.md` の出力の行番号が4節の範囲にある
- 5節に受け入れ基準の数え方がある：`grep -nF '行頭が `- ` か `数字. ` の行を数える' docs/vault-spec.md` の出力の行番号が5節の範囲（`## 5.` の行から `## 6.` の行の間）にある
- 9節の verdict が不正の行が5節の数え方を指す：`grep -n '^| verdict が不正.*受け入れ基準の行数（5節の数え方）' docs/vault-spec.md` の出力が1行
- 12節の共通モジュールの段落に解析規則の関数がある：`grep -n '^\*\*フックの共通モジュール\*\*.*count_criteria' docs/vault-spec.md` の出力が1行

## 決定済み
- 書く内容と位置（下の「 」の文言は受け入れ基準で grep するので、この文言を含める。前後の言い回しは自由）
  - 4節：「frontmatter は `id` と `status` の2つ。」の段落の後に段落を足す。内容は、1行目の `---` から次の `---` の行（無ければ末尾）までを frontmatter として読むこと、値は「前後の引用符を外して読む」（例：`status: "approved"` も approved）、読む規則は `.claude/hooks/_hooklib.py` の `frontmatter_value` にあり「`scripts/current_plan.sh`・`scripts/archive_plans.sh` も同じ規則で読む」こと
  - 4節：タスク表の下の箇条書き（「列の順序・列名・見出し名は変えない」の並び）に1行足す。「タスク表の行は行頭の空白を許す」（`_hooklib.py` の `parse_tasks`。3フックが同じ規則で読む）
  - 5節：箇条書きに1行足す。「## 受け入れ基準」見出しから次の `## ` 見出しまでで、「行頭が `- ` か `数字. ` の行を数える」こと（`_hooklib.py` の `count_criteria`）。stop_gate の verdict 検査（9節）と plan_guard の粒度検査（10節）が同じ数え方を使うこと
  - 9節：表の「verdict が不正」の行の「criteria の行数がタスク票の受け入れ基準の行数と不一致」を「criteria の行数がタスク票の受け入れ基準の行数（5節の数え方）と不一致」にする
  - 12節：「**フックの共通モジュール**」の段落（1段落で1行）の「3フックで共通に使う関数（…）」の括弧の中に、計画票の frontmatter（`frontmatter_value`）・タスク表（`parse_tasks`）・受け入れ基準の行数（`count_criteria`）の読み取りを足す。段落は1行のまま保つ（受け入れ基準の grep が行頭の `**フックの共通モジュール**` と同じ行の `count_criteria` を見る）
- 10節の「行頭が `- ` か `数字. ` の行数を数え」の記述は今のままで正しいので変えない（5節を参照する形に変えてもよい）
- 他の節の記述・表の列構成・見出しは変えない。1節の `scripts/current_plan.sh` の説明も変えない
- `docs/decisions.md` は変更しない（フェーズ2で新しく決めた方針は無い。D-011 の決定事項の範囲）
- フック・scripts・smoke.sh は変更しない（他タスクの担当）
- コミットは受け入れ基準に無いので、creator はしない
