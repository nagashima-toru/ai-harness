# T-0039 `scripts/install.sh` に `merge_settings_json.py` を組み込み、マニフェスト対象を確定する

## 目的
`.claude/settings.json` の複製を `copy_if_absent` から `merge_settings_json.py` 呼び出しに切り替
え、`scripts/merge_settings_json.py` 自身をマニフェスト対象（上書き対象）に加える。これで
`vault/designs/D-001.md` フェーズ1の受け入れ基準候補（settings.json のマージャ組み込み）を満た
す。

## 入力
- T-0037 の `--update` ロジックと対象パス列（`scripts/install.sh` 内）
- T-0038 の `scripts/merge_settings_json.py`
- `vault/designs/D-001.md`「## フェーズ1」の決定事項

## 成果物
- `scripts/install.sh`（変更）

## 受け入れ基準
- `.claude/settings.json` の `permissions.allow` に独自要素を足した状態で
  `bash scripts/install.sh --update <dst>` を実行すると、実行後の `<dst>/.claude/settings.json` に
  その独自要素と、欠けていた hooks エントリ（`hooks[].command` に `todo_guard.py` を含む文字列）の
  両方が含まれる
- `bash scripts/install.sh <dst>`（初回、フラグなし）を実行すると `scripts/merge_settings_json.py`
  が `<dst>/scripts/merge_settings_json.py` として複製される。確認コマンド:
  `test -f <dst>/scripts/merge_settings_json.py && echo ok`（`ok` が出る）
- `scripts/install.sh` の中で `.claude/settings.json` に対して `copy_if_absent` が呼ばれていない。
  確認コマンド: `grep -n 'settings.json' scripts/install.sh` の該当行を目視し、
  `merge_settings_json.py` の呼び出しだけになっていることを確認する
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（新規ケース込み）

## 決定済み
- `.claude/settings.json` の扱いは `--update` の有無・既存ファイルの有無にかかわらず常に
  `python3 "$SRC/scripts/merge_settings_json.py" "$SRC/.claude/settings.json" "$DST/.claude/settings.json"`
  を呼ぶ。settings.json は「上書き対象／利用者資産」の二分法に乗らない専用マージャ対象であり、
  T-0036・T-0037 で作った通常のマニフェスト照合ループの対象パス列には含めない
- `scripts/merge_settings_json.py` 自身は通常のハーネス本体ファイルなので、T-0036・T-0037 の対象
  パス列（マニフェスト管理・`--update` で上書き判定される対象）に追加する（T-0029 が
  `scripts/merge_claude_md.py` を複製対象に追加した時と同じ扱い）
- `.claude/` の複製ループ（`find . -type f ! -name 'settings.local.json'`）は `settings.json` も除
  外するよう変更する（既存の `find` 条件に `! -name 'settings.json'` を足す）。理由：専用マージャ
  で扱うため、複製ループとマニフェスト照合ループの二重処理を避ける
- 標準出力：`merge_settings_json.py` が返す `create`/`merge`/`skip` の1行をそのまま install.sh の
  出力に混ぜる（`merge_claude_md.py` の呼び出し方と同じ扱い）
- `settings.local.json` は従来どおり複製・マージのどちらの対象にもしない

## 進捗
- 読んだルール: roles.md, creator.md
- `scripts/install.sh` を4点変更した
  1. `.claude/` の複製ループの `find` に `! -name 'settings.json'` を追加（専用マージャで扱うため
     複製ループとマニフェスト照合の二重処理を避ける）
  2. `manifest_paths()` の固定パス列に `scripts/merge_settings_json.py` を追加
  3. `copy_if_absent "$SRC/scripts/merge_settings_json.py" ...` を追加（初回 install 用）
  4. `docs/vault-spec.md` の複製の直後に
     `python3 "$SRC/scripts/merge_settings_json.py" "$SRC/.claude/settings.json" "$DST/.claude/settings.json"`
     を追加。`--update` の有無・既存の有無にかかわらず常に呼ぶ
- 冒頭コメントの「複製するもの」から settings.json を外し、専用マージャで扱う旨と
  「インストール先が足した permissions.allow は消さない」ことを明記した
- 受け入れ基準の確認コマンドを一時ディレクトリで実行し、4件すべて通した
  - 初回 install → `<dst>/scripts/merge_settings_json.py` が存在（`test -f` → ok）
  - `grep -n 'settings' scripts/install.sh` → settings.json に対する `copy_if_absent` は無く、
    161行目の `merge_settings_json.py` 呼び出しだけになっている
  - dst の allow に独自要素を足し `hooks.PostToolUse` を消して `--update` → 出力に
    `merge .../settings.json`、独自の allow が残る=True、`todo_guard.py` の hooks が復元=True
  - `bash scripts/smoke.sh | tail -1` → `smoke: pass=89 fail=0`（NG 行なし）
- マニフェストは24件になった（T-0036 の23件＋`scripts/merge_settings_json.py`）。
  `.claude/settings.json` は決定済みのとおり対象外のまま
- `scripts/smoke.sh` に `== install.sh の settings.json 扱い ==` 節を追加（5ケース、(o)(p)）。
  既存ケースは変更していない
