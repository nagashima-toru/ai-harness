# ゴール
`docs/vault-spec.md` を、計画をまたぐキューを持たない新しい状態モデルで書き直す。`vault/todo.md` を廃止
し、計画票が状態を持つこと、ID 体系が `P-YYYYMMDD-<slug>` とスコープ付き `T-01` になること、タスク
票・verdict・ログが計画スコープのディレクトリに入ること、ブランチ名の導出規則を正本として定義する。
`vault/templates/plan.md` を新形式（frontmatter に `status`、本文にタスク表）に更新する。この時点では
コードを変更せず、旧方式が動いたままにする。`vault/designs/D-001.md` フェーズ2に対応する（設計文書の
再検討は行わない）。

## 分割方針
`docs/vault-spec.md` は1ファイルだが全面改訂なので、同じファイルを複数タスクが順に書き換える形にな
る。競合を避けるため直列（`after` の一本鎖）にし、各タスクは自分が担当する節だけを書き、他タスクが
担当する節の内容（特に「まだ書き換えていない旧文言が残っている」こと）を検査しない。

新しい章立て（全13節、最終形）を先に固定し、担当を割り振る：
1. ディレクトリ／2. 状態／3. ID・ファイル名・ブランチ名／4. 計画票の形式／5. タスク票／6.
verdict.json／7. ログ／8. 粒度の基準／9. Stop フックの判定／10. plan_guard フックの判定／11. ルー
ル（`vault/rules/`）／12. agent_write_guard フックの改ざん防止判定／13. 設計文書

- T-0041（契約タスク・依存なし）：1・3・4節。ディレクトリ構造、ID・ブランチ名の体系、計画票の
  frontmatter とタスク表の列（`id`/`status`/`attempt`/`after`/`title`/`question`）を固定する。旧
  「4. todo.md の形式」節は削除し、その内容（表の列定義）を新4節（計画票の形式）に統合する。以降の
  全タスクがこの列定義・ID 体系に依存する。
- T-0042（T-0041 の後）：2・5・6・7節。5状態の定義（`doing` は計画内で常に1件、に補記）、タスク票
  の6見出し（実質無変更、旧文言に `todo.md` 言及が無いため）、`verdict.json` の `task` 値を
  `<計画ID>/T-01` 形式に更新、ログのパスを `vault/log/<計画ID>.md` に更新する。
- T-0043（T-0042 の後）：8・9・10節。粒度の基準（run-queue 不変検査の対象ファイルを計画票に差し替
  え）、Stop フックの判定（読む先を計画票に差し替え、判定表の中身は変えない）、`todo_guard` フックを
  `plan_guard` フックに改称し、計画票のタスク表を検査する記述に差し替える。
- T-0044（T-0043 の後）：11・12・13節。ルール節（無変更・renumber のみ）、`agent_write_guard` の
  改ざん防止判定（`todo.md` の表解析を計画票のタスク表解析に差し替え、`todo_guard.py` への参照を
  `plan_guard.py` に差し替え、`HARNESS_ALLOW_RULES_WRITE` の例をスコープ付き ID 形式に更新）、設計
  文書節（無変更・renumber のみ）。**最後に `docs/vault-spec.md` 全体から `vault/todo.md` への言及
  が消えていることを確認する（全節が出そろった後でないと満たせない基準のため、このタスクだけが持
  つ）。**
- T-0045（T-0041 の後）：`vault/templates/plan.md` を新形式（frontmatter の `status` と、T-0041 が
  定義したタスク表の列）に更新する。ファイルが違うため T-0042〜T-0044 とは並行できるが、実行は
  run-queue が直列に処理する。

依存は T-0041 → T-0042 → T-0043 → T-0044 の一本鎖に、T-0041 → T-0045 が合流する形。循環はない。

## 計画の受け入れ基準
- 各タスクに成果物と受け入れ基準が1つずつある
- 依存に循環がない（T-0041 → T-0042 → T-0043 → T-0044 の一本鎖に T-0041 → T-0045 が合流）
- 1タスクが1コンテキストで終わる粒度である（`docs/vault-spec.md` の3節前後、または `vault/templates/plan.md` 1ファイル）
- `docs/vault-spec.md` から `vault/todo.md` を状態の正本とする記述が消え、計画票が状態を持つ旨に統一されている（T-0044 で最終確認）
- コード（フック・スキル・`install.sh`・`smoke.sh`）を変更するタスクを含まない
