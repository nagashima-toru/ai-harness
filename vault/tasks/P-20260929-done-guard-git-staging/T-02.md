# T-02 vault-spec.md 12節の done 判定の行に git add / git commit のみは対象外である旨を足す

## 目的
`docs/vault-spec.md` 12節の判定表にある「done のタスク票・verdict への書き込み拒否」の行に、T-01 で実装した「Bash コマンドの書き込み動詞が `git add` / `git commit` だけの場合は対象外（混在は従来どおり拒否）」を追記し、仕様の正本を実装と一致させる（issue #84）。

## 入力
- `docs/vault-spec.md` 12節（`## 12.` 〜 `## 13.`）。判定表の2行目（`vault/tasks/<計画ID>/<id>.md` または `vault/verdicts/<計画ID>/<id>.json` が対象の行）が追記対象
- T-01 の成果物 `.claude/hooks/agent_write_guard.py`（対象外にする条件の一次情報。特に `find_done_task_write` の除外判定と冒頭 docstring）
- `.claude/skills/run/SKILL.md` 手順6.3.4（追記の理由となる正規手順。読むだけで変更しない）

## 成果物
- `docs/vault-spec.md`

## 受け入れ基準
- done 判定の行に、`git add` と `git commit` のみのコマンドは対象外であることが書かれている。確認：`sed -n '/^## 12\./,/^## 13\./p' docs/vault-spec.md > /tmp/P-20260929-done-guard-git-staging-T-02-sec12.txt` を実行した後、`grep -E '^\| 対象が `vault/tasks/' /tmp/P-20260929-done-guard-git-staging-T-02-sec12.txt | grep -c 'git add'` の出力が `1`、`grep -E '^\| 対象が `vault/tasks/' /tmp/P-20260929-done-guard-git-staging-T-02-sec12.txt | grep -c 'git commit'` の出力が `1`
- 同じ行に、他の書き込み（リダイレクト・`cp`/`mv`/`rm`・`sed -i`・`tee` 等）が混在する場合は従来どおり拒否されることが書かれている。確認：`grep -E '^\| 対象が `vault/tasks/' /tmp/P-20260929-done-guard-git-staging-T-02-sec12.txt | grep -c '混在'` の出力が `1`
- 既存の記述（fail-open 条件と解除口が無いこと）が残っている。確認：`grep -E '^\| 対象が `vault/tasks/' /tmp/P-20260929-done-guard-git-staging-T-02-sec12.txt | grep -c '対象外'` が `1` 以上、かつ `grep -c '解除口は無い' /tmp/P-20260929-done-guard-git-staging-T-02-sec12.txt` が `2` 以上（vault/rules/ の行と done の行）
- 節見出し・表の列構成は変更されていない。確認：`git diff main -- docs/vault-spec.md | grep -E '^[+-](## |\| 状況 )'` の出力が空
- 変更が12節の該当行1行に限られている（行を増やさず同じ行に足す）。確認：`git diff main -- docs/vault-spec.md | grep -cE '^[+-][^+-]'` の出力が `2`（該当行の削除1 + 追加1）

## 決定済み
- 追記位置は、12節判定表の `vault/tasks/<計画ID>/<id>.md` または `vault/verdicts/<計画ID>/<id>.json` が対象の行（2行目）の中。新しい表の行は作らず、その行の条件列と判定列に文を足す。表の前後の段落、`vault/rules/` の行、「この判定は既存の verifier/planner 向け `ALLOWED` 判定より前に実行される。」の段落は変更しない
- 書く内容（文言は実装に合わせて調整してよいが、`git add`・`git commit`・`混在` の3語を必ず含める）：Bash の書き込み動詞が `git add` / `git commit` だけのコマンドは、ステージ・コミットがファイル内容を変えないためこの判定の対象外（`agent_type` は問わない）。リダイレクト・`cp`/`mv`/`rm`・`sed -i`・`tee`・`git rm` など内容を変える書き込みが混在するコマンドは従来どおりブロックする。実装の詳細（`shlex` によるクォート解釈、コマンド置換を含む場合は除外しない等）は仕様には書かない（実装の docstring が正本）
- 「解除口は無い」の文言は残す。除外は判定の対象範囲の定義であって解除口ではないことが分かる書き方にする
- 表の行は1行のまま（セル内に `|` を入れない。表が崩れる）
- 12節以外（`## 1.`〜`## 11.`・`## 13.`）は変更しない。`.claude/ai-harness.md`・`.claude/skills/run/SKILL.md` も変更しない
- T-01 が `done`（除外判定の実装が確定した状態）になってから着手する。実際に実装された除外条件と文言を一致させるため
