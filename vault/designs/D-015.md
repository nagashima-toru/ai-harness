# ゴール

ハーネスの守りを「本当に守らないと壊れるもの」だけに絞り、人の作業と、守りそのものが原因の詰まりを減らす。ハーネスの核は次の2つで、守りはこの2つを支えるものだけを残す。

- 作成 → 検証：verifier の PASS が無ければ done にしない
- `main` に入るのは、人がレビューしてマージした PR だけ

作業はすべて計画ブランチの上で進み、最後に人が PR をマージする。ブランチの中で壊れても捨てて作り直せるので、ブランチの中の作業は細かく縛らない。

D-014（保護領域の例外を足してサンドボックスを回避する設計。PR #134）は向きが逆なので閉じ、この文書で置き換える。

## 決定事項

| 決めたこと | なぜ |
|---|---|
| 守るのは次の3つだけ。(1) `main` とリモート（force push・`main` への直接コミット・エージェントによる PR のマージを拒否）、(2) PASS の無い done を作らない（`transition.py`・`stop_gate.py`・`plan_guard.py` の verdict の検査）、(3) done のタスク票・verdict を書き換えない（証跡の偽造の防止） | 人の指示「保護するのは本当に守らないと壊れるところだけでいい」。(1) は取り返しがつかない、または人の関門を飛ばす。(2)(3) はハーネスの存在理由。それ以外は PR のレビューと git の履歴で見える・戻せる |
| `/plan` は承認待ちで止まらない。計画を作り、粒度の検査を通したら自分で `approved` にしてコミットし、続けて `/run` を実行する。`/plan approve` は廃止する | 人の回答「plan のあとはすぐに run でいい」。計画の中身は PR で人が見る |
| `plan_guard.py` の会話記録による承認・unblock の裏付けの検査を廃止する | 承認を廃止するので、承認の裏付けは不要。unblock は人が `/plan unblock` で答える運用を残すが、裏付けの検査は git が半端な状態の時に誤検知でブロックし続けた原因で、守るものに見合わない |
| `vault/rules/` の保護をやめる（`agent_write_guard.py` の拒否、提案ファイル方式、会話記録への書き込みの拒否、`gh api`・`curl` のリモート直叩きの検知） | 人の回答「残さなくていい」。標準の役割定義は D-013 でエージェント定義に移っており、`vault/rules/` は導入先のルールだけ。変更は PR の差分で見える |
| このリポジトリの `.claude/settings.json` からサンドボックスの設定（`sandbox` キー全体と `excludedCommands`）を外す。`docs/install.md` の「サンドボックスを有効にする（任意）」は、ハーネス自身を変える作業には向かない旨を書いて残す | サンドボックスが守っていたのは `vault/rules/` と会話記録で、どちらも守る対象から外れる。一方で `.claude/` の保護パス・`.git`・`gh` の TLS・`mktemp` の詰まりと、`excludedCommands` による回避の積み増しを生んでいた |
| `permissions.deny` から `git reset --hard`・`git clean`・`git branch -D`・`curl`・`wget`・`claude` を外す。残すのは `git push --force` 系・`rm -rf` 系・`sudo`・`gh pr merge`・`glab mr merge` | 作業ブランチの上の reset・clean・ブランチ削除は壊れても戻せ、半端な git 状態をエージェント自身が直すのに要る。`curl`・`wget` は `vault/rules/` のリモート書き込み、`claude` は会話記録の偽造への対策で、守る対象から外れた。`rm -rf` はリポジトリの外まで消しうるので残す |
| `agent_write_guard.py` に残す判定は3つだけにする。(a) done のタスク票・verdict への Write/Edit の拒否、(b) `main` 上での `git commit` の拒否、(c) verifier の書き込みを `vault/verdicts/` に限る。Bash の書き込み解析（`bash_write_targets` など）と、creator・planner の書き込み先の制限は削る | (a)(b) は守る3つそのもの。(c) は「検証する側が成果物を直して PASS にする」のを防ぎ、作成 → 検証の核を守る。creator の宣言外の変更は差分ゲートが拒否するので、書き込み先の制限は重複している。Bash の解析は誤検知の修正が続いた割に、守るものが減ると要らない |
| `stop_gate.py` の未コミットの変更でのブロックをやめ、verdict の検査だけにする | 未コミットの変更は壊れる原因ではない。git が半端な状態の時にブロックし続けた原因になっていた |
| 半端な git 状態の診断スクリプトは作らない。runbook の「困ったとき」に、エージェントが自分で直す手順（`git merge --abort`・`git rebase --abort`・作業ブランチでの `git reset --hard`）を書く | deny を外せばエージェントが直せる。詰まりの原因（サンドボックス・deny・会話記録の検査）を取り除くので、検出の仕組みを足す必要が無い（調査に基づく設計判断） |

## フェーズ1 サンドボックスと不要な deny を外す

### ゴール文

`.claude/settings.json` から `sandbox` キーを丸ごと外す。`permissions.deny` から `Bash(git reset --hard*)`・`Bash(git clean *)`・`Bash(git branch -D *)`・`Bash(curl *)`・`Bash(wget *)`・`Bash(claude *)` を外す（`git push --force` 系・`rm -rf` 系・`sudo`・`gh pr merge*`・`glab mr merge*` は残す）。`.claude/skills/run/SKILL.md` の「worktree の後始末（サンドボックス）」の節と、その節への参照を削る。`docs/runbook.md` 9節「サンドボックスを確かめる」を削り、`docs/vault-spec.md` 12節の「サンドボックス」の小節を「使っていない。理由」の短い記述にする。`docs/install.md` の「サンドボックスを有効にする（任意）」に、ハーネス自身（`.claude/`）を変える作業には向かない旨を足す。

### 受け入れ基準の候補
- `.claude/settings.json` に `sandbox` キーが無い。確認：`python3 -c "import json;print('sandbox' in json.load(open('.claude/settings.json')))"` が `False`
- `permissions.deny` に `git reset --hard`・`git clean`・`git branch -D`・`curl`・`wget`・`claude` を含む項目が無く、`git push --force`・`git push -f`・`rm -rf`・`sudo`・`gh pr merge`・`glab mr merge` を含む項目は有る（`python3 -c` で `permissions.deny` を表示して確認）
- `.claude/skills/run/SKILL.md` に「worktree の後始末（サンドボックス）」の見出しと、それへの参照が無い。確認：`grep -c "後始末（サンドボックス）" .claude/skills/run/SKILL.md` が `0`
- `docs/runbook.md` に「サンドボックスを確かめる」の節が無く、`docs/vault-spec.md` と `docs/install.md` に `excludedCommands` の現在の値の説明が残っていない。確認：`grep -n "excludedCommands" docs/*.md`
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（参照切れの検査を含む）

### 決定済み
- `transition.py` の後始末（`git worktree remove --force`・`git branch -d`）はサンドボックスが無ければ成功するので、`transition.py` は変えない
- `scripts/discard_worktree.sh` は残す（ハング・中断からの再開で使う）。`scripts/vcs_finish.sh` も変えない
- 一時ファイルを `${TMPDIR:-/tmp}` の下に作る `mktemp` の書き方（D-013）は害が無いので戻さない
- `permissions.allow` は変えない
- `scripts/merge_settings_json.py` は変えない（もともと `sandbox` キーを導入先に足していない）
- smoke に `sandbox` キーの有無を見るケースがあれば、「無い」を確かめる形に直す

## フェーズ2 承認待ちをなくし、会話記録の検査を外す

### ゴール文

`/plan` を、承認待ちで止まらない流れにする。`.claude/skills/plan/SKILL.md` の A（計画を作る）の最後で、粒度の検査を通ったら計画票の `status` を `approved` にし、log に `- <日時> - draft→approved /plan による自動承認` を足してコミットし、続けて `/run`（`.claude/skills/run/SKILL.md`）の手順を実行する。B（`/plan approve`）は削る。C（`/plan unblock`）は残す。`.claude/hooks/plan_guard.py` から、会話記録による承認の裏付けの検査と unblock の裏付けの検査を削る（表の整合・done の行の verdict・粒度の検査は残す）。`.claude/ai-harness.md`・`docs/runbook.md` 1〜2節・`docs/vault-spec.md` 10節を合わせる。

### 受け入れ基準の候補
- `.claude/skills/plan/SKILL.md` に `/plan approve` の手順（B 節）が無く、A の最後が「approved にしてコミットし、`/run` を続けて実行する」になっている。確認：`grep -c "plan approve" .claude/skills/plan/SKILL.md` が `0`
- `plan_guard.py` は、作業ツリーでだけ approved の計画票があり会話記録に `/plan approve` が無い状態でもブロックしない（smoke のケース。旧ケースを置き換える）
- `plan_guard.py` は、HEAD で blocked の行が作業ツリーで todo になっていて会話記録に `/plan unblock` が無い状態でもブロックしない（smoke のケース）
- `plan_guard.py` の表の整合（列数・status・依存・blocked の question・id の重複）、done の行の verdict、粒度の検査の既存ケースが PASS する
- `.claude/ai-harness.md`・`docs/runbook.md`・`docs/vault-spec.md` に `/plan approve` が残っていない。確認：`grep -rn "plan approve" .claude/ai-harness.md docs/`。`bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- 計画票の `draft` の状態は残す。planner が書いている間だけ `draft` で、粒度の検査（`plan_guard.py`）は今どおり `draft` の計画票に効く
- `/plan` から続けて `/run` を実行する時、セッションのモデルは変えない（creator・verifier はサブエージェントで、それぞれの定義のモデルで動く）
- `/plan unblock` の C 節は手順を変えない。人が回答を渡す入口として残し、フックでの裏付けだけをやめる
- `_hooklib.py` の `human_messages` など、会話記録を読む関数は、ほかに使う所が無くなれば削る。使う所が残れば残す
- `scripts/transition.py` の「approved でなければ拒否」は残す（計画票の状態の整合のため）
- `vault/log/` の既存の行（`人の指示: /plan approve ...`）は書き換えない

## フェーズ3 agent_write_guard を3つの判定に絞る

### ゴール文

`.claude/hooks/agent_write_guard.py` の判定を次の3つだけにする。

- (a) done のタスク票（`vault/tasks/<計画ID>/<id>.md`）・verdict（`vault/verdicts/<計画ID>/<id>.json`）への Write・Edit・MultiEdit・NotebookEdit を、agent_type を問わず拒否する（今の判定と同じ条件）
- (b) 現在のブランチが `main` の時の `git commit` を拒否する（Bash のコマンドを正規表現で見る簡単な判定。引用符の中などの誤検知は許容する）
- (c) verifier の Write・Edit の書き込み先を `vault/verdicts/` に限る

`vault/rules/` の保護、会話記録への書き込みの拒否、リモート直叩き（`gh api`・`curl`）の検知、Bash の書き込み解析（`bash_write_targets` とその周辺）、creator・planner の書き込み先の制限は削る。worktree への委譲は残す。`scripts/smoke.sh` の削った判定のケースを消し、`docs/vault-spec.md` 11〜12節を新しい判定に合わせる（提案ファイル方式の記述も消す）。

### 受け入れ基準の候補
- done のタスク票・verdict への Edit は拒否され、doing のタスク票への Edit は許可される（smoke のケース）
- `main` 上の `git commit -m x` は拒否され、`work/<計画ID>` 上では許可される（smoke のケース）
- verifier の `vault/verdicts/` 以外への Write は拒否され、`vault/verdicts/` への Write は許可される（smoke のケース）
- creator・メインセッションの `vault/rules/x.md` への Write、`python3 -c` などの Bash による書き込みは拒否されない（smoke のケース）
- `agent_write_guard.py` に `bash_write_targets` が無い。確認：`grep -c "bash_write_targets" .claude/hooks/agent_write_guard.py` が `0`
- `docs/vault-spec.md` に「提案ファイル方式」と「改ざん防止」の記述が無い。`bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- done のタスク票・verdict の Bash による書き換えは拒否しない。PR の差分と、`plan_guard.py`・`stop_gate.py` の verdict の検査で見える
- (b) の判定は、`git` に続く `commit` を `&&`・`;`・改行で区切った各部分で見る程度にとどめる。`git -C . commit` の形も拒否する。ブランチが取れない時（detached HEAD）は素通りする（今どおり）
- `_hooklib.py` の関数で、どこからも使われなくなったものは削る
- 1タスクで消す行数が多くなるので、planner は「フックの本体」「smoke のケース」「文書」でタスクを分けてよい（同じファイルを2つのタスクで変えない）
- `vault/rules/` のディレクトリと `scripts/rules.sh` は残す（導入先のルールの置き場として使う）

## フェーズ4 stop_gate を verdict の検査だけにする

### ゴール文

`.claude/hooks/stop_gate.py` から、未コミットの変更でのブロックを削る。判定は、worktree への委譲・`stop_hook_active`・approved な計画票の件数・done の行の verdict・doing/review の行の verdict だけにする。`scripts/smoke.sh` の未コミットのケースを、ブロックしないことを確かめる形に直し、`docs/vault-spec.md` 9節の判定表を合わせる。

### 受け入れ基準の候補
- 承認済みの計画票が1件あり、未コミットの変更がある git リポジトリで、doing/review の行が無ければ `stop_gate.py` は許可する（smoke のケース）
- done の行に PASS の verdict が無い時は、今どおりブロックする（smoke の既存ケース）
- doing/review の行の verdict の判定（無い・不正・FAIL・PASS で done でない）の既存ケースが PASS する
- `docs/vault-spec.md` 9節の判定表に「未コミットの変更」の行が無い。確認：`sed -n '/^## 9\./,/^## 10\./p' docs/vault-spec.md | grep -c 未コミット` が `0`
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- `has_uncommitted_changes` は、ほかに使う所が無ければ削る
- `HARNESS_STRICT_STOP` と `run_unattended.py` の既定（`1`）は変えない
- approved な計画票が2件以上でブロックする判定は残す（1ブランチ1計画の不変条件）

## フェーズ5 文書を守りを絞った後の姿に揃える

### ゴール文

`docs/runbook.md`・`docs/install.md`・`docs/vault-spec.md`・`docs/vision.md`・`docs/decisions.md`・`.claude/ai-harness.md` を、フェーズ1〜4 の後の実際の状態に揃える。runbook の冒頭の「人の仕事」を「ゴールを入れる・blocked に答える・PR をマージする・月次で片づける」にする。「困ったとき」に、git が半端な状態（merge・rebase の途中、HEAD と作業ツリーの食い違い）になった時にエージェントが自分で直す手順を足す。`docs/decisions.md` に、守りを絞った判断（この文書の決定事項の1行目）を足す。runbook に「権限モードの選び方」の節を足す。ハーネス自身（`.claude/`）を変える計画は acceptEdits で立ち上げ、それ以外は auto モードでよい。auto モードで Self-Modification の拒否が出て blocked になった時は、acceptEdits で立ち上げ直して `/plan unblock` → `/run` で再開する。

### 受け入れ基準の候補
- `docs/runbook.md` の冒頭の人の仕事に「計画を承認する」が無く、「PR をマージする」が有る
- `docs/runbook.md` の「困ったとき」に、`git merge --abort`・`git rebase --abort`・作業ブランチでの `git reset --hard` を使う復旧の手順が有る。確認：`grep -n "rebase --abort" docs/runbook.md`
- `docs/decisions.md` に、守るのは3つだけにした判断と、その理由が1行で有る
- `docs/` と `.claude/ai-harness.md` に、`/plan approve`・`excludedCommands`・`提案ファイル`・`会話記録で確認` が残っていない。確認：`grep -rn "plan approve\|excludedCommands\|提案ファイル\|会話記録で確認" docs/ .claude/ai-harness.md`
- `docs/runbook.md` に「権限モードの選び方」の節があり、`.claude/` を変える計画は acceptEdits・それ以外は auto でよいこと・Self-Modification で blocked になった時の再開手順が書かれている。確認：`grep -n "acceptEdits" docs/runbook.md`
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- 文書の変更だけで、コード・設定は変えない
- 実際の値は `.claude/settings.json` とフックのコードを正とし、文書にはその意味を書く
- `vault/designs/` の過去の設計文書と `vault/log/`・`vault/archive/` は書き換えない（当時の記録として残す）
