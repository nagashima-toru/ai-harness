# T-05 runbook.md の PR 作成手順を vcs_finish.sh 経由の記述に更新する

## 目的
`docs/runbook.md`「3. キューを回す」節にある `gh pr create`/`gh pr merge` 前提の記述を、
`scripts/vcs_finish.sh` 経由の記述に更新する。

## 入力
- `docs/runbook.md`「## 3. キューを回す」節
- `vault/tasks/P-20260924-vcs-finish/T-01.md`「決定済み」（`scripts/vcs_finish.sh` の呼び出し方の契約）
- `vault/designs/D-005.md`（決定済み）

## 成果物
- `docs/runbook.md` の更新（この1ファイルのみ）

## 受け入れ基準
- `docs/runbook.md` に `gh pr create` という文字列が残っていない。確認:
  `grep -c "gh pr create" docs/runbook.md` が0
- 「3. キューを回す」節に `scripts/vcs_finish.sh` を実行する旨の記述がある。確認:
  `grep -n "vcs_finish.sh" docs/runbook.md` がヒットする
- ホスティング無し（`none`）時の案内（ブランチ名・`git merge --no-ff`）を人に伝え、それを使って
  `main` へ取り込む旨の記述がある。確認: `grep -n "git merge --no-ff" docs/runbook.md` がヒットする
- マージ手順の記述が GitHub 限定（`gh pr merge` だけ）ではなく、GitLab またはホスティング無しにも触
  れている。確認: `grep -c "glab\|GitLab\|ホスティング無し" docs/runbook.md` が1以上

## 決定済み
- 更新対象は「## 3. キューを回す」節の該当2行のみ。他の節（0・1・2・4）は変更しない
- 1行目の例：「承認済み計画の全タスクが `done` になったら、計画票の `status` を `done` にし
  `bash scripts/vcs_finish.sh` を実行する（GitHub なら `gh pr create`、GitLab なら `glab mr create` が
  呼ばれて PR/MR ができる。ホスティング無しの場合はブランチ名と `git merge --no-ff` の案内が出るの
  で、それを人に伝える）」のように書く
- 2行目の例：「PR/MR ができたら、人が内容を確認して GitHub/GitLab 上の通常のマージ操作でマージする
  （ホスティング無しの場合は案内された `git merge --no-ff` を人が実行する）。コンフリクトがあれば計
  画のブランチ上で人が解決する。エージェントは `scripts/vcs_finish.sh` の実行までしか行わない」のよう
  に更新する。エージェントがマージを実行しないという既存方針は変えない
- `HARNESS_VCS_HOST` という環境変数名や自動判定の詳細ロジックの説明は必須ではない（詳細は
  `docs/vault-spec.md` やスクリプト自体に譲ってよい）が、書いても構わない
