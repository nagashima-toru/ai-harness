# T-01 smoke.sh の /tmp 固定パスを $TMP 配下の一意なパスに置き換える

## 目的
`scripts/smoke.sh` を同時に複数走らせても、固定パスの git フィクスチャ（index.lock）や会話記録ファイルの取り合いで偽の fail が出ないようにする（Issue #95）。

## 入力
- `scripts/smoke.sh`（11〜12行目の `TMP`/trap、471・545・592・610・757・805・833・883・1354・1355 行付近）
- `vault/plans/P-20261002-smoke-tmp-unique.md` の「分割方針」（対象・対象外の一覧）

## 成果物
- `scripts/smoke.sh`（このファイルだけを変更する）

## 受け入れ基準
- 実体として作る・読む `/tmp/P-` 固定パスが残っていない。確認：`grep -nE '(=|")/tmp/P-' scripts/smoke.sh` の出力が空（変更前はちょうど10行出る）
- 置き換え後のパスが `$TMP` 配下である。確認：`grep -nE '^(TG_HOME|AP_TRANSCRIPT|UB_TRANSCRIPT|AP_REPO|UP_REPO|RU_PID|RU_ERR)=' scripts/smoke.sh` の7行すべてが `$TMP/` で始まる値を代入している
- 逐次実行の結果が変わらない。確認：`bash scripts/smoke.sh > /tmp/P-20261002-smoke-tmp-unique-T-01-seq.txt 2>&1` の後、`grep -x 'smoke: pass=435 fail=0' /tmp/P-20261002-smoke-tmp-unique-T-01-seq.txt` が1行出る
- 3並列で同時に走らせても全て fail=0。確認：Bash ツールの `run_in_background` で次の3コマンドを間を置かずに続けて起動し、3つとも終わってから `grep -h '^smoke:' /tmp/P-20261002-smoke-tmp-unique-T-01-par1.txt /tmp/P-20261002-smoke-tmp-unique-T-01-par2.txt /tmp/P-20261002-smoke-tmp-unique-T-01-par3.txt` の3行がすべて `smoke: pass=435 fail=0`。起動コマンド：`bash scripts/smoke.sh > /tmp/P-20261002-smoke-tmp-unique-T-01-parN.txt 2>&1`（N=1,2,3）
- 新たな `rm -rf` を足していない。確認：`grep -c 'rm -rf' scripts/smoke.sh` が 48 以下（計画時点の値は 48。コメントの言い換えで減るのは可）
- 変更したのは成果物とタスク票だけ。確認：`git status --porcelain` に出るパスが `scripts/smoke.sh` と `vault/tasks/P-20261002-smoke-tmp-unique/T-01.md` 以外に無い（計画票・`vault/log/` は run が変えるので除く）

## 決定済み
- 置き換え先は `$TMP` 配下にする（例：`TG_HOME="$TMP/transcript-guard-home"`、`AP_TRANSCRIPT="$TMP/approve-transcript.jsonl"`、`UB_TRANSCRIPT="$TMP/unblock-transcript.jsonl"`、`AP_REPO="$TMP/approve-post-repo"`、`UP_REPO="$TMP/unblock-post-repo"`、`RU_PID="$TMP/run-unattended.pid"`、`RU_ERR="$TMP/run-unattended.err"`）。名前は例のとおりでなくてよいが、変数名・代入の形（`VAR="$TMP/..."` を行頭に書く）は基準2の grep に合わせる。別の `mktemp -d` を増やす必要はない
- `$TMP` は git リポジトリではなく、`$TMP/vault/plans` は他のテストが使う。フィクスチャは `$TMP/vault/` と別の名前のサブディレクトリにし、`$TMP/vault/` の下には置かない
- 「存在しない会話記録」（592・805・883）は `$TMP` 配下の、どこでも作らない名前にする（例：`AP_NONEXIST="$TMP/approve-nonexistent.jsonl"`、`UB_NONEXIST="$TMP/unblock-nonexistent.jsonl"` を変数にして使い回す）。592 は単一引用符の JSON なので `'"$AP_NONEXIST"'` のように引用を区切って埋め込む。そのパスに書く処理を足さないこと（存在しないことを保つ）
- 後始末は既存の `trap 'rm -rf "$TMP"' EXIT` に任せる。git フィクスチャの `ap_reset`/`up_reset`（`git init` し直し・`update-ref -d HEAD` 等）や既存の `rm -f` はそのまま残してよい（`$TMP` 配下で毎回新しいので害はない）。新しく `rm -rf` を書かない
- 756 行付近のコメント「git フィクスチャは固定パス」、545 行付近の「固定パス方式」など、事実と合わなくなるコメントは「`$TMP` 配下（実行ごとに一意）」の趣旨に直す
- 対象外（触らない）：`run_guard`・`bp`・`bpc`・`expect_tg` 等に渡す JSON・コマンド文字列内の `/tmp/...`（例：512 行の `/tmp/P-20261002-write-guard-false-positive-note.md`、`/tmp/a`、`/tmp/x`）、1381 行のログ本文 `path=/tmp/wt-T-01`。これらはガード・集計に渡す文字列で、実ファイルを作らない。基準1の正規表現はこれらにマッチしないことを planner が確認済み
- テスト件数・判定は変えない。テストの追加・削除はしない（基準3の `pass=435` は、計画ブランチ作成時点で planner が逐次実行して得た値）
- 計画時点の再現：同じ3並列を変更前の smoke.sh で走らせると `pass=417 fail=18` 等になり、NG は `(approve-post)`・`(unblock-post)` に集中していた
- `RU_PID` は `HARNESS_RUN_CMD` の文字列に埋め込まれる（`echo \$! > $RU_PID`）。`$TMP`（macOS では `/var/folders/...`）は空白を含まないのでそのままでよい
- run スキル（`.claude/skills/run/SKILL.md`）に「smoke.sh は逐次で呼ぶ」旨の注記は入れない（根本修正で不要。ゴール外）
