# T-01 merge_settings_json.py に worktree.baseRef のマージ処理を足す

## 目的
`scripts/merge_settings_json.py` に、トップレベル `worktree.baseRef` を導入先へ冪等にマージする処理を追加する。導入先に無ければ足し、同じ値なら何もせず、別の値なら上書きせず `note` で案内する。

## 入力
- `vault/designs/D-007.md`（この計画の元設計文書）
- `scripts/merge_settings_json.py`（`merge_hooks`・`merge_deny`・`main` 関数。`merge_worktree_base_ref` 相当の関数をここに追加する）
- `scripts/unmerge_settings_json.py`（変更しないことを確認するためだけに読む）
- `.claude/settings.json`（ハーネス側 src。`worktree.baseRef` が `"head"`）

## 成果物
- `scripts/merge_settings_json.py`

## 受け入れ基準
- `worktree` キーを持たない dst に対して実行すると、出力の1行目が `merge` で始まり、dst の `worktree.baseRef` が `"head"` になる。確認：`STMP=$(mktemp -d); python3 -c "import json; d=json.load(open('.claude/settings.json')); del d['worktree']; open('$STMP/dst.json','w').write(json.dumps(d))"; python3 scripts/merge_settings_json.py .claude/settings.json "$STMP/dst.json"; python3 -c "import json;print(json.load(open('$STMP/dst.json'))['worktree']['baseRef'])"` の1行目が `merge ...`、最後の出力が `head`
- `worktree.baseRef` が `"fresh"` の dst に対して実行すると、値は `"fresh"` のまま変わらず、出力に `note` で始まり `worktree.baseRef` を含む行が出る。確認：`STMP=$(mktemp -d); python3 -c "import json; d=json.load(open('.claude/settings.json')); d['worktree']={'baseRef':'fresh'}; open('$STMP/dst.json','w').write(json.dumps(d))"; python3 scripts/merge_settings_json.py .claude/settings.json "$STMP/dst.json" | grep -c '^note.*worktree.baseRef'` が1以上、かつ `python3 -c "import json;print(json.load(open('$STMP/dst.json'))['worktree']['baseRef'])"` が `fresh`
- `worktree.baseRef` が既に `"head"` で hooks・deny も揃っている dst に対して実行すると、出力が `skip` で始まりファイルの中身が変わらない。確認：`STMP=$(mktemp -d); cp .claude/settings.json "$STMP/dst.json"; before=$(cat "$STMP/dst.json"); python3 scripts/merge_settings_json.py .claude/settings.json "$STMP/dst.json"` の出力1行目が `skip ...`、かつ `diff <(echo "$before") "$STMP/dst.json"` が空
- 利用者が足した `permissions.allow` の要素と `worktree` 配下の他のキーは、マージ後も残る。確認：`STMP=$(mktemp -d); python3 -c "import json; d=json.load(open('.claude/settings.json')); del d['worktree']['baseRef']; d['worktree']['other']='x'; d['permissions']['allow'].append('Bash(独自 *)'); open('$STMP/dst.json','w').write(json.dumps(d))"; python3 scripts/merge_settings_json.py .claude/settings.json "$STMP/dst.json"; python3 -c "import json;d=json.load(open('$STMP/dst.json'));print(d['worktree']['other'], 'Bash(独自 *)' in d['permissions']['allow'])"` が `x True`
- `scripts/unmerge_settings_json.py` を変更していない。確認：`git diff main -- scripts/unmerge_settings_json.py` の出力が空

## 決定済み
- 対象はトップレベルの `worktree` 配下の `baseRef` だけ。ほかのトップレベルキーを汎用的にマージする仕組みは作らない
- ハーネス側（src）に `worktree.baseRef` が無ければ何もしない（現状の `.claude/settings.json` には `"head"` があるので、この分岐は将来 src が変わった時のための保険でよい）
- 導入先の `worktree` がオブジェクトでない（配列・文字列など）場合は触らず、`note` で型が不正な旨を出す。終了コードは0のまま（hooks/deny の型不正時の非0終了とは扱いを分ける）
- 別の値が入っている時の `note` 行は「変更した/していない」の判定（`merge`/`skip` の分岐）には含めない。それだけなら `skip`。`note` 行は `merge`/`skip`/`create` の行より前に標準出力へ出す
- dst が存在しない時は今までどおり src を丸ごと書く（`worktree.baseRef` も自然に入る）。この経路（`create`）は変えない
- 関数名・実装の内部構成は自由。既存の `merge_hooks`/`merge_deny` と同様に、dst を破壊的に更新して足した/変更した件数や有無を呼び出し側に返せる形にすること
- `note` 文言は「`worktree.baseRef` が `<値>` のため `run` の worktree が計画ブランチから分岐せず blocked になる。`"head"` にすること」という趣旨を含めること（文言の一字一句は問わない）
