# T-07 README/runbook に PR 後の人によるマージ手順を追記する

## 目的
`README.md` と `docs/runbook.md` に、PR ができた後は人が内容を確認してマージする手順を明記する（エージェントは `gh pr create` までしか行わないことと対になる案内）。

## 入力
- `README.md`（「使い方」表・「仕組み」の節）
- `docs/runbook.md`（「## 3. キューを回す」の節）
- `vault/designs/D-001.md` の「## フェーズ5」

## 成果物
- `README.md`・`docs/runbook.md`（PR 後は人がマージする手順の追記）

## 受け入れ基準
- `README.md` に、PR ができた後は人が確認して `gh pr merge` でマージする旨の一文がある。確認：`grep -c 'PR ができたら' README.md` が1以上、`grep -c 'gh pr merge' README.md` が1以上
- `docs/runbook.md` に同様の一文がある。確認：`grep -c 'PR ができたら' docs/runbook.md` が1以上
- 既存のエージェント側の制約（`gh pr create` までで `gh pr merge` は実行しない）と矛盾しない文言になっている
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（ドキュメントのみの変更で影響しないことを確認する）

## 決定済み
- 追記する一文の例（そのまま使ってよい）：「PR ができたら、人が内容を確認して `gh pr merge` でマージする（コンフリクトがあれば計画のブランチ上で人が解決する。エージェントは `gh pr create` までしか行わない）。」
- `README.md` の追記先：「## 仕組み」の図の下、または「## 使い方」の表の下に1〜2行で追加する（見出し構成は変えなくてよい）
- `docs/runbook.md` の追記先：「## 3. キューを回す」の既存の `gh pr create` に触れている箇条書きの下に1行追加する（新しい番号見出しを起こす必要はない）
- 文言は日本語の一文でよく、grep 対象の「PR ができたら」「gh pr merge」をそのまま含める
- コード・フックには触れない、ドキュメントのみのタスク

## 進捗
- 読んだルール: git.md, roles.md, creator.md, git-workflow.md
- `README.md`：「仕組み」の図の直下に決定済みの一文をそのまま追記
- `docs/runbook.md`：「3. キューを回す」の既存の `gh pr create` に触れている箇条書きの下に
  同じ一文を1行追加
- 受け入れ基準の確認コマンドを実行し、4件すべて通した
  - README `PR ができたら`=1 / `gh pr merge`=1
  - runbook `PR ができたら`=1
  - 文言は「エージェントは gh pr create までしか行わない」と明記しており既存制約と矛盾しない
  - `bash scripts/smoke.sh | tail -1` → `smoke: pass=99 fail=0`
- `vault/rules/common/git.md` のルールに沿い、作業ステップごとにコミットする
