# T-03 planner.md の grep パターンの特殊文字の列挙に # がある

## 目的
Issue #211 を解決する。導入先で、パターンに `#` を含む単一の grep が creator の実行環境で複合コマンドとして拒否された。`.claude/agents/planner.md` の「やらないこと」の grep パターンの特殊文字の箇条と、「書き終えた後の確認」の対応する行に `#` を足し、`#` を `.` に置き換える例を示す。

## 入力
- `.claude/agents/planner.md`（「やらないこと」の、grep パターンにシェルの特殊文字を含めない箇条（94行付近）と、「書き終えた後の確認」の対応する行（104行付近））

## 成果物
- 主な成果物：`.claude/agents/planner.md`（1ファイル）
- 変えるファイル：
  - `.claude/agents/planner.md`

## 受け入れ基準
- 特殊文字の列挙が `#` を含む8つになっている：`grep -c '特殊文字（...・...・...・...・...・...・...・...・バッククォート）を含めない' .claude/agents/planner.md` の出力が `1`
- `#` を `.` に置き換える例がある：`grep -c 'grep -c ..61 で追加予定' .claude/agents/planner.md` の出力が `1`
- 経緯の Issue 番号が書かれている：`grep -c 'Issue .211' .claude/agents/planner.md` の出力が `1`
- セルフチェックの行が `#` に触れている：`grep -c 'パターンにシェルの特殊文字（....を含む）を含めていないか' .claude/agents/planner.md` の出力が `1`
- 文書のパス参照が壊れていない：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 「やらないこと」の箇条の冒頭の列挙を、`（`$`・`"`・`>`・`<`・`&`・`|`・`;`・`#`・バッククォート）` にする（`;` とバッククォートの間に `#` を足す。ほかの並びは変えない）
- 同じ箇条の既存の例（`remove --force ..LEAF` の例）の文の後ろに、次の文をこの文字どおり足す：「`#` を含む部分文字列も同じく `.` に置き換える（例：`#61 で追加予定` を含む行は、`grep -c '.61 で追加予定' <ファイル>` のように確かめる）。導入先の creator で、パターンに `#` を含む単一の grep が複合コマンドとして拒否されたことがある（Issue #211。単一引用符の中でもシェルのコメント記号とみなされた可能性があるが、原因は確定していない）。」
- 「書き終えた後の確認」の行「確認コマンドの grep パターンにシェルの特殊文字を含めていないか。含めずに書けない時は、特殊文字を `.` に置き換えたパターンにしたか」を、「確認コマンドの grep パターンにシェルの特殊文字（`#` を含む）を含めていないか。含めずに書けない時は、特殊文字を `.` に置き換えたパターンにしたか」にする
- `Issue #211` はこのファイルの中で上の1か所だけに書く
- `vault/rules/planner/ai-harness-lessons.md`（経緯集）は変えない（ゴールに含まれないため）
- 拒否の原因が `#` かどうかの再現は、このタスクでは行わない（Issue の提案の「可能なら」の部分。ゴールに含まれないため）
