# T-01 verifier エージェント定義に worktree からメインリポジトリへの書き込み先明記を追加する

## 目的
verifier が `EnterWorktree` で対象 worktree に入った状態のまま相対パスで `vault/verdicts/` を書くと worktree 側に書き込まれてしまう問題（issue #61）を防ぐため、`.claude/agents/verifier.md` に「書き込み先は必ずメインリポジトリ側のパスにする」ことを明記する。

## 入力
- `.claude/agents/verifier.md`（変更対象）
- `.claude/skills/run/SKILL.md` 手順5（verifier を対象 worktree に `EnterWorktree(path=...)` で呼び出す既存の運用。この呼び出し方自体は変更しない）
- issue #61 本文（`vault/plans/P-20260926-verifier-verdict-worktree-path.md` のゴール節に要約あり）

## 成果物
- `.claude/agents/verifier.md`（1ファイル）

## 受け入れ基準
- `grep -n "EnterWorktree" .claude/agents/verifier.md` の出力が1行以上ある（プロンプトで渡された worktree に入る手順が明記されている）
- `grep -n "ExitWorktree" .claude/agents/verifier.md` の出力が1行以上ある（verdict を書く前にメインリポジトリ側へ戻る、または絶対パスで書く手順が明記されている）
- `grep -c '^## ' .claude/agents/verifier.md` の出力が `5`（既存の見出し「入力/読むもの/手順/禁止/出力」が維持されている）
- `git status --porcelain -- . ':!.claude/agents/verifier.md' ':!vault/tasks/P-20260926-verifier-verdict-worktree-path/T-01.md'` の出力が空（成果物とタスク票以外に変更が無い）

## 決定済み
- 挿入位置は「手順」節。既存の番号付き手順（1〜10）はそのまま活かし、番号を振り直してよい。新しい指示は次の2箇所に相当する内容を追加する：
  1. プロンプトに「対象 worktree: `<path>`」が含まれる場合、検証を始める前に `EnterWorktree(path=<path>)` でその worktree に入ること（既存の手順1の前に置く）
  2. `vault/verdicts/<計画ID>/<id>.json` を書く直前（既存の手順10の直前）に、worktree に入っていた場合は `ExitWorktree(action: "keep")` を呼んでメインリポジトリ側の working directory に戻ってから Write すること。worktree・ブランチ自体は残したままでよい（`keep`）。絶対パス（`$CLAUDE_PROJECT_DIR` 基準）で直接書く代替でもよいが、どちらか一方の方法を明記すれば足りる
- 「メインリポジトリ」という語は、書き込み先の説明の中で使うこと（新設の独立した文でなくてよい）
- 既存の判定ロジック（曖昧判定・緩さ判定・起点コミット検査・JSON フォーマット・禁止事項）は変更しない。追記のみ行う
- verdict の JSON 構造例（`"task"`・`"attempt"` を含むブロック）は変更しない
