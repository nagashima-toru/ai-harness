# T-01 BASH_WRITE_PATTERNS・OTHER_WRITE_PATTERNS・DESTRUCTIVE_BASH_PATTERN を1つの定義から組み立てる

## 目的
`agent_write_guard.py` で3か所に書き分けられている書き込み動詞の正規表現（`BASH_WRITE_PATTERNS`・`OTHER_WRITE_PATTERNS`・`DESTRUCTIVE_BASH_PATTERN`）を、1つの動詞の定義から組み立てる形にまとめる。どの文字列に一致するかは変えない。

## 入力
- `vault/designs/D-011.md`（フェーズ3）
- `.claude/hooks/agent_write_guard.py`（72〜86行の `BASH_WRITE_PATTERNS`・`OTHER_WRITE_PATTERNS`、162〜165行の `DESTRUCTIVE_BASH_PATTERN`、229行の `GIT_WRITE_SUBCOMMANDS`）
- フィクスチャ：`vault/tasks/P-20261005-bash-write-unify/fixtures/patterns_check.py`（一本化前の定義の写しと201件のサンプル。planner が作成済み。編集しない）

## 成果物
- `.claude/hooks/agent_write_guard.py`（1ファイル）

## 受け入れ基準
- 構文が正しい：`python3 -B -c "import ast; ast.parse(open('.claude/hooks/agent_write_guard.py').read()); print('ok')"` の出力が `ok`
- 3つのパターンが一本化前と同じ文字列に一致する：`python3 -B vault/tasks/P-20261005-bash-write-unify/fixtures/patterns_check.py` の出力が `pattern_mismatch=0` と `samples=201` の2行だけ
- 動詞の並びを正規表現の文字列に直書きしていない：`grep -cE 'rm\|mv\|cp|checkout\|switch' .claude/hooks/agent_write_guard.py` の出力が `0`
- フックの判定が変わっていない：`python3 -B vault/tasks/P-20261005-bash-write-unify/fixtures/bash_writes_check.py` の出力の最後から2行目が `mismatch=change-example`
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 3つの名前と型は残す：`BASH_WRITE_PATTERNS`・`OTHER_WRITE_PATTERNS` は正規表現の文字列のリスト、`DESTRUCTIVE_BASH_PATTERN` は正規表現の文字列（`is_git_stage_or_commit_only`・`main` とフィクスチャがこの形で使う）
- 組み立て方
  - 動詞はタプル（または既存の frozenset）で1度だけ定義し、`"|".join(...)` で正規表現の選択肢を作る。例：ファイル操作の動詞 `FILE_WRITE_VERBS = ("rm", "mv", "cp", "touch", "mkdir", "chmod", "chown")`、そのうち `DESTRUCTIVE_BASH_PATTERN` に入る `("rm", "mv", "cp")`、git の `("add", "commit")` と `GIT_WRITE_SUBCOMMANDS`
  - git の書き込みサブコマンドは、既存の `GIT_WRITE_SUBCOMMANDS`（`analyze_bash_writes` が使う frozenset。中身は `OTHER_WRITE_PATTERNS` の git の並びと同じ集合）から作る。frozenset から作る時は `sorted()` で順序を固定する。`GIT_WRITE_SUBCOMMANDS` の定義はパターンより前に移してよい（中身は変えない）
  - `DESTRUCTIVE_BASH_PATTERN` には `touch`・`mkdir`・`chmod`・`chown` を入れない（今どおり。planner の `mkdir` ＋ 許可ディレクトリへのリダイレクトを通すため）
  - 正規表現の選択肢の順序は一致の真偽に影響しないので、元の並びと違ってよい
- 変数名・定数名は上の例と違ってよい。モジュール docstring・コメントで、新しい定数の役割を1行ずつ書く
- 変えないもの：`analyze_bash_writes`・`extract_bash_write_targets`・各判定関数・`main` の処理（パターンを使う側は触らない）。T-02・T-03 の担当
- `scripts/smoke.sh`・`docs/vault-spec.md`・`_hooklib.py`・他のフックは変更しない
- 既存の smoke が落ちた場合は、smoke.sh を直さず blocked にして、落ちたケース名と原因を question に書く
- 動作確認で import する時は `python3 -B` を使う。`py_compile` は使わない
- コミットは受け入れ基準に無いので、creator はしない
