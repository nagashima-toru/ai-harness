# T-04 docs/vault-spec.md の2節・7節に transition.py の使い方と推奨の経路であることを書く

## 目的
仕様の正本 `docs/vault-spec.md` に、状態遷移を1コマンドで行う `scripts/transition.py`（T-01・T-02）の使い方と、これが遷移を行う推奨の経路であることを書く。log の日時とモデルの記録をスクリプトが書くことも7節に足す（D-012 フェーズ2）。

## 入力
- `vault/designs/D-012.md` の「決定事項」（推奨の経路とし Edit を拒否しない・承認と解除は対象にしない・ブランチの検査）と「フェーズ2」の決定済み
- `scripts/transition.py`（T-01・T-02 の成果物。動きの正本はコードと先頭の docstring）
- `vault/tasks/P-20261007-transition-basic/T-01.md`・`T-02.md` の「決定済み」
- `docs/vault-spec.md` の2節（状態）・7節（ログ）

## 成果物
- `docs/vault-spec.md`（2節と7節への追記だけ。このファイルだけ）

## 受け入れ基準
- 2節に呼び出しの形がそのまま書かれている：`grep -nF 'python3 scripts/transition.py <計画ID> <id>[,<id>...] <遷移先> [--question <文> | --question-file <パス>] [--note <補足>] [--no-model]' docs/vault-spec.md` の出力が1行以上で、その行番号が `grep -n '^## ' docs/vault-spec.md` の `## 2.` の行と `## 3.` の行の間にある
- 2節に推奨の経路であることが書かれている：`grep -n '推奨の経路' docs/vault-spec.md` の出力に、`## 2.` と `## 3.` の行の間の行番号の行があり、その行か同じ段落に `scripts/transition.py` がある
- 2節の transition.py の記述に、許す7つの遷移、attempt の規則（todo→doing で1、doing→doing・review→doing で +1）、拒否して何も変えない条件（遷移表に無い・計画票が approved でない・ブランチが `work/<計画IDの英小文字>` でない・after の依存が done でない・attempt が上限を超える・blocked に question が無い・review→done で PASS の verdict が無い）、複数 id は全部許される時だけ1コミットで行うこと、終了コード 0・1・2 の意味、承認と blocked の解除は扱わないこと、Edit による直接の書き換えは拒否しないこと、が書かれている（Read で2節を読んで確かめる）
- 7節に、transition.py が log の日時を実行時の JST（UTC+9 固定）で書くことと、`creator=`・`verifier=` を `.claude/agents/<name>.md` の frontmatter から自動で付けること、`--no-model` で付けないことが書かれている：`grep -n -- '--no-model' docs/vault-spec.md` の出力に `## 7.` と `## 8.` の行の間の行番号の行がある
- smoke が通る（「参照される scripts の存在チェック」を含む）：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 2節の置き場所：遷移・attempt・`HARNESS_MAX_ATTEMPTS`・`HARNESS_MAX_PARALLEL` の段落の後（2節の末尾）に、transition.py の段落（箇条書き可）を足す。既存の段落は変えない
- 2節に書く内容（T-01・T-02 の決定済みと実装に合わせる。実装と食い違う時は実装を正とし、PR 本文ではなくこの文書の文面を実装に合わせる）：
  - 呼び出しの形を、受け入れ基準1の字句どおりにコードとして書く（`python3 scripts/transition.py <計画ID> <id>[,<id>...] <遷移先> [--question <文> | --question-file <パス>] [--note <補足>] [--no-model]`）
  - これが状態遷移を行う「推奨の経路」であること（この語を使う）。ただし Edit による計画票の直接の書き換えはフックで拒否せず、done の行の verdict の検査（9節・10節）で「PASS の無い done」が残らないことを守る
  - 許す遷移は todo→doing、doing→doing、doing→review、doing→blocked、review→done、review→doing、review→blocked の7つ。attempt は todo→doing で1、doing→doing・review→doing で +1、それ以外は変えない
  - タスク表の status・attempt・question を書き換え、log に遷移行を追記し、計画票と log（done の時は verdict も）だけを `git commit -m "<計画ID>/<id,...>: <旧>→<新>" -- <パス...>` でコミットする。ほかの staged な変更は混ぜない
  - question の `|` は `／` に、改行は空白に置き換えて表に書く。`--question-file` はファイルの中身を question にする（引用符の問題とガードの誤検知を避けるため）
  - 拒否して何も変えない条件（終了コード1）：受け入れ基準3に挙げたもの。review→done の PASS の条件は10節の done の行の verdict の検査と同じ（`_hooklib.py` の `done_rows_without_pass`）
  - 複数の id は、全部の行で同じ遷移が許される時だけ行う（1つでも拒否があれば何も変えない）。コミットは1回
  - 終了コード：0 遷移した／1 前提を満たさず何も変えていない（理由は標準エラー）／2 引数の誤り
  - 対象のリポジトリは実行時のカレントディレクトリの `git rev-parse --show-toplevel`
  - 承認（draft→approved）と blocked の解除（`/plan approve`・`/plan unblock`）は扱わず、今の `/plan` の Edit のまま（10節の裏付けの検査が「HEAD と作業ツリーの比較」で働くため）
  - 今の `/run`（`.claude/skills/run/SKILL.md`）の手順はまだ transition.py を呼ばない、と1文で書いてよい
- 7節に書く内容：「実行したモデルの記録」の段落の後に、transition.py で遷移した時は log の日時をスクリプトが実行時の JST（UTC+9 固定）で書くこと、`creator=`・`verifier=` を対象リポジトリの `.claude/agents/creator.md`・`verifier.md` の frontmatter の `model` から自動で付けること（読めない時は付けない）、`--no-model` を付けると付けないこと（中断からの再開・ハング・worktree が無い時の行のため）、`--note` の値が補足になること、を書く
- 「`--no-model`」「推奨の経路」「`scripts/transition.py`」の字句は上のとおりに使う（受け入れ基準が grep する）
- 2節・7節以外の節（1節の証跡・9節・10節・12節など）は変えない。`scripts/` の存在チェックがあるので、存在しないスクリプト名（`scripts/diff_gate.py` など後のフェーズのもの）を書かない
- `scripts/transition.py`・`scripts/smoke.sh`・`.claude/skills/run/SKILL.md` は変えない
