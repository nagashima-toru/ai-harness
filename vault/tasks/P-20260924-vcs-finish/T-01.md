# T-01 scripts/vcs_finish.sh を新規作成しホスティング判定とPR/MR作成を実装する

## 目的
`run`/`design` スキルが最終手順で直接呼んでいる `gh pr create` を、GitHub・GitLab・ホスティング無し
の3経路に対応させて置き換えられるようにするため、判定と実行をまとめた共有スクリプト
`scripts/vcs_finish.sh` を新規作成する。

## 入力
- `vault/designs/D-005.md`（フェーズ1のゴール文・受け入れ基準の候補・決定済み。本タスクの仕様の正本）
- 既存の `scripts/rules.sh`（同じ `scripts/` 配下のシェルスクリプトの書き方・`set -u` などのスタイル
  の参考）
- `vault/rules/common/git.md`（`gh pr merge` を実行しない、マージは人が行うという既存方針）

## 成果物
- `scripts/vcs_finish.sh`（新規、この1ファイルのみ。実行権限を付与する）

## 受け入れ基準
- スクリプトが存在し実行権限がある。確認: `test -x scripts/vcs_finish.sh && echo ok`
- `HARNESS_VCS_HOST=none` で実行すると終了コード0で終わり、標準出力に現在のブランチ名と
  `git merge --no-ff` の両方を含む。確認: `br=$(git rev-parse --abbrev-ref HEAD); out=$(HARNESS_VCS_HOST=none bash scripts/vcs_finish.sh); code=$?; echo "exit=$code"; printf '%s' "$out" | grep -F -- "$br" >/dev/null && echo has_branch; printf '%s' "$out" | grep -c 'git merge --no-ff'`
- `HARNESS_VCS_HOST=github` は `gh pr create "$@"` を、`HARNESS_VCS_HOST=gitlab` は
  `glab mr create "$@"` を呼ぶ記述がそれぞれ1箇所以上ある。確認:
  `grep -c 'gh pr create "$@"' scripts/vcs_finish.sh; grep -c 'glab mr create "$@"' scripts/vcs_finish.sh`
  （両方1以上）
- 環境変数未指定・`auto` 時は `git remote get-url origin` を参照して判定するロジックがある。確認:
  `grep -n 'remote get-url origin' scripts/vcs_finish.sh` がヒットする
- `gh pr merge`・`glab mr merge` を実行するコードが無い。確認:
  `grep -c 'gh pr merge\|glab mr merge' scripts/vcs_finish.sh` が0

## 決定済み
- 環境変数名は `HARNESS_VCS_HOST`。値は `github`/`gitlab`/`none`。未設定または `auto` なら自動判定
  する（既存の `HARNESS_MAX_PARALLEL`/`HARNESS_MAX_ATTEMPTS` と同じ「環境変数で上書きできる既定値」
  パターン）
- 自動判定：`git remote get-url origin` の値（コマンドが失敗する＝リモート無しの場合は空文字列扱いで
  よい）に部分文字列 `github.com` を含めば `github`、`gitlab` を含めば `gitlab`、どちらにも一致しな
  い・リモートが無ければ `none`
- `github` 判定時は `gh pr create "$@"` を実行し、その終了コードをそのまま `exit` する。`gitlab` 判定
  時は `glab mr create "$@"` を実行し、その終了コードをそのまま `exit` する。呼び出し元から渡された
  引数（`"$@"`）はそのまま渡す。スクリプト自身が `--fill` などのデフォルト引数を追加することはしない
- `none` 判定時は `gh`/`glab` を一切呼ばず、`git rev-parse --abbrev-ref HEAD` 等で取得した現在のブラ
  ンチ名と、`git merge --no-ff <branch>` の形の案内文を標準出力に書き、終了コード0で終える（呼び出し
  元のエージェントがこの標準出力をそのまま人に伝える。スクリプト自身はマージを一切実行しない）
- `origin` という名前のリモートが存在しない場合も `none` として扱う
- `gh`/`glab` コマンド自体が未インストール・未認証の場合の専用エラーハンドリング（分かりやすいメッセ
  ージ化など）は追加しない。現状の `gh pr create` 単体呼び出しと同様、コマンドが失敗すればそのエラー
  がそのまま出ればよい
- ファイル先頭は `#!/usr/bin/env bash` とし、`set -u` を使う（`scripts/rules.sh` と同じスタイル）。
  `chmod +x scripts/vcs_finish.sh` で実行権限を付与すること
- コミットは `vault/rules/common/git.md` の既存方針（成果物ができた区切りで小さく分けて行う）に従う
