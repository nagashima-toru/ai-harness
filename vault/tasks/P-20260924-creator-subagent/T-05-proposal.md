# 提案: vault/rules/creator/creator.md の修正案

反映対象の実体パス: `vault/rules/creator/creator.md`

`vault/rules/` へは agent_write_guard.py が常時書き込みを拒否するため、このファイルは下書きであり、実体への反映は人が手作業で行う（`docs/vault-spec.md` 12節「提案ファイル方式」）。

## 変更の要点

D-003 フェーズ2で creator がサブエージェント化され、計画票（`vault/plans/<計画ID>.md`）のタスク表の状態更新と `vault/log/<計画ID>.md` への追記は、呼び出し元のオーケストレーター（run のメインセッション）の役目になった（`.claude/agents/creator.md`・`.claude/skills/run/SKILL.md` 参照）。creator はこれらのファイルへの書き込みを `agent_write_guard.py` が常に拒否する。この役割分担の変更に合わせて、現行の `vault/rules/creator/creator.md` の「責務」節にある、作成エージェント自身がログ追記を行う前提の一文を書き換え、判断不能時の扱い（blocked を自分で確定させない）を追記する。

対象は「責務」節の該当2箇所のみ。「やらないこと」「確認方法」節、および `doing` の件数に関する記述（D-003 フェーズ1の対象）には触れない。`vault/rules/creator/git-workflow.md` には今回の役割分担変更と直接矛盾する記述が無いため、変更提案はしない。

## 適用後の「責務」節（全文）

以下を、現行の「責務」節の全文と置き換える。

```markdown
**責務**
- タスク票の6見出し（目的・入力・成果物・受け入れ基準・決定済み・進捗）を着手前に全部読み、「決定済み」を人の回答として最優先する。
- 着手時に `bash scripts/rules.sh creator` を実行し、列挙されたファイルをすべて読む。読んだルール名を「進捗」に `読んだルール: a.md, b.md` の形で1行残す。
- `doing` は常に1件だけ。今の1件が `done` / `blocked` になるまで次のタスクを取らない。
- 「進捗」はセッションが切れても再開できる粒度で追記する（何を作ったか・どの基準まで確認したか・次に何が残っているか）。
- 計画票（`vault/plans/<計画ID>.md`）のタスク表の状態更新と `vault/log/<計画ID>.md` への追記は、呼び出し元のオーケストレーター（run のメインセッション）が行う。creator はこれらに書き込まない（`agent_write_guard.py` が常に拒否する）。
- 「決定済み」に答えが無い判断が必要になった場合、自分で `blocked` を確定させない（計画票への書き込みはフックが常に拒否する）。代わりに「進捗」に判断できない理由を記録し、完了報告で「blocked: <質問文>」の形で返す。計画票への反映（status を `blocked` にし question 列に書く）はオーケストレーターが行う。
- 受け入れ基準に併記された確認コマンドを自分でも実行し、すべて通してから完了報告を返す。通っていない基準を残したまま回さない。
- verifier にはタスク ID だけを渡す。作業の経緯・苦労・言い訳・「実質満たしている」といった説明を渡さない。
- FAIL の後に直すのは verdict の `reasons` と該当する `criteria[].note` に書かれた点だけ。そこに無い箇所まで書き換えない。
- ルール変更（`vault/rules/` 配下のファイル）を成果物とするタスクでは、実体パスに直接書き込めない（`agent_write_guard.py` が常に拒否する）。代わりに `vault/tasks/<計画ID>/<id>-proposal.md` に追記案を下書きし、それを成果物として `review` に回す。実体への反映は人が手作業で行う。
```

### この節でのオリジナルからの変更点（参考。反映は上記の全文置き換えで行う）
- 旧来の「作成エージェント自身が状態変更のたびに `vault/log/` へ追記する」という趣旨の一文（旧「責務」5行目）を、状態更新・ログ追記はオーケストレーターの役目であり creator は書き込まない、という内容に置き換えた
- 「決定済み」に答えが無い判断が必要な場合の扱いとして、自分で `blocked` を確定させず、進捗に記録した上で完了報告に「blocked: <質問文>」を含めて返す、という一文を新規に追加した
- 旧「責務」6行目（受け入れ基準の確認コマンド実行）は、末尾を「`review` にする」から「完了報告を返す」に変更した（review への状態遷移自体はオーケストレーターが行うため）
- それ以外の行（`doing` は常に1件だけ、ルール変更の提案ファイル方式等）は変更していない

## 未変更の節（参考。反映不要）
「目的」「やらないこと」「確認方法」の3節は今回の提案に含めない。現行のまま維持する。
