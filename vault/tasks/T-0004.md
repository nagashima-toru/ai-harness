# T-0004 stop_gate.py に verdict 形式検証を追加し smoke.sh と vault-spec.md を更新

## 目的
`.claude/hooks/stop_gate.py` が `verdict.json` を読んだ後、形式が不正な verdict（result / criteria / note / reasons の異常）を「verdict が無い」ものとして扱い、ブロックして verifier の再実行を指示するようにする。既存の判定分岐は変えない。

## 入力
- `.claude/hooks/stop_gate.py`（現状の判定ロジック全体）
- `scripts/smoke.sh`（既存18件のテスト構造。`make_todo` / `make_verdict` / `run_stop` / `expect` の各ヘルパー）
- `docs/vault-spec.md` 第7節（verdict.json のスキーマ）と第10節（Stop フックの判定表）
- `vault/verdicts/T-0002.json`（note ありの正例）、`vault/verdicts/T-0003.json`（note が空文字の悪い例。(d) の参考）
- `vault/tasks/T-0001.md`（「## 受け入れ基準」節の書式の実例。箇条書きは `- ` で始まる）

## 成果物
- `.claude/hooks/stop_gate.py`（verdict 形式検証の追加）、`scripts/smoke.sh`（(a)〜(e) のテストケース追加）、`docs/vault-spec.md`（第10節に1行追加）の3ファイル一式（1つの変更としてまとめて検証する）

## 決定済み
- **検証を差し込む位置**：既存の `if verdict is None or stale: block(...)` の直後、`result = str(verdict.get("result", "")).upper()` より前に、形式検証（`problems = validate_verdict(verdict, tid, root)` のような関数）を呼ぶ。`problems` が非空なら「verdict が無い」場合と同種の block() を呼んで終了する。PASS/FAIL の分岐・上限判定・`stop_hook_active`・`HARNESS_STRICT_STOP` のコードは一切触らない（この検証は「verdict は存在し stale でもないが中身が壊れている」場合のみ発動する新しい分岐であり、既存分岐の条件式・メッセージ文言は変更しない）。
- **ブロック理由の文面**：「不正」という語を必ず含める（smoke.sh のアサーションで使うため）。例：`[stop_gate] {tid} の verdict の形式が不正です: <理由1>; <理由2>。verifier サブエージェントを再実行して vault/verdicts/{tid}.json を書き直すこと（attempt={attempt}）。` 理由文字列は (a)〜(e) のどれに該当するか分かる日本語にする。例：
  - (a) `result が PASS/FAIL 以外です（'FOO'）`
  - (b) `criteria が配列ではありません` / `criteria[2] に text/ok/note のいずれかがありません`
  - (c) `criteria の行数（2）がタスク票の受け入れ基準の行数（3）と一致しません`
  - (d) `criteria[0].note が空です`
  - (e) `reasons が配列ではありません`
- **(b) と (d) の重複回避**：`note` キー自体が無い要素は (b) の「text/ok/note のいずれかが無い」で検出する。(d) の空白チェックは `note` キーが存在する要素にのみ適用する。`note` が文字列でない場合（null・数値など）も (d) 側で不正として扱ってよい（`not isinstance(note, str) or not note.strip()` で判定する）。
- **criteria の要素が dict でない場合**（文字列・数値など）は (b) 違反として扱う（例：`criteria[0] が辞書ではありません`）。`isinstance` チェックで例外を出さないようにする。
- **(c) の数え方**：タスク票の「## 受け入れ基準」という見出し行から、次の「## 」で始まる見出し行の直前までの範囲で、行頭が `- `（ハイフン＋半角スペース）から始まる行だけを数える。行頭に空白があるネストした箇条書きは数えない。実装イメージ：
  ```python
  def count_acceptance_criteria(task_path):
      with open(task_path, encoding="utf-8") as f:
          lines = f.read().splitlines()
      in_section = False
      count = 0
      for line in lines:
          if line.startswith("## "):
              in_section = (line.strip() == "## 受け入れ基準")
              continue
          if in_section and line.startswith("- "):
              count += 1
      return count
  ```
- **タスク票が無い場合の扱い**：`vault/tasks/<id>.md`（`root` は既存の `project_dir()` が返すディレクトリ基準）が存在しない場合は (c) の検査を丸ごとスキップする（他の (a)(b)(d)(e) は通常どおり実施する）。これは smoke.sh の既存18件がタスク票を一切作らないため必須の仕様（スキップしないと既存ケースが全部 (c) 違反でブロックされ壊れる）。
- **Python 3.9 対応**：`match` 文、`X | Y` 形式の型ヒント（例：`str | None`）は使わない。型ヒントを書く場合は `typing.Optional[str]` を使うか、そもそも型ヒントを付けない。f-string と通常の `def` のみで実装する。
- **smoke.sh のフィクスチャ**：新しいヘルパー関数 `make_task` を追加する（既存の `make_todo` / `make_verdict` のシグネチャ・挙動は変更しない）。シグネチャ例：
  ```bash
  make_task() { # $1=id $2=受け入れ基準の箇条書き行数
    mkdir -p "$TMP/vault/tasks"
    {
      echo "# $1 テスト"
      echo
      echo "## 受け入れ基準"
      for i in $(seq 1 "$2"); do echo "- 基準$i"; done
      echo
      echo "## 決定済み"
    } > "$TMP/vault/tasks/$1.md"
  }
  ```
  (a)(b)(d)(e) のケースはタスク票を作らずに実施する（(c) のスキップ経路も同時に確認できる）。(c) のケースだけ事前に `make_task T-0001 3` のようにタスク票を作り、`criteria` の要素数をそれと不一致（例：2件）にした verdict を書く。
- **不正 verdict の書き込み方**：既存の `make_verdict` は `criteria:[]` 固定で (a)〜(e) 用の任意の壊れた JSON を作れないため、各テストケースでは generic な書き込み（例：`printf '%s' "$json" > "$TMP/vault/verdicts/T-0001.json"`）を使い、`task`/`attempt` は対象タスク（`make_todo T-0001 review 1` で作った `T-0001` / `attempt=1`）に一致させる。新規ケースは既存の `stop_gate.py` セクション（11件）の直後、`agent_write_guard.py` セクションの前に追加するのが自然。
- **`expect` の使い方**：判定は `block` を期待し、`sub` 引数に `"不正"` を渡して理由文言を確認する（必要なら (a)〜(e) を区別する固有語を追加で確認してもよいが必須ではない）。
