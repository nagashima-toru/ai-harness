# T-01 install.sh の .claude/ の複製とマニフェスト記録をハーネス本体の固定リストに限り、smoke にケースを足す

## 目的
導入済みリポジトリを配布元にして `scripts/install.sh` を実行しても、配布元が独自に置いた `.claude/` 配下のファイル（業務用 Skill・agent・hook）と `vault/templates/` の独自テンプレートが導入先に複製されず、`.claude/harness-manifest.json` の `files` にも載らないようにする（GitHub Issue #200）。

## 入力
- `scripts/install.sh`（154〜157行目の `.claude/` 複製ループ、81〜95行目の `manifest_paths()`、99〜152行目の `--update`、1〜20行目の冒頭コメント）
- `scripts/smoke.sh`（755行目の `expect_eq`、11行目の `smoke_tmpdir`、1257〜1267行目の `(install-gi) 07`：導入済みの一時ディレクトリを配布元にして install する既存の書き方の例）
- GitHub Issue #200 の要点（計画票のゴール）

## 成果物
- `scripts/install.sh`（主な成果物。`.claude/` の複製とマニフェスト記録を固定リストにする）
- `scripts/smoke.sh`（付随。`(inst-only)` のケースを足す）

## 受け入れ基準
- `scripts/install.sh` に固定リストの変数の定義行がちょうど1行ある（`grep -c '^CLAUDE_FILES=' scripts/install.sh` が `1`）
- `scripts/install.sh` に `.claude/` と `vault/templates/` を find で列挙する箇所が残っていない（`grep -c 'find .claude' scripts/install.sh` が `0`、`grep -c 'prune' scripts/install.sh` が `0`、`grep -c 'find vault/templates' scripts/install.sh` が `0`）
- smoke に追加した `(inst-only)` のケース5件がすべて ok になる（`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (inst-only) '` が `5`）
- smoke 全体が失敗0で終わる（`bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<数> fail=0` の形）
- 計画ブランチとの分岐点からの差分に `scripts/install.sh` と `scripts/smoke.sh` の両方が含まれる（creator の worktree の中で `git diff --merge-base work/p-20261012-install-harness-only-files --name-only` の出力に両パスがある）

## 決定済み
- 方式：`.claude/` 配下で配るファイルは、`scripts/install.sh` の中に変数 `CLAUDE_FILES`（リポジトリ相対パスのスペース区切り。既存の `RETIRED_RULES` と同じ書き方）で固定で持つ。一覧ファイルを別に作る方式は採らない（配布物が増え、導入先で編集されると配る範囲が変わるため）。変数名に `HARNESS_` の接頭辞を付けない（smoke の `(envref-1)` 系の検査 `envcheck` が `scripts/`・`.claude/` の `HARNESS_` で始まる語を `docs/configuration.md` の表と照合し、表に無いと NG にするため。この変数は利用者が設定する環境変数ではない）。
- 固定リストの中身は次の11ファイル（ai-harness 本体の現在の `.claude/` の一覧から、`settings.json`・`settings.local.json`・`harness-manifest.json`・`worktrees/` を除いたもの）。agents・hooks もファイル名で限定する（配布元が `.claude/agents/`・`.claude/hooks/` に独自ファイルを置きうるため）。
  - `.claude/ai-harness.md`
  - `.claude/agents/creator.md`・`.claude/agents/planner.md`・`.claude/agents/verifier.md`
  - `.claude/hooks/_hooklib.py`・`.claude/hooks/agent_write_guard.py`・`.claude/hooks/plan_guard.py`・`.claude/hooks/stop_gate.py`
  - `.claude/skills/plan/SKILL.md`・`.claude/skills/run/SKILL.md`・`.claude/skills/design/SKILL.md`
- 複製ループ（現在の155行目の `find . -path './worktrees' -prune ...`）は、`CLAUDE_FILES` を回して `copy_if_absent "$SRC/$rel" "$DST/$rel"` を呼ぶ形に置き換える。`find` は `.claude/` について一切使わない。`settings.json` は従来どおり `merge_settings_json.py` に任せる（リストに入れない）。
- `manifest_paths()` も同じ `CLAUDE_FILES` を使う（`find .claude/hooks`・`find .claude/agents`・`find .claude/skills` の3行をやめる）。`find vault/templates` もやめ、通常の複製ループ（165行目）が配っている4本 `vault/templates/task.md`・`vault/templates/plan.md`・`vault/templates/rule.md`・`vault/templates/design.md` を固定で列挙する。存在するものだけを出す現在の振る舞い（`[ -f "$p" ] && echo "$p"`）は保つ。`--update` は `manifest_paths()` を使っているので、これで `--update` の対象も固定リストに限られる。
- `scripts_list()`（`scripts/` 直下の検索）と `SCRIPTS_EXCLUDE` は変えない（計画の対象外。計画票の「次フェーズの候補」）。
- `chmod +x "$DST"/.claude/hooks/*.py` の行は変えなくてよい。
- 旧版の install で導入先に複製され、マニフェストに記録された配布元の独自ファイルは、`--update` でも削除しない（導入先の資産として残す。ビジョンの原則8）。新しいマニフェストは固定リストから作り直すので、その記録は外れる。`RETIRED_RULES` のような削除処理は足さない。
- 冒頭コメント（4行目の「複製するもの:」）を、`.claude/` は `CLAUDE_FILES` の固定リストだけを配り、配布元が独自に置いたファイルは配らない旨に書き換える。
- smoke のケースは新しい節 `echo "== install.sh は配布元の独自ファイルを配らない =="` に置き、名前の先頭をすべて `(inst-only) 0N `（N は1〜5）にする。`(inst-only)` で始まる ok 行がちょうど5行になるようにする（ほかのケース名に `(inst-only)` を使わない）。一時ディレクトリは既存どおり `smoke_tmpdir` で作り、節の最後に既存の節と同じく `rm -rf` で片付ける（smoke の中の後片付けは既存の書き方に従ってよい）。
  - 準備：`$ROOT` から一時ディレクトリ SA へ install し、SA に独自ファイル `.claude/skills/biz-skill/SKILL.md`・`.claude/skills/biz-skill/templates/t.md`・`.claude/skills/biz-skill/references/r.md`・`.claude/agents/biz-agent.md`・`.claude/hooks/biz_hook.py`・`vault/templates/biz.md` を作る。続けて `bash "$SA/scripts/install.sh" "$SB"` で別の一時ディレクトリ SB へ install する。
  - 01：SB に上の独自ファイル6つがどれも無い。
  - 02：SB のマニフェストの `files` に、`.claude/skills/biz-skill/` で始まるキー・`.claude/agents/biz-agent.md`・`.claude/hooks/biz_hook.py`・`vault/templates/biz.md` が無い。
  - 03：SB に固定リストの11ファイルがすべてあり、SB のマニフェストの `files` にも11パスすべてが載っている。
  - 04：`bash "$SA/scripts/install.sh" --update "$SB"` の後も、01・02 と同じく独自ファイルが SB に無く、マニフェストにも載らない。
  - 05：旧版の状態の再現。`$ROOT` から一時ディレクトリ SC へ install し、SC に `.claude/skills/biz-skill/SKILL.md` を作って、そのハッシュを SC のマニフェストの `files` に書き足す。`bash "$ROOT/scripts/install.sh" --update "$SC"` の後、そのファイルは SC に残り、マニフェストの `files` からは外れている。
- smoke は導入先でも実行される（smoke.sh 冒頭のコメント）。追加するケースは `$ROOT` を配布元にして一時ディレクトリへ install するだけにし、`$ROOT/.claude/` の中身がハーネス本体だけであることを前提にしない（導入先の `$ROOT` には業務用 Skill がありうる）。
- 書き換え前の install.sh で 01・02・04 が NG になることを creator が手元で確かめ、「進捗」に一言残す（基準ではない）。
