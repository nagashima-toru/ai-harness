# T-01 vcs_finish.sh に HARNESS_PUSH_BRANCH の push と head を足し smoke のケースを足す

## 目的
環境変数 `HARNESS_PUSH_BRANCH` が設定されている時、`scripts/vcs_finish.sh` の GitHub・GitLab の経路が毎回 `git push -u origin HEAD:<値>` で push し、PR/MR の head（source branch）にその値を使うようにする。動作を `scripts/smoke.sh` のケースで確かめる。

## 入力
- `vault/designs/D-20261010-base-branch-config.md`（「決定事項」と「フェーズ2」）
- `scripts/vcs_finish.sh`（フェーズ1の `base_branch` の読み方と、GitHub・GitLab・none の3経路）
- `scripts/smoke.sh` の `== vcs_finish.sh ==` の節（偽 `gh`/`glab`・`expect_vf`・`vf_notes_run`・`vf_rest_check`・`(base-1)`〜`(base-3)` のケース）と冒頭の `unset HARNESS_BASE_BRANCH`

## 成果物
- `scripts/vcs_finish.sh`（主な成果物）
- `scripts/smoke.sh`（付随：push のケース8件と冒頭の unset の1行。中身は「決定済み」）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(push-[1-8]\) '` の出力が `8` で、各ケースが「決定済み」の `(push-1)`〜`(push-8)` に書いた内容を検査している（ケースの中身は smoke.sh を読んで確かめる）
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<数> fail=0` の形である（既存のケースも全部通る）
- `env HARNESS_PUSH_BRANCH=ccr-x bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<数> fail=0` の形である（外の環境に値があっても smoke が影響を受けない）
- `grep -nE 'git push.*(--force|-f( |$)|\+HEAD)' scripts/vcs_finish.sh` の出力が空（force の push をしない）
- `bash -n scripts/vcs_finish.sh` の終了コードが0
- `scripts/vcs_finish.sh` の先頭のコメント（使い方の説明）に `HARNESS_PUSH_BRANCH` の意味（前後の空白を除いて空なら未設定・設定時の push と head・GitLab の `--source-branch`・none の経路では見ない）が書かれている（ファイルを読んで確かめる）

## 決定済み
- 値の読み方：`base_branch` と同じ書き方で前後の空白を除き、変数 `push_branch` に入れる。空なら未設定。値の形式（ブランチ名として正しいか）は検査しない
- GitHub の経路：`push_branch` が空でなければ、上流の有無に関係なく毎回 `git push -u origin "HEAD:$push_branch"` を実行する。順番は今と同じく、`check_notes` と（引数なしの時の）owner/repo の検査の後、PR 作成の前。push が失敗したら（non-fast-forward を含む）その終了コードで終わり、`gh` は呼ばない。引数なしの REST の3経路の `head=` は `push_branch`（空なら今どおり `git rev-parse --abbrev-ref HEAD`）
- GitLab の経路：push は GitHub と同じ。引数なしの3経路（本文ファイル・計画あり・`--fill`）は、今の引数の末尾（`--yes` の後）に `--source-branch "$push_branch"` を足す。未設定の時は何も足さない。ターゲットブランチ（`--target-branch`）は指定しない
- 引数ありの経路（`gh pr create "$@"`・`glab mr create "$@"`）でも push は `HEAD:<値>` で行う。PR/MR 作成の引数（`--head`・`--source-branch` など）は足さない
- `push_branch` が空の時の動作は今と同じ（上流が無ければ `git push -u origin <現在のブランチ>`、あれば push しない。head は現在のブランチ）。既存の smoke のケースの期待値は変えない
- ホスティング無し（`none`）の経路は `HARNESS_PUSH_BRANCH` を見ない（push しない。案内の文面も変えない）
- force は使わない（`--force`・`-f`・`+HEAD:` の refspec のいずれも使わない）
- ローカルのブランチ名・`find_plan_id` の探し方は変えない
- smoke の冒頭の `unset HARNESS_BASE_BRANCH` の次の行に `unset HARNESS_PUSH_BRANCH` を足す。新しいケースでは必要な呼び出しにだけ `env HARNESS_PUSH_BRANCH=...` で渡す
- smoke の push のケースは、smoke の一時ディレクトリ（`$TMP`）の中に `git init -q --bare` で bare リポジトリを作って `origin` にした作業リポジトリ（既存の `VF_REPO`・`VF_REPO2` とは別）を使い、`HARNESS_VCS_HOST` は明示する（origin がローカルのパスなので auto では判定できない）。push の結果は `git -C <bare> rev-parse <ブランチ>` が作業リポジトリの `git rev-parse HEAD` と一致することで確かめる。`gh`/`glab` は既存の偽コマンド（引数を `$VF_REC` に記録する方式）を使う。origin がローカルのパスでも owner/repo はパスの最後の2つの区切りから取れる（例：`$TMP` の名前と bare の名前）ので、`gh api` の記録は `head=` の行など必要な行だけを見る
- ケースの名前と中身（名前は `(push-<番号>) ` で始める）：
  - `(push-1)` github・引数なし・`HARNESS_PUSH_BRANCH=ccr-x` → bare の `ccr-x` が作業リポジトリの HEAD と一致し、`gh` の記録に `head=ccr-x` の行がある
  - `(push-2)` github・引数なし・前後に空白のある `' ccr-x '` → `(push-1)` と同じ（`head=ccr-x`）
  - `(push-3)` github・引数なし・未設定・上流無し → bare に現在のブランチ名のブランチができて HEAD と一致し、`head=<現在のブランチ名>` の行がある
  - `(push-4)` github・引数なし・上流ありの状態で `HARNESS_PUSH_BRANCH=ccr-x` → 新しいコミットを足した後でも bare の `ccr-x` が新しい HEAD に更新される（上流があっても毎回 push する）
  - `(push-5)` gitlab・引数なし・`HARNESS_PUSH_BRANCH=ccr-x` → bare の `ccr-x` が HEAD と一致し、`glab` の記録の最後の2行が `--source-branch` と `ccr-x`
  - `(push-6)` none・`HARNESS_PUSH_BRANCH=ccr-none` → 終了コード0で、案内に現在のブランチ名が出て、bare に `ccr-none` ができない（`git -C <bare> rev-parse --verify ccr-none` が失敗する）
  - `(push-7)` github・引数なし・bare の `ccr-x` が HEAD の祖先でない（non-fast-forward）状態で `HARNESS_PUSH_BRANCH=ccr-x` → 終了コードが0でなく、`gh` が呼ばれない（記録ファイルが無い）
  - `(push-8)` github・引数あり（`--title T --body B`）・`HARNESS_PUSH_BRANCH=ccr-x` → bare の `ccr-x` が HEAD と一致し、`gh` の記録が `pr create --title T --body B` のまま（`--head` を足さない）
- ケースの置き場所は `(base-3)` のケースの後（フックの `(base-4)` の前）。既存の `(base-*)` のケースの番号・中身は変えない
- 外部のネットワークに push するケースを作らない（origin はすべてローカルの bare）
