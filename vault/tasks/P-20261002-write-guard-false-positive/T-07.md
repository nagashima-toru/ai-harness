# T-07 main 直接コミット拒否の Bash 判定を analyze_bash_writes に載せ替える

## 目的
`main()` 冒頭の main 直接コミット拒否は、`GIT_COMMIT_PATTERN`（`\bgit\s+commit\b`）がコマンド文字列のどこかにマッチすれば拒否する。このため main 上では、`grep "git commit"`・引用符内の文字列・ヒアドキュメント本文のような読み取りやデータまで拒否される（issue #91 と同じ誤検知）。一方で、`git -C . commit`・`git -c k=v commit` は計画時点の現行コードで許可されてしまう。判定を `analyze_bash_writes` の結果に載せ替えて誤検知を解消する。実際に `git commit` を実行するコマンドは、`&&`・`;`・改行で連結した後ろにあるものも、`git -C` 等の前置オプション付きのものも拒否する。解析できない形は従来の判定に落とす（fail-closed）。

## 入力
- `.claude/hooks/agent_write_guard.py`（T-04 完了後の版。`GIT_COMMIT_PATTERN`・`current_branch`・`main()` 冒頭の `# main 直接コミット拒否` のブロック・`analyze_bash_writes`）
- `vault/tasks/P-20261002-write-guard-false-positive/T-01.md` の「決定済み」（verb `git-commit`・None の条件4にある `git` の直後が `-` の形・コマンド語の basename 照合）

## 決定済み
- **判定関数** `is_git_commit_command(cmd)` を追加する
  - `writes = analyze_bash_writes(cmd)` がリストなら、verb が `git-commit` の組が1つでもある時だけ True にする。読み取り（`grep`・`git log --grep` 等）、引用符内の文字列、ヒアドキュメント本文に `git commit` があっても False になる
  - `None` なら従来の判定にフォールバックする。`re.search(GIT_COMMIT_PATTERN, cmd)` か `re.search(GIT_PREOPT_COMMIT_PATTERN, cmd)` のどちらかがマッチすれば True にする。`GIT_PREOPT_COMMIT_PATTERN = r"\bgit\s+-[^;&|\n]*\bcommit\b"` を `GIT_COMMIT_PATTERN` の直後に定数で足す（`git -C . commit`・`git -c user.name=x commit` を捕まえる。T-01 の None の条件4により `git -<opt>` の形は必ず None になるので、この追加パターンで拒否側に倒す）
  - 追加パターンの副作用として、main 上の `git -C . log --grep commit` のような読み取りも拒否されうる。fail-closed 側なので許容する（緩めない）
- **`main()` の変更**：`if re.search(GIT_COMMIT_PATTERN, cmd) and current_branch(root) == "main":` を `if is_git_commit_command(cmd) and current_branch(root) == "main":` に替える。拒否の reason（`main への直接コミットはできません。…`）と、非 git・detached HEAD での fail-open は変えない。直前のコメントに「解析できた時は実際に実行される `git commit` だけを見る。解析できない形は従来の正規表現と `git -<opt> … commit` の形で判定する（issue #91）」を1〜2行で足す
- `analyze_bash_writes` 自体と他の判定（`targets_vault_rules`・`targets_transcript_dir`・`targets_creator_denied_paths`・`find_done_task_write`・ALLOWED 判定）は変えない。`analyze_bash_writes` を変える必要が出たら `blocked` にして question に書く
- 計画時点（T-01 着手前）の現行フックで planner が確認した結果：許可ケース5件はすべて拒否される（reason は main 直接コミット）。拒否ケースのうち 1〜7 は拒否され、8（`git -C . commit`）・9（`git -c user.name=x commit`）は許可される。8・9 は人の指示（「`git -C` 等の形を含めて引き続き拒否」）で拒否側に変える
- **smoke に足すケース**：既存の `(i) main で git commit → 拒否` のケース（`expect_guard "(i) ..." deny \` とその次の行）の直後、`git -C "$GTMP" checkout -q -b work/p-test` の行の直前に置く（`GTMP` が main ブランチにいる位置）
  - 名前は `(bash-parse-main) <説明> → 許可` / `(bash-parse-main) <説明> → 拒否` の形にする。拒否ケース8だけは説明の先頭を `git -C ` にする（例：`(bash-parse-main) git -C . で前置オプション付きの git commit → 拒否`）
  - 実行は `(i)` と同じ形（`printf '%s' '<json>' | CLAUDE_PROJECT_DIR="$GTMP" python3 "$GUARD_HOOK"`）で、その位置で有効な2引数版 `expect_guard` を使う。メインセッション（agent_type 無し）の Bash にする。`GTMP` には vault/ が無いので、拒否は main 直接コミット拒否からしか出ない
  - JSON はシェルの単一引用符で囲むので、コマンド中に `'` を使わない。ヒアドキュメントの区切り語は `<<\"EOF\"`（JSON の `\"`）で書く。改行は `\n`
  - 許可（5件。いずれも現行コードでは拒否される）：
    1. `grep -n "git commit" README.md`
    2. `git log --oneline --grep "git commit"`
    3. `echo "run git commit later"`
    4. `cat <<"EOF"`＋改行＋`git commit -m x`＋改行＋`EOF`（ヒアドキュメント本文）
    5. `cat README.md | grep "git commit"`
  - 拒否（9件）：
    1. `git add a && git commit -m x`
    2. `echo x; git commit -m x`
    3. `echo a`＋改行＋`git commit -m x`（改行区切り）
    4. `GIT_AUTHOR_NAME=x git commit -m x`（先頭の代入）
    5. `/usr/bin/git commit -m x`（絶対パスのコマンド語。T-01 の basename 照合で `git-commit` になる）
    6. `git commit -m "$(cat <<"EOF"`＋改行＋`msg`＋改行＋`EOF`＋改行＋`)"`（コマンド置換：従来判定）
    7. `bash -c "git commit -m x"`（インタプリタ：従来判定）
    8. `git -C . commit -m x`（前置オプション：追加パターン。現行では許可される）
    9. `git -c user.name=x commit -m x`（前置オプション：追加パターン。現行では許可される）
- 冒頭 docstring には main 直接コミット拒否の段落が無い。docstring は変えず、`main()` 内のコメントだけ直す
