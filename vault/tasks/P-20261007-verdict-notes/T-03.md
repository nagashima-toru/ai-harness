# T-03 model_stats.py の出力の末尾に noted_rate 列を足す

## 目的
creator のモデルごとに、最後の verdict の `reasons` が空でないタスクの割合（`noted_rate`）を `scripts/model_stats.py` の出力の末尾の列に足し、verifier の指摘の件数も数えられるようにする。既存の列と値は変えない。smoke にケースを足す。

## 入力
- `vault/designs/D-013.md` の「フェーズ2 verifier の指摘を見えるようにする」（受け入れ基準の候補・決定済み）
- `scripts/model_stats.py`
- `docs/vault-spec.md` 7節（`model_stats.py` の定義。読むだけ）
- `scripts/smoke.sh`（`== model_stats.py ==` の節の (ms-1)〜(ms-5)）

## 成果物
- `scripts/model_stats.py`（主な成果物）
- `scripts/smoke.sh`（`== model_stats.py ==` の節の期待値の更新とケースの追加）

## 受け入れ基準
- 見出しの行の末尾に列 `noted_rate` が足されている：`python3 scripts/model_stats.py | head -1` の出力がタブ区切りの `model`・`tasks`・`first_pass_rate`・`avg_attempt`・`blocked_rate`・`noted_rate` の6列
- `<base>/log/<計画ID>.md` の log から `<base>/verdicts/<計画ID>/<id>.json` を読み、reasons が空でないタスクの割合を出す（verdict が無い・読めないタスクは指摘なしとして数える）：`bash scripts/smoke.sh 2>&1 | grep -F 'ok   (ms-6)'` の出力が1行
- 既存の列と値は変わらない。既存の (ms-1)〜(ms-5) のケースが通り、その期待値の変更は各行の末尾に noted_rate の値（見出しは `noted_rate`）を足すことと、(ms-1) の「5列」を「6列」にすることだけ：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(ms-[1-5]\)'` の出力が `13`。期待値の変更は `git diff work/p-20261007-verdict-notes -- scripts/smoke.sh` を読んで確かめる
- 先頭の docstring か `HEADER` の近くのコメントに、`noted_rate` の定義（verdict の場所の決め方と、verdict が無いタスクの扱い）が書かれている（Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 見出しは `model	tasks	first_pass_rate	avg_attempt	blocked_rate	noted_rate`（タブ区切り）。新しい列は末尾に足す（既存の列を読む処理を壊さないため）。値は小数2桁
- `noted_rate`：対象タスク（既存の定義どおり、最後の遷移行が `→done` か `→blocked` のタスク）のうち、verdict の `reasons` が空でない配列のタスクの件数 ÷ 対象タスク数。分母は `tasks` 列と同じ
- verdict の場所は log ファイルのパスから決める：log が `<base>/log/<計画ID>.md` の時、`<base>/verdicts/<計画ID>/<id>.json`。log の親ディレクトリの名前が `log` でない時（smoke の既存のフィクスチャ `$MS_DIR/P-MS.md` のような時）は、verdict の場所を決められないので、そのタスクは指摘なしとして数える
- 次のどれも「指摘なし」として数える（エラーにしない）：verdict のファイルが無い、JSON として読めない、`reasons` が無い・配列でない・空
- verdict の `task`・`attempt`・`result` は見ない（最新のみが残る verdict の reasons をそのまま使う）
- アーカイブの log（`vault/archive/<年-月>/log/<計画ID>.md`）も同じ規則で `vault/archive/<年-月>/verdicts/<計画ID>/<id>.json` を読む
- 既存の smoke の期待値の更新：
  - (ms-1) の `ms_want` は、見出しに `\tnoted_rate`、各行に `\t0.00` を足す（フィクスチャが `log` ディレクトリの中に無いため全部 0.00）
  - (ms-1) の「見出し行がタブ区切りの5列」は、名前と期待値を「6列」・`6` に直す
  - (ms-5) の期待値 `haiku\t4\t0.00\t1.50\t0.75` は末尾に `\t0.00` を足す
  - (ms-2)・(ms-3)・(ms-4) は変えない
- 新しいケース (ms-6)（`expect_eq` 1回。(ms-4) の前、`rm -rf "$MS_DIR"` より前に置く）：`$MS_DIR/nt/vault/log/P-NT.md` に log を書き、`$MS_DIR/nt/vault/verdicts/P-NT/` に verdict を置いて、そのファイルを引数で渡す。(ms-2) の `$MS_DIR/root/` には置かない（(ms-2) の件数が変わるため）。例：
  - T-01：creator=sonnet、`review→done attempt=1`、verdict の reasons が1要素
  - T-02：creator=sonnet、`review→done attempt=1`、verdict の reasons が空
  - T-03：creator=sonnet、`doing→blocked attempt=1`、verdict 無し
  - T-04：creator=haiku、`review→done attempt=1`、verdict が JSON として読めない
  - 期待する出力：見出しの行と `haiku	1	1.00	1.00	0.00	0.00`・`sonnet	3	0.67	1.00	0.33	0.33` の3行
- 引数なしの既定の対象（`vault/log/*.md`。archive は含めない）は変えない
- `docs/` は変えない（T-05 で行う）
