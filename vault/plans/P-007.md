# ゴール

`scripts/rules.sh` を新規作成する。使い方は `bash scripts/rules.sh <creator|verifier|planner>`。`docs/vault-spec.md` の「12. ルール（vault/rules/）」節に従い、`vault/rules/common/*.md` をファイル名順に列挙し、続けて `vault/rules/<役割>/*.md` をファイル名順に列挙して、1行1パス（リポジトリルートからの相対パス）で標準出力に出す。該当ファイルが無ければ何も出さず exit 0。引数が無い・`creator`/`verifier`/`planner` 以外なら usage を標準エラーに出して exit 2。`vault/rules/` 自体が無くても exit 0。`CLAUDE_PROJECT_DIR` があればそれをルートに、無ければスクリプト自身の位置から求める。

あわせて `scripts/smoke.sh` に「== rules.sh ==」節を追加し、(a) common と creator にファイルを置いて creator を呼ぶと common→creator の順で列挙される、(b) verifier を呼ぶと creator/ のファイルが含まれない、(c) planner を呼ぶと common/ のファイルは含まれるが creator/・verifier/ は含まれない、(d) 空なら無出力 exit 0、(e) 不正な引数で exit 2、の5件を検査する。既存のテストは変更しない。

参考：`docs/roadmap-rules-extension.md` の「## ② ルール解決スクリプト scripts/rules.sh」節に全体設計・受け入れ基準の候補・決定済みが既にある。`## ① 仕様と置き場を決める（契約）`（P-006/T-0006）は完了済みで、`vault/rules/{common,creator,verifier,planner}/` と `docs/vault-spec.md` の「12. ルール」節は既に存在する。

## 分割方針

成果物は「1スクリプト（scripts/rules.sh）＋既存 smoke.sh への1節追加」というひとまとまりの契約兼実装であり、相互に強く結びついている（smoke.sh のケースはスクリプトの仕様そのものを検証するもの）ため分割せず、1タスクに収める。他タスク（run-queue／verifier／planner がこのスクリプトを呼ぶ変更）は別計画で行う対象外。
