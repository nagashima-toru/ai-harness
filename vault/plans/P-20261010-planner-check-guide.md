# ゴール
`.claude/agents/planner.md` の確認コマンド・受け入れ基準の書き方の指針（`## やらないこと` 節）に、次の4点を足す（Issue #150・#153・#157 の後半への対応）。
1. smoke の `(ref-1)`（文書のバッククォート内のパスの実在）が検査する文書を成果物に持つタスクには、`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1` になる基準を必ず入れる（#150）
2. 別のディレクトリで実行するコマンドは `env -C <dir>` で書かず、ガードが通す形で書く（#153 前半）
3. 削除を伴う確認（`purge_plan.sh --merged --apply` など）は受け入れ基準に入れず、非破壊モードで確かめる形を優先する（#153 後半）
4. 旧形式を検出する正規表現は、新形式に当たらないことを手元で確かめてから基準にする（#157 後半）

## 分割方針
- 変更は `.claude/agents/planner.md` 1ファイルに閉じるので、1タスク（T-01）にする。4点はどれも同じ節への箇条の追加で、分けると同じ節の取り合いになり、マージの衝突の元になるだけのため
- `.claude/hooks/` を読んで確かめた結果（`env -C` を名指しで拒否する判定は repo のフックに無い。#153 の拒否は Claude Code 側の仕組みによるものと判断）と、それに基づく指針の文言は、T-01 の「決定済み」に書いた
- planner.md は smoke の `(ref-1)` が検査する文書（`.claude/agents/*.md`）に該当するので、項目1を T-01 自身にも当てはめ、`(ref-1)` の基準を入れた。項目2・3も基準自身で守る（確認コマンドはリポジトリ相対で、削除を伴う操作を含まない）。項目4の旧形式検出は今回は使わず、例として書く正規表現の動作確認だけを基準にした
- docs/decisions.md への追記などの取り出しは、全タスクが done になった後にオーケストレーターが行うのでタスクにしない
