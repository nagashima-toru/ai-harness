# T-03 vault/templates/task.md の「成果物」に、変えるファイルをすべてバッククォートのパスで書く記法を足す

## 目的
タスク票の雛形の「成果物」節に、「creator が変えるファイルはすべてバッククォートで囲んだリポジトリ相対パスで書く（ディレクトリは末尾を `/`）」という記法と例を足す。差分ゲート `diff_gate.py`（T-01）がこの宣言を読んで creator の差分を照らし合わせるため（D-012 フェーズ3）。

## 入力
- `vault/designs/D-012.md` の「フェーズ3」の決定済み（宣言の読み方・雛形の記法の例・「成果物は1つに特定する」は変えない）
- `vault/templates/task.md`（今の雛形）
- `scripts/smoke.sh` の `== 参照される scripts の存在チェック ==` 節（`vault/templates/` 配下の `scripts/<名前>.sh|.py` という字句を、install 先に実在するかで検査する）

## 成果物
- `vault/templates/task.md`（「## 成果物」節への追記だけ。このファイルだけ）

## 受け入れ基準
- 見出しは6つのまま順序も変わらない：`grep '^## ' vault/templates/task.md` の出力が `## 目的`・`## 入力`・`## 成果物`・`## 受け入れ基準`・`## 決定済み`・`## 進捗` の6行（この順）
- 既存の粒度基準の行が残っている：`grep -nF -e '- 1つに特定する（1ファイル / 1PR / 1関数）' vault/templates/task.md` の出力が1行で、その行番号が `grep -n '^## ' vault/templates/task.md` の `## 成果物` の行と `## 受け入れ基準` の行の間にある
- 記法の行がある：`grep -nF 'creator が変えるファイルはすべて、バッククォートで囲んだリポジトリ相対パスで書く' vault/templates/task.md` の出力が1行で、その行番号が `## 成果物` と `## 受け入れ基準` の行の間にあり、同じ行に `末尾を `/` にする` を含む
- 例の行がある：``grep -nF -e '- 例：`src/foo.py`（1ファイル）' vault/templates/task.md`` の出力が1行で、その行番号が `## 成果物` と `## 受け入れ基準` の行の間にある
- smoke が通る（「参照される scripts の存在チェック」を含む）：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 「## 成果物」節を次の3行にする（1行目は今の行のまま。2・3行目を足す。字句は受け入れ基準が grep するのでこのとおりに書く）：
  - `- 1つに特定する（1ファイル / 1PR / 1関数）`
  - ``- creator が変えるファイルはすべて、バッククォートで囲んだリポジトリ相対パスで書く（ディレクトリは末尾を `/` にする）。自分のタスク票の「進捗」は書かなくてよい``
  - ``- 例：`src/foo.py`（1ファイル）``
- 例のパスは D-012 の決定済みにある `scripts/foo.py` ではなく `src/foo.py` にする。`vault/templates/` 配下は smoke の「参照される scripts の存在チェック」の対象で、実在しない `scripts/foo.py` を書くと smoke が fail するため（人への質問に挙げてある。答えが変われば計画票側で直す）
- 「成果物は1つに特定する」という既存の粒度基準は変えない（1つの成果物を特定したうえで、変えるファイルをすべて列挙する）
- ほかの節（目的・入力・受け入れ基準・決定済み・進捗）と見出しは変えない。`scripts/` で始まるパスの字句を雛形に書かない
- `.claude/agents/planner.md`（T-04）・`docs/vault-spec.md`（T-05）・`vault/rules/planner/planner.md` は変えない（`vault/rules/` はエージェントが書き込めない）
