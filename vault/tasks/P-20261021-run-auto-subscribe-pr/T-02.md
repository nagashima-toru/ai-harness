# T-02 vault-spec と decisions に PR の購読を記録する

## 目的
T-01 で run 手順7の8に足した PR の購読を、仕様の要約（`docs/vault-spec.md` 4節）と判断の記録（`docs/decisions.md`）に反映する（GitHub Issue #222）。

## 入力
- `.claude/skills/run/SKILL.md`（T-01 で足した `## 7. 次へ・完了` の小番号8・9）
- `docs/vault-spec.md`（`## 4. 計画票の形式` の「`done` は **PR 作成済み**という意味で、…」の段落）
- `docs/decisions.md`（表の最終行）

## 成果物
- `docs/vault-spec.md`（主な成果物。4節に1段落を足す）
- `docs/decisions.md`（付随。表の末尾に1行を足す）

## 受け入れ基準
- vault-spec に購読と解除の段落がある：`grep -c '^PR の監視：run 手順7の8で、GitHub の PR を作った時.*unsubscribe_pr_activity. で解除する' docs/vault-spec.md` が `1`
- vault-spec の段落に、購読後の対応の規則をハーネスが持たないことが書かれている：`grep -c '^PR の監視：.*ハーネスは規則を持たない' docs/vault-spec.md` が `1`
- decisions に判断の行がある：`grep -c '^. 2026-10-21 . run は PR を作った後、実行環境に .subscribe_pr_activity. ツールがあれば' docs/decisions.md` が `1`
- decisions の行に Issue 番号と計画 ID がある：`grep -c 'run は PR を作った後.*Issue .222.*P-20261021-run-auto-subscribe-pr' docs/decisions.md` が `1`
- 文書中のバッククォートのパスがすべて存在する：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- `docs/vault-spec.md` は、`## 4. 計画票の形式` の「`done` は **PR 作成済み**という意味で、ベースブランチへのマージは含まない。…」で始まる段落の直後に、空行を1つ挟んで次のコードブロックの中身どおり1行の段落を足す（囲みの ``` は書かない。バッククォートはこのとおり書く）。ほかの段落は変えない：

```
PR の監視：run 手順7の8で、GitHub の PR を作った時に限り、実行環境に `subscribe_pr_activity` ツールがある時だけ作った PR を購読し、マージ・close されたら `unsubscribe_pr_activity` で解除する。ツールが無い時は購読せず、完了報告に「監視は始めていない」と書く。GitLab の MR・ホスティング無し（`none`）の時は対象外。購読後の CI の失敗・レビューコメントへの対応は実行環境の指示に従い、ハーネスは規則を持たない（原則7）。手順の正本は `.claude/skills/run/SKILL.md` 手順7の8。
```

- `docs/decisions.md` は、表の最終行（`| 2026-10-21 | creator の worktree は …` の行）の後ろに、次のコードブロックの中身どおり1行を足す（3列の表の形を保つ。囲みの ``` は書かない）：

```
| 2026-10-21 | run は PR を作った後、実行環境に `subscribe_pr_activity` ツールがあれば作った PR を購読する。ツールが無い時は購読せず、GitLab の MR・ホスティング無し（`none`）は対象外にし、購読後の CI の失敗・レビュー対応は実行環境の指示に従う（Issue #222）（P-20261021-run-auto-subscribe-pr） | PR を作った後の監視が人の依頼を待たないと始まらなかった（PR #221）。購読はツールのある環境だけの任意の手順にし、ハーネス本体に PR 対応の規則を持たせない（原則7） |
```

- 2節の `/run` の箇条（「`/run`（`.claude/skills/run/SKILL.md`）は、計画票のタスク表と log の変更をすべて…」）は transition.py の使い分けの要約なので、購読は書き足さない
- `docs/runbook.md`・`docs/guide.md`・`docs/configuration.md` は変えない（環境変数は増えず、人の作業も変わらないため）
- `docs/decisions.md` は smoke の `(ref-1)` の検査対象ではないが、`docs/vault-spec.md` は対象。足す段落でバッククォートで囲む語のうち `vault/`・`scripts/`・`docs/`・`.claude/` で始まるのは `.claude/skills/run/SKILL.md` だけで、実在する
- smoke は約1分かかる
