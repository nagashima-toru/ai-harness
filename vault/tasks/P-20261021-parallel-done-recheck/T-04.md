# T-04 計画の差分が `/code-review` を通過する

## 目的
計画全体の差分（T-01〜T-03）を `/code-review` で確かめ、致命的な指摘が残っていない状態にする。修正で計画全体の動作を壊していないことを、smoke で確かめる。

## 入力
- 計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- `vault/tasks/P-20261021-parallel-done-recheck/T-01.md`〜`T-03.md` の「決定済み」
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節

## 成果物
- 主な成果物は計画の差分への修正（致命的な指摘が無ければ変更しない）
- 直してよいファイル：`scripts/transition.py`、`scripts/smoke.sh`、`docs/vault-spec.md`、`docs/decisions.md`、`.claude/skills/run/SKILL.md`

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<n> fail=0` の形（fail が 0）である
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-recheck) '` の出力が `6` である
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1` である

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う
- 設計の前提（変えない）：案A（done の時点で再検証）を採り、状態（5つ）は増やさない。再検証の判定は `git rev-list --count --merges --first-parent <plan-head>..HEAD` が1以上。これを変える指摘は設計・仕様の変更が要る指摘として扱う
- smoke は1分ほどかかる

## 進捗
- 読んだルール: vault/rules/common/vision.md
- /code-review を2回実行。1回目の致命的な指摘は1件（再検証分岐で log のコミット後に古い PASS の verdict を消し、OSError を握りつぶす順序。クラッシュ時に古い PASS で done になりうる）。scripts/transition.py で verdict の削除を log 書き込みの前に移し、FileNotFoundError 以外は fail() にして直した
- 2回目は致命的な指摘なし（残りは merge 数が代理指標であること＝設計の前提で変えない、コード構造・文言の好み、ほか軽微。直さない）
- 確認: smoke 末尾 `smoke: pass=590 fail=0`、(transition-recheck) ok=6、(ref-1) ok=1
