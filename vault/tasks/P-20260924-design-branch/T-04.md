# T-04 smoke.sh に design ブランチのフック非阻害を検証するケースを追加する

## 目的
`/design` が行うブランチ作成 → `vault/designs/` への書き込み → コミットという一連の操作が
`agent_write_guard.py` に阻害されないことを、一時 git リポジトリで実際に再現して確認し、回帰防止の
テストケースとして `scripts/smoke.sh` に固定する。

## 入力
- `.claude/hooks/agent_write_guard.py`（特に main 直接コミット拒否のロジックと `vault/rules/` 判定）
- `scripts/smoke.sh`（既存の `GTMP` を使った main/work ブランチ検証パターン、`(i)`〜`(j)` 付近）

## 成果物
- `scripts/smoke.sh`（新規テストケースの追加のみ。既存ケースの削除・改変はしない）

## 受け入れ基準
- 一時 git リポジトリで `main` から `design/d-999` ブランチ（`main` ではない）を作り、そのブランチ
  上での `git commit` が `agent_write_guard.py` に許可されることを検証するテストケースが追加されて
  いる。確認コマンド：`grep -c 'design/d-999' scripts/smoke.sh` の出力が1以上
- 同じブランチ上で `vault/designs/D-999.md` への Write（`agent_type` を指定しないメインエージェント
  想定）が `agent_write_guard.py` に許可されることを検証するテストケースが追加されている（
  `vault/rules/` 配下ではないため拒否されないことの確認）。確認コマンド：
  `grep -c 'vault/designs/D-999.md' scripts/smoke.sh` の出力が1以上
- 追加したテストケースを含め `bash scripts/smoke.sh` がすべて成功する。確認コマンド：
  `bash scripts/smoke.sh | tail -1` の出力が `smoke: pass=<N> fail=0` の形式（`fail=0`）になっている
- 既存のテストケースを削除・改変していない。確認コマンド：
  `git diff scripts/smoke.sh | grep -E '^-.*(expect|expect_guard) '` の出力が空

## 決定済み
- 実装コード（`agent_write_guard.py` 本体）の変更は不要という前提で進める。既存ロジック上、
  `vault/designs/D-999.md` は `vault/rules/` 配下ではないため Write は拒否されず、`design/d-999` は
  `main` ではないため `git commit` 拒否にも該当しないはず。テストを実際に実行し、想定どおり許可され
  ることを確認するのがこのタスクの目的
- もし実行してみて `agent_write_guard.py` が想定に反してブロックする（想定外の拒否が起きる）場合
  は、フック本体の修正は本タスクのスコープ外。status を `blocked` にし、question に「どの操作がどう
  拒否されたか」を具体的に書いて人の判断を仰ぐこと。自分でフックのロジックを変更しない
- 追加するテストケースは既存の `== agent_write_guard.py ==` 節の末尾に追記してよい。新しい `==` 見出
  しの節を作る必要はない
- テスト用のブランチ名は `design/d-999`、設計文書ファイル名は `vault/designs/D-999.md` を使う（実在
  する `vault/designs/` の ID と衝突しない、テスト専用の一時ディレクトリ内だけの値）
- 既存の `GTMP`（`scripts/smoke.sh` 内で `git init` → `main` で commit 確認 → `git checkout -b
  work/p-test` → commit 許可を確認する部分、`(i)`〜`(j)` ケース）と同じパターンを流用してよい
- `stop_gate.py` 側の検証は不要（承認済み計画票が無い状態では常に許可する既存ケース「approved な計
  画票が0件 → 許可」がすでにあり、`/design` 実行中は承認済み計画が存在しないため、そのケースがその
  まま根拠になる）
