# T-05 docs/runbook.md に新しいセッションでサンドボックスの効き目を確かめる手順を書く

## 目的
`docs/runbook.md` に、サンドボックスを有効にした後（このリポジトリでは計画のマージ後、導入先では手で足した後）、人が新しいセッションで効き目を確かめる手順の節を足す。

## 入力
- `vault/designs/D-013.md` の「フェーズ5 サンドボックスを有効にする」（受け入れ基準の候補の4つ目・決定済み）
- `.claude/settings.json` の `sandbox`（T-01 で足したもの）
- `docs/runbook.md`（「8. creator のモデルを比べる」節と「困ったとき」節）

## 成果物
- `docs/runbook.md`（1ファイル。節の追加だけ）

## 受け入れ基準
- 決定済みの見出しの節が「8. creator のモデルを比べる」と「困ったとき」の間に1つ足され、ほかの `## ` 見出しは変わっていない：`grep -n '^## 8\. \|^## 9\. サンドボックスを確かめる$\|^## 困ったとき$' docs/runbook.md` の出力がこの順の3行で、`grep -c '^## ' docs/runbook.md` の出力が `11`
- 節に、確かめることの3つがコマンドの形で書かれている：`grep -c "python3 -c \"open('vault/rules/x.md','w')\"\|^ *bash scripts/smoke.sh\|^ *bash scripts/vcs_finish.sh" docs/runbook.md` の出力が `3` 以上で、3つとも新しい節の中にある（Read）
- 節に、`/sandbox` の Config タブで `denyWrite` の2つが実際のパスに解決されていることを確かめる手順が書かれている：`grep -n '/sandbox' docs/runbook.md` の出力が1行以上（Read で新しい節の中にあることを確認）
- 節に、決定済みの「うまくいかなかった時」の3つの扱いが書かれている（Read）
- 節に、Claude Code を起動し直した新しいセッションで行うこと（設定はセッションの開始時に読まれるため）が書かれている（Read）

## 決定済み
- 節の見出しは `## 9. サンドボックスを確かめる` で、「8. creator のモデルを比べる」節の後、「困ったとき」節の前に置く。ほかの節は変えない
- 手順（番号付きの箇条で、この順に書く）：
  1. Claude Code を起動し直す（設定はセッションの開始時に読まれる。設定を変えたセッションのままでは効かない）
  2. `/sandbox` を開き、サンドボックスが有効であることと（有効でない・使えないと表示された時は、手順3〜5 を飛ばして「使えない環境」の扱いに進む）、Config タブで `denyWrite` の `./vault/rules` と `~/.claude/projects` が実際の絶対パス（このリポジトリの `vault/rules` とホームの `.claude/projects`）に解決されていることを確かめる
  3. Bash で `python3 -c "open('vault/rules/x.md','w')"` を実行し、失敗する（Permission denied などで終わり、`vault/rules/x.md` が作られない）ことを確かめる。このコマンドは `agent_write_guard.py` の Bash の解析では拒否されない形なので、失敗すればサンドボックスが効いている
  4. `bash scripts/smoke.sh` が `fail=0` で通ることを確かめる（コードブロックの中に行頭から書く）
  5. 計画の最後に `bash scripts/vcs_finish.sh` の push と PR 作成が通ることを確かめる（コードブロックの中に行頭から書く。このリポジトリでは、サンドボックスを入れた計画の次の計画の run の最後で確かめてよい）
- 「うまくいかなかった時」として書く3つ：
  - 3 の `python3 -c` が成功して `vault/rules/x.md` ができた時：サンドボックスが効いていない。作られたファイルは人が消し、2 の `/sandbox` の表示と `denyWrite` のパスの書き方を見直す
  - 4 の smoke が通らない時：どのケースが落ちたかを見て、サンドボックスの書き込み・通信の制限によるものかを確かめる。直し方は別の計画で決める
  - 5 の `vcs_finish.sh` が通らない時（`gh` の認証・ssh の remote への push）：D-013 の決定どおり、別の計画で `excludedCommands` に `bash scripts/vcs_finish.sh` を足す。それまでは人がサンドボックスの外（ターミナル）で `bash scripts/vcs_finish.sh` を実行する
- 導入先で有効にする手順は `docs/install.md` の「サンドボックスを有効にする（任意）」（T-03 が作る）を参照する一文を、節の冒頭に置く。このタスクでは `docs/install.md` は変えない
- 「困ったとき」の表は変えない
- このタスクの中で、手順のコマンド（特に 3）を実行して確かめない（このセッションではサンドボックスが効いていないため、`vault/rules/` への書き込みを試すことになる）
