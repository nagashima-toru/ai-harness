# T-01 vcs_finish.sh を引数なしで非対話で通るようにし、smoke にケースを足す

## 目的
`bash scripts/vcs_finish.sh` を引数なしで実行しても、`gh pr create`／`glab mr create` が非対話環境で title/body を求めて失敗しないようにする（issue #89 の1点目）。あわせて、その動作を実在の gh/glab を呼ばずに確かめる smoke のケースを足す。

## 入力
- `scripts/vcs_finish.sh`（全文。github 経路の `gh pr create "$@"`、gitlab 経路の `glab mr create "$@"`）
- `scripts/smoke.sh`（冒頭の `ROOT`・`TMP`・`PASS_N`/`FAIL_N`、末尾の `smoke: pass=... fail=...` の出力。`expect` 系の関数の ok/NG の出力形式は 66・193 行あたり）
- `gh issue view 89`

## 成果物
- `scripts/vcs_finish.sh`：引数が1つも無い時の既定値
- `scripts/smoke.sh`：vcs_finish.sh の新しい節（ケース4つ）

## 受け入れ基準
- `bash -n scripts/vcs_finish.sh` の終了コードが0で、出力が空
- smoke 全体が通る。確認：`bash scripts/smoke.sh > /tmp/P-20261003-run-finish-verifier-worktree-T-01-smoke.txt 2>&1` の後、`tail -1 /tmp/P-20261003-run-finish-verifier-worktree-T-01-smoke.txt` が `smoke: pass=<数> fail=0`
- 新しい節の4ケースが ok になっている。確認：`grep -c '^  ok   (vcs_finish) ' /tmp/P-20261003-run-finish-verifier-worktree-T-01-smoke.txt` が `4`。4ケースは「決定済み」のとおり（github 引数なし→`pr create --fill`、github 引数あり→そのまま、gitlab 引数なし→`mr create --fill --yes`、gitlab 引数あり→そのまま）で、各ケースがスタブに記録された引数を比べている（smoke.sh の該当節を Read で確認する）
- 新しい節のテストは実在の gh/glab を呼ばず、`git push` もしない。確認：smoke.sh の該当節を Read で読み、PATH の先頭にスタブのディレクトリを足して呼んでいること、上流が設定済みのフィクスチャの git リポジトリの中で実行していること（push の分岐に入らない）を確かめる
- ホスティング判定・push・none 経路・exit の行は変わっていない。確認：`git diff main -- scripts/vcs_finish.sh` の削除行（`-` で始まり `---` でない行）が、`gh pr create`・`glab mr create` の呼び出し行と、冒頭のコメントの行だけ（Read と目視で確認する）

## 決定済み
- 成果物を2ファイルにする理由：smoke.sh には今 vcs_finish.sh のテストが無い。実在の gh/glab を呼ばずに T-01 の動作を確かめるには、スタブで差し替えるテストが要る。実装とその回帰テストは切り離すと、どちらのタスクも単独では検証できない。そのため1タスクにまとめる
- 既定値の付け方：引数の数（`$#`）が0の時だけ、github は `gh pr create --fill`、gitlab は `glab mr create --fill --yes` を実行する。引数が1つでもある時は、今まで通り `gh pr create "$@"`／`glab mr create "$@"` をそのまま実行し、既定値は足さない（`--title` だけ渡された時に `--fill` を混ぜる、といった合成はしない）
- glab の既定値は、glab の公式ドキュメントにある `-f, --fill`（コミットの情報を使い、title/description を聞かない）と `-y, --yes`（送信の確認を飛ばす）による。このマシンに glab は入っていないので実機では確かめない（計画票の「人への質問」1）
- none 経路・未知の HARNESS_VCS_HOST・`command -v` の検査・上流が無い時の push・`exit $?` は変えない
- 冒頭コメントの「使い方」の行は、引数なしの時の既定値が分かる形に直してよい（例：`# 使い方: bash scripts/vcs_finish.sh [引数...]（引数なしなら gh は --fill、glab は --fill --yes を既定で付ける）`）
- smoke の新しい節
  - 見出しは `echo "== vcs_finish.sh =="` にし、末尾の `smoke: pass=...` の出力の直前（最後の節の後）に置く
  - 各ケースの名前は `(vcs_finish) ` で始める（例：`(vcs_finish) github・引数なし → gh pr create --fill`）。ok/NG の出力形式は既存のまま（`  ok   <名前>`／`  NG   <名前> ...`）にし、`PASS_N`/`FAIL_N` を数える。新しい比較の関数を作る時もこの形式に合わせる
  - スタブ：`$TMP` の下に bin のディレクトリを作り、`gh` と `glab` のスタブを置く（実行権限を付ける）。スタブは受け取った引数を1行1つずつ `$TMP` の下のファイルに書き、終了コード0で終わる。vcs_finish.sh は `PATH="<スタブのディレクトリ>:$PATH"` を付けて呼ぶ。PATH を丸ごと置き換えない（git が要る）
  - push の回避：`$TMP` の下に `git init` したフィクスチャのリポジトリを作り、空でないコミットを1つ置く。`git config branch.<ブランチ名>.remote .` と `git config branch.<ブランチ名>.merge refs/heads/<ブランチ名>` で上流を自分自身にする。これで `@{u}` が解決し、push の分岐に入らない。その中で（サブシェルで `cd` して）`HARNESS_VCS_HOST=github`／`gitlab` を付けて `bash "$ROOT/scripts/vcs_finish.sh" [引数]` を呼ぶ。git のコミットには `-c user.name=... -c user.email=...` を付け、利用者の設定に頼らない
  - 引数ありのケースの引数は `--title T --body B` にし、スタブの記録がちょうど `pr create --title T --body B`（gitlab は `mr create --title T --body B`）の並びで、`--fill` を含まないことを確かめる
  - 後片付けに `rm -rf` を足さない（`$TMP` は既存の `trap` で消える）
- 既存の smoke のケースは変えない
- コミットは不要（受け入れ基準に無い）
