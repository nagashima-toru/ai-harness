# T-03 smoke.sh に creator 向け expect_guard ケースを追加

## 目的
T-02 で追加した `agent_write_guard.py` の creator 向け拒否ルールを、`scripts/smoke.sh` の `expect_guard` パターンで機械的に検証できるようにする。

## 入力
- `scripts/smoke.sh`「`== agent_write_guard.py ==`」節の既存 `expect_guard` ケース群（特に `vault/rules/` 向けの deny/allow ケースの書き方）
- T-02 で変更済みの `.claude/hooks/agent_write_guard.py`

## 成果物
- `scripts/smoke.sh`

## 受け入れ基準
- `agent_type: creator` が `vault/plans/` へ Write → deny を期待するケースが、テスト名に「creator が vault/plans/ に Write → 拒否」という文字列で追加されている。確認コマンド: `grep -c 'creator が vault/plans/ に Write → 拒否' scripts/smoke.sh` の出力が1
- `agent_type: creator` が `vault/log/` へ Write → deny を期待するケースが、テスト名に「creator が vault/log/ に Write → 拒否」という文字列で追加されている。確認コマンド: `grep -c 'creator が vault/log/ に Write → 拒否' scripts/smoke.sh` の出力が1
- `agent_type: creator` が `README.md`（成果物パス）へ Write → allow を期待するケースが、テスト名に「creator が README.md に Write → 許可」という文字列で追加されている。確認コマンド: `grep -c 'creator が README.md に Write → 許可' scripts/smoke.sh` の出力が1
- `bash scripts/smoke.sh` を実行すると、追加した3ケースを含め全件 pass する。確認コマンド: `bash scripts/smoke.sh | tail -1` の出力が `smoke: pass=N fail=0`（N は追加分を含む総数）の形式で `fail=0` を含む

## 決定済み
- 追加ケースは既存の `expect_guard` 関数・`run_guard` ヘルパーをそのまま使う（新しいヘルパー関数は作らない）
- 追加位置は `== agent_write_guard.py ==` 節の既存ケース群の末尾（`(l) design/d-999 ブランチで...` の後、`== plan_guard.py ==` 節の前）
- テスト名の文字列は受け入れ基準にある3つをそのまま使う（この文字列で `grep` するため、言い換えない）
- 既存ケースの変更・削除は行わない（追加のみ）
