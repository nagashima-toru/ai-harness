## 決定済み
- ファイル名は `vault/rules/verifier/verifier.md` で固定
- 「ルール」は「責務」と「やらないこと」の2つの箇条書きの塊で書いてよい（見出しは3つのまま、区切りは太字の行か空行）
- 責務として書くこと（各1行）：受け入れ基準を上から1行ずつ真偽で判定する／確認コマンドがあれば実行して結果を根拠にする／`criteria` は受け入れ基準と同じ行数・同じ順序／`attempt` は todo.md の値に合わせる／`note` は全行で非空、書式は `実行コマンド: \`<command>\` / 出力: <要点>`／1行でも `ok: false` があれば FAIL／`vault/verdicts/<id>.json` 以外に書かない
- 「やらないこと」として書くこと：基準に無い観点（コードの好み・追加要望）で落とさない／判定不能を FAIL にしない（`ok: true` のまま note と reasons に理由を書く）／受け入れ基準がルールを参照していない行をルールを理由に FAIL にしない／`creator/` のルールを根拠にしない（そもそも渡されない）／タスク票の「進捗」や作成側の説明文を根拠にしない／確認コマンドが実行できなかった時に黙って別の方法に置き換えない（実行不可の理由・代替方法・その結果をセットで note に書く。T-0002 で note を必須化した経緯を根拠に挙げてよい）／成果物や todo.md を修正しない
- 「確認方法」には verdict を書き終えた直後のセルフチェックを3〜5行で書く（例：`criteria` の行数がタスク票の受け入れ基準の行数と一致するか、全行の `note` が非空で確認コマンドと出力を含むか、`result` と `ok` が矛盾していないか）
- `vault/rules/` は `doing`/`review` 中は書き込みが拒否される。人が `HARNESS_ALLOW_RULES_WRITE=T-0022` を設定して起動している前提で進め、Write が deny されたら `blocked` にして question に設定方法を書く
- `.claude/agents/verifier.md`・`docs/`・`README.md`・`scripts/` は変更しない（配布と文言修正は T-0023）
- git commit はしない（人が確認してからコミットする）
