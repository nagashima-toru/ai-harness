# T-04 README の構成節を1行1項目の表にする

## 目的
「## 構成」節のコードブロック（scripts/ の行が270文字ある）を、1行1項目の表に分けて読みやすくする。あわせて、README 全体で既存の情報が失われていないことをこの計画の最後に確かめる。

## 入力
- `README.md`（T-03 の後の版。「## 構成」節）
- `scripts/` 配下（各スクリプトの役割の確認用）

## 成果物
- `README.md`（1ファイル。「## 構成」節だけを変える。ほかの節は、下の基準の確認で欠けが見つかった時だけ戻す）

## 受け入れ基準
- 構成節にコードブロックが無く、今の構成に挙がっている27項目がそれぞれ表の1行になっている。確認：`awk '/^## 構成/{s=1;next} /^## /{s=0} s' README.md | grep -cP '^\x60{3}'` の出力が `0`。`awk '/^## 構成/{s=1;next} /^## /{s=0} s' README.md | grep -cE '^\| `(\.claude/settings\.json|\.claude/agents/|\.claude/hooks/|\.claude/skills/|vault/plans/|vault/tasks/|vault/designs/|vault/verdicts/|vault/log/|vault/templates/|vault/rules/|docs/vault-spec\.md|docs/install\.md|docs/runbook\.md|docs/vision\.md|docs/decisions\.md|scripts/smoke\.sh|scripts/install\.sh|scripts/uninstall\.sh|scripts/rules\.sh|scripts/current_plan\.sh|scripts/transition\.py|scripts/diff_gate\.py|scripts/vcs_finish\.sh|scripts/discard_worktree\.sh|scripts/run_unattended\.py|scripts/purge_plan\.sh)` \|'` の出力が `27`
- agents と skills の内訳が残っている。確認：`grep -cE '^\| `\.claude/agents/` \|.*creator.*verifier.*planner' README.md` が `1`、`grep -cE '^\| `\.claude/skills/` \|.*design.*plan.*run' README.md` が `1`
- 構成節の1行が長すぎない。確認：`awk '/^## 構成/{s=1;next} /^## /{s=0} s' README.md | python3 -c "import sys; print(max(len(l.rstrip('\n')) for l in sys.stdin))"` の出力が `100` 以下
- README 全体で既存の情報が残っている。確認：`grep -cE '^\| `(/design <ゴール>|/plan <ゴール>|/run|python3 scripts/run_unattended\.py)` \|' README.md` が `4`、`grep -cE '^\| `vault/rules/(common|creator|verifier|planner)/` \|' README.md` が `4`、`grep -cF '`/design` と `/plan` の使い分け' README.md` が `1`、`grep -cF 'ハーネスは標準ルールを同梱しない' README.md` が `1`、`grep -cF '人が日々やることは `docs/runbook.md`、Vault の仕様は `docs/vault-spec.md` を参照' README.md` が `1`、`grep -cF '詳細は [LICENSE](LICENSE) を参照' README.md` が `1`
- 見出し構成が変わっていない。確認：`grep -E '^## ' README.md` の出力がちょうど次の8行（この順）：`## 目的`・`## セットアップ`・`## クイックスタート`・`## 使い方`・`## 拡張ポイント（ルール）`・`## 仕組み`・`## 構成`・`## ライセンス`
- 文書中のパスが実在する。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`

## 決定済み
- 形式は `| パス | 内容 |` の表。表は1つでも、`.claude/`・`vault/`・`docs/`・`scripts/` ごとの4つに分けてもよい
- 各行の1列目はリポジトリ相対の完全なパスをバッククォートで囲む（例：`` | `scripts/smoke.sh` | フックの動作検証 | ``）。ディレクトリは末尾を `/` にする。`install.sh` と `uninstall.sh` も別の行にする（1行1項目）
- 載せるのは今の構成のコードブロックにある27項目ちょうど：`.claude/settings.json`・`.claude/agents/`・`.claude/hooks/`・`.claude/skills/`・`vault/plans/`・`vault/tasks/`・`vault/designs/`・`vault/verdicts/`・`vault/log/`・`vault/templates/`・`vault/rules/`・`docs/vault-spec.md`・`docs/install.md`・`docs/runbook.md`・`docs/vision.md`・`docs/decisions.md`・`scripts/smoke.sh`・`scripts/install.sh`・`scripts/uninstall.sh`・`scripts/rules.sh`・`scripts/current_plan.sh`・`scripts/transition.py`・`scripts/diff_gate.py`・`scripts/vcs_finish.sh`・`scripts/discard_worktree.sh`・`scripts/run_unattended.py`・`scripts/purge_plan.sh`。今の README に無いスクリプト（`model_stats.py` など）は足さない（ゴールを広げない）。同じパスの行を2つ作らない
- 内容の列は今の括弧書きの説明をそのまま使う（例：`.claude/settings.json` は「hooks・許可」、`vault/plans/` は「計画票（状態の正本）」、`docs/vault-spec.md` は「仕様の正本」、`scripts/purge_plan.sh` は「計画一式の除去とマージ済みの一括削除」）。`.claude/agents/` の行には `creator`・`verifier`・`planner` を、`.claude/skills/` の行には `design`・`plan`・`run` をこの順で書く
- 構成節の各行は100文字以下（Python の `len` で数える文字数）
- 構成節以外は、基準4の確認で欠けが見つかった場合に限り、元の文言に戻す目的でだけ変えてよい
