# T-03 stop_gate.py の doing/review 検査を全行ループに変更する

## 目的
`.claude/hooks/stop_gate.py` の「doing/review のタスクは1件だけ想定」というロジック（`next(...)` で1件だけ取り出す部分）を、doing/review の全行をそれぞれ検査するループに変更する。対応する `scripts/smoke.sh` のケースも更新する。

## 入力
- `.claude/hooks/stop_gate.py`（189行 `active = next((t for t in tasks if t["status"] in ("doing", "review")), None)` 以降の判定ロジック）
- `scripts/smoke.sh`（69〜82行付近の `== stop_gate.py ==` セクション）
- `vault/designs/D-003.md`（フェーズ1「決定済み」）

## 成果物
- `.claude/hooks/stop_gate.py`
- `scripts/smoke.sh` の `== stop_gate.py ==` セクションの対応ケース

## 受け入れ基準
- `stop_gate.py` に `next((t for t in tasks if t["status"] in ("doing", "review")), None)` という単一行取得のコードが無い。確認: `grep -c 'next((t for t in tasks' .claude/hooks/stop_gate.py` が0
- doing/review の行が複数ある計画票で、いずれか1件でも verdict が無い・不正な場合にブロックする（1件目に verdict があっても2件目に無ければ見落とさずブロックする）
- doing/review の行が複数あり、全行の verdict が PASS だが status が done でない場合、いずれかの行について「done にすること」のブロックを返す（全行が正常終了条件を満たしていない限り許可しない）
- doing/review の行が無い場合は従来どおり許可する（この分岐は変更しない）
- 単一の doing/review 行のみの既存シナリオ（`scripts/smoke.sh` 既存の4ケース：doing・verdict無し、FAIL・attempt<上限、FAIL・attempt=上限、doing/review無し）の判定結果が変更前と同じである
- 上記の複数行ケース・単一行の回帰ケースはいずれも `scripts/smoke.sh` に反映されており、`bash scripts/smoke.sh | tail -1` の出力で fail=0 になる

## 決定済み
- ループの検査順序はタスク表の行の出現順（上から順）とする
- 1回の Stop 実行で1つの block() だけを返す（stop_gate.py は1回の JSON 出力のみを想定しているため）。ループの中で最初に「許可できない」と判定した行が見つかった時点でその行の理由を reason にして block() を呼び、以降の行は検査しない。全行が問題無ければループを最後まで回して allow() する
- 「PASS だが status が done でない」行が複数あっても、最初に見つかった1件について done 化を指示すればよい（オーケストレーターがその行を done にした後、次の Stop 実行で残りの行が検査される前提。1回で全件分の指示を返す必要はない）
- verdict の読み込み・形式検証（`validate_verdict`）・attempt 上限（`HARNESS_MAX_ATTEMPTS`）のロジック自体は変更しない。変えるのは「どの行に対してこれらの検査を適用するか」というループ構造だけ
- `scripts/smoke.sh` の既存4ケースはそのまま通ることを確認した上で、複数 doing/review 行のケースを追記する（既存ケースの削除・意味変更はしない）
