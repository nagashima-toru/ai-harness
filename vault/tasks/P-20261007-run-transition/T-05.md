## 決定済み
- 手順7：
  - 計画票の frontmatter の approved→done は、今のまま Edit で行う（transition.py の対象外。D-012 の決定済み）。「frontmatter の `status` を `done` にし」の言い回しは残してよい（基準3の grep は `done` を数えない）。Edit の後、`bash scripts/vcs_finish.sh` の前に計画票をコミットすることは今の手順のとおりでよい
  - ホスティング無し（`none`）の時の「標準出力に出る現在のブランチ名と `git merge --no-ff <branch>` の案内をそのまま…」は、コマンド名を書かずに「標準出力に出る現在のブランチ名とマージの案内をそのまま…」に直す（基準2の grep のため。`scripts/vcs_finish.sh` の出力そのものは変えない）
  - そのほか（PR の作り方・MCP の代替・`gh pr merge` を実行しない）は変えない
- 手順8：内容は変えず、この変更に合わせて文言だけ直す（D-012 の決定済み）。直すところが無ければ変えなくてよい
- 「回帰確認」：
  - 冒頭の「手順2〜7は同じ経路（creator/verifier のサブエージェント呼び出し・worktree・逐次マージ）を通す」は「同じ経路（creator/verifier のサブエージェント呼び出し・worktree・transition.py による逐次の状態変更とマージ）」に直す
  - 観点2の log：各遷移が transition.py によって1行ずつ書かれ、日時は transition.py の実時刻である、という前提に直す。書式の例 `- <日時> <id> <遷移> attempt=<n> [補足]` は残してよい（基準3の grep に当たらない）
  - 観点3の成果物：差分の確認コマンド `git diff <PLAN_HEAD>..HEAD -- <成果物のパス>` は残す。「マージコミット以外の余分な差分が無い」に、worktree 側の収集コミット（`<計画ID>/<id>: creator 成果物をオーケストレーターが収集`）がありうることを書き足す
  - 観点5：PASS で done になれば transition.py の done が worktree とブランチを削除済み。blocked（新規コミット無し・宣言外の変更・コンフリクト・上限到達）の時だけ残ってよい
  - 最後の「差異があれば手順6・7の実装を見直す」は残す
- 「注意」：
  - 「creator のコミットは…（オーケストレーターが手順6.3.1 で worktree の未コミット分をコミットするのはこの対象外）」の括弧内を「（手順4の review の呼び出しで transition.py が worktree の未コミット分を収集コミットするのはこの対象外）」に直す
  - 「計画票のタスク表の列順・見出しは変えない」は残し、「タスク表と log は transition.py で変え、Edit や printf で直接書き換えない（frontmatter の approved→done だけは Edit）」を1行足す
  - Stop フックの説明・`vault/rules/` を編集しない、は残す
- ファイル全体の見直し：T-01〜T-04 の版に、番号の変わった手順への古い参照（`手順6.3.1`・`手順6.3.2`・`手順6.4.2`・`手順3.7`・`手順3.8` など）や、表を直接書き換える言い回しが残っていれば、この節に限らず文言だけ直してよい（基準3）。手順の中身（呼び出しの形・終了コードの扱い・早見表）は変えない
