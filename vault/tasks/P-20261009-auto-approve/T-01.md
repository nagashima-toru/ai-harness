# T-01 plan_guard.py から承認と unblock の会話記録による裏付けの検査を削り、smoke のケースを置き換える

## 目的
`/plan` が自分で計画を approved にする流れ（D-015 フェーズ2）にするため、`plan_guard.py` の会話記録による承認・unblock の裏付けの検査を削る。表の整合・done の行の verdict・粒度の検査は残す。

## 入力
- `vault/designs/D-015.md` の「決定事項」の表と「フェーズ2 承認待ちをなくし、会話記録の検査を外す」の節
- `.claude/hooks/plan_guard.py`（`newly_approved_plans`・`approval_check`・`unblocked_rows`・`unblock_check`・`main` の中の呼び出しと `finish` の警告の出力）
- `scripts/smoke.sh` の `== plan_guard.py ==` の後ろの「# 承認の裏付け検査（PostToolUse・D-010 フェーズ4 / T-04）」から、「# blocked の解除の裏付け検査（PostToolUse・D-010 フェーズ5 / T-02）」の節の最後の `rm -f "$UB_TRANSCRIPT"` まで（計画作成時は849〜1014行目）

## 成果物
- `.claude/hooks/plan_guard.py`（主な成果物）
- `scripts/smoke.sh`（付随。`(approve-post)`・`(unblock-post)` のケースの削除と、`(no-approve-check-N)`・`(no-unblock-check-N)` のケースの追加だけ）

## 受け入れ基準
- `plan_guard.py` が会話記録を読まない。確認：`grep -c "human_messages\|is_approve_command\|is_unblock_command\|transcript_path" .claude/hooks/plan_guard.py` の出力が `0`
- 承認と unblock の裏付けの関数が無い。確認：`grep -c "def newly_approved_plans\|def approval_check\|def unblocked_rows\|def unblock_check" .claude/hooks/plan_guard.py` の出力が `0`
- HEAD では draft で作業ツリーでだけ approved の計画票があり、会話記録に `/plan approve` が無い・会話記録が無い、のどちらでも plan_guard は何も出力せず、同じ状況で列数の不正はブロックする。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (no-approve-check-'` の出力が `3`
- HEAD で blocked の行が作業ツリーで todo になっていて、会話記録に `/plan unblock` が無い・会話記録が無い、のどちらでも plan_guard は何も出力しない。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (no-unblock-check-'` の出力が `2`
- 旧ケースが残っていない。確認：`bash scripts/smoke.sh 2>&1 | grep -c '(approve-post)\|(unblock-post)'` の出力が `0`
- 表の整合・粒度・done の行の verdict の既存ケースを含めて smoke が全部通る。確認：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- `plan_guard.py` から次を削る：関数 `newly_approved_plans`・`approval_check`・`unblocked_rows`・`unblock_check`、`main` の中のそれらの呼び出しと `warning`・`warning2` の組み立て、`finish` の中の `additionalContext` の警告の出力。`finish()` は `sys.exit(0)` だけにするか、呼び出しを `sys.exit(0)` に置き換える（どちらでもよい）。使われなくなった `import subprocess` も削る
- 残す検査（順も変えない）：粒度（`granularity_violation`・`plan_size_violation`）→ approved の件数 → 列数 → status → 依存 → blocked の question → id の重複 → done の行の verdict（`H.done_rows_without_pass`）。worktree への委譲も残す
- 冒頭の docstring は、検出する壊れ方 (a)〜(g) と (f) の説明を残す。会話記録・承認の裏付けについての記述が docstring にあれば消す（今は無い）
- `_hooklib.py` は変えない（`human_messages`・`is_approve_command`・`is_unblock_command` は `agent_write_guard.py` がまだ使う。`is_approve_command` は T-02 が消す）
- smoke.sh の直し方
  - 「# 承認の裏付け検査（PostToolUse・D-010 フェーズ4 / T-04）」の節の `(approve-post)` のケースと `ap_warn` を削る。フィクスチャの関数（`AP_REPO`・`ap_git`・`ap_reset`・`ap_plan`・`ap_commit_plan`・`run_ap_post`）は新しいケースで使うので残す
  - 「# blocked の解除の裏付け検査（PostToolUse・D-010 フェーズ5 / T-02）」の節の `(unblock-post)` のケースと `up_warn` を削る。フィクスチャの関数（`UP_REPO`・`up_git`・`up_reset`・`up_plan`・`up_commit`・`run_up_post`）は残す
  - それより前の `agent_write_guard.py` の節（`(approve-pre)`・`(unblock-pre)`、`make_transcript`・`T_CHAT` などの定義）は変えない（T-02 の担当）
  - 新しいケースは削った位置に置き、コメントを「# 承認と unblock の裏付けの検査はしない（D-015 フェーズ2）」にする。会話記録は `NC_TRANSCRIPT="$TMP/no-check-transcript.jsonl"` に `printf '%s\n' '{"type":"user","message":{"role":"user","content":"こんにちは"}}' > "$NC_TRANSCRIPT"` で作る（人の発言はあるが `/plan approve`・`/plan unblock` は無い）。無い会話記録は `run_ap_post ""`・`run_up_post ""`（transcript_path を省く）で表す
  - 名前と中身（「出力なし」の判定は既存の `if [ -z "$(...)" ]; then echo "  ok   (<名前>) ..."; PASS_N=$((PASS_N+1)); else echo "  NG   ..."; FAIL_N=$((FAIL_N+1)); fi` の書き方）
    - `(no-approve-check-1) HEAD は draft・作業ツリーは approved・/plan approve 無し → 出力なし`：`ap_reset; ap_commit_plan draft; ap_plan approved` の後に `run_ap_post "$NC_TRANSCRIPT"`
    - `(no-approve-check-2) 会話記録が無い → 出力なし（警告も出さない）`：同じ状態で `run_ap_post ""`
    - `(no-approve-check-3) 列数の不正は今どおりブロック`：同じ状態から旧ケースと同じ `sed -i.bak` で T-01 の行の列を1つ減らし、`expect "<名前>" block "$(run_ap_post "$NC_TRANSCRIPT")" "列数"`
    - `(no-unblock-check-1) HEAD で blocked の T-02 が作業ツリーで todo・/plan unblock 無し → 出力なし`：`up_reset; up_commit todo blocked; up_plan todo todo` の後に `run_up_post "$NC_TRANSCRIPT"`
    - `(no-unblock-check-2) 会話記録が無い → 出力なし（警告も出さない）`：同じ状態で `run_up_post ""`
- 一時ファイルの後始末は既存と同じく `rm -f "$NC_TRANSCRIPT"` でよい（`rm -rf` は使わない）
- `docs/vault-spec.md` の10節は T-06 が直すので、このタスクでは変えない
