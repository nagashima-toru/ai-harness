# T-04 vault/rules/common/vision.md を docs/vision.md へのシンボリックリンクとして作る

## 目的
このリポジトリの creator・verifier・planner が `bash scripts/rules.sh <役割>` の列挙を通して `docs/vision.md` を読むように、`vault/rules/common/vision.md` を `docs/vision.md` へのシンボリックリンクとして作る。本文は写さない。

## 入力
- `docs/vision.md`（リンク先。変えない）
- `scripts/rules.sh`（`vault/rules/common/*.md` をファイル名順に列挙する）
- `scripts/install.sh`（`vault/rules/` は README と .gitkeep の固定の列挙だけを配る。T-02 の smoke `(in-out)` が導入先に `vault/rules/common/vision.md` が無いことを確かめる）
- `vault/rules/planner/ai-harness-lessons.md`（このリポジトリ専用で配らないルールの前例）

## 成果物
- `vault/rules/common/vision.md`（シンボリックリンク1つ。リンク先は `../../../docs/vision.md`）

## 受け入れ基準
- `git ls-files -s vault/rules/common/vision.md | grep -c '^120000 '` が `1`（git でシンボリックリンクとして追跡されている）
- `readlink vault/rules/common/vision.md` の出力が `../../../docs/vision.md`、かつ `cmp vault/rules/common/vision.md docs/vision.md` が終了コード `0`（リンクが解決でき、中身が正本そのもの）
- `bash scripts/rules.sh creator | grep -cx 'vault/rules/common/vision.md'`・`bash scripts/rules.sh verifier | grep -cx 'vault/rules/common/vision.md'`・`bash scripts/rules.sh planner | grep -cx 'vault/rules/common/vision.md'` がどれも `1`
- `git grep -lF '実行を安いモデルに任せても成果が安定する' -- ':!vault/tasks/' ':!vault/plans/' ':!vault/verdicts/' ':!vault/log/'` の出力が `docs/vision.md` の1行だけ（vision の本文の写しがリポジトリのどこにも無い）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (in-out) '` が `5`、かつ `bash scripts/smoke.sh 2>&1 | grep -c '^  NG '` が `0`（導入先に `vault/rules/common/vision.md` と `docs/vision.md` が配られない）

## 決定済み
- 作り方は `ln -s ../../../docs/vision.md vault/rules/common/vision.md`（相対パス。絶対パスにしない。worktree でもクローン先でも解決できるようにするため）。通常ファイルのコピーにはしない
- 写しの確認で `vault/tasks/`・`vault/plans/`・`vault/verdicts/`・`vault/log/` を除くのは、計画一式のファイルが確認コマンドの文字列として検索語を含みうるため（これらは run の手順7で除去され `main` に入らない）。`vault/rules/` は除かない（シンボリックリンクの blob はリンク先のパスの文字列なので一致しない。通常ファイルの写しを置けば一致して検出される）
- `vault/rules/common/.gitkeep` は残す
- リンクの説明を書くファイル（README など）は足さない。`vault/rules/README.md` は導入先に配られるため、このリポジトリ専用の vision について書かない
- `scripts/install.sh`・`scripts/rules.sh`・`scripts/smoke.sh` は変えない。smoke の `(in-out)` が通らない時は blocked にして question に書く
- 「vision の要約を他に書かない」の対象には `README.md` の `docs/vision.md` へのリンクの1文（目的・原則・非ゴールがそこにある、という案内）は含まない（本文の写しではないため変えない）

## 進捗
- 読んだルール: (rules.sh creator の列挙は空)
- vault/rules/common/vision.md を ln -s ../../../docs/vision.md で作り git add 済み
- 基準5行すべて確認済み(120000=1, readlink一致・cmp=0, rules.sh 3役割とも1, 写し検索は docs/vision.md のみ, smoke (in-out) ok=5 NG=0)
