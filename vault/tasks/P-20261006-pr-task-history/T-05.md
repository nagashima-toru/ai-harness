# T-05 docs/vault-spec.md 1節の証跡の段落に PR 本文のタスク履歴を足す

## 目的
仕様の正本の「証跡は3層で残る」の段落に、PR 本文にタスク履歴表が載り、スカッシュマージ後もそこから辿れることを足す。

## 入力
- `docs/vault-spec.md` 1節の「証跡は3層で残る。」で始まる段落
- T-02 後の `scripts/vcs_finish.sh`、T-01 の `scripts/pr_body.py`

## 成果物
- `docs/vault-spec.md`（1節の証跡の段落への追記だけ）

## 受け入れ基準
- `grep -c 'scripts/pr_body.py' docs/vault-spec.md` の出力が `1` 以上で、その行が「## 1. ディレクトリ」の節にある（Read で確認）
- 追記した文に `スカッシュ` の語があり、スカッシュマージ後も PR 本文の表から辿れる旨が書かれている（Read で確認）
- `grep -c '^## ' docs/vault-spec.md` の出力が `13`（節の見出しを増減していない）

## 決定済み
- 追記は「証跡は3層で残る。…競合しない。」の段落の直後に1〜3文で書く。内容：引数なしの `scripts/vcs_finish.sh` は、現在のブランチ（`work/<計画IDの英小文字>`）の計画が見つかれば、PR/MR のタイトルを `<計画ID>: <ゴールの1行目>`、本文を `scripts/pr_body.py` が出す「タスク履歴」表（タスク ID・title・`<計画ID>/<id>: done` コミットの短縮ハッシュ・verdict）にする。PR がスカッシュマージされて main にタスクごとのコミットが残らなくても、この表から辿れる。マージ方式の運用は `docs/runbook.md` 3節を参照
- 他の節・段落は変えない（4節の `done` の意味・`gh pr merge` の deny の記述もそのまま）
