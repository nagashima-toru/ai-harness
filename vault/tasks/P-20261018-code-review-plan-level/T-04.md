# T-04 vault-spec と run スキルのコードレビューの記述を計画単位に合わせる

## 目的
`docs/vault-spec.md` の「コードレビューを参照する受け入れ基準」の要約と粒度の基準、`.claude/skills/run/SKILL.md` の早見表と手順6の3を、T-01〜T-03 で直した正本（planner・creator・verifier の定義）の計画単位のレビュータスクに合わせる。

## 入力
- `.claude/agents/planner.md` の「## 計画単位のレビュータスク」節（T-01 の成果物）
- `.claude/agents/creator.md` の「## コードレビューを参照する基準がある時」節（T-02 の成果物）
- `.claude/agents/verifier.md` の「## コードレビューを参照する基準の判定」節（T-03 の成果物）
- `docs/vault-spec.md` の6節（`reasons`）・8節（粒度の基準）・11節の「### コードレビューを参照する受け入れ基準」
- `.claude/skills/run/SKILL.md` の「transition.py の呼び出し（早見表）」と手順6の3

## 成果物

- `.claude/skills/run/SKILL.md`（付随。早見表と手順6の3）

## 受け入れ基準
- 小見出しが変わっていない：`grep -c '^### コードレビューを参照する受け入れ基準' docs/vault-spec.md` が `1`
- 要約の範囲がベースブランチとの分岐点からの差分になっている：`grep -c 'diff --merge-base .ベースブランチ.' docs/vault-spec.md` が1以上
- 要約の対象の行の既定の書き方が計画の差分になっている：`grep -c 'で計画の差分に致命的な指摘が残っていない' docs/vault-spec.md` が1以上
- 8節の粒度の基準に計画単位のレビュータスクの箇条がある：`grep -c '最後に計画単位のレビュータスクを持つ' docs/vault-spec.md` が1以上
- タスク単位の範囲・導入先任せ・レビューを強制しないの古い記述が残っていない：`grep -c -e 'そのタスクの差分' -e '導入先の planner ルール' -e 'で差分に致命的な指摘' -e 'レビューを強制しない' docs/vault-spec.md` が `0`
- run スキルに計画単位のレビュータスクが書かれている：`grep -c '計画単位のレビュータスク' .claude/skills/run/SKILL.md` が1以上
- smoke の `(ref-1)` が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- `docs/vault-spec.md` 11節の `### コードレビューを参照する受け入れ基準` の小見出しは変えない。冒頭の「正本は…」の文に `.claude/agents/planner.md`（「計画単位のレビュータスク」節）を足す
- (1) 対象の行：この行を持つのは planner が計画の最後に足す「計画単位のレビュータスク」で、既定の書き方は「`/code-review` で計画の差分に致命的な指摘が残っていない」と書く。コードを変更するタスクが1件以上ある計画にだけ足し、通常のタスクの受け入れ基準には `/code-review` の行を入れない。判定基準の正本は planner 定義と書く（判定基準そのものを重ねて書かなくてよい）。「どのタスクにこの行を入れるかは導入先の planner ルールで決め、ハーネス本体はレビューを強制しない（原則7）」の記述は消す
- (2) ツール：現行どおり
- (3) 範囲と呼び方：計画全体の差分で、`git -C <worktree のパス> diff --merge-base <ベースブランチ>`（ベースブランチは `HARNESS_BASE_BRANCH`、既定 `main`。分岐点から）。計画一式4種はレビューの対象にしない。worktree のパスを明示して呼ぶこと・引数の扱いは現行どおり
- (4) verifier の判定・(5) creator・(6) run：「差分」を「計画の差分」に直す程度で、扱いは現行どおり。(5) の「もう1回だけ実行して確かめる」は保つ
- 8節（粒度の基準）に次の箇条を1つ足す：「コードを変更するタスクがある計画は、最後に計画単位のレビュータスクを持つ（`.claude/agents/planner.md` の「計画単位のレビュータスク」節。1計画7タスクの上限に含める）」
- 6節の `reasons` の箇条（「コードレビューを参照する基準で、…」の2行）は、接頭辞と扱いが変わらないので変えなくてよい
- `.claude/skills/run/SKILL.md`：早見表の「verifier が人の判断を求めた PASS（手順6。review→blocked）」の行の場面の欄に、計画単位のレビュータスクで起きうる旨を短く足す（呼び出しの欄は変えない）。手順6の3の冒頭付近に、「`人の判断が必要:` の要素は、主に計画単位のレビュータスク（`.claude/agents/planner.md` の「計画単位のレビュータスク」節）の verdict に出る」旨を1文足す。run の処理（blocked にする条件・呼び出し）は変えない
- 正本（3つのエージェント定義）の文言と食い違う時は、要約側（このタスクの成果物）を正本に合わせる。正本の側は変えない
- `docs/decisions.md` は T-05 で直すので変えない。ほかの節・ほかのファイルは変えない
