# T-03 stop_gate.py で done の行の verdict を検査し validate_verdict を _hooklib.py に切り替える

## 目的
Stop フックで、承認済み計画票の done の行に attempt が一致する正しい PASS の verdict があるかを検査し、無ければブロックして review に戻すよう指示する。あわせて `validate_verdict` を `_hooklib.py` のものに切り替え、到達しない done の分岐を消す（D-012 フェーズ1）。

## 入力
- `vault/designs/D-012.md` の「フェーズ1」（ゴール文・決定済み）
- `.claude/hooks/stop_gate.py`
- `.claude/hooks/_hooklib.py` の `validate_verdict`・`done_rows_without_pass`（T-01 で追加済み）
- フィクスチャ `vault/tasks/P-20261007-done-verdict-check/fixtures/mixed/`・`fixtures/ok/`（変更しない）

## 成果物
- `.claude/hooks/stop_gate.py`（このファイルだけ）

## 受け入れ基準
- `validate_verdict` の定義が `_hooklib.py` にだけある：`grep -l "^def validate_verdict(" .claude/hooks/*.py` の出力が `.claude/hooks/_hooklib.py` の1行だけ
- done の行の verdict が正しくないとブロックする（review・verdict 無しの T-07 より先に、表の上から最初の T-02 で止まる）：`printf '{"stop_hook_active":false}' | env GIT_DIR=/nonexistent CLAUDE_PROJECT_DIR=vault/tasks/P-20261007-done-verdict-check/fixtures/mixed python3 .claude/hooks/stop_gate.py` の出力が次の1行と完全に一致する
  `{"decision": "block", "reason": "[stop_gate] P-FIX/T-02 は done ですが、attempt=1 の PASS の verdict がありません（verdict がありません）。計画票の T-02 の status を review に戻し、verifier を実行してください。"}`
- done の行に正しい PASS の verdict があれば許可する：`printf '{"stop_hook_active":false}' | env GIT_DIR=/nonexistent CLAUDE_PROJECT_DIR=vault/tasks/P-20261007-done-verdict-check/fixtures/ok python3 .claude/hooks/stop_gate.py` の出力が空
- `stop_hook_active` の扱いは変わらない：`printf '{"stop_hook_active":true}' | env GIT_DIR=/nonexistent CLAUDE_PROJECT_DIR=vault/tasks/P-20261007-done-verdict-check/fixtures/mixed python3 .claude/hooks/stop_gate.py` の出力が空
- 到達しない done の分岐が無い：`grep -c 'status == "done"' .claude/hooks/stop_gate.py` の出力が `0`
- 既存の smoke が全件通り、件数も変わらない：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=519 fail=0`

## 決定済み
- 検査の対象は自分のブランチの approved な計画票（`approved_plans` が1件の時）だけ。draft・done の計画票と `vault/archive/` は見ない（今の `approved_plans` の扱いのまま）
- 検査の位置：approved な計画票を1件に特定し、`tasks = H.parse_tasks(...)` を得た直後。`active_tasks`（doing/review）が無い時の `allow()` より前に置く（done の行だけの計画票でも検査する）
- `H.done_rows_without_pass(root, plan_id, tasks)` の戻り値が空でなければ、先頭の1件 `(id, 理由)` で `block()` する。文面は次のとおり（`<n>` はタスク表のその行の attempt の文字列そのまま）
  `[stop_gate] <計画ID>/<id> は done ですが、attempt=<n> の PASS の verdict がありません（<理由>）。計画票の <id> の status を review に戻し、verifier を実行してください。`
  - done のタスクの verdict への書き込みは `agent_write_guard.py` が拒否する。そのため、直す手順は「review に戻す → verifier」の順で書く
- ファイル内の `def validate_verdict(...)` を消し、呼び出しを `H.validate_verdict(...)` に替える。引数は今のまま
- 到達しない分岐の削除：doing/review の行のループ内の `if result == "PASS":` の中の `if status == "done": continue` を消し、PASS の時は常に「done にし log に追記」のブロックにする（`active_tasks` に done は入らないので挙動は変わらない）
- `stop_hook_active` の扱い・未コミット変更の検査・worktree 委譲・2件以上の approved のブロックは変えない（順序も今のまま：委譲 → stop_hook_active → 未コミット → approved の件数 → done の行の検査 → doing/review の検査）
- 既存の doing/review の判定・文言は変えない（smoke の既存ケースの reason の部分文字列が変わらないこと）
- モジュール冒頭の docstring に、done の行の verdict を検査することと、`_hooklib.py` の `validate_verdict`・`done_rows_without_pass` を使うことを1〜2行で足す
- 確認コマンドの `env GIT_DIR=/nonexistent` は、フィクスチャがリポジトリの中にあるため、未コミット変更の検査（`has_uncommitted_changes`）が作業ツリー全体を見て先にブロックしないようにするもの。フック側で GIT_DIR を特別扱いしない
- `.claude/hooks/agent_write_guard.py`・`plan_guard.py`・`_hooklib.py`・`scripts/smoke.sh` は変更しない（smoke の新ケースは T-05）
- フィクスチャは変更しない
