# T-02 creator 並行 worktree 起動と verifier 並行 EnterWorktree 起動の手順追加

## 目的
`run` スキルの「作る」「検証する」手順を、T-01 で選ばれた複数タスクそれぞれについて creator を `isolation: "worktree"` 付きで並行起動し、対応する verifier を対象 worktree に `EnterWorktree(path=...)` で入ってから検証する形に書き換える。

## 入力
- `vault/designs/D-003.md`（フェーズ3節。決定済み：「verifier は worktree を新規作成せず creator が得た既存 worktree に入る」）
- `.claude/skills/run/SKILL.md`（T-01 完了後の版。手順3「作る」・手順5「検証する」）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md`（入出力仕様・書き込み制限）
- `vault/rules/common/roles.md`（creator/verifier への受け渡しは必要最小限の情報に絞る方針）

## 成果物
- `.claude/skills/run/SKILL.md` の手順3「作る」・手順5「検証する」の書き換え

## 受け入れ基準
- 手順3に、選んだタスクそれぞれについて creator を `isolation: "worktree"` 付きで並行起動する旨（1メッセージで複数回の Agent 呼び出し）が明記されている。確認: `grep -n "isolation" .claude/skills/run/SKILL.md`
- 同箇所に、各呼び出しの結果からタスクごとの worktree パス・ブランチを受け取り、後続の verifier 呼び出し・マージで使えるよう記録する手順が書かれている
- worktree の分岐元がこのリポジトリの計画ブランチになっていることを確認する手順（具体的な確認方法・コマンド例を含む）が明記されている。確認: `grep -n "分岐元\|EnterWorktree" .claude/skills/run/SKILL.md` で該当記述の存在を確認する
- 手順5に、完了した creator それぞれについて verifier を並行起動する旨（通常の Agent 呼び出し、1メッセージで複数回）が明記されている
- 同箇所に、verifier へのプロンプトがタスク ID と対象 worktree のパスだけであり、verifier が `EnterWorktree(path=...)` でその worktree に入ってから検証する旨が明記されている。確認: `grep -n "EnterWorktree" .claude/skills/run/SKILL.md`
- 着手可能集合が1件だけの場合も、同じ経路（creator/verifier の worktree 起動、Agent 呼び出しが1回になるだけ）を通す旨が明記されている（専用の逐次フォールバックを作らない）

## 決定済み
- creator への呼び出しは、選んだタスクの数だけ1メッセージ内で複数回 Agent ツールを呼ぶ（プロンプトは既存どおりタスク ID のみに `isolation: "worktree"` オプションを添える）。各呼び出しの完了報告から得た worktree のパス・ブランチ名は、run のセッション内でタスク ID に紐づけて保持すれば足りる（ファイルへの永続化は不要）
- `isolation: "worktree"` の分岐元が計画ブランチになっているかどうかの具体的な確認方法（設定項目名・コマンド）は実装時に調査して SKILL.md に書く。分岐元が `origin/main` 相当になってしまう場合は、`isolation` の他のオプションで起点を明示的に指定する調整方法も併記する
- verifier への呼び出しは、対応する creator が完了したタスクの数だけ1メッセージ内で複数回 Agent ツールを呼ぶ（`isolation` は付けない通常呼び出し）。プロンプトはタスク ID と対象 worktree のパスの2つだけにする（roles.md の「タスク ID 以外を渡さない」方針を踏襲しつつ、検証対象の worktree を特定するための最小限の情報として worktree パスを許容する）
- creator 呼び出し自体（worktree 作成を含む）が失敗した場合の自動リトライは対象外（D-003「今回やらないこと」）。詳細な復旧戦略までは書かなくてよい

  - 各呼び出し結果の worktree パス・ブランチ名をタスク ID に紐づけてセッション内で保持する手順を追加（ファイル永続化は不要と明記）

- 手順5「検証する」を書き換え：

  - verifier が `EnterWorktree(path=...)` で渡された worktree に入ってから検証する旨（新規に worktree を作らない）を明記
  - 全 verifier の完了を待ってから `vault/verdicts/<計画ID>/<id>.json` を読む手順を維持
