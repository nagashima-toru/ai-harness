# T-01 stop_gate の review・verdict なしの理由文に verifier の完了通知を待つ案内を入れる

## 目的
status が review で verdict が無い（または task / attempt が不一致の古い）時の stop_gate のブロック理由に、「待機中なら問題ありません」と verifier の完了通知を待つ案内を入れる。判定（ブロックするかどうか）は変えず、文言だけを変える（GitHub Issue #193）。

## 入力
- `.claude/hooks/stop_gate.py`（`if verdict is None or stale:` の分岐。doing・記録行なしの理由文が手本）
- `scripts/smoke.sh`（`# 記録行の無い doing の block 理由だけ完了通知の案内が付く` から始まる async-wait 系のテスト、および冒頭の `make_plan_task`・`make_verdict`・`run_stop`・`expect`・`expect_eq`）
- `docs/decisions.md` の 2026-10-10 と 2026-10-12 の `stop_gate.py` の行（判定は変えず文言だけ、という人の選択）

## 成果物
- `.claude/hooks/stop_gate.py`（主な成果物。review の理由文とモジュール docstring）
- `scripts/smoke.sh`（async-wait 系のテストの書き換えと追加）

## 受け入れ基準
- `grep -c 'verifier の完了通知を待っている場合は' .claude/hooks/stop_gate.py` の出力が `1`
- `grep -c 'async-wait-3.*verifier の完了通知を待っている場合' scripts/smoke.sh` の出力が `1`（async-wait-3 が新しい文言を期待する形に書き換わっている）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (async-wait-[1-6]) '` の出力が `6`（既存の1〜5と、追加した6がすべて ok）
- `bash scripts/smoke.sh 2>&1 | grep -c 'fail=0$'` の出力が `1`（smoke 全体が通り、`stop_hook_active=true + HARNESS_STRICT_STOP=1 → ブロック` などの既存テストも壊していない）
- `git diff --merge-base work/p-20261012-verifier-wait-stop-gate --name-only` の出力に `.claude/hooks/stop_gate.py` と `scripts/smoke.sh` の両方が含まれる

## 決定済み
- 判定は変えない。ブロックするかどうか・判定の順序・doing の分岐（記録行の有無で文言を変える既存の動き）はそのまま。変えるのは status が review で verdict が無い・古い時の理由文だけ（D-20261010-async-agent-wait と、人が 2026-10-12 に選んだ「止める判定は変えず文言だけ」の B 案）
- 対象の条件：`verdict is None or stale` で、かつ `status == "review"` の時。verdict が古い（stale）時も含める（FAIL 後の再試行で attempt=2 の verifier を待つ間は、attempt=1 の verdict が残っているため）。doing で記録行がある時（async-wait-2・5 の状況）は今の文言のまま変えない
- review の理由文は次のとおりにする（この文字どおり。`{...}` は既存の変数）：
  `[stop_gate] {task_key} は {status} ですが {why}。verifier の検証待ちです。待機中なら問題ありません。verifier の完了通知を待っている場合は、そのままターンを終えて通知を待ってください（2回目の停止は許可されます）。待っていないなら verifier サブエージェントを実行して vault/verdicts/{task_key}.json を書くこと（attempt={attempt}）。`
  - 既存テストが「verifier」「古い」「verdict が無い」の部分一致を見ているので、`{why}` と `verifier サブエージェントを実行して` は残す
- モジュール docstring の「doing で、その id の最後の着手…」の段落に、review で verdict が無い・古い時も同じく「待機中なら問題ありません」と verifier の完了通知を待つ案内を足す旨を1〜2文で追記する
- smoke の書き換え：
  - async-wait-3 を、review・verdict 無し・log 無しで block になり、出力に `verdict が無い`・`待機中なら問題ありません`・`verifier の完了通知を待っている場合` がそれぞれ含まれることを確かめるテストに書き換える。名前は `(async-wait-3) review・verdict 無し・log 無し → block・verdict が無い・verifier の完了通知を待っている場合の文言あり` とする。既存の async-wait-3 と同じく `expect_eq` と `grep -c` の数え方でよい（期待値は `block 1 1 1`）
  - async-wait-6 を async-wait-5 の後（`rm -rf "$TMP/vault/log" "$TMP/vault/verdicts"` の行の前）に足す。`make_plan_task T-0001 review 2` と `make_verdict T-0001 1 FAIL` で、古い verdict の review を作り、block になり、出力に `verdict が古い` と `verifier の完了通知を待っている場合` が含まれることを確かめる。名前は `(async-wait-6) review・古い verdict（attempt 不一致）→ block・verifier の完了通知を待っている場合の文言あり` とする
  - 既存の async-wait-1・2・4・5 は変えない。smoke.sh 内のテストの前後処理は既存の書き方（`rm -rf "$TMP/..."` を含む）に合わせてよい（smoke 自身の一時ディレクトリの中の操作で、確認コマンドではない）
- `docs/vault-spec.md`・`.claude/skills/run/SKILL.md`・`docs/decisions.md` は T-02 で直すので、このタスクでは触らない
- smoke は1回およそ1分かかる。確認コマンドの3つ目と4つ目はそれぞれ smoke を実行する
