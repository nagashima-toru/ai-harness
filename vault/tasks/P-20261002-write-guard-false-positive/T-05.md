# T-05 run/SKILL.md 手順6.3.4 にログ追記・git add・git commit を別々に実行する旨を明記する

## 目的
done 遷移の書き込みとコミットを1つの Bash に連結すると、ガードの解析できない形（`$(cat <<'EOF' …)` のコマンド置換など）になり拒否されることがある（issue #87）。`.claude/skills/run/SKILL.md` 手順6.3.4 に、別々のコマンドで実行することと、コミットメッセージの渡し方を明記する（計画の方針：案1）。

## 入力
- `.claude/skills/run/SKILL.md` 手順6「verdict に従う」の 3.4（`マージが衝突なく成功したら、status を ...` で始まる行）
- `vault/plans/P-20261002-write-guard-false-positive.md` の「分割方針」（案1を採り案2を採らない理由）

## 成果物
- `.claude/skills/run/SKILL.md` の手順6.3.4 への追記（1ファイル）

## 受け入れ基準
- 手順6.3.4 の行に、ログ追記・`git add`・`git commit` を `&&`・`;` で連結せず別々の Bash 呼び出しで実行する旨がある。確認：`grep -n '別々の Bash 呼び出し' .claude/skills/run/SKILL.md` の出力が1行で、その行が `マージが衝突なく成功したら` を含む
- 同じ行に、コミットメッセージを1行の `-m` で渡し、コマンド置換・ヒアドキュメントを使わない旨がある。確認：`grep -n 'コマンド置換・ヒアドキュメントは使わない' .claude/skills/run/SKILL.md` の出力が1行で、その行が `マージが衝突なく成功したら` を含む
- 手順6.3.4 の既存の手順（done への更新・log 追記・`git add`・コミット・`git worktree remove`・`git branch -d`）が残っている。確認：`grep -n 'マージが衝突なく成功したら' .claude/skills/run/SKILL.md` の行に `review→done attempt=<n> verifier=<モデル>`・`git worktree remove`・`git branch -d` がすべて含まれる
- 手順の番号と見出しを変えていない。確認：`git diff main -- .claude/skills/run/SKILL.md` の出力に、`+## ` か `-## ` で始まる行が無い
- 成果物以外のファイルを変更していない。確認：`git status --porcelain` に出るパスが `.claude/skills/run/SKILL.md` と `vault/tasks/P-20261002-write-guard-false-positive/T-05.md` だけ

## 決定済み
- 追記は手順6.3.4 の行の末尾（`git branch -d <ブランチ名>` ... で削除する の後）に、次の文をそのまま足す（受け入れ基準の grep がこの文言に依存する）。改行して別の行にはしない（手順の番号付きリストの構造を保つため）
  「ログ追記（`printf ... >> vault/log/<計画ID>.md`）・`git add`・`git commit` は `&&` や `;` で連結せず、別々の Bash 呼び出しで実行する。コミットメッセージは `git commit -m "<計画ID>/<id>: done"` のように1行の `-m` で渡し、`$(cat <<'EOF' …)` のようなコマンド置換・ヒアドキュメントは使わない（`agent_write_guard.py` はコマンド置換を含むコマンドを解析できず、従来の判定でメッセージ中の done の verdict パスを書き込み対象とみなして拒否するため。issue #87）」
- 他の手順（6.3.1 の `git -C <worktree> commit` など）には同じ注意を足さない。今回の範囲は 6.3.4 だけ（ゴールを広げない）
- `.claude/ai-harness.md`・`docs/vault-spec.md` は変えない（vault-spec は T-06 で扱う）
- コミットは受け入れ基準に無いので creator は行わない
