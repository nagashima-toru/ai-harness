# T-02 stop_gate.py の parse_tasks・count_acceptance_criteria を _hooklib の関数に置き換える

## 目的
`stop_gate.py` が持つ厳しい側の複製（行頭の空白を許さない `parse_tasks`、行頭 `- ` だけを数える `count_acceptance_criteria`）を消し、`_hooklib` の `parse_tasks`・`count_criteria` を使う。番号付きの受け入れ基準のタスク票やインデントしたタスク表の行でも、正しく判定されるようにする。

## 入力
- `vault/designs/D-011.md`（フェーズ2）
- `.claude/hooks/_hooklib.py`（T-01 の成果物。`parse_tasks`・`count_criteria`）
- `.claude/hooks/stop_gate.py`（消す関数：`parse_tasks`・`count_acceptance_criteria`。使う側：`validate_verdict`・`main`）
- フィクスチャ：`vault/tasks/P-20261004-hooklib-rules/fixtures/`（planner が作成済み。編集しない）

## 成果物
- `.claude/hooks/stop_gate.py`（1ファイル）

## 受け入れ基準
- 構文が正しい：`python3 -B -c "import ast; ast.parse(open('.claude/hooks/stop_gate.py').read()); print('ok')"` の出力が `ok`
- 複製の関数定義が残っていない：`grep -nE '^def (parse_tasks|count_acceptance_criteria|count_criteria)\(' .claude/hooks/stop_gate.py` の出力が空
- 番号付きの受け入れ基準4行を4件と数え、件数の不一致は従来どおり検出する：`python3 -B -c "import runpy; g = runpy.run_path('.claude/hooks/stop_gate.py', run_name='sg'); c = {'text': 'x', 'ok': True, 'note': 'n'}; v = g['validate_verdict']; p = 'vault/tasks/P-20261004-hooklib-rules/fixtures/numbered-criteria.md'; print(v({'result': 'PASS', 'criteria': [c] * 4, 'reasons': []}, 'P/T-01', p), v({'result': 'PASS', 'criteria': [c] * 3, 'reasons': []}, 'P/T-01', p))"` の出力が `[] ['criteria の行数（3）がタスク票の受け入れ基準の行数（4）と一致しません']`
- インデントした doing の行を検査対象にする（未コミット検査は差し替えて飛ばす）：`printf '{}' | env CLAUDE_PROJECT_DIR=vault/tasks/P-20261004-hooklib-rules/fixtures python3 -B -c "import runpy; g = runpy.run_path('.claude/hooks/stop_gate.py', run_name='sg'); g['main'].__globals__['has_uncommitted_changes'] = lambda root: False; g['main']()"` の出力が `P-FIXTURE-QUOTED/T-01 は doing ですが verdict が無い` を含む
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- `parse_tasks` と `count_acceptance_criteria` の定義を消す
  - `main` の `tasks = parse_tasks(f.read())` は `tasks = H.parse_tasks(f.read())` にする
  - `validate_verdict(verdict, expected_task, task_path)` の引数は変えない。中で `os.path.isfile(task_path)` の時にファイルを読み、本文を `H.count_criteria(text)` に渡す（D-011：`count_criteria` は本文を受け取り、stop_gate 側はファイルを読んでから渡す）
  - 別名（`parse_tasks = H.parse_tasks` など）は作らない
- 使わなくなった `import re` は消してよい（他で使っていなければ）
- ブロックのメッセージ・判定の順序・`project_dir`・`has_uncommitted_changes` は変えない。`project_dir` は各フックで役割が違うので統一しない（D-011）
- モジュール docstring に「タスク表と受け入れ基準の読み方は `_hooklib.py` の `parse_tasks`・`count_criteria` を使う」趣旨の1行を足してよい（必須ではない）
- `_hooklib.py`・他の2フック・scripts・smoke.sh・docs は変更しない（他タスクの担当）
- 既存の smoke が落ちた場合は、smoke.sh を直さず blocked にして、落ちたケース名と原因を question に書く
- 動作確認で import する時は `python3 -B` を使う。`.claude/hooks/__pycache__/_hooklib*` を作ってしまったら消しておく
- コミットは受け入れ基準に無いので、creator はしない
