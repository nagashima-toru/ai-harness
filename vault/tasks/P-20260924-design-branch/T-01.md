## 決定済み
- ブランチ名は `design/d-xxx`（`xxx` は D-ID の3桁を小文字化。例：D-002 → `design/d-002`）
- PR マージは `/plan` の `run` が最後に作る PR と同じ運用（`gh pr create` まで。`gh pr merge` はエー
  ジェントが実行しない。マージは人が行う）
- 設計文書は1セッションで全フェーズの4点セットを書き切ってから提示するので、丸ごと1回の PR で
  `main` にマージする。マージのタイミングはフェーズ1の実装着手前（人が PR をレビュー・マージしてか
  ら、フェーズ1のゴール文を `/plan` に渡す）
- `/plan` 側の手順は変更しない。「現在のブランチが `main` であることを確認してから `work/...` を切
  る」という既存ルールのまま。`design/d-xxx` から直接分岐する特別ルートは作らない
- 章番号や既存の章立ては変えない。追記は第13節の中に追記する形でよく、新しい章番号は不要
- 文言は `.claude/skills/design/SKILL.md`（T-02 で更新）と揃える必要はあるが、T-02 の作業を待つ必要
  はない。本タスクの「決定済み」に書かれた内容がそのまま両方の正本になる
