# T-01 planner.md の差分確認の指針を main と比べない形（計画ブランチとの分岐点）に直す

## 目的
`.claude/agents/planner.md` の「やらないこと」節の、差分確認の指針（現在の68行目、「他タスクの成果物を変更していないことの確認は、`git diff main -- <path>` ではなく `git status --porcelain`…」で始まる項目）を、単一タスクの計画でも `main` と比べず、verifier が収集コミット後の worktree で実行しても機能する形に書き直す。

## 入力
- `.claude/agents/planner.md`（「やらないこと」節の68行目・69行目）
- `.claude/skills/run/SKILL.md`（手順3・手順4・手順5。worktree の分岐元 `PLAN_HEAD`、review での収集コミット、verifier が worktree に `cd` して実行すること）
- `scripts/transition.py`（`collect_worktree`。review への遷移で worktree の未コミット分を `git add -A` してコミットする）
- `.claude/skills/plan/SKILL.md` 手順2（`git fetch origin <ベースブランチ>:<ベースブランチ>` でローカルの `main` が進む）

## 成果物
- `.claude/agents/planner.md`（1ファイル。「やらないこと」節の差分確認の項目1つを置き換える）

## 受け入れ基準
1. 旧い指針の文言が文書に残っていない：`grep -rlF --exclude-dir=worktrees '成果物パス以外に変更が無いことを確認する形' .claude docs README.md vault/rules` の出力が空
2. 新しい項目が推奨する形が planner.md にちょうど1回書かれている：`grep -cF 'diff --merge-base work/' .claude/agents/planner.md` の出力が `1`
3. 単一タスクの計画でも `main` と比べないことが書かれている：`grep -cF '単一タスクの計画でも' .claude/agents/planner.md` の出力が `1`
4. `git status --porcelain` が収集コミットの後は空になり使えない理由が書かれている：`grep -cF '収集コミット' .claude/agents/planner.md` の出力が `1`
5. 推奨する形が対象 worktree の中で実際に機能する（未コミットでも収集コミット後でも成果物が出る）：対象 worktree で `git diff --merge-base work/p-20261011-planner-check-cmd-guidance --name-only | grep -cxF '.claude/agents/planner.md'` の出力が `1`
6. 文書の参照が壊れていない：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
7. smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 置き換えるのは68行目の項目1つだけ。69行目（「成果物は `<ファイル>` のみで…」の除外パスにタスク票自身を入れる項目）は変えない（新しい形でも creator の「進捗」追記でタスク票は差分に出るので、そのまま有効）。「書き終えた後の確認」節も変えない。ほかの項目・節も変えない。
- 置き換え後の項目は、次の文をそのまま書く（言い回しの微修正は可。ただし下の「必ず書く語」と「書かない語」を守る）。

  ```
  - 差分の確認を、ベースブランチ（既定 `main`）と比べる形（`git diff main -- <path>`・`git diff --numstat main -- <path>` など）で書かない。単一タスクの計画でも同じ。作業中にローカルの `main` が進むと（`/plan` の手順2の `git fetch origin main:main` など）、タスクと無関係な差分が混ざって誤って FAIL になる。複数タスクの計画では、run がタスクを完了順に `git merge --no-ff` で計画ブランチに取り込むため、先行タスクの変更まで差分に出る。`git status --porcelain` も使わない。`scripts/transition.py` が review への遷移で worktree の未コミット分を収集コミットにするので、verifier が検証する時点では `git status --porcelain` は空になり、何も確かめない基準になる。差分は計画ブランチとの分岐点と比べ、`git diff --merge-base work/<計画IDの英小文字> --name-only` の形で書く（行数まで見る時は `--name-only` を `--numstat` に替え、対象を絞る時は末尾に `-- <path>` を足す）。分岐点は creator の worktree の分岐元（`PLAN_HEAD`）で、作業ツリーと比べるので、creator が収集の前に実行しても verifier が収集の後に実行しても同じ結果になり、`main` や計画ブランチが後から進んでも変わらない（git 2.30 以降）。このコマンドは対象 worktree の中で実行する前提で、計画ブランチ上で実行すると空になる。そのため、空の出力で通る基準（「成果物以外のパスが出ない」など）だけにせず、成果物のパスが出力に含まれることを確かめる基準を併記する
  ```
- 必ず書く語（受け入れ基準2〜4が数える）：`diff --merge-base work/`（ファイル全体でちょうど1回。言い換えの説明で同じ並びを繰り返さない）、`単一タスクの計画でも`（ファイル全体で1回）、`収集コミット`（ファイル全体で1回。上の文では「収集コミットにする」の1回だけで、「収集の前に」「収集の後に」は `収集コミット` を含まない）。
- 書かない語：`起点コミット`（smoke の `(agents-1)` が planner.md にこの語が無いことを検査している）。`成果物パス以外に変更が無いことを確認する形`（旧い指針の文言。基準1）。計画 ID・issue 番号などこのリポジトリ固有の経緯（planner.md は導入先に配る汎用の文書で、経緯は T-03 が `vault/rules/planner/ai-harness-lessons.md` に書く）。
- `work/<計画IDの英小文字>` は `/plan` が切る計画ブランチの名前（`HARNESS_PUSH_BRANCH` が設定されていてもローカルのブランチ名は `work/…` のまま。`docs/vault-spec.md` 1節）。`<` を含むので smoke の `(ref-1)` はパスとして検査しない。
- 推奨する形は planner が一時リポジトリで確かめ済み：worktree の未コミットの変更でも、収集コミットの後でも、`main` と計画ブランチが進んだ後でも、`git diff --merge-base <計画ブランチ> --name-only` は worktree の変更ファイルだけを出した。`git status --porcelain` は収集コミットの後は空だった。このリポジトリの git は 2.43。
- 受け入れ基準5は、creator は自分の worktree で（未コミットのまま）、verifier は手順5のとおり対象 worktree に `cd` して実行する。出力にはタスク票自身（`vault/tasks/P-20261011-planner-check-cmd-guidance/T-01.md`）の行も出るが、`-x` の完全一致で planner.md の行だけを数えるので影響しない。
- 受け入れ基準1の範囲から `vault/plans/`・`vault/tasks/`・`vault/log/` を外す理由：この計画の計画票・タスク票は旧い文言を引用して説明しており、計画一式は PR の前に除去されるため。`vault/rules/` は範囲に含める（現時点でこの文言は無い）。`--exclude-dir=worktrees` は、メインリポジトリの `.claude/worktrees/` 配下にある他の worktree（旧い版の写し）を数えないため。
