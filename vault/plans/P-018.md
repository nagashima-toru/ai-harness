# ゴール
人が提示した「Git 運用ルール」原案を、このハーネスのプロセス（todo→doing→review→done、verdict PASS が done の条件、1計画=複数タスク＋after 依存）に翻案し、`vault/rules/` のルール文書・フック・スキル・配布ドキュメントとして実装する。

範囲は人が既に決めた8項目の決定事項（ブランチ粒度=1計画1ブランチ、マージは人・PR作成はエージェントまで、フックとルール文書の両輪で強制、コミット粒度=作業ステップごと、done≠マージの二層構造、破棄は`git restore`のみで足りなければ人に報告、配置先は`vault/rules/common/git.md`＋creator側手順、`--force-with-lease`を deny に追加）をそのまま実装に落とすことに限定する。ゴールを広げない。

## 分割方針
- 契約タスク（T-0030）で `vault/rules/common/git.md` に方針（原則・ブランチ・コミット・完了の定義の二層構造・セッション終了時の扱い・禁止・例外）を先に固定する。以降の全タスクはこれを前提にする。
- T-0031（creator 向け手順）と T-0032（agent_write_guard.py の main 直接コミット拒否＋`--force-with-lease` deny）と T-0033（stop_gate.py の未コミット差分検査）は、いずれも T-0030 の方針を実装・具体化するだけなので、T-0030 にのみ依存させ並行可能にする（実行は run-queue が直列に処理するため実質順番になるが、依存関係としては循環しない）。
- T-0034（`run-queue` SKILL.md の手順改訂）は、creator 手順（T-0031）とフックの実際の挙動（T-0032・T-0033）を正しく記述する必要があるため、その3つ全部に依存させる。
- T-0035（配布・周知：install.sh の複製対象、`.gitignore`、README/runbook/decisions.md）は最後に全部が揃ってから1つにまとめる（`vault/rules/README.md` 方式の T-0023 と同じ理由：実在パスを列挙するため）。
- `.claude/skills/plan/SKILL.md`（計画承認時の処理）は変更しない：ブランチ名は計画承認時ではなく、creator が「そのタスクが属する計画の最初のタスクを取った時」に `vault/plans/` を検索して決定的に導出する（T-0031 の決定済みに具体的な手順を書く）。承認フローに新しい入力（ブランチ名の決定）を増やすと `/plan` の責務が広がるため採らない。
- `docs/vault-spec.md` は変更しない：git 運用はタスクの状態遷移そのものを変えるものではなく、既存の「12. ルール（vault/rules/）」の拡張ポイントの範囲内に収まるため。

## 備考（鶏卵問題）
このP-018自体を run-queue で処理する間は、T-0030〜T-0033が完了するまで新しい git ルール（1計画1ブランチ・main直接コミット拒否・未コミット差分検査）はまだ存在しない、または存在しても未強制。したがって、この計画の実施中は既存の `vault/rules/creator/creator.md`（現行版）の運用に従えばよく、新ブランチ運用を自分に適用する必要はない。人が任意でこの計画自体を dogfooding する場合（例：`work/p-018-git-ops` を手で切って進める）は妨げないが、それを行うかどうかはタスクの受け入れ基準には含めない。

## 計画の受け入れ基準
- 各タスクに成果物と受け入れ基準が1つずつある
- 依存に循環がない（T-0030 → {T-0031, T-0032, T-0033} → T-0034 → T-0035）
- 1タスクが1コンテキストで終わる粒度である
- 人が決めた8項目の決定事項（ブランチ粒度・マージ主体・二重の強制・コミット粒度・二層構造・破棄手段・配置先・force-with-lease）がすべていずれかのタスクの成果物に反映されている

## 次フェーズの候補（このプランでは票を起こさない）
- 一時 install 先で `claude -p "/run-queue"` を用いた git ルールの通し検証（実際にブランチが切られ、ステップごとにコミットされ、計画完了後に PR が作られることを確認して `docs/decisions.md` に記録）
- `git commit --amend` / `git rebase` を人の指示なく実行することを検知・拒否するフック（今回は main への直接コミットと未コミット差分の検査のみに限定した）
- 月次 archive 手順（`docs/runbook.md` 第5節）とブランチ削除の関係の整理（現状はマージ後のブランチ削除も人の操作のまま）
