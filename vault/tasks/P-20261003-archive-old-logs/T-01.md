# T-01 計画一式を archive に移す scripts/archive_plans.sh を作る

## 目的
done かつ PR がマージ済みの計画の一式（計画票・タスク票・verdict・log）を、安全装置付きで `vault/archive/<年-月>/` へ `git mv` で移すスクリプトを作る。実際の移動は人が行い、エージェントは `--dry-run` だけを使う前提にする。

## 入力
- `docs/runbook.md` 5節（現在の手動手順。名前が衝突する欠陥がある：計画票の「分割方針」を見る）
- `vault/archive/2026-09/`（既存の archive の形。種別ごとのサブディレクトリ）
- `scripts/current_plan.sh`（frontmatter の読み方の規則。同じ規則で読む）
- `scripts/discard_worktree.sh`・`scripts/vcs_finish.sh`（既存の bash スクリプトの書き方）
- 計画票 `vault/plans/P-20261003-archive-old-logs.md` の「分割方針」

## 成果物
- `scripts/archive_plans.sh`（新規。1ファイル）

## 受け入れ基準
- 構文エラーが無い：`bash -n scripts/archive_plans.sh` の出力が空
- done かつ main にマージ済みの計画を渡すと、4種別の移動行を出す：`bash scripts/archive_plans.sh --dry-run P-20260920-freeze-legacy | grep -c ' vault/archive/2026-09/\(plans\|tasks\|verdicts\|log\)/P-20260920-freeze-legacy'` の出力が `4`
- 現在の計画（approved で main に無い）を渡すと NG 行を出す：`bash scripts/archive_plans.sh --dry-run P-20261003-archive-old-logs 2>&1 | grep -c '^archive_plans: NG P-20261003-archive-old-logs: '` の出力が `1` 以上
- 1件でも NG があれば移動行を1行も出さない：`bash scripts/archive_plans.sh --dry-run P-20260920-freeze-legacy P-20261003-archive-old-logs 2>&1 | grep -c ' vault/archive/'` の出力が `0`
- `--dry-run` も `--apply` も無い時は usage を出す：`bash scripts/archive_plans.sh P-20260920-freeze-legacy 2>&1 | grep -c '^usage: '` の出力が `1`
- `--dry-run` は何も移さない：上の各コマンドの実行後に `git status --porcelain -- vault/archive` の出力が空

## 決定済み
- 使い方：`bash scripts/archive_plans.sh (--dry-run|--apply) [--base <ref>] [--from-file <path>] [<計画ID> ...]`。`--dry-run` と `--apply` はどちらか1つを必ず指定する（両方・どちらも無しは usage を stderr に出して終了コード2）。計画 ID は引数と `--from-file` の両方から集めてよく、合わせて1件も無ければ usage で終了コード2。`--from-file` は1行1件、空行と `#` で始まる行は読み飛ばす。`--base` の既定は `main`
- usage の行は `usage: ` で始める（stderr）
- リポジトリのルートは `git rev-parse --show-toplevel`（カレントディレクトリ基準）で決める。git リポジトリの外なら stderr にメッセージを出して終了コード2。スクリプト自身の置き場所は基準にしない（smoke.sh で一時リポジトリから呼ぶため）
- 配置：計画 ID の日付部分から `<年-月>` を作り（`P-20260924-x` → `2026-09`）、次の4つを移す。存在しないもの（例：verdict の無い計画）は飛ばす（NG にしない）。計画票が無いのは NG
  - `vault/plans/<ID>.md` → `vault/archive/<年-月>/plans/<ID>.md`
  - `vault/tasks/<ID>` → `vault/archive/<年-月>/tasks/<ID>`
  - `vault/verdicts/<ID>` → `vault/archive/<年-月>/verdicts/<ID>`
  - `vault/log/<ID>.md` → `vault/archive/<年-月>/log/<ID>.md`
- 安全装置（全 ID について先にすべて検査し、1件でも NG があれば何も移さず、移動行も出さずに終了コード1）。NG は1件ごとに stderr へ `archive_plans: NG <ID>: <理由>` の1行で出す（1つの ID に複数の理由があれば複数行でよい）
  1. ID が `^P-[0-9]{8}-[a-z0-9][a-z0-9-]*$` に一致する（`P-019` などの旧形式は NG）
  2. 同じ ID が2回以上渡されていない
  3. `vault/plans/<ID>.md` があり、frontmatter の `status` が `done`（approved・draft は NG。frontmatter の読み方は `scripts/current_plan.sh` と同じ：1行目が `---`、次の `---` まで）
  4. タスク表のデータ行（先頭のセルが `T-` で始まる行）が1行以上あり、全行の status 列（2列目）が `done`
  5. `git show <base>:vault/plans/<ID>.md` が成功し、その版の frontmatter の `status` も `done`（＝ PR がマージ済み。読めなければ NG）
  6. 現在のブランチ名が `work/<ID を英小文字にしたもの>` でない
  7. 移動元の4パスに未コミットの変更・未追跡ファイルが無い（`git status --porcelain -- <パス>` が空）
  8. 移動先の4パスがまだ存在しない
- 出力：検査がすべて通ったら、移動1件ごとに stdout へ `git mv <移動元> <移動先>` の1行を出す（パスはリポジトリのルートからの相対パス）。`--dry-run` はそこで終了コード0。`--apply` は同じ行を出しつつ、移動先の親ディレクトリを `mkdir -p` してから実際に `git mv` する。途中で `git mv` が失敗したら stderr に出して終了コード1（それまでの移動は戻さない。人が `git status` で確かめる）
- コミットはしない（人が中身を確かめてからコミットする）
- 冒頭のコメントに「`--apply` は人が手元で実行する。エージェント（creator を含む）は `--dry-run` だけを使う。creator は `vault/plans/`・`vault/log/` に書き込めず、スクリプト経由の移動はその禁止を回避することになるため」と書く
- `scripts/install.sh` の `SCRIPTS_EXCLUDE` は変えない（導入先にも配る。汎用のスクリプトのため）。install.sh は触らない
- 受け入れ基準の確認コマンドは、`vault/plans/P-20260920-freeze-legacy.md` が done・`main` にも done で存在すること、この計画の計画票が approved で `main` に無いことを前提にしている（2026-10-03 時点で planner が確認済み）
- `.claude/hooks/`・`.claude/settings.json` は触らない（issue #85）
