# ゴール
GitHub Issue #109 を解決する（#91・#87 の続き）。`.claude/hooks/agent_write_guard.py` が、コマンドの本文・引数に出てくるだけの `vault/rules/` のパス文字列を書き込み先とみなし、「vault/rules/ へは書き込めません」と拒否する誤検知を、実際の書き込みの拒否を落とさずに減らす。

## 分割方針
- planner が確かめた原因（会話記録に残っていた実際の拒否コマンドを `analyze_bash_writes` に通して確認した）：
  - (a) `gh issue create --body "$(cat <<'EOF' … EOF)"`：`$(` を含むので `analyze_bash_writes` が None を返す（ヒアドキュメントが二重引用符の中にあり `_strip_heredocs` は本文を捨てない）。従来判定 `_legacy_targets_vault_rules_bash` は、本文の `>`（例：`… > /tmp/…`）を書き込みパターンとして拾い、本文中の `vault/rules/…` の語を候補にして拒否する。
  - (b) issue の説明と違い、原因はグロブではなく**先頭の `cd <リポジトリのルート>;`**。`cd` が `UNPARSEABLE_COMMANDS` にあるため None になる。`cd` を外した同じコマンドは解析でき、書き込み対象は `/dev/null` だけになって許可される。他の拒否例（verifier の `cd … && cat > vault/verdicts/… <<'EOF'` で本文に `vault/rules/` がある等）も同じ原因。
  - 残る誤検知（この計画では直さない）：`cd` 先が worktree などルート以外、`python3`・`bash -c` などのインタプリタ、変数を含む対象、`cat` のヒアドキュメント以外のコマンド置換。fail-closed を保つため従来判定のまま。
- 直し方（案A）：解析できる形を2つ足す。T-02 で「本文が `cat` のヒアドキュメントだけのコマンド置換」を解析前に1語の文字列に置き換える。T-03 で「先頭の `cd <ルートと同じディレクトリ>`」を読み飛ばす。どちらも、書き込みの起こりえない形だけを解析できる側に移すもので、従来判定そのもの（`_legacy_…`）は変えない。
- T-01 で先に smoke.sh に回帰ケース（誤検知が通る6件・拒否されるべきものが拒否される9件）を足す。直す前は誤検知の6件が NG になり、T-02 で heredoc の4件、T-03 で cd の2件が ok に変わる。T-02・T-03 の受け入れ基準はこの smoke の出力で機能を確かめる（確認コマンドに `vault/rules/` や `$(` を埋め込まずに済む）。
- smoke.sh の既存ケース「(bash-parse-done) #87 の2例目 …（解析不能は従来判定）→ 拒否」は、コミットメッセージの本文に done の verdict のパスがあるだけの誤検知そのもので、T-02 の後は許可になる。T-01 でこのケースを「(guard-text heredoc) … → 許可」に置き換える（実際の書き込みの拒否は、既存の「commit メッセージ内のコマンド置換で done のタスク票へ書き込み → 拒否」で残る）。
- T-02・T-03 は同じファイル（`agent_write_guard.py`）を直すので直列にする。issue #85 により、creator の `.claude/hooks/` の編集が auto mode の分類器に拒否されることがある。その時は回避せず blocked にし、人が手で適用する（各タスク票の「決定済み」）。
- T-04 は planner のルールの提案ファイル。T-02・T-03 で解析できる形が変わるので、`planner.md` の (2)（解析できない形）の記述に、`vault/rules/` のパス文字列が拒否されうることと2つの例外を足し、避け方（分けて実行するか Read で読む）を1文足す。issue の「提案」の2つ目（回避策をルールに書く）に当たり、残る誤検知への備えも兼ねる。
- planner が事前に確かめたこと：T-02 の置き換え処理を python の中で試作し、(a) の形・done の verdict のパスを本文に持つコミットメッセージは解析でき（書き込みは空 / git-commit だけ）、`echo "$(cat <<'EOF' … EOF)" > vault/rules/a.md` は vault/rules/ へのリダイレクトとして残り、展開される本文に `$(` がある形・`EOF` の後ろに別のコマンドがある形は None のままになることを確認した。T-04 の置き換え後の全文を python の中で組み立て、`diff` のハンクが `46a47`・`48c49` の2つになることを確認した。現行の smoke.sh は pass=440 fail=0。
