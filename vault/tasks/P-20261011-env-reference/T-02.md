# T-02 smoke に表とコードの HARNESS_* の一致検査を足し、configuration.md を ref-1 の対象にする

## 目的
`scripts/`・`.claude/` に出てくる `HARNESS_*` と `docs/configuration.md` の表の変数がずれたら `scripts/smoke.sh` が fail するようにし、`docs/configuration.md` のバッククォート内のパスも `(ref-1)` で検査する。

## 入力
- `vault/designs/D-20261011-user-guide.md`（フェーズ1の「決定済み」：smoke の照合方法・ref-1 の対象にすること）
- `scripts/smoke.sh`（`refcheck` 関数と `(ref-1)`〜`(ref-4)` のケース、`expect_eq`）
- `docs/configuration.md`（T-01 の成果物）
- `.claude/agents/planner.md` の「やらないこと」節（`(ref-1)` の対象の文書を列挙している行）

## 成果物
- `scripts/smoke.sh`（主な成果物）
- `.claude/agents/planner.md`（`(ref-1)` の対象の列挙に `docs/configuration.md` を足すだけ）

## 受け入れ基準
- 追加・変更したケースがすべて ok：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \((envref-1|envref-2|ref-1|ref-5)\) '` が `4`
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<数> fail=0` の形
- `refcheck` の対象に `docs/configuration.md` が入っている：`grep -cxF 'docs += ["README.md", "docs/vault-spec.md", "docs/runbook.md", "docs/install.md", "docs/configuration.md"]' scripts/smoke.sh` が `1`
- `(envref-2)` のフィクスチャの期待値が決定済みのとおり：`grep -cxF 'コードに無い: HARNESS_ONLY_DOC' scripts/smoke.sh` が `1`、`grep -cxF '表に無い: HARNESS_ONLY_CODE' scripts/smoke.sh` が `1`（期待値の文字列を複数行の変数に1行ずつ書くため、行全体で一致する）
- `.claude/agents/planner.md` の `(ref-1)` の対象の列挙が更新されている：`grep -cF '`docs/runbook.md`・`docs/install.md`・`docs/configuration.md`）を成果物に持つタスク' .claude/agents/planner.md` が `1`

## 決定済み
- 照合の関数は `envcheck() { # $1=ルート` として `refcheck` と同じく `python3 - "$1" <<'PY'` のヒアドキュメントで書く（設計文書の `grep -rhoE 'HARNESS_[A-Z_]+'` と同じ集め方を python で行う。grep で書いてもよいが、除外と出力は下のとおりにする）
  - コード側：`<ルート>/scripts` と `<ルート>/.claude` の下の全ファイルを再帰的に読み、正規表現 `HARNESS_[A-Z_]+` に一致する語の集合を作る。除外：ファイル名が `smoke.sh` のもの（フィクスチャの変数名を含むため）・`settings.local.json`（利用者ごとのローカル設定）・ディレクトリ `.claude/worktrees/`（creator の worktree の複製）・`.claude/projects/`・`__pycache__/`。読めない文字は無視する（`errors="ignore"`）。`vault/`・`docs/` は見ない
  - 表側：`<ルート>/docs/configuration.md` の、行頭が `| `HARNESS_XXX` |` の形の行の1列目の変数名の集合（正規表現 `^\| `(HARNESS_[A-Z_]+)` \|`）。ファイルが無ければ空集合
  - 出力：コードにあって表に無いものを `表に無い: <変数>`、表にあってコードに無いものを `コードに無い: <変数>` で1行ずつ。`表に無い:` の行を先に、それぞれ変数名の昇順で出す。差が無ければ何も出さない
- ケースは `(ref-4)` の直後（`async-wait` の前）に置く：
  - `expect_eq "(envref-1) scripts/・.claude/ の HARNESS_* と docs/configuration.md の表の変数が一致する" "" "$(envcheck "$ROOT")"`
  - `(envref-2)`：`$TMP/envref` にフィクスチャを作る。`scripts/a.sh` に `HARNESS_ONLY_CODE` と `HARNESS_BOTH`、`.claude/x.md` に `HARNESS_ONLY_CLAUDE`、`scripts/smoke.sh` に `HARNESS_IN_SMOKE`、`.claude/worktrees/w/y.sh` に `HARNESS_IN_WORKTREE`、`docs/configuration.md` に表の行 `| `HARNESS_BOTH` | x | x | x | x | x |` と `| `HARNESS_ONLY_DOC` | x | x | x | x | x |`。期待値は次の3行ちょうど（除外の動作も同時に確かめる）：
    ```
    表に無い: HARNESS_ONLY_CLAUDE
    表に無い: HARNESS_ONLY_CODE
    コードに無い: HARNESS_ONLY_DOC
    ```
    期待値は `RC_WANT` と同じく、複数行の文字列を変数に入れて渡す（各行が行頭から始まるように書く。受け入れ基準4がこの行を行全体で照合する）
- `refcheck` の docs の行を `docs += ["README.md", "docs/vault-spec.md", "docs/runbook.md", "docs/install.md", "docs/configuration.md"]` に変える（この1行だけ。他の行は変えない）
- `(ref-5)` を `(ref-4)` の直後に足す：`$RC/d/docs/configuration.md` に `` `docs/no-such-g.md` `` の1行を書き、`expect_eq "(ref-5) docs/configuration.md の存在しないパスも見つける" "docs/configuration.md:1: docs/no-such-g.md" "$(refcheck "$RC/d")"`。`(ref-2)` のフィクスチャと期待値は変えない
- `.claude/agents/planner.md` は「やらないこと」節の `(ref-1)` の項目の列挙 `…・`docs/runbook.md`・`docs/install.md`）を成果物に持つタスクに…` を `…・`docs/runbook.md`・`docs/install.md`・`docs/configuration.md`）を成果物に持つタスクに…` に変えるだけ。他の文言は変えない
- フィクスチャの後片付けは既存の smoke のやり方（`$TMP` 配下に作り、smoke 全体の終了処理に任せる）に従う。新たに `rm -rf` を足さなくてよい
- `envref-1` が実リポジトリで fail したら（表に無い変数がコードにある等）、`docs/configuration.md` ではなく原因を進捗に書いて `blocked` にする（このタスクの成果物は `docs/configuration.md` を含まない）
- `scripts/install.sh`・既存の docs は変えない
