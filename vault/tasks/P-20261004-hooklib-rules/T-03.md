# T-03 plan_guard.py の parse_tasks・count_criteria を _hooklib の関数に置き換える

## 目的
`plan_guard.py` に残っている `parse_tasks`・`count_criteria`・`COLUMNS` を消し、T-01 で `_hooklib.py` に移した同じ規則の関数を使う。規則は変わらず、複製だけがなくなる。

## 入力
- `vault/designs/D-011.md`（フェーズ2）
- `.claude/hooks/_hooklib.py`（T-01 の成果物。`TASK_COLUMNS`・`parse_tasks`・`count_criteria`）
- `.claude/hooks/plan_guard.py`（消すもの：`COLUMNS`・`parse_tasks`・`count_criteria`。使う側：`granularity_violation`・`main`）
- フィクスチャ：`vault/tasks/P-20261004-hooklib-rules/fixtures/`（planner が作成済み。編集しない）

## 成果物
- `.claude/hooks/plan_guard.py`（1ファイル）

## 受け入れ基準
- 構文が正しい：`python3 -B -c "import ast; ast.parse(open('.claude/hooks/plan_guard.py').read()); print('ok')"` の出力が `ok`
- 複製の定義が残っていない：`grep -nE '^def (parse_tasks|count_criteria)\(|^COLUMNS' .claude/hooks/plan_guard.py` の出力が空
- 引用符付きの approved・インデントした行の計画票で、question が空の blocked 行を検出する：`printf '{}' | env CLAUDE_PROJECT_DIR=vault/tasks/P-20261004-hooklib-rules/fixtures python3 -B .claude/hooks/plan_guard.py` の出力が `P-FIXTURE-QUOTED の T-02 が blocked なのに question 列が空です` を含む
- 既存の smoke が全件通る（粒度検査・依存の検査のケースを含む）：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- `COLUMNS`・`parse_tasks`・`count_criteria` の定義を消す
  - `parse_tasks(text)` の呼び出しは `H.parse_tasks(text)` にする
  - `count_criteria(text)` の呼び出しは `H.count_criteria(text)` にする
  - 別名（`parse_tasks = H.parse_tasks` など）は作らない
- `CRITERIA_MIN`・`CRITERIA_MAX`・`TASK_PATH_RE`・`PLAN_ROWS_MAX`・`STATUSES`・`dependency_violations`・`project_dir` はこのファイルに残す（plan_guard だけが使う。`project_dir` は統一しない：D-011）
- `main` の列数検査は今どおり `H.raw_rows` の生のセルで行う（6列でない行の検出は `parse_tasks` では埋めてしまうため）
- docstring で「stop_gate.py と同じ規則」と書いている箇所があれば、「`_hooklib.py` の `parse_tasks` を使う」趣旨に直す
- ブロックのメッセージ・判定の順序は変えない
- `_hooklib.py`・他の2フック・scripts・smoke.sh・docs は変更しない（他タスクの担当）
- 既存の smoke が落ちた場合は、smoke.sh を直さず blocked にして、落ちたケース名と原因を question に書く
- 動作確認で import する時は `python3 -B` を使う。`.claude/hooks/__pycache__/_hooklib*` を作ってしまったら消しておく
- コミットは受け入れ基準に無いので、creator はしない
