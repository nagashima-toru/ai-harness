# T-05 .claude/ai-harness.md の「blocked → todo は人だけ」に /plan unblock の旨を追記する

## 目的
全セッションが最初に読む共通ルールで、blocked の解除の窓口が `/plan unblock` であることを明示し、エージェントが独断で解除しないようにする（D-010 フェーズ5）。

## 入力
- `.claude/ai-harness.md`（「状態遷移（5つで固定）」節、「スキル」節）
- `.claude/skills/plan/SKILL.md` の C 節（T-03 の成果物）

## 成果物
- `.claude/ai-harness.md` の変更（1ファイル）

## 受け入れ基準
- 「状態遷移」節の `blocked → todo` の記述が、人が `/plan unblock <計画ID> <id> [回答]` で指示した時だけ行える旨を含む。確認：`grep -n 'blocked → todo' .claude/ai-harness.md` の行に `/plan unblock` を含む
- 「スキル」節の `/plan` の説明に、`/plan unblock` による解除を含む。確認：`grep -c '/plan unblock' .claude/ai-harness.md` が 2 以上
- 変更が上記の2箇所以内で、他の節（開始時に読む順・質問のしかた・役割・禁止）の文が変わっていない。確認：`git diff -- .claude/ai-harness.md | grep -E '^[+-][^+-]' | wc -l` が 8 以下で、目視で確認する
- `bash scripts/smoke.sh` の最終行が `fail=0` になる（`tail -1` で確認）

## 決定済み
- 追記の趣旨：「`blocked → todo` は人だけ」を「`blocked → todo` は人が `/plan unblock <計画ID> <id> [回答]` で指示した時だけ（フックが会話記録で確認する。エージェントの独断は不可）」に改める
- 「スキル」節の `/plan approve <計画ID>` の記述の近くに、`/plan unblock <計画ID> <id> [回答]`（blocked を解除して todo に戻す）を並べる
- 「質問のしかた」の blocked の記述（question 列に書く）は変えない
- ファイルの冒頭の文・見出し名は変えない（`CLAUDE.md` が import している）
