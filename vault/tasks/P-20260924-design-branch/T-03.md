# T-03 design.md テンプレートの見出し構成を確認し必要な追記をする

## 目的
`vault/templates/design.md` の見出し構成が新しい運用（design ブランチ・PR マージ・単体マージでの動
作完結保証）と矛盾しないか確認し、必要な範囲で「受け入れ基準の候補」の説明文に1文を追記する。

## 入力
- `vault/templates/design.md`（現状）
- `docs/vault-spec.md` 第13節（T-01 で更新される内容と同じ文言方針）
- `.claude/skills/design/SKILL.md`（T-02 で更新される内容と同じ文言方針）

## 成果物
- `vault/templates/design.md`（この1ファイルのみ。見出し構成の変更が不要と判断した場合でも、その
  判断の根拠になった確認箇所を「決定済み」の指示どおりに追記して成果物とする）

## 受け入れ基準
- 「受け入れ基準の候補」節の説明に、フェーズ単体で `main` にマージされてもシステムが動作する状態を
  保証する旨が追記されている。確認コマンド：
  `grep -cF '単体で' vault/templates/design.md` の出力が1以上
- 既存の見出し語（ゴール / 決定事項 / 依存関係 / ゴール文 / 受け入れ基準の候補 / 決定済み / 依存 /
  今回やらないこと）がすべて残っている。確認コマンド：
  `for w in ゴール 決定事項 依存関係 ゴール文 受け入れ基準の候補 決定済み 依存 今回やらないこと; do grep -qF "$w" vault/templates/design.md || echo "missing:$w"; done`
  の出力が空
- frontmatter（`id: D-001` のみで `status` を持たない1行構成）が変わっていない。確認コマンド：
  `sed -n '1,3p' vault/templates/design.md` が `---` / `id: D-001` / `---` の3行のままである

## 決定済み
- ブランチ・PR 運用そのもの（`design/d-xxx` の作り方や `gh pr create` の運用）はテンプレートには書
  かない。テンプレートは文書の見出し構成だけを規定するものであり、運用手順は `docs/vault-spec.md` と
  `.claude/skills/design/SKILL.md` の役割
- 追記は「フェーズ1 <タイトル>」の下にある「### 受け入れ基準の候補」の説明行（`- （3〜7行。各行は
  真偽で判定できる文にし、機械で確認できるものは確認コマンドを併記する）`）に1文足す形でよい。文言
  例：「そのフェーズだけが単体で `main` にマージされてもシステムが動作する状態を保証する内容にす
  る」
- 「フェーズ2 <タイトル>」以下はプレースホルダ（`-` のみ）なので、同じ説明を重複して書く必要はない
- 見出し構成の変更が本当に不要だと判断した場合でも、上記の1文追記は行うこと（受け入れ基準の1行目が
  それを検証する）。見出し名・順序・frontmatter は変更しない
