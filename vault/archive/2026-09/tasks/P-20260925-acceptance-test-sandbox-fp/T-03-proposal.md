## 目的
計画エージェント（planner）が何を作り、何を作らないかを定める。
状態遷移・ファイル形式は `docs/vault-spec.md`、役割間の受け渡しは `vault/rules/common/roles.md` を正本とし、ここでは繰り返さない。

## ルール

**責務**
- ゴールを1コンテキストで終わるタスクに割る（受け入れ基準3〜7行、成果物1つ、人手1〜2時間相当）。
- 計画 ID は `P-YYYYMMDD-<slug>`（採番不要）、タスク ID は計画スコープの `T-01`〜。ID の衝突判定・採番は行わない（`/plan` スキルが決めた計画 ID をそのまま使う）。
- タスク票の6見出しをすべて埋め、「決定済み」には creator が聞きそうなことを先回りで書く（「進捗」は空のまま）。
- 型・API・テスト雛形などの契約タスクを先に切り、実装タスクを `after` でそれに依存させる。
- 1計画は5〜7タスクまで。超える分は計画票末尾に「次フェーズの候補」として書くだけにし、票を起こさない。
- 書き込むのは `vault/plans/` と `vault/tasks/` だけ。承認（`status` を `approved` にすること）は人が行う。
- 計画票の `status` は `draft` のままにする。自分で `approved` にしない。
- 不明点が出てもゴールを広げない。計画票末尾の「## 人への質問」に列挙して人に返す。
- ルール変更（`vault/rules/` 配下のファイル）を成果物とするタスクを計画する時は、タスク票の『成果物』を実体パスではなく `vault/tasks/<計画ID>/<id>-proposal.md` にする。受け入れ基準の確認コマンドも、実体ではなく提案ファイルを対象にする（`agent_write_guard.py` が実体パスへの書き込みを常に拒否するため）。

**やらないこと（このリポジトリで実際に起きた失敗から）**
- run が必ず変えるファイル（計画票のタスク表・`vault/log/<計画ID>.md`・タスク票の「進捗」）の差分不変を受け入れ基準にしない。
  状態ファイルへの `git diff --quiet` を基準にしたため T-0002 が blocked になった（旧方式での失敗例）。
  形式の不変を見たい時は見出し行・列構成に限定する。例：`git diff -- vault/plans/<計画ID>.md | grep -E '^[+-](## |\| id )'` の出力が空。
- 語を数えるだけの緩い確認コマンドを書かない。
  T-0016 の `grep -c 'planner' <file>` が1以上、は「planner を呼ばない」と書けていなくても通ってしまう。
  数えるのではなく、検査したい文言・構造そのものに一致するパターンを書く。
- 成果物本文に無い文字列を grep する受け入れ基準を書かない。
  T-0012（`vault/rules`）・T-0013（「## 構成」ツリーの `rules.sh`）では、基準を通すために creator が後から文言を足す羽目になった。
  grep する文言は、そのタスク票の「成果物」か「決定済み」で「この語を書くこと」と明示する。
- 確認コマンドを、自分で読み取り専用で実行しないまま受け入れ基準に書かない。実行して初めて緩さや期待値の食い違いに気づく。
- 他タスクの成果物ファイルを変更していないことを確認する受け入れ基準の確認コマンドは、`git diff main -- <path>` ではなく `git status --porcelain`（成果物パス以外に変更が無いことを確認する形）で書く。
  `run`/`vault/rules/common/git.md` の運用は1計画=1ブランチに複数タスクを完了順に `git merge --no-ff` で逐次マージしていくため、後続タスクの検証時点では先行タスクの変更が既に計画ブランチに含まれている。この状態で `git diff main` を使うと、後続タスクが変更していないファイルまで（先行タスク由来の差分として）非空になり誤検知する。
  `P-20260925-worktree-baseref-merge` の T-01・T-03 では、この形（`git diff main -- ...` が空）で書かれた基準が字句どおり機能せず、過去2回 verifier が自力に `git status --porcelain` 等の代替確認に切り替えて正しく PASS 判定した（issue #42）。
- 機能テストの受け入れ基準で、一時ディレクトリの後片付けに `rm -rf` を使うことを前提にしない。
  `.claude/settings.json` の `permissions.deny` に `Bash(rm -rf *)` 系パターンがあり、`mktemp -d` で作った一時ディレクトリを確認コマンドの中で `rm -rf` で消す書き方は実行できない。
