## 決定済み
- plan 手順A-2 は、上の受け入れ基準の文から始め、続けて「確認は `git branch --show-current` の出力と、`echo "${HARNESS_BASE_BRANCH:-}"` の出力（前後の空白を除き、空なら `main`）を比べる」旨を書く。違えばブランチを切らず「ベースブランチ（`<値>`）に戻ってから `/plan` を実行してください」と伝えて**止まる**。括弧書きの「（既存の作業ブランチに別の計画を重ねる運用は入れない）」は残す
- design 手順1 も同じ形で書く（止まる時の文言は「ベースブランチ（`<値>`）に戻ってから `/design` を実行してください」）。ベースブランチ上なら `git checkout -b design/d-<YYYYMMDD>-<スラッグ>` で切る、の後半は今のまま
- design の手順4（受け入れ基準の候補の「単体で `main` にマージされても」）・手順7（「`main` 直接コミット拒否には引っかからない」）・手順8（「`main` にマージされてから」）の `main` も「ベースブランチ」に言い換える（手順7は「ベースブランチと `main` への直接コミット拒否」）。手順8の head・base の扱いはフェーズ2の範囲なので触らない
- run 手順7の MCP 代替の段落は、`base（`main`）` を受け入れ基準の `base（ベースブランチ。…）` の字句に置き換える。head（現在のブランチ）はフェーズ2の範囲なので変えない。run 手順3.6 の「`origin/main` 等から分岐してしまっている」は分岐元の例示なので変えない
- creator.md の行は `- ベースブランチ（`HARNESS_BASE_BRANCH`、既定 `main`）と `main` に直接コミットしない（`agent_write_guard.py` がフックで強制する）` にする
- `HARNESS_PUSH_BRANCH` に関する開始条件（push 先ブランチ上で HEAD がベースと同一コミットなら許可）はフェーズ2の範囲なので書かない
- これらの文書は smoke の `(ref-1)` の対象。バッククォートの中に存在しないリポジトリ相対パス（`vault/`・`scripts/`・`docs/`・`.claude/` で始まり `<`・`*`・`{`・`$`・空白を含まないもの）を書かない
