# T-05 smoke.sh に done の行の verdict 検査のケースを両フック5件ずつ足す

## 目的
T-03・T-04 で stop_gate.py と plan_guard.py に足した done の行の verdict の検査を、smoke の回帰ケースにする（verdict 無し・FAIL・attempt 不一致・形式不正でブロック、正しい PASS で許可）。

## 入力
- `vault/designs/D-012.md` の「フェーズ1」の受け入れ基準の候補
- `scripts/smoke.sh`（`make_plan_task`・`make_verdict`・`make_task`・`write_verdict`・`run_stop`・`run_plan_guard`・`expect`・`OK_C` の定義）
- `.claude/hooks/stop_gate.py`・`.claude/hooks/plan_guard.py` のブロック理由の文面（T-03・T-04）

## 成果物
- `scripts/smoke.sh`（新しい節を1つ足す。このファイルだけ）

## 受け入れ基準
- 全件通り、ちょうど10件増える：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=529 fail=0`
- stop_gate のケースが5件通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (done-verdict stop_gate) '` の出力が `5`
- plan_guard のケースが5件通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (done-verdict plan_guard) '` の出力が `5`
- ブロックのケースは reason に `<計画ID>/<id>` と done の検査の文面を含むことを確かめている：`grep -c -F '"P-TEST/T-0001 は done ですが"' scripts/smoke.sh` の出力が `8`
- 節の見出しがある：`grep -c -F 'echo "== done-verdict（D-012 フェーズ1） =="' scripts/smoke.sh` の出力が `1`

## 決定済み
- 節の位置：`echo "== rules.sh =="` の直前に `echo "== done-verdict（D-012 フェーズ1） =="` を置き、その下に10ケースを書く
- 節の先頭で `rm -rf "$TMP/vault/plans" "$TMP/vault/verdicts" "$TMP/vault/tasks"; mkdir -p "$TMP/vault/plans"` で前の節の状態を消し、節の末尾でも同じ形で後片付けする（`$TMP` は smoke 自身の一時ディレクトリ。git リポジトリではないので stop_gate の未コミット変更の検査には当たらない）
- 使う計画は `make_plan_task`（計画 ID `P-TEST`・approved・1行）。ケース名・期待値・reason の部分文字列は次の10件をこの字句どおりに書く（`expect "<ケース名>" <block|allow> "$(run_stop)" "<部分文字列>"` の形。plan_guard は `run_plan_guard`）
  - stop_gate（`run_stop`）
    1. `(done-verdict stop_gate) done・verdict 無し → ブロック`：`make_plan_task T-0001 done 1`、verdict を置かない → block、`"P-TEST/T-0001 は done ですが"`
    2. `(done-verdict stop_gate) done・FAIL → ブロック`：`make_plan_task T-0001 done 1; make_verdict T-0001 1 FAIL` → block、`"P-TEST/T-0001 は done ですが"`
    3. `(done-verdict stop_gate) done・attempt 不一致 → ブロック`：`make_plan_task T-0001 done 2; make_verdict T-0001 1 PASS` → block、`"P-TEST/T-0001 は done ですが"`
    4. `(done-verdict stop_gate) done・criteria の行数不一致 → ブロック`：`make_plan_task T-0001 done 1; make_task T-0001 3` と、`write_verdict` で `{"task":"P-TEST/T-0001","attempt":1,"result":"PASS","checked_at":"","criteria":['"$OK_C"','"$OK_C"'],"reasons":[]}`（criteria 2件）→ block、`"P-TEST/T-0001 は done ですが"`
    5. `(done-verdict stop_gate) done・正しい PASS → 許可`：タスク票を消し（`rm -f "$TMP/vault/tasks/P-TEST/T-0001.md"`）、`make_plan_task T-0001 done 1; make_verdict T-0001 1 PASS` → allow（部分文字列なし）
  - plan_guard（`run_plan_guard`）：上の1〜5と同じ前提・同じ期待値で、ケース名の `stop_gate` を `plan_guard` に替えた5件
- ケースごとに前のケースの verdict・タスク票が残らないようにする（verdict 無しのケースの前は `rm -f "$TMP/vault/verdicts/P-TEST/T-0001.json"`、criteria の行数のケースの後はタスク票を消す）
- 部分文字列 `"P-TEST/T-0001 は done ですが"` は、ブロックの4件 × 2フック = 8回、この字句どおりに書く（基準4が数える）。正しい PASS のケースには部分文字列を付けない
- 既存のケース・ヘルパー関数は変えない（T-02 で直した4ケースを含む）。新しいヘルパー関数は作らなくてよい
- フックのファイル（`.claude/hooks/`）は変更しない
