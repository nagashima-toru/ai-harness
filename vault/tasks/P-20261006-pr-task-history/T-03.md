# T-03 docs/runbook.md に PR のマージ方式とタスク履歴の辿り方を書く

## 目的
人が PR をマージする時の方式（スカッシュを推奨、通常のマージも可）と、スカッシュした時にタスクごとの履歴を PR 本文の表から辿れることを、runbook に明記する。

## 入力
- `docs/runbook.md` の3節（PR/MR ができた後の人の操作を書いた行）
- T-02 後の `scripts/vcs_finish.sh`（引数なしで計画が見つかれば、PR タイトルが `<計画ID>: <ゴールの1行目>`、本文が `scripts/pr_body.py` の「タスク履歴」表）

## 成果物
- `docs/runbook.md`（3節への追記だけ）

## 受け入れ基準
- `grep -c -F '  - PR のマージ方式：スカッシュマージを推奨する。' docs/runbook.md` の出力が `1`
- `grep -c 'scripts/pr_body.py' docs/runbook.md` の出力が `1` 以上で、その行が3節（`## 3.` と `## 4.` の間）にある（Read で確認）
- `grep -c -F 'Pull request title and description' docs/runbook.md` の出力が `1`（スカッシュ時に表をコミットメッセージにも残す GitHub の設定を書いている）
- `grep -c '^## ' docs/runbook.md` の出力が `9`（節の見出しを増減していない）

## 決定済み
- 書く場所は3節の「PR/MR ができたら、人が内容を確認して…」の箇条の直後。同じ深さ（行頭2空白の `  - `）で `  - PR のマージ方式：スカッシュマージを推奨する。` で始まる箇条を1つ足し、理由と補足を同じ行か、その下の一段深い箇条で書く
- 書く内容：
  - 推奨の理由：main の履歴が1計画1コミットになり読みやすい。タスクごとの履歴は `scripts/vcs_finish.sh` が作る PR 本文の「タスク履歴」表（タスク ID・title・コミット・verdict。生成は `scripts/pr_body.py`）から辿れる。表のコミットは PR の Commits タブで見られる
  - GitHub でスカッシュする時は、リポジトリ設定の squash merge の既定コミットメッセージを `Pull request title and description` にして、表がスカッシュコミットのメッセージ（= main の `git log`）にも残るようにする（設定は人が行う）
  - 通常のマージ（merge commit）も可：main にタスクごとのコミットが残る。ホスティング無しの `git merge --no-ff` の案内は今のまま
- スカッシュ推奨は計画票の「人の回答」1による人の決定
- 他の節（0〜2・4〜7・困ったとき）は変えない
