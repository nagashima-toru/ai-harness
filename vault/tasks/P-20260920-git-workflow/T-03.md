# T-03 agent_write_guard.py に main 直接コミット拒否を追加する

## 目的
現在のブランチが `main` の時は、`agent_type` を問わず（メインエージェント含む）`git commit` を拒否し、main への直接コミットを構造で防ぐ。git リポジトリでない場合は fail-open（許可）にする。

## 入力
- `.claude/hooks/agent_write_guard.py`（改訂対象。既存の doing/review 判定の実装パターンを踏襲する）
- `scripts/smoke.sh`（`== agent_write_guard.py ==` セクションに新規ケースを追加）
- `vault/designs/D-001.md` の「## フェーズ5」

## 成果物
- `.claude/hooks/agent_write_guard.py`（main 直接コミット拒否ロジックの追加）
- `scripts/smoke.sh`（新規 smoke ケース2件の追加。同一コミットで対応してよい）

## 受け入れ基準
- 現在ブランチが `main` の時、`agent_type` を問わず Bash の `git commit` を deny する。確認：新規 smoke ケース「main ブランチで git commit → deny」が `ok`
- `main` 以外のブランチでは同じ `git commit` コマンドを（この判定では）拒否しない。確認：新規 smoke ケース「main 以外のブランチで git commit → allow」が `ok`
- 既存の `agent_write_guard.py` の smoke ケース（role別許可・doing/review 中の vault/rules/ 改ざん防止）がすべて引き続き通る
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

## 決定済み
- 判定対象は Bash の `git commit`（正規表現例：`r"\bgit\s+commit\b"`）。`agent_type` に関係なく適用する（既存の `doing/review` 中の `vault/rules/` 判定と同じ位置づけで、`ALLOWED` の role 判定より前に置いてよい）
- 現在ブランチの取得は `subprocess.run(["git", "rev-parse", "--abbrev-ref", "HEAD"], cwd=root, capture_output=True, text=True)` を使う。`returncode != 0`（非 git リポジトリ・HEAD が無い等）なら fail-open（この判定は素通りし、後続の判定に進む）
- ブランチ名が `main` の時だけ deny する。deny 理由には「main への直接コミットはできません」等、対象コマンドと理由がわかる文言を入れる
- smoke ケースの作り方：`TMP` 内で `git init -q && git config user.email t@example.com && git config user.name t && git commit -q --allow-empty -m init` として git リポジトリを用意する。1件目はデフォルトブランチ名を `main` にして（`git init -q -b main` 等）検証、2件目は `git checkout -q -b work/p-test` に切り替えてから検証する
- 既存の smoke ケース（`TMP` に git を初期化しないまま実行しているもの）が今まで通り allow のままであることが「非 git リポジトリは fail-open」の確認を兼ねる。新たに非 git 用のケースを追加する必要はない
- 既存の deny/allow 判定（role別の書き込み制限、`vault/rules/` 改ざん防止と `HARNESS_ALLOW_RULES_WRITE`）は変更しない
