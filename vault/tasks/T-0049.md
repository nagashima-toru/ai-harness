# T-0049 `/plan` にブランチ作成を追加し `planner.md` を新ID方式に直す

## 目的
`.claude/skills/plan/SKILL.md` を、ゴール入力時に計画 ID の決定とブランチ作成
（`work/<計画IDの英小文字>`）まで行う形に直す。承認は計画票 frontmatter の `status` を
`approved` にするだけにし、`vault/todo.md` への登録手順を削除する。`.claude/agents/planner.md` の
ID 採番・出力先の記述を、`P-YYYYMMDD-<slug>` と計画スコープの `T-01`〜、出力先
`vault/plans/<計画ID>.md`・`vault/tasks/<計画ID>/T-01.md` に直す。

## 入力
- `.claude/skills/plan/SKILL.md`（現行）
- `.claude/agents/planner.md`（現行）
- `docs/vault-spec.md` 1〜5節（ディレクトリ／状態／ID・ファイル名・ブランチ名／計画票の形式／タス
  ク票）
- `vault/designs/D-001.md`「## 決定事項」「### 新しいディレクトリ構造」「## フェーズ3」の決定済み
  （ブランチ作成は `/plan` が行う、承認引数は計画 ID、`/plan` は planner サブエージェントを呼ぶ構
  成を変えない）
- `vault/templates/plan.md`・`vault/templates/task.md`（新形式。既に更新済み）

## 成果物
- `.claude/skills/plan/SKILL.md`
- `.claude/agents/planner.md`

## 受け入れ基準
- `.claude/skills/plan/SKILL.md` に、計画 ID の決定（`P-<TZ=Asia/Tokyo date '+%Y%m%d'>-<slug>`
  形式、採番は不要）と、現在のブランチが `main` であることを確認した上での
  `git checkout -b work/<計画IDの英小文字>` の手順がある。確認：`grep -c 'work/' .claude/skills/plan/SKILL.md` が1以上
- 承認手順が計画票 frontmatter の `status` を `approved` にするだけになり、`vault/todo.md` への登
  録手順が消えている。確認：`grep -c 'todo.md' .claude/skills/plan/SKILL.md` が0
- `.claude/agents/planner.md` の「読むもの」「手順」から、`vault/todo.md`・`vault/tasks/` 全体・
  `vault/archive/` を既存 ID の最大値の参照先とする記述が消え、計画 ID は `P-YYYYMMDD-<slug>`
  （採番不要）、タスク ID は計画スコープの `T-01`〜、出力先は `vault/plans/<計画ID>.md`・
  `vault/tasks/<計画ID>/T-01.md` になっている。確認：`grep -c 'todo.md' .claude/agents/planner.md` が0
- タスク票の6見出し（目的／入力／成果物／受け入れ基準／決定済み／進捗）と、粒度の基準（受け入れ基
  準3〜7行・成果物1つ・1計画5〜7タスクまで）は変更しないことが明記されている
- `/plan approve <計画ID>` の形で承認を受け付けることが明記されている（引数が計画 ID である点は
  変えない）

## 決定済み
- 計画 ID の決定は `/plan` スキル（メインエージェント）が行う。日付は
  `TZ=Asia/Tokyo date '+%Y%m%d'` で取る。スラッグはゴールの内容から英小文字・ハイフン区切りで
  人が読める形を選ぶ（自動生成アルゴリズムは規定しない。人に確認してから決めてもよい）
- ブランチ作成は現在のブランチが `main` であることを確認してから行う。`main` でなければブランチを
  切らずに「`main` に戻ってから `/plan` を実行してください」と伝えて止まる（既存の作業ブランチに
  別の計画を重ねる運用は今回入れない）
- 計画 ID・ブランチ名を先に決めてから planner サブエージェントを呼ぶ。呼び出し prompt にはゴールと
  決定済みの計画 ID を渡し、planner はその ID をそのまま使ってファイルを書く（ID の衝突判定・採番
  は planner 側で行わない）
- `planner.md` の「禁止」節（`vault/plans/`・`vault/tasks/` 以外への書き込み禁止、`status` を
  `approved` にしない、ゴールを広げない）は変更しない
- git worktree の自動化はしない（`vault/designs/D-001.md`「今回やらないこと」）。`/plan` は通常の
  `git checkout -b` でブランチを作るだけでよい
- `README.md`・`docs/runbook.md` など他ドキュメントの一括修正はこのタスクの範囲外（次フェーズで行
  う）

## 進捗
- 読んだルール: roles.md, creator.md
- `.claude/skills/plan/SKILL.md` を全面書き換え。手順Aに計画 ID の決定（`P-<日付>-<slug>`、採番
  不要）、`main` 確認（違えば止まる）、`git checkout -b work/<計画IDの英小文字>`、planner 呼び出し
  時に計画 ID を渡す、の4手順を追加。手順Bを frontmatter の `status` を `approved` にするだけに
  簡略化し、`vault/todo.md` への登録手順（旧2〜4）を削除。frontmatter の `description`／
  `argument-hint` も新方式に更新
- `.claude/agents/planner.md`：「読むもの」から `vault/todo.md`・`vault/tasks/` 全体・
  `vault/archive/`（ID の最大値参照）を削除し、`vault/plans/` の重複確認に絞った。「入力」に
  「`/plan` スキルが決めた計画 ID」を追加。「手順」を「渡された計画 ID をそのまま使う（採番しない）」
  「`vault/plans/<計画ID>.md` に書く」「`vault/tasks/<計画ID>/T-01.md` に書く（計画スコープの連番）」
  「計画票のタスク表に6列で書く」に書き換えた
- 「粒度の基準」内の run-queue 不変検査の注意書きも計画票ベース（`vault/log/<計画ID>.md`・
  `vault/tasks/<計画ID>/T-01.md`）に更新。旧方式の失敗例（T-0002）は文字列 `vault/todo.md` を含め
  ずに言い換えた（基準3の `grep -c 'todo.md'` が厳密に0を要求するため、歴史的言及も含めて消した）
- 「タスク票の6見出し」「粒度の基準（3〜7行・成果物1つ・1計画5〜7タスク）」は変更していない
  （既存の記述をそのまま残した）
- 受け入れ基準の確認コマンドを実行し、5件すべて通した
  - `grep -c 'work/' plan/SKILL.md`=1 / `grep -c 'todo.md' plan/SKILL.md`=0
  - `grep -c 'todo.md' planner.md`=0
  - タスク票6見出し・3〜7行・成果物1つ・5〜7タスクの4文言がいずれも1以上
  - `/plan approve <計画ID>` の形が SKILL.md に明記されている
- コードは触っていないが念のため `bash scripts/smoke.sh | tail -1` を実行 → `smoke: pass=95 fail=0`
  （影響なし）
