# T-01 smoke に docs/guide.md の参照切れ・項目の形・節の実在の検査を足す

## 目的
T-02 で作る `docs/guide.md`（やりたいこと別の入口）のリンク切れと項目の形の崩れを、`scripts/smoke.sh` で機械的に止められるようにする。`docs/guide.md` を `(ref-1)` の対象に足し、「詳しく」で挙げた節名がリンク先の文書の見出しに実在するかを確かめる検査を足す。

## 入力
- `scripts/smoke.sh` の「主な文書の参照切れの検査」（`refcheck()`）と「scripts/・.claude/ の HARNESS_* と docs/configuration.md の表の一致検査」（`envcheck()`）、その後の `(ref-1)`〜`(ref-5)`・`(envref-1)`・`(envref-2)` のケース
- `.claude/agents/planner.md` の「やらないこと」節の `(ref-1)` の項目（refcheck が見る文書の列挙）
- `vault/designs/D-20261011-user-guide.md` のフェーズ2
- 本票の「決定済み」（guide.md の書式）

## 成果物
- `scripts/smoke.sh`（主な成果物。refcheck の対象に guide.md を足し、guidecheck とケースを足す）
- `.claude/agents/planner.md`（`(ref-1)` の項目の文書の列挙に `docs/guide.md` を足す1か所だけ）

## 決定済み
- refcheck の対象：`docs += [...]` の列の末尾（`"docs/configuration.md"` の後）に `"docs/guide.md"` を足す。`(ref-6)` は `(ref-5)` と同じ形のフィクスチャ（`$RC/e/docs/guide.md` に存在しないパスを1つ書き、`docs/guide.md:1: <そのパス>` が出ることを確かめる）。ケース名は「(ref-6) docs/guide.md の存在しないパスも見つける」
- guidecheck は `guidecheck() { # $1=ルート }` として refcheck・envcheck と同じく `python3 - "$1" <<'PY'` の形で書き、envcheck の定義の後に置く。`<ルート>/docs/guide.md` が無ければ何も出さずに終わる
- guide.md の書式（T-02 がこの書式で書く。guidecheck はこれを検査する）：
  - 各項目は `## <やりたいこと>` の見出しで始まり、次の `## ` の行か末尾までがその項目
  - 項目の中に `すること：` で始まる行がある（その後ろにコマンドや設定の最小例のコードブロックを置く）
  - 項目の中に `詳しく：` で始まる行が1行あり、その行にリンクが1つ以上ある。リンクの形は ``[`docs/<ファイル>.md`](<ファイル>.md) の「<節名>」``（節名は、リンク先の文書の見出し行から先頭の `#` と空白を除いた文字列そのまま）。同じ文書の2つの節を挙げる時はリンクを2つ書き、`・` で区切る
- guidecheck の検査と出力（1件1行。この順で出す）：
  1. 見出しの順に、`すること：` で始まる行が無い項目は `docs/guide.md: <見出しの文字列（## を除く）>: すること：が無い`、`詳しく：` で始まる行が無い項目は `docs/guide.md: <見出し>: 詳しく：が無い`、`詳しく：` の行に上のリンクの形が1つも無い項目は `docs/guide.md: <見出し>: 詳しく：にリンクが無い`
  2. ファイル全体の行の順に、正規表現 ``\[`(docs/[^`]+\.md)`\]\([^)]*\) の「([^」]+)」`` に当たる各リンクについて、`<ルート>/<パス>` が無いか、そのファイルに `^#{1,6} <節名>\s*$` に当たる行が無ければ `docs/guide.md:<行番号>: <パス> 「<節名>」`
- `(guide-1)` は `expect_eq "(guide-1) docs/guide.md の各項目に すること・詳しく があり、詳しく の節がリンク先に実在する" "" "$(guidecheck "$ROOT")"`
- `(guide-2)` はフィクスチャ（`$TMP` の下。既存の `$RC` と同じ置き方）に、`## 1. A` の見出しを持つ `docs/runbook.md` と、次の3項目を持つ `docs/guide.md` を作る：正しい項目（すること：と、「1. A」へのリンクのある詳しく：）、すること：が無く詳しく：のリンク先の節が実在しない項目（例：「9. 無い」）、すること：はあるが詳しく：にリンクが無い項目。期待値は上の書式どおりの3行（構造の指摘2行→リンクの指摘1行の順）。ケース名は「(guide-2) 項目の形の崩れと実在しない節を見つけ、正しい項目は指摘しない」
- 新しいケースは `(envref-2)` の直後に置く
- `.claude/agents/planner.md` は、`(ref-1)` の項目の括弧内の列挙の `` `docs/configuration.md` `` の後に `` ・`docs/guide.md` `` を足すだけにする。ほかの文言は変えない
- `scripts/install.sh` は変えない（guide.md は導入先に配らない。設計文書の決定事項）。導入先では guide.md が無いので guidecheck は何も出さない
- smoke の一時ファイルは既存の `$TMP` の下に作り、`rm -rf` を足さない
