# T-03 README・runbook・planner 定義・run スキルの旧形式の設計文書 ID を直す

## 目的
設計文書の ID を `D-<YYYYMMDD>-<スラッグ>`（ブランチ `design/d-<YYYYMMDD>-<スラッグ>`）に変えるのに合わせ、仕様と `/design` スキル以外で旧形式（`D-xxx.md`・`design/d-xxx`）を書いている文書を直す。

## 入力
- `README.md` の30行目付近（`/design` の行の `vault/designs/D-xxx.md`）
- `docs/runbook.md` の11行目付近（`vault/designs/D-xxx.md`）
- `.claude/agents/planner.md` の「人 → planner」節（`vault/designs/D-xxx.md`）
- `.claude/skills/run/SKILL.md` の150行目付近（`design/d-xxx` など）

## 成果物
- `README.md`（1か所）
- `docs/runbook.md`（1か所）
- `.claude/agents/planner.md`（1か所）
- `.claude/skills/run/SKILL.md`（1か所）
- 主な成果物は「旧形式の設計文書 ID の置き換え」という1つの変更で、上の4ファイルの1か所ずつに限る

## 受け入れ基準
- 3つの文書の設計文書のパスが新しい形式になっている（`grep -nF 'vault/designs/D-<YYYYMMDD>-<スラッグ>.md' README.md docs/runbook.md .claude/agents/planner.md` が、3ファイルのそれぞれについて1行以上出す）
- run スキルのブランチの例が新しい形式になっている（`grep -nF 'design/d-<YYYYMMDD>-<スラッグ>' .claude/skills/run/SKILL.md` が1行出す）
- 旧形式の記述が残っていない（`grep -nE 'D-xxx|d-xxx|vault/designs/D-[0-9]{3}|design/d-[0-9]{3}' README.md docs/runbook.md .claude/agents/planner.md .claude/skills/run/SKILL.md` が何も出さない）
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<N> fail=0` を出す（run スキルの記述の検査 (run-skill-1〜5) と参照切れ検査 (ref-1) を含む）

## 決定済み
- D-016 の決定事項（転記）：設計文書の ID は `D-<YYYYMMDD>-<スラッグ>`、ブランチは `design/d-<YYYYMMDD>-<スラッグ>`。旧方式（`D-` と3桁の番号）の最後は D-016
- 置き換えは字句どおり：`vault/designs/D-xxx.md` → `vault/designs/D-<YYYYMMDD>-<スラッグ>.md`、`design/d-xxx` → `design/d-<YYYYMMDD>-<スラッグ>`。文の意味は変えない
- `README.md` の `designs/（設計文書）`・`docs/install.md` のディレクトリ名の列挙は ID の形式に依存しないので触らない（成果物にも入れない）
- docs に残る過去の `D-0xx` への言及（例：runbook の「D-015 フェーズ2 で廃止」）は書き換えない（D-016 の決定：読み物として残す）
- 参照切れ検査（smoke の refcheck）は `<` を含むパスを対象外にするので、新しい形式のパスは検査に引っかからない。smoke の除外リストの `vault/designs/D-xxx.md` は T-04 が外すので、このタスクでは smoke を触らない
- `.claude/skills/run/SKILL.md` で変えるのは手順7の中の `design/d-xxx` の1語だけ。手順7のほかの文言と順（smoke の (run-skill-1)・(run-skill-4)・(run-skill-5) が見ている）は変えない
- `.claude/skills/design/SKILL.md`・`docs/vault-spec.md` は T-02・T-01 が直すので触らない
