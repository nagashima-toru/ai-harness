# T-01 agent_write_guard.py に worktree 委譲ロジックを追加する

## 目的
`.claude/hooks/agent_write_guard.py` に、PreToolUse 呼び出しの `payload["cwd"]` が git worktree を指している場合はそのルート配下の `.claude/hooks/agent_write_guard.py` へ委譲する（委譲先の stdout をそのまま自分の stdout として出し `exit 0` する）ロジックを追加する。委譲先が存在しない・実行が失敗/タイムアウトした場合はフェイルオープンでメインリポジトリ側の既存ロジックにフォールバックし、委譲は1段までとして環境変数で二重委譲を防止する（issue #56 対応、`vault/designs/D-008.md` フェーズ1）。

## 入力
- `vault/designs/D-008.md`（「決定事項」表と「フェーズ1」節。今回のゴール文・受け入れ基準・決定済みの一次情報）
- `.claude/hooks/agent_write_guard.py`（変更対象。`git_toplevel()`・`resolve_root()`・`main()` が委譲判定を組み込む箇所の参考になる）
- `scripts/smoke.sh`（`== agent_write_guard.py ==` セクション。202〜222行目の `git worktree add` を使った一時 worktree テスト（(worktree) / (worktree nested) ケース）が、今回追加するテストケースの型として流用できる）
- `.claude/settings.json`（`hooks.PreToolUse` のタイムアウトが30秒であることの確認。委譲の `subprocess.run` タイムアウトはこれより短くする）

## 成果物
- `.claude/hooks/agent_write_guard.py` の修正（委譲ロジックの追加）と、`scripts/smoke.sh` への回帰・新規テストケース追加（1PR分の関連する2ファイル変更）

- 二重委譲防止に環境変数 `_HOOK_DELEGATED` を使い、委譲先呼び出し前にセットする箇所と、委譲するかどうかの判定でこれを参照する箇所の両方がある。確認コマンド: `grep -c "_HOOK_DELEGATED" .claude/hooks/agent_write_guard.py` の出力が2以上
- 委譲先呼び出しの `subprocess.run` のタイムアウトが20秒（`timeout=20`）に固定されている。確認コマンド: `grep -n "timeout=20" .claude/hooks/agent_write_guard.py` の出力が1行以上
- worktree 委譲・委譲失敗時のフェイルオープン・二重委譲防止の3シナリオを検証する `scripts/smoke.sh` のテストケースが、テスト名の先頭に `(delegate)` を付けて追加されている。確認コマンド: `grep -c "(delegate)" scripts/smoke.sh` の出力が3以上

## 決定済み
- 委譲するかどうかの判定は `payload["cwd"]` から `git rev-parse --show-toplevel`（既存の `git_toplevel()` 関数を流用してよい）で求めた worktree ルートだけで行う。`resolve_root()`（Write/Edit の対象 `file_path` 起点のルート解決）はこの判定に使わない・変更しない
- 「自リポジトリのルート」との比較対象は、このスクリプト自身のファイルパス（`os.path.abspath(__file__)`）から `git_toplevel()` で求めたルート、または `CLAUDE_PROJECT_DIR` のいずれかを使ってよい（どちらでも smoke.sh のテストが通れば実装は自由）。`payload["cwd"]` から求めたルートがこれと異なり、かつそのルート配下に `.claude/hooks/agent_write_guard.py` が存在する場合にのみ委譲する
- 委譲は `_HOOK_DELEGATED=1` を委譲先プロセスの環境変数にセットして呼び出す。呼び出し前に自分自身の環境で既に `_HOOK_DELEGATED` が設定されている場合は委譲せず、必ずメインリポジトリ側のローカル判定にフォールバックする（1段まで）
- 委譲先には同じ payload を `json.dumps()` で再シリアライズし、標準入力として渡す（自分が標準入力を一度読み切っているため、委譲先に生の stdin を中継することはできない）
- 委譲が成功した場合は委譲先の stdout をそのまま自分の stdout として `print` し、`exit 0` する（委譲先の判定をそのまま採用する。自分でさらに判定を続けない）
- 委譲先が存在しない・`subprocess.run` が例外を送出する・タイムアウトする・非0で終了する、のいずれの場合もフェイルオープンとし、通常どおりメインリポジトリ側のローカル判定（この関数を呼ばなかった場合の既存フロー）に進む
- 委譲ロジックはこのファイル内に閉じて実装する（他ファイルへの `import` はしない。`stop_gate.py` が既存の判定ロジックをコピーして使う流儀と同じ）
- 既存の判定ロジック（`vault/rules/` 改ざん防止、`main` 直接コミット拒否、`ALLOWED`/`DENIED_FOR_CREATOR` の書き込み先制限）はメインリポジトリ側・委譲先側のどちらのコードも変更しない
- `scripts/smoke.sh` の新規テストケースは、202〜222行目の `git worktree add`/`git worktree remove --force`/`rm -rf` を使う既存パターン（一時ディレクトリの片付けを含む）をそのまま踏襲してよい。委譲先の判定を変える確認には、一時 worktree 内の `.claude/hooks/agent_write_guard.py` を「常に allow を返すだけの短いスクリプト」に差し替えて置く方法を使う
- コミットは行わない（受け入れ基準にコミットの指示が無いため）。`main` 上で作業する場合は既存のブランチ運用（`vault/rules/common/git.md`）に従うこと
- （2026-09-26 人の判断・blocked 解消）受け入れ基準5「`bash scripts/smoke.sh` が全件PASSし rc=0」は、今回の変更（`delegate_to_worktree` 追加分）と無関係な既存の環境依存の失敗（`(worktree)`・`(worktree nested)`・discard_worktree.sh の `(a)`、および `.claude/worktrees/` 配下に未削除の worktree が残っていることに起因する「参照される scripts」チェックのフレーキーな失敗）をスコープ外として無視してよい。判定は「新規追加した `(delegate)` の3ケースがすべて `ok` であること」「既存の失敗の件数・内容が変更前 HEAD 時点から悪化していないこと（新たな失敗が増えていないこと）」の2点で行う。rc=0・fail=0 の字義通りの達成は求めない
