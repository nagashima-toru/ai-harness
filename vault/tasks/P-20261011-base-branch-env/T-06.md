# T-06 smoke.sh に既定 main と develop のケースを足す

## 目的
`scripts/smoke.sh` に、`HARNESS_BASE_BRANCH=develop`（別名ベース）と既定（未設定＝`main`）の両方で、`scripts/vcs_finish.sh`・`.claude/hooks/agent_write_guard.py` (b)・`scripts/purge_plan.sh --merged` が期待どおり動くことを確かめるケースを足す。あわせて、ゴール全体で固定の `main` の旧い記述が残っていないことを確かめる。

## 入力
- `scripts/smoke.sh`（`== agent_write_guard.py ==`・`== purge_plan.sh --merged ==`・`== vcs_finish.sh ==` の節）
- T-01〜T-05 の成果物（`scripts/vcs_finish.sh`・`.claude/hooks/agent_write_guard.py`・`scripts/purge_plan.sh`・スキルと docs。どれもこのタスクでは変えない）
- `vault/designs/D-20261010-base-branch-config.md`（「フェーズ1」の「決定済み」）

## 成果物
- `scripts/smoke.sh`（1ファイル）

## 受け入れ基準
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- 足したケースが9件ともある：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (base-[1-9]) '` が `9`
- 呼び出し元の環境の値に左右されない：`env HARNESS_BASE_BRANCH=develop bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わり、`grep -c '^unset HARNESS_BASE_BRANCH$' scripts/smoke.sh` が `1`
- 既定のケースの期待値が残っている：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (vf-rest-[123]) '` が `3`
- ゴールの範囲で固定の `main` の旧い記述が残っていない：`grep -rnE 'base=main|main 固定|"main:vault/plans|ブランチが `main` であることを確認|base（`main`）|^- `main` に直接コミットしない' scripts/vcs_finish.sh scripts/purge_plan.sh .claude/ docs/` の出力が空

## 決定済み
- smoke の先頭付近（`set` や `ROOT=` の定義の後、最初のケースより前）に `unset HARNESS_BASE_BRANCH` の1行を足す（行頭から、この字句だけの行）。既存のケースはすべて未設定（＝`main`）の前提で動き、足すケースは必要な時だけ `env HARNESS_BASE_BRANCH=…` か `HARNESS_BASE_BRANCH=… <コマンド>` でその呼び出しにだけ渡す
- 足すケースの名前と内容は次の9件に固定する（名前は `(base-<番号>) ` で始め、`ok`/`NG` の出力は既存の `expect_eq`・`expect_guard`・`vf_rest_check` などの書式にそろえる）：
  - `(base-1)` vcs_finish・github・本文ファイルとタイトル・`HARNESS_BASE_BRANCH=develop` → 偽 `gh` の記録が vf-rest-1 の期待値の `base=main` を `base=develop` にしたものと一致
  - `(base-2)` vcs_finish・github・計画無し・引数なし・`HARNESS_BASE_BRANCH=' develop '`（前後に空白）→ 記録に `base=develop` の行がある
  - `(base-3)` vcs_finish・`HARNESS_VCS_HOST=none`・`HARNESS_BASE_BRANCH=develop` → 標準出力に `の内容を develop に取り込むには` がある
  - `(base-4)` フック・develop ブランチ上・`HARNESS_BASE_BRANCH=develop` で `git commit` → 拒否され、理由に `develop への直接コミットはできません` を含む
  - `(base-5)` フック・main ブランチ上・`HARNESS_BASE_BRANCH=develop` で `git commit` → 拒否
  - `(base-6)` フック・`work/p-test` ブランチ上・`HARNESS_BASE_BRANCH=develop` で `git commit` → 許可
  - `(base-7)` フック・develop ブランチ上・未設定で `git commit` → 許可（未設定なら main だけを拒否する）
  - `(base-8)` purge_plan・`HARNESS_BASE_BRANCH=develop` で `--merged --list` → develop の版で判定した計画 ID だけを出す
  - `(base-9)` purge_plan・未設定で `--merged --list` → main の版で判定した計画 ID だけを出す
- vcs_finish のケースは既存の偽 `gh`（`VF_BIN`・`VF_REC`。引数を1行ずつ記録する）と既存のリポジトリ（`VF_REPO` など）を使い、`== vcs_finish.sh ==` 節の vf-rest のケースの後に置く。既存ケース（vf-rest-1〜3 の `base=main` を含む）の期待値は変えない
- フックのケースは `smoke_tmpdir` で一時リポジトリを作り（`git init -q -b main`、空コミット、`develop` と `work/p-test` のブランチを作る）、`git -C <dir> checkout -q <ブランチ>` で切り替えて、既存の (guard3-b) と同じく payload に `cwd` を入れず `CLAUDE_PROJECT_DIR=<dir>` を付けて `$GUARD_HOOK` を呼ぶ。理由の部分文字列を見る (base-4) は、4引数版の `expect_guard`（smoke の 361 行付近で再定義されるもの）の後に置くか、出力を直接 grep する
- purge_plan のケースの一時リポジトリは `$TMP` の下に作り（既存の `pm_make` と同じ置き場所・`pm_plan` の関数を使ってよい）、次の形にする：作業ツリー（ブランチ `work/p-20990209-cur`）には計画 A（`P-20990201-basea`）と計画 B（`P-20990202-baseb`）の両方が `status: done`・全行 done。`main` の版は B が `status: done` で A は無い。`develop` の版は A が `status: done` で B は `status: approved`。(base-8) の期待値は `P-20990201-basea` の1行、(base-9) は `P-20990202-baseb` の1行。`--merged --apply` はこのケースでは使わない
- 一時ディレクトリの後片付けは、既存の smoke と同じ書き方（smoke 自身の中で行うもの）にそろえる。確認コマンドとしての削除は求めない
- 受け入れ基準の最後の grep から `scripts/smoke.sh` を除くのは、既定（main）のケースの期待値として `base=main` を残すため（設計の決定済み「既存ケースの期待値は変えない」）。`README.md` を除くのは、図の `orchestrator (main)` がメインセッションの意味で対象外のため
- `scripts/vcs_finish.sh`・`.claude/hooks/agent_write_guard.py`・`scripts/purge_plan.sh`・スキル・docs はこのタスクでは変えない。ケースが通らない原因がそれらの側にある時は、直さずに blocked にして理由を書く
