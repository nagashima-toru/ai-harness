## 決定済み
- 基準1・2の grep のため、手順7に `python3 scripts/verdict_notes.py <計画ID>` と `env HARNESS_PR_BODY_FILE=<本文ファイル> HARNESS_PR_TITLE="<計画ID>: <ゴールの1行目>" bash scripts/vcs_finish.sh` の2つの文字列をこのとおりに書く（バッククォートで囲む）
- 手順7の流れ（全タスクが done になった時）：
  1. 計画票の frontmatter の `status` を `done` にする（今どおり Edit。コミットの扱いも今の記述のまま）
  2. `python3 scripts/pr_body.py <計画ID>` と `python3 scripts/verdict_notes.py <計画ID>` を実行し、出力を読む
  3. 本文ファイルを Write ツールで一時ファイル（例：`/tmp/<計画ID>-pr-body.md`。手順3の質問ファイルと同じ書き方）に書く。中身は計画 ID の1行、`pr_body.py` の出力（タスク一覧。計画 ID・id・title・commit・verdict の表）、`## verifier の指摘` の見出しと `verdict_notes.py` の出力。出力は言い換えずに写す
  4. `env HARNESS_PR_BODY_FILE=<本文ファイル> HARNESS_PR_TITLE="<計画ID>: <ゴールの1行目>" bash scripts/vcs_finish.sh` を実行する（`env` で始めるのは許可リストの `Bash(env *)` で通すため。タイトルは今の既定と同じ形にする）
  5. 完了報告に `verdict_notes.py` の出力をそのまま含める（「指摘なし」の時も1行で含める）
- `vcs_finish.sh` の終了コードの扱い（0 で完了・`none` の案内をそのまま報告・127 の時の MCP の代替）は今の記述を残す。MCP の代替では、本文に本文ファイルの中身、タイトルに `HARNESS_PR_TITLE` の値を引き継ぐと書き足す
- 引数なしの `bash scripts/vcs_finish.sh`（`HARNESS_PR_BODY_FILE` 無し）の既定の動き（`pr_body.py` の本文・`--fill`）の説明は、`/design` などが使う経路として短く残してよい
- `verdict_notes.py` が終了コード0以外で終わった時は、PR は作り、本文の「verifier の指摘」節と完了報告にその旨（標準エラーの内容）を書く（指摘の一覧が無いことで PR 作成を止めない）
- 手順7以外の節（手順0〜6・8・早見表・注意）と見出しの行は変えない。手順8の「`scripts/vcs_finish.sh` 呼び出し手順自体は変更しない」の文も変えない
- `vault/rules/`・`.claude/agents/` は変えない。`docs/` は変えない（T-05 で行う）
