# T-07 README.md の使い方の表と仕組みの図から /plan approve を外し、自動承認の流れにする

## 目的
`README.md` の `/plan` の説明を、承認待ちの無い流れ（D-015 フェーズ2）に合わせる。計画票の「人への質問」2の回答で追加したタスク。

## 入力
- `vault/designs/D-015.md` の「フェーズ2」の節
- `README.md`（「## 使い方」の表の `/plan <ゴール>` の行。計画作成時は31行目。「## 仕組み」の図の `/plan approve <計画ID>` と `計画票の status を approved に` と `/run` の行。計画作成時は62〜64行目）

## 成果物
- `README.md`（1ファイル）

## 受け入れ基準
- `/plan approve` が残っていない。確認：`grep -c "plan approve" README.md` の出力が `0`
- 使い方の表の `/plan` の行が自動承認と `/run` の続行を説明している。確認：`grep -c -F '粒度の確認を通ったら approved にしてコミットし、続けて `/run` を実行する' README.md` の出力が `1`
- 仕組みの図に自動承認の行がある。確認：`grep -c "approved に（自動）" README.md` の出力が `1`
- 見出しの数は変わらない。確認：`grep -c "^## " README.md` の出力が `7`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む（参照切れの検査を含む）

## 決定済み
- 使い方の表の `/plan <ゴール>` の行の説明は次にする：「計画 ID を決めてブランチ（`work/<計画ID>`）を切り、planner がタスクに分割して draft を作る。粒度の確認を通ったら approved にしてコミットし、続けて `/run` を実行する（planner の質問があれば、解消するまで止まる）」
- 仕組みの図は、`│ /plan approve <計画ID>  │` の行と `├───…▶ 計画票の status を approved に` の行と `│ /run` の行の3行を、オーケストレーター側の次の2行にする：`│                        │ 粒度の確認後、status を approved に（自動）` と `│                        │ 続けて /run の手順を実行`。その次の `├───…▶ todo→doing → creator …` の行は先頭の `├──────────────────────▶` を `│                        │ ` に変える（人の操作ではなくなるため）。右側の罫線（`│`）は前後の行に揃える
- 「## 使い方」の `/run` の行・`run_unattended.py` の行、「## 仕組み」の図のそのほかの行、図の下の段落は変えない
- 「## 構成」以降や `vault/rules/` の説明（提案ファイル方式の記述など）は変えない（D-015 フェーズ3 以降で扱う）
