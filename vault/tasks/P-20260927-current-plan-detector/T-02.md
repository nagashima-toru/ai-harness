# T-02 smoke.sh に current_plan.sh のテストを追加する

## 目的
`scripts/smoke.sh` に、T-01 で作った `scripts/current_plan.sh` の動作を検証する新セクションを追加する。

## 入力
- T-01 の成果物 `scripts/current_plan.sh`（出力仕様：frontmatter の `status` が `approved` の計画票の id を1行1件、ファイル名順、id 無しはファイル名フォールバック、本文中の文字列は無視）
- `scripts/smoke.sh`：`expect_eq` 定義（484行目付近）、`make_plan` ヘルパー（14〜30行目）、`TMP` 変数（10行目）、既存セクションの区切り方（`echo "== ... =="`）

## 成果物
- `scripts/smoke.sh`

## 受け入れ基準
- 新セクション「== current_plan.sh ==」が追加され、ケース名の先頭に共通タグ `current_plan.sh:` を付けたケースが5件以上ある。確認：`bash scripts/smoke.sh > /tmp/P-20260927-current-plan-detector-T-02-out.txt` を実行した後、`grep -c 'current_plan.sh:' /tmp/P-20260927-current-plan-detector-T-02-out.txt` が5以上
- それら5件以上のケースに NG が無い。確認（直前のファイルを再利用）：`grep -E 'NG.*current_plan\.sh:' /tmp/P-20260927-current-plan-detector-T-02-out.txt` の出力が空
- スイート全体が pass する。確認（同ファイル）：`tail -1 /tmp/P-20260927-current-plan-detector-T-02-out.txt` が `fail=0` を含む
- 5件のケースは少なくとも「id 無し時はファイル名フォールバック」「approved が2件以上でファイル名順に複数行」の2観点を含む。確認：`grep -cE 'フォールバック|ファイル名順' /tmp/P-20260927-current-plan-detector-T-02-out.txt` が2以上

## 決定済み
- 新セクションは `expect_eq` の定義（484行目）より後、「== uninstall.sh ==」節（736行目）の直前に置く（既存の追記で行番号がずれても、この前後関係だけ守ればよい）
- 変数 `CURRENT_PLAN_SH="$ROOT/scripts/current_plan.sh"` を他の `*_SH`/`*_HOOK` 変数と同様の場所に追加してよい
- ケース名は必ず `current_plan.sh: ` で始める（例：`current_plan.sh: (a) approved 1件 → id が1行`）
- 各ケースの前に `rm -rf "$TMP/vault/plans"; mkdir -p "$TMP/vault/plans"` でリセットしてよい（`plan_guard.py` セクションの既存パターンと同じ）
- 用意するケース（すべて `expect_eq` で判定する）
  - 「(a) approved 1件 → id が1行」：既存の `make_plan "P-CUR" "approved"` を再利用してよい（タスク表のデータ行は `current_plan.sh` の判定に無関係なので省略可）。`CLAUDE_PROJECT_DIR="$TMP" bash "$CURRENT_PLAN_SH"` の結果が `P-CUR` と一致することを確認する
  - 「(b) 本文中の status: approved は無視される」：frontmatter の `status` が `done` で、本文に `status: approved` という行を含むファイルを直接書き、出力が空になることを確認する
  - 「(c) id 無し → ファイル名フォールバック」：frontmatter に `id:` を書かず `status: approved` のファイル（例：ファイル名 `noidplan.md`）を直接書き、出力が `noidplan` になることを確認する
  - 「(d) approved が0件 → 出力なし」：`vault/plans` を空にしてから実行し、出力が空文字列になることを確認する
  - 「(e) approved が2件以上 → ファイル名順に複数行」：id が異なる2ファイル（例：ファイル名 `p-aa.md` / id `P-CUR-AA`、ファイル名 `p-bb.md` / id `P-CUR-BB`、共に `status: approved`）を書き、出力が `P-CUR-AA` の行・改行・`P-CUR-BB` の行の順（`$(printf 'P-CUR-AA\nP-CUR-BB')` と一致）になることを確認する
- 確認コマンドはパイプ・`&&`・コマンド置換を含まない単純なコマンドに分解して1つずつ実行する（`vault/rules/planner/planner.md`）
- T-01 が `done`（`scripts/current_plan.sh` が存在し動作する状態）になってから着手する
