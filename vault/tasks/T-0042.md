# T-0042 `docs/vault-spec.md` の2・5・6・7節（状態／タスク票／verdict／ログ）を書き直す

## 目的
`docs/vault-spec.md` の「状態」「タスク票」「verdict.json」「ログ」の4節を、計画スコープの状態モデ
ルに合わせて更新する。5状態の遷移ルール自体は変えず、`doing` が計画内で常に1件であることの補記、
verdict の `task` 値の形式変更、ログのパス変更のみを行う。

## 入力
- `docs/vault-spec.md`（T-0041 が終わった時点のもの。現行の「## 2. 状態」「## 5. タスク票」「## 6.
  計画票」（T-0041 で消えている）「## 7. verdict.json」「## 8. ログ」に相当する範囲）
- `vault/designs/D-001.md`（「## 決定事項」「## フェーズ2」）
- `vault/tasks/T-0041.md`（先行タスクが固定した ID 体系・計画票の形式）

## 成果物
- `docs/vault-spec.md` のうち、状態／タスク票／verdict.json／ログの4節の書き直し（新章立てで「2.
  状態」「5. タスク票」「6. verdict.json」「7. ログ」に相当する範囲。他の節には触れない）

## 受け入れ基準
- 状態の節に「doing は常に1件（計画内で）」の趣旨の一文がある。確認：`grep -F '計画内で常に1件'
  docs/vault-spec.md` の出力が1行以上
- verdict.json の例の `task` フィールドが `<計画ID>/T-01` 形式になっている。確認：`grep -F
  '"task": "P-20260919-git-ops/T-01"' docs/vault-spec.md` の出力が1行以上
- verdict の attempt 照合の説明が「計画票のタスク表の attempt と一致させる」旨に更新されている。確
  認：`grep -F '計画票のタスク表の attempt' docs/vault-spec.md` の出力が1行以上
- ログの節でパスが `vault/log/<計画ID>.md` になっており、1行形式の例に計画スコープの短い ID
  （`T-01` 形式）が使われている。確認：`grep -F 'vault/log/<計画ID>.md' docs/vault-spec.md` と
  `grep -F 'T-01 doing→review attempt=1' docs/vault-spec.md` の出力がそれぞれ1行以上
- タスク票の節の6見出し（目的 / 入力 / 成果物 / 受け入れ基準 / 決定済み / 進捗）が残っている。確

  1行以上

## 決定済み
- 新しい章立て（全13節）は `vault/plans/P-020.md` の「分割方針」を正本とする。このタスクは新2節
  （状態）・新5節（タスク票）・新6節（verdict.json）・新7節（ログ）を担当し、他の節には触れない
- 状態の5つ（todo/doing/review/blocked/done）・遷移（todo→doing→review→(done|doing[attempt+1]|
  blocked)）・`attempt` の増分ルール・`HARNESS_MAX_ATTEMPTS` は意味を変えない。`doing`/`review`/
  `blocked`/`done` は「その計画のタスク表の中で」の話であることが分かるように一文を補うだけでよい
- タスク票の節（6見出し・受け入れ基準3〜7行）は内容を変えない。番号だけ新5節に振り直す
- verdict.json の形式（`task`/`attempt`/`result`/`checked_at`/`criteria`/`reasons` の6キー、
  `criteria` の各要素、`note` の必須・書式）は変えない。変えるのは `task` の値の例だけ（`T-0001` →
  `<計画ID>/T-01`、例として `P-20260919-git-ops/T-01` を使う）
- ログの1行形式はこれまでどおり `- YYYY-MM-DD HH:MM T-01 doing→review attempt=1 補足`。計画が
  ファイルパスで特定できるので、タスク ID は計画スコープの短い形（`T-01`）のままでよい（`<計画
  ID>/T-01` のように長く書き直す必要はない）
- 「9. 粒度の基準」「10. Stop フックの判定」「11. todo_guard フックの判定」（旧番号）の内容には触
  れない。次タスク（T-0043）が担当する
