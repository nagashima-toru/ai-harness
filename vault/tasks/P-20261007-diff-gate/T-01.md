# T-01 scripts/diff_gate.py を新設し、作業ブランチの差分を base の版のタスク票の「成果物」と照らし合わせる

## 目的
creator の作業ブランチの差分（`<base>..<branch>` のコミット済みの変更）が、base の版のタスク票の「成果物」に宣言されたファイルの範囲に収まっているかを確かめる `scripts/diff_gate.py` を作る（D-012 フェーズ3）。フェーズ4の `transition.py` から `check()` を import して使えるようにする。このフェーズでは run から呼ばない。

## 入力
- `vault/designs/D-012.md` の「決定事項」（差分ゲートの行）と「フェーズ3 差分ゲート diff_gate.py と「成果物」の記法」（ゴール文・受け入れ基準の候補・決定済み）
- `scripts/transition.py`（直近の作りの参考：先頭の docstring・`sys.dont_write_bytecode`・argparse・`git rev-parse --show-toplevel` での対象リポジトリの決め方・Python 3.9 互換の書き方）
- `docs/vault-spec.md` の5節（タスク票の6見出し）
- `vault/tasks/P-20261007-diff-gate/fixtures/try.sh`（確認用のフィクスチャ。使い方・preset・宣言の中身は先頭のコメント）

## 成果物
- `scripts/diff_gate.py`（新規の1ファイルだけ。ほかのファイルは変えない）

## 受け入れ基準
- 宣言どおりの変更・空の差分・未コミットの変更は違反にならない：`bash vault/tasks/P-20261007-diff-gate/fixtures/try.sh ok`・`try.sh empty`・`try.sh uncommitted` のどれも出力に `exit=0`・`check=` だけの行・`unchanged=yes` があり、stdout 節が空（`try.sh` は1行目と同じパス。以下同じ）
- 宣言外の変更とリネームを違反にする：`try.sh extra` の出力に `exit=1`・`check=docs/readme.md extra.txt` があり、stdout 節が `docs/readme.md: ` で始まる行と `extra.txt: ` で始まる行の2行だけ。`try.sh rename` の出力に `exit=1`・`check=scripts/bar.py` がある
- 自分のタスク票は「進捗」以外の節の変更を違反にし、宣言は base の版で読む：`try.sh criteria` と `try.sh head` の出力に `exit=1`・`check=vault/tasks/P-TEST/T-01.md`、`try.sh selfdecl` の出力に `exit=1`・`check=extra.txt vault/tasks/P-TEST/T-01.md`、`try.sh othertask` の出力に `exit=1`・`check=vault/tasks/P-TEST/T-02.md` がある
- 宣言があっても常に違反にする：`try.sh forbidden` の出力に `exit=1`・`check=vault/log/P-TEST.md vault/plans/P-TEST.md vault/rules/common/x.md vault/verdicts/P-TEST/T-01.json` があり、stdout 節が4行
- `.claude/` 配下は宣言があれば許し、無ければ違反にする：`try.sh hookundecl` の出力に `exit=1`・`check=.claude/hooks/y.py`、`try.sh hooks P-TEST T-02 main work/b` の出力に `exit=1`・`check=.claude/agents/creator.md .claude/hooks/x.py .claude/settings.json` がある（宣言ありの許可は1行目の `try.sh ok` で確かめる）
- 終了コード2：`try.sh newtask P-TEST T-03 main work/b`（base にタスク票が無い）と `try.sh ok P-TEST T-01 nosuch work/b`（git の失敗）の出力に `exit=2`・`check_error=GateError`・`unchanged=yes` があり、`try.sh ok P-TEST T-01 main`（引数の不足）の出力に `exit=2` がある
- 既存の smoke が変わらず通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=559 fail=0`

## 決定済み
- 呼び出しの形：`python3 scripts/diff_gate.py <計画ID> <id> <base> <branch>`。引数は argparse の位置引数4つで読み、不足・過剰・未知のオプションは argparse の既定どおり終了コード2
- 対象のリポジトリ：実行時のカレントディレクトリでの `git rev-parse --show-toplevel`（`transition.py` と同じ。スクリプトの置き場所ではない）。失敗したら終了コード2
- 関数：`check(root, plan_id, task_id, base, branch)` を定義し、違反を `[(パス, 理由), ...]`（タプルのリスト。順序は `git diff` の出力順）で返す。違反が無ければ空のリスト。次の時は例外 `GateError`（`diff_gate.py` に定義する `Exception` の派生クラス）を送出する：base か branch がコミットとして解決できない（`git rev-parse --verify --quiet <ref>^{commit}`）・base にタスク票が無い・git コマンドが失敗した。CLI（`main`）は `GateError` を捕まえて標準エラーに `[diff_gate] <理由>` を出し終了コード2
- import できる形にする：モジュールの読み込み時に引数を読んだり出力したり終了したりしない。CLI は `if __name__ == "__main__":` の下で `sys.exit(main())`。フェーズ4の `transition.py` がこの `check` を import して使う（このタスクでは `transition.py` は変えない）
- 変わったファイル：`git -C <root> -c core.quotePath=false diff --name-only --no-renames -z <base> <branch>` で取り、NUL で分けて空要素を捨てる（リネームは削除と追加の両方として扱う）。見るのはコミット済みの差分だけで、作業ツリーの未コミット分・未追跡ファイルは対象外
- タスク票は `git show <base>:vault/tasks/<計画ID>/<id>.md` で読む（UTF-8）。作業ツリーや branch 側の版を宣言の読み取りに使わない
- 宣言の読み方：
  - 行頭が `## ` の行を見出しとし、`rstrip()` した見出しが `## 成果物` の節（次の `## ` 見出しの前まで）にある、バッククォートで囲まれた文字列（正規表現 `` `([^`\n]+)` ``）をすべて候補にする。前後の空白は落とし、空になったものは捨てる
  - 末尾が `/` の候補は前方一致、それ以外は完全一致で照らし合わせる。`./` の除去などの正規化はしない
  - パスでない文字列（関数名など）が混じっても害は無いので、そのまま候補に入れる
- 判定の順（1つのパスに理由は1つ。最初に当たったものを使う）：
  1. `vault/plans/`・`vault/log/`・`vault/verdicts/`・`vault/rules/` のどれかで始まる → 違反。理由は `<その接頭辞> 配下は宣言があっても変更できない`（例：`vault/plans/ 配下は宣言があっても変更できない`）
  2. 自分のタスク票 `vault/tasks/<計画ID>/<id>.md` → 宣言の有無にかかわらず節で判定する。base と branch の版を `## ` 見出しで節に分け（最初の見出しより前の部分も1つの節）、`rstrip()` した見出しが `## 進捗` の節を除いた残りの (見出し, 本文) の並びが一致すれば許す。一致しない・branch 側で消えている時は違反。理由は `タスク票の「進捗」以外の節が変わっている`
  3. 宣言のどれかに一致する → 許す
  4. それ以外 → 違反。理由は `「成果物」に宣言されていない`
- `.claude/hooks/`・`.claude/settings.json`・`.claude/agents/` は特別扱いしない（3・4の通常の宣言の判定で、宣言があれば許し、無ければ違反になる）。他の計画・他のタスクのタスク票やフィクスチャも、宣言が無ければ4で違反
- 節の分割は `diff_gate.py` の中に書く（`_hooklib.py` には置かない・import もしない）
- 出力：違反1件につき標準出力に `<パス>: <理由>` を1行（`check` の戻り値の順）。違反が無ければ何も出さない
- 終了コード：0 違反なし／1 違反あり／2 引数の誤り・base にタスク票が無い・git コマンドが失敗した（対象リポジトリが git でない時を含む）
- リポジトリの状態を変えない（読むだけ。checkout・stash・index の変更をしない）
- ファイル先頭に使い方・判定・終了コードの docstring を書く。`sys.dont_write_bytecode = True` を入れる。標準ライブラリだけを使い、Python 3.9 で動く書き方にする（`match` 文や `X | Y` の型注釈は使わない）
- `install.sh` は `scripts/` 直下の `*.py` を自動で配るので変えない。`scripts/smoke.sh`（T-02）・`docs/vault-spec.md`（T-05）・`vault/templates/task.md`（T-03）・`.claude/agents/planner.md`（T-04）・`.claude/skills/run/SKILL.md`・`scripts/transition.py`・`.claude/hooks/` は変えない
- フィクスチャ `try.sh` は成果物ではない。変えない。`check=` の行はフィクスチャが `check()` を import して返したパスを空白でつないだもの、`check_error=` は送出された例外のクラス名
