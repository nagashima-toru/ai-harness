# T-01 smoke.sh に vault/rules/ パス文字列の誤検知の回帰ケースを足す

## 目的
issue #109 の誤検知（本文・引数に `vault/rules/` のパスがあるだけで拒否される）を直す前に、smoke.sh に回帰ケースを足す。誤検知が通るべき6件（直す前は NG）と、拒否されるべきものが拒否される9件（直す前から ok）を揃え、T-02・T-03 の受け入れ基準の物差しにする。

## 入力
- `scripts/smoke.sh`（189〜194行目の `run_guard`・`expect_guard`、403〜411行目の4引数版 `expect_guard`、461〜462行目の「(bash-parse-done) #87 の2例目 …」、503〜523行目の `bp` の節。引用符の書き方は512・514行目に倣う）
- `.claude/hooks/agent_write_guard.py`（`analyze_bash_writes`・`_legacy_targets_vault_rules_bash`・`targets_vault_rules`。読むだけ）
- 計画票 `vault/plans/P-20261003-guard-rules-path-text.md` の「分割方針」（原因の調査結果）

## 成果物
- `scripts/smoke.sh`（回帰ケースの追加と、既存1ケースの置き換え）

## 受け入れ基準
- ラベルが `(guard-text heredoc)` のケースが7件、`(guard-text cd)` のケースが8件ある。確認：`grep -c '^expect_guard "(guard-text heredoc) ' scripts/smoke.sh` が `7`、`grep -c '^expect_guard "(guard-text cd) ' scripts/smoke.sh` が `8`
- 既存の「#87 の2例目」のケースが無くなっている（H3 に置き換わっている）。確認：`grep -c '#87 の2例目' scripts/smoke.sh` が `0`
- 直す前のガードで、smoke の NG がちょうど6件で、すべて `(guard-text` のケース。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  NG'` が `6`、`bash scripts/smoke.sh 2>&1 | grep -c '^  NG   (guard-text'` が `6`
- 拒否されるべき9件は、直す前のガードで ok。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard-text'` が `9`
- NG の6件が、決定済みの「許可」を期待する6件（H1・H2・H3・H4・C1・C2）である。確認：`bash scripts/smoke.sh 2>&1 | grep '^  NG   (guard-text'` の出力の6行すべてが `want=allow got=deny` を含む
- 変更したのは smoke.sh だけ。確認：`git status --porcelain` の出力が `scripts/smoke.sh` と `vault/tasks/P-20261003-guard-rules-path-text/T-01.md` の行だけ

## 決定済み
- ケースの書き方：各ケースを既存と同じく `expect_guard "<ラベル>" <allow|deny> \` の行と、`  "$(run_guard '<JSON>')"`（拒否を期待するものは末尾に `"vault/rules/"` を4つ目の引数として付ける）の行の2行で書く。ヘルパー関数は作らない（受け入れ基準の `grep '^expect_guard "(guard-text …'` で数えるため）。ラベルは `(guard-text heredoc) <名前>` か `(guard-text cd) <名前>`。名前は自由（`→ 許可`・`→ 拒否` で終える）
- 置き場所：H3 は461〜462行目の「#87 の2例目」のケースをその場で置き換える（P-FIX の計画票がある位置のため）。それ以外の14件は523行目（`bp "絶対パスのコマンド語 /bin/rm …"`）の直後、`bpc` の節の前に、heredoc の6件、cd の8件の順で置く
- 引用符：JSON の中のシングルクォートは既存（512・514行目）と同じく `'"'"'` で書く。改行は JSON の `\n`、二重引用符は `\"`。`$TMP` は `'"$TMP"'` で埋め込む（既存の196行目などと同じ）。`run_guard` は `CLAUDE_PROJECT_DIR="$TMP"` で動き、payload に `cwd` を入れないのでルートは `$TMP` になる
- 15件の中身（`command` の値を、シェルで実行される文字列として書く。`<改行>` は JSON の `\n`）。main は agent_type 無し：
  - H1 許可（main）：`gh issue create --title t --body "$(cat <<'EOF'<改行>## 該当箇所<改行>- vault/rules/planner/planner.md の確認コマンド（... > /tmp/x.md）<改行>EOF<改行>)"`
  - H2 許可（agent_type=planner）：H1 と同じ command
  - H3 許可（main。461〜462行目の置き換え）：command は既存のまま（`git commit -m "$(cat <<'EOF'<改行>P-FIX/T-01 vault/verdicts/P-FIX/T-01.json<改行>EOF<改行>)"`）。期待を `allow` にし、4つ目の引数 `"done"` は外す
  - H4 許可（main。区切り語を引用符で囲まない形）：`gh issue create --title t --body "$(cat <<EOF<改行>see vault/rules/common/git.md > x<改行>EOF<改行>)"`
  - H5 拒否（main）：`echo "$(cat <<'EOF'<改行>x<改行>EOF<改行>)" > vault/rules/a.md`
  - H6 拒否（main。展開される本文にコマンド置換）：`echo "$(cat <<EOF<改行>$(echo x > vault/rules/a.md)<改行>EOF<改行>)"`
  - H7 拒否（main。区切り語の後ろに別のコマンド）：`echo "$(cat <<'EOF'<改行>x<改行>EOF<改行>cp y vault/rules/a.md<改行>)"`
  - C1 許可（agent_type=planner。issue の再現例）：`cd $TMP; ls scripts/ scripts/*/ 2>/dev/null | head -30; grep -c x vault/rules/planner/planner.md; wc -l vault/rules/planner/planner.md`
  - C2 許可（main）：`cd $TMP && grep -n x vault/rules/common/git.md > /tmp/out.txt`
  - C3 拒否（main）：`cd $TMP && echo x > vault/rules/a.md`
  - C4 拒否（main）：`cd $TMP; cp x.txt vault/rules/common/a.md`
  - C5 拒否（main）：`cd $TMP && printf x | tee vault/rules/a.md`
  - C6 拒否（main。ルート以外への cd）：`cd /tmp && echo x > vault/rules/a.md`
  - C7 拒否（main。2つ目の cd）：`cd $TMP; cd vault/rules/common && echo x > a.md`
  - C8 拒否（main。gh api）：`cd $TMP; gh api -X PUT repos/o/r/contents/vault/rules/common/roles.md -f content=Zm9v`
- 直す前の期待（planner が既存のコードで確かめた）：H1・H2・H3・H4・C1・C2 は deny になり NG、残り9件は deny で ok。T-02 の後は H1〜H4 が ok、T-03 の後は C1・C2 も ok になる。既存のケースの期待は H3 以外は変えない
- この T-01 の時点で smoke は fail=6 で終わる（意図どおり。T-03 で fail=0 になる）。fail を0にするためにガードを触らない
- `.claude/hooks/` は触らない。コミットは不要（受け入れ基準に無い）
- 確認コマンドを自分で試す時、`vault/rules/` のパスと `$(`・`cd`・インタプリタを同じコマンドに入れると、今回の誤検知で拒否されることがある。smoke.sh の実行と grep は上の受け入れ基準の形（単一コマンドかパイプ1段）で行う
