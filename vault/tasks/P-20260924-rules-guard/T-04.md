# T-04 planner ルールへの提案ファイル方式の指示を提案ファイルとして用意する

## 目的
`vault/rules/planner/planner.md` に、「ルール変更が成果物のタスクを計画する際は、タスク票の成果物欄
を実体パスではなく `vault/tasks/<計画ID>/<id>-proposal.md` にする」旨の指示を追記する内容を、実体
ファイルではなく提案ファイルとして下書きする。

## 入力
- `vault/rules/planner/planner.md`（現行。追記先）
- `vault/designs/D-002.md`「## 決定事項」「## フェーズ1」
- このタスク自身の `doing`/`review` 中は `vault/rules/` への書き込みが（旧ロジック・新ロジックいず
  れでも）フックで拒否されるため、実体を直接編集できない（この計画のゴールそのものが前提とする制
  約。T-03 と同じ理由）

## 成果物
- `vault/tasks/P-20260924-rules-guard/T-04-proposal.md`（`vault/rules/planner/planner.md` に追記す
  る内容の提案。追記後のファイル全文、または追記する差分のどちらの形式でもよい）

## 受け入れ基準
- 提案ファイルが存在し、追記対象を明記している。確認：
  `grep -c 'vault/rules/planner/planner.md' vault/tasks/P-20260924-rules-guard/T-04-proposal.md` が1
  以上
- 提案内容に、ルール変更が成果物のタスクでは成果物欄を `vault/tasks/<計画ID>/<id>-proposal.md` にす
  る旨の指示が含まれる。確認：
  `grep -c -- '-proposal.md' vault/tasks/P-20260924-rules-guard/T-04-proposal.md` が1以上
- 提案内容に、実パス（`vault/rules/` 配下）を成果物欄に書いてはいけない旨の記述が含まれる。確認：
  `grep -c 'vault/rules/' vault/tasks/P-20260924-rules-guard/T-04-proposal.md` が1以上かつ、その行の
  近傍に「成果物」の語がある（目視確認）
- `vault/rules/planner/planner.md` 自体には手を付けていない（提案のみで実体は変えない）。確認：
  `git status --porcelain -- vault/rules/planner/planner.md` の出力が空
- `bash scripts/smoke.sh | tail -1` に `fail=0` が含まれる

## 決定済み
- 提案ファイルの中身は、既存の `planner.md` の見出し構成（目的 / ルール / 確認方法）を崩さない追記
  案にする。追記位置は「## ルール」の「**責務**」箇条書きの末尾を想定する
- 追記する文言の例（そのまま使ってよい）：「ルール変更（`vault/rules/` 配下のファイル）を成果物とす
  るタスクを計画する時は、タスク票の『成果物』を実体パスではなく
  `vault/tasks/<計画ID>/<id>-proposal.md` にする。受け入れ基準の確認コマンドも、実体ではなく提案フ
  ァイルを対象にする（`agent_write_guard.py` が実体パスへの書き込みを常に拒否するため）」
- 提案ファイルの反映（`vault/rules/planner/planner.md` への実際の追記）は人が手作業で行う。このタス
  ク自身で反映を試みない・自動化しない
- Write が `vault/rules/` 配下に対して deny された場合でも、status を `blocked` にせず、決定済みど
  おり提案ファイルに切り替えて進める
