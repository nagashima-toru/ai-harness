# T-02 smoke.sh に参照される scripts の存在チェックを追加する

## 目的
`scripts/smoke.sh` に、新規ディレクトリへ install した結果について、導入先の `.claude/`・`vault/rules/`・`vault/templates/`・`docs/vault-spec.md`・`CLAUDE.md` に書かれた `scripts/<名前>.sh`／`.py` がすべて `<target>/scripts/` に存在することを確かめるケースを足す。

## 入力
- `scripts/smoke.sh`（「== install.sh のマニフェスト ==」節 361〜382行目、`expect`／`expect_eq` ヘルパーの使い方）
- T-01 の成果物 `scripts/install.sh`（`SCRIPTS_EXCLUDE` 変数と検索方式の複製ループが入っていること）
- `vault/designs/D-007.md` フェーズ1（決定事項）

## 成果物
- `scripts/smoke.sh`

## 受け入れ基準
- `scripts/smoke.sh` に参照チェックのケースがあり、ケース名に「参照される scripts」を含む。確認：`bash scripts/smoke.sh | grep -c '参照される scripts'` が1以上
- そのケースは新規インストール先で全件 ok になる。確認：`bash scripts/smoke.sh | grep '参照される scripts'` に `NG` を含む行が無い
- `scripts/install.sh` の `SCRIPTS_EXCLUDE` に一時的に `vcs_finish.sh` を入れて `bash scripts/smoke.sh` を実行すると、そのケースが NG になる（確認後 `git restore scripts/install.sh` で元に戻す）
- `bash scripts/smoke.sh | tail -1` が `fail=0` で終わる（新しいケースを含む全件）

## 決定済み
- 検索パターンは `scripts/[A-Za-z0-9_.-]+\.(sh|py)`。対象は導入先の `.claude/`（`settings.json` を含む）・`vault/rules/`・`vault/templates/`・`docs/vault-spec.md`・`CLAUDE.md`（ディレクトリはファイルを再帰的に検索する）
- 見つかった名前は重複除去し、それぞれ `<target>/scripts/<名前>` の存在を確かめる。1件でも欠けていれば NG にし、欠けた名前を出力する
- ケースの表示書式は既存の `expect`／`expect_eq` と同じ `  ok   <名前>` / `  NG   <名前> ...`
- テスト対象は「== install.sh のマニフェスト ==」節と同様に、新規ディレクトリへ `bash "$ROOT/scripts/install.sh" "$NTMP"` を実行した結果を使う（`$ROOT/scripts/install.sh` を使う既存の作法に合わせ、ai-harness 本体でも導入先で smoke を実行した時でも同じスクリプトで動くようにする）
- NG 確認用に `scripts/install.sh` の `SCRIPTS_EXCLUDE` を一時的に書き換えて smoke を実行し、確認後 `git restore scripts/install.sh` で元に戻す手順は、確認コマンドとして自分（作成エージェント）が実行してよい（`vault/rules/common/git.md` の「変更を破棄する時は `git restore` のみを使う」に沿う）
- T-01 が `done`（`scripts/install.sh` に検索方式の複製ロジックが入っている状態）になってから着手する
