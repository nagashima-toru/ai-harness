# T-01 agent_write_guard.py の常時拒否化と smoke.sh 更新

## 目的
`.claude/hooks/agent_write_guard.py` の `vault/rules/` 拒否判定から `HARNESS_ALLOW_RULES_WRITE` によ
る明示解除（環境変数の読み取り・`rules_write_allowed`・`doing`/`review` の有無による条件分岐）を削
除し、`vault/rules/` 配下への書き込みをタスクの状態や計画の有無に関わらず常に拒否する判定に置き換
える。

- `docs/vault-spec.md` 第11節・第12節（T-02 で書き直される側。参照のみ、このタスクでは編集しない）

## 成果物

## 受け入れ基準
- `HARNESS_ALLOW_RULES_WRITE` / `rules_write_allowed` に関する記述が消えている。確認：
  `grep -c HARNESS_ALLOW_RULES_WRITE .claude/hooks/agent_write_guard.py` が0、
  `grep -c rules_write_allowed .claude/hooks/agent_write_guard.py` が0
- `vault/rules/` 配下への Write/Edit/MultiEdit/NotebookEdit・Bash 経由の書き込みが、`doing`/`review`
  の有無や approved な計画の有無を問わず常に deny になる。確認：`bash scripts/smoke.sh 2>&1` の
  `== agent_write_guard.py ==` セクションに、doing/review が無い状態・approved な計画が0件の状態そ
  れぞれで `vault/rules/` への Write が deny になるケースがあり、`NG` が無い
- `HARNESS_ALLOW_RULES_WRITE` を使う smoke.sh のケース（旧 (d)(e)(f)）が削除されている。確認：
  `grep -c HARNESS_ALLOW_RULES_WRITE scripts/smoke.sh` が0
- `ALLOWED`（verifier / planner の書き込み先制限）と main 直接コミット拒否の判定は変えていない。確
  認：`grep -c 'ALLOWED = {' .claude/hooks/agent_write_guard.py` が1、`bash scripts/smoke.sh 2>&1` の
  `== agent_write_guard.py ==` セクションで `ALLOWED` に関する既存ケース（verifier/planner のパス制
  限、メインエージェントの通常ファイル編集許可）に `NG` が無い
- `bash scripts/smoke.sh | tail -1` に `fail=0` が含まれる

## 決定済み
- 常時拒否にする対象は「`vault/rules/` 配下への書き込み」のみ。`ALLOWED`（verifier/planner のパス制
  限）・main 直接コミット拒否・`BASH_WRITE_PATTERNS` によるコマンド検出・`targets_vault_rules` の判
  定ロジック自体は変えない。変えるのは「いつ deny するか」の条件だけ（常に deny にする）
- `active_doing_review_task_ids` とそれが使う `approved_plans` / `doing_review_ids_in_plan` /
  `plan_id_and_status` は、旧・条件分岐（`doing`/`review` の有無で判定を変える）のためだけに存在す
  る。常時拒否にすると不要になるため、まとめて削除してよい。`current_branch` は main 直接コミット拒
  否判定でも使うため残す
- ファイル冒頭の docstring（改ざん防止の説明）と `main()` 内のコメントを「`doing`/`review` 中のタス
  クがあれば」から「常に」に書き換える。`HARNESS_ALLOW_RULES_WRITE` に触れている行はすべて削除する
- deny 時のメッセージは新方式を促す内容にしてよい（例：「`vault/rules/` へは書き込めません。ルール
  変更が成果物のタスクは `vault/tasks/<計画ID>/<id>-proposal.md` に下書きし、実体への反映は人が行い
  ます」）。文言はこのタスクの裁量とする
- smoke.sh のケース更新方針：現行 (a)（doing 中→deny）と (c)（doing 中に verifier が verdicts/ へ
  Write→allow、`vault/rules/` と無関係なので不変）はそのまま残せる。(b)（doing/review 無し→allow）
  と (g)（approved 計画0件→allow）は、常時拒否になるため期待値を deny に変える（ケース名の文言も実
  態に合わせて書き換えてよい）。(d)(e)(f)（`HARNESS_ALLOW_RULES_WRITE` 関連）は丸ごと削除する。(h)
  （approved 2件以上・doing あり→deny）は期待値は変わらないためそのまま残してよい
- `docs/vault-spec.md` の書き換えは T-02 の担当。このタスクでは触らない
