# T-01 docs/vault-spec.md 7節に worktree の記録行の書式を追記する

## 目的
run の再開情報（worktree のパス・ブランチ名・PLAN_HEAD）を log に記録する行の書式を仕様の正本に定め、後続タスク（run SKILL.md の書く側・読む側）が参照できるようにする（D-010 フェーズ6、issue #78）。

## 入力
- `docs/vault-spec.md` 7節（`## 7. ログ`）。特に承認・解除の行の追記の書き方
- `vault/designs/D-010.md` フェーズ6のゴール文と決定済み

## 成果物
- `docs/vault-spec.md` の変更（1ファイル。7節への追記だけ）

## 受け入れ基準
- 7節に記録行の書式 `- <日時> <id> worktree path=<パス> branch=<ブランチ名> plan_head=<sha>` が書かれている。確認：`grep -n 'plan_head=' docs/vault-spec.md` が7節内の行にヒットする
- 7節が、この行は状態遷移ではない（`→` を含まない）補足行で、creator の完了報告の受領直後に run が1タスク1行ずつ追記する旨を書いている（目視で確認）
- 7節が、再開時に参照するのはその id の最後の記録行である旨と、doing の中断時の再開の補足は `中断から再開` とする旨を書いている（目視で確認）
- 変更が7節に収まっている。確認：`git diff -- docs/vault-spec.md` を出力し、`@@` 行の位置が7節（`## 7.` から `## 8.` の手前）に収まることを目視で確認する
- `bash scripts/smoke.sh` の最終行が `fail=0` になる

## 決定済み
- 検査対象ファイルの範囲：変更してよいのは `docs/vault-spec.md` と、このタスク票自身（`vault/tasks/P-20260930-run-resume-info/T-01.md` の「進捗」）だけ。宣言外ファイルの変更は verifier が `git status --porcelain` で検査する（`vault/log/`・`vault/verdicts/`・計画票は run が更新するので除外）。起点コミットの記録は必須ではないが、書いてもよい
- 書式の例は `- 2026-09-30 10:15 T-01 worktree path=/path/to/.claude/worktrees/agent-xxxx branch=worktree-agent-xxxx plan_head=<40桁の sha>` の形にする。`plan_head=` の値は `git rev-parse HEAD` の完全な sha
- 記録先は log（タスク票の「進捗」ではない）。計画票のタスク表の列は変えない
- 複数タスクの場合は、タスクごとに1行ずつ、手順3の中でまとめて追記する
- 再開時に参照するのは、その id の最後の記録行
- 「`→` を含む遷移行以外は状態の集計に使わない」旨は、F8（`model_stats.py`）が遷移行だけを見る前提なので、1文で書いてよい
- stop_gate.py・plan_guard.py は log を読まないので、書式の追記でフックは変更しない
- 7節の既存の文（承認・解除の行）は書き換えない。追記だけにする
