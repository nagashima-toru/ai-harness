# T-03 plan スキルの A を自動承認と /run の続行にし、B（/plan approve）を削る

## 目的
`/plan` を承認待ちで止まらない流れにする（D-015 フェーズ2）。A（計画を作る）の最後で粒度の確認を通ったら approved にして log を足してコミットし、続けて `/run` の手順を実行する。B（`/plan approve`）を削り、C（`/plan unblock`）は手順を変えずに残す。

## 入力
- `vault/designs/D-015.md` の「決定事項」の表と「フェーズ2」の節
- `.claude/skills/plan/SKILL.md`（frontmatter・冒頭の説明・A・B・C・注意）
- `.claude/skills/run/SKILL.md` の「## 1. 計画票を見つける」の2

## 成果物
- `.claude/skills/plan/SKILL.md`（主な成果物）
- `.claude/skills/run/SKILL.md`（付随。「## 1. 計画票を見つける」の2の1行だけ）

## 受け入れ基準
- plan スキルに `/plan approve` が残っていない。確認：`grep -c "plan approve" .claude/skills/plan/SKILL.md` の出力が `0`
- B が消え、C が B に繰り上がっている。確認：`grep -c "^## " .claude/skills/plan/SKILL.md` の出力が `3`、`grep -c "^## B\. blocked を解除する" .claude/skills/plan/SKILL.md` の出力が `1`
- A の最後に自動承認の log の行と `/run` の続行がある。確認：`grep -c -F -- '- <日時> - draft→approved /plan による自動承認' .claude/skills/plan/SKILL.md` の出力が `1`、`grep -c -F '続けて `/run`（`.claude/skills/run/SKILL.md`）の手順1から実行する' .claude/skills/plan/SKILL.md` の出力が `1`
- 自動承認のコミットでタスク票も名前を指定して stage する。確認：`grep -c -F 'git add vault/plans/<計画ID>.md vault/tasks/<計画ID>/ vault/log/<計画ID>.md' .claude/skills/plan/SKILL.md` の出力が `1`
- frontmatter の argument-hint から approve が消えている。確認：`grep -c -F 'argument-hint: [ゴール | unblock <計画ID> <id> [回答]]' .claude/skills/plan/SKILL.md` の出力が `1`
- run スキルが `/plan approve` を案内しない。確認：`grep -c "plan approve" .claude/skills/run/SKILL.md` の出力が `0`、`grep -c -F '`/plan <ゴール>` で計画を作ってください' .claude/skills/run/SKILL.md` の出力が `1`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む（参照切れの検査を含む）

## 決定済み
- frontmatter
  - description：「ゴールをタスクに分割して計画を作り、そのまま実行する。「計画を立てて」「タスクに分割して」「これをやりたい」「plan」と言われたら必ずこのスキルを使う。計画 ID とブランチを決め、planner サブエージェントで draft を作り、粒度の確認を通ったら計画票の status を approved にしてコミットし、続けて /run の手順を実行する（人の承認を待たない）。blocked になったタスクの解除（unblock）にも使う。「blocked を解除」「T-02 の blocked を戻して」と言われたらこのスキルを使い、人が `/plan unblock <計画ID> <id> [回答]` のコマンドを打つよう案内する。」にする
  - argument-hint：`[ゴール | unblock <計画ID> <id> [回答]]`
- 冒頭の説明の「人の承認を経て計画票の `status` を `approved` にする」は「粒度の確認を通ったら計画票の `status` を `approved` にし、続けて `/run` を実行する」にする。「注意：このスキルは考える工程なので、強いモデル（opus）のセッションで実行する。」は残す
- A の手順1〜5は変えない。手順6以降を次にする（番号はこのとおり）
  - 6. 人に提示する：計画 ID、タスクの一覧（ID / title / after / 受け入れ基準の要約）
  - 7. 計画票に「## 人への質問」があれば、質問を提示して**止まる**（`status` は draft のまま）。人が会話で答えたら、回答を計画票とタスク票の「決定済み」に反映し（大きな直しは planner を呼び直す）、手順5からやり直す。質問が無ければ手順8へ進む（人の回答待ちの既定案。計画票の「人への質問」3）
  - 8. `vault/plans/<計画ID>.md` の frontmatter `status` を `draft` から `approved` にする（Edit）
  - 9. `TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M'` で日時を取り、`vault/log/<計画ID>.md` に次の1行を追記する（ファイルが無ければ作る）：`- <日時> - draft→approved /plan による自動承認`
  - 10. `git add vault/plans/<計画ID>.md vault/tasks/<計画ID>/ vault/log/<計画ID>.md` でファイルを名前で指定して stage し、`git commit`（メッセージ例：`<計画ID>: 計画を作り自動承認する`）する。work ブランチ上で行う。`git add .` や `git add -A` は使わない。stage とコミットは別々の Bash 呼び出しにし、コミットメッセージにコマンド置換を使わない
  - 11. 続けて `/run`（`.claude/skills/run/SKILL.md`）の手順1から実行する。セッションのモデルは変えない（creator・verifier はサブエージェントで、それぞれの定義のモデルで動く）
- 旧 B（「## B. 承認する（引数が `approve <計画ID>` のコマンドの時）」の節）は丸ごと削る。代わりの節は足さない
- 旧 C は見出しを「## B. blocked を解除する（引数が `unblock <計画ID> <id> [回答]` のコマンドの時）」にし、本文（手順1〜7と「1回のコマンドで解除するのは1行だけ。…」の段落）は1文字も変えない（D-015 の決定済み「C 節は手順を変えない」）
- 「## 注意」の節は変えない
- `.claude/skills/run/SKILL.md` は「## 1. 計画票を見つける」の2を「出力が0行なら「承認済みの計画が見つかりません。`/plan <ゴール>` で計画を作ってください」と報告して終わる」にするだけ。ほかの行は変えない
- `vault/log/` の既存の行（`人の指示:` で始まる承認の行）は書き換えない
