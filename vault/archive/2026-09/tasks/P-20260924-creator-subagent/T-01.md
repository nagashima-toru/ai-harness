# T-01 .claude/agents/creator.md の新設

## 目的
`run` スキルの「3. 作る」相当のロジックを、Agent ツールで呼び出せるサブエージェント定義 `.claude/agents/creator.md` に切り出す。creator の入出力仕様（タスク ID のみを受け取る、状態・ログには書かない、成果物と進捗だけを書く）をここで固定し、後続タスク（T-04・T-05）はこの定義を参照する。

## 成果物
- `.claude/agents/creator.md`（新規ファイル）

## 受け入れ基準
- frontmatter に `name: creator` と `tools:` がある。確認コマンド: `grep -c '^name: creator$' .claude/agents/creator.md` の出力が1、かつ `grep -c '^tools:' .claude/agents/creator.md` の出力が1
- 「入力」相当の節に、タスク ID だけを受け取る旨が明記されている（verifier.md の「入力」節と同様の書き方）
- 本文に、`bash scripts/rules.sh creator` を実行してルールを読む手順が含まれる。確認コマンド: `grep -c 'rules.sh creator' .claude/agents/creator.md` の出力が1以上
- 本文に、`vault/plans/` と `vault/log/` へは書き込まず、状態更新とログ追記はオーケストレーター（呼び出し元）の役目である旨が明記されている。確認コマンド: `grep -c 'vault/plans/' .claude/agents/creator.md` の出力が1以上、かつ `grep -c 'vault/log/' .claude/agents/creator.md` の出力が1以上
- 本文に、「決定済み」に答えが無い判断が必要になった場合は自分で `blocked` にせず、進捗に記録した上で質問を完了報告として返す旨が明記されている
- 本文に、完了報告として成果物のパスと確認コマンドの実行結果の要約（または blocked の場合は質問文）を返す旨が明記されている

## 決定済み
- frontmatter は `name: creator`、`description` は「run から Agent ツールで呼ばれ、タスク ID を受け取って成果物を作る作成エージェント」といった内容にする。`tools` は `Read, Grep, Glob, Bash, Write, Edit`（成果物作成に必要な一式。`planner.md`・`verifier.md` の前例と同じ書式）、`model: sonnet`
- 手順の内容は現行 `run/SKILL.md` 手順3（1〜5）をそのまま踏襲する：タスク票の6見出しを読み「決定済み」を優先→`bash scripts/rules.sh creator` の列挙を読む→成果物を作り確認コマンドを自分でも実行して通す→「進捗」に箇条書きで追記→判断が必要で「決定済み」に無ければそこで止まる
- creator が書き込めるのは成果物ファイルと `vault/tasks/<計画ID>/<id>.md` の「進捗」だけ。`vault/plans/`・`vault/log/` への書き込みは T-02 でフックが常に拒否する前提で、ルール文書側にも明記する
- 「決定済み」に答えが無い判断が出た場合、creator は計画票の `status` を `blocked` にする操作自体を行わない（`vault/plans/` への書き込みになるため）。代わりに「進捗」に判断できない理由を記録し、完了報告の中で「blocked: <質問文>」の形で返す。計画票への `blocked` 反映と log 追記はオーケストレーター（呼び出し元）が行う
- verifier の呼び出しはこのタスクの対象外（creator は verifier を呼ばない。呼ぶのはオーケストレーター）
