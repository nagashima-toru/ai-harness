# T-01 transition.py の creator= に HARNESS_CREATOR_MODEL を優先させる

## 目的
`scripts/transition.py` が log の `doing→review`・`doing→blocked` の行に付ける `creator=` の値を、環境変数 `HARNESS_CREATOR_MODEL` が空でなければその値にし、無ければ今どおり `.claude/agents/creator.md` の frontmatter の `model` にする。smoke にケースを足し、smoke 全体がこの環境変数に左右されないようにする。

## 入力
- `vault/designs/D-013.md` の「フェーズ3 creator のモデルの切り替えと計測」（ゴール文2・受け入れ基準の候補の1行目・決定済み）
- `scripts/transition.py`（先頭の docstring・`MODEL_AGENT`・`agent_model`・`main` の `model` を決める箇所）
- `scripts/smoke.sh`（`== transition.py（D-012 フェーズ2） ==` の節。`tr_setup`・`tr_run`・`tr_lastlog`・既存の (transition) 05・06）
- `docs/vault-spec.md` 7節（`creator=` の書式。このタスクでは変えない）

## 成果物
- `scripts/transition.py`（主な成果物）
- `scripts/smoke.sh`（`unset HARNESS_CREATOR_MODEL` の追加と、`== transition.py（D-012 フェーズ2） ==` の節へのケースの追加）

## 受け入れ基準
- `HARNESS_CREATOR_MODEL=haiku` の時、doing→review の log の行が `creator=haiku` で終わる：`bash scripts/smoke.sh 2>&1 | grep -F 'ok   (transition-model-1)'` の出力が1行
- 同じ環境変数があっても review→done の行は `verifier=smoke-verifier` のまま、空文字の時は `creator=smoke-creator`、`--no-model` の時はモデルを付けない：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(transition-model-[2-4]\)'` の出力が `3`
- 未設定の時は今どおり frontmatter の値が付く（既存のケースが名前を変えずに通る）：`bash scripts/smoke.sh 2>&1 | grep -F 'ok   (transition) 05 doing→review の log 行が creator=smoke-creator で終わる'` の出力が1行
- 呼び出し元の環境に `HARNESS_CREATOR_MODEL` があっても smoke が通る：`env HARNESS_CREATOR_MODEL=haiku bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- 先頭の docstring に、`creator=` の値は `HARNESS_CREATOR_MODEL` を優先し、無ければ frontmatter の `model` であることが書かれている（Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- `HARNESS_CREATOR_MODEL` は、未設定と空文字を同じ扱いにする（どちらも frontmatter の値を使う）。前後の空白は取り除いてから判定してよい
- 値の検査はしない（設計の決定済み）。設定された文字列をそのまま `creator=<値>` にする
- 適用するのは creator のモデルを付ける場面すべて（`MODEL_AGENT` で creator にあたる遷移と、`--worktree` 付きで creator のモデルを使う箇所）。`main` の中で `agent_model(root, "creator")` を呼んでいる所を、環境変数を優先する関数（例：`creator_model(root)`）に置き換える形でよい
- verifier のモデル（`verifier=`）は環境変数を見ない。`HARNESS_VERIFIER_MODEL` のような変数は作らない
- `--no-model` の時は、環境変数があってもモデルを付けない
- 差し戻しの `doing→doing` の行にモデルを付けない今の動きは変えない
- smoke の変更：
  - smoke.sh の先頭付近（`TMP` を作るあたり）に `unset HARNESS_CREATOR_MODEL` を置き、既存のケースが呼び出し元の環境に左右されないようにする
  - 新しいケースは `== transition.py（D-012 フェーズ2） ==` の節の既存の (transition) 06 の後に置き、名前は `(transition-model-N) ` で始める。1つの番号につき `expect_eq` は1回だけにする（受け入れ基準の件数がそのまま数えられるように）
  - 環境変数は新しいケースの間だけ設定し、ケースの後に `unset` するなどして、後のケースに漏らさない（`tr_run` はシェル関数なので、`export HARNESS_CREATOR_MODEL=haiku` → `tr_run ...` → `unset HARNESS_CREATOR_MODEL` の形が確実）
  - (transition-model-1)：`tr_setup std` の後、`HARNESS_CREATOR_MODEL=haiku` で `tr_run P-TEST T-04 review` → 最後の log の行が ` T-04 doing→review attempt=1 creator=haiku` で終わる
  - (transition-model-2)：`HARNESS_CREATOR_MODEL=haiku` で `tr_run P-TEST T-06 done` → 最後の行が ` T-06 review→done attempt=1 verifier=smoke-verifier` で終わる
  - (transition-model-3)：`HARNESS_CREATOR_MODEL=`（空文字）で `tr_run P-TEST T-04 review` → `creator=smoke-creator` で終わる
  - (transition-model-4)：`HARNESS_CREATOR_MODEL=haiku` で `tr_run P-TEST T-04 review --no-model` → 最後の行が ` T-04 doing→review attempt=1` で終わり、`creator=` を含まない
- `docs/`・`.claude/skills/` は変えない（T-03・T-04 で行う）。`scripts/model_stats.py` は変えない
