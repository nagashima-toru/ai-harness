# T-03 README.md の /run と無人実行の説明・仕組みの図・構成の節を今の構成に合わせる

## 目的
`README.md` の `/run` の説明（使い方の表・無人実行・仕組みの図）と構成の節を、今の run（オーケストレーター＋creator/verifier のサブエージェント、全部 done で PR）と今のファイル構成（`.claude/agents/` の3つ、`scripts/` の主なスクリプト）に合わせる。

## 入力
- `README.md`（直す対象。27〜39行目の「使い方」、56〜76行目の「仕組み」、78〜84行目の「構成」）
- `.claude/skills/run/SKILL.md`（正）
- `docs/runbook.md` の30〜34行目（無人実行は `python3 scripts/run_unattended.py` を使う）
- `.claude/agents/`・`scripts/` の実ファイル
- `vault/designs/D-013.md` の「フェーズ7」

## 成果物
- `README.md`（1ファイル）

## 受け入れ基準
- 使い方の表の `/run` の行が今の動きになっている：`grep -c '^| `/run` | 自分のブランチの承認済み計画の取れるタスクを、全部 done になるまで処理し、PR を作る' README.md` の出力が `1`
- 無人実行が `run_unattended.py` になっている：`grep -c '`claude -p "/run"` |' README.md` の出力が `0`、かつ `grep -c '^| `python3 scripts/run_unattended.py` | ' README.md` の出力が `1`
- 古い言い方が残っていない：`grep -cE '1タスク処理する|作成エージェント（メイン）' README.md` の出力が `0`、かつ仕組みの図の列見出しが `grep -c 'オーケストレーター（メイン）' README.md` で `1`
- 構成の節に `.claude/agents/` の3つが書かれている：`grep -c '^\.claude/ .*agents/（creator, verifier, planner）' README.md` の出力が `1`
- 構成の節に `scripts/` の主なスクリプトが書かれている：`grep -cE '^scripts/ .*smoke\.sh.*install\.sh.*uninstall\.sh.*rules\.sh.*current_plan\.sh.*transition\.py.*diff_gate\.py.*vcs_finish\.sh.*discard_worktree\.sh.*run_unattended\.py.*archive_plans\.sh' README.md` の出力が `1`
- 見出しの数が変わっていない：`grep -c '^## ' README.md` の出力が `7`

## 決定済み
- 使い方の表（「## 使い方」）
  - `/run` の行の説明を「自分のブランチの承認済み計画の取れるタスクを、全部 done になるまで処理し、PR を作る（creator → verifier → done / 再試行 / blocked）」にする（この文字列をそのまま書く）
  - `claude -p "/run"` の行を「| `python3 scripts/run_unattended.py` | 同じことを無人（非対話）で行う（タイムアウト付きのラッパー。中で `claude -p "/run"` を実行する） |」に置き換える
  - 表の下の箇条書き「無人で回す場合は `claude -p "/run"` を cron や CI から定期実行する」を「無人で回す場合は `python3 scripts/run_unattended.py` を cron や CI から定期実行する（手順は `docs/runbook.md`）」にする
  - `/design`・`/plan` の行、使い分けの段落、ほかの箇条書きは変えない
- 仕組みの図（「## 仕組み」のコードブロック）
  - 1行目の列見出し「作成エージェント（メイン）」を「オーケストレーター（メイン）」にする
  - 「todo→doing → 成果物を作る → review」の行は「todo→doing → creator が worktree で作る → review」にする。列の位置（`──▶` の後の「受け入れ基準を照合」）がずれる時は、空白の数で整えてよい
  - ほかの行は変えない
- 構成の節（「## 構成」のコードブロック）。4行を次のとおりにする（`vault/` の行は今のまま）
  - `.claude/   settings.json（hooks・許可・サンドボックス）、agents/（creator, verifier, planner）、hooks/、skills/（design, plan, run）`
  - `docs/      vault-spec.md（仕様の正本）、install.md（インストール手順）、runbook.md、vision.md、decisions.md`
  - `scripts/   smoke.sh（フック検証）、install.sh・uninstall.sh（他プロジェクトへの複製と取り外し）、rules.sh（ルール解決）、current_plan.sh（承認済みの計画の特定）、transition.py（状態遷移）、diff_gate.py（差分ゲート）、vcs_finish.sh（PR 作成）、discard_worktree.sh（worktree の破棄）、run_unattended.py（無人実行のラッパー）、archive_plans.sh（古い計画の移動）`
  - 上に無いスクリプト（`pr_body.py`・`verdict_notes.py`・`model_stats.py`・`usage_stats.py`・`merge_*`・`unmerge_*`）は書かない（主なものだけ）
  - 仕組みの図・構成のコードブロックの中にはバッククォートを書かない
- 「## 拡張ポイント（ルール）」の節と、その中の例 `vault/rules/common/naming.md` は変えない（例として挙げているだけで、T-05 の検査で除かれる）
- 新たにバッククォートで書くパスは実在するものだけにする（T-05 の参照切れの検査の対象になる）。`scripts/run_unattended.py`・`docs/runbook.md` は実在する
- 書く内容は今の `.claude/skills/run/SKILL.md`・`docs/runbook.md` を正とする。それらは変えない
- 文書だけの変更なので、確認は受け入れ基準の grep で行う。`bash scripts/smoke.sh` は実行しなくてよい
