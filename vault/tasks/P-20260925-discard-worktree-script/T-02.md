# T-02 scripts/install.sh に discard_worktree.sh を配布対象・マニフェスト対象として追加する

## 目的
導入先の `run` スキルも手順6.3.2 で `scripts/discard_worktree.sh` を呼ぶため、`scripts/install.sh` の配布・マニフェスト対象に加える（`scripts/uninstall.sh` はマニフェスト駆動なので追加対応は不要）。

## 入力
- T-01 の成果物 `scripts/discard_worktree.sh`
- `scripts/install.sh`（`manifest_paths()` の `for p in ...` 列挙と、通常複製ループの `copy_if_absent "$SRC/scripts/..."` 行の両方に追加する既存パターン。例：`scripts/rules.sh`・`scripts/merge_claude_md.py` の行）
- `vault/designs/D-006.md`（決定事項）

## 成果物
- `scripts/install.sh`

## 受け入れ基準
- `manifest_paths()` 関数内の `for p in ...` 列挙に `scripts/discard_worktree.sh` が追加されている。確認：`grep -n 'scripts/discard_worktree.sh' scripts/install.sh` が2箇所以上ヒットする（`manifest_paths` の列挙と、通常複製ループの `copy_if_absent` 呼び出しの両方）
- 新規ディレクトリへ `bash scripts/install.sh <target>` を実行すると `<target>/scripts/discard_worktree.sh` が配置される。確認：`T=$(mktemp -d); bash scripts/install.sh "$T" >/dev/null 2>&1; test -f "$T/scripts/discard_worktree.sh" && echo ok` が `ok`
- 同じ実行で `.claude/harness-manifest.json` の `files` に `scripts/discard_worktree.sh` がSHA256（64桁16進）の値付きで載る。確認：`python3 -c "import json,re;d=json.load(open('$T/.claude/harness-manifest.json'))['files'];print(bool(re.fullmatch('[0-9a-f]{64}', d.get('scripts/discard_worktree.sh',''))))"` が `True`
- `bash scripts/smoke.sh | tail -1` が `fail=0` で終わる（既存の install/uninstall 系ケースを壊していない）

## 決定済み
- 追加は既存パターンに厳密に合わせる：`manifest_paths()` の `for p in ...` の列挙（複数行にまたがる `\` 継続でよい）と、通常複製ループの `copy_if_absent "$SRC/scripts/discard_worktree.sh" "$DST/scripts/discard_worktree.sh"` 行の両方
- `scripts/uninstall.sh` はマニフェストの `files` を元に除去するため変更不要（`vault/designs/D-006.md` の決定どおり）。触らない
- `.claude/settings.json`・`merge_settings_json.py`・`unmerge_settings_json.py` は本タスクの対象外（deny ルールは変更しないため）
- T-01 が先に完了している前提（`scripts/discard_worktree.sh` が実在すること）。実在しない場合は自分で作らず `blocked` にする
- 一時ディレクトリでの検証は `mktemp -d` で作り、確認後に消す必要はない（`scripts/smoke.sh` 自体は独自に一時ディレクトリを使うため、ここで作ったものが残っても smoke の結果に影響しない）
