# T-0005 todo_guard フックで todo.md の整合性を PostToolUse でチェックする

## 目的
`vault/todo.md` の状態表が壊れたまま作業が進まないよう、PostToolUse フック `todo_guard.py` で整合性を検査する。

## 入力
- `.claude/hooks/stop_gate.py`（`parse_tasks` と `project_dir` の参考。コピーしてよいが本体は変更しない）
- `.claude/settings.json`（hooks 登録先）
- `scripts/smoke.sh`（既存23件のテスト構造）
- `docs/vault-spec.md`（追記対象）
- `CLAUDE.md`（「## フック」節への追記対象、60行以内）
- `vault/todo.md`（表の形式の実例）

## 成果物
- `.claude/hooks/todo_guard.py`（新規ファイル。PostToolUse で `vault/todo.md` の整合性を検査するフック本体）
（`.claude/settings.json` の登録、`scripts/smoke.sh` のケース追加、`docs/vault-spec.md` と `CLAUDE.md` への追記は本タスクに付随する変更として同時に行う）

## 受け入れ基準
- `.claude/hooks/todo_guard.py` が存在し、以下の壊れたケースそれぞれでトップレベル `decision: "block"` と `reason`（何が壊れているか・直し方を含む）を返す：(a) doing が2件以上、(b) blocked なのに question が空、(c) status が5値以外、(d) 「## タスク」表の id 重複、(e) データ行の列数が6でない。確認：`bash scripts/smoke.sh` 内の該当ケースが `ok` になる
- `vault/todo.md` が存在しない場合、および「## タスク」表にデータ行が無い場合は何も出力せず exit 0 で終わる。確認：`printf '{}' | CLAUDE_PROJECT_DIR=<todo.mdが無い一時dir> python3 .claude/hooks/todo_guard.py; echo $?` の出力が空文字列＋`0`
- `.claude/settings.json` の `hooks.PostToolUse` に matcher `Write|Edit|MultiEdit|Bash` で `todo_guard.py` が登録されている。確認：`python3 -c "import json; d=json.load(open('.claude/settings.json')); print(any(g['matcher']=='Write|Edit|MultiEdit|Bash' and any('todo_guard.py' in h['command'] for h in g['hooks']) for g in d['hooks']['PostToolUse']))"` が `True`
- `bash scripts/smoke.sh` が既存23件＋新規ケース全件を成功で終える。確認：`bash scripts/smoke.sh | tail -1` が `fail=0` を含み、かつ pass の件数が24以上（既存23件より増えている）
- `docs/vault-spec.md` に `todo_guard.py` の説明が1〜2行追記されている。確認：`grep -c todo_guard.py docs/vault-spec.md` が1以上
- `CLAUDE.md` の「## フック」節に `todo_guard.py` の説明が1行追加され、かつファイル全体が60行以内。確認：`grep -c todo_guard.py CLAUDE.md` が1以上、かつ `wc -l < CLAUDE.md` が60以下

## 決定済み
- **parse_tasks / project_dir の扱い**：`stop_gate.py` の `parse_tasks` 関数は同じ規則のためそのままコピーして `todo_guard.py` に含めてよい（import はしない。`stop_gate.py` 自体は変更禁止）。`project_dir` は素直に「`CLAUDE_PROJECT_DIR` → 無ければ stdin の `cwd` → それでも無ければ自身のパスから2階層上」の順で決める簡潔な実装でよい（`stop_gate.py` の `project_dir` は todo.md の存在チェック付きだが、`todo_guard.py` では todo.md が無い場合の分岐を別途書くため、その存在チェックは踏襲しなくてよい）。
- **(a)〜(e) の判定順序**：どれか1つでも該当すればその時点で block してよい（全件チェックして複数理由をまとめる必要はない）。複数該当時にどれを最初に報告するかは自由（実装しやすい順でよい）。
- **reason の文面**：`[todo_guard] ` プレフィックスを付け、`stop_gate.py` と同様に日本語で「何が壊れているか」＋「直し方」を1文で書く。例：
  - (a) `[todo_guard] doing の行が2件あります（T-0001, T-0002）。doing は常に1件にしてください。`
  - (b) `[todo_guard] T-0003 が blocked なのに question 列が空です。question 列に人へ聞くことを書いてください。`
  - (c) `[todo_guard] T-0004 の status が 'pending' です。todo/doing/review/blocked/done のいずれかにしてください。`
  - (d) `[todo_guard] id T-0001 が重複しています。id は一意にしてください。`
  - (e) `[todo_guard] T-0005 の行の列数が5です。id/status/attempt/after/title/question の6列にしてください。`
  文面はこの例に厳密一致させる必要はない。smoke.sh の `expect` は部分文字列一致（`grep`）で判定するので、`"NG"` や該当する語（`doing`／`question`／`status`／`重複`／`列数` など）を含めればよい。
- **列数チェック(e) の数え方**：`parse_tasks` は6列未満のセルを空文字で埋めて6列に揃えてから返すため、そのままでは列不足を検出できない。(e) の検査は `parse_tasks` とは別に、生の行を `|` で split して素の列数（先頭 `id` 見出し行・区切り線・空行を除く実データ行）を数える簡易ロジックを追加すること。
- **smoke.sh のフィクスチャ**：既存 `make_todo()`（1行専用）は他のテストが依存しているため変更しない。複数行の表を作る新ヘルパー（例：`make_todo_rows()`。可変長引数または改行区切り文字列で複数のデータ行を受け取り `vault/todo.md` に書く）を追加する。「## タスク」表にデータ行が無いケースは、`make_todo_rows` を引数なしで呼ぶ（ヘッダのみ）か専用の小さいヘルパーで作ってよい。
- **todo.md が存在しないケース**：smoke.sh 内で新しく別の一時ディレクトリ（`mktemp -d`）を作り `vault/todo.md` を置かずにフックへ渡すか、既存 `$TMP` から一時的に `vault/todo.md` を `mv` で退避して呼び出し、終わったら戻す。どちらでもよい。
- **フックの呼び出し方**：PostToolUse なので stdin の JSON は `{"hook_event_name":"PostToolUse","tool_name":"Write","cwd":"..."}` のような形を想定してよい（`todo_guard.py` は `tool_name` の値を判定に使わない。matcher で既に絞られている前提でよい）。stdin が壊れていても例外を投げず exit 0 で許可する（他フックと同じ作法）。
- **settings.json への登録位置**：`hooks` オブジェクト内、既存の `"Stop"` と `"PreToolUse"` に続けて `"PostToolUse"` キーを追加する（配列内オブジェクトの `matcher` は `"Write|Edit|MultiEdit|Bash"`、`hooks` は `python3 "${CLAUDE_PROJECT_DIR}/.claude/hooks/todo_guard.py"` を `type: command` で1件）。
- **CLAUDE.md の追記位置**：33〜35行目の「## フック」節に、既存の Stop・PreToolUse の行に続けて `PostToolUse：todo_guard.py が todo.md の整合性（doing重複・blocked時のquestion空・status不正・id重複・列数不正）を検査する` 相当の1行を追加する。現在36行なので1行追加しても37行で60行制約に十分収まる。他の節は変更しない。
- **docs/vault-spec.md の追記位置**：既存の「## 10. Stop フックの判定」節の後に短い新節（例：「## 11. todo_guard フックの判定」）を1〜2行で追加するか、既存の関連箇所（例：4節「todo.md の形式」末尾）に1〜2行追記するかは実装者の判断でよい。分量は1〜2行に収める。
- **正常系ケース**：smoke.sh には壊れていない todo.md（doing 1件、blocked かつ question あり、status が正常5値のいずれか、id 重複なし、列数6）を渡して allow（無出力・exit 0）になることを確認するケースも追加する。

## 進捗

- settings.json に PostToolUse（matcher: Write|Edit|MultiEdit|Bash）として登録
- smoke.sh に make_todo_rows / run_todo_guard を追加し (a)〜(e) と正常系・データ行無し・todo.md 無しの8件を追加。pass=31 fail=0
- docs/vault-spec.md に第11節、CLAUDE.md のフック節に1行を追記（41行、60行以内）
- 受け入れ基準6件の確認コマンドをすべて実行し通過
