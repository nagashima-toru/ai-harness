# T-02 planner.md と経緯集に、バッククォートを含む文言の基準の書き方を足す

## 目的
planner が「決定済み」に書いた文言から受け入れ基準の grep の文字列を抜き出す時に、バッククォートの所をまたいで食い違わせないよう、`.claude/agents/planner.md` に書き方と T-01 の plan_guard の検査を書き、`vault/rules/planner/ai-harness-lessons.md` に Issue #204 の経緯を残す。

## 入力
- `.claude/agents/planner.md` の「やらないこと」節（特に「成果物本文に無い文字列を grep する受け入れ基準を書かない」と「確認コマンドの grep パターンに、シェルの特殊文字…を含めない」の箇条）と「書き終えた後の確認」節
- `vault/rules/planner/ai-harness-lessons.md`（「ルール」節の各項目の書式）
- `.claude/hooks/plan_guard.py` の `literal_mismatches`・`literal_violation`（T-01 で足したもの）
- `docs/vault-spec.md` の10節（T-01 で足した箇条）

## 成果物

- `vault/rules/planner/ai-harness-lessons.md`（経緯の追加）

## 受け入れ基準
- planner.md の「やらないこと」節に、バッククォートをまたいで文字列を抜き出さない箇条がある：`grep -c '文言のバッククォートをまたいで、受け入れ基準の grep の文字列を抜き出さない' .claude/agents/planner.md` の出力が `1`
- その箇条に、決定済みの文言の例と、バッククォートを `.` に置き換えたパターンの例が同じ行にある：`grep -c 'JobConfig.。命名は方式設計' .claude/agents/planner.md` の出力が `1`
- その箇条に、plan_guard が止めることが書かれている：`grep -c 'plan_guard.py. が draft のタスク票の Write・Edit の後に止める' .claude/agents/planner.md` の出力が `1`
- planner.md の「書き終えた後の確認」節に確認の行がある：`grep -c 'バッククォートの有無で食い違っていないか' .claude/agents/planner.md` の出力が `1`
- 経緯集に Issue #204 の経緯がある：`grep -c 'Issue #204' vault/rules/planner/ai-harness-lessons.md` の出力が `1`
- smoke の参照切れの検査が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`

## 決定済み
- planner.md の「やらないこと」節の末尾（「確認コマンドの grep パターンに、シェルの特殊文字…」の箇条の後）に、1行の箇条を1つ足す。書き出しは「- 「決定済み」に書いた文言のバッククォートをまたいで、受け入れ基準の grep の文字列を抜き出さない。」とする（この文をそのまま書く）
- その箇条に書くこと（すべて同じ1行の中に書く）：
  - 理由：creator は「決定済み」どおりにバッククォート（Markdown のコード）ごと書くので、バッククォートを落とした `-F` の文字列は当たらず、blocked と `/plan unblock`・`scripts/amend_task.py` の差し替えが要った（Issue #204）
  - 書き方：バッククォートをまたがない部分文字列を選ぶか、バッククォートを `.` に置き換えたパターン（`-F` を付けない）にする。grep パターンにバッククォートを直接書かないのは、上のシェルの特殊文字の箇条のとおり
  - 例：決定済みの文言が「`{Xxx}JobConfig`。命名は方式設計 §11」なら、`grep -c '.{Xxx}JobConfig.。命名は方式設計 §11' <ファイル>` にする（決定済みの文言の例とこのパターンの例を、この箇条の同じ行に書く。planner.md のほかの行に `JobConfig` を書かない）
  - 仕組み：「`.claude/hooks/plan_guard.py` が draft のタスク票の Write・Edit の後に止める」という文をそのまま書き（パス `.claude/hooks/plan_guard.py` はバッククォートで囲む）、止めるのは `-F` の固定文字列と、`[ ] * ^ $ \` を含まない基本正規表現で、`-E`・`-P` のパターンは止めないので自分で確かめる、と書く
- planner.md の「書き終えた後の確認」節に、1行の箇条を1つ足す。「受け入れ基準の grep の文字列が「決定済み」の文言とバッククォートの有無で食い違っていないか」の文言をそのまま含める（plan_guard の対象外の `-E`・`-P` も含めて見る、と添えてよい）
- 「やらないこと」節の既存の箇条（特に「成果物本文に無い文字列を grep する…」と「確認コマンドの grep パターンに、シェルの特殊文字…」）は書き換えない。新しい箇条から参照するだけにする（重複・矛盾を作らない）
- 経緯集 `vault/rules/planner/ai-harness-lessons.md` の「## ルール」節の最後の項目（「確認コマンドを `python3 -c` の中の subprocess…」）の後に、既存と同じ書式（太字の教訓の行と、`- 経緯：` で始まる行）で1項目を足す。教訓の行は「**「決定済み」の文言のバッククォートをまたいで grep の文字列を抜き出さない**」。経緯の行には、導入先の計画の T-03 で、受け入れ基準が `-F` の `{Xxx}JobConfig。命名は方式設計 §11`、決定済みの置換文言がバッククォートありの「`{Xxx}JobConfig`。命名は方式設計 §11」だったため、creator が決定済みどおりに書いて基準が通らず blocked になり、人の `/plan unblock` と `scripts/amend_task.py` の `--replace-criterion` が要ったこと、Issue #204 として ai-harness に移され、`P-20261017-planner-criterion-literal` で plan_guard の検査と planner.md の箇条を足したことを書く。`Issue #204` の文字列はこの経緯の行に1回だけ書く
- 経緯集の「## 目的」「## 確認方法」節は変えない
- planner.md には、存在しないパスをバッククォートで書かない（`(ref-1)` の対象。`.claude/hooks/plan_guard.py`・`scripts/amend_task.py` は既にある）
- `docs/vault-spec.md`・`.claude/hooks/plan_guard.py`・`.claude/skills/plan/SKILL.md` はこのタスクでは変えない
- planner.md の frontmatter と、「やらないこと」「書き終えた後の確認」以外の節は変えない
