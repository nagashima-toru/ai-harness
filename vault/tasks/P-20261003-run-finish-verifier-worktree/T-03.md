# T-03 verifier ルールの worktree の扱いを絶対パス方式に書き換える提案を書く

## 目的
`vault/rules/verifier/verifier.md` の「責務」にある worktree の扱い（`EnterWorktree` で入り、`ExitWorktree` で戻る前提）を、verifier が実際にやっている「worktree に入らず、絶対パスと `git -C` で検証し、verdict はメインリポジトリ側に書く」形に書き換える提案を作る（issue #89 の2点目）。

## 入力
- `vault/rules/verifier/verifier.md`（現行の実体。17行目が書き換えの対象）
- `.claude/agents/verifier.md` の4行目（tools に `EnterWorktree`/`ExitWorktree` が無い）
- `docs/vault-spec.md` 12節「提案ファイル方式」

## 成果物
- `vault/tasks/P-20261003-run-finish-verifier-worktree/T-03-proposal.md`：`vault/rules/verifier/verifier.md` を変更した後の全文（`vault/rules/` には書けないため提案ファイル方式。実体への反映は人が行う）

## 受け入れ基準
- 提案ファイルが変えたのは17行目の1行だけ。確認：`diff vault/rules/verifier/verifier.md vault/tasks/P-20261003-run-finish-verifier-worktree/T-03-proposal.md` の出力がちょうど4行（`17c17`、`<` で始まる1行、`---`、`>` で始まる1行）
- 書き換えた行が「決定済み」の文と一字一句同じ。確認：`grep -c -F -e '- verifier は対象 worktree に入らない（`EnterWorktree`・`ExitWorktree` は使わない）。' vault/tasks/P-20261003-run-finish-verifier-worktree/T-03-proposal.md` が `1`。あわせて、その行（Read で17行目を読む）が「決定済み」の書き換え後の文と同じ
- 提案ファイルが `ExitWorktree(action` の手順を含まない。確認：`grep -c -F 'ExitWorktree(action' vault/tasks/P-20261003-run-finish-verifier-worktree/T-03-proposal.md` が `0`
- 書き換えた行に、このリポジトリ固有の issue 番号・計画 ID が無い。確認：`grep -nE 'issue #|P-20[0-9]{6}' vault/tasks/P-20261003-run-finish-verifier-worktree/T-03-proposal.md` の出力が空

## 決定済み
- 成果物は提案ファイル1つ。`vault/rules/verifier/verifier.md` の実体は編集しない（ガードが常に拒否する）。中身は変更後の全文にする（差分ではない）。17行目以外は1文字も変えない（28行目の `T-0002` などの既存の文言もそのまま残す）
- 17行目を、まるごと次の1行に置き換える（一字一句同じ。行頭の `- ` を含む）：
  `` - verifier は対象 worktree に入らない（`EnterWorktree`・`ExitWorktree` は使わない）。プロンプトに「対象 worktree: `<path>`」が含まれる場合は、git は `git -C <path> ...`、ファイルは `<path>/` から始まる絶対パスで読み、作業ディレクトリが要るコマンドは同じ Bash 呼び出しの中で `cd <path>` してから実行する。`vault/verdicts/<id>.json` はメインリポジトリ側のパス（`$CLAUDE_PROJECT_DIR` を基準にした絶対パス）に書き、worktree の下には書かない。 ``
- 方針（人の代理の設計判断。変えない）：verifier に `EnterWorktree` を持たせない。この文は T-02（run スキル手順5の2）・T-04（エージェント定義の手順1・11）と同じ趣旨にそろえてある
- 19行目（起点コミットの検査）は変えない。`git diff --name-only` などを worktree に向けて実行することは、17行目の「git は `git -C <path> ...`」で足りる
- 「確認方法」節に行は足さない
- コミットは不要（受け入れ基準に無い）
