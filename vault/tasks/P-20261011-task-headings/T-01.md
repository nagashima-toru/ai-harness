# T-01 plan_guard.py にタスク票の6見出しの検査を足し、smoke にケースを足す

## 目的
draft の計画のタスク票に `vault/templates/task.md` の6見出し（目的・入力・成果物・受け入れ基準・決定済み・進捗）が欠けていれば、planner が書いた時点で `plan_guard.py` が止める（Issue #166）。あわせて、見出しの無いタスク票に creator が見出しごと追記した時に差分ゲートを通ることを smoke で確かめる。

## 入力
- `.claude/hooks/plan_guard.py`（`granularity_violation` と `main` の呼び出し順）
- `.claude/hooks/_hooklib.py`（`plan_id_and_status`・`count_criteria`）
- `vault/templates/task.md`（6見出し）
- `scripts/smoke.sh`（`make_task`・`run_plan_guard_file`・`(granularity-task)` のケース・`== diff_gate.py` の節の `dg_task`・`dg_setup`・`dg_run`・`expect_eq`）
- `scripts/diff_gate.py`（`_split_sections`・`_non_progress`）
- `docs/vault-spec.md` の5節・10節（読むだけ。変えない）

## 成果物
- 主な成果物：`.claude/hooks/plan_guard.py` に追加する見出しの検査（関数 `heading_violation`）
- 付随して変えるファイル：`scripts/smoke.sh`（ケースの追加と `make_task` の修正）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (headings-task) '` の出力が `5`
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (diff_gate-progress) '` の出力が `2`
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (granularity-task) '` の出力が `9`（既存の粒度のケースが見出し検査を足した後もすべて通る）
- `grep -n '^def heading_violation(payload, root):' .claude/hooks/plan_guard.py` の出力が1行
- `grep -rL --include='T-*.md' '^## 進捗$' vault/tasks/` の出力が空（この計画のタスク票もすべて「## 進捗」の見出しを持つ）

## 決定済み
- 検査は `plan_guard.py` に置く。`.claude/skills/plan/SKILL.md` の手順5は変えない（フックが Write/Edit の時点で機械的に止めるので、手順5の目視の確認に足す必要が無い）
- 関数のシグネチャは `def heading_violation(payload, root):`。対象外・問題なしは `None`、違反は理由文（str）を返す。契機と fail-open は `granularity_violation` と同じにする：`tool_name` が `Write` か `Edit`、`file_path` がリポジトリ相対で `vault/tasks/<計画ID>/T-<2桁>.md`（`TASK_PATH_RE`）、計画票 `vault/plans/<計画ID>.md` の status が `draft` の時だけ検査する。計画票が無い・読めない・status が取れない・タスク票が読めない時は `None`。Bash・MultiEdit・approved 以降は検査しない
- 必須の見出しは `## 目的`・`## 入力`・`## 成果物`・`## 受け入れ基準`・`## 決定済み`・`## 進捗` の6つ。各行を `rstrip()` した結果が見出しと完全一致する行があれば「ある」とする。順序は検査しない。見出しの下の本文が空でもよい（「## 進捗」は本文が空なのが正しい形）
- 理由文は次の形にする（欠けた見出しは上の6つの順に「、」でつなぐ）：`[plan_guard] <計画ID>/<id> のタスク票に見出しが足りません（## 決定済み、## 進捗）。vault/templates/task.md の6見出し（## 目的・## 入力・## 成果物・## 受け入れ基準・## 決定済み・## 進捗）をそろえてください。「## 進捗」は見出しだけを書き、本文は空にします。`
- `main` では `heading_violation` を `granularity_violation` より前に呼び、違反なら `block` する（見出しが欠けた票で受け入れ基準の行数「0行」という分かりにくい理由が先に出ないようにするため）
- モジュール先頭の docstring に、この検査を1行で書き足す
- smoke の `make_task` は6見出しをこの順で書く形に直す：`## 目的`・`## 入力`・`## 成果物`（3つとも本文は空でよい）、`## 受け入れ基準`（今と同じく `- 基準<i>` を $2 行）、`## 決定済み`、`## 進捗`（本文なし）。引数（$1=id $2=行数）は変えない。既存の `(granularity-task)` 9ケースの名前と期待値は変えない
- `(headings-task)` のケースは次の5つちょうどにし、名前は `(headings-task) ` で始める。置き場所は `(granularity-task)` のケースの直後（`rm -rf "$TMP/vault/tasks"` の前でも後でもよいが、draft の計画票を置き直してから実行する）。見出しを欠いた票は、6見出しの票から該当の見出し行を除く形で作ってよい（ヘルパーの追加は任せる）
  1. draft・「## 進捗」だけ欠落 → block、理由に `## 進捗` を含む
  2. draft・「## 決定済み」と「## 進捗」が欠落 → block、理由に `## 決定済み、## 進捗` を含む
  3. draft・6見出しそろい・基準3行 → allow
  4. approved・「## 進捗」欠落 → allow（検査しない）
  5. draft・「## 進捗」欠落・tool_name が Bash → allow（対象外）
- `(diff_gate-progress)` のケースは次の2つちょうどにし、`== diff_gate.py` の節の既存ケースの後に置く。名前は `(diff_gate-progress) ` で始め、`expect_eq` で終了コードを比べる。base（main）の T-01 のタスク票は、`dg_setup` の後に「## 進捗」の見出し行を除いた形で用意する（`dg_setup` の中で直接作る・main 側で除いてコミットし直すなど方法は任せる。既存の diff_gate のケースの結果は変えない）。base の票の末尾は `- なし` の行と改行1つで終わる形にする
  1. 既存の内容を変えず、末尾に空行1つ・`## 進捗` の行・`- 進捗の追記` の行を足してコミット → 終了コード 0
  2. 既存の内容を変えず、末尾に空行を挟まずに `## 進捗` の行・`- 進捗の追記` の行を足してコミット → 終了コード 1（直前の「決定済み」節の本文が変わったと判定される）
- `scripts/diff_gate.py` は変えない（2つ目のケースは現状の判定をそのまま記録するもの）
- 「成果物のみで他ファイル不変」の確認は書かない（差分ゲートに任せる）
