# T-03 smoke.sh に transition.py のケースを22件以上足す

## 目的
`scripts/transition.py`（T-01・T-02）の遷移・attempt・log の時刻とモデル・review→done の verdict 検査・拒否条件・question の置き換えを `scripts/smoke.sh` の回帰ケースにし、install 先でも同じ検査が走るようにする（D-012 フェーズ2の受け入れ基準の候補を smoke に起こす）。

## 入力

- `scripts/transition.py`（T-01・T-02 の成果物。使い方・終了コードは先頭の docstring）
- `scripts/smoke.sh`（`expect_eq`・`expect` の定義、`$TMP` と `trap` の後片付け、`== vcs_finish.sh ==` の一時 git リポジトリの作り方、`run_plan_guard` の呼び方）
- `vault/tasks/P-20261007-transition-basic/fixtures/try.sh`（T-01・T-02 の確認に使ったフィクスチャ。リポジトリの組み方の参考。smoke からは呼ばない）

## 決定済み
- 節は最後の節（`== bash-write-unify ==`）の後、最後の `echo` と `echo "smoke: pass=$PASS_N fail=$FAIL_N"` の前に足す。見出しは `echo "== transition.py（D-012 フェーズ2） =="` の字句どおり
- 判定は既存の `expect_eq`（名前・期待値・実際の値）を使う。ケース名はすべて `(transition) NN ` で始め（`NN` は下の一覧の2桁の番号）、後ろに内容を書く。1つの番号に1件以上の `expect_eq` を書いてよい（その時は同じ番号で始まる名前を複数使う）
- 一時リポジトリは `$TMP/tr` の下に作る（`$TMP` は既存の `trap` で消える）。ケースごとに `rm -rf` してから作り直すヘルパー関数（例：`tr_setup <preset>`）を節の中に定義する。形はフィクスチャ `try.sh` と同じでよい：
  - `git init -q -b main` → リポジトリ内の `git config user.name`・`user.email` → 計画票・log・agents をコミット → `git checkout -q -b work/p-test`
  - 計画票 `vault/plans/P-TEST.md`（`status: approved`）のタスク表に、必要な行（todo・after 付きの todo・doing・attempt が上限の doing・review・blocked など）を置く
  - verdict は未追跡のまま置く（run の実際と同じ）
  - agents は `.claude/agents/creator.md` に `model: smoke-creator`、`verifier.md` に `model: smoke-verifier`
- transition.py は `( cd "$TR" && python3 "$ROOT/scripts/transition.py" ... )` で呼ぶ。終了コードは `$?` で取る。「何も変えない」は、終了コードが1・`git rev-list --count HEAD` が前と同じ・計画票と log が前と同じ（`cmp -s` で写しと比べる）の3つを1つの `expect_eq` の値（例：`1 0 same same`）にまとめて見てよい
- 日時の検査：実行の直前と直後に `TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M'` を取り、log の追記行の日時がどちらかと一致することを見る
- 必須ケース（番号と内容。名前の後半の文言は自由）：
  - 01 2行の todo→doing で両行が doing・attempt=1 になる
  - 02 log に2行（`T-01 todo→doing attempt=1` と `T-02 …`）が追記される
  - 03 コミットが1つ増え、そのファイルが計画票と log だけ（`git show --name-only --format= HEAD`）
  - 04 log の追記行の日時が実行前後の JST と一致する
  - 05 doing→review の行が `creator=smoke-creator` で終わる
  - 06 review→done（正しい PASS）で done になり、行が `verifier=smoke-verifier` で終わる
  - 07 review→done のコミットに verdict のファイルが含まれる
  - 08 review→done・verdict 無し → 何も変えない（終了コード1）
  - 09 review→done・FAIL → 何も変えない
  - 10 review→done・attempt 不一致 → 何も変えない
  - 11 遷移先が todo → 何も変えない
  - 12 遷移先が approved → 何も変えない
  - 13 blocked の行からの遷移 → 何も変えない
  - 14 計画票が approved でない（draft）→ 何も変えない
  - 15 現在のブランチが `work/p-test` でない（main）→ 何も変えない
  - 16 after の依存が done でない行を doing にする → 何も変えない
  - 17 再試行で attempt が `HARNESS_MAX_ATTEMPTS` を超える → 何も変えない
  - 18 blocked にするのに question が無い → 何も変えない
  - 19 `--question-file` で `|` と改行を含む question を渡すと、表に `／` と空白で書かれ、その計画票で `plan_guard.py` が許可する（`printf '{"hook_event_name":"PostToolUse","tool_name":"Edit"}' | CLAUDE_PROJECT_DIR="$TR" python3 "$PLAN_GUARD_HOOK"` の出力に `"decision": "block"` が無い）
  - 20 複数 id のうち1つが拒否される時、全部の行が変わらない
  - 21 ほかに staged な変更があってもコミットに混ぜない（コミットのファイルに含まれず、staged のまま残る）
  - 22 `--no-model --note 中断から再開` の doing→review の行にモデルが付かず `attempt=1 中断から再開` で終わる
- question のファイルは `$TMP/tr_q.txt` などリポジトリの外に置く（リポジトリ内に置くと未追跡ファイルになる）
- 既存のケース・ヘルパー関数・節は変えない（足すだけ）
- `scripts/transition.py`・`docs/vault-spec.md`・フィクスチャは変えない
