# T-01 planner.md に確認コマンドで複合コマンドを避ける指針を追記する提案を書く（issue #48）

## 目的
`P-20260925-acceptance-test-sandbox-fp`/T-02 の調査（`T-02-findings.md`）で、"git" 等の語を含む文字列をパイプ・コマンド置換で組み合わせた複合コマンドが、Claude Code のツール実行時サンドボックス（worktree 隔離のための git 検出）に「即時拒否」または「無応答ハング」のどちらかを引き起こすことが分かっている（issue #46, #48）。今後 planner が受け入れ基準に書く確認コマンドで同種の複合コマンドを避けるよう、`vault/rules/planner/planner.md` への追記案をまとめる。ルール実体への反映は人が行うため、このタスクでは提案ファイルを書くところまでとする。

## 受け入れ基準
- 成果物ファイルの冒頭付近に、追記対象ファイルとして `vault/rules/planner/planner.md` と明記している。確認コマンド：`grep -c 'vault/rules/planner/planner.md' vault/tasks/P-20260925-sandbox-hang-timeout/T-01-proposal.md` の出力が `1` 以上
- 追記案の本文に「パイプ」という語がある。確認コマンド：`grep -c 'パイプ' vault/tasks/P-20260925-sandbox-hang-timeout/T-01-proposal.md` の出力が `1` 以上
- 追記案の本文に「コマンド置換」という語がある。確認コマンド：`grep -c 'コマンド置換' vault/tasks/P-20260925-sandbox-hang-timeout/T-01-proposal.md` の出力が `1` 以上
- 追記案の本文に issue #48 への参照がある。確認コマンド：`grep -c '#48' vault/tasks/P-20260925-sandbox-hang-timeout/T-01-proposal.md` の出力が `1` 以上
- 成果物は `T-01-proposal.md` のみで、他ファイルは変更していない（このタスク票 `T-01.md` 自身の「進捗」節への追記は対象外とする）。確認コマンド：`git status --porcelain | grep -v -e 'T-01-proposal.md' -e 'T-01.md'` の出力が空

## 決定済み
- 追記先は「やらないこと（このリポジトリで実際に起きた失敗から）」節の末尾（issue #46 対応で追記済みの `rm -rf` 前提の項目の直後）に1項目追加する形。既存項目の書き換えはしない
- 追記内容には少なくとも次の3点を含めること：(1) 確認コマンドにパイプ・`&&`・コマンド置換を含む複合コマンドを使うと、Claude Code のツール実行時サンドボックスが「即時拒否」または「無応答ハング」のどちらかを引き起こしうる（issue #46, #48）、(2) 対象は "git" という語を含む場合に限らない（issue #48 では `&&` 連結・末尾に `git status --porcelain | grep` を含む長い複合コマンドでもハングが再現している）ため、rm-rf 限定だった従来項目とは別に「複合コマンド全般」を対象にする、(3) 代替として、確認コマンドは素朴な単一コマンドに分解するか、事前にファイルへ書き出してから読む形にすることを推奨する
- 成果物ファイルの構成は自由（`vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-03-proposal.md` の「追記内容」「反映後の該当ファイル全文（参考）」という構成を踏襲してよいが必須ではない）
- `.claude/settings.json`・`.claude/hooks/`・`vault/rules/` の実体は変更しない（触らない）
- verifier が確認する grep 対象語（「パイプ」「コマンド置換」「#48」）は本タスク票の受け入れ基準・この決定済みで明示済みなので、提案文に必ずこれらの語を使うこと
- 受け入れ基準5は attempt=1〜3 で3回とも文字通りの確認コマンド（`grep -v 'T-01-proposal.md'` のみ）でFAILした。原因はタスク票自身の「進捗」節への追記が受け入れ基準に含まれておらずコミットされないため。人が2026-09-25に「進捗欄以外の変更がなければOK」と判断し、確認コマンドをタスク票自身のパスも除外する形に修正した（本ファイルの受け入れ基準5を参照）
