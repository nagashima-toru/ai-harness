# T-03 verifier 定義のコードレビューの判定を計画全体の差分に合わせる

## 目的
verifier の「コードレビューを参照する基準の判定」の節を、計画単位のレビュータスクで計画全体の差分（ベースブランチとの分岐点から）を判定する形に直す。差分の外・致命的でない指摘・人の判断・呼べなかった時の扱いは現行どおり。

## 入力
- `.claude/agents/verifier.md`（「## 手順」の3・「## コードレビューを参照する基準の判定」）
- `docs/vault-spec.md` 1節の `HARNESS_BASE_BRANCH` の段落・6節の `reasons`・11節の「コードレビューを参照する受け入れ基準」（現行の要約。このタスクでは変えない）

## 成果物
- `.claude/agents/verifier.md`（1ファイル）

## 受け入れ基準
- 節の見出しが変わっていない：`grep -c '^## コードレビューを参照する基準の判定' .claude/agents/verifier.md` が `1`
- 判定の範囲がベースブランチとの分岐点からの差分になっている：`grep -c 'diff --merge-base .ベースブランチ.' .claude/agents/verifier.md` が1以上
- 対象の行の既定の書き方が計画の差分になっている：`grep -c 'で計画の差分に致命的な指摘が残っていない' .claude/agents/verifier.md` が1以上、かつ `grep -c '計画単位のレビュータスク' .claude/agents/verifier.md` が1以上
- 差分の外と人の判断の接頭辞が現行どおり残っている：`grep -c '対象外（既存コード）: ' .claude/agents/verifier.md` が1以上、かつ `grep -c '人の判断が必要: ' .claude/agents/verifier.md` が1以上
- タスク単位の範囲・導入先任せ・レビューを強制しないの古い記述が残っていない：`grep -c -e 'そのタスクの差分' -e '導入先の planner ルール' -e 'で差分に致命的な指摘' -e 'レビューを強制しない' .claude/agents/verifier.md` が `0`
- smoke の `(ref-1)` が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- 見出し `## コードレビューを参照する基準の判定` は変えない（`docs/vault-spec.md` が節の名前で参照しているため）。番号付きの7項目の構成も保つ
- 1（対象の行）：既定の書き方を「`/code-review` で計画の差分に致命的な指摘が残っていない」にする。この行を持つのは planner が計画の最後に足す「計画単位のレビュータスク」（`.claude/agents/planner.md` の「計画単位のレビュータスク」節）で、通常のタスクの基準には入らない旨を書く。「どのタスクにレビューを求めるかは導入先の planner ルールが決め、ハーネスはレビューを強制しない」の記述は消す。説明・引用しているだけの行は対象にしないこと、基準に無ければ `/code-review` を呼ばないことは残す
- 2（範囲と呼び方）：対象は計画全体の差分で、`git -C <worktree のパス> diff --merge-base <ベースブランチ>` の差分（ベースブランチとの分岐点から HEAD まで。verifier の時点では収集コミットの後なので作業ツリーとの差分と同じ）と書く。ベースブランチは環境変数 `HARNESS_BASE_BRANCH`（前後の空白を除いて空なら `main`）。ローカルにベースブランチの ref が無ければ `origin/<ベースブランチ>` を使い、どちらも無ければ7（呼べなかった時）と同じ扱いにする。計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない（状態ファイルで、PR の前に除去されるため）。Skill ツールで `code-review` を呼び、対象 worktree のパスを明示して渡すこと・基準の行の引数の扱い（ハーネスは既定値を持たない）は現行どおり。呼び方の例は「対象は <worktree の絶対パス>。cd してから `git diff --merge-base <ベースブランチ>` の差分をレビューする（計画一式4種は除く）」にする
- 3（致命的な指摘）：「差分で変えた行」を「計画の差分で変えた行」にする。判定（1件でも残れば `ok: false`、`reasons` に要点）は現行どおり
- 4（差分の外）：「計画の差分で変えていない既存コード」への指摘とする。`対象外（既存コード）: ` の接頭辞と `ok: true` のままにする扱いは現行どおり
- 5（人の判断）・6（致命的でない指摘）・7（呼べなかった時）：現行どおり（`人の判断が必要: ` の接頭辞を変えない）
- 「## 手順」の3と「## 手順」の7の note の書式例（`git diff --merge-base work/<計画IDの英小文字> --numstat -- README.md`）は変えない（後者は通常の差分確認の例でコードレビューの範囲ではない）
- ほかの節と frontmatter（tools・model）は変えない（smoke の `(agents-2)` が tools の Skill を検査している）
- `.claude/agents/creator.md`・`.claude/agents/planner.md` などほかのファイルは別のタスクで直すので変えない
