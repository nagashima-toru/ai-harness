# T-02 creator の tools に Skill を足し、完了前のコードレビューの手順を書く

## 目的
creator が Claude Code 組み込みの `/code-review`（Skill の `code-review`）を呼べるようにし、受け入れ基準がコードレビューを参照する時は、完了報告の前に verifier と同じ範囲でレビューして差分内の致命的な指摘を直してから返すようにする（GitHub Issue #214 の提案1・3。差し戻しを減らすため）。

## 入力
- `.claude/agents/creator.md`（今の定義。tools・手順・受け渡し・禁止・やらないこと・完了前の確認）
- `docs/vision.md` の原則5・7

## 成果物
- `.claude/agents/creator.md`（1ファイル）

## 受け入れ基準
- `grep -c '^tools: Read, Grep, Glob, Bash, Write, Edit, Skill$' .claude/agents/creator.md` の出力が `1` である
- `grep -c '^## コードレビューを参照する基準がある時$' .claude/agents/creator.md` の出力が `1` である
- `grep -c 'クラッシュ・データ破損・誤った結果' .claude/agents/creator.md` の出力が `1` である
- 「## コードレビューを参照する基準がある時」節が、決定済みの (1) 対象の行の見分け方 (2) 範囲と呼び方（worktree のパスを引数で明示する） (3) 差分で変えた行への致命的な指摘を直し、直した後にもう1回だけ実行して確かめること (4) 差分の外への指摘は直さないこと (5) 設計・仕様の変更が要る指摘は直さずに「blocked: <質問文>」で返すこと (6) 「進捗」に残すこと の6点をすべて書いている（Read で節を読んで確かめる）
- 「## 完了前の確認」節に、コードレビューを参照する基準がある時は (3) の確認を済ませたかを問う箇条が1つある（Read で確かめる）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1` である

## 決定済み
- tools の行は `tools: Read, Grep, Glob, Bash, Write, Edit, Skill` にする（`Skill` を末尾に足すだけ。他のツールは足さない・順序を変えない）。`model` などほかの frontmatter は変えない
- 新しい節の見出しは `## コードレビューを参照する基準がある時` とし、「## 手順」節の後・「## 受け渡し」節の前に置く。「## 手順」の手順6（完了報告の前に確認コマンドをすべて通す）に、コードレビューを参照する基準がある時はこの節も済ませる旨の1文を足してよい
- 節に書く内容（語句は次のとおりに書く。判定の正本は `.claude/agents/verifier.md` の同名の趣旨の節で、creator は同じ範囲・同じ基準で先回りする）：
  - (1) 対象の行：受け入れ基準の行が `/code-review` の結果で真偽を決める行である時だけ行う。書き方の既定は「`/code-review` で差分に致命的な指摘が残っていない」。行の中で `/code-review` を説明・引用しているだけの行は対象にしない。基準に無ければ `/code-review` を呼ばない（ハーネスはレビューを強制しない。どのタスクに求めるかは導入先の planner ルールが決める）
  - (2) 範囲と呼び方：対象はそのタスクの差分で、`git -C <worktree のパス> diff --merge-base work/<計画IDの英小文字>` の差分（計画ブランチとの分岐点 PLAN_HEAD から作業ツリーまで。未コミットの変更も含む）。Skill ツールで `code-review` を呼び、引数に自分の worktree の絶対パス（`pwd` で得る）を明示して渡す（例：「対象は <worktree の絶対パス>。cd してから `git diff --merge-base work/<計画IDの英小文字>` の差分をレビューする」）。明示しないと別の作業ディレクトリをレビューしうることを理由として書く。受け入れ基準の行に `/code-review` の引数（`effort`・`--max-findings` など）があればそのまま渡し、無ければ付けない
  - (3) 直すもの：差分で変えた行への指摘のうち、クラッシュ・データ破損・誤った結果 に当たるものを直す。直した後に同じ範囲でもう1回だけ実行して確かめ、それ以上は繰り返さない（判定は verifier が行う）。語句「クラッシュ・データ破損・誤った結果」はファイル中に1回だけ書く
  - (4) 直さないもの：差分の外（既存コード）への指摘と、致命的でない指摘（好み・軽微な改善）は直さない（受け入れ基準に無い作業を足さない。「成果物」に宣言されていないファイルの変更は差分ゲートが差し戻す）
  - (5) 人に渡すもの：直すのに設計・仕様の変更が要る指摘は、直さずに「進捗」に理由を書き、完了報告を「blocked: <質問文>」にして返す（既存の手順5と同じ扱い）
  - (6) 記録：「進捗」に、`/code-review` を実行した回数と、差分内の致命的な指摘の件数と直したかどうかを書く
- 「## 完了前の確認」節には、上の (3) の確認（差分内の致命的な指摘を直し、もう1回の実行で確かめたか）を問う箇条を1つ足す
- 「起点コミット」の語は使わない（smoke の `(agents-1)` が禁じている）
- 新しく作るファイルへのバッククォート参照は書かない（`(ref-1)` のため）
- verifier の定義（`.claude/agents/verifier.md`）は T-01 が変えるので、このタスクでは変えない
