# T-01 planner.md に python3 -c 内の subprocess で外部コマンドを呼ぶ確認コマンドを禁じる指針を足す

## 目的
確認コマンドを `python3 -c` の中から subprocess で git などの外部コマンドを呼ぶ形で書くと、creator の worktree でツールの制限により拒否される（Issue #187 の提案1）。planner がその形の基準を書かないよう、`.claude/agents/planner.md` に指針と確認項目を1つずつ足す。

## 入力
- `.claude/agents/planner.md`（「## やらないこと」の複合コマンドの箇条（`- 確認コマンドを、パイプ・` で始まる行）と、「自分で読み取り専用で実行しないまま」の箇条、「## 書き終えた後の確認」節）
- `scripts/smoke.sh` の `refcheck`（`(ref-1)` の検査）

## 成果物

## 決定済み
- 新しい箇条は「## やらないこと」の、`- 確認コマンドを、パイプ・` で始まる複合コマンドの箇条（現在71行目）の直後に、1行（改行を含まない1つの箇条）で挿入する。ほかの箇条の順番・文言は変えない
- 新しい箇条は次の文言で始めること：`` - 確認コマンドを、`python3 -c` の中から subprocess `` （続けて「（`subprocess.check_output` 等）で git などの外部コマンドを呼ぶ形にしない。」のように書く）。「の中から subprocess」という語句はこの箇条でだけ使う
- 新しい箇条に書く内容と順番：(1) 理由：導入先で planner が書いた `python3 -c` 内の `subprocess.check_output(['git','show',...])` を使う基準が、creator の worktree でツールの制限により拒否され、creator が `git show` を単独で実行してファイルに保存し、読み込み元を差し替える回避が必要になった（Issue #187）。(2) 代わりの書き方：外部コマンドは「単独のコマンド」として基準に書き、出力の一部を見たい時に限り「パイプ1段」（上の複合コマンドの箇条と同じ）にする。Python での処理が要る時は、外部コマンドを呼ばずに済む形（標準入力から読む、リポジトリ内のファイルを読む）にする。(3) 上の「自分で読み取り専用で実行しないまま受け入れ基準に書かない」と合わせ、planner 自身が確認コマンドをガードを通る形（単独のコマンド・パイプ1段）で「試走」してから書く。「単独のコマンド」「パイプ1段」「試走」の3語をこの順で含めること
- 「## 書き終えた後の確認」節（ゴール文の「自己チェック」はこの節を指す）に確認項目を1つ箇条で加える。位置は「複合コマンド」に触れている3つ目の箇条（`- run で必ず差分が出るファイルの不変検査、` で始まる行）の直後。文言は「`python3 -c` の中の subprocess で git などの外部コマンドを呼ぶ確認コマンドが基準に混ざっていないか。試走したか」の趣旨で書き、「の中から subprocess」という語句は使わない（受け入れ基準3の grep が新しい箇条だけに当たるようにするため）
- subprocess という語は、上の2箇所（新しい箇条と確認項目）にだけ書く。各箇所で1行に収める（改行しない）
- 既存の「自分で読み取り専用で実行しないまま」の箇条（現在67行目）は変えない。両立は新しい箇条の中で書く
- バッククォートの中にリポジトリのパスを書く時は、存在するパスだけを書く（`(ref-1)` が存在しないパスで NG になる）。`python3 -c` や `subprocess.check_output` は `vault/`・`scripts/`・`docs/`・`.claude/` で始まらないため検査されない
- 経緯集 `vault/rules/planner/ai-harness-lessons.md` は変えない（このタスクの成果物ではない）。`.claude/skills/plan/SKILL.md`（Issue #187 の提案2、実装済み）も変えない
- 「古い記述が残っていない」ことの確認は、このゴールが追加のみで既存の記述を置き換えないため不要。subprocess の記述の範囲は planner.md に限る（ほかの文書に同じ指針を足すことはゴールに含まれない）
