# T-02 transition.py の done に --worktree（差分ゲート・--no-ff マージ・衝突時の blocked・後始末）を足す

## 目的
`python3 scripts/transition.py <計画ID> <id> done --worktree <パス> --branch <ブランチ> --plan-head <sha>` で、PASS の verdict と差分ゲートを確かめてから計画ブランチへ `git merge --no-ff` し、done にしてコミットし、worktree とブランチを消すまでを1コマンドで行えるようにする。衝突したらマージを中止して review→blocked にする（D-012 フェーズ4の (2)）。

## 決定済み
- 呼び出し：`done --worktree <パス> --branch <ブランチ> --plan-head <sha>`。`--plan-head` は必須（無ければ終了コード2）。id は1つだけ。T-01 で「まだ対応していない」として終了コード2にしていた done の `--worktree` を受け付けるようにする（doing・blocked は T-03 まで2のまま）
- 検査の順（どれかに当たったら何も変えずに終了コード1）：
  1. フェーズ2の検査（review→done が遷移表にある＝今の status が review、ほか）と、PASS の verdict の検査（フェーズ2と同じ `_hooklib.done_rows_without_pass`）
  2. T-01 の worktree とブランチの検証
  3. `--plan-head` の40桁への解決
- done では収集コミットをしない。worktree の未コミット・未追跡のファイル（verifier がコマンドを実行して生じたものなど）はマージに入れない（D-012 の決定事項。収集は review の時だけ）
- 検査が通った後の順：
  1. 新規コミットの判定（T-01 と同じ `rev-list --count <plan_head>..<branch>`）。0なら review→blocked。question は `worktree に新規コミットが無い（マージ対象の差分が無い）`、log の補足は `新規コミット無し`
  2. 差分ゲート（T-01 と同じ呼び出し。base は plan_head の40桁）。review の後に worktree のブランチは変わらないはずだが、マージする内容をもう一度確かめる。`GateError` なら終了コード1（何も変えない）。違反があれば review→blocked。question と log の補足は `宣言外の変更: <パス一覧>`（タスク票の「進捗」には書かない。差し戻しではないため）
  3. マージ：メインの作業ツリー（計画ブランチ）で `git -C <root> merge --no-ff <branch> -m "<計画ID>/<id>: マージ"` を実行する
  4. マージが成功したら、フェーズ2の review→done と同じ書き換えとコミット（計画票・log・verdict を `git commit -m "<計画ID>/<id>: review→done" -- <パス...>`。`verifier=` はフェーズ2の規則どおり付く）を行い、その後で後始末：`git worktree remove --force <realpath>` → `git branch -d <branch>`（`--force` は verifier の実行で残った未追跡ファイルがあっても消せるようにするため。ブランチはマージ済みなので `-d` で消える）。終了コード0、標準出力はフェーズ2と同じ1行
- マージが失敗した時：
  - `git -C <root> diff --name-only --diff-filter=U` で衝突ファイルを取ってから、マージ中の状態（`git rev-parse --git-path MERGE_HEAD` のファイル）があれば `git -C <root> merge --abort` で中止する。`git status` にマージ中の状態を残さない
  - 衝突ファイルが1つ以上あれば、question は `マージで衝突したファイル: <ファイル一覧>`（`, ` でつなぐ）、log の補足は `マージコンフリクト`
  - 衝突ファイルが無い失敗（作業ツリーの変更で上書きできない等）は、question を `マージに失敗した: <git の標準エラーの最初の行>`、log の補足を `マージ失敗` にする
  - どちらも review→blocked にして計画票と log をコミットし、worktree とブランチは残す（人が調査に使う）。終了コード4
- review→blocked の行の `verifier=` はフェーズ2の規則どおり付く（`--no-model` なら付けない）。`--note` は自動の補足の後ろに付く
- 終了コード4の時の標準出力は T-01 と同じ形の1行：`<計画ID>/<id>: review→blocked attempt=<n> <question>。worktree を残した`
- マージは成功したが、その後の状態のコミットに失敗した時は、計画票と log を元に戻し、マージコミットは取り消さずに、理由（マージ済みであること）を標準エラーに出して終了コード1にする。後始末（worktree・ブランチの削除）に失敗した時は標準エラーに警告を出し、終了コードは0のままにする
- コミットの件名はフェーズ2のまま変えない（`scripts/pr_body.py` が `<計画ID>/<id>: done` を探す件とは、計画票の「人への質問」で扱う。このタスクでは `pr_body.py` を変えない）
- 先頭の docstring に done の動きを書き足す
- `scripts/smoke.sh`・`docs/vault-spec.md`・`scripts/diff_gate.py`・`scripts/discard_worktree.sh`・`scripts/pr_body.py`・`.claude/skills/run/SKILL.md`・`.claude/hooks/` は変えない。フィクスチャ `try.sh` は変えない
