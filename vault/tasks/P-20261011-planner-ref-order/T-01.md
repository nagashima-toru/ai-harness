# T-01 planner.md に新規ファイルへの参照順の規則と確認項目を足す

## 目的
planner が、計画の中で新しく作るファイルのパスを、そのファイルを作るタスクより前のタスクの `(ref-1)` 対象文書に書かせないようにする（Issue #172）。

## 入力
- `.claude/agents/planner.md`（「やらないこと」節の `(ref-1)` の項目と、「書き終えた後の確認」節）
- `scripts/smoke.sh` の `refcheck`（2701行付近。対象の文書一覧と、バッククォート内のパスの存在検査）
- `vault/rules/planner/ai-harness-lessons.md`（経緯集の書式）

## 成果物
- `.claude/agents/planner.md`（主な成果物）
- `vault/rules/planner/ai-harness-lessons.md`（経緯を1項目足す）

## 受け入れ基準
- 「やらないこと」節に、新しく作るファイルのパスへのバッククォート参照を、そのファイルを作るタスクかその後のタスクに入れる規則の項目が1つある：`awk '/^## やらないこと/{f=1;next} /^## /{f=0} f' .claude/agents/planner.md | grep -c '計画の中で新しく作るファイルのパス'` が `1`
- 「書き終えた後の確認」節に、この点の確認項目が1つある：`awk '/^## 書き終えた後の確認/{f=1;next} /^## /{f=0} f' .claude/agents/planner.md | grep -c 'そのファイルを作るタスクより前のタスク'` が `1`
- 経緯集に経緯の項目が1つある：`grep -c '^\*\*新しく作るファイルへの参照は、そのファイルを作るタスク以降に入れる\*\*$' vault/rules/planner/ai-harness-lessons.md` が `1`
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 「やらないこと」節の新しい項目は、既存の `(ref-1)` の項目（「smoke の `(ref-1)` が検査する文書…を成果物に持つタスクに…」）の直後に1行の箇条書き（`- ` で始まる1行）で足す。その1行に「計画の中で新しく作るファイルのパス」という語をそのまま書くこと。内容は次の趣旨：`(ref-1)` の対象文書（`scripts/smoke.sh` の `refcheck` が見る文書。README・docs の文書や `.claude/agents/planner.md` 自身も含む）に、計画の中で新しく作るファイルのパスをバッククォートで書く変更は、そのファイルを作るタスクか、それより後（`after` でそのタスクに依存させた）タスクに入れる。理由として、先行タスクに書くとその時点ではファイルが無く `(ref-1)` が NG になり、`fail=0` や `(ref-1)` の基準と同時に満たせない（受け入れ基準どうしが矛盾する）ことを書く。代わりの書き方として、そのファイルを作るタスクの成果物に参照の追加も含める（同じタスクで作って参照する）か、参照を足すタスクを別に起こして `after` で依存させることを書いてよい
- 「書き終えた後の確認」節には、既存の `(ref-1)` の確認項目の行の直後に1行の箇条書きを足す。その1行に「そのファイルを作るタスクより前のタスク」という語をそのまま書くこと。内容の趣旨：計画の中で新しく作るファイルへのバッククォート参照が、そのファイルを作るタスクより前のタスク（`after` で依存させていないタスクを含む）の成果物に入っていないか
- 既存の `(ref-1)` の項目・確認項目の文言は変えない（足すだけ）
- 新しく書く文の中のバッククォートで囲むパスは、実在するパス（例：`scripts/smoke.sh`・`.claude/agents/planner.md`）か、`<` `*` などを含む雛形にする。例として存在しないパスをバッククォートで書かない（`(ref-1)` が NG になる）。背景の例に出す `docs/guide.md` は実在するので書いてよい
- 経緯集 `vault/rules/planner/ai-harness-lessons.md` には、「## ルール」節の最後の項目（「単語の出現有無・回数だけを唯一の確認コマンドにしない」）の後ろ、「## 確認方法」の前に、既存項目と同じ書式で足す。見出し行は `**新しく作るファイルへの参照は、そのファイルを作るタスク以降に入れる**` の1行そのもの（行頭から行末までこの文字列だけ）にし、続けて `- 経緯：` で始まる1行に「P-20261011-user-guide-entry の T-01 で `.claude/agents/planner.md` に、後続の T-02 で作る `docs/guide.md` をバッククォートで書かせたため、smoke の `(ref-1)` が NG になり `fail=0` の基準と同時に満たせず blocked になった（issue #172）」の趣旨を書く。項目の前後の空行は既存項目に合わせる
- `vault/rules/` 配下は `refcheck` の検査対象外なので、経緯集に書くパスの存在は `(ref-1)` に影響しない
- smoke は1分強かかる。2つの smoke の基準は別々に実行してよい

## 進捗

- planner.md に規則項目と確認項目を追加、ai-harness-lessons.md に経緯を追加
- 基準5件の確認コマンドを実行し、1/1/1/1/fail=0 を確認済み
