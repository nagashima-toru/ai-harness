# T-03 README の仕組み節の図を ASCII だけの図と番号付き手順にする

## 目的
「## 仕組み」節の図は日本語ラベル（全角文字）のせいで等幅表示でも縦線・矢印がずれる。図を ASCII 文字だけで描き直して桁をそろえ、日本語の説明は図の下の番号付き手順に移して、今の図にある情報を失わないようにする。

## 入力
- `README.md`（T-02 の後の版。「## 仕組み」節の図と、その下の PR のマージの段落）
- `.claude/skills/run/SKILL.md`（流れの確認用）

## 成果物
- `README.md`（1ファイル。「## 仕組み」節だけを変える）

## 受け入れ基準
- 仕組み節のコードブロック（図）が ASCII 文字だけで8行以上ある。確認：`awk '/^## 仕組み/{s=1;next} /^## /{s=0} s&&substr($0,1,3)=="\140\140\140"{c=!c;next} s&&c' README.md | grep -cP '[^\x00-\x7F]'` の出力が `0`、かつ `awk '/^## 仕組み/{s=1;next} /^## /{s=0} s&&substr($0,1,3)=="\140\140\140"{c=!c;next} s&&c' README.md | grep -c .` の出力が `8` 以上
- 図の縦線（`|`）と矢印の桁が、同じレーンの中で行をまたいでそろっている（verifier が `README.md` の図を等幅で読んで確認する。ASCII だけなので文字数＝表示幅で判定できる）
- 仕組み節に番号付き手順が6項目以上あり、今の図の情報が残っている。確認：`awk '/^## 仕組み/{s=1;next} /^## /{s=0} s' README.md | grep -cE '^[0-9]+\. '` の出力が `6` 以上。`awk '/^## 仕組み/{s=1;next} /^## /{s=0} s' README.md | grep -oF -e '/plan <ゴール>' -e 'work/<計画ID>' -e 'planner' -e 'approved' -e '/run' -e 'creator' -e 'worktree' -e 'verifier' -e 'vault/verdicts/<計画ID>/<id>.json' -e 'PASS' -e 'FAIL' -e 'blocked' -e '.claude/hooks/stop_gate.py' -e 'scripts/vcs_finish.sh' -e 'vault/plans/<計画ID>.md' -e 'vault/log/<計画ID>.md'` の出力に、この16個の文字列がすべて1回以上現れる
- PR 後に人がマージする説明が残っている。確認：`grep -cE 'PR ができたら、人が内容を確認して `gh pr merge` でマージする.*`bash scripts/vcs_finish\.sh` で PR を作るまでしか行わない' README.md` の出力が `1`
- 見出し構成が変わっていない。確認：`grep -E '^## ' README.md` の出力がちょうど次の8行（この順）：`## 目的`・`## セットアップ`・`## クイックスタート`・`## 使い方`・`## 拡張ポイント（ルール）`・`## 仕組み`・`## 構成`・`## ライセンス`
- 文書中のパスが実在する。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`

## 決定済み
- 方式は「ASCII だけの図（```` ```text ```` のコードブロック1つ）＋図の下の番号付き手順」にする。図をやめて手順だけにする案は取らない
- 図のラベルは英語・ASCII にする（例：`human`・`orchestrator (main)`・`verifier (separate context)`・`planner`・`creator (worktree)`・`Stop hook (stop_gate.py)`・`vault/plans/<id>.md`）。線は `|`・`-`・`+`、矢印は `>`・`<`・`v`・`^` を使う。罫線素片（`│`・`─`・`▶`・`◀`・`▼` など）や全角文字・全角空白は図の中に使わない
- 番号付き手順（`1. ` の形、日本語）には、今の図にある次の情報をすべて書く：人が `/plan <ゴール>` を打つ／ブランチ `work/<計画ID>` を作る／planner が計画票とタスク票を draft で作る／粒度の確認後に approved（自動）／続けて `/run`／todo→doing で creator が worktree で作り review／verifier（別コンテキスト）が受け入れ基準を照合し `vault/verdicts/<計画ID>/<id>.json` を書く／PASS → done・FAIL → doing（attempt+1）・上限 → blocked／全タスク done で計画票を done にし `scripts/vcs_finish.sh` で PR／Stop フック `.claude/hooks/stop_gate.py` が計画票のタスク表と verdict を照合して整合しない終了をブロック／人は blocked に答えて戻し、PR をマージする／状態の正本 `vault/plans/<計画ID>.md` と追記ログ `vault/log/<計画ID>.md`
- 手順の直後の段落「PR ができたら、人が内容を確認して `gh pr merge` でマージする（コンフリクトがあれば計画のブランチ上で人が解決する。エージェント（オーケストレーター）は `bash scripts/vcs_finish.sh` で PR を作るまでしか行わない）。」は1文字も変えずに残す
- 仕組み節以外は変えない
