# T-0015 設計文書の vault 仕様とテンプレート・置き場を作る

## 目的
`/design` スキルが出力する設計文書の置き場・ID 採番・フェーズごとの4点セットの形式・`/plan` との関係を `docs/vault-spec.md` に新節として定義し、雛形テンプレートと空の置き場を用意する。`/design` スキル本体（T-0016）はこの仕様に沿って書く契約タスク。

## 入力
- `docs/vault-spec.md`（節構成・ID 採番規則の書き方。特に「3. ID・ファイル名」「6. 計画票」）
- `docs/roadmap-rules-extension.md`（今回実際に使った設計文書の実例。フェーズごとの4点セット（`/plan` に渡す文／受け入れ基準の候補／決定済み／依存）の具体形はこれを抽象化する）
- `vault/templates/plan.md`・`vault/templates/task.md`（テンプレートの書式：frontmatter + 見出し）

## 成果物
`docs/vault-spec.md` の新節「設計文書（`vault/designs/`）」
（付随：`vault/templates/design.md`、`vault/designs/.gitkeep`）

## 受け入れ基準
- `docs/vault-spec.md` に新節があり、ID 採番規則（`D-` + 3桁、既存最大値+1、再利用禁止）が書かれている。確認：`grep -c 'D-' docs/vault-spec.md` の出力が節追加前より増えている
- 節に、フェーズごとの4点セット（ゴール文／受け入れ基準の候補／決定済み／依存）の形式が書かれている
- 節に、`/design` の出力（`vault/designs/D-xxx.md`）を人が確認してから `/plan` に渡す、`/design` は planner サブエージェントを呼ばない、という plan との関係が明記されている
- `vault/templates/design.md` が存在し、frontmatter に `id` を持ち、フェーズ単位で繰り返す4点セットの見出し構成になっている
- `vault/designs/.gitkeep` が存在する
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（既存の検証が壊れていない）

## 決定済み
- ID は `D-` + 3桁（例 `D-001`）。採番は `vault/designs/` 内の既存ファイルの最大値+1（タスク・計画とは独立した採番系列）
- 設計文書に `status`（draft/approved 等）のライフサイクルは持たせない。`/design` の出力は一度提示して終わる読み物であり、タスク・計画のような5状態遷移の対象ではないため。frontmatter は `id` のみでよい
- 4点セットの見出しは「ゴール文 / 受け入れ基準の候補 / 決定済み / 依存」の4つに固定し、フェーズの数だけ繰り返す（`docs/roadmap-rules-extension.md` の①〜⑧の構造を抽象化したもの）
- `vault/designs/.gitkeep` は既存の `vault/tasks/.gitkeep` 等と同じ、空ディレクトリを git 管理下に置くための空ファイル
- このタスクではコード（スキル・フック・install.sh）は変更しない。ドキュメントとテンプレート・置き場のみ

## 進捗
- `bash scripts/rules.sh creator` を実行。出力は空だったため何もしていない
- `docs/vault-spec.md` に「## 14. 設計文書（vault/designs/）」を追加（ID と採番／形式の表／`/plan` との関係の3小節）
- あわせて第1節のディレクトリ表に `vault/designs/D-001.md` の行、第3節の ID 規則に `D-` + 3桁と独立採番を追記
- `vault/templates/design.md` を作成。frontmatter は `id` のみ。ゴール／決定事項／依存関係／フェーズごとの4点セット（ゴール文・受け入れ基準の候補・決定済み・依存）／今回やらないこと、の構成
- `vault/designs/.gitkeep` を作成
- 受け入れ基準6件の確認コマンドをすべて実行し通過（`grep -c 'D-' docs/vault-spec.md` は 0→4、4点セットの表を確認、planner を呼ばない旨1件、テンプレートの見出し構成を確認、.gitkeep 存在、`bash scripts/smoke.sh` は pass=40 fail=0）
