## 決定済み
- 3点（「creator はブランチを切らない」「コミットは受け入れ基準にある時だけ」「PR はオーケストレーターが作る」）は、基準の grep と一致するように「ブランチを切らない」「受け入れ基準にある時だけ」「オーケストレーター」の語をそのまま本文に書く
- creator のブランチ：`/plan` が計画ブランチ（`work/<計画IDの英小文字>`）を切り、run が `isolation: "worktree"` で creator 用の worktree を用意する。creator は自分でブランチを切らない・切り替えない
- creator のコミット：タスク票の受け入れ基準にコミットがある時だけ行う。それ以外の未コミット分は、PASS 後にオーケストレーターが worktree でまとめてコミットし、計画ブランチへ `git merge --no-ff` で取り込む（run SKILL.md 手順6.4）。creator は計画票のタスク表と `vault/log/<計画ID>.md` に書き込まない
- PR：全タスクが `done` になった後、オーケストレーターが `bash scripts/vcs_finish.sh` で作る。creator は PR を作らない。マージは人が行う
- 例外時：creator が受け入れ基準にあるコミットで失敗した場合や判断が必要になった場合は、自己判断で解決せず、完了報告を `blocked: <質問文>` の形にしてオーケストレーターに返す（計画票を `blocked` にするのはオーケストレーター）。マージのコンフリクトはオーケストレーターが扱う
- 起点コミット：`doing` の作業開始時に `git rev-parse --short HEAD` を取り、タスク票の「進捗」の先頭に `起点コミット: <短縮ハッシュ>` を1行記録する手順は残す
- 提案ファイルは全文で書く（差分ではなく）。前置きや frontmatter は付けない
- `vault/rules/common/git.md`・`.claude/skills/run/SKILL.md` は変更しない（ゴール外。整合は計画票の「人への質問」に挙げた）
- 実体 `vault/rules/creator/git-workflow.md` は変更しない（フックで拒否される。反映は人が行う）
- smoke.sh はこのタスクの基準に含めない（T-06 で流す）
