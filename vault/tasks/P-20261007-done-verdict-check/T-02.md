# T-02 smoke.sh の done の行を含む既存ケースに PASS の verdict を置く

## 目的
T-03・T-04 でフックが done の行の verdict を検査し始めても既存の smoke ケースが落ちないよう、approved な計画票の done の行を使って「許可」を期待している既存ケースに、attempt が一致する PASS の verdict を前提として置く。期待値は変えない。

## 入力
- `vault/designs/D-012.md` の「フェーズ1」の決定済み（既存の smoke で done の行を含むケースは PASS の verdict を置くよう前提を直してよい。期待値は変えない）
- `scripts/smoke.sh`（`make_verdict` の定義、`== stop_gate.py ==` の (delegate stop_gate)、`== plan_guard.py ==` の (a-5)・正常な計画票・(delegate plan_guard)）
- `vault/plans/P-20261007-done-verdict-check.md` の「分割方針」（対象ケースの一覧）

## 成果物
- `scripts/smoke.sh`（下の4ケースの前提だけを直す。このファイルだけ）

## 受け入れ基準
- 既存の smoke が全件通り、件数も変わらない：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=519 fail=0`
- (a-5) の直前に verdict を置いている：`grep -B2 -F 'expect "(a-5) doing の after が done なタスクを指す → 許可"' scripts/smoke.sh` の出力に `make_verdict T-0001 1 PASS` を含む
- 正常な計画票のケースの直前に verdict を置いている：`grep -B2 -F 'expect "正常な計画票（doing 1件・blocked に question あり）→ 許可"' scripts/smoke.sh` の出力に `make_verdict T-0001 1 PASS` を含む
- (delegate stop_gate) の計画票の隣に verdict を置いている：`grep -c -F '$DWSMAIN/vault/verdicts/P-TEST/T-0001.json' scripts/smoke.sh` の出力が `1`
- (delegate plan_guard) の計画票の隣に verdict を置いている：`grep -c -F '$DWPMAIN/vault/verdicts/P-TEST/T-0001.json' scripts/smoke.sh` の出力が `1`

## 決定済み
- 直すのは次の4ケースだけ。ケース名・期待値（block/allow と reason の部分文字列）・ケースの数は変えない
  1. `plan_guard.py` の「(a-5) doing の after が done なタスクを指す → 許可」：`make_plan` の行と `expect` の行の間に `make_verdict T-0001 1 PASS` の1行を足す（`make_plan` の行の末尾に `; make_verdict T-0001 1 PASS` を足す形でもよい）
  2. `plan_guard.py` の「正常な計画票（doing 1件・blocked に question あり）→ 許可」：1と同じ
  3. `stop_gate.py` の (delegate stop_gate) のうち `DWSMAIN` のリポジトリ：計画票を書いた直後、`git -C "$DWSMAIN" add -A` より前に `mkdir -p "$DWSMAIN/vault/verdicts/P-TEST"` と、`printf` で `"$DWSMAIN/vault/verdicts/P-TEST/T-0001.json"` に `make_verdict` と同じ形の JSON（`{"task":"P-TEST/T-0001","attempt":1,"result":"PASS","checked_at":"2026-01-01 00:00","criteria":[],"reasons":["r1"]}`）を書く。`add -A` の前に置くことで verdict もコミットされ、stop_gate の未コミット変更の検査に当たらない
  4. `plan_guard.py` の (delegate plan_guard) のうち `DWPMAIN` のリポジトリ：3と同じ形で `"$DWPMAIN/vault/verdicts/P-TEST/T-0001.json"` に書く（計画票を書いた直後）
- 3・4 で verdict のパスは `"$DWSMAIN/vault/verdicts/P-TEST/T-0001.json"`・`"$DWPMAIN/vault/verdicts/P-TEST/T-0001.json"` の字句どおりに書き、それぞれ smoke.sh に1回だけ現れるようにする（基準4・5が数える）
- `DWSMAIN2`・`DWPMAIN2`（委譲失敗のケース）は done の行を使っていないので直さない
- 「(d) id が重複」と「(ms-4) 補足付き log・plan_guard: id 重複」は done の行に verdict が無いまま残す。既存の検査（id の重複）が done の行の検査より先にブロックすることの確認になる（T-04 の決定済み）
- 「PASS・done → 許可」と (ms-4) の stop_gate のケースは既に PASS の verdict があるので直さない
- 置いた verdict は今のフック（done の行を検査しない）の判定を変えない。T-03・T-04 の後に、これらのケースが許可のままであることを T-03・T-04 の基準（smoke が `fail=0`）で確かめる
- smoke.sh のほかの部分（ヘルパー関数・他のケース・後片付け）は変えない
