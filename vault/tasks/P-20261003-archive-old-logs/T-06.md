# T-06 移す対象の計画 ID 一覧を確定し dry-run で検査する

## 目的
人が `--apply` で移す対象の一覧を事前に確定し、`scripts/archive_plans.sh --dry-run` がすべての対象を NG 無しで受け付けることを確かめる。実際の移動はこのタスクでは行わない（人が PR ブランチ上で行う）。

## 入力
- `vault/plans/*.md`（status とタスク表）・`vault/log/*.md`（最初の日時行）
- `scripts/archive_plans.sh`（T-01 の成果物）と T-01 タスク票の「決定済み」（`--list`・`--from-file` の形式、候補の条件、「新しい」の基準）
- 計画票 `vault/plans/P-20261003-archive-old-logs.md` の「ゴール」（人の回答）と「分割方針」

## 成果物
- `vault/tasks/P-20261003-archive-old-logs/T-06-targets.txt`（新規。移す計画 ID の一覧。1ファイル）

## 受け入れ基準
- 一覧が49件：`grep -c '^P-' vault/tasks/P-20261003-archive-old-logs/T-06-targets.txt` の出力が `49`
- スクリプトが既定（`--keep 5`）で選ぶ対象も49件：`bash scripts/archive_plans.sh --list | grep -c '^P-'` の出力が `49`
- 一覧とスクリプトの選ぶ対象が一致する：`bash scripts/archive_plans.sh --list | grep -c -x -F -f vault/tasks/P-20261003-archive-old-logs/T-06-targets.txt` の出力が `49`
- 新しい5件が一覧に無い：`grep -c -x -e P-20261003-guard-rules-path-text -e P-20261003-planner-no-tmp-redirect -e P-20261003-model-stats-blocked-creator -e P-20261003-run-finish-verifier-worktree -e P-20261002-verify-cmd-guard-align vault/tasks/P-20261003-archive-old-logs/T-06-targets.txt` の出力が `0`
- 一覧を渡したドライランが NG 無しで移動行を195行出す（計画票49・タスク票49・verdict 48・log 49）：`bash scripts/archive_plans.sh --dry-run --from-file vault/tasks/P-20261003-archive-old-logs/T-06-targets.txt | grep -c ' vault/archive/20'` の出力が `195`
- 何も移していない：`git status --porcelain -- vault/archive` の出力が空

## 決定済み
- 対象は人の回答（計画票の「ゴール」）のとおり、done かつ main でもマージ済みの計画のうち、log の最初の日時行で新しい順に5件を残した、それより古い全部。2026-10-03 時点で planner が数えた値は、候補54件・残す5件・移す49件
  - 残す5件：`P-20261003-guard-rules-path-text`・`P-20261003-planner-no-tmp-redirect`・`P-20261003-model-stats-blocked-creator`・`P-20261003-run-finish-verifier-worktree`・`P-20261002-verify-cmd-guard-align`
  - この計画自身（`P-20261003-archive-old-logs`）は現在のブランチの計画で、main にも無いので候補に入らない（一覧に入れない）
  - `P-019`〜`P-021` は旧形式の ID で候補に入らない（一覧に入れない）
- 一覧は `bash scripts/archive_plans.sh --list` の出力をそのまま写す（自分で選び直さない）。`--list` が49件でなかった場合は、一覧を作らずに blocked にし、question に `--list` の件数と、計画票の「分割方針」の値との違いを書く
- ファイルの形式：1行1件、計画 ID だけを書く（行頭が `P-`）。`#` のコメント行と空行は書かない。計画 ID の後ろに空白や注記を付けない。並びは `--list` の出力の順（古い順）。一覧の条件・作成日などの説明はこのタスク票の「進捗」に書く
- `P-20260924-worktree-isolation-guard` は verdict のディレクトリが無いので、移動行は3行になる（195行 = 49 × 4 − 1）
- 移動後の `model_stats.py` の既定の集計の見込み（planner が残す5件の log を引数に渡して実際に数えた値）：`sonnet 14 1.00 1.00 0.00` の1行（この計画のタスクの分は別に増える）。`unknown` は 131 → 0。この見込みの確認は人が `--apply` した後に行うもので、このタスクの受け入れ基準にはしない。「進捗」に書き写してよい
- ドライランで NG が出た場合は、一覧から外さずに blocked にし、question に NG の行を書く（対象を勝手に減らさない）
- `--apply` は実行しない。`vault/plans/`・`vault/log/`・`vault/tasks/`（このファイルと、このタスク票の「進捗」以外）・`vault/verdicts/` は変えない
- このファイルは T-06 の成果物で、提案ファイル（`-proposal.md`）ではない。人が `--apply --from-file` でそのまま使う
