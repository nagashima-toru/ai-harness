# ゴール
GitHub Issue #214（P-20261017-code-review-in-agents、#216 でマージ済み）の続き。`/code-review` のタスク単位の実行は費用がタスク数に比例して高すぎるので、計画単位に移す。人の決定事項：
(1) planner は、計画にコードを変更するタスクが1件以上ある時、全タスクを after に持つ最後のタスク「計画の差分が /code-review を通過する」を自動で足す。このタスクの成果物は計画の差分への修正（直す対象は計画で変えたファイル）で、受け入れ基準は「/code-review で計画の差分に致命的な指摘が残っていない」。「コードを変更する」の判定基準は planner 定義に書く。
(2) このタスクのレビュー範囲はタスク差分ではなく計画全体の差分（ベースブランチ HARNESS_BASE_BRANCH、既定 main との分岐点から）。creator・verifier の「コードレビューを参照する基準」の節、docs/vault-spec.md の該当節、.claude/skills/run/SKILL.md の早見表などをこの範囲に合わせて直す。差分の外（既存コード）・致命的でない指摘・人の判断の扱いは現行どおり。
(3) 通常のタスクの受け入れ基準には /code-review の行を入れない（planner の手順・ルールを直す）。creator の先回りレビューは計画単位タスクでも「実行→直す→1回だけ再確認」までに抑える。
(4) docs/decisions.md に「ハーネスはレビューを強制しない」から「コード変更を含む計画には最後に計画単位のレビュータスクを足す」への方針変更と理由（タスク単位では費用がタスク数に比例する。小さく切るほど割高）を1行追記する。

## 分割方針
- 役割定義ごとに1タスクにする。planner（足す側）・creator（先回りする側）・verifier（判定する側）は互いの文言を参照しないので並行に進める（T-01〜T-03）。新しい用語は「計画単位のレビュータスク」に統一し、各タスク票の「決定済み」で同じ語・同じ範囲の書き方を指定して食い違いを防ぐ。
- 要約側（`docs/vault-spec.md` と `.claude/skills/run/SKILL.md`）は、正本の3定義が直った後に実ファイルを見て書く（T-04）。
- 方針変更の記録と、古い記述（「レビューを強制しない」「導入先の planner ルール」「そのタスクの差分」）がリポジトリ全体に残っていないことの確認を最後に行う（T-05）。
- 新ルール (1) の判定：この計画の成果物はすべて `.md`（`.claude/agents/*.md`・`.claude/skills/*/SKILL.md`・`docs/*.md`）で、コードを変更するタスクが無い。そのため計画単位のレビュータスクは足さない。`scripts/smoke.sh` は変更しない（成果物に入れるとコードを変更するタスクになり、ゴールにも検査の追加は含まれないため）。
