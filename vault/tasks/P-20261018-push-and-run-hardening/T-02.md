# T-02 run SKILL に Agent 呼び出しがエラーで返った時の節がある

## 目的
Issue #207 を解決する。手順3（creator）・手順5（verifier）の Agent 呼び出しが、応答の無いハングではなくエラーで即時に返った時（429 のレート制限など）の扱いを `.claude/skills/run/SKILL.md` に定め、同じセッションで取る行動が手順から一意に決まるようにする。

## 入力
- `.claude/skills/run/SKILL.md`（早見表の27・28行、手順2の2、手順3の2、手順5、「ハング時の復旧」節）
- `docs/vault-spec.md` 7節（再開・ハング・worktree が無い時の遷移行の補足の一覧、202行）
- `.claude/hooks/stop_gate.py` の doing・review の判定（`docs/vault-spec.md` 9節）

## 成果物
- 主な成果物：`.claude/skills/run/SKILL.md` の新しい節「Agent 呼び出しがエラーで返った時（手順3・5）」
- 変えるファイル：
  - `.claude/skills/run/SKILL.md`
  - `docs/vault-spec.md`

## 受け入れ基準
- 新しい節が「ハング時の復旧」節の直後にある：`grep '^## ' .claude/skills/run/SKILL.md | grep -A1 'ハング時の復旧'` の出力の2行目が `## Agent 呼び出しがエラーで返った時（手順3・5）`
- レート制限・一時的な API エラーでは状態を変えない：`grep -c 'transition.py を呼ばず、状態を変えない（doing・review のまま）' .claude/skills/run/SKILL.md` の出力が `1`
- リセット後の再開の案内がある：`grep -c 'リセット後に ./run. を実行すれば、手順2.2' .claude/skills/run/SKILL.md` の出力が `1`
- creator のエラーの再試行の補足が SKILL と仕様の両方にある：`grep -c 'creator呼び出しエラーにより再試行' .claude/skills/run/SKILL.md docs/vault-spec.md` の出力が `.claude/skills/run/SKILL.md:1` と `docs/vault-spec.md:1` の2行
- verifier のエラーの blocked の補足が SKILL と仕様の両方にある：`grep -c 'verifier呼び出しエラー' .claude/skills/run/SKILL.md docs/vault-spec.md` の出力が `.claude/skills/run/SKILL.md:1` と `docs/vault-spec.md:1` の2行
- 文書のパス参照が壊れていない：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 節の見出しは `## Agent 呼び出しがエラーで返った時（手順3・5）` の1行とし、「ハング時の復旧」節（「無人実行（cron・CI）の場合」の段落まで）の直後、`## 6. verdict に従う（逐次処理）` の前に置く
- 節の冒頭に、対象を書く：手順3（creator）・手順5（verifier）の Agent ツール呼び出しが、応答の無いハングではなく、エラーで即時に返った時（Issue #207。例：`Agent terminated early due to an API error: ... rate_limit, HTTP 429`）。creator の `model` の指定を受け付けないエラーは手順3の2のとおりに扱い、この節の対象にしない
- 見分け方：エラーの文言に `429`・`rate_limit`・`overloaded`・`529`・`API error` のいずれかを含むものを「レート制限（429）・一時的な API エラー」とし、それ以外を「それ以外のエラー」とする（文言の完全一致には頼らない）
- 1つ目の項目「レート制限（429）・一時的な API エラー」には次を書く。文「transition.py を呼ばず、状態を変えない（doing・review のまま）。」をこの文字どおり書く（この文はファイルの中でここの1か所だけにする）。worktree は破棄しない。新しい Agent 呼び出し（ほかのタスクの creator・verifier を含む）はしない。既に完了報告を受けたほかのタスクは手順4〜6を手順どおり進めてよい。そのうえで、エラーの内容と対象のタスク ID を人に報告して止まり、「レート制限のリセット後に `/run` を実行すれば、手順2.2（doing は中断から再開、review は記録行から worktree を復元して verifier を呼び直す）で再開できる」と案内する（「リセット後に `/run` を実行すれば、手順2.2」の部分はこの文字どおり、ファイルの中でここの1か所だけに書く）。止まる時に stop_gate が「待機中なら問題ありません」の理由でブロックしても、そのままターンを終えてよい
- 2つ目の項目「それ以外のエラー」には、「ハング時の復旧」の1・2と同じく回数を数えることを書く
  - creator（手順3）：worktree のパスとブランチ名が返っていれば `bash scripts/discard_worktree.sh <worktree のパス> <ブランチ名>` で破棄する。attempt が上限（`HARNESS_MAX_ATTEMPTS`、既定3）未満なら `python3 scripts/transition.py <計画ID> <id> doing --no-model --note "creator呼び出しエラーにより再試行"` を呼んで手順3から creator を呼び直す。上限に達していれば、質問文（「creator 呼び出しがエラーで返った」とエラーの内容）を Write ツールで一時ファイルに書き、`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --no-model --note "creator呼び出しエラー"` を呼ぶ
  - verifier（手順5）：worktree は破棄しない。verifier を呼び直してよいが、同一タスクでエラーによる再試行が2回に達したら（attempt とも、ハング再試行回数とも別に数える）、質問文（「verifier 呼び出しがエラーで返った」とエラーの内容と worktree のパス）を一時ファイルに書き、`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --no-model --note "verifier呼び出しエラー"` を呼ぶ（review→blocked）。worktree は残す
- 補足の文字列 `creator呼び出しエラーにより再試行`・`verifier呼び出しエラー` は、`.claude/skills/run/SKILL.md` ではこの節の中にそれぞれ1回だけ書く（`verifier呼び出しエラー` を含むほかの文を SKILL に書かない）。`creator呼び出しエラー`（再試行でない方）も節の中に書く
- 早見表の2行（27・28行）の場面の列を、「中断からの再開・ハング・呼び出しエラー・worktree が無い時の再試行（doing→doing・review→doing）」と「中断・ハング・呼び出しエラー・worktree が無い時の上限での blocked（doing→blocked・review→blocked）」にする。コマンドの列は変えない
- `docs/vault-spec.md` 7節の202行を、「再開・ハング・呼び出しエラー・worktree が無い時の遷移行は、run が transition.py を `--no-model --note "<補足>"` で呼んで書く。補足は `中断から再開`・`中断が上限に達した`・`worktree が無いため作り直し`・`worktree が無いため`・`creator呼び出しハングにより再試行`・`creator呼び出しハング`・`verifier呼び出しハング`・`creator呼び出しエラーにより再試行`・`creator呼び出しエラー`・`verifier呼び出しエラー` のいずれか。」にする（`docs/vault-spec.md` の中で `creator呼び出しエラーにより再試行`・`verifier呼び出しエラー` を書くのはこの行の1回ずつだけ）。`docs/vault-spec.md` のほかの行は変えない（1節の `HARNESS_PUSH_BRANCH` の段落は T-01 が変えるので触らない）
- transition.py は `--note` の値を検査しないので、スクリプトの変更は要らない
