# T-0023 標準ルールを install.sh で配り「ルールを同梱しない」の記述を直す

## 目的
T-0019〜T-0022 で作った役割定義の標準ルール4本をインストール先にも配り、`README.md`・`docs/vault-spec.md`・`vault/rules/README.md` の「ハーネス本体はルールを同梱しない」という記述を「役割定義の標準ルールだけは同梱し、ドメイン固有のルールはインストール先で書く」という趣旨に直す。

## 入力
- `scripts/install.sh`（`copy_if_absent` と `vault/` の複製ループ。T-0012 で `rules/README.md`・各 `.gitkeep` を追加した時と同じパターンで足す）
- `README.md` の「## 拡張ポイント（ルール）」節（39行目に「ハーネス本体はルールを同梱しない」）
- `docs/vault-spec.md` 第12節（125行目に「ハーネス本体はルールを同梱しない」）
- `vault/rules/README.md`（3行目に「ハーネス本体はルールを同梱しない」）
- T-0019〜T-0022 の成果物4ファイル（複製対象のパス）

## 成果物
- `scripts/install.sh`（付随：`README.md`・`docs/vault-spec.md`・`vault/rules/README.md` の該当箇所の修正）

## 受け入れ基準
- `scripts/install.sh` の複製対象に標準ルール4本が入っている。確認：`grep -c 'rules/common/roles.md' scripts/install.sh`、`grep -c 'rules/planner/planner.md' scripts/install.sh`、`grep -c 'rules/creator/creator.md' scripts/install.sh`、`grep -c 'rules/verifier/verifier.md' scripts/install.sh` がいずれも1以上
- 一時ディレクトリへ `bash scripts/install.sh <tmpdir>` を実行すると上記4ファイルが複製され、同じ一時ディレクトリへの2回目の実行では4ファイルとも `skip` になる
- `README.md`・`docs/vault-spec.md`・`vault/rules/README.md` から「ルールを同梱しない」という記述が消えている。確認：`grep -c 'ルールを同梱しない' README.md docs/vault-spec.md vault/rules/README.md` がすべて0
- 3ファイルそれぞれに、役割定義の標準ルールは同梱し、ドメイン固有のルールはインストール先で書く旨が1〜3行で書かれている。確認：`grep -c '同梱' README.md docs/vault-spec.md vault/rules/README.md` がいずれも1以上
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

## 決定済み
- `install.sh` への追加は、既存の `vault/` 複製ループ（`for f in tasks/.gitkeep ... rules/planner/.gitkeep; do copy_if_absent ...`）のリストに4パスを足すだけでよい。`copy_if_absent` を使い、既存ファイルは上書きしない（インストール先が標準ルールを編集していたらその編集を残す）
- `.gitkeep` の複製対象はそのまま残す（標準ルールを消したインストール先でもディレクトリが残るように）
- `README.md` の修正は「## 拡張ポイント（ルール）」節の冒頭1〜3行のみ。表・箇条書き・「## 構成」ツリーは変えない。標準ルール4本のパスを列挙するかは任意（節が25行以内に収まる範囲で）
- `docs/vault-spec.md` は第12節の冒頭の1文のみを直す。ディレクトリ構成のブロック・読み込み順・「ルールと受け入れ基準の関係」・「改ざん防止」の各項は変えない
- `vault/rules/README.md` は冒頭の1文のみを直す。全体20行以内を維持する
- 文言の趣旨（3ファイルで揃える）：「ハーネスは planner / creator / verifier の役割定義を標準ルールとして同梱する。コーディングルール・方式設計・テスト観点などドメイン固有のルールはインストール先で書く」
- `vault/rules/README.md` は `vault/rules/` 配下なので、`doing`/`review` 中は書き込みが拒否される。人が `HARNESS_ALLOW_RULES_WRITE=T-0023` を設定して起動している前提で進め、Write が deny されたら `blocked` にして question に設定方法を書く
- 標準ルール4本の中身（T-0019〜T-0022 の成果物）は変更しない。`scripts/smoke.sh`・`scripts/rules.sh`・フック・エージェント定義・スキルも変更しない
- 一時ディレクトリでの install 検証にはインストール先の `git init` もコミットも不要。検証後の一時ディレクトリは残さない
- git commit はしない（人が確認してからコミットする）
