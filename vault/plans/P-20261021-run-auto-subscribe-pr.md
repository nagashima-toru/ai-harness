# ゴール
run: PR を作ったら subscribe_pr_activity で自動的に監視する（GitHub Issue #222）

`/run` 手順7で `scripts/vcs_finish.sh` が PR を作った後、実行環境に `subscribe_pr_activity` ツールがある時（クラウドセッションなど）は、作った PR を購読して監視を始める。ツールが無い時は何もせず、完了報告に「監視は始めていない」と書く。ホスティングが `none`（PR が作られない）の時は対象外。購読したことを完了報告に含める。購読後の CI 失敗・レビュー対応は実行環境の指示（PR イベントの扱い）に従い、ハーネス側で新しい規則は足さない。マージ・close されたら `unsubscribe_pr_activity` で解除する旨も添える。

## 分割方針
- T-01 で手順の正本（`.claude/skills/run/SKILL.md` 手順7）に購読の小手順（手順7の8）を足し、完了報告を手順7の9に繰り下げて監視の結果を含める
- T-02 で仕様の要約（`docs/vault-spec.md`）と判断の記録（`docs/decisions.md`）に反映する。手順7の8の番号を参照するので T-01 の後にする
- スクリプトは新設しない。購読は「ツールがあれば使う」任意の手順にし、ハーネス本体に PR 対応の規則（ドメイン知識）を持ち込まない（原則7）
- 計画単位のレビュータスクは足さない：T-01・T-02 の成果物はすべて拡張子 `.md` のファイルで、コードを変更するタスクが0件のため
