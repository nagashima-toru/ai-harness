# T-02 run スキルに creator/verifier 呼び出しハング時の復旧手順を追加する（issue #48）

## 目的
`run` スキル（`.claude/skills/run/SKILL.md`）の手順3（creator 呼び出し）・手順5（verifier 呼び出し）で、Agent ツール呼び出しが長時間応答を返さない「ハング」状態になった場合の復旧手順を追加する。issue #48 では、同種のコマンドが「即時拒否」される場合と「無応答のままハングする」場合の両方が観測されており、ハングは人（またはオーケストレーターの運用者）が気づいて強制終了しない限り解消しない。このタスクは、強制終了された後にオーケストレーターが取るべき手順（worktree を破棄して再試行する／attempt 上限で blocked にする）を明文化し、手動介入のたびに毎回その場で判断する状態を無くすことが目的。自動検出の仕組みを新設することはこのタスクの範囲外（Agent ツール呼び出しは同期的にブロックするため、呼び出し中のエージェント自身が自分の呼び出しに自動でタイムアウトを設定する手段は前提にしない）。

## 入力
- `.claude/skills/run/SKILL.md`（特に手順3「作る」・手順5「検証する」・手順6.3「FAIL の場合」の worktree 破棄・attempt 再試行・blocked 化の既存パターン）
- `docs/vault-spec.md`（2節：状態遷移・attempt の仕様。`HARNESS_MAX_ATTEMPTS` 既定3）
- `scripts/discard_worktree.sh`（既存の worktree 破棄スクリプト。FAIL 再試行時に手順6.3.2で既に使われている）
- GitHub issue #48 本文（このタスクの入力として渡された計画ゴールに転記済み。observed な事象：creator 側2回・verifier 側1回のハング、TaskStop による強制終了、worktree 状態確認、再試行という手動フロー）

## 成果物
- `.claude/skills/run/SKILL.md`（新しい見出しを1つ追加する形の追記。既存の `## 0.`〜`## 8.` の見出し番号・既存の文言は変更しない）

## 受け入れ基準
- `.claude/skills/run/SKILL.md` に「ハング」という語を含む新しい `## ` 見出し行が追加されている。確認コマンド：`grep -c '^## .*ハング' .claude/skills/run/SKILL.md` の出力が `1`
- 追加した節に、応答なしとみなす目安時間が具体的な分数で書かれている。確認コマンド：`grep -E -c '[0-9]+分' .claude/skills/run/SKILL.md` の出力が `1` 以上
- 追加した節に、ハング検知後の worktree の扱いとして `discard_worktree.sh` への言及がある（既存の手順6.3.2の1件に加えて新規の1件、計2件以上になる）。確認コマンド：`grep -c 'discard_worktree.sh' .claude/skills/run/SKILL.md` の出力が `2` 以上
- 追加した節に「ハング」という語が2箇所以上ある（見出しだけでなく本文にも説明がある）。確認コマンド：`grep -c 'ハング' .claude/skills/run/SKILL.md` の出力が `2` 以上
- 既存の見出し（`## 0.` 〜 `## 8.`）の行がすべてそのまま残っている。確認コマンド：`grep -c '^## [0-8]\.' .claude/skills/run/SKILL.md` の出力が `9`
- 成果物は `.claude/skills/run/SKILL.md` のみで、他ファイルは変更していない。確認コマンド：`git status --porcelain | grep -v 'SKILL.md'` の出力が空

## 決定済み
- 新しい見出しの挿入位置は「## 5. 検証する」の後、「## 6. verdict に従う」の前を推奨する（手順3・5のどちらのハングにも触れる内容のため）。ただし既存の `## 0.`〜`## 8.` の見出し番号は変更しない（新見出しには番号を付けず、例えば `## ハング時の復旧（手順3・5の Agent 呼び出しが応答しない場合）` のようなタイトルにする）
- 目安時間は15分とする（issue #48 で観測された「約17分以上応答が無い」事象を踏まえた保守的な値）。正確な自動計測は前提にしない。人またはオーケストレーターの運用者が気づいて TaskStop（またはそれに相当する強制終了の手段）で止める運用を明記すること
- creator 呼び出し（手順3）がハングした場合：対象タスクの worktree を `bash scripts/discard_worktree.sh <worktree のパス> <ブランチ名>` で破棄し、既存の FAIL 再試行パターン（手順6.3.2）と同様に attempt が上限未満なら attempt+1 で creator を呼び直す。attempt が上限（`HARNESS_MAX_ATTEMPTS`、既定3）に達していれば blocked にし、question に「creator 呼び出しがハングした（応答無し、強制終了で復旧）」ことを明記する
- verifier 呼び出し（手順5）がハングした場合：creator の成果物が入っている worktree を破棄しない（維持する）。verifier を呼び直してよいが、同一タスクでのハング再試行が2回に達したら（task の attempt カウンタとは別に、ハング再試行回数として数える）blocked にし、question に「verifier 呼び出しがハングした」ことと worktree のパスを明記する。この場合も worktree は削除しない（人が調査に使えるようにする、既存の blocked 時の温存方針と同じ）
- いずれの場合も、状態変更（doing への差し戻し・blocked 化）は `vault/log/<計画ID>.md` に既存の書式（`- <日時> <id> <遷移> attempt=<n> 補足`）で追記する運用を踏襲する（補足に「ハング」の語を含める）
- `.claude/hooks/`・`.claude/settings.json`・`vault/rules/` は変更しない（触らない）
