# T-01 current_plan.sh で承認済み計画票を検出するスクリプトを作る

## 目的
`vault/plans/*.md` のうち frontmatter（ファイル先頭の `---` から次の `---` まで）の `status` が `approved` の計画票について、その計画 ID だけを1行1件で標準出力に出す `scripts/current_plan.sh` を新規作成する。本文中（frontmatter の外）に `status: approved` という文字列があっても検出しない。

## 入力
- `.claude/hooks/plan_guard.py` の `plan_id_and_status` 関数（134〜149行目）：frontmatter 解析・id フォールバックの既存規則。同じ規則にする
- `scripts/rules.sh`：ルート解決（`CLAUDE_PROJECT_DIR` 優先、無ければ親ディレクトリ）の書き方
- `docs/vault-spec.md` 1節：「自分のブランチの計画票」の定義（frontmatter の `status` が `approved` のものを取る）

## 成果物
- `scripts/current_plan.sh`

## 受け入れ基準
- 構文が正しい。確認：`bash -n scripts/current_plan.sh`（出力なし・終了コード0）
- frontmatter の `status` が `approved` の計画票の id だけをファイル名順で1行1件出力し、id が無ければファイル名（`.md` を除いたもの）を使い、本文中（frontmatter の外）の `status: approved` という文字列は無視する。確認：下記「決定済み」のフィクスチャ手順で `/tmp/P-20260927-current-plan-detector-T-01/vault/plans` を作った上で `CLAUDE_PROJECT_DIR=/tmp/P-20260927-current-plan-detector-T-01 bash scripts/current_plan.sh` を実行すると、出力が `approved-no-id` の行、`P-FIX-A` の行の2行（この順）になる
- approved な計画票が0件のディレクトリでは何も出力せず終了コードが0になる。確認：`mkdir -p /tmp/P-20260927-current-plan-detector-T-01-empty/vault/plans` を実行した後、`CLAUDE_PROJECT_DIR=/tmp/P-20260927-current-plan-detector-T-01-empty bash scripts/current_plan.sh` の出力が空
- 現在の `main` ブランチの `vault/plans` を対象に実行すると何も出力しない（現時点の `main` には approved な計画票が無いため）。確認：下記「決定済み」の main 抽出手順で `/tmp/P-20260927-current-plan-detector-T-01-main-dir` を作った上で `CLAUDE_PROJECT_DIR=/tmp/P-20260927-current-plan-detector-T-01-main-dir bash scripts/current_plan.sh` の出力が空

## 決定済み
- 実装は bash + awk で書く（`python3` も可だが、既存の `scripts/rules.sh` と揃えて bash を優先する）
- ルート解決：`CLAUDE_PROJECT_DIR` が設定されていればそれを使う。無ければ `cd "$(dirname "$0")/.." && pwd`（`scripts/rules.sh` と同じ解決方法）
- `LC_ALL=C` を設定し、`vault/plans/*.md` を（シェルの glob の既定順＝ファイル名順）で処理する
- frontmatter とみなすのは、ファイルの1行目が厳密に `---` で、その次に現れる `---` 行までの間だけ（`.claude/hooks/plan_guard.py` の `plan_id_and_status` と同じ規則）。1行目が `---` でない計画票は frontmatter 無しとして無視する
- frontmatter 内の `id:` 行・`status:` 行から値を取り、前後の空白を取り除く。`status` の値が完全一致で `approved` の場合だけ出力対象にする。frontmatter を閉じる `---` 行に到達したら、それ以降（本文）は一切見ない
- 出力する計画 ID は frontmatter の `id` の値。`id` が無ければファイル名から `.md` を除いたものを使う
- 出力は1行1件（末尾に余分な空行を作らない）。標準エラー出力・終了コードは常に0（0件でも2件以上でも0。件数の判定は呼び出し側が行う）
- 受け入れ基準2用のフィクスチャ手順：`mkdir -p /tmp/P-20260927-current-plan-detector-T-01/vault/plans` を実行した上で、次の3ファイルを作る
  - `/tmp/P-20260927-current-plan-detector-T-01/vault/plans/approved-with-id.md`
    ```
    ---
    id: P-FIX-A
    status: approved
    ---
    # ゴール
    本文
    ```
  - `/tmp/P-20260927-current-plan-detector-T-01/vault/plans/approved-no-id.md`（`id:` 行を書かない）
    ```
    ---
    status: approved
    ---
    # ゴール
    本文
    ```
  - `/tmp/P-20260927-current-plan-detector-T-01/vault/plans/not-approved-body-trap.md`
    ```
    ---
    id: P-FIX-C
    status: done
    ---
    # ゴール
    本文中に status: approved と書いても frontmatter の外なので無視されるべき
    ```
  ファイル名の並び順（`LC_ALL=C`）は `approved-no-id.md` → `approved-with-id.md` → `not-approved-body-trap.md`。期待出力は先頭2件分の `approved-no-id`・`P-FIX-A`（この順）で、`not-approved-body-trap.md` 由来の出力（`P-FIX-C` 等）は出ない
- 受け入れ基準4用の main 抽出手順：リポジトリのルートで次を1コマンドずつ順に実行する
  1. `git archive -o /tmp/P-20260927-current-plan-detector-T-01-main.tar main -- vault/plans`
  2. `mkdir -p /tmp/P-20260927-current-plan-detector-T-01-main-dir`
  3. `tar -xf /tmp/P-20260927-current-plan-detector-T-01-main.tar -C /tmp/P-20260927-current-plan-detector-T-01-main-dir`
- 確認コマンドはパイプ・`&&`・コマンド置換を含まない単純なコマンドに分解して1つずつ実行する（複合コマンドによるサンドボックスのハングを避けるため。`vault/rules/planner/planner.md`）
- `.claude/hooks/stop_gate.py`・`.claude/hooks/plan_guard.py` は既に frontmatter を正しく解析しているので変更しない。`scripts/install.sh` も変更しない（`scripts/` 直下の `*.sh` は自動で配布対象になる）
