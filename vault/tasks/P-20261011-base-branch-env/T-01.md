# T-01 vcs_finish.sh の base とマージ案内を HARNESS_BASE_BRANCH にする

## 目的
`scripts/vcs_finish.sh` が固定で使っている `main`（GitHub REST の `base`、ホスティング無しのマージ案内の取り込み先）を、環境変数 `HARNESS_BASE_BRANCH`（前後の空白を除いて空なら `main`）の値にする。未設定なら今の動作を変えない。

## 入力
- `scripts/vcs_finish.sh`
- `vault/designs/D-20261010-base-branch-config.md`（「決定事項」と「フェーズ1」の「決定済み」）
- `scripts/smoke.sh` の `== vcs_finish.sh ==` 節（既存のケース。このタスクでは変えない）

## 成果物
- `scripts/vcs_finish.sh`（1ファイル）

## 受け入れ基準
- `scripts/vcs_finish.sh` に固定の `main` が残っていない：`grep -cE 'base=main|main 固定|main に取り込む|main への取り込み' scripts/vcs_finish.sh` が `0`
- GitHub REST の経路3つがベースブランチの変数を `base` に渡す：`grep -cF -- '-f "base=$base_branch"' scripts/vcs_finish.sh` が `3`
- ホスティング無しの案内の取り込み先が値に従う：`env HARNESS_VCS_HOST=none HARNESS_BASE_BRANCH=develop bash scripts/vcs_finish.sh | grep -c 'の内容を develop に取り込むには'` が `1`
- 前後の空白を除く：`env HARNESS_VCS_HOST=none HARNESS_BASE_BRANCH='  develop  ' bash scripts/vcs_finish.sh | grep -c 'の内容を develop に取り込むには'` が `1`、`env HARNESS_VCS_HOST=none HARNESS_BASE_BRANCH='   ' bash scripts/vcs_finish.sh | grep -c 'の内容を main に取り込むには'` が `1`
- 未設定なら従来どおり main：`env -u HARNESS_BASE_BRANCH HARNESS_VCS_HOST=none bash scripts/vcs_finish.sh | grep -c 'の内容を main に取り込むには'` が `1`
- 既定のままの既存動作が変わらない（vf-rest-1〜3 の `base=main` の期待値を含む）：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 値の読み方は、`set -u` の直後（`host=` の行より前）のトップレベルで次の4行をそのまま書く（変数名は `base_branch`。値の形式は検査しない）：
  ```
  base_branch="${HARNESS_BASE_BRANCH:-}"
  base_branch="${base_branch#"${base_branch%%[![:space:]]*}"}"
  base_branch="${base_branch%"${base_branch##*[![:space:]]}"}"
  [ -n "$base_branch" ] || base_branch=main
  ```
- GitHub の引数なしの REST の3行（本文ファイル・計画あり・計画無し）は `-f base=main` を `-f "base=$base_branch"` にする（この字句で書く。受け入れ基準が `-f "base=$base_branch"` を3件数える）
- ホスティング無しの案内は、`の内容を main に取り込むには` を `の内容を ${base_branch} に取り込むには` に、`main への取り込みは人が行ってください` を `${base_branch} への取り込みは人が行ってください` にする。それ以外の文言は変えない
- 冒頭のコメントの「base は main 固定」は「base は HARNESS_BASE_BRANCH（前後の空白を除いて空なら main）」のように書き換え、`HARNESS_BASE_BRANCH` の説明を1〜2行足す（「main 固定」の字句は残さない）
- 引数ありの経路（`gh pr create "$@"`・`glab mr create "$@"`）には base を足さない。GitLab の引数なしの経路（`--fill`・`--title`/`--description`）もターゲットブランチを指定しない（glab の既定に任せる）
- `HARNESS_PUSH_BRANCH` はフェーズ2の範囲なので扱わない。push・head の動作は変えない
- `scripts/smoke.sh` はこのタスクでは変えない（develop のケースは T-06 で足す。既存ケースの `base=main` の期待値はそのまま通る）
- 確認コマンドの `bash scripts/vcs_finish.sh` は `HARNESS_VCS_HOST=none` なので push も PR 作成もしない（案内を出して終了コード0で終わるだけ）
