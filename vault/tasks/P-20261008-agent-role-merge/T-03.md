# T-03 標準ルールの planner 向けの内容を .claude/agents/planner.md に統合する

## 目的
`vault/rules/` の標準ルールのうち planner に関わる内容（`planner/planner.md`・`common/roles.md` の planner が送り手か受け手の節・`common/git.md` の planner に関係する部分）を、今の run の手順と矛盾しない形で `.claude/agents/planner.md` に統合する。統合後は6本が無くても planner の計画の書き方が定義どおりになる。

## 入力
- `vault/designs/D-013.md` の「フェーズ4 標準の役割定義をエージェント定義に統合する」（決定済み）
- 統合元：`vault/rules/planner/planner.md`、`vault/rules/common/roles.md`（「人 → planner」「planner → creator」の節）、`vault/rules/common/git.md`（planner に関係する部分）
- 統合先：`.claude/agents/planner.md`（今の定義）
- 経緯の参照：`vault/rules/planner/ai-harness-lessons.md`（読むだけ。変えない）
- 矛盾の判定の正本：`.claude/skills/run/SKILL.md`（手順3〜6）、`.claude/skills/plan/SKILL.md`、`docs/vault-spec.md`（5節の差分ゲート・8節）、`scripts/diff_gate.py` の docstring

## 成果物
- `.claude/agents/planner.md`（1ファイル）

## 受け入れ基準
- 統合元（`planner/planner.md` の全箇条、`roles.md` は planner が関わる2節、`git.md` は planner に関係する部分）の「ルール」節の箇条が、`.claude/agents/planner.md` に同じ意味で書かれている。ただし決定済みで落とす・言い換えると決めたものは除く（Read で統合元1本ずつ見比べて確認）
- 今の手順と矛盾する記述が無い：`grep -nE 'D-012 フェーズ5で呼ぶ|今の run はまだ呼ばない|作成エージェント（run のメイン）|vault/tasks/<id>\.md' .claude/agents/planner.md` の出力が空
- `planner.md` の「やらないこと」の各項目（確認コマンドの書き方・書き込みガードに拒否される形など）が、見出し `## やらないこと` の節にまとまっている：`grep -n '^## やらないこと$' .claude/agents/planner.md` の出力が1行（あわせて Read で各項目が節の中にあることを確認）
- 6本と経緯集への参照が無い：`grep -nE 'vault/rules/(common/roles|common/git|creator/creator|creator/git-workflow|verifier/verifier|planner/planner|planner/ai-harness-lessons)\.md' .claude/agents/planner.md` の出力が空
- frontmatter が変わっておらず、長さが150行以内：`git diff main -- .claude/agents/planner.md | grep -E '^[+-](name|description|tools|model):'` の出力が空で、`wc -l .claude/agents/planner.md` の数が150以下
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 変えるのは `.claude/agents/planner.md` だけ。`vault/rules/` は書けない（フックが拒否する）ので触れない。`vault/rules/planner/ai-harness-lessons.md` は変えない
- frontmatter（`name`・`description`・`tools`・`model`）は1文字も変えない
- 今の見出し（入力 / 読むもの / 粒度の基準（必ず守る） / 「成果物」の書き方 / 手順 / 禁止 / 出力）は残す。足す節：`## 受け渡し`（roles.md 由来）、`## やらないこと`（planner.md の「やらないこと」由来。見出しはこの文字列ちょうどにする。経緯集 `ai-harness-lessons.md` が「`planner.md` の『やらないこと』」を指しているため）。統合元の「確認方法」節は、矛盾しないものを `## 書き終えた後の確認` として書いてよい（必須ではない）
- `planner.md` の「責務」のうち今の定義と重なるもの（粒度・ID・6見出し・5〜7タスク・draft のまま・ゴールを広げない・提案ファイル）は、今の定義の箇条に寄せて二重に書かない
- 「読むもの」の `bash scripts/rules.sh planner` は残す（導入先のルールと、このリポジトリの経緯集を読む口として使い続ける）
- 落とす・言い換えるもの（今の手順と矛盾する）：
  - 「成果物」の書き方の節の「（今の run はまだ呼ばない。D-012 フェーズ5で呼ぶ）」→ 今は `scripts/transition.py` が review と done で差分ゲートを呼ぶ、に直す
  - `planner.md` の「`run`/`vault/rules/common/git.md` の運用は1計画=1ブランチに…逐次マージ」→ 参照先のパスを外し、「run は1計画=1ブランチに、タスクを完了順に `git merge --no-ff` で取り込む」とだけ書く
  - `planner.md` の「`vault/rules/verifier/verifier.md` に既にある起点コミットベースの検査」→「verifier の起点コミットの検査（`.claude/agents/verifier.md`）と、`transition.py` の差分ゲート」に直す。差分ゲートは「成果物」に宣言されていないファイルの変更を差し戻すので、「成果物のみで他ファイル不変」の基準は書かずに差分ゲートに任せてよい、と添える
  - `roles.md` の `vault/tasks/<id>.md` は `vault/tasks/<計画ID>/<id>.md` に直す
  - `roles.md` の「承認前の draft を creator は取らない」は「承認（`status` を `approved` にする）は人が行い、承認前の計画票を run は処理しない」にする
  - `git.md` からは「planner はブランチを切らず、コミットもしない（ブランチは `/plan` スキルが切る）」だけを書く
- 残すもの：「やらないこと」の各項目の本文（汎用の教訓）。T-xxxx・issue 番号などの経緯は経緯集にあるので、今の `planner.md` にあるもの以上は足さない
- 6本・`vault/rules/planner/ai-harness-lessons.md` のパスを書かない（導入先には無いため）。`vault/rules/` という語自体（提案ファイル方式・書き込みガードの保護対象）は書いてよい
- 長さは150行以内を目安にする（受け入れ基準では上限）。書き込みガードの項目は長いので、意味を変えずに箇条を詰めてよい
- 「進捗」に「落とした記述:」「言い換えた記述:」で始まる行を書き、上の一覧（と、ほかに落とした・言い換えたもの）を統合元のファイル名付きで列挙する
- `run/SKILL.md`・`plan/SKILL.md`・`docs/`・他のエージェント定義は変えない
