# T-01 docs/vision.md の作成とREADMEへのリンク追加

## 目的
このハーネスが解決する問題（目的）・恒久的な方針（原則）・意図的に目指さないこと（非ゴール）を `docs/vision.md` に固定し、将来「これはハーネスに入れるべきか」を判断する内規にする。README「目的」節から導線を張る。

## 入力
- `vault/designs/D-009.md`（本タスクの元になった設計文書。決定事項・受け入れ基準の候補をそのまま踏まえる）
- `README.md`（「目的」節。既存4行のbulleted listは変更しない）
- `docs/decisions.md`（原則の根拠を確認する）
- `docs/vault-spec.md`（原則の根拠を確認する。状態5つ固定、質問の仕方、ルール拡張点など）
- `.claude/ai-harness.md` / `CLAUDE.md`（原則の根拠を確認する）

## 成果物
- `docs/vision.md`（新規作成）と、README.md の「目的」節への1行追記（リンク追加のみ）

## 受け入れ基準
- `docs/vision.md` が存在し、`^## 目的`・`^## 原則`・`^## 非ゴール` の3見出しをこの順で含む。確認コマンド：`grep -n '^## ' docs/vision.md`
- 「原則」に列挙した各項目が、README・docs/decisions.md・docs/vault-spec.md のいずれかの既存記述と矛盾しない（1件ずつ元の記述箇所を目視確認する）
- 「非ゴール」に、マルチユーザー化・SaaS化・GUI化を目指さない旨、汎用のプロジェクト管理・タスク管理ツールを目指さない旨、Claude Code以外のランタイム対応を現時点では目指さない旨のいずれも明記されている。確認コマンド：`grep -n -e 'マルチユーザー' -e 'SaaS' -e 'GUI' -e 'プロジェクト管理' -e 'タスク管理' -e 'Claude Code' docs/vision.md`（該当行が見つかること）
- README.md の「目的」節に `docs/vision.md` へのリンクが1行追加されている。確認コマンド：`grep -n 'docs/vision.md' README.md`
- README.md の「目的」節にある既存4行のbulletの文言・順序が変更・削除されていない。確認コマンド：`git diff main -- README.md > /tmp/P-20260926-vision-doc-T01-readme.diff` を実行した後、`grep -c '^-' /tmp/P-20260926-vision-doc-T01-readme.diff` が `0`（削除行が無い＝追加のみ）

## 決定済み
- `docs/vision.md` に frontmatter は付けない（`vault/designs/` の設計文書とは別系統の通常の docs ファイル）
- 「原則」「非ゴール」の各項目は簡潔な1行見出し＋必要なら1行の補足程度にする。理由の長い説明や具体的な実装への言及（特定のフック名・スクリプト名等）は書かない。原則は実装詳細ではなく方針を書く場所
- ロードマップ・次にやることのリストは書かない
- README「目的」節の既存4行は文言も順序も変更しない。リンクは既存4行の後に追加する独立した1行とする
- 「原則」に列挙する項目は次の7件（1件1行、順不同で構わない）：
  1. 作成→検証の二段構成（作成エージェントの成果物を、別コンテキストの検証エージェントが受け入れ基準で採点する）
  2. 状態はすべて `vault/` のファイルに集約する
  3. タスクの状態は5つで固定し、状態を変えたら必ずログに追記する
  4. 質問は着手前にまとめて聞き、着手後に判断が必要になったら止めて聞く（推測で進めない）
  5. 最終的な承認・決定権は人が持つ
  6. ドメイン固有の知識（コーディングルール等）は `vault/rules/` の拡張点に分離し、ハーネス本体には持たない
  7. 1セッション＝1計画＝1ブランチで作業を閉じる
- 「非ゴール」に列挙する項目は次の3件：
  1. マルチユーザー化・SaaS化・GUI化はしない（個人の私的ツールとして閉じたままでよい）
  2. 汎用のプロジェクト管理・タスク管理ツールになることは目指さない
  3. Claude Code以外のランタイムへの対応は現時点では目指さない
- 本タスクの成果物ファイルは `docs/vision.md` と `README.md` の2つだが、両者は「vision文書の新設とそこへの導線」という1つの変更意図であり、計画の分割方針どおり分割しない
