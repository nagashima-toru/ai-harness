# T-03 ガードが先頭の cd <リポジトリのルート> を読み飛ばして解析するようにする

## 目的
`cd /path/to/repo; ls … 2>/dev/null; grep … vault/rules/…` のように、先頭でリポジトリのルートに `cd` するだけのコマンドは、`cd` が解析しないコマンド語のため従来判定に落ち、引数の `vault/rules/` を書き込み先とみなされる（issue #109 の2つ目の再現の実際の原因）。ルートと同じディレクトリへの先頭の `cd` だけは読み飛ばして解析する。

## 入力
- `.claude/hooks/agent_write_guard.py`（`analyze_bash_writes`、`UNPARSEABLE_COMMANDS`、`analyze_bash_writes` を呼ぶ6か所：`targets_vault_rules`・`targets_transcript_dir`・`targets_creator_denied_paths`・`find_done_task_write`・`is_git_commit_command`・`main` の許可リストの判定、モジュールの docstring）
- `scripts/smoke.sh`（T-01 で足した `(guard-text cd)` のケース、既存の「(bash-parse) cd 後の相対リダイレクト（vault/rules/common 配下）→ 拒否」）
- 計画票 `vault/plans/P-20261003-guard-rules-path-text.md` の「分割方針」

## 成果物
- `.claude/hooks/agent_write_guard.py`（`analyze_bash_writes` に引数 `root` を足し、先頭の cd を読み飛ばす処理を加え、呼び出し6か所で root を渡す）

## 受け入れ基準
- smoke がすべて通り、回帰ケース15件が ok。確認：`bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=454 fail=0`、`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guard-text'` が `15`
- ルート以外への cd を含む既存の拒否が残っている。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (bash-parse) cd 後の相対リダイレクト'` が `1`
- `analyze_bash_writes` が root を受け取り、6か所すべてで root を渡している。確認：`grep -c '^def analyze_bash_writes(cmd, root=None):' .claude/hooks/agent_write_guard.py` が `1`、`grep -c 'analyze_bash_writes(cmd, root)' .claude/hooks/agent_write_guard.py` が `6`
- 構文が正しい。確認：`python3 -m py_compile .claude/hooks/agent_write_guard.py` の終了コードが0
- 変更したのはガードだけ。確認：`git status --porcelain` の出力が `.claude/hooks/agent_write_guard.py` と `vault/tasks/P-20261003-guard-rules-path-text/T-03.md` の行だけ

## 決定済み
- 読み飛ばす形：トークン列の最初のセグメントが、語がちょうど2つ（`cd` と1つの引数）、リダイレクト無しで、直後の区切りが `;` か `&&`（改行は `_strip_heredocs` が `;` に変える）のもの。引数に `$`・`~`・`*`・`?`・`[`・`{`・`` ` `` を含まず、`-` でもないこと。引数が相対パスなら root を起点に解決し、`os.path.realpath` した結果が `os.path.realpath(root)` と一致する時だけ、そのセグメントと区切りを捨てて残りを通常どおり解析する
- 読み飛ばさない形（従来どおり `_Unparseable` で None）：root が None、cd 先がルート以外（worktree・サブディレクトリ・`/tmp` など）、引数なしの `cd`、`cd -`、区切りが `||`・`|`・`&`、2つ目以降のセグメントにある `cd`（先頭で1回読み飛ばした後に再び `cd` が出た時も None）。`UNPARSEABLE_COMMANDS` から `cd` は外さない
- 引数：`def analyze_bash_writes(cmd, root=None):` とし、root が None の時は今までと同じ動作にする。呼び出し6か所はすべて `analyze_bash_writes(cmd, root)` と書く（受け入れ基準の `grep -c` が `6` になる書き方。`is_git_commit_command` は `def is_git_commit_command(cmd, root=None):` にし、`main` からの呼び出しを `is_git_commit_command(cmd, root)` にする）
- smoke の pass 数：T-01 の後の 440 − 1（置き換えたケース）+ 15 = 454。T-01・T-02 の後で他のケースが増減していれば、`smoke: pass=<数> fail=0` の数はその時の数になってよいが、fail=0 と `(guard-text` の ok 15件は必須
- 2つの smoke 失敗（C1・C2）が ok になればよい。それ以外の既存ケースの期待は変えない。smoke.sh は編集しない
- docstring：モジュールの docstring の issue #91 の段落の末尾に、「先頭のリポジトリのルートへの cd は読み飛ばして解析する（issue #109）」旨の1文を足す。`analyze_bash_writes` の docstring にも root 引数と cd の例外を1文足す
- worktree など、ルート以外への cd の解析は扱わない（計画票の「次フェーズの候補」）
- issue #85 の扱い：`.claude/hooks/agent_write_guard.py` への Edit・Write が、reason が `[agent_write_guard]` で始まらない形（auto mode の分類器・権限判定）で拒否された時は、Bash の `sed`・`python3` での書き込みなど別の手段で回避しない。書くつもりの変更（変更する関数の全文と、6か所の呼び出しの変更・docstring に足す文と挿入位置）を `vault/tasks/P-20261003-guard-rules-path-text/T-03-patch.md` に書き、status を blocked、question に「hook の編集が権限判定で拒否された。T-03-patch.md の変更を人が手で適用してから unblock してほしい」と書く
- コミットは不要（受け入れ基準に無い）
