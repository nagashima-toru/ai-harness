## 決定済み
- ファイル名は `vault/rules/common/roles.md` で固定（小文字ケバブケース）
- 書くのは「受け渡しの契約」だけ。目安は次の3つで、各1〜3行：
  - planner→creator：渡すのはタスク票の6見出し。creator は「決定済み」を回答として優先し、書かれていないことは自分で決めずに blocked にする
  - creator→verifier：渡すのは成果物と受け入れ基準の確認コマンドだけ。verifier に会話・言い訳を渡さない。verifier は「進捗」や作成側の説明文を根拠にしない
  - verifier→creator/人：渡すのは `vault/verdicts/<id>.json` の `result` / `reasons` / `criteria[].note`。creator は verifier の返答文ではなく verdict ファイルを根拠に次の行動を決める
- 加えて「人→planner（ゴールと設計文書）」「creator→人（blocked の question）」に各1行触れてよいが、全体で100行を超えない範囲に留める
- 役割ごとの具体的な禁止（失敗例）はここには書かない。T-0020（planner）・T-0021（creator）・T-0022（verifier）の各ファイルに書く
- 「確認方法」には、このルールを満たしているか人が見る観点（例：verdict の note が成果物と実行結果だけを根拠にしているか）を2〜4行で書く。機械的な確認コマンドが無くてもよい
- `vault/rules/` は `doing`/`review` 中は書き込みが拒否される。このタスクは人が `HARNESS_ALLOW_RULES_WRITE=T-0019 claude`（または同形の `claude -p "/run-queue"`）で起動している前提で進める。Write が deny されたら自分でフックや設定を変えず、status を `blocked` にし question に「`HARNESS_ALLOW_RULES_WRITE=T-0019` を設定して再実行してください」と書く
- `README.md`・`CLAUDE.md`・`docs/vault-spec.md`・エージェント定義・スキル・フック・`scripts/` は変更しない（配布と文言修正は T-0023）
- git commit はしない（人が確認してからコミットする）
