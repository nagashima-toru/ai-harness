# T-02 planner.md に拒否されにくい grep パターンの書き方の指針を足す

## 目的
確認コマンドの grep パターンにシェルの特殊文字（`$`・`"`・リダイレクト記号など）を含めたため、Claude Code 側のガードにコマンドごと拒否されたことへの対策として、`.claude/agents/planner.md` に拒否されにくい grep パターンの書き方の指針を足す。

## 入力
- `.claude/agents/planner.md`（「やらないこと」節と「書き終えた後の確認」節。T-01 で差分確認の項目が書き換わった後の版）
- `.claude/settings.json`（`permissions.allow`・`permissions.deny`）
- `.claude/hooks/agent_write_guard.py`（Bash で拒否するのはベースブランチ上の `git commit` だけ）
- `scripts/smoke.sh` 2006行目付近（例に使う行：`git -C "$WTMAIN" worktree remove --force "$LEAF" >/dev/null 2>&1`）

## 成果物
- `.claude/agents/planner.md`（1ファイル。「やらないこと」節に項目を1つ足し、「書き終えた後の確認」節に確認を1つ足す）

## 受け入れ基準
1. 「やらないこと」節に、特殊文字を含まない短い一意な部分文字列で grep する指針がある：`grep -cF '短い一意な部分文字列' .claude/agents/planner.md` の出力が `1`
2. 原因を確定せず、再現しなかったことが書かれている：`grep -cF '再現しなかった' .claude/agents/planner.md` の出力が `1`
3. 特殊文字を `.` に置き換えた例が書かれている：`grep -cF 'remove --force ..LEAF' .claude/agents/planner.md` の出力が `1`
4. その例が書かれたとおりに機能する：`grep -c 'remove --force ..LEAF' scripts/smoke.sh` の出力が `1`
5. 「書き終えた後の確認」節に確認が足されている：`grep -cF 'grep パターンにシェルの特殊文字を含めていないか' .claude/agents/planner.md` の出力が `1`
6. 文書の参照が壊れていない：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
7. smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 「やらないこと」節の末尾（「旧形式の記述が残っていないことを検出する正規表現を…」の項目の後）に、次の項目をそのまま足す（言い回しの微修正は可。ただし下の「必ず書く語」と「書かない語」を守る）。

  ```
  - 確認コマンドの grep パターンに、シェルの特殊文字（`$`・`"`・`>`・`<`・`&`・`|`・`;`・バッククォート）を含めない。単一引用符で囲んでいても、`$変数`・`"`・リダイレクト記号を含むパターンの grep が、Claude Code 側のガード（サンドボックス／権限判定）にコマンドごと拒否されたことがある。このリポジトリのフックと `.claude/settings.json` の `permissions.deny` には該当する判定が無く、別のセッションで同じコマンドを実行した時は再現しなかったので、拒否の原因は確定していない。パターンは、検査したい行の中から特殊文字を含まない短い一意な部分文字列を選ぶ。特殊文字をまたぐ必要がある時は、その文字を正規表現の `.` に置き換える（例：`git -C "$WTMAIN" worktree remove --force "$LEAF" >/dev/null 2>&1` の行は、`grep -c 'remove --force ..LEAF' scripts/smoke.sh` が `1` になることで確かめる）。一意かどうかは、planner が実行して期待値を確かめてから書く
  ```
- 「書き終えた後の確認」節の、「`(ref-1)` の対象の文書を成果物に持つタスクに…」の行の後に、次の1行をそのまま足す（下のコードブロックの中身1行）。この行には `短い一意な部分文字列` の語を入れない（入れると基準1が `2` になる）
  ```
  - 確認コマンドの grep パターンにシェルの特殊文字を含めていないか。含めずに書けない時は、特殊文字を `.` に置き換えたパターンにしたか
  ```
- 必ず書く語（受け入れ基準1〜3・5が数える。各語ともファイル全体でちょうど1回）：`短い一意な部分文字列`・`再現しなかった`・`remove --force ..LEAF`（以上は「やらないこと」の項目に）、`grep パターンにシェルの特殊文字を含めていないか`（「書き終えた後の確認」の行に）。
- 書かない語：`起点コミット`（smoke の `(agents-1)` が planner.md にこの語が無いことを検査している）。計画 ID・issue 番号などこのリポジトリ固有の経緯（planner.md は導入先に配る汎用の文書で、経緯は T-03 が `vault/rules/planner/ai-harness-lessons.md` に書く）。
- 拒否の原因について planner が確かめたこと：planner のセッション（メインセッション、auto mode）で `grep -cF 'git -C "$WTMAIN" worktree remove --force "$LEAF" >/dev/null 2>&1' scripts/smoke.sh` を `cd` 付き・無しの両方で実行したが拒否されず、出力は `1` だった。`.claude/hooks/agent_write_guard.py` が Bash で拒否するのはベースブランチ上の `git commit` だけで、`.claude/settings.json` の `permissions.deny` に grep に当たる項目は無く、`permissions.allow` に `Bash(grep *)` がある。creator（サブエージェント）で拒否された原因は確定していないので、項目にも原因を断定して書かない。
- 受け入れ基準4の例は planner が実行済み（出力 `1`）。`..` は `"$` の2文字に当たる。`grep -cF 'worktree remove --force'` は `12` 件に当たり一意でないので例に使わない。
- T-01 で書き換わった差分確認の項目には触れない。ほかの項目・節も変えない。

## 進捗
- 読んだルール: vault/rules/common/vision.md
- planner.md の「やらないこと」末尾に項目、「書き終えた後の確認」末尾に1行を追加
- 基準1〜7の確認コマンドを実行し、すべて期待値（1,1,1,1,1,1、fail=0）
