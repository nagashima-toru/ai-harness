# T-0021 creator（run-queue メイン）の責務と「やらないこと」をルール化する

## 目的
作成エージェント（run-queue のメインエージェント）の責務・入出力と、実際に起きた失敗から導いた「やらないこと」を `vault/rules/creator/` に1ファイルで定義し、review へ回す前の手戻りを減らす。

## 入力
- `vault/rules/common/roles.md`（T-0019 の成果物。受け渡しの契約。ここと重複させない）
- `.claude/skills/run-queue/SKILL.md`（現在の手順。重複させすぎない）、`vault/templates/rule.md`（3見出し）
- `CLAUDE.md`（状態遷移・質問のしかた・禁止）、`docs/vault-spec.md` 第2節・第8節
- 失敗例の一次情報：`vault/tasks/T-0002.md`（満たせない受け入れ基準に当たった時の対応が「進捗」に残っている）

## 成果物

## 受け入れ基準
- `vault/rules/creator/creator.md` が存在し、見出しが `## 目的` / `## ルール` / `## 確認方法` の3つだけ。確認：`grep -c '^## ' vault/rules/creator/creator.md` が3
- 100行以内。確認：`grep -c '' vault/rules/creator/creator.md` が100以下
- 「ルール」に (a) 着手時に `bash scripts/rules.sh creator` を実行して列挙されたファイルを読む、(b) タスク中に `vault/rules/` を編集しない、(c) 受け入れ基準の確認コマンドを自分でも実行して通してから `review` にする、の3点が各1項目以上ある。確認：`grep -c 'rules.sh creator' vault/rules/creator/creator.md` が1以上
- 「やらないこと」に、満たせない受け入れ基準に当たった時は基準やフック・設定を自分で書き換えず `blocked` にして question を書く旨があり、根拠のタスク ID を明記している。確認：`grep -c 'T-00' vault/rules/creator/creator.md` が1以上
- `bash scripts/rules.sh creator` の出力に `vault/rules/creator/creator.md` が含まれ、`bash scripts/rules.sh verifier` と `bash scripts/rules.sh planner` の出力には含まれない
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

## 決定済み
- ファイル名は `vault/rules/creator/creator.md` で固定
- 「ルール」は「責務」と「やらないこと」の2つの箇条書きの塊で書いてよい（見出しは3つのまま、区切りは太字の行か空行）
- 責務として書くこと（各1行）：タスク票の6見出しを全部読み「決定済み」を回答として優先する／着手時に `rules.sh creator` を読み、読んだルール名を「進捗」に1行残す／`doing` は常に1件／進捗はセッションが切れても再開できる粒度で追記する／状態を変えたら `vault/log/queue.md` に1行追記する／受け入れ基準の確認コマンドを自分でも実行してから `review` にする／verifier には ID だけを渡し、説明や言い訳を渡さない／FAIL 後は verdict の `reasons` だけを根拠に直す
- 「やらないこと」として書くこと：受け入れ基準・タスク票の受け入れ基準行を自分で書き換えない／`vault/rules/` をタスク中に編集しない（verifier の判定基準を自分で緩めないため。フックでも拒否される）／フックや `settings.json` を通すために書き換えない／`done` のタスク票・verdict を編集しない／「決定済み」に答えが無い判断を勝手にせず `blocked` にする（T-0002 で満たせない基準に当たった時に blocked にして人に確認した例を根拠として挙げる）／受け入れ基準に無い作業（リファクタ・コミット）を足さない
- 「確認方法」には review に回す直前のセルフチェックを3〜5行で書く（例：受け入れ基準の各行の確認コマンドを実行し出力を控えたか、進捗に読んだルールと実行結果が残っているか、log を追記したか）
- `vault/rules/` は `doing`/`review` 中は書き込みが拒否される。人が `HARNESS_ALLOW_RULES_WRITE=T-0021` を設定して起動している前提で進め、Write が deny されたら `blocked` にして question に設定方法を書く
- `.claude/skills/run-queue/SKILL.md`・`CLAUDE.md`・`docs/`・`README.md`・`scripts/` は変更しない（配布と文言修正は T-0023）
- git commit はしない（人が確認してからコミットする）
