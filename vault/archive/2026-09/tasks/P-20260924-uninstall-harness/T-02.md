# T-02 scripts/unmerge_settings_json.py を作る（settings.json からハーネス由来のエントリのみ除去）

## 目的
`scripts/merge_settings_json.py` の逆処理として、`.claude/settings.json` からハーネスが足した hooks エントリと `permissions.deny` の項目だけを取り除くスクリプトを作る。利用者が自分で足した `permissions.allow` やその他の設定には触れない。

## 入力
- `/home/user/ai-harness/scripts/merge_settings_json.py`（対になる正処理。`commands()` による command 文字列集合の比較方法、バックアップの作り方、メッセージ文言の流儀をそろえる）
- `/home/user/ai-harness/.claude/settings.json`（テスト時の src サンプルとして使える実例）

## 成果物
- `scripts/unmerge_settings_json.py`（新規ファイル1つ）

## 受け入れ基準
- `src` の hooks に含まれる `command` 文字列が `dst` の同じ event の hooks エントリに存在する場合、その command だけを除去する。利用者が追加した別の command は残す。確認：テスト用 dst に「src と同じ command」＋「利用者が追加した別 command」を同じ event の別エントリとして用意して実行し、後者だけが残ること（`python3 -c "import json; ..."` で dst を読んで検証）
- hooks 除去の結果、あるエントリの `hooks` 配列が空になったら、そのエントリ自体を event の配列から削除する。確認：除去後の JSON にそのエントリ（matcher）が残っていないこと
- `src` の `permissions.deny` に含まれる文字列のうち `dst` にも存在するものだけを除去し、`dst` 独自の deny 項目は残す。確認：`python3 -c` で dst の `permissions.deny` を読み、src 由来の項目が無く利用者項目が残ることを確認
- `permissions.allow` は一切変更しない。確認：実行前後で `dst` の `permissions.allow` が完全に一致すること（`python3 -c "import json;print(json.load(open(p))['permissions'].get('allow'))"` を前後で比較）
- 除去対象が無い時は書き換えず `skip <dst>` と出力する。確認：src の内容が dst に一つも含まれない状態で実行し、出力に `skip` を含み、実行前後で dst の mtime とバイト内容が変わらないこと
- 書き換えが発生した時だけ `<dst>.bak-<YYYYMMDDHHMMSS>` のバックアップを作る（`merge_settings_json.py` と同じ命名規則）。確認：バックアップファイルの存在と、その中身が実行前の dst 内容と一致すること

## 決定済み
- インターフェースは `merge_settings_json.py` と対称：`python3 scripts/unmerge_settings_json.py <src_settings_json> <dst_settings_json>`
- 一致判定は「command 文字列の完全一致」「deny 項目の文字列の完全一致」のみで行う（`merge_settings_json.py` の `commands()` と同じ粒度）。matcher の値や hooks エントリの他フィールドは比較しない
- 利用者が harness と偶然同じ command / deny 文字列を独自に追加していた場合、区別できずに一緒に消える可能性がある。これは許容する仕様上の限界とし、`docs/install.md`（T-05）に注記する
- `src` や `dst` が JSON として読めない・オブジェクトでない場合はエラーメッセージを stderr に出し exit 1 する（`merge_settings_json.py` の既存のエラー処理と同じ方針でよい）
- `dst` が存在しない場合は「削除対象が無い」として何もせず `skip <dst>` を出力する（`create` に相当する逆操作は無い。存在しないファイルを作る必要は無い）
