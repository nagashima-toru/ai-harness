# T-01 着手可能集合の算出と doing への一括反映（HARNESS_MAX_PARALLEL 導入）

## 目的
`run` スキルの「取り出す」手順を、単一の `todo` を1件ずつ選ぶ方式から、着手可能集合（`todo` かつ `after` が全て `done` な行）を環境変数 `HARNESS_MAX_PARALLEL`（既定 3）件まで選び、選んだタスク全部をまとめて1回で `doing` にする方式に変更する。

## 入力
- `vault/designs/D-003.md`（フェーズ3節、73〜93行目。特に「決定済み」の `HARNESS_MAX_PARALLEL` 導入方針）
- `.claude/skills/run/SKILL.md`（現状の手順2「取り出す」）
- `docs/vault-spec.md`（2節：状態遷移と `HARNESS_MAX_ATTEMPTS` の既定値の書き方のパターン）
- `vault/plans/P-20260924-run-parallel-state.md` と配下タスク票（フェーズ1で緩和済みの「`doing`/`review` は着手可能集合に限り複数件になりうる」前提）

## 成果物
- `.claude/skills/run/SKILL.md` の手順2「取り出す」の書き換え、および `docs/vault-spec.md` の該当箇所（2節）への `HARNESS_MAX_PARALLEL` の既定値追記（1つの変更としてまとめて扱う）

## 受け入れ基準
- `run/SKILL.md` の手順2に「着手可能集合」という語があり、`after` が全て `done` である `todo` 行を列挙する説明が書かれている。確認: `grep -n "着手可能集合" .claude/skills/run/SKILL.md`
- 同手順に `HARNESS_MAX_PARALLEL` と既定値「3」が書かれ、着手可能集合の先頭からその上限までを選ぶ手順になっている。確認: `grep -n "HARNESS_MAX_PARALLEL" .claude/skills/run/SKILL.md`
- 選んだタスク全部を `doing` にする計画票への書き込みが、タスクごとに分けず1回にまとまっている旨が明記されている。確認: 該当箇所を Read し「まとめて」「一括」等、複数タスクを同一手順内で連続して更新する旨の記述があることを確認する
- ログ追記についても、選んだタスク分をこの手順の中でまとめて（1回、または連続して）追記する旨が明記されている
- `docs/vault-spec.md` に `HARNESS_MAX_PARALLEL`（既定 3）の記載がある。確認: `grep -n "HARNESS_MAX_PARALLEL" docs/vault-spec.md`

## 決定済み
- 着手可能集合の定義は「`todo` かつ、`after` に列挙された全タスクの `status` が `done`（`after` が `-` なら無条件）」。計画票のタスク表の上から順に並べ、`HARNESS_MAX_PARALLEL`（既定 3。未設定時は3を使う。`stop_gate.py` の `HARNESS_MAX_ATTEMPTS` と同じ環境変数パターンを踏襲）件まで先頭から選ぶ
- 手順2の既存ロジック（`doing`/`review` の行があれば新規選定をせずそちらを再開する）は変更しない。変更するのは「新たに `todo` から選ぶ」部分を複数選択に広げる箇所だけ
- `HARNESS_MAX_PARALLEL` の既定値の明記先は `docs/vault-spec.md`（`HARNESS_MAX_ATTEMPTS` の既定値が書かれている2節）にする。`.claude/ai-harness.md` はこの数値を持たない既存パターンに合わせ、追記は不要
- 「1回にまとめる」とは、選んだタスク全部の `status`/`attempt` 変更を、他の処理を挟まずこの手順の中で連続して行うことを指す。実際のツール呼び出しが Edit 1回か複数回かは問わない。ログ追記も同様に、選んだタスク分をこの手順内でまとめて行う
- 手順3（作る）以降の creator の並行 worktree 起動方法は T-02 の範囲。このタスクでは変更しない
