# T-06 vault/rules/README.md の書き換え案を提案ファイルに書く

## 目的
エージェントは `vault/rules/` に書けないので、`vault/rules/README.md` を「ハーネスは標準ルールを同梱しない。役割定義は `.claude/agents/` にある。`vault/rules/` は導入先のルール専用」の形にする全文の案と、人が行う作業（6本の `git rm` と README への反映）を提案ファイルにまとめる。人はこれを見て PR のマージ前に同じブランチで反映する。

## 入力
- `vault/designs/D-013.md` の「フェーズ4 標準の役割定義をエージェント定義に統合する」（決定済み：6本の削除と README への反映は人が行う）
- `vault/rules/README.md`（今の全文）
- `docs/vault-spec.md` 11節・`README.md` の拡張ポイントの節（T-05 の結果。文言を揃える）
- `docs/install.md` の「ハーネスを更新する」節（T-05 の結果。旧版の6本の扱いの文言を揃える）

## 成果物

## 受け入れ基準
- 提案ファイルに見出し `## 提案：vault/rules/README.md の全文` と `## 人が行う作業` がこの順にある：`grep -nE '^## (提案：vault/rules/README\.md の全文|人が行う作業)$' vault/tasks/P-20261008-agent-role-merge/T-06-proposal.md` の出力が2行で、1行目が「提案」の行
- 全文の案に「ハーネスは標準ルールを同梱しない」の文と `.claude/agents/` への案内があり、6本のファイル名が無い：`sed -n '/^## 提案/,/^## 人が行う作業/p' vault/tasks/P-20261008-agent-role-merge/T-06-proposal.md | grep -nE 'roles\.md|creator/creator\.md|verifier/verifier\.md|planner/planner\.md|common/git\.md|git-workflow\.md'` の出力が空で、同じ範囲を Read して「ハーネスは標準ルールを同梱しない」と `.claude/agents/` が書かれていることを確認
- 全文の案が、今の `vault/rules/README.md` の「振り分け」「書き方」「verifier との関係」「注意」の各節の内容を同じ意味で保っている（Read で見比べて確認）
- 「人が行う作業」に、6本それぞれの `git rm` のコマンド（計6行）と、全文の案を `vault/rules/README.md` に反映する手順と、反映後に `bash scripts/smoke.sh` を実行する手順が書かれており、`vault/rules/planner/ai-harness-lessons.md` を削除の対象にしていない（Read で確認）
- 提案ファイルのほかに変えたファイルが無い：`git status --porcelain -- vault/rules` の出力が空

## 決定済み
- 全文の案は、反映時にそのまま貼れるよう、`## 提案：vault/rules/README.md の全文` の下に README の本文（`# vault/rules/ の書き方` から始まる）をそのまま書く。コードブロックで囲むかは任せる
- 冒頭の段落は T-05 の `docs/vault-spec.md` 11節の文言に揃える：「ハーネスは標準ルールを同梱しない。」で始め、役割定義は `.claude/agents/creator.md`・`.claude/agents/verifier.md`・`.claude/agents/planner.md` にあること、`vault/rules/` はコーディングルール・開発標準・方式設計・テスト観点など導入先のルールの置き場であることを書く
- 旧版の導入先にある6本の扱い（`install.sh --update` が未編集なら削除、編集済みは残して note で案内）を一文入れてよい。6本のファイル名は書かない
- 「人が行う作業」には次を書く：`git rm vault/rules/common/roles.md` などの6行（`vault/rules/common/roles.md`・`vault/rules/common/git.md`・`vault/rules/creator/creator.md`・`vault/rules/creator/git-workflow.md`・`vault/rules/verifier/verifier.md`・`vault/rules/planner/planner.md`）、全文の案を `vault/rules/README.md` に貼る、コミットする、`bash scripts/smoke.sh 2>&1 | tail -1` が `fail=0` を含むことを確かめる。`vault/rules/planner/ai-harness-lessons.md` と `.gitkeep` は残すと明記する
- `vault/rules/planner/ai-harness-lessons.md` の参照先の直しは T-07 の提案ファイル（`vault/tasks/P-20261008-agent-role-merge/T-07-proposal.md`）で扱う。この提案ファイルには直し案を書かず、「人が行う作業」に「T-07 の提案ファイルも反映する」と1行で触れるだけにする
- `vault/rules/` の実体には書き込まない（フックが常に拒否する）。`docs/`・`README.md`・`.claude/` も変えない
