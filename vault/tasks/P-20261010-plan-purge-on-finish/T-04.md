# T-04 vault-spec・runbook・ai-harness.md を計画一式の除去に揃え、古い記述が残っていないことを確かめる

## 目的
T-01〜T-03 の変更（`scripts/purge_plan.sh`・`scripts/plan_record.py`・run スキル手順7の新しい順序と PR 本文の構成）を、仕様の正本 `docs/vault-spec.md`、人向けの `docs/runbook.md`、共通ルール `.claude/ai-harness.md` に揃える。計画一式が PR の直前に除去されて `main` に入らないこと、証跡が PR に残ることを明記し、古い PR 本文の構成の記述がリポジトリに残っていないことを確かめる。

## 入力

- 仕様の7節に、log の全行が plan_record.py で PR 本文に写されることと使い方がある。確認：`awk '/^## 7\. /,/^## 8\. /' docs/vault-spec.md | grep -cF 'log の全行は `scripts/plan_record.py` が PR 本文に写す'` の出力が `1`、かつ `awk '/^## 7\. /,/^## 8\. /' docs/vault-spec.md | grep -cF 'python3 scripts/plan_record.py <計画ID>'` の出力が `1`

## 決定済み
- 確認の範囲から外すもの（理由）：`docs/decisions.md`（判断の記録で過去の行を書き換えない）、`vault/plans/`・`vault/tasks/`・`vault/log/`・`vault/verdicts/`・`vault/archive/`・`vault/designs/`（履歴と状態。D-016 自身が古い構成に触れている）。受け入れ基準の grep はこれらを対象に入れていない
- `docs/vault-spec.md` の直し方（実際の動きは T-01〜T-03 の成果物を正とする）
  - 1節：「証跡は3層で残る」の段落の後（`HARNESS_PR_BODY_FILE` の段落の後でもよい）に、計画一式の除去の段落を足す。書くこと：計画一式4種（`vault/plans/<計画ID>.md`・`vault/tasks/<計画ID>/`・`vault/verdicts/<計画ID>/`・`vault/log/<計画ID>.md`）は、run の手順7で `PR を作る直前に除去し、`main` には入れない`（この字面を1節で1回だけ使う）。除去は `bash scripts/purge_plan.sh [--dry-run] <計画ID>`（この字面を1節で1回だけ使う）で、条件（ブランチが `work/<計画IDの英小文字>`・計画票が `status: done`・タスク表が1行以上で全行 done・対象パスに未コミットの変更が無い）、存在しないパスは飛ばすこと、`--dry-run` は消す予定のパスを1行1件で出して何も変えないこと、終了コード（0・1・2）、コミットしないこと（オーケストレーターが `<計画ID>: 計画一式を除去` でコミットする）。続けて「`証跡は PR に残る`」（この字面を1節で1回だけ使う）として、PR 本文に計画のゴール・タスク表・log の全行・verifier の指摘が写り、タスク票と verdict の中身は PR のコミット履歴から辿ること、残すべき情報は除去の前に docs への追記か Issue 化で取り出すこと（取り出しの結果は PR 本文の `## 取り出した情報`）を書く。`vault/harness-improvements/` は除去の対象外であることも書く
  - 1節の「証跡は3層で残る」の段落：3層が計画ブランチの中の証跡であることと、マージ後は PR（本文とコミット履歴）から辿ることが分かるように直す（3層の中身は変えない）
  - 1節の `HARNESS_PR_BODY_FILE` の段落の最後の文「run は全タスクが done になった後、この経路で本文（計画 ID・`scripts/pr_body.py` のタスク一覧・「verifier の指摘」節）を渡す（6節）」を、新しい構成（計画 ID の1行・`scripts/pr_body.py` の出力・`## verifier の指摘`・`scripts/plan_record.py` の出力・`## 取り出した情報` の順）に直す
  - 2節の `/run` の箇条の「例外として、計画票の frontmatter の approved→done（手順7）は Edit で行い、…」に、続けて計画一式の除去（`scripts/purge_plan.sh` の `git rm` と除去のコミット）も transition.py を通さない例外であることを足す。`git add vault/plans/<計画ID>.md` の字面はこの箇条の1か所のまま（増やさない）
  - 4節の status の表の `done` の行：意味を「全タスクが `done` になり、計画一式を除去して `scripts/vcs_finish.sh` を実行済み」の趣旨にし、表の後に、done にした計画票は除去のコミットで消えるため計画ブランチの履歴にだけ残ること（`main` にある done の計画票はこの方式より前のもの）を1文で足す
  - 7節：段落を足す。書くこと：`log の全行は `scripts/plan_record.py` が PR 本文に写す`（この字面を7節で1回だけ使う）。使い方 `python3 scripts/plan_record.py <計画ID>`（この字面を7節で1回だけ使う）、出力の見出し（`## 計画の記録` の下に `### ゴール`・`### タスク表`・`### log`。log は `<details>` で畳む）、ファイルに書き込まないこと、終了コード（0 出力した／1 計画票か log が無い／2 引数の誤り）。あわせて、log は除去されて `main` に残らないので、`scripts/model_stats.py` の既定（`vault/log/*.md`）で計画をまたいで集計できるのは計画ブランチの中と除去より前の分だけで、除去後の集計は PR 本文の log から人が行う（D-016 の「今回やらないこと」）ことを1文で書く
- `docs/runbook.md` の直し方
  - 3節の「承認済み計画の全タスクが `done` になったら、計画票の `status` を `done` にしてコミットしてから `bash scripts/vcs_finish.sh` を実行する…」の箇条を、計画票を done にしてコミットし、計画の記録を PR 本文に写し、残すべき情報を docs への追記か Issue 化で取り出し、`scripts/purge_plan.sh` で計画一式を除去してコミットしてから `bash scripts/vcs_finish.sh` を実行する、の趣旨に直す（GitHub・GitLab・ホスティング無しの説明は残す）。`scripts/purge_plan.sh` の字面は runbook の中でこの1か所だけにする
  - 3節の「PR のマージ方式」の箇条に、PR 本文には「タスク履歴」表に加えて計画の記録（ゴール・タスク表・log の全行）と verifier の指摘・取り出した情報が載り、計画一式は `main` に入らないので、マージ後に計画を調べる時は PR を見ることを足す
  - 5節（archive）・1行目の「月次で片づける」はフェーズ2で書き換えるので変えない
- `.claude/ai-harness.md` の「役割」のオーケストレーターの行の「成果物は自分で作らない」の後に、例外として「全タスクが done になった後の取り出し（docs への追記・Issue 化）と、`scripts/purge_plan.sh` による計画一式の除去は行う」の趣旨を、この順（`取り出し（docs への追記・Issue 化）` の字面が先、`scripts/purge_plan.sh` が後）で同じ行に足す。行は `- オーケストレーター` で始まる1行のまま
- `README.md`・`docs/decisions.md`・`docs/install.md`・`docs/vision.md`・`.claude/skills/`・`scripts/` はこのタスクでは変えない（README は図と scripts の一覧が要約で、今回の変更と食い違う記述が無い。フェーズ2で archive の記述と合わせて見直す）
- バッククォートで書くパスは実在するもの（`scripts/purge_plan.sh`・`scripts/plan_record.py` など）か、`<計画ID>` などの雛形を含む形にする（smoke の `(ref-1)` が実在しないパスを落とす）
