# T-03 docs/vault-spec.md の verdict 節に reasons の意味論拡張を明記する

## 目的
`reasons` が FAIL の理由だけでなく、判定不能・基準が緩いと判断した場合・宣言外ファイルの変更を検出した場合の
記録にも使われることを、正本である `docs/vault-spec.md` の verdict の節に明記する。

## 入力
- `docs/vault-spec.md` の「## 6. verdict.json」節（改訂対象）
- `vault/rules/verifier/verifier.md`（T-01 で追加した2責務の文言。本票の決定済みに引用済みなので参照は任意）

## 成果物
- `docs/vault-spec.md`（既存ファイルの改訂。「## 6. verdict.json」節への追記のみ）

## 受け入れ基準
- 「## 6. verdict.json」節に、`reasons` が FAIL 理由だけでなく「判定不能」「基準が緩い」「宣言外ファイル」の記録にも使われる旨の記述がある。確認：`sed -n '/^## 6\. verdict.json/,/^## 7\./p' docs/vault-spec.md | grep -c -e '判定不能' -e '基準が緩い' -e '宣言外ファイル'` が3以上
- 追加した記述に、これらの記録は `result` を FAIL にはしない旨も明記されている。確認：`sed -n '/^## 6\. verdict.json/,/^## 7\./p' docs/vault-spec.md | grep -c 'FAIL にはしない'` が1以上
- 既存の「`result` は `PASS` / `FAIL` の2値」という記述行が変更されていない。確認：`grep -c '\`result\` は \`PASS\` / \`FAIL\` の2値' docs/vault-spec.md` が1
- 見出し数（`## ` で始まる行）が13のまま変わっていない。確認：`grep -c '^## ' docs/vault-spec.md` が13

## 決定済み
- 追記する文面（「## 6. verdict.json」節の既存の箇条書き末尾、コードブロックより後ろに1行足す形でよい）。
  `- \`reasons\` は FAIL の理由だけでなく、判定不能・基準が緩いと判断した場合・宣言外ファイルの変更を検出した場合の記録にも使う（\`vault/rules/verifier/verifier.md\` を根拠とする）。いずれも \`result\` を FAIL にはしない。`
- 既存のコードブロック中の JSON サンプル（`"reasons": ["FAIL の理由。PASS なら空配列"]`）は書き換えない。サンプルはそのままで、上記の追記文で意味論を補足する形にする。
- 「## 」で始まる見出し行以外（節の中の `###` や本文の `##` を含む行頭以外の出現）は数えない。見出し数が変わらないことだけを保証すればよく、既存節番号の振り直しは不要（今回は既存節への追記のみで新しい `## ` 見出しを作らない）。

## 進捗
- 読んだルール: git.md, roles.md, creator.md, git-workflow.md
- `docs/vault-spec.md` の「## 6. verdict.json」節の箇条書き末尾（`note` の説明の後、「## 7. ログ」の前）に
  `reasons` の意味論拡張を追記した
- **決定済みの文面（1行）では受け入れ基準1を満たせなかった。** 基準1は
  `grep -c -e '判定不能' -e '基準が緩い' -e '宣言外ファイル'` が3以上を要求するが、`grep -c` は
  マッチ数ではなく**行数**を数えるため、3語を1行に書くと1行としか数えられない。基準は書き換えず、
  意味を保ったまま親ブレット1行＋3つの子ブレット（判定不能／基準が緩い／宣言外ファイルを各1行）に
  分割して解消した
- 既存の JSON サンプル・`result` は `PASS` / `FAIL` の2値の行は変更していない
- 受け入れ基準の確認コマンドを実行し、4件すべて通した
  - 3語の行数=3（基準3以上を満たす）/ `FAIL にはしない`=1
  - `` `result` は `PASS` / `FAIL` の2値 ``=1（変更なし）/ 見出し数=13（変更なし）
- `vault/rules/common/git.md` のルールに沿い、作業ステップごとにコミットする
