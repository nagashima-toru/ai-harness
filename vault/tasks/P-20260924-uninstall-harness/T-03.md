# T-03 scripts/uninstall.sh を作る（マニフェスト照合削除 + 3種報告）

## 目的
導入先リポジトリで `.claude/harness-manifest.json` と照合し、未編集のハーネス本体ファイルだけを自動削除する `scripts/uninstall.sh` を作る。`CLAUDE.md` と `.claude/settings.json` はそれぞれ T-01・T-02 のスクリプトに委譲し、`vault/` の利用者資産には一切触れない。

## 入力
- `/home/user/ai-harness/scripts/install.sh`（`manifest_paths()`、`--update` の照合ロジック、報告文言 `copy` / `skip (exists)` / `skip (edited)` / `update` の流儀）
- `vault/tasks/P-20260924-uninstall-harness/T-01.md`・`T-02.md`（契約：`unmerge_claude_md.py <target_claude_md>`、`unmerge_settings_json.py <src> <dst>` のインターフェース）
- 計画票「分割方針」の `settings_src` 契約（`.claude/harness-manifest.json` に `settings_src` キーを持たせる。無ければ settings.json の自動処理をスキップする）

## 成果物
- `scripts/uninstall.sh`（新規ファイル1つ）

## 受け入れ基準
- `.claude/harness-manifest.json` の `files` に記録され、かつ現状のハッシュが記録値と一致するファイルは削除され `remove <path>` と報告される。確認：一時ディレクトリに `install.sh` でインストールし、そのまま `uninstall.sh` を実行して、マニフェスト記録済みファイルが存在しないこと
- マニフェスト記録後に利用者が編集した（ハッシュが変わった）ファイルは削除されず `skip (edited) <path>` と報告される。確認：install 後に1ファイルを書き換えてから `uninstall.sh` を実行し、そのファイルが残っていること
- `vault/plans` `vault/tasks` `vault/verdicts` `vault/log` `vault/designs` `vault/archive`、およびマニフェストに記録が無い `vault/rules/` 配下（ドメイン固有ルール）には一切触れない。確認：それらのディレクトリにダミーファイルを置いてから実行し、実行前後でそのファイル一覧が一致すること（`diff <(find <dir> -type f | sort) <(...)>`）
- `CLAUDE.md` の処理は `scripts/unmerge_claude_md.py` を呼び出して行い、`.claude/settings.json` の処理は `.claude/harness-manifest.json` の `settings_src` を一時ファイルに書き出して `scripts/unmerge_settings_json.py` に渡すことで行う（uninstall.sh 自身が CLAUDE.md や settings.json を直接パースしない）。確認：`grep -n 'unmerge_claude_md.py\|unmerge_settings_json.py' scripts/uninstall.sh`
- `.claude/harness-manifest.json` に `settings_src` キーが無い場合は settings.json の自動処理をスキップし、`note  .claude/settings.json は手動確認してください（docs/install.md 参照）` のような案内を出す（エラー終了はしない）。確認：`settings_src` を持たない manifest で実行し、終了コードが `0` かつ出力に `note` を含むこと
- `.claude/harness-manifest.json` が存在しない対象ディレクトリを指定すると、何も削除せずエラーメッセージを stderr に出して exit 1 する。確認：マニフェストの無い空ディレクトリを指定して実行し、`echo $?` が `1`、かつ対象ディレクトリにファイルが増減しないこと

## 決定済み
- 使い方：`bash scripts/uninstall.sh <target-dir>`（`install.sh` と対称。フラグは無くてよい、`--dry-run` 等は不要）
- 処理の最後に `.claude/harness-manifest.json` 自体を削除してよい（利用者資産ではなく、ハーネスの記帳ファイルであるため）。これは受け入れ基準の対象外（削除してもしなくても基準は変えない）だが、削除する場合は `remove .claude/harness-manifest.json` として報告する
- 空になった `.claude/` `vault/rules/<role>/` 等のディレクトリ自体は削除しない（ファイル削除のみ行い、ディレクトリの rmdir はしない）
- `settings_src` を一時ファイルに書き出す際の一時ファイルは `mktemp` を使い、`trap ... EXIT` で必ず削除する（`install.sh` の `HANDLED_LIST`/`SKIPPED_LIST` と同じ流儀）
- 報告は3種類の見出し（自動で消した／編集済みなので残した／利用者資産なので触れない）に相当する行を出す。「利用者資産なので触れない」は個別ファイルを毎回列挙する必要は無く、対象ディレクトリ名の案内1行でよい（例：`note  vault/ の利用者資産（plans/tasks/verdicts/log/designs/archive・標準4本以外の rules/）には触れていません`）
- マニフェストに記録されているが現状ファイルが既に存在しない（利用者が既に消した等）場合は、エラーにせず黙って無視してよい（報告しなくてよい）
