# T-0038 `scripts/merge_settings_json.py` を新規作成する

## 目的
`.claude/settings.json` に対し、hooks の欠落エントリと `permissions.deny` の不足分だけを足すマー
ジャを、`merge_claude_md.py` と同じ発想の独立した Python スクリプトとして新規作成する。
`permissions.allow` は読み取るだけで変更しない。install.sh への組み込みは次タスクで行うので、この
タスクでは単体スクリプトとして完結させる。

## 入力
- `scripts/merge_claude_md.py`（書きぶりの参考。create/merge/skip の判定・バックアップの作り方）
- `.claude/settings.json`（対象の構造。`permissions.allow`/`permissions.deny`/`hooks.Stop`/
  `hooks.PreToolUse`/`hooks.PostToolUse`）
- `vault/designs/D-001.md`「## フェーズ1」の決定事項（マージャの挙動）
- `scripts/smoke.sh`（既存の `expect_eq` ヘルパーと `== merge_claude_md.py ==` 節の書き方）

## 成果物
- `scripts/merge_settings_json.py`（新規、python3）
- `scripts/smoke.sh`（`== merge_settings_json.py ==` 節を追記。既存ケースは変更しない）

## 受け入れ基準
- dst が存在しない状態で `python3 scripts/merge_settings_json.py <src> <dst>` を実行すると dst が
  作成され、標準出力が `create ` で始まる
- dst の `permissions.allow` に独自の要素を1つ足した settings.json に対して実行すると、実行後もそ
  の要素が残っている。確認コマンド:
  `python3 -c "import json;print('独自要素' in json.load(open('<dst>'))['permissions']['allow'])"`
  が `True`
- dst の `hooks.PostToolUse` エントリを削除した settings.json に対して実行すると、実行後の
  `hooks.PostToolUse` の `hooks[].command` のいずれかに `todo_guard.py` を含む文字列がある
- dst の `permissions.deny` から要素を1つ削除した settings.json に対して実行すると、実行後の
  `permissions.deny` にその要素が含まれる
- 同じ src/dst の組で直後にもう一度実行すると、標準出力が `skip ` で始まる（冪等）
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（新規ケース込み）

## 決定済み
- 呼び出し形式：`python3 scripts/merge_settings_json.py <src_settings.json> <dst_settings.json>`
- hooks のマージ：src の `hooks.<EventName>` の各エントリについて、その `hooks[].command` の文字
  列のいずれかが dst の同じ `<EventName>` の既存エントリの `hooks[].command` のどれかと完全一致し
  ていれば、そのエントリは足さない。一致するものが無ければ、src のエントリ（`matcher` を含む）を
  そのまま dst の `hooks.<EventName>` 配列の末尾に追加する。dst に `hooks` キーや `<EventName>`
  キーが無ければ作る
- `permissions.deny` のマージ：src と dst それぞれの `permissions.deny` を文字列の集合とみなし、
  src にあって dst に無い文字列だけを、src の並び順で dst の `permissions.deny` 配列の末尾に追加す
  る。dst に既にある要素の順序・重複は変更しない
- `permissions.allow`：読み取るだけで一切変更しない。dst の内容をそのまま残す（src の allow は無
  視する）
- dst が存在しない場合は src の内容をそのまま書き込み `create <dst>` を1行出力する
- 変更が無い場合（hooks・deny のどちらにも追加が発生しない）は書き換えず `skip <dst>` を出力する
- 変更がある場合は書き換え前に `<dst>.bak-<YYYYMMDDHHMMSS>` を作ってから上書きし、`merge <dst>` を
  出力する（`merge_claude_md.py` の `update`/`merge` に相当する分岐をまとめて `merge` の1語にす
  る。settings.json には「マーカー範囲の置換」という概念が無いため区別しない）
- JSON の書き出しは `json.dumps(..., indent=2, ensure_ascii=False)` とし、ファイル末尾に改行を1つ
  付ける
- 実装は標準ライブラリのみ（`json`・`sys`・`pathlib`・`datetime`）。`sed -i` は使わない
- このタスクでは `scripts/install.sh` に組み込まない（次タスクの範囲）。`scripts/smoke.sh` には
  `== merge_settings_json.py ==` という新しい見出し節を追加し、既存の `TMP` とは別に
  `mktemp -d` した作業ディレクトリを使ってよい

## 進捗
- 読んだルール: roles.md, creator.md
- `scripts/merge_settings_json.py` を新規作成した。標準ライブラリのみ（json / sys / datetime /
  pathlib）。`merge_claude_md.py` の構成（docstring に振る舞いを書く・`create` / `merge` / `skip` の
  3語を stdout に1行・merge 時だけ `.bak-<YYYYMMDDHHMMSS>` を残す）に合わせた
- hooks のマージ：`commands()` で各エントリの `hooks[].command` を集合にし、src のエントリの
  command がどれも dst の同じ EventName に無い時だけ matcher ごと末尾に追加する。dst に `hooks` や
  該当 EventName が無ければ作る
- `permissions.deny`：文字列の集合として差分だけを src の並び順で末尾に追加。既存の順序・重複は
  触らない。`permissions.allow` は読み取りもせず dst のものをそのまま残す（src の allow は無視）
- 冪等判定は「足すものが無ければ `skip`」にした。`new == old` の比較を条件に入れると、インストール
  先の整形が違うだけで書き換えてしまい、利用者のファイルを無用に触ることになるため
- 受け入れ基準の確認コマンドを一時ディレクトリで実行し、6件すべて通した
  - dst 無し → `create ...` / 直後に再実行 → `skip ...`
  - allow に独自要素を足し、deny から `Bash(sudo *)` を削り、`hooks.PostToolUse` を消した
    settings.json に対して実行 → `merge ...`
  - allow の独自要素が残る=True（件数 52＝元51＋独自1。src の allow で上書きされていない）
  - PostToolUse に `todo_guard.py` が復元=True / deny に `Bash(sudo *)` が復元=True（件数 14）
  - バックアップ `settings.json.bak-20260919211502` が1つできる
  - `bash scripts/smoke.sh | tail -1` → `smoke: pass=84 fail=0`
- `scripts/smoke.sh` に `== merge_settings_json.py ==` 節を追加（7ケース、(m)(n)）。既存ケースは変更なし
- 決定済みのとおり `scripts/install.sh` には組み込んでいない。マニフェストの対象パス列にも
  まだ入れていない（どちらも T-0039 の範囲）
