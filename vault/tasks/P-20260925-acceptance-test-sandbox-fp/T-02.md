# T-02 grep 誤検知（issue #42 時の事象）の原因が hook かサンドボックスかを切り分ける（issue #46）

## 目的
`P-20260925-vcs-finish-push-and-diff-criteria`/T-02 の creator が `grep -c "git diff main" T-02-proposal.md` 相当のコマンドを実行しようとして拒否された事象について、原因が `.claude/hooks/agent_write_guard.py`（PreToolUse フック）かそれ以外（Claude Code のツール実行時サンドボックス等、`.claude/` 側で直接直せない可能性がある経路）かを切り分け、結論を記録する。対応方針の決定・実装はこのタスクでは行わない。

## 入力
- `.claude/hooks/agent_write_guard.py`（特に `BASH_WRITE_PATTERNS`・`targets_vault_rules`・`targets_creator_denied_paths`。これらはいずれも `grep -c "git diff main" ...` のようなコマンド文字列にマッチしない）
- `.claude/settings.json` の `permissions.allow` に `Bash(grep *)` が無条件許可であること（32行目）
- `vault/plans/P-20260925-vcs-finish-push-and-diff-criteria.md`（issue #42 の事象の記述）
- planner が事前に実行した確認（下記の受け入れ基準1のコマンドと同じもの）：出力が空（＝`agent_write_guard.py` は deny しない）だった

## 成果物
- `vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-02-findings.md`

## 受け入れ基準
- 次のコマンドを実行し、出力（deny の JSON が出たか、何も出なかったか）を `T-02-findings.md` に記録している。確認コマンド：`echo '{"tool_name":"Bash","tool_input":{"command":"grep -c \"git diff main\" /tmp/dummy.md"},"agent_type":"creator","cwd":"'$(pwd)'"}' | python3 .claude/hooks/agent_write_guard.py` を実行すると出力が空になる
- `T-02-findings.md` に `## 結論` の見出しがあり、原因が `agent_write_guard.py` かどうか（yes/no）を明記している。確認コマンド：`grep -c '^## 結論' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-02-findings.md` の出力が `1`
- `T-02-findings.md` に `## 次の一手（未決定）` の見出しがあり、対応候補を2つ以上、優先順位を付けずに列挙している。確認コマンド：`grep -c '^## 次の一手（未決定）' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-02-findings.md` の出力が `1`
- 成果物は `T-02-findings.md` のみで、他ファイルは変更していない。確認コマンド：`git status --porcelain | grep -v 'T-02-findings.md'` の出力が空

## 決定済み
- ゴールは原因切り分けの結論を出すことまで。修正の実装や `.claude/settings.json`・`.claude/hooks/agent_write_guard.py`・`vault/rules/` への変更はこのタスクの範囲外（触らない）
- planner が事前に確認済みのとおり、`agent_write_guard.py` を単体で模擬実行すると deny されない（受け入れ基準1のコマンドの出力が空）。creator は同じコマンドを自分でも実行し、結果を `T-02-findings.md` に転記すること
- 加えて、creator 自身の Bash ツール呼び出しで実際に `grep -c "git diff main" <一時ファイル>` を実行し、拒否されるかどうかも記録する。拒否されない場合は「今回の環境では再現しなかった」と書いてよい。再現しないこと自体も有効な調査結果として扱う
- 結論が「`agent_write_guard.py` が原因ではない（＝プラットフォームのサンドボックス由来の可能性が高い）」となった場合でも、根本原因のさらなる特定や `.claude/` 側での対処はこのタスクでは行わない。`## 次の一手（未決定）` には、例えば「人に事例を再現してもらい発生条件を特定する」「該当語を避けるよう planner 側の指針を追加する（別タスクとして起票）」等の候補を、決定せず列挙するに留める
- `T-02-findings.md` に「次の一手」を決定的に1つだけ書く（対応を確定する）のは禁止。必ず複数候補を未決定のまま列挙すること
