# T-01 scripts/amend_task.py を作る（成果物の追加・受け入れ基準の差し替えと log の記録）

## 目的
`/plan unblock` の回答が成果物の追加や受け入れ基準の差し替えを含む時に、オーケストレーターが手でタスク票を直さずに済むよう、タスク票の「成果物」への宣言の追加と「受け入れ基準」の行の差し替えを行い、log に1行残してコミットするスクリプトを作る（Issue #189）。

## 入力
- `scripts/transition.py`（計画票・ブランチの検査、`commit_files`・`now_jst` などの共通部品。import して使ってよい）
- `scripts/diff_gate.py`（「成果物」節の宣言の読み方・禁止ディレクトリ）
- `.claude/hooks/_hooklib.py`（`parse_tasks`・`frontmatter_status`・`count_criteria` の数え方）
- `docs/vault-spec.md` 5節（タスク票・成果物の記法・差分ゲート）、7節（log）
- `scripts/smoke.sh` の `tw_setup`（一時リポジトリの作り方。テストで流用する）

## 成果物
- `scripts/amend_task.py`（新規。主な成果物）
- `scripts/smoke.sh`（テストの追加）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (amend-task) 0[1-6] '` の出力が `6`（決定済みのテスト 01〜06 がすべて通る）
- `python3 scripts/amend_task.py --help` の終了コードが0で、出力に `--add-deliverable` と `--replace-criterion` の両方が現れる
- `python3 scripts/amend_task.py P-X T-01` （変更の指定が1つも無い）の終了コードが2
- `git diff --merge-base work/p-20261012-unblock-resume-and-install-fixes --name-only -- scripts/amend_task.py` の出力が `scripts/amend_task.py`

## 決定済み
- 呼び出しの形：`python3 scripts/amend_task.py <計画ID> <id> [--add-deliverable <パス>]... [--replace-criterion <番号> <文>]... [--note <補足>]`。`--add-deliverable` と `--replace-criterion` はそれぞれ複数回指定でき、指定した順に適用する。どちらも1つも無ければ argparse のエラー（終了コード2）。この引数の検査はリポジトリの検査より前に行う（リポジトリの外でも終了コード2になる）
- 対象のリポジトリは実行時のカレントディレクトリの `git rev-parse --show-toplevel`（transition.py と同じ）
- 拒否して何も変えない条件（終了コード1、理由は標準エラーに `[amend_task] ` で始めて出す）：計画票が無い・status が approved でない／現在のブランチが `work/<計画IDの英小文字>` でない／id がタスク表に無い／その行の status が `blocked`・`todo` 以外（done・doing・review は拒否。done の票はフックも書き込みを拒否する）／タスク票 `vault/tasks/<計画ID>/<id>.md` が無い・「## 成果物」「## 受け入れ基準」の見出しが無い／`--replace-criterion` の番号が1〜（その票の受け入れ基準の行数）の範囲外／`--add-deliverable` のパスが `vault/plans/`・`vault/log/`・`vault/verdicts/` で始まる（差分ゲートが宣言があっても違反にするため）。複数の指定のうち1つでも拒否に当たれば何も変えない
- `--add-deliverable <パス>`：「## 成果物」節の最後の空でない行の直後に `` - `<パス>`（amend_task.py で追加） `` の1行を足す（バッククォートで囲む。全角括弧の文言はこのとおり）。その節にすでに同じパスがバッククォートで宣言されていれば足さず、標準出力に `skip <パス>（宣言済み）` を出す（拒否はしない）
- `--replace-criterion <番号> <文>`：「## 受け入れ基準」節の中で、`_hooklib.count_criteria` と同じ数え方（行頭が `- ` か `数字. `）で数えて `<番号>` 番目の行を `- <文>` の1行に置き換える。行数は変わらない。基準の追加・削除の引数は作らない
- log：`vault/log/<計画ID>.md` に1行だけ追記する。形は `- <日時> <id> amend <要約>` で、日時は transition.py と同じ JST の実時刻（`YYYY-MM-DD HH:MM`）。要約は適用した変更を指定の順に空白区切りで並べたもので、成果物の追加は `成果物追加=<パス>`、差し替えは `基準差し替え=<番号>`。`--note` があれば最後に空白を挟んで付ける。行に `→` を含めない（状態遷移の行ではないため。`model_stats.py` などの集計は `→` を含む行だけを見る）。宣言済みで足さなかったパスも要約に含めない
- コミット：タスク票と log だけを1回で `git commit -m "<計画ID>/<id>: amend" -- <タスク票> <log>` する（ほかの staged な変更を混ぜない）。失敗したら書いたファイルを元に戻して終了コード1（transition.py の `commit_files` と同じ動き。import して使ってよい）
- 成功時は終了コード0。標準出力に適用した変更を1件1行で出す（形は自由。`skip` の行を含む）
- 計画票（`vault/plans/<計画ID>.md`）は読むだけで書き換えない。status・attempt は変えない（解除は `/plan unblock` の手順が行う）
- 新しい環境変数（`HARNESS_*`）は作らない（smoke の `(envref-1)` が `docs/configuration.md` の表との一致を検査しているため）
- smoke のテストは、`scripts/smoke.sh` の `# --- 主な文書の参照切れの検査 ---` の行の直前に、`# amend_task.py` の見出しコメントから始まる1つのブロックとして足す（ほかのタスクが別の場所にテストを足すので、この位置から動かさない）。フィクスチャは既存の `tw_setup`（一時リポジトリ・計画票・タスク票の作成）を流用してよい。テスト名は `(amend-task) 01 …`〜`(amend-task) 06 …` とし、番号ごとに `expect_eq` を1つだけ書く（1つの expect_eq で複数の値を空白区切りで比べてよい）：
  - 01：blocked の行に `--add-deliverable src/new.txt` → 終了コード0で、「## 成果物」節に `` - `src/new.txt`（amend_task.py で追加） `` の行が1行ある
  - 02：01 の後、計画ブランチの HEAD から作ったブランチで `src/new.txt` を作ってコミットし、`python3 scripts/diff_gate.py P-TEST T-01 <その HEAD> <そのブランチ>` の終了コードが0（宣言の追加が差分ゲートに効く）
  - 03：`--replace-criterion 1 新しい基準` → 受け入れ基準節の1行目が `- 新しい基準` になり、受け入れ基準の行数が変わらない
  - 04：01・03 の log の最後の行が `- <日時> T-01 amend 成果物追加=src/new.txt` などの決定済みの形で、`→` を含まない
  - 05：拒否（status が done・doing・review のいずれかの行、範囲外の番号、`vault/plans/` で始まるパス）で終了コード1になり、タスク票・log・コミット数が変わらない
  - 06：成功時のコミットが1つ増え、そのコミットのファイルがタスク票と log の2つだけで、件名が `P-TEST/T-01: amend`
