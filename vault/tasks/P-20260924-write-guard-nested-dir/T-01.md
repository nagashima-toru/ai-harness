# T-01 agent_write_guard: 未作成の祖先ディレクトリでも worktree root を解決する

## 目的
`.claude/hooks/agent_write_guard.py` の `resolve_root()` が、worktree 内でまだ存在しないディレクトリ配下への書き込みを判定する際、対象パスの存在する祖先まで遡ってから `git_toplevel()` を呼ぶようにし、誤ってメインチェックアウトへフォールバックして正当な書き込みを拒否する不具合（GitHub Issue #24）を直す。

## 入力
- `.claude/hooks/agent_write_guard.py`（`resolve_root()`・`git_toplevel()` 関数。修正対象）
- `scripts/smoke.sh`（197〜206行目に既存の worktree 回帰テストがある。ただしそのケースは `mkdir -p "$WLEAF/vault/verdicts"` で対象ディレクトリを事前作成しており、今回のバグ（祖先ディレクトリ未作成）は再現しない）
- GitHub Issue #24（再現条件・原因・直したいことの記述。本タスク票の「決定済み」に転記済み）

## 成果物
- `.claude/hooks/agent_write_guard.py` の修正（1ファイル）。あわせて `scripts/smoke.sh` に回帰テストケースを1つ追加する

## 受け入れ基準
- `resolve_root()`（または `git_toplevel()`）に、`probe_dir` が存在しない場合に存在する祖先ディレクトリまで `os.path.dirname()` で遡ってから `git -C` を呼ぶ処理が入っている。確認コマンド：`grep -n "isdir" .claude/hooks/agent_write_guard.py` に `probe_dir` 探索に関わる行が出力される
- worktree 内でまだ存在しないネストしたディレクトリ（例：`vault/verdicts/<新規計画ID>/`）配下への Write が、メインチェックアウトへのフォールバックによって誤って拒否されないことを確認する回帰テストが `scripts/smoke.sh` に追加されている。既存の197〜206行目のケースとは異なり、対象ディレクトリを事前に `mkdir -p` しないこと。確認コマンド：`grep -n "nested" scripts/smoke.sh`（追加したテスト名に `nested` を含める）
- `bash scripts/smoke.sh` を実行すると全件 pass する（追加したテストを含む）。確認コマンド：`bash scripts/smoke.sh | tail -1` の出力が `smoke: pass=<N> fail=0`
- 修正後も `resolve_root()` の最終フォールバック順序（`CLAUDE_PROJECT_DIR` → `payload.cwd` → `os.getcwd()`）は変更されていない。確認コマンド：`git diff -- .claude/hooks/agent_write_guard.py | grep -E '^[+-]\s*fallback = '` の出力が空（フォールバック行自体は変更しない）

## 決定済み
- 再現条件（Issue #24 本文の要約）：worktree 内で、まだ存在しないディレクトリ配下に新規ファイルを Write しようとすると、`git -C <存在しないpath> rev-parse --show-toplevel` が exit 128 で失敗し `git_toplevel()` が `None` を返す。結果 `resolve_root()` は `CLAUDE_PROJECT_DIR`（メインチェックアウト）にフォールバックし、worktree 側の絶対パスをそこからの相対パスに変換しようとして `../../` を含む無関係な相対パスになり、`vault/verdicts/` 配下ではないと誤判定されて拒否される。
- 修正方針（Issue #24 本文で提案されている方式をそのまま採用してよい）：`probe_dir` が存在しない場合、`os.path.dirname(probe_dir)` を存在するディレクトリが見つかるまで繰り返し遡ってから `git_toplevel()` に渡す。worktree のルート自体は常に存在するため、これで正しく解決できる。ルートまで遡っても見つからない（ほぼ起こらない）場合は、既存どおり `git_toplevel()` が `None` を返しフォールバックする現行の fail-open 挙動のままでよい
- 影響範囲は Write/Edit/MultiEdit/NotebookEdit 経由の `probe_dir` 起点の解決のみ。Bash 経由（`payload.cwd` 起点）は cwd が常に存在するディレクトリのはずなので変更不要（必要と判断した場合のみ触ってよいが、受け入れ基準はこのケースを要求しない）
- 回帰テストは `scripts/smoke.sh` の `git -C "$WMAIN" worktree add` を使った既存パターン（201〜204行目付近）を流用し、別の一時 worktree を作って `mkdir -p` を呼ばずに、存在しないネストしたパス（例 `vault/verdicts/P-NEW/T-1.json`）へ `agent_type: verifier` で Write を試みて `allow` になることを確認する。テスト名に `nested` を含めること
- 既存の197〜206行目のケース（事前に `mkdir -p` している方）は削除・変更しない。新規ケースとして追加する
- 修正はこの1ファイル（`.claude/hooks/agent_write_guard.py`）と回帰テスト追加（`scripts/smoke.sh`）の範囲に閉じる。`docs/vault-spec.md` 等の仕様書更新は本タスクのスコープ外（挙動の修正であり仕様変更ではないため）
