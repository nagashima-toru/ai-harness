## 決定済み
- 提案ファイルは全文で書く（差分ではない）。前置きや frontmatter は付けず、人がそのまま実体へコピーできる形にする。見出しは `## 目的`・`## ルール`・`## 確認方法` の3つだけにし、`###` などの小見出しも付けない（基準1の `grep -c '^#'` が3になるように）
- 基準の grep と一致させるため、次の語を本文にそのまま書く。「コミットは受け入れ基準に含まれている場合だけ行う」（SKILL.md 72行目の引用と一字一句同じ）、「自己判断で解決しない」（SKILL.md 76行目と同じ）、`git merge --no-ff`、`scripts/vcs_finish.sh`、「マージは人が行う」、「直接コミットしない」、`discard_worktree.sh`
- ルールに書く内容（原則と主語。この順で書かなくてもよい）：
  - ブランチ：`/plan` が計画ごとに1つだけ切る（`work/<計画IDの英小文字>`）。1ブランチ＝1計画。creator はブランチを切らない（run が worktree を用意する）
  - `main` へは直接コミットしない（`agent_write_guard.py` がフックで強制する、は残してよい）
  - コミット：creator のコミットは受け入れ基準に含まれている場合だけ行う。worktree に残った未コミット分は、PASS の後にオーケストレーター（run のメインセッション）がまとめてコミットし、計画ブランチへ `git merge --no-ff` で取り込む。計画票・log・verdict の状態遷移を書き、コミットするのもオーケストレーター
  - PR：全タスクが `done` になった後、オーケストレーターが `bash scripts/vcs_finish.sh` で作る。マージは人が行う。エージェントは `gh pr merge` を実行しない
  - 破棄：作業ツリーの変更の破棄は `git restore` だけを使い、`git clean` / `git reset --hard` は使わない（`permissions.deny` で拒否済み、は残してよい）。不採用になった worktree の破棄は、オーケストレーターが `scripts/discard_worktree.sh` で行う
  - コンフリクト：計画ブランチへのマージで起きたコンフリクトは自己判断で解決しない。マージを行うオーケストレーターがタスクを `blocked` にし、question に状況を書いて人の判断を仰ぐ。creator は判断が要る時、自分で解決せずオーケストレーターに返す（返し方の形式は書かず、git-workflow.md に任せる）
- 書かないもの（重複を避ける）：起点コミット、`blocked: <質問文>` の形式、`git -C`・`git add -A`・`git merge --abort`・`git worktree remove` などのコマンド列、ハング時の扱い。必要なら「手順の詳細は `vault/rules/creator/git-workflow.md` と `.claude/skills/run/SKILL.md` に従う」と1文で参照する
- 「目的」は1〜2行。「1セッション1計画1ブランチの前提で、ブランチ・コミット・PR・破棄の原則と、それぞれを誰が行うか（creator / オーケストレーター / 人）を定める」という趣旨にする
- 「確認方法」から「コミットが作業ステップ単位に分かれているか」を外す。代わりに観点を書く（例：creator のコミットが受け入れ基準にある分だけか、PR が vcs_finish.sh でだけ作られているか、`main` に直接コミットしていないか）。`bash scripts/rules.sh creator`（および `verifier`・`planner`）の出力に git.md が含まれるか、の行は残してよい
- `.claude/skills/run/SKILL.md` と `vault/rules/creator/git-workflow.md` は変更しない（人への質問の案A。案B が選ばれた時は別タスクで扱う）
- 実体 `vault/rules/common/git.md` は変更しない。フックで拒否され、反映は人が行う
- smoke.sh はこのタスクの基準に含めない（T-02 で流す）
- このタスクではコミットしない（受け入れ基準にコミットが無いため。未コミット分はオーケストレーターが収集する）
