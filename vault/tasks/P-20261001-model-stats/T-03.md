# T-03 run SKILL.md の手順4・6に creator=/verifier= の記録を足す

## 目的
run のオーケストレーターが、log の遷移行の補足にその工程のモデル（`creator=` / `verifier=`）を書くようにする。

## 入力
- `.claude/skills/run/SKILL.md`（手順3.8・4・6、ハング時の復旧）
- `docs/vault-spec.md` 7節（T-01 で確定した書式）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md`（frontmatter の `model`）

## 成果物
- `.claude/skills/run/SKILL.md`（1ファイルの改訂）

## 受け入れ基準
- 手順4の `doing→review` の log 追記（および手順3.8の `doing→blocked`）の補足に `creator=<モデル>` を付ける旨がある（`grep -n 'creator=' .claude/skills/run/SKILL.md` がヒットする）
- 手順6の `review→done`・`review→doing`・`review→blocked` の log 追記の補足に `verifier=<モデル>` を付ける旨がある（`grep -n 'verifier=' .claude/skills/run/SKILL.md` がヒットする）
- モデルの値は `.claude/agents/creator.md`・`.claude/agents/verifier.md` の frontmatter の `model` から読む旨が書かれている（`grep -n 'frontmatter' .claude/skills/run/SKILL.md` に該当行がある）
- 追記の書式を `docs/vault-spec.md` 7節への参照として示し、書式をこの文書で二重に定義していない（`grep -n 'vault-spec' .claude/skills/run/SKILL.md` に該当行がある）
- `.claude/skills/run/SKILL.md` 以外のファイルが変わっていない（`git status --porcelain` の出力が `.claude/skills/run/SKILL.md` と、計画票・タスク票・log・verdict 以外を含まない）

## 決定済み
- モデルの値は `.claude/agents/<name>.md` の frontmatter の `model`（現在はどちらも `sonnet`）。実行時にその値を読んで書く。固定値を SKILL.md に埋め込まない
- 付ける行：`doing→review`・`doing→blocked` には `creator=<モデル>`、`review→done`・`review→doing`・`review→blocked` には `verifier=<モデル>`。ほかの行（`todo→doing`、再開時の `doing→doing`、ハング・マージ衝突由来の行など）には付けない。理由要約など他の補足がある行は、`creator=`/`verifier=` を先頭に置き、空白区切りで後ろに続ける
- 手順6 内でマージ衝突などにより `review→blocked` にする行にも `verifier=` を付ける（verifier が判定を出した後の遷移のため）
- log の再開情報の記録行（`worktree path=...`）は変えない
- 記録先は log（verdict ではない）。verdict.json の形式・stop_gate.py は変えない
- smoke.sh への追加は T-04 で行う。このタスクでは smoke.sh に触らない

- 確認: grep の creator=/verifier=/frontmatter/vault-spec 各ヒット、git status は SKILL.md とタスク票のみ
