# T-0041 `docs/vault-spec.md` の1・3・4節（ディレクトリ／ID・ブランチ名／計画票の形式）を書き直す

## 目的
`docs/vault-spec.md` の「1. ディレクトリ」「3. ID・ファイル名」「4. todo.md の形式」の3節を、計画
をまたぐキューを持たない新しい構造（ディレクトリ構成・ID/ブランチ命名・計画票の状態表現）に書き直
す。以降の全タスクが依存する契約（ID 体系・タスク表の列定義）をここで固定する。

## 入力
- `docs/vault-spec.md`（現行）
- `vault/designs/D-001.md`（「## 決定事項」「### 新しいディレクトリ構造」「## フェーズ2」）
- `vault/plans/P-020.md`（この計画の「分割方針」に新しい章立て全体像がある）

## 成果物
- `docs/vault-spec.md` のうち、冒頭の未適用注記と、現行の「## 1. ディレクトリ」「## 3. ID・ファイル
  名」「## 4. todo.md の形式」に相当する範囲の書き直し（他の節には触れない）

## 受け入れ基準
- ディレクトリの節（新「## 1. ディレクトリ」）の表に `vault/log/<計画ID>.md` の行がある。確認：
  `grep -F 'vault/log/<計画ID>.md' docs/vault-spec.md` の出力が1行以上
- ID の節（新「## 3. ID・ファイル名・ブランチ名」）に `P-YYYYMMDD-<slug>` と `work/p-` を含むブラ
  ンチ名の例がある。確認：`grep -c 'P-YYYYMMDD' docs/vault-spec.md` と `grep -c 'work/p-'
  docs/vault-spec.md` がそれぞれ1以上
- 旧「## 4. todo.md の形式」節が消え、その内容（タスク表の列定義）が計画票の節（新「## 4. 計画票の
  形式」）に統合されている。確認：`grep -F '| id | status | attempt | after | title | question |'
  docs/vault-spec.md` の出力が1行以上
- 計画票の節に frontmatter の `status`（`draft` / `approved` / `done`）の3値の意味（`done` は全タ
  スクが done で PR 作成済み。main へのマージは含まない）が書かれている。確認：`grep -F
  'PR 作成済み' docs/vault-spec.md` の出力が1行以上
- ディレクトリまたは ID の節に「1セッション = 1計画 = 1ブランチ」の原則が明記されている。確認：
  `grep -F '1セッション' docs/vault-spec.md` の出力が1行以上
- 文書の冒頭（最初の `## ` 見出しより前）に、この仕様がまだ未適用である旨の注記がある。確認：
  `grep -F 'この仕様はフェーズ3〜4の実装が完了するまで未適用' docs/vault-spec.md` の出力が1行以上

## 決定済み
- 文書の冒頭（タイトル行の直後、最初の `## ` 見出しより前）に次の引用ブロックを置く。これは旧方式
  の仕様を併記するものではなく、「この文書がまだ実装に追いついていない」という状態の注記である。
  フック・スキルがまだ `vault/todo.md` で動いている間、作成エージェントがこの文書と run-queue
  スキルの矛盾した指示を同時に読むのを防ぐために置く。削除は D-001 フェーズ4で行う

  ```
  > この仕様はフェーズ3〜4の実装が完了するまで未適用。
  > 実際の運用は現時点では `.claude/skills/run-queue/SKILL.md` に従う。
  > （D-001 フェーズ4の完了時にこの注記を削除する）
  ```
- 新しい章立て（全13節）は `vault/plans/P-020.md` の「分割方針」を正本とする。このタスクは1・3・4
  節を担当し、他の節（2, 5〜13）の中身には触れない（見出しの直後・直前の連結だけ壊さないようにす
  る）
- 旧「4. todo.md の形式」節と旧「6. 計画票」節（`vault/templates/plan.md` の frontmatter 説明のみ
  だった）を統合し、新しい「4. 計画票の形式」節を作る。統合後の内容は次を満たす：
  - frontmatter は `id` と `status`（`draft`/`approved`/`done` の3値。`draft`=planner が作った直
    後、`approved`=人が承認、`done`=全タスクが done で `gh pr create` 済み。main へのマージは含ま
    ない。マージは人が行う）
  - 本文にタスク表（状態の正本）を持つ。列は `id | status | attempt | after | title | question`
    （この順序・列名は変えない。旧 `vault/todo.md` の「## タスク」表の列をそのまま踏襲する）
  - `after`・`question` の意味は旧 `vault/todo.md` の説明を踏襲する（`after` は依存タスク ID、複数
    はカンマ区切り、無ければ `-`。`question` は `blocked` の時に人へ聞くこと。必須）
- ID の節は次の4種を表で示す：計画 ID（`P-YYYYMMDD-<slug>`、例 `P-20260919-git-ops`）、タスク ID
  （計画スコープの `T-` + 2桁、例 `T-01`）、ブランチ名（計画 ID を英小文字化し `work/` を付ける、例
  `work/p-20260919-git-ops`）、設計文書 ID（`D-` + 3桁、計画・タスクとは独立採番、無変更）
  - スラッグは英小文字・ハイフン区切り。厳密な自動生成アルゴリズムは規定しない
  - 「自分のブランチの計画票」は `vault/plans/*.md` を走査し frontmatter の `status` が `approved`
    のものを取る。2つ以上 approved があるのは異常（1ブランチ1計画の不変条件）、という一文を
    ID かディレクトリの節のどちらかに含める
- 証跡は3層（`vault/log/<計画ID>.md` の状態遷移ログ／`vault/verdicts/<計画ID>/T-xx.json` の判定根
  拠／git のステップごとコミットと PR）であることをディレクトリの節に一文で触れる
- ディレクトリ表の `vault/archive/` の説明は「done になった計画一式を月次でまとめる先」程度に留め、
  新しいアーカイブ内部構造（計画ごとのサブディレクトリ等）は今回設計しない（D-001 フェーズ4の範囲）
- 旧「3. ID・ファイル名」にあった「タスク：`T-`+4桁ゼロ埋め」「計画：`P-`+3桁」「採番は既存の最大
  値+1」等の記述は、新しい ID 体系（日付+slug、計画スコープ2桁、採番不要）に合わせて置き換える。
  「欠番は許容、再利用は禁止」のような採番前提の記述は計画・タスク ID には残さない（設計文書 ID
  `D-xxx` は引き続き既存の最大値+1で採番するので、その部分だけは残す）
- 見出し番号は目安。このタスク終了時点で1・3・4節の番号・タイトルが最終形（「1. ディレクトリ」「3.
  ID・ファイル名・ブランチ名」「4. 計画票の形式」）になっていればよく、5節以降の番号がまだ旧番号の
  ままでも構わない（後続タスクが順に直す）

## 進捗
- 読んだルール: roles.md, creator.md
- 冒頭（タイトル行の直後、前文より前）に未適用注記の引用ブロックを決定済みの実文どおり置いた
- 新「## 1. ディレクトリ」：表を計画スコープの5パス＋`vault/rules/`＋`vault/archive/` に差し替え、
  `vault/todo.md` の行を削除。表の後に3段落を足した
  （1セッション=1計画=1ブランチ／`approved` の計画票を走査して自分の計画を特定し2つ以上は異常／
  証跡は3層でブランチ内に閉じる）
- 新「## 3. ID・ファイル名・ブランチ名」：4種を表にした（計画 `P-YYYYMMDD-<slug>`、タスク `T-01`、
  ブランチ `work/p-...`、設計文書 `D-001`）。旧の4桁/3桁ゼロ埋めと「既存の最大値+1」の採番記述を
  外し、採番が不要な理由（並行セッションで衝突しない）を明記。設計文書 ID の採番だけは残した
- 新「## 4. 計画票の形式」：旧「4. todo.md の形式」と旧「6. 計画票」を統合。frontmatter の
  `status` 3値を表にし、`done` が PR 作成済みでマージを含まないこと・マージは人が行うことを明記。
  タスク表の6列と `after`/`question` の意味は旧 todo.md の説明を踏襲し、`after` が同じ計画内の
  タスクしか指せないことを1行足した
- 旧「## 6. 計画票（`vault/templates/plan.md`）」節を削除した（新4節へ統合済みのため）
- 例のコードフェンス内に `## タスク一覧` と書いたところ、`grep -n '^## '` が見出しとして拾ったので、
  フェンスからその行を外して散文側で説明する形に直した
- 受け入れ基準の確認コマンドを実行し、6件すべて通した
  - `vault/log/<計画ID>.md`=2件 / `P-YYYYMMDD`=1 / `work/p-`=1 / 6列のヘッダ行=1
  - `PR 作成済み`=1 / `1セッション`=1 / 未適用注記=1
- 現時点の見出しは 1〜5, 7〜14（旧6節を抜いた分の欠番）。決定済みのとおり5節以降の番号は
  後続タスク（T-0042〜T-0044）が詰める。`vault/todo.md` への言及は3箇所残っており、
  これも後続タスクの担当節（8・11・13節）にある
