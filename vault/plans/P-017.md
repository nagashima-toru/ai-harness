# ゴール
既存の CLAUDE.md を壊さずにハーネスのルールを入れられるようにする。ハーネス共通ルールの本文を
`.claude/ai-harness.md` に外出しし、ルートの `CLAUDE.md` はマーカー付きスタブ
（`<!-- ai-harness:begin v1 -->` 〜 `<!-- ai-harness:end -->` で囲んだ見出し1行 +
`@.claude/ai-harness.md` の4行）にする。`scripts/merge_claude_md.py` を新規作成してマージを
冪等に行い、`scripts/install.sh` から呼び出す（`--no-claude-md` で従来の note 案内に戻せる）。
`scripts/smoke.sh`・`docs/install.md`・`README.md`・`docs/decisions.md` を実挙動に合わせて更新する。

## 分割方針
- T-0027 で「スタブ化されたルート CLAUDE.md」と「本文を持つ .claude/ai-harness.md」という契約
  （正確なファイル形式）を先に固定する。以降の2タスクはこの形式に依存する。
- T-0028 でマージの中核ロジック（merge_claude_md.py）と、その4パターン
  （create/merge/update/skip）の検証を smoke.sh に追加する。install.sh には触れない。
- T-0029 で install.sh に組み込み、`--no-claude-md` フラグを追加し、docs/install.md・
  README.md・docs/decisions.md を実挙動に合わせて更新する。smoke.sh には `--no-claude-md` の
  ケースを追加する。
- 3タスクは一本鎖（T-0027 → T-0028 → T-0029）。依存に循環はない。
- `.claude/settings.json` の hooks/permissions マージは別計画で扱う（今回は含めない）。

## 計画の受け入れ基準
- 各タスクに成果物と受け入れ基準が1つずつある
- 依存に循環がない（T-0027 → T-0028 → T-0029 の一本鎖）

- `bash scripts/install.sh <dir>` を既存 CLAUDE.md のあるリポジトリに対して実行すると、既存本文を
