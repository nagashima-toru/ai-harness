# ゴール
`run` スキル手順6.3.2（FAIL 再試行時）が指示する `git branch -D <ブランチ名>` が、`.claude/settings.json` の deny ルール `Bash(git branch -D *)` に拒否され、無人実行（`claude -p` 等）では再試行が完了できない（issue #34）。deny ルールはそのまま残し、creator 用 worktree とその作業ブランチの破棄だけを、対象を検証する専用スクリプト `scripts/discard_worktree.sh` に切り出して衝突を解消する。

## 決定事項

| 決めたこと | なぜ |
|---|---|
| 専用スクリプト `scripts/discard_worktree.sh <worktree のパス> <ブランチ名>` を新設し、手順6.3.2 はこれを呼ぶ。`settings.json` の `Bash(git branch -D *)` deny は変更しない | 人の判断（推奨案採用）。Claude Code の権限は deny が allow より優先されるため「`worktree-agent-*` だけ許可」は settings.json では表現できない。保護ブランチ名を列挙する方式は列挙漏れで保護が弱くなる。スクリプトは既存 allow の `Bash(bash scripts/*)` で実行できる |

## フェーズ1 FAIL 再試行時の worktree 破棄を専用スクリプトに切り出す

### ゴール文
`run` スキル手順6.3.2（verifier が FAIL で attempt が上限未満の時）が直接実行している `git worktree remove <worktree のパス> --force` と `git branch -D <ブランチ名>` を、新しいスクリプト `scripts/discard_worktree.sh <worktree のパス> <ブランチ名>` の呼び出しに置き換える。`.claude/settings.json` の deny ルール `Bash(git branch -D *)` は変更しない（スクリプトは既存 allow の `Bash(bash scripts/*)` で実行される）。スクリプトは、(1) 引数が2つであること、(2) ブランチ名が `worktree-agent-` で始まること、(3) `git worktree list --porcelain` 上で指定パスが登録済み worktree であり、その `branch` が `refs/heads/<ブランチ名>` と一致すること、をすべて確認してから `git worktree remove --force <パス>` と `git branch -D <ブランチ名>` を実行し終了コード0で終わる。いずれかの確認に失敗した場合は何も削除せず、理由を標準エラーに出して非0で終わる。`scripts/smoke.sh` に、一時 git リポジトリ上でこのスクリプトの正常削除と拒否ケースを確かめるケースを追加する。`scripts/install.sh` の配布対象とマニフェストにもこのスクリプトを加える（`scripts/uninstall.sh` はマニフェストに載ったファイルを除去するので変更不要）。PASS 時（手順6.3.1-4）の片付け手順は変更しない。

### 受け入れ基準の候補
- `scripts/discard_worktree.sh` が存在し、`worktree-agent-` で始まるブランチの登録済み worktree を指定すると、worktree とブランチの両方が削除され終了コード0で終わる。確認：`bash scripts/smoke.sh` の該当ケースが pass（一時リポジトリで `git worktree add -b worktree-agent-test <path>` → スクリプト実行 → `git worktree list` にパスが無く `git rev-parse --verify worktree-agent-test` が失敗する）
- ブランチ名が `worktree-agent-` で始まらない場合（例：`main`）、およびパスが未登録またはパスの worktree のブランチが指定ブランチと一致しない場合、スクリプトは何も削除せず非0で終わる。確認：`bash scripts/smoke.sh` の拒否ケース（3種）が pass し、実行後もブランチ・worktree が残っている
- `.claude/skills/run/SKILL.md` の手順6.3.2 から `git branch -D` と `git worktree remove <worktree のパス> --force` の直接記述が消え、`bash scripts/discard_worktree.sh <worktree のパス> <ブランチ名>` に置き換わっている。確認：`grep -n "git branch -D" .claude/skills/run/SKILL.md` がヒットせず、`grep -n "discard_worktree.sh" .claude/skills/run/SKILL.md` がヒットする
- `.claude/settings.json` の `permissions.deny` に `Bash(git branch -D *)` が残っている。確認：`jq -r '.permissions.deny[]' .claude/settings.json | grep -Fx 'Bash(git branch -D *)'` がヒットする
- `scripts/install.sh` で新規導入した先に `scripts/discard_worktree.sh` が配置され、`.claude/harness-manifest.json` の `files` に載る。確認：`bash scripts/smoke.sh` の install ケースに配置とマニフェスト掲載の確認が含まれ pass する
- `bash scripts/smoke.sh | tail -1` が `fail=0` で終わる

### 決定済み
- スクリプトのパスは `scripts/discard_worktree.sh`、引数は位置引数2つ（`<worktree のパス> <ブランチ名>`）。オプションは設けない
- ブランチ名の接頭辞 `worktree-agent-` は、スクリプト内の定数として持つ（環境変数での上書きは設けない）
- worktree の照合は `git worktree list --porcelain` の `worktree <絶対パス>` 行と直後の `branch refs/heads/<名前>` 行で行う。渡されたパスは絶対パスに正規化してから比較する（相対パスで渡されても動くようにする）
- 削除の順序は `git worktree remove --force <パス>` → `git branch -D <ブランチ名>`。前者が失敗したら後者を実行せず非0で終わる
- スクリプトは作業ディレクトリの git リポジトリ（計画ブランチ側のメインの作業ツリー）で実行される前提。`git -C` の指定は不要
- deny ルールの文字列照合では `bash scripts/discard_worktree.sh ...` は `Bash(git branch -D *)` に一致しないため、スクリプト内部の `git branch -D` は拒否されない（permissions はエージェントの Bash ツール呼び出しのコマンド文字列にだけ適用される）
- `.claude/hooks/agent_write_guard.py` は変更しない。スクリプトを呼ぶのは run のメインセッション（オーケストレーター）で、agent_type 制限の対象外
- 手順6.3.3（上限到達で blocked）とコンフリクト時・新規コミット無し時の「worktree を残す」方針は変更しない
- `docs/vault-spec.md` と `docs/runbook.md` に `git branch -D` を前提にした FAIL 時の破棄手順の記述があれば、同じくスクリプト経由の表現に直す。無ければ触らない
- smoke の一時リポジトリは既存ケースと同じく `$TMP` 配下に `git init` で作り、`git -c user.name=... -c user.email=... commit --allow-empty` で初期コミットを作ってから worktree を追加する
- `scripts/install.sh` への追加は既存の `copy_if_absent "$SRC/scripts/..."` 行とマニフェスト対象の列挙（`for p in ...`）の両方に行う。`scripts/uninstall.sh` はマニフェストの `files` を元に除去するため変更しない
