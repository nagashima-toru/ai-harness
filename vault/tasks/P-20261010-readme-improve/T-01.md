# T-01 README 冒頭に位置づけと vision へのリンク、クイックスタート節を足す

## 目的
README を開いた人が、最初の数行で「何のためのものか」を知り（詳細は `docs/vision.md` へ辿る）、clone から最初の PR のマージまでの最小手順を1節で追えるようにする。

## 入力
- `README.md`（現状）
- `docs/vision.md`（リンク先。本文は写さない）
- `docs/install.md` パターン1の「8. 最初のゴールを入れる」（クイックスタートの参考）
- `.claude/skills/plan/SKILL.md`・`.claude/skills/run/SKILL.md`（/plan が承認後に /run を続けて実行すること、PR を作るまでで止まること）

## 成果物
- `README.md`（1ファイル。冒頭の追記と「## クイックスタート」節の新設）

## 受け入れ基準
- 冒頭（最初の `## ` 見出しより前）に、位置づけの文とリンクが同じ行にある。確認：`awk '/^## /{exit} {print}' README.md | grep -cE '実行を安いモデルに任せても成果が安定する汎用のタスク実行基盤.*\]\(docs/vision\.md\)'` の出力が `1`。冒頭は短いまま：`awk '/^## /{exit} {print}' README.md | grep -c .` の出力が `4` 以下
- vision の本文（原則・非ゴール）を写していない。確認：`grep -cE '完了かどうかは作った本人に決めさせない|守らせたい規律はプロンプトに頼らず|タスクは1コンテキストで終わる小ささに切る|状態はモデルの記憶ではなくファイルに置く|迷ったら推測で進めずに止める|考える工程と実行する工程でモデルを分ける|ハーネス本体はドメイン知識を持たない|導入先の既存資産を壊さない|最終決定は人が持つ|マルチユーザー化|より安いモデルでできるなら' README.md` の出力が `0`
- 「## クイックスタート」節に clone → smoke → /plan → /run → マージの順で手順がある。確認：`awk '/^## クイックスタート/{s=1;next} /^## /{s=0} s' README.md | grep -oE 'git clone|bash scripts/smoke\.sh|/plan <ゴール>|/run\b|gh pr merge'` の出力がちょうど5行で、上から `git clone`・`bash scripts/smoke.sh`・`/plan <ゴール>`・`/run`・`gh pr merge` の順
- README の見出し構成が確定している。確認：`grep -E '^## ' README.md` の出力がちょうど次の8行（この順）：`## 目的`・`## セットアップ`・`## クイックスタート`・`## 使い方`・`## 拡張ポイント（ルール）`・`## 仕組み`・`## 構成`・`## ライセンス`
- 既存の情報が残っている。確認：`grep -cE '^\| `(/design <ゴール>|/plan <ゴール>|/run|python3 scripts/run_unattended\.py)` \|' README.md` が `4`、`grep -cE '^\| `vault/rules/(common|creator|verifier|planner)/` \|' README.md` が `4`、`grep -cF '`/design` と `/plan` の使い分け' README.md` が `1`、`grep -cF '詳細は [LICENSE](LICENSE) を参照' README.md` が `1`
- 文書中のパスが実在する。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`

## 決定済み
- 冒頭の位置づけの文には、`実行を安いモデルに任せても成果が安定する汎用のタスク実行基盤` という語句をそのまま書き、同じ行に `[docs/vision.md](docs/vision.md)` のリンクを置く（例：`実行を安いモデルに任せても成果が安定する汎用のタスク実行基盤です。目的・原則・非ゴールは [docs/vision.md](docs/vision.md) を参照。`）。vision の原則・非ゴールの本文や要約は書かない（`docs/vision.md` が唯一の正本という P-20261010-vision-local-only の決定）
- 冒頭（タイトル行を含め、最初の `## ` より前の空でない行）は4行以下。既存の2行（二段構成の説明・雛形の説明）は残してよいが、4行に収まらなければ1行にまとめる
- 「## 目的」節の箇条書き（verifier・Stop フック・vault・状態のファイル化）はそのまま残す。節の末尾の「ハーネス全体の目的・原則・非ゴールは [docs/vision.md](docs/vision.md) にまとめている。」の行は、冒頭のリンクと重複するので消してもよい（残してもよい）
- 「## クイックスタート」節は「## セットアップ」節の直後、「## 使い方」の直前に置く。見出し名は `## クイックスタート` ちょうど
- クイックスタートは番号付きの5手順程度にする。各手順で次の語句をそれぞれ1回だけ書く（節の中でほかの箇所に重ねて書かない）：`git clone`（URL は今の README の `git@github.com:nagashima-toru/ai-harness.git`）、`bash scripts/smoke.sh`（最終行が `fail=0` なら OK、程度の補足）、`/plan <ゴール>`（`claude` を起動して入力する）、`/run`（粒度の確認を通ると自動で approved になり `/run` が続けて走る。planner の質問があれば答えるまで止まる）、`gh pr merge`（PR ができたら人が内容を確認してマージする。エージェントはマージしない）
- クイックスタート節では `docs/runbook.md` や `run_unattended.py` に触れない（`/run\b` の検査が `/runbook`・`/run_unattended` に当たらないようにするため、また最小の手順に留めるため）
- この時点ではセットアップ節の clone・smoke のコードブロックは消さなくてよい（T-02 で整理する）。仕組み節・構成節も触らない（T-03・T-04）
- 「## 使い方」「## 拡張ポイント（ルール）」の本文と表は変えない
