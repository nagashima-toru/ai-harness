# T-01 vcs_finish.sh が上流の有無に関係なく毎回現在のブランチを push する

## 目的
Issue #217 を解決する。`HARNESS_PUSH_BRANCH` が無く、現在のブランチに上流（`@{u}`）が既に設定されていると、`do_push` が push せずに PR を作り、最後のコミットがリモートに載らない。上流の有無に関係なく毎回 push するようにし、smoke で確かめる。

- `docs/vault-spec.md` 1節の `HARNESS_PUSH_BRANCH` の段落（36行）

## 決定済み
- `do_push` の新しい動作：`HARNESS_PUSH_BRANCH`（`push_branch`）があれば今までどおり `git push -u origin "HEAD:$push_branch"`。無ければ上流の有無を見ずに（`git rev-parse --abbrev-ref --symbolic-full-name @{u}` の分岐を消す）、毎回 `current_branch="$(git rev-parse --abbrev-ref HEAD)"` を取って `git push -u origin "$current_branch"` する。`-u` は付けたまま（上流が無い時に設定するため。上流があっても fast-forward の push なので非破壊）。force は使わない。push が失敗したらその終了コードで終わる（今と同じ）。ホスティング無し（`none`）の経路は push しない（今と同じ、変えない）
- `do_push` の直前のコメント（44行）は「push する。push_branch があれば毎回 HEAD:<値>、無ければ上流の有無に関係なく毎回現在のブランチ。失敗したらその終了コードで終わる。」にする。冒頭のコメントの `HARNESS_PUSH_BRANCH` の説明（20行の「前後の空白を除いて空なら未設定（今までどおり）。」）は「前後の空白を除いて空なら未設定で、上流の有無に関係なく毎回 git push -u origin <現在のブランチ> で push する。」にする
- `docs/vault-spec.md` 36行の「前後の空白を除いて空（未設定を含む）なら未設定で、今の動作（上流が無ければ現在のブランチ名で push、head は現在のブランチ）のまま。」を、「前後の空白を除いて空（未設定を含む）なら未設定とする。未設定なら上流の有無に関係なく毎回現在のブランチ名で push し（`git push -u origin <現在のブランチ>`。上流が設定済みでも push する。Issue #217）、head は現在のブランチにする。」に置き換える。この段落のほかの文は変えない
- smoke に足す検査の名前は `(push-9) github・引数なし・未設定・上流あり・先行 → 現在のブランチの新しい HEAD が push される` とし、`(push-8)` のブロックの直後（`BGTMP="$(smoke_tmpdir)"` の行の前）に置く。手順：`pb_reset` → `pb_run github`（上流無しの1回目。`-u` で上流が設定される）→ `git -C "$PB_WORK" rev-parse --abbrev-ref --symbolic-full-name @{u}` が成功する（上流が設定済み）ことを確かめる → `pb_commit ahead`（ローカルが1コミット先行）→ `pb_run github`（2回目）→ `[ "$(pb_bare pbmain)" = "$(pb_head)" ]` かつ `$VF_REC` に `head=pbmain` の行がある、の全部で `vf_ok=1`。判定は既存の `vf_rest_check` を使う。修正前の `do_push` ではこの検査が NG になる（2回目が push されない）
- smoke の既存のフィクスチャ `VF_REPO`・`VF_REPO2` は、origin が `https://github.com/o/r.git` で、上流を `.`（`branch.<名前>.remote .`）にして push を避けていた。上流があっても push するようになると実際に github.com へ push して失敗するので、push 先だけをローカルの bare に向ける：それぞれ `$TMP/vf_push.git`・`$TMP/vf_push2.git` を `git init -q --bare` で作り、`git remote add origin ...` の後に `git remote set-url --push origin <その bare>` を足す（`git remote get-url origin` は fetch の URL を返し続けるので、ホスティング判定と owner/repo の取り出しは変わらない。`(vf-rest-4)` の `git remote set-url origin <URL>` も push の URL を変えない。planner が一時リポジトリで確かめた）。既存の `branch.<名前>.remote .` の設定は残してよい。ほかの既存の検査の期待値は変えない
- 古い記述の検索で除外するディレクトリと理由：`vault/`（この計画の計画票・タスク票が古い記述を引用している）、`.git`（git の内部）、`worktrees`（メインリポジトリの `.claude/worktrees/` にある、並行して動くほかのタスクの worktree）。smoke の検査名の「上流無し」（`(push-3)`）は「上流が無」に当たらないので変えなくてよい
- smoke の一時ファイルは smoke の `$TMP` の中に作る（既存の書き方どおり）。`rm -rf` は使わない
