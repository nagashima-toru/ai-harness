# T-01 計画一式を archive に移す scripts/archive_plans.sh を作る

## 目的
done かつ PR がマージ済みの計画のうち、新しい順に `--keep`（既定5）件を残し、それより古い計画の一式（計画票・タスク票・verdict・log）を、安全装置付きで `vault/archive/<年-月>/` へ `git mv` で移すスクリプトを作る。実際の移動は人が行い、エージェントは `--list`・`--dry-run` だけを使う前提にする。

## 入力
- 計画票 `vault/plans/P-20261003-archive-old-logs.md` の「ゴール」（人の回答）と「分割方針」（「新しい」の基準・配置・フックとの関係）
- `docs/runbook.md` 5節（現在の手動手順。名前が衝突する欠陥がある）
- `vault/archive/2026-09/`（既存の archive の形。種別ごとのサブディレクトリ）
- `scripts/current_plan.sh`（frontmatter の読み方の規則。同じ規則で読む）
- `scripts/discard_worktree.sh`・`scripts/vcs_finish.sh`（既存の bash スクリプトの書き方）

## 成果物
- `scripts/archive_plans.sh`（新規。1ファイル）

## 受け入れ基準
- 構文エラーが無い：`bash -n scripts/archive_plans.sh` の出力が空
- 既定（`--keep 5`）で移す対象が49件：`bash scripts/archive_plans.sh --list | grep -c '^P-'` の出力が `49`
- 新しい5件は残り、6件目から移す：`bash scripts/archive_plans.sh --list | grep -c -x -e P-20261002-smoke-tmp-unique -e P-20261002-verify-cmd-guard-align -e P-20261003-guard-rules-path-text` の出力が `1`（6件目の `P-20261002-smoke-tmp-unique` だけが出る）
- 候補が `--keep` 件以下なら何も出さない：`bash scripts/archive_plans.sh --list --keep 60 | grep -c .` の出力が `0`
- 計画 ID を渡すと4種別の移動行を出す：`bash scripts/archive_plans.sh --dry-run P-20260920-freeze-legacy | grep -c ' vault/archive/2026-09/\(plans\|tasks\|verdicts\|log\)/P-20260920-freeze-legacy'` の出力が `4`
- 新しい5件に入る計画 ID を渡すと NG 行を出す：`bash scripts/archive_plans.sh --dry-run P-20261003-guard-rules-path-text 2>&1 | grep -c '^archive_plans: NG P-20261003-guard-rules-path-text: '` の出力が `1` 以上
- モードの指定が無い時は usage を出す：`bash scripts/archive_plans.sh P-20260920-freeze-legacy 2>&1 | grep -c '^usage: '` の出力が `1`

## 決定済み
- 使い方：`bash scripts/archive_plans.sh (--list|--dry-run|--apply) [--keep <N>] [--base <ref>] [--from-file <path>] [<計画ID> ...]`
  - `--list`・`--dry-run`・`--apply` はどれか1つを必ず指定する（2つ以上・無しは usage を stderr に出して終了コード2）。usage の行は `usage: ` で始める
  - `--keep` の既定は `5`。0 以上の整数でなければ usage で終了コード2。`--base` の既定は `main`
  - 計画 ID は引数と `--from-file`（1行1件。空行と `#` で始まる行は読み飛ばす）から集める。1件も渡さなければ「移す対象」の全部を扱う。渡した時は、その ID だけを扱う
- リポジトリのルートは `git rev-parse --show-toplevel`（カレントディレクトリ基準）で決める。git リポジトリの外なら stderr にメッセージを出して終了コード2。スクリプト自身の置き場所は基準にしない（smoke.sh で一時リポジトリから呼ぶため）
- 候補（移すか残すかを決める母集団）：`vault/plans/*.md` のうち、次を全部満たすもの。満たさないものは候補にならず、移さない（残す。`--keep` の件数にも数えない）
  1. 計画 ID が `^P-[0-9]{8}-[a-z0-9][a-z0-9-]*$` に一致する（`P-019` などの旧形式は候補にしない）
  2. 現在のブランチ名が `work/<計画 ID を英小文字にしたもの>` でない（現在のブランチの計画は常に残し、5件に数えない）
  3. frontmatter の `status` が `done`（frontmatter の読み方は `scripts/current_plan.sh` と同じ：1行目が `---`、次の `---` まで）
  4. タスク表のデータ行（先頭のセルが `T-` で始まる行）が1行以上あり、全行の status 列（2列目）が `done`
  5. `git show <base>:vault/plans/<ID>.md` が成功し、その版の frontmatter の `status` も `done`（＝ PR がマージ済み）
  6. `vault/log/<ID>.md` があり、`- YYYY-MM-DD HH:MM ` で始まる行が1行以上ある
- 「新しい」の基準：候補を「log の最初の日時行の `YYYY-MM-DD HH:MM`、同じなら計画 ID の文字列順」で古い順に並べ、後ろ（新しい方）から `--keep` 件を残す。それより前の全部が「移す対象」。候補が `--keep` 件以下なら移す対象は空で、stderr に `archive_plans: 移す計画がありません` を出して終了コード0（`--list`・`--dry-run`・`--apply` のどれでも、stdout には何も出さない）
- 計画 ID を渡した時は、各 ID が「移す対象」に入っていなければ NG。NG は1件ごとに stderr へ `archive_plans: NG <ID>: <理由>` の1行で出す（理由は、候補の条件1〜6のどれを満たさないか、または「新しい <N> 件に入る」。同じ ID が2回以上渡された時も NG）
- 移すものごとの追加の検査：移動元の4パス（下記）に未コミットの変更・未追跡ファイルが無い（`git status --porcelain -- <パス>` が空）、移動先の4パスがまだ存在しない。満たさなければ NG
- 全部か無しか：NG が1件でもあれば何も移さず、移動行も一覧も出さずに終了コード1
- 配置：計画 ID の日付部分から `<年-月>` を作り（`P-20260924-x` → `2026-09`）、次の4つを移す。存在しないもの（例：verdict の無い計画）は飛ばす（NG にしない）
  - `vault/plans/<ID>.md` → `vault/archive/<年-月>/plans/<ID>.md`
  - `vault/tasks/<ID>` → `vault/archive/<年-月>/tasks/<ID>`
  - `vault/verdicts/<ID>` → `vault/archive/<年-月>/verdicts/<ID>`
  - `vault/log/<ID>.md` → `vault/archive/<年-月>/log/<ID>.md`
- 出力（NG が無い時）
  - `--list`：移す計画 ID を1行1件、古い順に stdout へ出して終了コード0。何も変えない
  - `--dry-run`：移動1件ごとに stdout へ `git mv <移動元> <移動先>` の1行を出して終了コード0（パスはリポジトリのルートからの相対パス）。何も変えない
  - `--apply`：`--dry-run` と同じ行を出しつつ、移動先の親ディレクトリを `mkdir -p` してから実際に `git mv` する。途中で `git mv` が失敗したら stderr に出して終了コード1（それまでの移動は戻さない。人が `git status` で確かめる）。コミットはしない
- 冒頭のコメントに「`--apply` は人が手元で実行する。エージェント（creator を含む）は `--list`・`--dry-run` だけを使う。creator は `vault/plans/`・`vault/log/` に書き込めず、スクリプト経由の移動はその禁止を回避することになるため」と書く
- `scripts/install.sh` の `SCRIPTS_EXCLUDE` は変えない（導入先にも配る。汎用のスクリプトのため）。install.sh は触らない
- 受け入れ基準の期待値（49件・6件目が `P-20261002-smoke-tmp-unique`・`P-20260920-freeze-legacy` の移動行4行）は、2026-10-03 時点の `vault/plans/`・`vault/log/` と `main` を planner が数えた値。この計画の計画票は approved で `main` に無いので候補に入らない
- `.claude/hooks/`・`.claude/settings.json` は触らない（issue #85）
