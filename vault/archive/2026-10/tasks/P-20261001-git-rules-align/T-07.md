# T-07 smoke を通し SKILL.md の引用と提案の一致を確認する

## 目的
T-01〜T-06 の変更がそろった計画ブランチで `bash scripts/smoke.sh` が通ることを確認する。あわせて、`.claude/skills/run/SKILL.md` が `vault/rules/common/git.md` から引いている2つの文言が T-01 の提案ファイルに実在すること（反映後に出典の食い違いが解消されること）と、提案ファイル2つがそろっていることを突き合わせる。

## 入力
- `scripts/smoke.sh`（/tmp の固定パスを使うので、他タスクと並行させない）
- `vault/tasks/P-20261001-git-rules-align/T-01-proposal.md`・`T-02-proposal.md`
- `.claude/skills/run/SKILL.md`（72行目・76行目）
- T-03〜T-06 の成果物（`.claude/agents/verifier.md`・`docs/vault-spec.md`・`README.md`・`.claude/skills/run/SKILL.md`）

## 成果物
- smoke の実行結果（`/tmp/P-20261001-git-rules-align-T-07.txt` に書き出し、最終行をこのタスク票の「進捗」に記録する）

## 受け入れ基準
- `bash scripts/smoke.sh > /tmp/P-20261001-git-rules-align-T-07.txt 2>&1` を実行した後、`tail -1 /tmp/P-20261001-git-rules-align-T-07.txt` の出力が `fail=0` で終わる（`smoke: pass=<N> fail=0` の形）
- 提案ファイル2つがそろっている（`ls vault/tasks/P-20261001-git-rules-align/T-01-proposal.md vault/tasks/P-20261001-git-rules-align/T-02-proposal.md` が終了コード0）
- SKILL.md 72行目の引用文言が、SKILL.md と提案ファイルの両方にある（`grep -n 'コミットは受け入れ基準に含まれている場合だけ行う' .claude/skills/run/SKILL.md` と `grep -n 'コミットは受け入れ基準に含まれている場合だけ行う' vault/tasks/P-20261001-git-rules-align/T-01-proposal.md` がそれぞれヒットする）
- SKILL.md 76行目の引用文言が、SKILL.md と提案ファイルの両方にある（`grep -n '自己判断で解決しない' .claude/skills/run/SKILL.md` と `grep -n '自己判断で解決しない' vault/tasks/P-20261001-git-rules-align/T-01-proposal.md` がそれぞれヒットする）
- マージ後の計画ブランチで、旧方式の記述が実体から消えている（`grep -c '作業ステップ' .claude/agents/verifier.md` が `0`、`grep -c 'ステップごと' docs/vault-spec.md` が `0`、`grep -c 'pr create' README.md` が `0`）

## 決定済み
- このタスクではファイルを変更しない（「進捗」への記録を除く）。smoke が `fail=0` にならない場合や、文言・件数が合わない場合は直さない。`blocked` にして、question に失敗したテスト名または合わなかった確認コマンドと、出力の要点を書く。T-01〜T-06 の成果物はそれぞれのタスクのものなので、このタスクでは書き換えない
- pass の件数は基準にしない（`fail=0` だけを見る）
- 書き出し先は固定パス `/tmp/P-20261001-git-rules-align-T-07.txt`。実行前の後片付け（`rm -rf` など）は要らない（`>` で上書きされる）
- 実体 `vault/rules/` 配下が変わったことは検査しない（反映は人が行う）
- このタスクではコミットしない（受け入れ基準にコミットが無いため）
