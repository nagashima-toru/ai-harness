# T-01 vcs_finish.sh の GitHub の PR 作成を REST（gh api）にし smoke にケースを足す

## 目的
Claude Code の Web セッションでは `gh pr create` が `HTTP 403: GitHub GraphQL is not available` で失敗する。`scripts/vcs_finish.sh` の GitHub の経路を REST（`gh api` の `repos/<owner>/<repo>/pulls`）で PR を作る形にし、GraphQL が使えない環境でも PR ができるようにする。

## 入力
- `scripts/vcs_finish.sh`（直す対象）
- `scripts/smoke.sh` の `== vcs_finish.sh ==` 節（1407行目付近から `== archive_plans.sh ==` の前まで）
- `vault/harness-improvements/P-20261009-sandbox-remove.md`・`vault/harness-improvements/P-20261010-docs-align-guards.md`（提案の元）
- `docs/vault-spec.md` 1節（`HARNESS_PR_BODY_FILE`・`HARNESS_PR_TITLE` の今の扱い。文書の更新は T-06 が行うので、このタスクでは変えない）

## 成果物
- `scripts/vcs_finish.sh`（主な成果物）
- `scripts/smoke.sh`（vcs_finish.sh の節のケース）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- REST の6ケースがすべて通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (vf-rest-[1-6])'` の出力が `6`
- GitLab の経路のケースが今のまま通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   .*gitlab'` の出力が `4`
- GitHub の引数なしの経路から `gh pr create` の呼び出しが無くなり、smoke にも残っていない。確認：`grep -c 'gh pr create --' scripts/vcs_finish.sh scripts/smoke.sh` の出力が `scripts/vcs_finish.sh:0` と `scripts/smoke.sh:0` の2行
- `bash -n scripts/vcs_finish.sh` が終了コード0で何も出力しない

## 決定済み
- GitHub の経路の順序：(1) `gh` が無ければ今どおり終了コード127 → (2) `check_notes`（今どおり）→ (3) owner/repo の取り出し → (4) push（今どおり。upstream があれば push しない）→ (5) PR の作成。owner/repo が取れない時は push の前に終わる
- owner/repo の取り出し：`git remote get-url origin` の値の末尾の `/` を外し、続けて末尾の `.git` を外し、`/` と `:` で区切った最後の2つを owner と repo にする（`https://github.com/o/r.git`・`https://github.com/o/r`・`git@github.com:o/r.git`・`ssh://git@github.com/o/r.git/` がどれも `o`/`r` になる）。origin が無い・2つ取れない時は、標準エラーに `vcs_finish.sh: origin の URL から owner/repo を取れません: <URL>` を出して終了コード2で終わる（`gh` は呼ばない）
- PR の作成は次の形で `gh api` を呼ぶ（引数の順序もこのとおり。smoke の期待値はこの順で書く）。head は `git rev-parse --abbrev-ref HEAD`、base は `main` 固定（このハーネスは `main` を前提にしている：`/plan` は `main` からブランチを切り、`agent_write_guard.py` は `main` へのコミットを止める）
  - `HARNESS_PR_BODY_FILE` の経路：`gh api -X POST repos/<owner>/<repo>/pulls -f title=<notes_title の値> -f head=<ブランチ> -f base=main -F body=@<HARNESS_PR_BODY_FILE のパス> --jq .html_url`
  - 計画が見つかった引数なしの経路：`gh api -X POST repos/<owner>/<repo>/pulls -f title=<pr_title> -f head=<ブランチ> -f base=main -f body=<pr_body> --jq .html_url`
  - 計画が見つからない引数なしの経路（今の `--fill`）：title は `git log -1 --format=%s`、body は `git log -1 --format=%b`（空でもよい）で、`gh api -X POST repos/<owner>/<repo>/pulls -f title=<件名> -f head=<ブランチ> -f base=main -f body=<本文> --jq .html_url`
  - 引数がある時は今どおり `gh pr create "$@"` にそのまま渡す（任意の引数を REST に変換できないため。owner/repo の取り出しはこの経路でも行ってよいが、取れなくても終わらせない。`gh pr create "$@"` の行はこの1か所だけ残す）
- 作った PR の URL は `--jq .html_url` で `gh api` が標準出力に出す。スクリプトは `gh api` の終了コードで終わる
- タイトル・本文・`HARNESS_PR_BODY_FILE`・`HARNESS_PR_TITLE` の扱い（どの時にどれを使うか、読めない本文ファイルで終了コード2）は今と同じ。GitLab・`none` の経路と、`gh`/`glab` が無い時のメッセージは変えない
- 冒頭のコメント（使い方の説明）を REST の形に合わせて直す。コメントにも `gh pr create --` の形を書かない
- smoke のフェイクの `gh`：今のフェイク（引数を1行1つで `$VF_REC` に書く）に、第1引数が `api` の時は標準出力に `https://github.com/o/r/pull/1` を1行出す動きを足す。`$VF_REPO`・`$VF_REPO2` には `git remote add origin https://github.com/o/r.git` を足す（upstream は今の `.` のままにして push させない）
- 足すケース（どれも1ケース1行の `ok`/`NG` を出す。名前は `(vf-rest-<番号>)` で始める）：
  - `(vf-rest-1)` `$VF_REPO`・`HARNESS_PR_BODY_FILE=$VF_NOTES`・`HARNESS_PR_TITLE=NT` → 記録が `api` `-X` `POST` `repos/o/r/pulls` `-f` `title=NT` `-f` `head=vfmain` `-f` `base=main` `-F` `body=@<$VF_NOTES のパス>` `--jq` `.html_url` と完全に一致
  - `(vf-rest-2)` `$VF_REPO2`・引数なし（計画あり）→ 記録の先頭が `api` `-X` `POST` `repos/o/r/pulls` `-f` `title=P-20990101-vf: vf goal line` `-f` `head=work/p-20990101-vf` `-f` `base=main` `-f` で、`body=` で始まる引数にタスク履歴の T-01・T-02 の行があり、最後の2つが `--jq` `.html_url`
  - `(vf-rest-3)` `$VF_REPO`・引数なし（計画無し）→ 記録が `api` `-X` `POST` `repos/o/r/pulls` `-f` `title=init` `-f` `head=vfmain` `-f` `base=main` `-f` `body=` `--jq` `.html_url` と完全に一致（`init` は `$VF_REPO` の最新コミットの件名）
  - `(vf-rest-4)` origin を `git@github.com:o2/r2.git`・`https://github.com/o2/r2`・`ssh://git@github.com/o2/r2.git/` に順に変えて実行すると、3回とも記録に `repos/o2/r2/pulls` がある（3回とも満たした時だけ ok。終わったら origin を `https://github.com/o/r.git` に戻す）
  - `(vf-rest-5)` origin の無いリポジトリ（新しく作る。upstream は `.`）で `HARNESS_VCS_HOST=github` → 終了コード2で、`gh` を呼ばない（記録ファイルが無い）
  - `(vf-rest-6)` `(vf-rest-1)` と同じ条件で、`vcs_finish.sh` の標準出力が `https://github.com/o/r/pull/1` の1行だけ
- 今ある GitHub の引数なしのケース（`(vcs_finish) github・引数なし`・`(vcs_finish-body) github・計画あり・引数なし`・`(vf-notes-1)`・`(vf-notes-3)`）は、`(vf-rest-*)` に置き換えて消すか、REST の形の期待値に直す（直す時も名前を `(vf-rest-` で始めない。`(vf-rest-` のケースは上の6つだけにする）。ケースの名前・期待値に `gh pr create --` の文字列を残さない
- 引数ありのケース（`(vcs_finish) github・引数あり`・`(vcs_finish-body) github・計画あり・引数あり`・`(vf-notes-4)`）、GitLab のケース（名前に `gitlab` を含む4つ）、`(vf-notes-5)` は期待値と名前を変えない。名前に `gitlab` を含むケースを新しく足さない
- 一時ファイルは smoke の既存の `$TMP` の下に作る（smoke の後片付けに任せる）
- run・design スキル・`docs/` の記述はこのタスクでは変えない（T-04・T-06 が行う）
