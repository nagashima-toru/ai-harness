# T-0018 agent_write_guard に人だけが使えるルール編集の解除口を追加する

## 目的
`doing` / `review` 中は `vault/rules/` への書き込みが拒否されるため、ハーネス標準ルールを run-queue の作成エージェントが書けない。人が起動時に環境変数でタスク ID を指定した時だけ、この改ざん防止判定を解除できるようにする。

## 入力
- `.claude/hooks/agent_write_guard.py`（改ざん防止判定は `main()` の先頭、`active_doing_review_task_ids()` / `targets_vault_rules()`）
- `scripts/smoke.sh` の `== agent_write_guard.py ==` 節（`run_guard` は `CLAUDE_PROJECT_DIR="$TMP" python3 "$GUARD_HOOK"` の形。環境変数を前置すれば追加できる）
- `docs/vault-spec.md` 第13節「agent_write_guard フックの改ざん防止判定」（判定表がある）
- `vault/plans/P-015.md`（この解除口が必要な理由）

## 成果物
- `.claude/hooks/agent_write_guard.py`（付随：`scripts/smoke.sh` にケース2件、`docs/vault-spec.md` 第13節に判定行と説明）

## 受け入れ基準
- `doing` が1件あり `HARNESS_ALLOW_RULES_WRITE` が未設定の時、`vault/rules/` 配下への Write が従来どおり deny になる（既存の smoke ケースが ok のまま）
- `doing` のタスク ID と `HARNESS_ALLOW_RULES_WRITE` の値が一致する時、同じ Write が allow になる（smoke に新ケース1件）
- 値が `doing` のタスク ID と一致しない時は deny になる（smoke に新ケース1件）。確認：`grep -c 'HARNESS_ALLOW_RULES_WRITE' scripts/smoke.sh` が2以上
- `.claude/hooks/agent_write_guard.py` に解除判定がある。確認：`grep -c 'HARNESS_ALLOW_RULES_WRITE' .claude/hooks/agent_write_guard.py` が1以上
- `docs/vault-spec.md` 第13節に解除条件（環境変数名と ID 一致の条件）が書かれている。確認：`grep -c 'HARNESS_ALLOW_RULES_WRITE' docs/vault-spec.md` が1以上
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

## 決定済み
- 環境変数名は `HARNESS_ALLOW_RULES_WRITE`。値は解除を許すタスク ID（例：`T-0019`）。カンマまたは空白区切りで複数指定できるようにする
- 解除条件は「`doing`/`review` の ID がすべて値に含まれる時」。未設定・空文字・不一致・値が `1` や `true` のような ID でない文字列の場合は従来どおり deny する（真偽値では解除しない。必ず ID を書かせる）
- 使い方は `HARNESS_ALLOW_RULES_WRITE=T-0019 claude` または `HARNESS_ALLOW_RULES_WRITE=T-0019 claude -p "/run-queue"`。フックは Claude Code プロセスの環境を継承するため、作成エージェントが Bash 内で `export` しても解除できない（実質的に人しか解除できない）。この点をフックの docstring に1行書く
- 既存の verifier / planner 向け `ALLOWED` 判定は変更しない。解除しても verifier・planner は `vault/rules/` に書けないまま（後段の判定で拒否される）
- 実装は既存の改ざん防止ブロック（`if active_ids and targets_vault_rules(...)`）の条件に解除判定を足すだけでよい。`active_doing_review_task_ids()` / `targets_vault_rules()` / `BASH_WRITE_PATTERNS` は変えない
- `docs/vault-spec.md` 第13節の判定表に「解除された場合」の行を1行足し、表の下に環境変数の説明を1〜2行足す。既存の行・列は変えない
- 他のフック（`stop_gate.py` / `todo_guard.py`）・`scripts/install.sh`・`README.md` は変更しない
- smoke の既存ケースは削除・改変しない（追加のみ）
- git commit はしない（人が確認してからコミットする）

## 進捗
- `bash scripts/rules.sh creator` を実行。出力は空だったため何もしていない
- `.claude/hooks/agent_write_guard.py` に `rules_write_allowed()` を追加。`HARNESS_ALLOW_RULES_WRITE` をカンマ／空白区切りで分解し、doing/review の ID がすべて含まれる時だけ True。空・不一致・`1` や `true` のような ID でない値では解除しない
- 既存の改ざん防止ブロックの条件に `and not rules_write_allowed(active_ids)` を足しただけ。`active_doing_review_task_ids()` / `targets_vault_rules()` / `BASH_WRITE_PATTERNS` と ALLOWED 判定は未変更
- deny の reason に、人が付けるべき環境変数の指定例を1文追加
- docstring に、フックが Claude Code プロセスの環境を継承するため作成エージェントの `export` では解除できない旨を追記
- `scripts/smoke.sh` に3ケース追加（ID 一致→許可、不一致→拒否、`1` のような非 ID 値→拒否）。既存ケースは未変更
- `docs/vault-spec.md` 第13節の判定表に解除の行を1行足し、「### 明示解除」小節で環境変数の使い方と制約を説明
- 受け入れ基準6件の確認コマンドをすべて実行し通過。`bash scripts/smoke.sh` は pass=43 fail=0（既存40件から+3）
