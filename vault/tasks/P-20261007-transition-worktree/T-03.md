# T-03 transition.py の doing（FAIL の再試行）と blocked に --worktree を足す

## 目的
`doing --worktree <パス> --branch <ブランチ>`（FAIL の再試行：attempt+1 して worktree を破棄。上限なら verdict の reasons を question にして review→blocked）と、`blocked --worktree <パス> --branch <ブランチ> --plan-head <sha>`（creator が blocked を報告した時：記録行を書いて blocked にし、worktree は残す）を1コマンドで行えるようにする（D-012 フェーズ4の (3)・(4)）。これで4つのサブコマンドがそろう。

## 入力
- `vault/designs/D-012.md` の「フェーズ4 transition.py に worktree の運用を足す」（ゴール文・受け入れ基準の候補・決定済み）
- `vault/tasks/P-20261007-transition-worktree/T-01.md`・`T-02.md` の「決定済み」（共通部品・終了コード・標準出力の形・question と補足の書き方）
- `scripts/transition.py`（T-02 の後の版）
- `.claude/skills/run/SKILL.md` の手順3.8・6.4（今 run がしていること。このファイルは変えない）
- `vault/tasks/P-20261007-transition-worktree/fixtures/try.sh`（確認用のフィクスチャ。`expect_note`・`expect_question` は決定済みの規則で計算した期待値）

## 成果物

## 受け入れ基準
- FAIL の再試行：`bash vault/tasks/P-20261007-transition-worktree/fixtures/try.sh fail doing --worktree @WT --branch @BR` の出力に `exit=3`・`| T-01 | doing | 2 | - | A | |`・`commit=1 P-TEST/T-01: review→doing :: vault/log/P-TEST.md vault/plans/P-TEST.md`・`wt_registered=no`・`wt_dir=no`・`branch_exists=no` があり、log_new 節が ` T-01 review→doing attempt=2 verifier=fx-verifier-model <expect_note の値>` で終わる1行、stdout 節が `P-TEST/T-01: review→doing attempt=2 ` で始まる1行だけ
- 上限なら reasons を question にして blocked：`try.sh fail3 doing --worktree @WT --branch @BR`（`try.sh` は1行目と同じパス。以下同じ）の出力に `exit=4`・`| T-01 | blocked | 3 | - | A | <expect_question の値> |`・`wt_registered=yes`・`branch_exists=yes`・`plan_guard=allow` があり、log_new 節が ` T-01 review→blocked attempt=3 verifier=fx-verifier-model <expect_note の値>` で終わる1行、stdout 節が `P-TEST/T-01: review→blocked attempt=3 ` で始まる1行だけ
- creator の blocked の報告：`try.sh blk blocked --question-file @QFILE --worktree @WT --branch @BR --plan-head @PH` の出力に `exit=4`・`| T-01 | blocked | 1 | - | A | 質問A／B 次の行 |`・`commit=1 P-TEST/T-01: doing→blocked :: vault/log/P-TEST.md vault/plans/P-TEST.md`・`wt_registered=yes`・`wt_new_commits=0`・`wt_porcelain= M src/ok.txt`（収集しない）があり、log_new 節が2行で、1行目が ` T-01 worktree path=<wt_path の値> branch=worktree-agent-fx plan_head=<plan_head の値>`、2行目が ` T-01 doing→blocked attempt=1 creator=fx-creator-model` で終わり、stdout 節が `P-TEST/T-01: doing→blocked attempt=1 ` で始まる1行だけ
- 前提を満たさなければ何もしない：`try.sh pass doing --worktree @WT --branch @BR`（verdict が PASS）・`try.sh rev doing --worktree @WT --branch @BR`（doing からの doing）・`try.sh fail doing --worktree @WT --branch worktree-agent-other` の出力に `exit=1`・`new_commits=0`・`wt_registered=yes` がある。`try.sh blk blocked --question-file @QFILE --worktree @WT --branch @BR`（`--plan-head` 無し）の出力に `exit=2` がある
- T-01・T-02 の動きが変わらない：`try.sh rev review --worktree @WT --branch @BR --plan-head @PH` の出力に `exit=0`、`try.sh pass done --worktree @WT --branch @BR --plan-head @PH` の出力に `exit=0`・`new_commits=2` がある
- `--worktree` 無しはフェーズ2のまま：`try.sh fail doing` の出力に `exit=0`・`commit=1 P-TEST/T-01: review→doing :: vault/log/P-TEST.md vault/plans/P-TEST.md`・`wt_registered=yes`（worktree に触れない）がある。`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=594 fail=0`

## 決定済み
- `--worktree` を受け付ける遷移先は review・done・doing・blocked の4つになる。T-01・T-02 で「まだ対応していない」として終了コード2にしていた doing・blocked を受け付けるようにし、それ以外の遷移先（todo など）に `--worktree` を付けたら終了コード2
- doing（FAIL の再試行）：
  - 呼び出し：`doing --worktree <パス> --branch <ブランチ>`。`--plan-head` は使わない（渡されても無視する）。id は1つだけ
  - 今の status が review の時だけ行う（review→doing）。doing（中断からの再開・ハング）に `--worktree` を付けたら終了コード1。中断からの再開・ハングはフェーズ2の呼び出し（`--no-model`・`--note`）のまま
  - verdict `vault/verdicts/<計画ID>/<id>.json` が、JSON として読め、`task` が `<計画ID>/<id>`、`attempt` が表の値と文字列として一致し、`result` が `FAIL`（大文字小文字は区別しない）の時だけ行う。それ以外は終了コード1（何も変えない）
  - reasons：verdict の `reasons`（配列でない・空の時は `["verdict の reasons が空"]` とみなす。要素が文字列でなければ `str()` する）
  - log の補足：`clean_text(reasons[0])` の先頭80文字（Python の文字数）
  - 今の attempt を n として n+1 ≦ `HARNESS_MAX_ATTEMPTS` なら：review→doing attempt=n+1 にし（`verifier=` はフェーズ2の規則どおり付く）、計画票と log をコミット（verdict はコミットに含めない。フェーズ2と同じ）した後で worktree を破棄する（T-01 の破棄の処理：`git worktree remove --force` → `git branch -D`）。終了コード3。標準出力は `<計画ID>/<id>: review→doing attempt=<n+1> <補足>。worktree を破棄した`
  - 上限（n+1 が上限を超える）なら：review→blocked attempt=n にし、question は `clean_text("／".join(reasons))` の先頭200文字、log の補足は上と同じ80文字。計画票と log をコミットし、worktree は残す。終了コード4。標準出力は `<計画ID>/<id>: review→blocked attempt=<n> <question>。worktree を残した`
  - 80文字・200文字は `clean_text` を通した後の文字列を切る（フィクスチャの `expect_note`・`expect_question` と同じ規則）
- blocked（creator の blocked の報告）：
  - 呼び出し：`blocked --question-file <パス>`（または `--question <文>`）`--worktree <パス> --branch <ブランチ> --plan-head <sha>`。`--plan-head` は必須（無ければ終了コード2）。question が無ければフェーズ2どおり終了コード1
  - 今の status が doing の時だけ行う（doing→blocked）。review に `--worktree` 付きの blocked を渡したら終了コード1（verifier のハングの review→blocked はフェーズ2の呼び出しのまま）
  - 収集コミット・新規コミットの判定・差分ゲートはしない。worktree の中身には触れない
  - log に再開情報の記録行（T-01 と同じ形・同じ日時）と `doing→blocked attempt=<n>` の行（`creator=` はフェーズ2の規則どおり。補足は `--note` があればその値だけ）をこの順に書き、計画票と log をコミットする。worktree は残す。終了コード4。標準出力は `<計画ID>/<id>: doing→blocked attempt=<n> <question>。worktree を残した`
- 検査の順・worktree の検証・状態のコミットの後の破棄の失敗の扱い（警告を出して終了コードはそのまま）は T-01・T-02 と同じ
- 先頭の docstring に doing・blocked の動きを書き足し、4つのサブコマンドと終了コード 0〜4 がそろった形にする
- `scripts/smoke.sh`・`docs/vault-spec.md`・`scripts/diff_gate.py`・`scripts/discard_worktree.sh`・`.claude/skills/run/SKILL.md`・`.claude/hooks/` は変えない。フィクスチャ `try.sh` は変えない
