# T-01 settings.json から sandbox と6つの deny を外し、smoke の deny のケースを合わせる

## 目的
このリポジトリの `.claude/settings.json` からサンドボックスの設定と、守る対象から外れた deny を外す（D-015 フェーズ1）。smoke の deny のケースを新しい設定に合わせる。

## 入力
- `vault/designs/D-015.md` の「決定事項」の表と「フェーズ1 サンドボックスと不要な deny を外す」の節
- `.claude/settings.json`
- `scripts/smoke.sh` の `(approve-settings)` のケース（`for ent in 'Bash(gh pr merge*)' 'Bash(glab mr merge*)' 'Bash(claude *)'; do` の行）と、その直後の `== install.sh の settings.json 扱い ==`

## 成果物
- `.claude/settings.json`（主な成果物）
- `scripts/smoke.sh`（付随。`(approve-settings)` のケースの直しと `(deny-1)`・`(deny-2)` のケースの追加だけ）

## 受け入れ基準
- `.claude/settings.json` に `sandbox` キーが無く、ほかのトップレベルのキー・`permissions.allow` の件数・`hooks` のイベントは変わらない。確認：`python3 -c "import json;d=json.load(open('.claude/settings.json'));print(sorted(d), len(d['permissions']['allow']), sorted(d['hooks']))"` の出力が `['hooks', 'permissions', 'worktree'] 46 ['PostToolUse', 'PreToolUse', 'Stop']`
- `permissions.deny` が残す12項目だけで、元の並び順のまま。確認：`python3 -c "import json;print(json.load(open('.claude/settings.json'))['permissions']['deny'])"` の出力が `['Bash(rm -rf *)', 'Bash(rm -fr *)', 'Bash(rm -r *)', 'Bash(rm -Rf *)', 'Bash(sudo *)', 'Bash(git push --force*)', 'Bash(git push -f*)', 'Bash(git push * --force*)', 'Bash(git push * -f*)', 'Bash(git push --force-with-lease*)', 'Bash(gh pr merge*)', 'Bash(glab mr merge*)']`
- smoke の `(approve-settings)` のケースが `Bash(gh pr merge*)`・`Bash(glab mr merge*)` の2つだけになり、どちらも ok になる。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (approve-settings)'` の出力が `2`
- smoke に `(deny-1)`（外した6項目がそれぞれ deny に無い）と `(deny-2)`（本体の settings.json に `sandbox` が無い）のケースがあり、7件とも ok になる。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (deny-'` の出力が `7`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- `.claude/settings.json` は `sandbox` キーを丸ごと消す（`excludedCommands`・`filesystem`・`network` を含む）。`worktree`・`permissions.allow`・`hooks` は1文字も変えない。`permissions.deny` は6項目（`Bash(git reset --hard*)`・`Bash(git clean *)`・`Bash(git branch -D *)`・`Bash(curl *)`・`Bash(wget *)`・`Bash(claude *)`）を消すだけで、残りの並び順は変えない。インデントは今のファイルと同じ2スペースの JSON
- `permissions` の最後の要素の後ろ（`"deny": [...]` の閉じ）と `hooks` の閉じのカンマに注意し、`json.load` で読めること
- smoke.sh の `(approve-settings)` は、`for ent in ...` の並びから `'Bash(claude *)'` を消すだけ（ケース名・判定の書き方は変えない）
- smoke.sh に足すケースは `(approve-settings)` の for 文の直後に置き、今と同じ `expect_eq` と `jq` の書き方にする。名前は次のとおり
  - `(deny-1) deny に <ent> が無い`：`'Bash(git reset --hard*)' 'Bash(git clean *)' 'Bash(git branch -D *)' 'Bash(curl *)' 'Bash(wget *)' 'Bash(claude *)'` の6つを for 文で回し、期待値は `false`（`jq --arg e "$ent" '.permissions.deny | index($e) != null' "$ROOT/.claude/settings.json"`）
  - `(deny-2) ハーネス本体の settings.json に sandbox が無い`：期待値 `false`、実際の値は `jq 'has("sandbox")' "$ROOT/.claude/settings.json"`
- smoke の `== sandbox を導入先に入れない ==`（`(sb-1)`〜`(sb-6)`）は、フィクスチャに `sandbox` を足して見るケースで本体の `sandbox` に依存しないので変えない
- `scripts/merge_settings_json.py`・`scripts/transition.py`・`scripts/discard_worktree.sh`・`scripts/vcs_finish.sh`・`.claude/hooks/` は変えない（D-015 フェーズ1 の決定済み。成果物にも宣言していない）
- `.claude/settings.json` の編集が拒否された時（サンドボックスの保護パスなど）は、別の手段で書き換えず、拒否の理由を question に書いて `blocked` にする
- 文書（`docs/`・`.claude/skills/`）の記述は T-02〜T-05 が直すので、このタスクでは変えない
