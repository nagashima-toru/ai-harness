# T-01 stop_gate.py の記録行の無い doing のブロック理由に完了通知待ちの案内を足し smoke で確かめる

## 目的
バックグラウンドで起動した creator の完了通知を待つためにオーケストレーターがターンを終えた時、stop_gate.py のブロック理由が「そのままターンを終えて通知を待てばよい」と案内するようにする。判定（block/allow）は1つも変えない。

## 入力
- `vault/designs/D-20261010-async-agent-wait.md`（決定事項・フェーズ1の決定済み）
- `.claude/hooks/stop_gate.py`（verdict が無い・古い時の `block(...)` の分岐）
- `docs/vault-spec.md` 7節（記録行 `- <日時> <id> worktree path=...` の書式の正本）・9節
- `scripts/smoke.sh`（`== stop_gate.py ==` の節、`make_plan_task`・`run_stop`・`expect`・`expect_eq` の各ヘルパー）

## 成果物
- `.claude/hooks/stop_gate.py`（主な成果物。1ファイル）
- `scripts/smoke.sh`（確かめるケースを3つ足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | grep -c '^smoke: pass=[0-9]* fail=0$'` の出力が `1`（smoke 全体が失敗0で終わる）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (async-wait-[123]) '` の出力が `3`（決定済みの3ケースがすべて ok）
- (async-wait-1) は、記録行の無い doing・verdict 無しで stop_gate.py が block を返し、reason に「完了通知」を含むことを確かめている（`grep -n 'async-wait-1' scripts/smoke.sh` で該当行を読み、`expect` の第2引数が `block`、部分文字列が `完了通知` であることを目視で確認する）
- (async-wait-2)・(async-wait-3) は、記録行のある doing・verdict 無し、review・verdict 無しのそれぞれで block を返し、reason に「verdict が無い」を含み「完了通知」を含まないことを確かめている（`grep -n 'async-wait-[23]' scripts/smoke.sh` で該当行を読んで確認する）
- 既存の smoke のケースを消したり期待値を書き換えたりしていない：`git diff --numstat work/p-20261010-async-agent-wait...HEAD -- scripts/smoke.sh` の出力の2列目（削除行数）が `0`

## 決定済み
- 判定（block/allow）・判定の順は変えない。変えるのは、doing/review の行の「verdict が無い、または task/attempt が不一致」の分岐（`if verdict is None or stale:`）で、status が `doing` かつ記録行が無い時の reason の文面だけ。それ以外（review の時・記録行のある doing の時）の reason は今の文面を1文字も変えない
- 記録行の有無：`<root>/vault/log/<計画ID>.md` に、正規表現 `^- \S+ \S+ <id> worktree path=`（`<id>` は `re.escape` したタスク ID）に当たる行が1行でもあれば「記録行がある」。ファイルが無い・読めない（例外）時は「記録行が無い」として扱う。前回の attempt の記録行が残っていれば「記録行がある」扱いになり今の文面が出るが、それでよい（設計文書の定義どおり。判定には影響しない）
- 判定の関数は `stop_gate.py` の中に置く（`_hooklib.py` は変えない。成果物に含めない）
- 記録行の無い doing の reason は次の文面にする（`{why}` は今の「verdict が無い」または「verdict が古い（…）」をそのまま使う）：`[stop_gate] {task_key} は doing ですが {why}。まだ creator の記録行がありません（vault/log/{plan_id}.md）。creator の完了通知を待っている場合は、そのままターンを終えて通知を待ってください（2回目の停止は許可されます）。待っていないなら creator・verifier サブエージェントを実行して vault/verdicts/{task_key}.json を書くこと（attempt={attempt}）。`。「verdict が無い」「verifier」「完了通知」の3語が入ることが必須（既存の smoke のケース「doing あり・verdict なし」（部分文字列 `verifier`）・(f2)・(hooklib-rules)（部分文字列 `verdict が無い`）がこの分岐を通るため、これらを書き換えずに通す）
- 冒頭の docstring に、記録行の無い doing の時に文面が変わること（判定は同じ）を1〜2行で足してよい
- smoke に足すケースの名前は `(async-wait-1)`・`(async-wait-2)`・`(async-wait-3)` で始める（`expect`・`expect_eq` の第1引数の先頭）。それぞれ1行の ok/NG になるようにする
  - (async-wait-1)：`make_plan_task` で doing・attempt=1 の行、verdict 無し、`$TMP/vault/log/P-TEST.md` 無し → `expect ... block "$(run_stop)" "完了通知"`
  - (async-wait-2)：doing・attempt=1、verdict 無し、`$TMP/vault/log/P-TEST.md` に `- 2026-10-10 10:00 T-0001 worktree path=/tmp/wt branch=b plan_head=0000000000000000000000000000000000000000` の1行 → block で reason に `verdict が無い` を含み、`完了通知` を含まない
  - (async-wait-3)：review・attempt=1、verdict 無し、log 無し → block で reason に `verdict が無い` を含み、`完了通知` を含まない
  - 「含まない」の確認は `expect` では書けないので、`expect_eq` で `grep -c '完了通知'` が `0` になることを見るなど、block であることと合わせて1ケース1行に収まる形にする。`expect_eq` は smoke.sh の720行付近で定義されているので、ケースはその定義より後（例：ファイル末尾の集計の直前）に置くか、`expect` と同じ形の小さなヘルパーを足す
  - 置いた log・verdict はケースの後で `rm -f` で消し、後続のケースに影響させない（smoke 内の一時ディレクトリの中だけを触る）
- 既存のケース・既存の行は消さない・書き換えない（追加だけ）
- `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` は使わない・書かない（設計文書の決定事項）
- 無人実行（`scripts/run_unattended.py`・`HARNESS_STRICT_STOP=1`）の扱いは変えない
