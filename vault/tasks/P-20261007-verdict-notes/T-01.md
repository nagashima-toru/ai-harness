# T-01 verdict の reasons を一覧にする scripts/verdict_notes.py を新設する

## 目的
1つの計画の verdict（`vault/verdicts/<計画ID>/*.json`）の `reasons` を `<id>: <reason>` の形で1行ずつ標準出力に出すスクリプトを新設し、verifier の指摘（基準が緩い・判定不能など）を人の目に届く形にする。smoke にケースを足す。

## 入力
- `vault/designs/D-013.md` の「フェーズ2 verifier の指摘を見えるようにする」（受け入れ基準の候補・決定済み）
- `docs/vault-spec.md` 6節（verdict.json の形式と `reasons` の使われ方）
- `scripts/pr_body.py`（`repo_root()` の書き方・使い方の出し方の参考。読むだけ）
- `scripts/smoke.sh`（`== model_stats.py ==` の節・`expect_eq` の使い方）

## 成果物
- `scripts/verdict_notes.py`（主な成果物。新規）
- `scripts/smoke.sh`（`== verdict_notes.py ==` の節の追加）

## 受け入れ基準
- smoke に `(vn-1)`〜`(vn-6)` の6ケースがあり、すべて通る：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(vn-[1-6]\)'` の出力が `6`
- 実データで、指摘がある計画は `<id>: <reason>` の行を出す：`python3 scripts/verdict_notes.py P-20261005-bash-write-unify` の出力が1行だけで、`T-05: 変更ファイル検査：` で始まる
- 実データで、指摘が無い計画は「指摘なし」の1行だけを出す：`python3 scripts/verdict_notes.py P-20261007-stop-gate-scope` の出力が `指摘なし` の1行だけ
- `--dir` で読み込み先を変えられる：`python3 scripts/verdict_notes.py P-20261004-hooklib-extract --dir vault/verdicts/P-20261005-bash-write-unify` の出力が1行だけで、`T-05: ` で始まる（計画 ID ではなく `--dir` のディレクトリを読む）
- 先頭の docstring に使い方（`python3 scripts/verdict_notes.py <計画ID> [--dir <ディレクトリ>]`）・出力の形・終了コードが書かれている（Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 呼び出しの形：`python3 scripts/verdict_notes.py <計画ID> [--dir <ディレクトリ>]`。標準ライブラリだけで書く（`argparse` を使ってよい）。ファイルには書き込まない
- 読み込み先：既定は `<リポジトリのルート>/vault/verdicts/<計画ID>/` の `*.json`。リポジトリのルートは `scripts/pr_body.py` の `repo_root()` と同じ（カレントディレクトリの `git rev-parse --show-toplevel`、失敗したらカレントディレクトリ）。`--dir` を渡した時は、そのディレクトリ（`<id>.json` を直接持つディレクトリ。例：`vault/archive/2026-10/verdicts/<計画ID>`）の `*.json` を読み、計画 ID は読み込み先の決定には使わない。相対パスはカレントディレクトリ基準
- id はファイル名から `.json` を除いたもの。ファイル名の順（`sorted`）に処理する。verdict の `task` の値は見ない
- 出力：`reasons` が空でない verdict について、要素ごとに `<id>: <reason>` を1行。1つの verdict に要素が2つあれば2行。`reasons` は言い換えず、分類もしない（D-013 の決定済み）。要素の中の改行（`\r`・`\n`）は空白1つに置き換えて1行に収める。要素が文字列でなければ `str()` にする
- 1行も出すものが無ければ `指摘なし` の1行だけを出す
- JSON として読めない verdict、`reasons` が無い・配列でない verdict は読み飛ばし、標準エラーに `verdict_notes.py: 読み飛ばした: <パス>` を1行出す（終了コードは0のまま）
- 終了コード：0 出力した（「指摘なし」を含む）／1 読み込み先のディレクトリが無い（標準エラーに理由）／2 引数の誤り（計画 ID が無いなど）
- result（PASS/FAIL）や attempt は出さない。verdict は最新のみ（上書き）なので「最後の verdict」の reasons になる
- smoke のケース（`== vcs_finish.sh ==` の節の前、`== model_stats.py ==` の節の後に `echo "== verdict_notes.py =="` の節を置く。名前は `(vn-N)` で始め、各ケース `expect_eq` 1回）：
  - (vn-1)：一時ディレクトリに `vault/verdicts/P-VN/` を作り、`T-01.json`（reasons 1要素）・`T-02.json`（reasons 空）・`T-03.json`（reasons 2要素。片方に改行を含む）を置いて、そのディレクトリを cwd にして既定の読み込み先で実行 → 出力が期待どおりの3行と一致（T-01 の1行、T-03 の2行。改行は空白になる）
  - (vn-2)：reasons が全部空の計画 → 出力が `指摘なし` だけ
  - (vn-3)：`--dir` に別のディレクトリを渡すと、計画 ID の既定のディレクトリではなくそちらを読む
  - (vn-4)：JSON として読めないファイルが混じっていても終了コード0で、ほかの verdict の行は出る
  - (vn-5)：読み込み先のディレクトリが無い → 終了コード1
  - (vn-6)：引数なし → 終了コード2
- smoke の一時ディレクトリは既存の節と同じく `mktemp -d` で作り、節の最後に既存と同じ形で片付けてよい（smoke の中の後片付けは既存どおり）。一時ディレクトリは git リポジトリにしなくてよい（`repo_root()` がカレントディレクトリに落ちる）
- 基準2〜4の実データ（`vault/verdicts/P-20261005-bash-write-unify/T-05.json` など）は読むだけで変えない。人が `archive_plans.sh --apply` でこれらを移していた場合は、基準2・3は `--dir vault/archive/2026-10/verdicts/<計画ID>` を付けて確かめてよい
- `scripts/install.sh` は scripts/ 直下の `*.py` を自動で配るので変えない
- `docs/`・`.claude/skills/` は変えない（T-04・T-05 で行う）
