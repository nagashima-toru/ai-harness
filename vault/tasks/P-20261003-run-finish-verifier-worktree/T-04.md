# T-04 verifier エージェント定義の手順1・11を絶対パス方式に書き換える

## 目的
`.claude/agents/verifier.md` の手順1（`EnterWorktree` で worktree に入る）と手順11（`ExitWorktree` で戻る）を、verifier の tools で実際にできる「worktree に入らず、絶対パスと `git -C` で検証し、verdict はメインリポジトリ側の絶対パスに書く」形に書き換える（issue #89 の2点目）。verifier の tools は増やさない。

## 入力
- `.claude/agents/verifier.md`（4行目の tools、23行目＝手順1、33行目＝手順11）
- `.claude/skills/run/SKILL.md` 手順5（verifier へのプロンプトに「対象 worktree: <パス>」が付く）

## 成果物
- `.claude/agents/verifier.md`

## 受け入れ基準
- `EnterWorktree`/`ExitWorktree` の語が手順1の1行だけに残り、その行が「使わない」と書いている。確認：`grep -nE 'EnterWorktree|ExitWorktree' .claude/agents/verifier.md` の出力がちょうど1行で、その行が `1. プロンプトに` で始まり、`` `EnterWorktree`・`ExitWorktree` は使わない``・`git -C <path>`・`cd <path>` の3つを含む
- 手順11が、verdict をメインリポジトリ側の絶対パスに書く手順になっている。確認：`grep -n -F '$CLAUDE_PROJECT_DIR/vault/verdicts/<計画ID>/<id>.json' .claude/agents/verifier.md` の出力がちょうど1行で、その行が `11. ` で始まる
- tools は変わっていない。確認：`grep -c '^tools: Read, Grep, Glob, Bash, Write$' .claude/agents/verifier.md` が `1`
- 変えたのは手順1・手順11の2行だけ。確認：`git diff --numstat main -- .claude/agents/verifier.md` の出力が `2	2	.claude/agents/verifier.md`

## 決定済み
- 方針（人の代理の設計判断。変えない）：verifier に `EnterWorktree` を持たせない（権限を増やさない）。frontmatter（tools・model など）は変えない
- 23行目（手順1）を、まるごと次の1行に置き換える：
  `` 1. プロンプトに「対象 worktree: `<path>`」が含まれる場合、creator の成果物はその worktree にある。`EnterWorktree`・`ExitWorktree` は使わない（tools に無い）。git は `git -C <path> ...`、ファイルは `<path>/` から始まる絶対パスで読み、作業ディレクトリが要るコマンド（スクリプトの実行など）は同じ Bash 呼び出しの中で `cd <path>` してから実行する。受け入れ基準の確認コマンドにある相対パスは `<path>` からの相対パスとして読む。含まれない場合はメインリポジトリでそのまま検証する ``
- 33行目（手順11）を、まるごと次の1行に置き換える：
  `` 11. `vault/verdicts/` はメインリポジトリ側の絶対パス（`$CLAUDE_PROJECT_DIR/vault/verdicts/<計画ID>/<id>.json`）に書く。対象 worktree のパスの下には書かない（書くとメインリポジトリ側から見えなくなる。issue #61） ``
- 手順の番号（1〜12）と、他の手順の文（手順10の `git diff --name-only`・`git status --porcelain` を含む）は変えない。worktree に向けて実行することは、手順1の「git は `git -C <path> ...`」で足りる
- この文は T-02（run スキル手順5の2）・T-03（verifier ルール17行目の提案）と同じ趣旨にそろえてある
- `.claude/agents/` への creator の書き込みが auto mode などの権限判定で拒否された場合、別の書き方での回避はしない。blocked にし、拒否のメッセージを質問文に書く
- コミットは不要（受け入れ基準に無い）
