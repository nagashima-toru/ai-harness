# T-0009 verifier にルール読み込みと参照時の判定手順を追加する

## 目的
verifier が `scripts/rules.sh verifier` の出力するルールファイルを読み、受け入れ基準がルールを参照する行はそれを根拠に判定し、note に参照したルールファイルのパスを書けるようにする。ルールを参照していない基準をルールで落とすことは明示的に禁止する。

## 入力
- `.claude/agents/verifier.md`（編集対象本体）
- `docs/vault-spec.md`（「## 7. verdict.json」節、特に note の説明部分。追記対象）
- `docs/roadmap-rules-extension.md` の「## ④ verifier にルールを渡す」節（設計・受け入れ基準の候補・決定済みの参考）
- `docs/vault-spec.md` の「## 12. ルール」節（`vault/rules/` の仕様・振り分け・ルールと受け入れ基準の関係の正本）
- `scripts/rules.sh`（`verifier` を渡した時の列挙順・挙動の確認用）

## 成果物

## 決定済み
- 対象は `.claude/agents/verifier.md` と `docs/vault-spec.md` の2ファイルのみ。run-queue・planner・フック・install.sh・README.md は変更しない
- 「読むもの（これだけ）」への追加は、既存の4項目（todo.md／タスク票／成果物／確認コマンド結果）の後に5番目の項目として追加する。書き方の例：「`bash scripts/rules.sh verifier` が列挙するルールファイル（無ければ読まない）」。読み方は Bash で `cat` せず、列挙されたパスを Read で読む（`docs/roadmap-rules-extension.md` の④の決定済みに合わせる）
- `creator/` のルールは verifier からは見えない（`scripts/rules.sh verifier` はそもそも `creator/` を列挙しないため、追加の除外処理は不要。既存スクリプトの仕様のまま）
- 「## 手順」への追加位置は、既存の手順5（note は必須）の近く（5の直後に新項目として挿入し、以降の番号を1つずつ繰り下げる、または5の文中に追記する、のどちらでもよい。番号のずれよりも内容の正確さを優先する）
- 「## 禁止」への追加位置は既存3項目（`vault/verdicts/` 以外への書き込み／成果物の修正等／基準に無いことを理由にした FAIL）の末尾に4項目目として追加する
- `docs/vault-spec.md` への追記位置は「## 7. verdict.json」の note の説明（現在の箇条書き、書式の例や代替確認方法の例がある付近）の末尾に1〜2行足す。新しい節は作らない
- 受け入れ基準の grep 対象文言（`ルールファイルのパス` / `参照していない` / `ルールを根拠にした場合`）はこのタスクで実際に書く文言に厳密に合わせること。言い回しを変える場合は grep パターンも合わせて成果物の中に同じ語が含まれるように書く（例のまま使ってよい）
- `docs/roadmap-rules-extension.md` は参考資料であり編集対象ではない（変更不要、変更しても可否には影響しない）
