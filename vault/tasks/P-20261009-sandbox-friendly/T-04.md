## 決定済み
- 12節の「サンドボックス」の小節の `allowUnsandboxedCommands` の項目は「`false`。サンドボックスの外で実行し直す逃げ道は無い。」までにし、「`excludedCommands` は設定していない」の文を消す
- その次に、`excludedCommands` の項目を1つ足す。書き出しは受け入れ基準2行目の文字列のとおり（`- \`excludedCommands\`：` で始め、4つのパターンをバッククォートで囲んで `・` でつなぎ、「の4つ」と続ける）。続けて次を書く
  - PR の作成（`git push -u` の `.git/config` への書き込みと、`gh` の TLS の証明書の検証）と worktree の後始末（`.git/worktrees/` への書き込み）はサンドボックスの中では通らないので、この2つのスクリプトだけをサンドボックスの外で実行する
  - `allowUnsandboxedCommands: false` のままでも、プロジェクトの設定の `excludedCommands` は効く。無視されるのは managed の設定か `--settings` で `allowUnsandboxedCommands: false` を設定した時など（Claude Code 2.1.294 の設定スキーマの説明で確認。公式ドキュメントでは未確認）
  - 除外したコマンドも permissions の判定とフック（`agent_write_guard.py`）は受ける
  - 既知の弱点として、受け入れ基準4行目の文字列（「excludedCommands はコマンドの文字列で照合するので、worktree の中の同じ名前のスクリプトもサンドボックスの外で動く」）をこのとおり書き、続けて「creator が worktree の `scripts/vcs_finish.sh` を書き換えて実行すると、その中身はサンドボックスの外で動く。サンドボックスを入れる前と同じ水準で、塞ぐかは別の計画で決める」の旨を書く
- 同じ小節に、一時ファイルの項目を1つ足す（書き出しは `- 一時ファイル：`）。中身は次のとおり
  - サンドボックスの中の Bash が書けるのは、リポジトリのほかは `$TMPDIR`（Claude Code が設定する）と `/tmp/claude/` の下だけ
  - macOS の `mktemp` はテンプレートを渡さないと `$TMPDIR` を使わずに失敗するので、スクリプトは `mktemp [-d] "${TMPDIR:-/tmp}/<名前>.XXXXXX"` の形（ディレクトリの時は `-d` を付ける）で作る。受け入れ基準5行目の1つ目の文字列（`mktemp [-d] "${TMPDIR:-/tmp}/<名前>.XXXXXX"`）は12節のこの項目に1回だけ書く
  - `scripts/smoke.sh`・`scripts/install.sh`・`scripts/uninstall.sh`・`scripts/archive_plans.sh` はこの形で一時ディレクトリ・一時ファイルを作り、作れない時は `<スクリプト名>: 一時ディレクトリ（smoke.sh）／一時ファイル（ほかの3つ）を作れません（TMPDIR=<値>）。中断します` を出して終了コード2で中断する（空の変数のまま git やファイルを操作しないため。uninstall.sh はファイルを消す前に中断する）
  - そのため smoke はサンドボックスの中でも通る。受け入れ基準5行目の2つ目・3つ目の文字列を使って「smoke はサンドボックスの中でも通り、人がサンドボックスの外で流す必要は無い。ただし全件が通ることは未確認で、計画（P-20261009-sandbox-friendly）の run の後に人が1回確かめる」の旨を書く（計画作成時に、4つのスクリプトの `mktemp` を差し替えたリポジトリの複製でサンドボックスの中の smoke が `fail=0` になったことは確かめてあるが、計画ブランチの実ファイルでは確かめていないため）。2つの文字列はそれぞれ1回だけ書く
  - エージェントが作った一時ファイルは消さず、人にも消させない（`rm -rf` は permissions で拒否される。OS の掃除に任せる）。フィクスチャの置き場は `/tmp/claude/<計画ID>-<タスクID>/` の固定パスにする
- 2節の done（review→done）の項目の「`git worktree remove --force` と `git branch -d` で後始末（失敗は警告だけで終了コード 0）」の後に、「サンドボックスの中で後始末に失敗した時は、run が `bash scripts/discard_worktree.sh` で消す（`.claude/skills/run/SKILL.md` の「worktree の後始末（サンドボックス）」、12節の「サンドボックス」）」の旨の1文を足す。受け入れ基準6行目の文字列（`run が \`bash scripts/discard_worktree.sh\` で消す`）はこの1か所だけに書く
- 見出し（`## `・`### `）は足さない・消さない（受け入れ基準7行目）。項目は既存の小節の箇条書きに足す
- 「残る弱点」（343行目付近）・「`agent_write_guard.py` の Bash の解析は削らず、当面残す」の項目は変えない
- `.claude/settings.json`・`.claude/skills/`・`scripts/`・`docs/runbook.md`（T-05）は変えない
- 文書だけの変更なので、確認は受け入れ基準のコマンドで行う。`bash scripts/smoke.sh` は実行しない
