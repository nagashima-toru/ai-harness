# T-02 scripts/model_stats.py を新規作成する

## 目的
log ファイル群から、creator のモデル別に対象タスク数・1回目 PASS 率・平均 attempt・blocked 率を集計して標準出力に出す。

## 入力
- `docs/vault-spec.md` 7節（T-01 で確定した書式。集計の定義もここ）
- `vault/designs/D-010.md` のフェーズ8（決定済み）
- `vault/log/*.md`（既存の log。形式の確認用）
- 既存の Python スクリプト（`scripts/run_unattended.py` など。標準ライブラリのみ・`python3` で動く書き方に合わせる）

## 成果物
- `scripts/model_stats.py`（新規1ファイル。標準ライブラリのみ）

## 受け入れ基準
- 引数に log ファイルのパスを渡すとそれだけを集計し、引数が無ければ `vault/log/*.md` を対象にする（`vault/archive/` 配下は既定の対象に含めない）。`python3 scripts/model_stats.py` を現在の `vault/log/*.md` に対して実行すると終了コード0で、1行目が `model	tasks	first_pass_rate	avg_attempt	blocked_rate`（タブ区切り）になる
- 一時ディレクトリに作ったフィクスチャ log（sonnet で1回目 PASS 1件、haiku で2回目 PASS 1件と blocked 1件）を引数で渡すと、`sonnet` 行が `sonnet	1	1.00	1.00	0.00` になり、`haiku` 行が tasks=2・first_pass_rate=0.00・blocked_rate=0.50 で、avg_attempt が最後の遷移行の attempt の平均（フィクスチャの値から定義どおり計算）になる（率・平均は小数2桁、タブ区切り）
- `creator=` の無い既存形式の遷移行だけで終わるタスクは `unknown` として集計され、エラーにならない
- 遷移行（`→` を含む行）以外の行（`worktree path=... plan_head=...` やハングの補足行）が混じっていても結果が変わらない
- `scripts/model_stats.py` 以外のファイルが変わっていない（`git status --porcelain` の出力が `scripts/model_stats.py` と、計画票・タスク票・log・verdict 以外を含まない）

## 決定済み
- 集計の定義：
  - 対象タスク：その計画・id の最後の遷移行が `→done` または `→blocked` のもの（`計画ID/id` で一意にする。計画 ID は log のファイル名（拡張子を除く）から取る）
  - 集計キー：そのタスクの最後の `doing→review` 行の `creator=` の値。無ければ `unknown`
  - 1回目 PASS 率：`review→done attempt=1` で終わった件数 ÷ 対象タスク数
  - 平均 attempt：最後の遷移行の `attempt=` の平均
  - blocked 率：`→blocked` で終わった件数 ÷ 対象タスク数
- 遷移行（`<状態>→<状態>` を含む行）以外の行は無視する。F6 の記録行（`worktree path=...`）やハングの補足行も含む
- 出力はタブ区切りで、1行目を見出し（`model	tasks	first_pass_rate	avg_attempt	blocked_rate`）とする。率・平均は小数2桁
- `vault/archive/` 配下の log は、引数で明示的に渡せば集計できる。既定の対象には含めない
- verifier のモデル別の集計は今回は出さない（記録だけしておく）
- 行の日時・タスク ID の位置は `- YYYY-MM-DD HH:MM <id> <遷移> ...`。タスク ID の位置が `-` の行（承認など計画単位の行）は集計に使わない
- 対象タスクが0件でも見出し行だけを出して終了コード0で終わる。モデルの行の順序は model 名の昇順
- smoke.sh への追加は T-04 で行う。このタスクでは smoke.sh に触らない
