# T-05 /plan unblock の手順に amend_task.py・基準の文字列での todo 票の探索・--fresh を入れる

## 目的
`/plan unblock` の手順（`.claude/skills/plan/SKILL.md` の「B. blocked を解除する」）で、回答が成果物の追加や受け入れ基準の差し替えを含む時に `scripts/amend_task.py` を使う正式な手順を定め、回答が他タスクにも効く時の追記先を基準の文字列で探す手順にする（Issue #189）。あわせて、再着手で worktree を引き継ぐか作り直すかを人が unblock の時に選べるようにする（Issue #190。既定は引き継ぎ）。

## 入力
- `.claude/skills/plan/SKILL.md`（「B. blocked を解除する」と frontmatter）
- `scripts/amend_task.py`（T-01 の成果物。呼び出しの形・拒否の条件・log の行。先頭の docstring と `--help` を読む）
- `scripts/transition.py`（T-02 で足した `--resume-worktree` の説明。先頭の docstring を読む）
- `scripts/discard_worktree.sh`（worktree の破棄）
- `docs/vault-spec.md` 7節（blocked の解除の log の行・記録行）

## 成果物
- `.claude/skills/plan/SKILL.md`（1ファイル）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- `grep -c '^argument-hint: .ゴール . unblock .計画ID. .id. .--fresh. .回答..$' .claude/skills/plan/SKILL.md` の出力が `1`
- `grep -c 'python3 scripts/amend_task.py .計画ID. .id. ' .claude/skills/plan/SKILL.md` の出力が1以上（B 節に呼び出しの形がある）
- `grep -c 'grep -l -F -e ' .claude/skills/plan/SKILL.md` の出力が1以上（他の todo 票を基準の文字列で探すコマンドがある）
- `grep -c 'discard_worktree.sh' .claude/skills/plan/SKILL.md` の出力が1以上（`--fresh` の時の破棄）
- `grep -rn '大きな書き換えは planner を呼ぶ' .claude docs README.md` の出力が空（受け入れ基準を直す時に planner へ回す古い案内が残っていない）

## 決定済み
- コマンドの形を `/plan unblock <計画ID> <id> [--fresh] [回答]` にする。frontmatter の行はちょうど `argument-hint: [ゴール | unblock <計画ID> <id> [--fresh] [回答]]` にする。`description` と B-1 の案内の文のコマンドの形も同じにそろえる。`--fresh` は `<id>` の直後にだけ書ける（回答の中の `--fresh` の文字列は回答の一部として扱う）
- 既定（`--fresh` 無し）は引き継ぎ：unblock では worktree に触れない。再着手の時に `/run` が `scripts/transition.py` の `--resume-worktree` で、log のその id の最後の記録行の worktree を引き継ぐ（残っていなければ `/run` が新しい worktree で作り直す）。B の手順の中で、この既定と `--fresh` の違いを1〜2文で説明する
- `--fresh` の時：status を todo に戻す前に、`vault/log/<計画ID>.md` のその id の最後の記録行のパスとブランチ名を取り、そのパスが `git worktree list` にあれば `bash scripts/discard_worktree.sh <パス> <ブランチ名>` で破棄する（記録行が無い・パスが無い時は何もしない）。log の解除の行は `- <日時> <id> blocked→todo 人の指示: /plan unblock <計画ID> <id> --fresh` にする（`--fresh` 無しの時の行は今のまま）
- 回答が成果物の追加（宣言されていないファイルを変えてよい）や受け入れ基準の変更を含む時は、タスク票の「成果物」「受け入れ基準」を Edit で直さず、`python3 scripts/amend_task.py <計画ID> <id> [--add-deliverable <パス>]... [--replace-criterion <番号> <文>]...` で直す（この形を B 節にそのまま書く）。amend_task.py はタスク票と log をコミットするので、この呼び出しは「決定済み」への追記より前に行う。受け入れ基準と食い違う回答は、決定済みに読み替えの注記を書いて済ませず、`--replace-criterion` で基準そのものを差し替える（verifier は基準を判定するので、注記と基準が食い違うと判定不能になる。Issue #189）。基準の行の追加・削除が要る時（行数が変わる時）や、成果物の主を変えるほどの書き換えの時は、amend_task.py では行わず、人にその旨を伝えて止まる（planner の呼び直しは案内しない。今の「大きな書き換えは planner を呼ぶよう案内する」の文は削る）
- 回答が解除する `<id>` 以外のタスクにも効く時の追記先の探し方：回答文に書かれたタスク ID に頼らない。blocked の question と回答が関わる受け入れ基準の行（または「決定済み」の前提の行）から、タスク ID を含まない特徴的な部分文字列を選び、`grep -l -F -e '<文字列>' vault/tasks/<計画ID>/` で同じ文字列を持つタスク票を探す（このコマンドの形を B 節に書く）。見つかった票のうち計画票のタスク表で todo の票だけに、同じ回答を「決定済み」に追記し、成果物の追加・基準の差し替えが要るものは同じく amend_task.py で直す（基準の番号はその票で数え直す）。todo 以外の票には追記しない（今の理由の文は残す）
- B の手順の番号の振り直し・文の言い回しは自由。ただし今の B の手順の内容（解除の指示がコマンドで来たかの確認・blocked かの確認・status を todo・attempt を 0・question を空にする・log に1行・名前を指定した `git add` とコミット・報告）は残す。報告（今の B-7）では、引き継ぎか作り直しか（`--fresh` の有無）も伝える
- A 節（計画を作る）と「注意」節は変えない
