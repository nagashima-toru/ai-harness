# T-04 decisions.md に守りを絞った判断を1行足し、vision.md から承認を外す

## 目的
`docs/decisions.md` に D-015 の決定事項の1行目（守るのは3つだけ）を理由付きで1行足し、`docs/vision.md` の「最終決定は人が持つ」から、廃止した計画の承認を外す。

## 入力
- `vault/designs/D-015.md`（冒頭の「決定事項」表の1行目・2行目）
- `docs/decisions.md`（表の書式：`| 日付 | 何を | なぜ |`）
- `docs/vision.md`（原則 9）

## 成果物
- `docs/decisions.md`（主な成果物）
- `docs/vision.md`（付随して変える）

## 受け入れ基準
- `docs/decisions.md` に、守るのは3つだけにした判断の行が1行ある。確認：`grep -c '^| 2026-10-10 | 守るのは次の3つだけにする' docs/decisions.md` が `1`
- その行の「なぜ」の列に理由がある。確認：`grep -c '^| 2026-10-10 | 守るのは.* | .*取り返しがつかない.*PR のレビューと git の履歴' docs/decisions.md` が `1`
- 既存の行を消さず、1行だけ足している。確認：`grep -c '^|' docs/decisions.md` が `28`
- `docs/vision.md` の原則 9 から承認が外れている。確認：`grep -c '^9\. \*\*最終決定は人が持つ\*\*：マージ・blocked の解除。$' docs/vision.md` が `1`、`grep -n '承認' docs/vision.md` が何も出力しない
- `bash scripts/smoke.sh 2>&1 | tail -1` が `fail=0` を含む

## 決定済み
- 足す行は表の末尾（2026-10-04 の行の後）に置き、日付は `2026-10-10`、「何を」の列は `守るのは次の3つだけにする` で始める。続けて3つを書く：(1) `main` とリモート（force push・`main` への直接コミット・エージェントによる PR のマージを拒否）、(2) PASS の無い done を作らない（`transition.py`・`stop_gate.py`・`plan_guard.py` の verdict の検査）、(3) done のタスク票・verdict を書き換えない。末尾に「（D-015）」を付けてよい
- 「なぜ」の列は D-015 の決定事項の1行目の理由を要約する。次の語句をこの順で含めること：`取り返しがつかない`（(1) は取り返しがつかない、または人の関門を飛ばす）、(2)(3) はハーネスの存在理由、`PR のレビューと git の履歴`（それ以外は PR のレビューと git の履歴で見える・戻せる）。人の指示「保護するのは本当に守らないと壊れるところだけでいい」も入れてよい
- 行の中で `|` を使わない（表の列が崩れる）。1行に収める（改行しない）
- 既存の行（2026-09-17 の書き込み先制限・Bash の書き込み判定・`vault/rules/` の改ざん防止の確認など）は、当時の判断の記録なので書き換えない・消さない
- `docs/vision.md` の原則 9 は次の1行にする：`9. **最終決定は人が持つ**：マージ・blocked の解除。` 計画の承認は D-015 フェーズ2 で廃止し、計画の中身は PR で人が見る。vision.md のほかの行は変えない（原則 2「仕組みで強制する」は守る3つに当てはまるので残す）
- 古い語（`/plan approve`・`excludedCommands`・`提案ファイル`・`会話記録で確認`）は書かない
