# T-05 README.md の PR 作成の主語と手段を直す

## 目的
`README.md` の「仕組み」節の69行目（図の中の「全タスク done → status を done にし gh pr create」）と76行目（「エージェントは `gh pr create` までしか行わない」）を、PR はオーケストレーターが `bash scripts/vcs_finish.sh` で作る、という現在の run に合わせて直す。

## 入力
- `README.md` 59〜76行目（「## 仕組み」節の図と直後の段落）
- `.claude/skills/run/SKILL.md` 手順7（`bash scripts/vcs_finish.sh`。ホスティング無しの場合は案内だけを出す）

## 成果物
- `README.md`（69行目と76行目の書き換え）

## 受け入れ基準
- 旧記述が無い（`grep -c 'pr create' README.md` が `0`）
- 図の行が直っている（`grep -n '全タスク done → status を done にし' README.md` の出力行に `vcs_finish.sh` が含まれる）
- 段落が直っている（`grep -n 'までしか行わない' README.md` の出力行に `bash scripts/vcs_finish.sh` が含まれる）
- 変更が2行に限られている（`git diff -U0 main -- README.md` の出力のハンク見出し（`@@` で始まる行）がちょうど2つで、それぞれ `-69`/`+69` と `-76`/`+76` を含む）
- マージは人が行う旨が残っている（`grep -n 'gh pr merge' README.md` がヒットし、76行目であることを確認する）

## 決定済み
- 69行目は図の中の1行なので、行頭の罫線（`│                        │ `）はそのまま残し、本文を「全タスク done → status を done にし vcs_finish.sh で PR」の趣旨に置き換える。図の右端の揃えは気にしなくてよい（この行は右端に罫線が無い）
- 76行目は「エージェントは `gh pr create` までしか行わない」を「エージェント（オーケストレーター）は `bash scripts/vcs_finish.sh` で PR を作るまでしか行わない」の趣旨に置き換える。「人が内容を確認して `gh pr merge` でマージする」と「コンフリクトがあれば計画のブランチ上で人が解決する」は残す
- ホスティング無し（`none`）の場合の案内など、vcs_finish.sh の詳細は README に書き足さない
- 行数を増やさない（基準4の行番号を保つため）。README の他の節は変更しない
- 基準4の `git diff -U0 main` は、このファイルを変更するタスクがこの計画で T-05 だけなので、誤検知は起きない
- smoke.sh はこのタスクの基準に含めない（T-07 で流す）
- このタスクではコミットしない（受け入れ基準にコミットが無いため）
