# T-01 install.sh の scripts/ の複製とマニフェスト記録を固定リスト SCRIPTS_FILES に限り、smoke に (inst-scr) を足す

## 目的
導入済みリポジトリを配布元にしても、配布元が `scripts/` 直下に置いた独自スクリプトが導入先に複製されず、`.claude/harness-manifest.json` にも載らないようにする（Issue #201）。あわせて、ハーネス本体にスクリプトを足した時の固定リストの更新漏れを smoke で検出する。

## 入力
- `scripts/install.sh`（`SCRIPTS_EXCLUDE`・`scripts_list()`（55〜71行目付近）、`CLAUDE_FILES`、`manifest_paths()`、169〜172行目付近の scripts の複製ループ、冒頭4行目のコメント）
- `scripts/smoke.sh`（「== install.sh は配布元の独自ファイルを配らない ==」の節（`(inst-only)`、1270〜1320行目付近）。`expect_eq`・`smoke_tmpdir`・`abort_tmp` の使い方）
- `docs/decisions.md` の最終行（#200 での判断。変数名に `HARNESS_` を付けない理由など）

## 成果物
- `scripts/install.sh`（主な成果物。scripts/ 直下の配布を固定リスト `SCRIPTS_FILES` に限る）
- `scripts/smoke.sh`（`(inst-scr)` のケース7つを足す）

## 受け入れ基準
- `scripts/install.sh` に `SCRIPTS_FILES=` で始まる行がちょうど1行あり（`grep -c '^SCRIPTS_FILES=' scripts/install.sh` が `1`）、検索方式の名残が無い（`grep -c -e 'find scripts' -e SCRIPTS_EXCLUDE -e scripts_list scripts/install.sh` が `0`）
- smoke の `(inst-scr)` のケースが7つすべて ok になる（`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (inst-scr) '` が `7`）
- smoke の `(inst-scr)` に NG が無い（`bash scripts/smoke.sh 2>&1 | grep -c '^  NG   (inst-scr) '` が `0`）
- smoke 全体が失敗0件で終わる（`bash scripts/smoke.sh 2>&1 | grep -c '^smoke: pass=[0-9]* fail=0'` が `1`）
- 計画ブランチとの分岐点からの差分に `scripts/install.sh` と `scripts/smoke.sh` の両方が含まれる（worktree の中で `git diff --merge-base work/p-20261012-install-scripts-fixed-list --name-only` の出力に両方の行がある）

## 決定済み
- 変数名は `SCRIPTS_FILES`（`HARNESS_` を付けない。smoke の envcheck の照合対象外にするため。#200 の `CLAUDE_FILES` と同じ理由）。値はリポジトリ相対パスのスペース区切りで、`CLAUDE_FILES` の定義の直後に置く。値は次の21本をこの順で、そのまま書く：
  `scripts/amend_task.py scripts/current_plan.sh scripts/diff_gate.py scripts/discard_worktree.sh scripts/install.sh scripts/merge_claude_md.py scripts/merge_settings_json.py scripts/model_stats.py scripts/plan_record.py scripts/pr_body.py scripts/purge_plan.sh scripts/rules.sh scripts/run_unattended.py scripts/smoke.sh scripts/transition.py scripts/uninstall.sh scripts/unmerge_claude_md.py scripts/unmerge_settings_json.py scripts/usage_stats.py scripts/vcs_finish.sh scripts/verdict_notes.py`
- `SCRIPTS_EXCLUDE` と `scripts_list()` は削除する。`manifest_paths()` は `for p in $CLAUDE_FILES ... ; do` のループに `$SCRIPTS_FILES` を加える形にし（存在するものだけを出す今の `[ -f "$p" ]` の判定はそのまま）、通常の複製ループは `for rel in $SCRIPTS_FILES; do copy_if_absent ...; done` にする
- `SCRIPTS_FILES` の定義の直前に、「scripts/ 直下で配るハーネス本体のスクリプト。固定で持ち、配布元が独自に置いたスクリプトは配らない（マニフェストにも記録しない）。ハーネス本体にスクリプトを足したらここにも足す（smoke の (inst-scr) 06 が足し忘れを検出する）」という趣旨のコメントを書く
- 冒頭4行目のコメントの scripts の部分は「scripts/ はハーネス本体の固定リスト SCRIPTS_FILES のスクリプトだけ（配布元が独自に置いたスクリプトは配らない）」に書き換える。169行目付近のコメントも同じ趣旨に直す。`scripts/install.sh`・`scripts/smoke.sh` のどこにも「検索方式」・`SCRIPTS_EXCLUDE`・`scripts_list` の語を書かない（smoke の関数名・コメントも含む。T-02 がリポジトリ全体で残っていないことを確かめる）
- 旧版で配布元の独自スクリプトがマニフェストに記録されていた導入先では、`--update` はそのファイルを削除せず、マニフェストから外すだけにする（#200 と同じ。原則8）。これは `manifest_paths()` が固定リストだけを返せば今の実装のまま成り立つので、`--update` の Python 部分は変えない
- `scripts/uninstall.sh` は変えない（マニフェストの `files` だけを見るため）
- smoke のケースは `(inst-only)` の節の直後に新しい節 `echo "== install.sh は配布元の独自スクリプトを配らない =="` として足す。ラベルは `(inst-scr) 01`〜`(inst-scr) 07` の7つで、すべて `expect_eq` で出す。独自スクリプトのフィクスチャは `scripts/biz_tool.sh` と `scripts/biz_tool.py` の2つ（中身は1行でよい）。一時ディレクトリは既存の節と同じく `smoke_tmpdir` で作り、節の最後に既存の節と同じ形で `rm -rf` で消す（smoke の中の後片付けは既存の書き方に合わせてよい）
  - 01：`$ROOT` から A に install し、A に独自スクリプト2つを置き、A の `scripts/install.sh` で B に install → B に独自スクリプトが1つも無い（期待値 `0`）
  - 02：B のマニフェストの `files` に独自スクリプトのキーが無い（期待値 `0`）
  - 03：`SCRIPTS_FILES` の全パスが B にあり、マニフェストにも全部載っている（期待値は `"<件数> <件数>"`。件数は `$ROOT/scripts/install.sh` の `SCRIPTS_FILES=` の行から読み取った語数で、smoke に21を直書きしない）
  - 04：A の `scripts/install.sh --update` で B を更新した後も、独自スクリプトが無く、マニフェストにも載らない（期待値 `0 0`）
  - 05：`$ROOT` から C に install し、C に `scripts/biz_tool.sh` を置いてそのハッシュをマニフェストの `files` に書き足し（旧版の状態を再現）、`$ROOT` の `scripts/install.sh --update` で C を更新 → ファイルは残り、マニフェストからは外れる（期待値 `1 0`）
  - 06：更新漏れの検出。`$ROOT/scripts/` 直下の `*.sh`・`*.py` のうち `SCRIPTS_FILES` に無いものの数が `0`。`$ROOT/.claude/harness-manifest.json` があるリポジトリ（導入先）では利用者の独自スクリプトがありうるので数えずに `0` とし、ラベルに「（導入先では省略）」を含める
  - 07：06 の数え方そのものが働くことの確認。06 で使う数え方を関数にし（引数はディレクトリ）、独自スクリプト2つを置いた A（`$ROOT` から install したもの）に対して呼ぶと `2` になる（A のマニフェストの有無では省略しない。省略の判定は 06 の呼び出し側に置く）
- `SCRIPTS_FILES` の語の読み取りは、smoke の中で `$ROOT/scripts/install.sh` の `SCRIPTS_FILES=` の行を読んで行う（読み方は sed・python のどちらでもよい）。install.sh に新しいオプション（一覧の出力など）は足さない
- 受け入れ基準の smoke の実行には数分かかる。タイムアウトは長め（600000ms）にしてよい

- 人の回答（計画票「人への質問」）：scripts/ 直下は固定リスト `SCRIPTS_FILES` にする。リスト更新漏れは smoke で検出する（ai-harness 本体でだけ。導入先では省略）。今ある21本すべてを配る。
