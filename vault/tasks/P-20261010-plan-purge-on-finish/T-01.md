# T-01 scripts/purge_plan.sh を作り smoke にケースを足す

## 目的
run の完了時に、計画一式4種（`vault/plans/<計画ID>.md`・`vault/tasks/<計画ID>/`・`vault/verdicts/<計画ID>/`・`vault/log/<計画ID>.md`）を `git rm` で除去するスクリプト `scripts/purge_plan.sh` を作る。条件を満たさない時は何も消さない。

## 入力
- `vault/designs/D-016.md` の「フェーズ1」（受け入れ基準の候補・決定済み）
- `scripts/archive_plans.sh`（frontmatter の `status` の読み方 `fm_status`、タスク表の数え方 `table_counts`、`git rev-parse --show-toplevel` の扱い、使い方の出し方を参考にする）
- `scripts/smoke.sh`（`expect_eq` の書き方、`== archive_plans.sh ==` 節の一時リポジトリの作り方）

## 成果物
- `scripts/purge_plan.sh`（主な成果物。新規）
- `scripts/smoke.sh`（`== purge_plan.sh ==` 節を足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- purge_plan.sh のケースが8つとも通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (pp-[1-8])'` の出力が `8`
- 引数なしで実行すると、何も変えずに終了コード2で終わる。確認：`bash scripts/purge_plan.sh` の終了コードが `2`
- 現在のブランチの計画でない計画 ID を渡すと、dry-run でも何も出さずに終了コード1で終わり、標準エラーに理由が出る。確認：`bash scripts/purge_plan.sh --dry-run P-20261010-harness-improvements-followup` の終了コードが `1`、標準出力が空、標準エラーが1行以上
- `bash -n scripts/purge_plan.sh` が終了コード0で何も出力しない

## 決定済み
- 使い方：`bash scripts/purge_plan.sh [--dry-run] <計画ID>`。引数は `--dry-run`（任意）と計画 ID 1つだけ。計画 ID が無い・2つ以上・未知のオプション（`-` で始まる `--dry-run` 以外）・計画 ID が `^P-[0-9]{8}-[a-z0-9][a-z0-9-]*$` に一致しない時は、使い方を標準エラーに出して終了コード2。git リポジトリの外（`git rev-parse --show-toplevel` が失敗）も終了コード2。フェーズ2で `--merged` を足す予定だが、このタスクでは足さない
- 対象のリポジトリは実行時のカレントディレクトリの `git rev-parse --show-toplevel`（`CLAUDE_PROJECT_DIR` は見ない。smoke の一時リポジトリで動かすため）。そこへ `cd` してから相対パスで扱う
- 条件（全部を満たす時だけ消す）：(1) 現在のブランチ（`git symbolic-ref --short -q HEAD`）が `work/<計画IDを英小文字にしたもの>`、(2) `vault/plans/<計画ID>.md` があり、frontmatter の `status` が `done`（読み方は `scripts/archive_plans.sh` の `fm_status` と同じ。引用符付きの `"done"` も done）、(3) タスク表のデータ行（第1列が `T-` で始まる `|` の行。`table_counts` と同じ）が1行以上で、全行の第2列が `done`、(4) `git status --porcelain --untracked-files=all -- <対象パス>` の出力が空（未コミット・未追跡・stage 済みの変更が無い）
- `fm_status`・`table_counts` 相当の処理は purge_plan.sh の中に持つ（`scripts/archive_plans.sh` を source しない。フェーズ2で archive_plans.sh を消すため）
- 条件を外れた時は、外れた条件ごとに `purge_plan.sh: <理由>` を1行ずつ標準エラーに出し、標準出力には何も出さず、何も変えずに終了コード1。理由の文言は自由（どの条件かが分かればよい）。計画票が無い時は (2)(3) の代わりに「計画票が無い」の1行でよい
- 対象パスは次の順の4つ：`vault/plans/<計画ID>.md`・`vault/tasks/<計画ID>/`・`vault/verdicts/<計画ID>/`・`vault/log/<計画ID>.md`。作業ツリーに存在しないもの（例：verdicts が無い）は飛ばす（出力にも出さず、`git rm` にも渡さない。条件 (4) の検査にも渡さなくてよい）
- `--dry-run`：条件の検査は同じに行い、満たせば消す予定のパス（上の順、存在するものだけ）を1行1件で標準出力に出して終了コード0。作業ツリーとインデックスを変えない。満たさなければ上と同じく終了コード1
- 実行（`--dry-run` なし）：`git rm -r -q -- <存在する対象パス...>` を1回呼び、成功したら消したパスを dry-run と同じ形で標準出力に出して終了コード0。`git rm` が失敗したら標準エラーに出して終了コード1
- コミットはしない（コミットはオーケストレーターが `<計画ID>: 計画一式を除去` のメッセージで行う。T-03 で手順7に書く）。verdict が PASS かの検査はしない（plan_guard と Stop フックがしている）
- スクリプト冒頭のコメントに、使い方・条件・終了コード（0 消した／dry-run で出した、1 条件を満たさない・何も消さない、2 引数の誤り・git リポジトリの外）・「コミットしない」・「run の手順7でオーケストレーターが使う」を書く。`set -u` と `export LC_ALL=C` を使う
- smoke のケース（名前は `(pp-<番号>)` で始め、どれも1ケース1行の `ok`/`NG` を `expect_eq` で出す。複数の確認がある時は全部を満たした時だけ ok にする）。一時リポジトリは smoke の `$TMP` の下に `git init -q` で作り、計画 ID は `P-20990101-pp`、ブランチは `work/p-20990101-pp`、計画票は `status: done`・タスク表 T-01・T-02 が done、タスク票・verdict・log を1つずつ置いてコミットした状態を基本にする（ケースごとに作り直してよい）
  - `(pp-1)` `--dry-run`：終了コード0、標準出力が `vault/plans/P-20990101-pp.md`・`vault/tasks/P-20990101-pp/`・`vault/verdicts/P-20990101-pp/`・`vault/log/P-20990101-pp.md` の4行（この順）と完全に一致、`git status --porcelain` が空
  - `(pp-2)` 実行：終了コード0、4つの対象が作業ツリーから消え、`git status --porcelain` の全行が `D ` で始まり（stage 済みの削除）、HEAD のコミットが実行前と同じ（コミットしていない）
  - `(pp-3)` ブランチが `work/p-20990101-pp` でない：終了コード1、標準出力が空、`git status --porcelain` が空
  - `(pp-4)` frontmatter が `status: approved`：終了コード1、何も変わらない
  - `(pp-5)` タスク表に done でない行がある時と、データ行が0行の時：2回とも終了コード1で何も変わらない
  - `(pp-6)` 対象パスに未コミットの変更がある時（log の追記をコミットしない）と、未追跡のファイルがある時（`vault/tasks/P-20990101-pp/` に新しいファイル）：2回とも終了コード1で、対象のファイルが1つも消えていない
  - `(pp-7)` `vault/verdicts/P-20990101-pp/` が無い：`--dry-run` が終了コード0で、標準出力が verdicts を除いた3行
  - `(pp-8)` 引数なし・未知のオプション（`--bogus P-20990101-pp`）・形式の違う計画 ID（`P-1`）・git リポジトリの外（`$TMP` の下の git でないディレクトリ）：4回とも終了コード2
- smoke の節は `== verdict_notes.py ==` 節の後か `== archive_plans.sh ==` 節の前に `echo "== purge_plan.sh =="` で足す（フェーズ2で archive_plans.sh の節を消すので、その中には混ぜない）。後片付けは smoke の既存の `$TMP` の trap に任せる
- `scripts/` 直下に置くので `install.sh` の配布対象に自動で入る（`SCRIPTS_EXCLUDE` は触らない）。文書（`docs/`・スキル）はこのタスクでは変えない（T-03・T-04 が行う）
