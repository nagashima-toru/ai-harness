## 決定済み
- 小節の見出しは `### サンドボックス（OS による書き込みと通信の制限）` で、「Bash の書き込み対象の解析（issue #91・#87）」小節の後、「提案ファイル方式（ルール自体を変更するタスク用）」小節の前に置く
- 小節に書くこと：
  - このリポジトリの `.claude/settings.json` で Claude Code のサンドボックスを有効にしている（`sandbox.enabled: true`）。値は `.claude/settings.json` を正とし、文書には各キーの意味を書く
  - 対象は Bash とその子プロセス（`python3`・`bash -c` を含む）。Write・Edit などのツールの書き込みはサンドボックスの対象外で、今どおり `agent_write_guard.py` が判定する
  - `filesystem.denyWrite` の `vault/rules/` と `~/.claude/projects/`（会話記録）への書き込みは、Bash の解析の成否にかかわらず OS が拒否する。`python3 -c` による書き込みのような、解析できない形の抜け道を塞ぐ
  - `network.allowedDomains` は GitHub のドメインだけ（`github.com`・`*.github.com`・`*.githubusercontent.com`）。Anthropic の API のドメインを入れないので、入れ子の claude による会話記録の偽造もできない
  - `allowUnsandboxedCommands` が `false` なので、サンドボックスの外で実行し直す逃げ道は無い。`excludedCommands` は設定していない
  - `failIfUnavailable` は設定しない。サンドボックスが使えない環境でも Claude Code を起動でき、その時は Bash の解析だけが守りになる
  - 導入先には既定で入れない（`merge_settings_json.py` は既存の settings.json に `sandbox` を足さない。手順は `docs/install.md` の「サンドボックスを有効にする（任意）」）
  - 設定はセッションの開始時に読まれる。効き目の確かめ方は `docs/runbook.md` の「9. サンドボックスを確かめる」
- 「残る弱点」の行の直し方：行頭の `- 残る弱点：` は残し、最初に「Bash とその子プロセスの `vault/rules/`・`~/.claude/projects/` への書き込みはサンドボックスで OS が拒否するので、Bash の解析はその補助になる（サンドボックスが使えない環境では解析が唯一の守り）」という趣旨の文を置く。続けて既存の3つの弱点を、「Bash の解析としての弱点」として残す（削らない）。この1行に「サンドボックス」と「補助」の語を必ず入れる
- 「検知範囲：`gh api` / `curl` によるリモート直叩き」小節は変えない（サンドボックスの通信先の制限との関係は、新しい小節で一言触れるだけでよい）
- `agent_write_guard.py` の Bash の解析は削らない（人の回答：当面残す）。文書にもそう書く
- 12節の表・ほかの小節・ほかの節は変えない
