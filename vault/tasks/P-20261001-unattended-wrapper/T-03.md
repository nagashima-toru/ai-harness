## 目的
無人実行の手順を、素の `claude -p "/run"` ではなくタイムアウト付きラッパーを cron・CI から呼ぶ形にして、ハングで居座らないようにする（D-010 フェーズ7、issue #79）。

- `docs/runbook.md` 3節「キューを回す」の「無人」の項目
- `scripts/run_unattended.py`（T-01 の成果物。環境変数と終了コードの仕様）
- `vault/designs/D-010.md` フェーズ7のゴール文と決定済み

## 成果物

## 受け入れ基準
- 3節の無人実行の手順が `python3 scripts/run_unattended.py` を cron / CI から呼ぶ形になっている。確認：`grep -n 'run_unattended.py' docs/runbook.md` が3節の行にヒットする
- 環境変数 `HARNESS_RUN_CMD`（既定 `claude -p "/run"`）と `HARNESS_RUN_TIMEOUT`（秒、既定 3600）の説明がある。確認：`grep -n 'HARNESS_RUN_TIMEOUT' docs/runbook.md` と `grep -n 'HARNESS_RUN_CMD' docs/runbook.md` がヒットする
- タイムアウト時は終了コード124で終わり、次回の `/run` が中断した地点から再開する旨が書かれている。確認：`grep -n '124' docs/runbook.md` がヒットする
- 既存の記述（初回のフォルダ信頼、`HARNESS_MAX_ATTEMPTS`、全 done 後の `vcs_finish.sh`、人によるマージ）が残っている。確認：`grep -n 'HARNESS_MAX_ATTEMPTS' docs/runbook.md` と `grep -n 'vcs_finish.sh' docs/runbook.md` がヒットする
- 変更が3節の範囲に収まる。確認：`git diff -- docs/runbook.md` の `@@` 行が3節（`## 3.` から `## 4.` の手前）に収まることを目視で確認する
- `bash scripts/smoke.sh` の最終行が `fail=0` になる

## 決定済み
- 検査対象ファイルの範囲：変更してよいのは `docs/runbook.md` と、このタスク票自身（`vault/tasks/P-20261001-unattended-wrapper/T-03.md` の「進捗」）だけ。宣言外ファイルの変更は verifier が `git status --porcelain` で検査する（`vault/log/`・`vault/verdicts/`・計画票は run が更新するので除外）。`scripts/run_unattended.py`・SKILL.md・`scripts/smoke.sh` は変更しない
- 書く内容：呼び出し例は `python3 scripts/run_unattended.py`（cron・CI から）。`HARNESS_RUN_CMD` を未設定なら `claude -p "/run"` が実行される。`HARNESS_RUN_TIMEOUT` を過ぎると SIGTERM、10秒待って SIGKILL、終了コード124。時間内なら子の終了コードをそのまま返す
- 人が対話で `/run` を打つ運用の項目（「対話」）は変えない
- タイムアウトで止めた後は、次回の `/run` が `.claude/skills/run/SKILL.md` 手順2.2（フェーズ6の再開手順）で続きから再開する。同じ地点で止まり続けても `HARNESS_MAX_ATTEMPTS` で blocked になって止まる、と書く
- ラッパーは vault のファイルに書かない。タイムアウトは標準エラーの `run_unattended: timeout <秒>s` で分かる、と書く（cron のログや CI のログで確認できる）
- 実行例を書くときは `grep` で拾える形（バッククォート内の `python3 scripts/run_unattended.py`）でそのまま書く
