# T-04 scripts/smoke.sh に discard_worktree.sh の動作確認ケース（正常系・拒否系3種・install配置確認）を追加する

## 目的
`scripts/discard_worktree.sh`（T-01）の正常削除・拒否の各挙動と、`scripts/install.sh`（T-02）での配布・マニフェスト掲載を、`scripts/smoke.sh` の回帰テストとして自動確認できるようにする。

## 入力
- T-01 の成果物 `scripts/discard_worktree.sh`（引数・検証条件・終了コード）
- T-02 の成果物 `scripts/install.sh`（配布・マニフェストへの追加）
- `scripts/smoke.sh` 既存の worktree 関連ケース（203〜222行目付近：`mktemp -d` → `rmdir` → `git worktree add -q -b <branch> <path>` の作法、`expect_guard`/`expect_eq` の使い方）
- `scripts/smoke.sh` の「== install.sh のマニフェスト ==」節（254行目付近、既存のマニフェスト検証パターン）

## 成果物
- `scripts/smoke.sh`

## 受け入れ基準
- `scripts/smoke.sh` に新セクション `== discard_worktree.sh ==` があり、次の5ケースが追加されすべて ok になる：(a) 正常系（worktree/branch とも削除・rc0）、(b) ブランチ名が `worktree-agent-` で始まらない、(c) 未登録パス、(d) パスのブランチが指定と不一致、(e) install.sh で配置されマニフェストに載る。確認：`bash scripts/smoke.sh 2>&1 | grep -E '^  ok   \([a-e]\) discard_worktree\.sh' | wc -l` が `5`
- (a) の正常系ケースは、一時リポジトリで `git worktree add -q -b worktree-agent-test <path>` した後にスクリプトを実行し、実行後 `git worktree list` に対象パスが含まれず `git rev-parse --verify worktree-agent-test` が失敗することを確認している。確認：`sed -n '/== discard_worktree.sh ==/,/^echo "==/p' scripts/smoke.sh | grep -c 'rev-parse --verify worktree-agent-test'` が1以上
- (b)〜(d) の拒否系ケースは、実行後も対象の worktree ディレクトリと git ブランチが削除されずに残っていることをそれぞれ確認している。確認：`sed -n '/== discard_worktree.sh ==/,/^echo "==/p' scripts/smoke.sh | grep -c 'git worktree list'` が3以上
- (e) は `scripts/discard_worktree.sh` が install 先に複製され、`.claude/harness-manifest.json` の `files` に載ることを確認している。確認：`sed -n '/== discard_worktree.sh ==/,/^echo "==/p' scripts/smoke.sh | grep -c 'harness-manifest'` が1以上
- `bash scripts/smoke.sh | tail -1` が `fail=0` で終わる

## 決定済み
- 新セクションの見出しは `echo "== discard_worktree.sh =="` を使う（既存の `== rules.sh ==` 等と同じ書式）。挿入位置は既存の worktree 関連ケース（`agent_write_guard.py` の節）より後ろで構わない
- 5ケースの表示名は受け入れ基準の grep パターンに厳密に合わせる：`(a) discard_worktree.sh ...` 〜 `(e) discard_worktree.sh ...` の形（`expect_guard`/`expect_eq` 等どの既存ヘルパーを使うか、専用の `expect_rc`/`expect_discard` を新設するかは任せる。ok/NG の出力書式は既存ヘルパー（`  ok   <name>` / `  NG   <name> ...`）に合わせる）
- 一時リポジトリの作り方は既存の worktree ケース（203〜222行目付近）・T-01 の「決定済み」と同じ：`git init` 後 `git -c user.name=test -c user.email=test@example.com commit --allow-empty -m init` で初期コミットを作ってから `git worktree add -q -b <branch> <path>` する。`<path>` は `mktemp -d` して `rmdir` した未使用パスを使う（`git worktree add` 自身にディレクトリを作らせる）
- (e) のケースは T-02 で追加済みの `bash scripts/install.sh <target>` の配布結果と `.claude/harness-manifest.json` を読み、`scripts/discard_worktree.sh` のキー存在とハッシュの妥当性（64桁16進）を確認する形にする（既存の「== install.sh のマニフェスト ==」節の書き方を流用してよい）
- 各ケースの後片付け（一時ディレクトリ・一時リポジトリの削除）は既存ケースと同様 `rm -rf` で行ってよい（`scripts/smoke.sh` 自体はテスト対象コードではなくテストコードなので、`.claude/settings.json` の deny 対象にはならない。deny はエージェントの Bash ツール呼び出しに対する制約であり、smoke.sh の中身のシェルコマンドには適用されない）
- T-01・T-02 が先に完了している前提。どちらかが未完了なら自分で作らず `blocked` にする
