# T-02 bash_write_targets を足し vault/rules・会話記録・creator の拒否判定を載せ替える

## 目的
Bash コマンドの書き込み対象を求める関数 `bash_write_targets(cmd, root)` を `agent_write_guard.py` に足す。解析できた時は `analyze_bash_writes` の結果を、解析できない時は4通りの従来判定の候補の和集合を返し、同じコマンドでは2回目から計算しない（メモ化）。`targets_vault_rules`・`targets_transcript_dir`・`targets_creator_denied_paths` をこの結果をパスで絞り込むだけの形に書き直す。

- 計画票 `vault/plans/P-20261005-bash-write-unify.md` の「分割方針」（4通りの従来判定の候補の一覧）
- フィクスチャ：`vault/tasks/P-20261005-bash-write-unify/fixtures/targets_check.py`・`bash_writes_check.py`（planner が作成済み。編集しない）

## 成果物

## 決定済み
- `bash_write_targets(cmd, root)` の仕様（名前・戻り値の形は固定。フィクスチャと T-03 が使う）
  - 戻り値は `(parsed, writes)`。`parsed` は `analyze_bash_writes(cmd, root)` が None でない時 True。`writes` は `(verb, target)` のタプルのタプル（リストではなくタプル。メモ化した値を呼び出し側が変えないように）
  - 解析できた時：`writes = tuple(analyze_bash_writes の結果)`
  - 解析できない時：`masked = mask_angle_placeholders(cmd)` が `BASH_WRITE_PATTERNS` のどれにも一致しなければ `(False, ())`。一致したら、次の候補をこの順に集める
    - `("legacy-redirect", t)`：`masked` に対する従来のリダイレクトの正規表現 `>{1,2}\s*([^\s;&|]+)` の結果
    - `("legacy-write", t)`：`extract_bash_write_targets(cmd)` の結果（リダイレクト先も含む。重複してよい）
    - `("legacy-path", t)`：保護対象パスを含む path-like トークン。接頭辞の選択肢は `vault/(?:rules|plans|log|tasks|verdicts)/` と `\.claude/projects`（末尾の `/` なし）。`cmd`（マスクしない）に対して、区切りの文字クラスを `[^\s'"]` にした版と、`)` も区切る `[^\s'")]` にした版の2回 findall する（従来の4つの正規表現の候補を1つも落とさないため。done 判定の旧正規表現は `)` を区切っていた）
    - 全ての候補は末尾の `)`・`"`・`'`・バッククォート・`;` を `rstrip` で落とし、空になったものは捨てる
    - 1つも残らなければ `(("legacy-unknown", ""),)` を返す（書き込み動詞はあるが対象を特定できない印。T-03 の ALLOWED 判定が「許可しない」に使う）
  - メモ化：モジュールの辞書で `(cmd, root)` をキーに結果を覚え、2回目からは `analyze_bash_writes` を呼ばない。`analyze_bash_writes` はモジュールのグローバル名で呼ぶ（別名に束縛しない。フィクスチャと smoke がグローバル名を差し替えて回数を数える）
- 3つの判定の書き直し（Write 系ツールの分岐と、`targets_vault_rules` の `targets_vault_rules_remote` の先行検査は今どおり）
  - `targets_vault_rules`：`bash_write_targets` の全ての target のうち空でないものについて `normalize(t, root).startswith("vault/rules/")` が1つでもあれば True。`parsed` で分岐しない。`_legacy_targets_vault_rules_bash` は消す
  - `targets_transcript_dir`：全ての空でない target について `is_under_transcript_dir(t, root)`
  - `targets_creator_denied_paths`：全ての空でない target について `normalize(t, root).startswith(DENIED_FOR_CREATOR)`
  - 解析できない時の候補は、各判定の従来の候補の上位集合なので、拒否は減らない（増える分は D-011 の「拒否する側に倒す」に当たる）
- このタスクで変えないもの：`find_done_task_write`・`is_git_commit_command`・`main` の ALLOWED 判定（T-03 の担当。この時点では `analyze_bash_writes`・`BASH_WRITE_PATTERNS` を直接使ったままでよい）、`analyze_bash_writes`・`extract_bash_write_targets`・`is_git_stage_or_commit_only`、T-01 で組み立てたパターン
- 3つの判定関数の docstring の「解析できない時は従来の判定に落とす」趣旨の文は、`bash_write_targets` の結果で判定する趣旨に直す。モジュール docstring は T-03 でまとめて直すので、このタスクでは触らなくてよい
- `scripts/smoke.sh`・`docs/vault-spec.md`・`_hooklib.py`・他のフックは変更しない
- 既存の smoke が落ちた場合は、smoke.sh を直さず blocked にして、落ちたケース名と原因を question に書く
- 動作確認で import する時は `python3 -B` を使う。`py_compile` は使わない
- コミットは受け入れ基準に無いので、creator はしない
