# T-06 planner.md の一時ファイルの置き場を /tmp/claude/ にし、人に消させないと書く

## 目的
planner がタスク票に書く一時ファイル・フィクスチャの置き場を、サンドボックスの中でも書ける `/tmp/claude/<計画ID>-<タスクID>/` にする。あわせて、エージェントが作った一時ファイルは消さず、人にも消させない（計画票の「マージ後に人が行う作業」に一時ファイルの削除を書かない）と planner の定義に書き、人の手作業を増やさないようにする。

## 入力
- `.claude/agents/planner.md` の「## やらないこと」の、`rm -rf` を前提にしない項目（70行目付近。今は「`/tmp/<計画ID>-<タスクID>` のように ID を含む固定パスにし、開始時に `mkdir -p` で作り直す」とある）
- `vault/plans/P-20261009-sandbox-friendly.md` の分割方針（サンドボックスの中で書けるのは `$TMPDIR` と `/tmp/claude/` の下だけ）

## 成果物
- `.claude/agents/planner.md`（1ファイル）
- （リポジトリの外。差分ゲートの宣言ではない）上のファイルの編集が拒否された時だけ、決定済みの最後から2つ目の項目のパッチ /tmp/claude/P-20261009-sandbox-friendly-T-06/planner.patch を残す

## 受け入れ基準
- 古い置き場の書き方が無い：`grep -cF '`/tmp/<計画ID>-<タスクID>`' .claude/agents/planner.md` の出力が `0`
- 新しい置き場が書かれている：`grep -cF '`/tmp/claude/<計画ID>-<タスクID>/`' .claude/agents/planner.md` の出力が `1`
- 一時ファイルを消さない・人に消させないと書かれている：`grep -cF '一時ファイルは消さず、人にも消させない' .claude/agents/planner.md` の出力が `1`
- frontmatter は main の版と同じ：`python3 -c "import subprocess; a=open('.claude/agents/planner.md').read().split('---')[1]; b=subprocess.run(['git','show','main:.claude/agents/planner.md'],capture_output=True,text=True).stdout.split('---')[1]; print(a==b)"` の出力が `True`
- `## ` の見出しの数は変わっていない：`grep -c '^## ' .claude/agents/planner.md` の出力が `10`

## 決定済み
- 直すのは「## やらないこと」の「機能テストの後片付けに `rm -rf` を使う前提にしない」の項目だけ。次のとおりにする
  - 「`/tmp/<計画ID>-<タスクID>` のように ID を含む固定パスにし」を「`/tmp/claude/<計画ID>-<タスクID>/` のように ID を含む固定パスにし（サンドボックスの中の Bash が書けるのは、リポジトリのほかは `/tmp/claude/` と `$TMPDIR` の下だけ。`$TMPDIR` は Write ツールでは展開されないので、固定パスは `/tmp/claude/` にする）」に直す
  - 同じ項目に「一時ファイルは消さず、人にも消させない（計画票の「マージ後に人が行う作業」に一時ファイルの削除を書かない。OS の掃除に任せる）」の文を足す。受け入れ基準3行目の文字列はこのとおりに1回だけ書く
  - 「ただし verifier の Bash では repo の外（/tmp など）への書き込みが権限判定で止まることがある。フィクスチャが要る時は creator が作るか、リポジトリ内の既存ファイルを使う」は残す
- ほかの項目・節・frontmatter は変えない。`/tmp/claude/<計画ID>-<タスクID>/` の文字列はこの項目に1回だけ書く（受け入れ基準2行目）
- `vault/rules/planner/ai-harness-lessons.md`（経緯集。`/tmp/vftest_a` などの経緯が書いてある）は変えない（`vault/rules/` は書けず、経緯は経緯のまま残す）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` は変えない
- 文書だけの変更なので、確認は受け入れ基準のコマンドで行う。`bash scripts/smoke.sh` は実行しない
- 編集が拒否された時（サンドボックスの書き込み保護などで `.claude/agents/planner.md` を変えられない時）は、別の手段で worktree のファイルを書き換えようとしない。代わりに次のとおりにして `blocked` にする（計画票の人への質問4）
  1. `mkdir -p /tmp/claude/P-20261009-sandbox-friendly-T-06/patch`
  2. worktree の `.claude/agents/planner.md` を `/tmp/claude/P-20261009-sandbox-friendly-T-06/patch/planner.md` に `cp` で写し、写したファイルを Edit で直す
  3. 受け入れ基準の1〜3・5行目を、`.claude/agents/planner.md` の代わりに `/tmp/claude/P-20261009-sandbox-friendly-T-06/patch/planner.md` で確かめる（4行目は写しを開く形に読み替える）
  4. `diff -u --label a/.claude/agents/planner.md --label b/.claude/agents/planner.md <worktree>/.claude/agents/planner.md /tmp/claude/P-20261009-sandbox-friendly-T-06/patch/planner.md > /tmp/claude/P-20261009-sandbox-friendly-T-06/planner.patch` でパッチを残す（`git apply` で当てられる形）
  5. question に「`.claude/agents/planner.md` の編集が拒否された（拒否の理由）。パッチ：/tmp/claude/P-20261009-sandbox-friendly-T-06/planner.patch（受け入れ基準1〜5行目は写しで確認済み）」と書く。人がパッチを計画ブランチに当ててコミットし、`/plan unblock P-20261009-sandbox-friendly T-06` で進める
- 解除後の再開（worktree の `.claude/agents/planner.md` が既に受け入れ基準を満たしている時）：creator はファイルを変えず、受け入れ基準1〜5行目を確かめ、このタスク票の「進捗」に `- 人が当てたパッチが計画ブランチに入っていることを受け入れ基準1〜5行目で確認した` の1行を足して完了を報告する（「進捗」の追記が無いと worktree に新規コミットができず、review で `新規コミット無し` の blocked になるため）
- `/tmp/claude/P-20261009-sandbox-friendly-T-06/` の下のファイルは消さない（人にも消させない）
