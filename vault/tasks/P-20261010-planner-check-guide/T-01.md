# T-01 planner.md の「やらないこと」に確認コマンドの指針4点を足す

## 目的
planner が書く受け入れ基準・確認コマンドが、smoke の `(ref-1)` の取りこぼし・`env -C` の拒否・削除系の権限停止・旧形式検出の正規表現の誤マッチで止まらないよう、`.claude/agents/planner.md` の `## やらないこと` 節に4つの箇条を足す。

## 入力
- `.claude/agents/planner.md`（63〜72行目の `## やらないこと` 節、74行目からの `## 書き終えた後の確認` 節）
- `scripts/smoke.sh` の `refcheck`（2477行目付近。`(ref-1)` が検査する文書の一覧）
- `.claude/hooks/agent_write_guard.py`・`.claude/hooks/_hooklib.py`（`env -C` を拒否する判定が無いことの確認）
- `.claude/skills/run/SKILL.md` の手順5の2（verifier は同じ Bash 呼び出しで対象 worktree に `cd` してから実行する）
- `docs/vault-spec.md` 1節の `purge_plan.sh --merged` の説明（`--apply` は人だけが実行する）

## 成果物
- `.claude/agents/planner.md`（1ファイル。`## やらないこと` 節の末尾に4つの箇条を足し、`## 書き終えた後の確認` 節に1つの箇条を足す）

- 項目3の箇条が `## やらないこと` 節にある：`sed -n '/^## やらないこと/,/^## 書き終えた後の確認/p' .claude/agents/planner.md | grep -cF '非破壊モード（`--dry-run`・`--list`・`--report`）'` が1以上、かつ `sed -n '/^## やらないこと/,/^## 書き終えた後の確認/p' .claude/agents/planner.md | grep -cF 'Irreversible Deletion'` が1以上

## 決定済み
- 4つの箇条は `## やらないこと` 節の末尾（今の最後の箇条「コード変更を伴う受け入れ基準で、`grep` 等による…」の後）に、項目1〜4の順で、既存の箇条と同じ「〜しない。理由。代わりにこう書く」の文体で足す。既存の箇条は変えない
- planner.md は導入先にも配る汎用の文書なので、issue 番号・計画 ID・タスク ID は書かない（経緯は `vault/rules/planner/ai-harness-lessons.md` の役目。今回は変えない）
- 文言の案（この語句は受け入れ基準が grep するので、少なくとも次の語句はそのまま書くこと：`grep -c '^  ok   (ref-1) '`・`` `env -C <dir>` で書かない ``・`作業ディレクトリが要るコマンドはリポジトリ相対のまま書く`・`` 非破壊モード（`--dry-run`・`--list`・`--report`） ``・`Irreversible Deletion`・`` `vault/designs/D-[0-9]{3}([^0-9]|$)` ``）。ほかの部分の言い回しは整えてよい
  - 項目1：「smoke の `(ref-1)` が検査する文書（`scripts/smoke.sh` の `refcheck` が見る `.claude/ai-harness.md`・各スキルの `SKILL.md`・`.claude/agents/` 配下の定義・`README.md`・`docs/vault-spec.md`・`docs/runbook.md`・`docs/install.md`）を成果物に持つタスクに、`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1` になる基準を入れずに書かない。文書だけのタスクでも、バッククォートで書いた存在しないパスがそのまま計画ブランチに入り、smoke 全体を基準に持つ後続タスクが自分と無関係な失敗で止まる」
  - 項目2：「別のディレクトリで実行するコマンドを `env -C <dir>` で書かない。このリポジトリのフック（`.claude/hooks/`）に `env -C` を拒否する判定は無いが、creator の worktree の外へ移って実行する形は Claude Code 側のガードに拒否されたことがある。作業ディレクトリに依存しないコマンドは `git -C <dir> ...` か、スクリプトを絶対パスで呼ぶ形（`bash <dir>/scripts/x.sh`）にする。作業ディレクトリが要るコマンドはリポジトリ相対のまま書く（verifier は `.claude/skills/run/SKILL.md` の手順5のとおり、同じ Bash 呼び出しの中で対象 worktree に `cd` してから実行する）。確認コマンドの中に `cd` は書かない（`&&`・`;` を使わない上の指針と両立しないため）」
  - 項目3：「削除を伴う確認（`purge_plan.sh --merged --apply` のように、ファイルやブランチを消す操作）を受け入れ基準の確認コマンドにしない。auto mode の権限チェック（classifier）が Irreversible Deletion として止め、タスク票の「決定済み」に許可を書いても通らない。非破壊モード（`--dry-run`・`--list`・`--report`）で消す予定の対象を確かめる形を優先し、削除そのものの動作は、一時リポジトリの中で削除を試すテスト（smoke など）を実行して確かめる」
  - 項目4：「旧形式の記述が残っていないことを検出する正規表現を、新形式に当たらないことを手元で確かめないまま基準にしない。`vault/designs/D-[0-9]{3}` は新形式の `D-20991231` の先頭3桁にも当たる。桁数の後ろを `([^0-9]|$)` で閉じ（例：`vault/designs/D-[0-9]{3}([^0-9]|$)`）、旧形式と新形式の例を `printf` でパイプして、旧形式だけに当たることを確かめてから書く」
- `## 書き終えた後の確認` 節に1つ箇条を足す：「`(ref-1)` の対象の文書を成果物に持つタスクに `(ref-1)` の基準があるか。`env -C`・確認コマンドの中の `cd`・削除を伴う操作が基準に混ざっていないか。旧形式を検出する正規表現が新形式に当たらないか」。受け入れ基準では検査しないが、書くこと
- `.claude/hooks/` を確かめた結果：`agent_write_guard.py` の判定は main 上の git commit の拒否・done のタスク票と verdict への書き込みの拒否・verifier の書き込み先の制限の3つと、cwd が別 worktree の時の委譲だけで、`env -C` を名指しで拒否する判定は無い。`plan_guard.py`・`stop_gate.py` も Bash のコマンドの形を見ない。`.claude/settings.json` の allow には `Bash(env *)` もある。よって指針は「repo のフックは拒否しないが、Claude Code 側のガードに拒否された実績があるので避ける」とする。フック側は変えない
- 「`cd <dir> && ...` で書く」は勧めない。既存の箇条（複合コマンドにしない）と矛盾するため。cwd が要る場合の `cd` は run/SKILL.md 手順5で verifier の実行時の手順として既に決まっているので、planner はリポジトリ相対のコマンドを書けばよい
- 受け入れ基準の `env -C` の全体検査から `vault/` を外す理由：計画票とこのタスク票（と、run が書く log・verdict）が説明のために `env -C` を含むため。`docs/decisions.md` は検査範囲（`docs`）に入っていて、今は `env -C` を含まない。`.claude/worktrees/` は creator の作業コピーなので範囲に入れていない（`.claude/agents` などを個別に挙げている）
- 新しく書くバッククォート内のパスは、実在するもの（`scripts/smoke.sh`・`.claude/hooks/`・`.claude/skills/run/SKILL.md`・`docs/vault-spec.md` など）か、`<`・`*`・`{`・`$`・空白を含んで `(ref-1)` の検査から外れるものだけにする。`SKILL.md` のように接頭辞（`vault/`・`scripts/`・`docs/`・`.claude/`）で始まらない語は検査されない
- smoke は1回あたり1分ほどかかる。タイムアウトは長め（5分程度）にしてよい
