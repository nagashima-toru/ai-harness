# T-05 docs/install.md と README.md の CLAUDE.md の配布の説明を合わせる

## 目的
T-01〜T-03 の後の挙動（ハーネス側の `CLAUDE.md` のマーカーブロックだけを配り、マーカーの外の行は配らない。`--no-claude-md` で `CLAUDE.md` が無い時もマーカーブロックだけで作る）に、`docs/install.md` と `README.md` の説明を合わせる。

## 入力
- `docs/install.md`（「3. ハーネスを複製する」の複製されるものの一覧・`CLAUDE.md` のマージの説明と出力の表・`--no-claude-md` の段落）
- `README.md`（`CLAUDE.md` は「マーカー付きの4行ブロックだけを持つ」と書いた段落）
- `scripts/merge_claude_md.py`・`scripts/install.sh`（T-01・T-02 の後の挙動）、`CLAUDE.md`（T-03 の後。マーカーの外に `@docs/vision.md` がある）

## 成果物
- `docs/install.md`（主な成果物）
- `README.md`

## 受け入れ基準
- `grep -n 'マーカーの外の行.*配らない' docs/install.md` の出力が1行以上（マージに使うのはマーカーブロックだけで、マーカーの外の行は配らないと書いてある）
- `grep -n 'が無い時はマーカーブロックだけで作る' docs/install.md` の出力が1行以上（`--no-claude-md` で `CLAUDE.md` が無い時の挙動が書いてある）
- `grep -n 'ブロックだけを持つ' README.md` の出力が空、かつ `grep -c 'マーカーの外の行は導入先に配らない' README.md` が `1`（このリポジトリの `CLAUDE.md` が4行ブロックだけを持つという、事実と食い違う記述が残っていない）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`
- `bash scripts/smoke.sh 2>&1 | grep -c '^  NG '` が `0`

## 決定済み
- `docs/install.md` の `CLAUDE.md` のマージの説明（「マージされるのは次の4行だけで…」の段落の近く）に、次の趣旨の文を足す。文中に「マーカーの外の行」と「配らない」をこの順で同じ行に書く：「マージに使うのはハーネス側の `CLAUDE.md` のマーカーブロックだけで、マーカーの外の行（ハーネス本体のリポジトリだけが読む `@docs/vision.md` など）は配らない。」
- `docs/install.md` の `--no-claude-md` の段落に、次の文言をそのまま含む文を足す：「`CLAUDE.md` が無い時はマーカーブロックだけで作る（出力は `create <path>/CLAUDE.md`）」。既存の `note  CLAUDE.md は既にあります。...` の記述はそのまま残す
- `docs/install.md` の「3. ハーネスを複製する」の複製されるものの一覧の末尾の `` `CLAUDE.md` `` を `` `CLAUDE.md`（マーカーブロックだけ） `` にする
- `README.md` の「`CLAUDE.md` はそれを `@` で読み込むマーカー付きの4行ブロックだけを持つ」を、導入先の `CLAUDE.md` に入るのはその4行ブロックだけであること、このリポジトリの `CLAUDE.md` はマーカーの外に `@docs/vision.md` を1行持つこと、を書いた文に直す。文言「マーカーの外の行は導入先に配らない」をそのまま1回だけ書く。「ブロックだけを持つ」という言い回しは使わない
- `docs/vision.md` の本文・要約はどちらの文書にも写さない。`README.md` の既存の `docs/vision.md` への案内の1文と `## 構成` の `vision.md` の記載は変えない
- `docs/vault-spec.md` は変えない（`merge_claude_md.py` と `CLAUDE.md` の配布を説明していないため）。`vault/rules/README.md` も変えない（導入先に配られるため、このリポジトリ専用の `vault/rules/common/vision.md` について書かない）
- バッククォートで書くパスは実在するものだけにする（`(ref-1)` が検査する）。`@docs/vision.md` は `@` で始まるので `(ref-1)` の対象外
