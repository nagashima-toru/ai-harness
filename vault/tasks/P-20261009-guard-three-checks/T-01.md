# T-01 agent_write_guard.py を3つの判定と worktree への委譲だけにし、使われなくなった _hooklib.py の関数を削る

## 目的
`agent_write_guard.py` の判定を (a) done のタスク票・verdict への書き込みの拒否、(b) `main` 上の `git commit` の拒否、(c) verifier の書き込み先を `vault/verdicts/` に限る、の3つと worktree への委譲だけにする（D-015 フェーズ3）。

## 入力
- `vault/designs/D-015.md` の「フェーズ3 agent_write_guard を3つの判定に絞る」と「決定事項」の表
- `.claude/hooks/agent_write_guard.py`（今の判定。`main()` の順に読む）
- `.claude/hooks/_hooklib.py`、`.claude/hooks/plan_guard.py`、`.claude/hooks/stop_gate.py`、`scripts/transition.py`（`_hooklib` の関数の使用箇所）

## 成果物
- `.claude/hooks/agent_write_guard.py`（主な成果物。3つの判定と worktree への委譲だけにする）
- `.claude/hooks/_hooklib.py`（使われなくなった関数を削る）

## 受け入れ基準

- (c) verifier の `vault/verdicts/` 以外への Write は拒否され、`vault/verdicts/` への Write は許可される。確認：`printf '%s' '{"agent_type":"verifier","tool_name":"Write","tool_input":{"file_path":"README.md"}}' | python3 .claude/hooks/agent_write_guard.py | grep -c '"deny"'` が `1`、`printf '%s' '{"agent_type":"verifier","tool_name":"Write","tool_input":{"file_path":"vault/verdicts/P-X/T-01.json"}}' | python3 .claude/hooks/agent_write_guard.py | grep -c '"deny"'` が `0`
- 削った判定は効かない。確認：`printf '%s' '{"tool_name":"Write","tool_input":{"file_path":"vault/rules/common/x.md"}}' | python3 .claude/hooks/agent_write_guard.py | grep -c '"deny"'`、`printf '%s' '{"agent_type":"creator","tool_name":"Write","tool_input":{"file_path":"vault/plans/P-X.md"}}' | python3 .claude/hooks/agent_write_guard.py | grep -c '"deny"'`、`printf '%s' '{"agent_type":"planner","tool_name":"Write","tool_input":{"file_path":"README.md"}}' | python3 .claude/hooks/agent_write_guard.py | grep -c '"deny"'` がどれも `0`
- `agent_write_guard.py` に、削った判定の関数名・語が残っていない。確認：`grep -cE 'bash_write_targets|analyze_bash_writes|targets_vault_rules|transcript|find_plan_unblocks|DENIED_FOR_CREATOR|gh api|vault/rules' .claude/hooks/agent_write_guard.py` が `0`
- `_hooklib.py` から `human_messages` と `is_unblock_command` が消え、4つのモジュールが読み込める。確認：`grep -cE 'def (human_messages|is_unblock_command)' .claude/hooks/_hooklib.py` が `0`、`python3 -B -c "import sys;sys.path.insert(0,'.claude/hooks');import _hooklib,plan_guard,stop_gate,agent_write_guard;print('ok')"` が `ok`

## 決定済み
- `main()` の順は「worktree への委譲 → (b) → (a) → (c)」にする。どれにも当たらなければ何も出力せず終了コード0で終わる（`{}` のような空の payload も同じ）
- (a)：対象のツールは Write・Edit・MultiEdit・NotebookEdit（`file_path`、無ければ `notebook_path`）。agent_type を問わない（メインセッションも verifier も）。今の `plan_task_status`・`match_task_or_verdict_path`・`TASK_FILE_RE`・`VERDICT_FILE_RE` と reason の文言（`status が done のため` を含む）はそのまま使う。計画票が無い・行が無い時は許可（fail-open）も今どおり。Bash による書き換えは見ない（D-015 の決定済み。PR の差分と plan_guard・stop_gate の verdict の検査で見える）
- (b)：Bash だけを見る。コマンドを `&&`・`;`・改行で区切った各部分に、今の `GIT_COMMIT_PATTERN`（`\bgit\s+commit\b`）か `GIT_PREOPT_COMMIT_PATTERN`（`\bgit\s+-[^;&|\n]*\bcommit\b`。`git -C . commit` を拾う）が当たり、`current_branch(root)` が `main` の時に拒否する。区切らずにコマンド全体へ2つの正規表現を当てても結果は同じなので、どちらで書いてもよい。agent_type は問わない。`grep -n "git commit" README.md` のような引用符の中の誤検知は許容する（main 上では拒否されてよい）。ブランチが取れない時（非 git・detached HEAD で `HEAD` が返る時）は素通り。reason は今の「main への直接コミットはできません」の文言を残す
- (c)：`agent_type` が `verifier` で、ツールが Write・Edit・MultiEdit・NotebookEdit の時だけ見る。`normalize(path, root)` が `vault/verdicts/` で始まらなければ拒否する。reason は `[agent_write_guard] verifier は vault/verdicts/ 以外に書き込めません: <path>` の形にする。verifier の Bash は制限しない。planner・creator の書き込み先は制限しない（`ALLOWED` の planner の行と `DENIED_FOR_CREATOR` を削る）
- worktree への委譲：`H.delegate_to_worktree` を呼ぶ前の判定（今の `writes_inside_worktree`）を、Write 系は `file_path`（`~` を展開し、相対パスは payload の `cwd` 基準、`os.path.realpath` で比べる）が worktree のルートの中の時だけ委譲、Bash とそれ以外のツールは常に委譲、にする。Bash で残る判定は (b) だけで、`cwd` から求めた root のブランチを見るため、worktree の版に判定させてよい。worktree のルートが求まらない時は今どおり委譲しない（`delegate_to_worktree` が None を返す）
- 削るもの（`agent_write_guard.py`）：Bash の書き込み解析一式（`analyze_bash_writes`・`bash_write_targets`・`_strip_heredocs`・`_segment_writes`・`_split_positional`・`_copy_move_targets`・`_replace_cat_heredoc_substitutions`・`extract_bash_write_targets`・`is_git_stage_or_commit_only`・`is_git_commit_command`・`mask_angle_placeholders`・`is_outside_root`・書き込み動詞の正規表現と定数）、`vault/rules/` の保護（`targets_vault_rules`・`targets_vault_rules_remote`・`_is_vault_rules_path`・`main_repo_root`・`GITHUB_API_HOSTS`）、会話記録（`transcript_dir`・`is_under_transcript_dir`・`targets_transcript_dir`）、creator の制限（`targets_creator_denied_paths`）、blocked の解除の判定（`find_plan_unblocks`・`content_after_write`・`apply_edit`・`PLAN_FILE_RE`）、使わなくなった import（`shlex` など）
- 残すもの：`deny`・`normalize`・`resolve_root`・`current_branch`・`plan_task_status`・`match_task_or_verdict_path`、`sys.dont_write_bytecode = True` と `_hooklib` の読み込みに失敗した時の終了コード2（smoke の `(hooklib-broken)`・`(hooklib-pycache)` が見ている）
- モジュールの docstring とコメントは3つの判定と委譲の説明に書き直す。受け入れ基準4の grep に当たる語（`transcript`・`gh api`・`vault/rules` など）は、「やめた」という説明でも書かない
- `_hooklib.py`：`human_messages`・`is_unblock_command` を削る。削る前に `grep -rn "human_messages\|is_unblock_command" .claude/hooks/ scripts/` で、`agent_write_guard.py` のほかに使う所が無いことを確かめる（計画作成時の調べでは無い）。ほかの関数（`existing_ancestor`・`git_toplevel`・`delegate_to_worktree`・`frontmatter_value`・`frontmatter_status`・`plan_id_and_status`・`approved_plans`・`raw_rows`・`parse_tasks`・`count_criteria`・`validate_verdict`・`done_rows_without_pass`）は `plan_guard.py`・`stop_gate.py`・`scripts/transition.py` が使うので残す（`raw_rows` は agent_write_guard から使われなくなるが plan_guard が使う）。モジュールの docstring に会話記録の関数の説明があれば合わせて直す
- `scripts/smoke.sh` と `docs/vault-spec.md` は変えない（T-02・T-03 の成果物）。T-01 の時点では smoke の agent_write_guard の節に NG が出るが、それは想定どおりで、このタスクの基準にしない
- 受け入れ基準1の done のタスク票は、マージ済みの計画 `P-20261009-auto-approve` の T-01（タスク表で done）を使う。done でない方は、この計画の T-02（T-01 の検証の時点では todo）を使う。どちらもファイルが無くても判定は計画票だけで決まる
