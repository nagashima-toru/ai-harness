# T-03 docs/install.md に permissions.allow 不足案内の挙動と影響・限界を書く

## 目的
導入先の `.claude/settings.json` にハーネスの許可が足りない時に note 行で案内されること、許可が入らない場合の影響、判定の限界を、利用者が install.md で読めるようにする。

## 入力
- `scripts/merge_settings_json.py`（T-01 の成果物。note 行の実際の文言）と T-01 タスク票の「決定済み」
- `docs/install.md`（109行目の段落、「ハーネスを更新する」節の142行目の箇条書き、145行目のバックアップの段落）

## 成果物
- `docs/install.md`（1ファイル）

## 受け入れ基準
- 新しい段落の見出し語が1つある：`grep -c '^\*\*`permissions.allow` の不足案内\*\*' docs/install.md` の出力が `1`
- 影響が1行で書かれている：`grep -c '^\*\*`permissions.allow` の不足案内\*\*.*`note`.*確認ダイアログ.*`claude -p`.*拒否' docs/install.md` の出力が `1`
- 完全一致の限界が例つきで書かれている：`grep -c '完全一致.*`Bash(git:\*)`.*`Bash(git \*)`' docs/install.md` の出力が `1` 以上
- 個人設定を読まないことが書かれている：`grep -c '`~/.claude/settings.json`.*読まない' docs/install.md` の出力が `1` 以上
- 142行目付近の箇条書きが note 案内に触れている：`grep -c '^- \*\*`.claude/settings.json`\*\*.*`permissions.allow` は変更しない.*`note`' docs/install.md` の出力が `1`
- 実際の note 行の書き出しが doc に載っている：`grep -c 'note .claude/settings.json: permissions.allow にハーネスが使う許可が' docs/install.md` の出力が `1` 以上

## 決定済み
- 「ハーネスを更新する」節の `merge_settings_json.py は書き換える時だけ ... .bak-<日時> を残す` の段落（145行目付近）の直後に、`**`permissions.allow` の不足案内**` で始まる段落を1つ足す。段落の本文は1行（改行しない）で、次をこの順で含める
  - ハーネス側 `.claude/settings.json` の `permissions.allow` のうち導入先に無いものがあれば、`merge_settings_json.py` が `note` 行で列挙する（`permissions.allow` 自体は変更しない）
  - 許可が入らないままだと、対話実行では確認ダイアログが出て、無人実行（`claude -p`）では拒否される。必要なら note に出た項目を手で `permissions.allow` に足す
  - 導入先に settings.json が無い（`create`）場合は丸ごと作られるので note は出ない
- 同じ段落か直後の段落に、次の2点を書く
  - 判定は文字列の完全一致で、パターンの包含関係は見ない。例として「導入先に `Bash(git:*)` があっても `Bash(git *)` は不足として出る」と書く（`Bash(git:*)` と `Bash(git *)` をこの順で同じ行に書く）
  - スクリプトは利用者の個人設定 `~/.claude/settings.json` を読まない（そこで許可していれば実際は確認が出ないこともある）。「`~/.claude/settings.json` は読まない」の語順で同じ行に書く
- note 行の例を1つ載せる。T-01 の実装を実際に動かした出力に合わせ、`note .claude/settings.json: permissions.allow にハーネスが使う許可が 2 件足りない: ...` の形で書く（コードブロックでも本文中のインラインコードでもよい）
- 142行目の箇条書き（`- **`.claude/settings.json`** は ...`）の末尾 `インストール先で足した `permissions.allow` は変更しない` は残し、その後に「不足があれば `note` 行で案内する（後述）」の旨を同じ行に足す
- 109行目の段落と、アンインストール節（164行目）は変えなくてよい
- `docs/vault-spec.md`・`scripts/` は変更しない（成果物は docs/install.md だけ）
- T-01 の実装の文言が「決定済み」の形と違っていた場合は、doc を実装に合わせず blocked にして question に書く
