# T-01 scripts/transition.py を新設し遷移・attempt・拒否条件・表と log の書き換え・コミットを実装する

## 目的
計画票のタスク表の状態遷移（status・attempt・question の書き換え、log への実時刻の追記、計画票と log だけのコミット）を1コマンドで行う `scripts/transition.py` を作る。log の日時をモデルが書く値ではなくスクリプトの実時刻にし、遷移の規則を機械で守る（D-012 フェーズ2）。review→done の verdict 検査とモデルの記録は T-02 で足す。

## 入力
- `vault/designs/D-012.md` の「決定事項」と「フェーズ2」（ゴール文・受け入れ基準の候補・決定済み）
- `.claude/hooks/_hooklib.py`（`frontmatter_status`・`frontmatter_value`・`raw_rows`・`parse_tasks`）
- `.claude/hooks/plan_guard.py`（`_hooklib` の import の仕方、タスク表の検査）
- `docs/vault-spec.md` の2節（状態・遷移・attempt・`HARNESS_MAX_ATTEMPTS`）・3節（ブランチ名・日時）・4節（タスク表）・7節（log の行の形）
- `vault/tasks/P-20261007-transition-basic/fixtures/try.sh`（確認用のフィクスチャ。使い方は先頭のコメント）

## 成果物
- `scripts/transition.py`（新規の1ファイルだけ。ほかのファイルは変えない）

## 受け入れ基準
- 2つの id を一度に doing にできる：`bash vault/tasks/P-20261007-transition-basic/fixtures/try.sh std P-TEST T-01,T-02 doing` の出力に `exit=0`・`new_commits=1`・`subject=P-TEST/T-01,T-02: todo→doing`・`commit_files=vault/log/P-TEST.md vault/plans/P-TEST.md `・`plan_guard=allow` の行があり、table 節に `| T-01 | doing | 1 | - | A | |` と `| T-02 | doing | 1 | - | B | |` があり、log 節の最後の2行が `- <日時> T-01 todo→doing attempt=1` と `- <日時> T-02 todo→doing attempt=1`（`<日時>` は出力の `before=` か `after=` の値）
- attempt の規則と補足：`try.sh std P-TEST T-04 doing` で table が `| T-04 | doing | 2 |…`・log の最後の行が `T-04 doing→doing attempt=2` で終わり、`try.sh std P-TEST T-07 doing` で `| T-07 | doing | 2 |…`、`try.sh std P-TEST T-04 review --note 補足の文` で `| T-04 | review | 1 |…`・log の最後の行が `T-04 doing→review attempt=1 補足の文` で終わる（いずれも `exit=0`。`try.sh` は1行目と同じパス）
- log が無ければ作り、ほかの staged な変更をコミットに混ぜない：`try.sh nolog P-TEST T-01 doing` で `exit=0`・`log_changed=yes`、log 節が `T-01 todo→doing attempt=1` の1行だけ。`try.sh staged P-TEST T-01 doing` で `exit=0`・`commit_files=vault/log/P-TEST.md vault/plans/P-TEST.md `・`staged=extra.txt `
- 次の各実行で `exit=1`・`new_commits=0`・`plan_changed=no`・`log_changed=no` になる：`try.sh std P-TEST T-01 todo`／`try.sh std P-TEST T-04 approved`／`try.sh std P-TEST T-10 doing`（blocked から）／`try.sh draft P-TEST T-01 doing`／`try.sh main P-TEST T-01 doing`／`try.sh std P-TEST T-03 doing`（after が done でない）
- 次の各実行でも `exit=1`・`new_commits=0`・`plan_changed=no`・`log_changed=no` になる：`try.sh std P-TEST T-05 doing`（attempt が上限3を超える）／`try.sh std P-TEST T-11 doing`（同）／`try.sh std P-TEST T-04 blocked`（question 無し）／`try.sh std P-TEST T-01,T-03 doing`（1つでも拒否なら全部変えない）
- question の書き方と引数の誤り：`try.sh std P-TEST T-04 blocked --question-file @QFILE` で `exit=0`・`plan_guard=allow`・table に `| T-04 | blocked | 1 | - | D | A／B 次の行 |` があり、`try.sh std P-TEST T-04 blocked --question x --question-file @QFILE` と `try.sh std P-TEST T-04 review --question x` と `try.sh std P-TEST` はどれも `exit=2`・`new_commits=0`
- 既存の smoke が変わらず通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=529 fail=0`

## 決定済み
- 呼び出しの形：`python3 scripts/transition.py <計画ID> <id>[,<id>...] <遷移先> [--question <文> | --question-file <パス>] [--note <補足>] [--no-model]`。引数は argparse で読み、位置引数の不足・未知のオプション・`--question` と `--question-file` の同時指定（相互排他グループ）は argparse の既定どおり終了コード2
- 引数の誤り（終了コード2）の検査は、リポジトリや計画票を読む前提の検査（終了コード1）より先に行う
- `_hooklib` の import：`sys.dont_write_bytecode = True` → `os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", ".claude", "hooks")` を `sys.path` の先頭に入れる → `import _hooklib`（D-011 の「`scripts/` から `_hooklib.py` を使わない」は D-012 で改めた）。import に失敗したら標準エラーに理由を出して終了コード1
- 計画票の frontmatter は `_hooklib.frontmatter_status`、タスク表の値は `_hooklib.parse_tasks` で読む。タスク表の解析規則を自前で複製しない。書き換えのために行の位置を探す処理だけは transition.py に書き、`raw_rows` と同じ規則（`## タスク表` で始まる見出しの節の中で、strip して `|` で始まる行の1つ目のセルが id）で探す
- 対象のリポジトリ：実行時のカレントディレクトリでの `git rev-parse --show-toplevel`。スクリプト自身の置き場所ではない（フィクスチャ・smoke は一時リポジトリに cd して `$ROOT/scripts/transition.py` を呼ぶ）。git でなければ終了コード1
- 前提の検査（どれかに当たれば何も変えずに終了コード1。理由は標準エラーに `[transition] ` で始まる1行以上で出す）：
  - `<root>/vault/plans/<計画ID>.md` が無い、または frontmatter の status が `approved` でない
  - 現在のブランチ（`git rev-parse --abbrev-ref HEAD`）が `work/` + 計画IDの英小文字 でない。main で `git commit` させないことはこの検査で担保する
  - id がタスク表に無い。渡した id の現在の status がそろっていない（コミットのメッセージの `<旧>→<新>` を1組にするため）
  - (現在の status, 遷移先) が遷移表に無い。遷移表は todo→doing、doing→doing、doing→review、doing→blocked、review→done、review→doing、review→blocked の7つだけ。`todo`・`approved`・未知の語を遷移先にした時、blocked・done の行からの遷移も、すべてこれに当たる（argparse の choices にはしない）
  - todo→doing で、その行の `after`（カンマ区切り。`-` か空なら依存無し）の id に、タスク表で status が `done` でないもの（表に無い id を含む）がある。同じ呼び出しで一緒に doing にする行は done ではないので満たさない
  - 遷移後の attempt が `HARNESS_MAX_ATTEMPTS`（環境変数。無い・整数でない時は3）を超える
  - 遷移先が blocked なのに question が無い（指定が無い、または下の置き換えの後に空）
  - T-01 の時点では review→done を「review→done は T-02 で verdict の検査を実装するまで扱えません」という趣旨の理由で拒否する（T-02 で verdict の検査に置き換える）
- id の引数：`,` で分けて前後の空白を落とす。空の要素や重複があれば引数の誤り（終了コード2）
- 遷移先が blocked でないのに `--question`／`--question-file` を渡したら引数の誤り（終了コード2）。`--question-file` が読めない時も終了コード2。ファイルは UTF-8 で読む
- attempt：todo→doing は1にする。doing→doing・review→doing は +1。それ以外（doing→review・doing→blocked・review→done・review→blocked）は変えない
- question 列：遷移先が blocked ならその question を書く。それ以外の遷移では空にする（`/plan unblock` が question を空にするのと揃える）
- question と `--note` の置き換え：`|` は `／`（全角）に、改行（`\r\n`・`\r`・`\n`）は半角空白1つに置き換え、前後の空白を落とす。例：`A|B\n次の行\n` → `A／B 次の行`
- 書き換える行は `| <id> | <status> | <attempt> | <after> | <title> | <question> |` の形にする（id・after・title は元のセルの値のまま、行頭の空白は保つ）。対象の行以外の行は1バイトも変えない（末尾の改行の有無も保つ）
- log：`<root>/vault/log/<計画ID>.md` に、渡した id の順に1行ずつ `- <日時> <id> <旧>→<新> attempt=<n>[ <補足>]` を追記する（`<n>` は遷移後の attempt、`<補足>` は `--note`）。ファイル（とディレクトリ）が無ければ作る。既存の内容が改行で終わっていなければ先に改行を1つ足す。`creator=`・`verifier=` は T-02 で足す。T-01 では `--no-model` を受け付けるだけで何もしない
- 日時：`datetime.datetime.now(datetime.timezone(datetime.timedelta(hours=9))).strftime("%Y-%m-%d %H:%M")`（UTC+9 固定。`TZ` 環境変数や `date` コマンドに頼らない）。1回の実行の全行で同じ値を使う
- 書き込みの順：すべての id の検査を先に済ませ（all-or-nothing）、通った時だけ計画票を書き、log に追記し、コミットする
- コミット：パスはリポジトリ相対で、計画票と log だけ（done の時の verdict は T-02 で足す）。`git add -- <パス...>` の後に `git commit -q -m "<計画ID>/<id,...>: <旧>→<新>" -- <パス...>`（`<id,...>` は渡した順にカンマでつなぐ。例：`P-TEST/T-01,T-02: todo→doing`）。パスを指定するので、ほかに staged な変更があってもコミットに混ぜない（staged のまま残る）。コミットは1回だけ
- `git add`・`git commit` が失敗したら、計画票と log を実行前の内容に戻し（log を新しく作った時は消す）、`git reset -q -- <パス...>` で index を戻し、git の標準エラーを添えて終了コード1
- 成功時は標準出力に id ごとに `<計画ID>/<id>: <旧>→<新> attempt=<n>` を1行ずつ出し、終了コード0
- 終了コード：0 遷移した／1 前提を満たさず何も変えていない／2 引数の誤り
- 承認（draft→approved）と blocked の解除（blocked→todo）は扱わない（blocked からの遷移は遷移表に無いので拒否になる）
- 標準ライブラリだけを使い、Python 3.9 で動く書き方にする（`match` 文や `X | Y` の型注釈は使わない）。ファイルの先頭に使い方・終了コードの docstring を書く
- `install.sh` は `scripts/` 直下の `*.py` を自動で配るので変えない。`scripts/smoke.sh`・`docs/vault-spec.md`・`.claude/skills/run/SKILL.md`・`.claude/hooks/` は変えない（smoke は T-03、文書は T-04。run の手順はフェーズ5）
- フィクスチャ `try.sh` は成果物ではない。変えない。`@QFILE` は中身が `A|B<改行>次の行` の一時ファイルのパスに置き換わる
