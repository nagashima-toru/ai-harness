# T-02 plan_guard.py の doing 判定を after 依存検査に置き換える

## 目的
`.claude/hooks/plan_guard.py` の「doing の行が2件以上ならブロック」という判定を、「doing/review の集合内に `after` 依存関係が張られていたらブロック」という判定に置き換える。対応する `scripts/smoke.sh` のケースも更新する。

## 入力
- `.claude/hooks/plan_guard.py`（`doing = [...]` `if len(doing) >= 2:` の判定部分、178〜199行付近の smoke.sh 実行部）
- `scripts/smoke.sh`（177〜199行付近の `== plan_guard.py ==` セクション、特に181〜182行の「(a) doing が2件 → ブロック」ケース）
- `vault/designs/D-003.md`（フェーズ1「決定済み」）

## 成果物
- `.claude/hooks/plan_guard.py`
- `scripts/smoke.sh` の `== plan_guard.py ==` セクションの対応ケース

## 受け入れ基準
- `plan_guard.py` から「doing が2件以上」でブロックする条件分岐が消えている。確認: `grep -c 'len(doing) >= 2' .claude/hooks/plan_guard.py` が0
- doing/review の複数行が `after` 依存を持たない計画票（例: T-01 doing after=-、T-02 doing after=-）では許可を返す（依存が無ければブロックしない、という回帰確認を兼ねる）
- doing/review のいずれかの行の `after` 列に、まだ `done` でない他の doing/review 行の id が含まれる場合はブロックする（例: T-01 doing after=-、T-02 doing after=T-01）
- doing 同士が相互に `after` で参照し合う場合もブロックする（例: T-01 doing after=T-02、T-02 doing after=T-01）
- 単一タスクのみが doing の既存シナリオ（依存が無い1件）の判定結果が変更前と同じ（許可）である
- 上記4つの新規・回帰ケースは `scripts/smoke.sh` に追加・修正されており、`bash scripts/smoke.sh | tail -1` の出力で fail=0 になる

## 決定済み
- 依存判定のアルゴリズム：doing/review の各行について、その行の `after` 列（カンマ区切り、`-` は依存無し）に列挙された id のうち、タスク表内に実在し、かつその行の status が `done` でないものが1つでもあれば、その doing/review 行の存在自体をブロック理由とする。`after` が指す id がタスク表に存在しない場合や `done` の行を指す場合はブロックしない
- 判定順序や1回のブロックで報告する範囲（最初に見つかった違反1件を reason に書く／複数まとめて書く）は実装の裁量に委ねる。ブロック時の reason には該当する id の組を含めること
- 計画票の列構成・見出し（`id | status | attempt | after | title | question`）、他の既存判定（blocked の question 空・status 5値外・id 重複・列数6でない・approved 重複）は変更しない
- `scripts/smoke.sh` の既存ケース「(a) doing が2件 → ブロック」（181〜182行）は、依存の無い2件を許可に、依存のある2件をブロックにする形へ書き換えてよい（ケース名・コメントも実態に合わせて変更してよい）
- `HARNESS_MAX_PARALLEL` 環境変数はこのタスクでは導入しない
