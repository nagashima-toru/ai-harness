# T-01 計画のタスク履歴表を PR 本文として出力する scripts/pr_body.py を作る

## 目的
計画 ID を受けて、その計画のタスクごとの一覧（id・title・コミット・verdict）を Markdown で標準出力に出す。T-02 で `scripts/vcs_finish.sh` が PR/MR 本文に使い、スカッシュマージ後も PR 本文から履歴を辿れるようにする。

## 入力
- `vault/plans/<計画ID>.md` のタスク表（`docs/vault-spec.md` 4節）
- `vault/verdicts/<計画ID>/<id>.json`（`docs/vault-spec.md` 6節）
- `.claude/skills/run/SKILL.md` 手順6.3.4（done コミットのメッセージ `<計画ID>/<id>: done`）
- 動作確認用の既存データ：`vault/plans/P-20261004-hooklib-rules.md`、`vault/verdicts/P-20261004-hooklib-rules/`、ローカルブランチ `work/p-20261004-hooklib-rules`（`P-20261004-hooklib-rules/T-01: done` は `74da76b`）

## 成果物
- `scripts/pr_body.py`（新規。この1ファイルだけ）

## 受け入れ基準
- `python3 scripts/pr_body.py P-20261004-hooklib-rules work/p-20261004-hooklib-rules | grep -c -F '| id | title | commit | verdict |'` の出力が `1`
- `python3 scripts/pr_body.py P-20261004-hooklib-rules work/p-20261004-hooklib-rules | grep -c '^| T-0[1-8] | .* | [0-9a-f]\{7,\} | PASS (attempt=1) |$'` の出力が `8`（全タスクに done コミットと verdict が入る）
- `python3 scripts/pr_body.py P-20261004-hooklib-rules work/p-20261004-hooklib-rules | grep -c '^| T-01 | .* | 74da76b[0-9a-f]* | PASS (attempt=1) |$'` の出力が `1`（コミット列が `P-20261004-hooklib-rules/T-01: done` のコミットを指す）
- rev を省くと HEAD で探す：`python3 scripts/pr_body.py P-20261004-hooklib-rules | grep -c '^| T-0[1-8] | .* | - | PASS (attempt=1) |$'` の出力が `8`（main にはスカッシュされて done コミットが無いため、コミット列が `-` になる）
- 行の順が計画票のタスク表の順と同じ：`python3 scripts/pr_body.py P-20261004-hooklib-rules | grep -o '^| T-0[0-9]'` の出力が上から T-01, T-02, T-03, T-04, T-05, T-08, T-06, T-07 の順
- `python3 scripts/pr_body.py P-00000000-none` が終了コード0以外で終わり、標準エラーに `計画票` を含むメッセージを出し、標準出力に何も出さない

## 決定済み
- 使い方は `python3 scripts/pr_body.py <計画ID> [<rev>]`。`<rev>` はコミットを探す起点で、省略時は `HEAD`。引数の数が違う時は使い方を標準エラーに出して終了コード2
- リポジトリのルートは、カレントディレクトリでの `git rev-parse --show-toplevel` で決める（スクリプトの置き場所からは決めない。T-02 の smoke では別の一時リポジトリから呼ぶため）。そこから `vault/plans/<計画ID>.md`・`vault/verdicts/<計画ID>/<id>.json` を読む
- 計画票が無い・読めない時は、標準エラーに `pr_body.py: 計画票がありません: vault/plans/<計画ID>.md` の形で出し、終了コード1。標準出力には何も出さない
- タスク表の読み方：`| id | status | attempt | after | title | question |` の見出し行の後のデータ行（行頭の空白を許す。区切り行 `|---|` は飛ばす）。1列目が `T-` で始まる行だけを取り、表の順に出す。`.claude/hooks/_hooklib.py` は import せず、このファイルの中で読む（`scripts/` だけで完結させる）
- 出力の形（この見出し・文言で書く）：
  ```
  ## タスク履歴

  計画: `<計画ID>`（計画票 `vault/plans/<計画ID>.md`、ログ `vault/log/<計画ID>.md`）

  | id | title | commit | verdict |
  |---|---|---|---|
  | T-01 | <title> | <短縮ハッシュ> | PASS (attempt=1) |
  ```
- commit 列：`git log --format=%h -n 1 --grep='^<計画ID>/<id>: done$' <rev>` の結果（subprocess でリストとして渡し、シェルを通さない）。見つからない・git が失敗した時は `-`
- verdict 列：verdict の JSON の `result` と `attempt` から `<result> (attempt=<attempt>)`。ファイルが無い・JSON として読めない・キーが無い時は `-`
- title に `|` があれば `\|` にする。status 列・question 列は出さない（ゴールの4項目だけ）
- ファイルには一切書き込まない（標準出力だけ）。依存は標準ライブラリだけ
- 確認に使う `work/p-20261004-hooklib-rules` ブランチは計画作成時点でローカルに存在する（`git branch` で確認済み）。基準4は、main がその計画をスカッシュマージしているので HEAD からは done コミットが辿れない、という今の事実に依る
