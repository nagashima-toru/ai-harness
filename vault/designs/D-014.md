# ゴール

ハーネス自身の保護領域（`.claude/skills/`・`.claude/hooks/`・`.claude/agents/`・`.claude/settings.json`）を変更する計画が、環境（ローカルのサンドボックス・Web）によらず人の手作業なしで取り込めるようにする。D-013 フェーズ6〜7 の実作業で起きた次の5つを片づける。

- `transition.py` の done の `git merge` が、成果物に `.claude/hooks/` を含むと「Operation not permitted」で失敗し、PASS 済みのタスクが blocked になる
- `git checkout`・`git pull --rebase` が保護ファイルの更新で途中で止まり、HEAD と作業ツリーが食い違う
- その状態で `plan_guard.py` が「承認が会話記録に無い」と誤検知し続け、`stop_gate.py` も未コミットでブロックし続ける
- 復旧に使う `git reset --hard`・`git clean`・`git branch -D` が `permissions.deny` で止まり、人がターミナルを使えないと直せない
- Web の auto モードでは `.claude/` 配下の編集が分類器の「Self-Modification」で拒否される

## 決定事項

| 決めたこと | なぜ |
|---|---|
| サンドボックスの保護パス（`.claude/hooks/`・`.claude/skills/`・`.claude/agents/`・`.claude/settings.json`）を `sandbox.filesystem.allowWrite` で書けるようにする。保護するのは、ハーネス自身の作業で書く必要が無い `vault/rules/` と `~/.claude/projects/`（既存の `denyWrite`）に絞る | 人の回答「サンドボックスなんだから保護しなくていい」。ハーネスは自分自身を作業対象にするので、標準の保護とは目的がぶつかる。フックの書き換えは `agent_write_guard.py` と差分ゲート（宣言外のパスの変更を拒否）が見張る。なお `allowWrite` が Claude Code の標準の保護より優先されるかは未確認で、フェーズ1で人が確かめる（調査に基づく設計判断） |
| 特定の環境（Web・acceptEdits）を前提にしない。ローカルのサンドボックス・Web のどちらでも、同じ手順で保護領域の変更が通る設計にする | 人の回答「環境によらない設計」。Web の auto モードの分類器（Self-Modification）は設定で変えられないので、拒否された時は creator が blocked にして理由を書き、runbook に acceptEdits で立ち上げ直す手順を書くところまでを扱う |

## フェーズ1 サンドボックスの保護パスを書けるようにする

### ゴール文

`.claude/settings.json` の `sandbox.filesystem` に `allowWrite` を足し、`.claude/hooks`・`.claude/skills`・`.claude/agents`・`.claude/settings.json` を入れる（`denyWrite` の `./vault/rules`・`~/.claude/projects` は変えない）。あわせて `docs/runbook.md` 9節に、新しいセッションで人が確かめる手順を足す（保護領域のファイルへ Bash で書けること、`git merge` が保護領域の変更を含むブランチで通ること、`vault/rules/` へは書けないままであること）。確かめて `allowWrite` が保護パスに効かなかった時の記録先も runbook に書く。`docs/vault-spec.md` 12節の「サンドボックス」の小節も合わせる。

### 受け入れ基準の候補
- `.claude/settings.json` の `sandbox.filesystem.allowWrite` に `.claude/hooks`・`.claude/skills`・`.claude/agents`・`.claude/settings.json` が入っている。確認：`python3 -c "import json;print(json.load(open('.claude/settings.json'))['sandbox']['filesystem']['allowWrite'])"`
- `sandbox.filesystem.denyWrite` は `./vault/rules` と `~/.claude/projects` のまま。`enabled: true`・`allowUnsandboxedCommands: false` も変わっていない（同じ `python3 -c` で確認）
- `docs/runbook.md` 9節に、保護領域への書き込みと保護領域を含む `git merge` を確かめる手順（期待する結果つき）と、効かなかった時に記録する場所が書かれている。確認：`grep -n "allowWrite" docs/runbook.md`
- `docs/vault-spec.md` 12節の「サンドボックス」の小節に `allowWrite` の説明があり、「保護領域は書けない」とする記述が残っていない
- `bash scripts/install.sh <一時ディレクトリ>` の後、導入先の `.claude/settings.json` に `sandbox` キーが無い（既存の smoke のケースが PASS する。`bash scripts/smoke.sh | tail -1` が `fail=0` を含む）

### 決定済み
- パスの書き方は、既存の `denyWrite`（`./vault/rules`・`~/.claude/projects`）と同じ形式。`allowWrite` にはリポジトリの相対パスで入れる
- `agent_write_guard.py` の判定・差分ゲートは変えない。保護領域への書き込みは、これまでどおり宣言した成果物のパスだけが通る
- `.claude/worktrees/` は `allowWrite` に入れない（worktree はサンドボックスの外で作る運用が既にある）
- 効き目は creator・verifier のセッションの中では確かめられない（設定はセッション開始時に読まれる）。このフェーズの受け入れは設定の形と文書まで。効き目はマージ後に人が runbook の手順で確かめる
- `allowWrite` が保護パスに効かないと分かった場合は、人が結果を `vault/designs/D-014.md` の末尾ではなく、新しい設計文書（D-015）の入力にする。フェーズ2以降は `allowWrite` の効き目に依存しないので、そのまま進めてよい
- `transition.py`・`vcs_finish.sh`・`discard_worktree.sh` の `excludedCommands` は変えない

## フェーズ2 半端な git 状態を検出して案内する

### ゴール文

読み取り専用の診断スクリプト `scripts/git_state_check.sh` を作る。次を検出して、1件ずつ「状態」と「復旧手順」を出力する。

- detached HEAD
- `MERGE_HEAD`・`REBASE_HEAD`・`CHERRY_PICK_HEAD` が有る（途中で止まった操作）
- HEAD と作業ツリーの食い違い（`git status` に出る、HEAD に無い承認済みの計画票・保護領域の変更の取り残し）
- 現在のブランチが `work/<計画ID>` なのに、承認済みの計画票が HEAD に無い

復旧手順は、`git merge --abort`・`git rebase --abort`・`git restore`・`git checkout` など非破壊のものを先に出し、その後に破壊的な `git reset --hard`・`git clean`（フェーズ4で作業ブランチ上では通る）を「最後の手段」として出す。何も検出しなければ `git_state_check: 異常なし` を出して終了コード0。`docs/runbook.md` の「困ったとき」に症状を足し、`scripts/smoke.sh` にケースを足す。

### 受け入れ基準の候補
- 一時リポジトリで正常な状態に対して実行すると、`git_state_check: 異常なし` を出して終了コード0になる（smoke のケース）
- 一時リポジトリで `MERGE_HEAD` が有る状態（衝突を起こして merge を止める）に対して、終了コード1で `git merge --abort` を案内する（smoke のケース）
- 一時リポジトリで detached HEAD の状態に対して、終了コード1でブランチへの戻し方を案内する（smoke のケース）
- スクリプトは git の状態を変えない。確認：実行の前後で `git status --porcelain` と `git rev-parse HEAD` が変わらない（smoke のケースで比べる）
- `docs/runbook.md` の「困ったとき」に、HEAD と作業ツリーが食い違う症状と `bash scripts/git_state_check.sh` が書かれている。`bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- 引数なしで現在のリポジトリを見る。`git` が使えない・リポジトリでないときは終了コード2で標準エラーに理由を出す
- 終了コード：0 異常なし／1 異常あり（案内を標準出力に出す）／2 実行できない
- `settings.json` の `permissions.allow` の `Bash(bash scripts/*)` で通る。`excludedCommands` には入れない（読み取りだけなので、サンドボックスの中で動けばよい）
- smoke のフィクスチャは `$TMPDIR` の下に `mktemp -d "${TMPDIR:-/tmp}/..."` で作る（D-013 の規約。作れなければ中断）
- 復旧手順の文は日本語。コマンドは `git branch --show-current` などで現在のブランチ名を埋めて、そのまま貼れる形にする

## フェーズ3 フックの誤検知を抑え、半端な状態を案内する

### ゴール文

`.claude/hooks/plan_guard.py` の承認の裏付けの検査に、半端な git 状態の判定を足す。`MERGE_HEAD`・`REBASE_HEAD`・`CHERRY_PICK_HEAD` が有る、または detached HEAD の時は、「承認が会話記録に無い」のブロックをやめて、警告（`additionalContext` 相当）に落とし、`bash scripts/git_state_check.sh` を案内する。それ以外の時は今のままブロックする（人の指示なしに承認が通る抜け道を作らない）。`.claude/hooks/stop_gate.py` は、未コミットでブロックする理由に、半端な状態なら `bash scripts/git_state_check.sh` の案内を足す。共通の判定は `_hooklib.py` に置く。`docs/vault-spec.md` 9節・10節の判定表と合わせる。

### 受け入れ基準の候補
- 承認済みの計画票が作業ツリーにだけ有り、会話記録に承認の指示が無い通常の状態は、今までどおりブロックされる（smoke の既存ケースが PASS する）
- 同じ状態で `MERGE_HEAD` が有る時は、ブロックせず、理由に `git_state_check.sh` を含む警告を出す（smoke のケース）
- 同じ状態で detached HEAD の時も同様に警告になる（smoke のケース）
- `stop_gate.py` は、未コミットの変更があって `MERGE_HEAD` が有る時、ブロックの理由に `git_state_check.sh` を含む（smoke のケース）
- 半端な状態の判定は `_hooklib.py` の1か所にあり、`plan_guard.py`・`stop_gate.py` の両方がそれを使う。確認：`grep -n "def is_partial_git_state" .claude/hooks/_hooklib.py`
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- 半端な状態の判定は git の状態（`rev-parse --git-path MERGE_HEAD` などの有無、`symbolic-ref -q HEAD` の失敗）だけで決める。会話記録・ファイルの内容では決めない（人の指示なしに承認が通るのを防ぐため）
- `_hooklib` が読み込めない時の扱いは今のまま（理由を標準エラーに出して終了コード2）
- `stop_gate.py` のブロックを許可に変えない。案内を足すだけ
- worktree への委譲（`delegate_to_worktree`）の動きは変えない
- 診断スクリプトが無い導入先（古いハーネス）でも、案内の文だけが出る。スクリプトの存在は検査しない

## フェーズ4 deny を緩め、フックで守る

### ゴール文

`.claude/settings.json` の `permissions.deny` から `Bash(git reset --hard*)`・`Bash(git clean *)`・`Bash(git branch -D *)` を外す（`git push --force` 系・`rm -rf` 系・`gh pr merge` などは残す）。代わりに `.claude/hooks/agent_write_guard.py` の Bash の解析で、次を拒否する。

- 現在のブランチが `main`・`master` の時の `git reset --hard`・`git clean`
- `git branch -D`・`git branch -d` の対象が `main`・`master`・現在のブランチの時
- `git clean` に `-x`・`-X`（無視ファイルの削除）が付く時

`docs/runbook.md` の「困ったとき」に、人がターミナルを使えなくてもエージェントが復旧できる手順を足し、`docs/vault-spec.md` 12節の記述（deny の一覧）を合わせる。

### 受け入れ基準の候補
- `.claude/settings.json` の `permissions.deny` に `git reset --hard`・`git clean`・`git branch -D` が無く、`git push --force` 系・`rm -rf` 系・`gh pr merge*`・`glab mr merge*` は有る。確認：`python3 -c` で `permissions.deny` を表示する
- `agent_write_guard.py` は、現在のブランチが `main` の時の `git reset --hard` を拒否し、`work/<計画ID>` の時は許可する（smoke のケース）
- `git branch -D main` と `git branch -D <現在のブランチ>` を拒否し、別の作業ブランチの `-D` は許可する（smoke のケース）
- `git clean -fdx` は拒否し、`git clean -fd` は作業ブランチで許可する（smoke のケース）
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- 現在のブランチは、フックの `cwd`（worktree なら worktree のブランチ）で `git branch --show-current` を取って決める。取れない時（detached HEAD）は拒否側に倒す
- 拒否の理由文には、代わりに使える非破壊のコマンド（`git restore`・`git switch`）を含める
- `git reset --hard` の引数（`origin/main` など）は見ない。ブランチだけで分ける
- `permissions.allow` の `Bash(git *)` は変えない
- `agent_write_guard.py` の既存の Bash 書き込み解析（D-013）は変えない。拒否条件を足すだけ

フェーズ3（同じ `.claude/hooks/` を変えるため）

## フェーズ5 環境によらない手順を文書にまとめる

### 受け入れ基準の候補

- 導入先の `settings.json` への既定の追加（`merge_settings_json.py` は変えない）
