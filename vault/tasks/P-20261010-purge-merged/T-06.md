# T-06 README・install.md・decisions.md を直し archive の残りを確かめる

## 目的
README と `docs/install.md` から archive の記述を除き、`docs/decisions.md` に archive 廃止の判断を追記する。あわせて、ゴールの範囲（docs・.claude・scripts・README.md）に archive_plans と archive の古い記述が残っていないことを確かめる。

## 入力
- `vault/designs/D-016.md` の「フェーズ2」と「決定事項」
- `README.md`（「## 構成」のコードブロックの `vault/` と `scripts/` の行）
- `docs/install.md`（複製されるものの段落・`vault/` を追跡する勧めの段落・uninstall が触れない利用者資産の段落）
- `docs/decisions.md`（表の末尾）
- T-01〜T-05 の成果物（`scripts/purge_plan.sh`・`docs/runbook.md` 5節・`docs/vault-spec.md`）

## 成果物
- `docs/decisions.md`（主な成果物。行を1つ追記する）
- `README.md`（「## 構成」の2行）
- `docs/install.md`（archive の記述3か所）

## 受け入れ基準
1. ゴールの範囲に `archive_plans` が残っていない（過去の判断の記録 `docs/decisions.md` を除く）。確認：`grep -rn 'archive_plans' docs .claude scripts README.md --exclude=decisions.md` の出力が空
2. ゴールの範囲に archive の配置・集計・空ディレクトリの古い記述が残っていない。確認：`grep -rnE 'archive/<年-月>|archive/\*/log|archive/\.gitkeep|designs/archive|designs,archive|`archive/`|、archive/、' docs .claude scripts README.md --exclude=decisions.md` の出力が空
3. README と docs/install.md に `archive` の語が無く、README の `scripts/` の行が purge_plan.sh を挙げている。確認：`grep -n 'archive' README.md docs/install.md` の出力が空、`grep -c 'purge_plan.sh（計画一式の除去とマージ済みの一括削除）' README.md` が `1`
4. decisions.md に archive 廃止の行が1行追記され、2026-10-03 の archive_plans.sh を足した行は書き換えられていない。確認：`grep -c '^| [0-9-]* | 2026-10-03 の `scripts/archive_plans.sh` を廃止し、`scripts/purge_plan.sh --merged` に置き換える' docs/decisions.md` が `1`、`grep -c '^| 2026-10-03 | 2026-09-17 の「月次 archive はスクリプト化せず runbook の手順（`git mv`）のみ」を置き換え、`scripts/archive_plans.sh` を足す' docs/decisions.md` が `1`
5. smoke 全体が通る。確認：`bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<数> fail=0` の形

## 決定済み
- README の「## 構成」：`vault/` の行の `、archive/` を消す。`scripts/` の行の `、archive_plans.sh（古い計画の移動）` を `、purge_plan.sh（計画一式の除去とマージ済みの一括削除）` に置き換える（この文字列のまま。受け入れ基準3）。ほかの行・ほかの節は変えない
- docs/install.md：
  - 複製されるものの段落の `vault/{plans,tasks,verdicts,log,designs,archive,templates,rules}` を `vault/{plans,tasks,verdicts,log,designs,templates,rules}` にする
  - `vault/` を追跡する勧めの段落の `` / `archive/` `` を消す
  - uninstall の段落の `` `plans`/`tasks`/`verdicts`/`log`/`designs`/`archive` `` を `` `plans`/`tasks`/`verdicts`/`log`/`designs` `` にする
  - ほかに `archive` の語があれば同じ趣旨で除く
- decisions.md：表の末尾に1行追記する。書式は既存の行と同じ `| <日付> | <何を> | <なぜ> |`。日付は作業した日（JST、`YYYY-MM-DD`）。「何を」の列は次の文字列で始める：`2026-10-03 の `scripts/archive_plans.sh` を廃止し、`scripts/purge_plan.sh --merged` に置き換える`（続けて、`--list`・`--report`・`--apply` を持ち、`main` にマージ済みの計画一式と `vault/archive/` を一括で `git rm` すること、`--keep` は持たないこと、`--apply` は人が実行することを書く。D-016 フェーズ2）。「なぜ」の列：計画一式は run の手順7で PR の前に除去するので `main` に溜まらなくなり、archive に移して残す理由が無くなった（D-016 の決定事項「既存の分も削除する。archive_plans.sh は廃止する」、人の選択）。他の計画の done のタスク票・verdict を消すのはフックと差分ゲートを通らない経路になるので、実行は人が行う
- decisions.md の過去の行（2026-09-17 の月次 archive の行、2026-10-03 の archive_plans.sh の行など）は書き換えない（D-016 の決定済み）。そのため受け入れ基準1・2は `--exclude=decisions.md` で decisions.md を除く
- 受け入れ基準1・2で除かずに残るもの（直さない）：`scripts/model_stats.py` の docstring の「vault/archive/ 配下は含めない」（D-016「model_stats.py のコードは変えない」）、smoke の `(ms-2)` と install.sh のマニフェストの検査の `vault/archive/`（パスの例として使っているだけ）、`scripts/purge_plan.sh` の `vault/archive/`（削除の対象として扱う）、runbook 5節と vault-spec 1節の `--merged --apply` の説明の `vault/archive/`。どれも受け入れ基準2のパターンには一致しない
- 受け入れ基準1・2が空にならない時は、原因が T-02〜T-05 の成果物（`scripts/`・`docs/runbook.md`・`docs/vault-spec.md`）にあっても、このタスクでは直さない。`blocked` にして question に一致した行を書く（このタスクの成果物は上の3ファイルだけ）
- `vault/` 配下（計画一式・`vault/archive/`・`vault/designs/`・`vault/rules/`）は確認の範囲に入れない。計画一式と `vault/archive/` はこの計画のマージ後に人が runbook 5節の手順で消し、設計文書は D-016 フェーズ3で扱うため
- `.claude/` 配下に archive の記述は2026-10-10 時点で無い（`grep -rn 'archive' .claude` が空）。見つかった場合は blocked にする
