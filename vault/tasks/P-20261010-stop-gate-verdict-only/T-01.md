# T-01 stop_gate.py から未コミットの変更でのブロックを削り smoke のケースを直す

## 目的
`.claude/hooks/stop_gate.py` の判定を、worktree への委譲・`stop_hook_active`・approved な計画票の件数・done の行の verdict・doing/review の行の verdict だけにする。未コミットの変更があってもブロックしないことを smoke で確かめる。

## 入力
- `vault/designs/D-015.md` の「## フェーズ4 stop_gate を verdict の検査だけにする」
- `.claude/hooks/stop_gate.py`（`has_uncommitted_changes` と、`main()` の件数判定の直後にあるその呼び出し、docstring の判定順）
- `scripts/smoke.sh`（`sg_plan` の後の (f)・(g) のケース、`(stop-scope-1)`・`(stop-scope-2)` の前のコメント、`(delegate stop_gate)` の前のコメント、`(stop_gate worktree)` のケース）

## 成果物
- `.claude/hooks/stop_gate.py`（主な成果物。未コミットの判定を削る）
- `scripts/smoke.sh`（未コミットのケースをブロックしない形に直す）

## 受け入れ基準
- `stop_gate.py` に未コミットの判定の名残（関数名・文言・`git status`）が無い。確認：`grep -c "has_uncommitted_changes\|未コミット\|git status" .claude/hooks/stop_gate.py` の出力が `0`
- `has_uncommitted_changes` を参照する所が `.claude`・`scripts`・`docs` に無い。確認：`git grep -n has_uncommitted_changes -- .claude scripts docs` の出力が空
- 承認済みの計画票が1件・未コミットの変更あり・doing/review の行が無い git リポジトリで許可する。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (f) 未コミットの変更がある・doing/review の行が無い → 許可$'` の出力が `1`
- 未コミットの変更があっても doing の行の verdict の判定へ進む。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (f2) 未コミットの変更がある・doing の行の verdict が無い → ブロック（verdict の判定）$'` の出力が `1`
- worktree（`.git` がファイル）で未コミットのファイルがあっても許可する。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (stop_gate worktree) 未コミットのファイルがある → 許可$'` の出力が `1`
- done の行の verdict の検査（5件）と approved の件数の検査（2件）の既存ケースが通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (done-verdict stop_gate)\|^  ok   (stop-scope-'` の出力が `7`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- `has_uncommitted_changes` は関数ごと削り、`main()` の呼び出し（`block(...未コミットの変更があります...)` の if 文）も削る。`import subprocess` はこの関数でしか使っていないので削る（ほかで使うなら残す）
- 判定順は「委譲 → `stop_hook_active` → approved な計画票の件数 → done の行 → doing/review の行」。approved が0件なら許可、2件以上なら件数でブロック、1件なら done の行の検査へ進む。この3つの分岐は今の挙動のまま変えない
- docstring の判定順の段落は上の順に書き直す。`stop_gate.py` の中には「未コミット」という語も `git status` という文字列も残さない（コメント・docstring を含む）
- `HARNESS_STRICT_STOP`・`HARNESS_MAX_ATTEMPTS` の読み方、`_hooklib` の読み込み失敗時の扱い、done の行・doing/review の行の判定とメッセージは変えない。`scripts/run_unattended.py` は変えない（成果物にも入れない）
- smoke の直し方（ケース名は受け入れ基準の文字列と完全に同じにする。`expect` は `  ok   <ケース名>` を出す）
  - (f)：名前を `(f) 未コミットの変更がある・doing/review の行が無い → 許可` にし、期待を `allow` にする（部分文字列の引数は付けない）
  - (f2)：新しく足す。承認済みの計画票（`T-0001` が `doing`・attempt `1`）を置いてコミットした git リポジトリに未コミットのファイルを置き、verdict は置かない。名前は `(f2) 未コミットの変更がある・doing の行の verdict が無い → ブロック（verdict の判定）`、期待は `block`、部分文字列は `verdict が無い`。計画票は `sg_plan` を使わず、その場で `printf` などで書いてよい（`sg_plan` 自体は変えない。ほかのケースが使うため）。一時ディレクトリは既存と同じく `smoke_tmpdir` で作り、後片付けも既存のケースと同じ書き方でよい
  - (g)：名前・期待とも今のまま（`(g) 未コミットの変更が無い → 許可（既存判定へ進む）`）
  - `(stop-scope-1)`・`(stop-scope-2)` は名前・期待とも今のまま。前のコメント「未コミットの検査より先に件数で判定する」は、未コミットの変更があっても件数だけで判定することを表す文に直す
  - `(stop_gate worktree) 未コミットのファイルがある → ブロック` は、名前を `(stop_gate worktree) 未コミットのファイルがある → 許可` にし、期待を `allow` にする（部分文字列の引数は外す）。前提の `.git` がファイルであることの確認と、`(stop_gate worktree) ファイルを消す → 許可` は残す
  - `(delegate stop_gate)` の前のコメントから、`has_uncommitted_changes()` と未コミット変更ブロックが先に発火するという説明を削る（事前の commit の手順自体は消さなくてよい）
- ほかの smoke のケース（`diff_gate`・`transition-wt` の「未コミット」を含むケースなど）は変えない
- `docs/vault-spec.md` は T-02 で直すので、このタスクでは変えない
