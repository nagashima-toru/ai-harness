# T-02 plan スキル C.3 に、他の未着手タスク票の「決定済み」への追記を足す

## 目的
`/plan unblock` の回答が、解除する1タスクだけでなく他の未着手タスクの前提も変える時に、それらの票の「決定済み」にも同じ回答を残す。こうして、古い手順が残った後続タスクがまた blocked になるのを防ぐ（issue #102 の3つ目の提案）。

## 入力
- `.claude/skills/plan/SKILL.md`（「## C. blocked を解除する」の手順3）
- `docs/vault-spec.md`（2節の状態、12節の done の書き込み拒否）

## 成果物
- `.claude/skills/plan/SKILL.md`（手順 C.3 の1行だけを変える）

## 受け入れ基準
- C.3 の行に、他の未着手タスク票への追記の文がある。確認：`grep -n '^3\. 回答があれば.*同じ前提を持つ未着手（todo）のタスク票の「決定済み」にも同じ回答を追記する' .claude/skills/plan/SKILL.md` の出力がちょうど1行
- C.3 の行に、追記した票を手順6の add に含めるという文がある。確認：`grep -n '^3\. 回答があれば.*追記した票は手順6の git add に名前を指定して含める' .claude/skills/plan/SKILL.md` の出力がちょうど1行
- C.3 の行に、todo 以外の票には追記しないという文がある。確認：`grep -n '^3\. 回答があれば.*todo 以外の票には追記しない' .claude/skills/plan/SKILL.md` の出力がちょうど1行
- C.3 の既存の文が残っている。確認：`grep -c -F -e '回答の内容で受け入れ基準を直す必要がある時は、回答に基づく追記までにとどめ、大きな書き換えは planner を呼ぶよう案内する' .claude/skills/plan/SKILL.md` が `1`
- 変わったのは C.3 の1行だけ（他の手順・見出しは変えていない）。確認：`git diff --numstat 9ead5b8 -- .claude/skills/plan/SKILL.md` の出力が `1	1	.claude/skills/plan/SKILL.md` の1行（追加1・削除1）

## 決定済み
- 変えるのは C.3 の行（`3. 回答があれば、タスク票 …` で始まる行）だけ。行を分けず、既存の文の末尾（「…大きな書き換えは planner を呼ぶよう案内する」の後ろ）に句点を付けて続ける。C の他の手順（1・2・4〜7）、A・B、見出し、「1回のコマンドで解除するのは1行だけ。…」の行、「## 注意」は変えない
- 足す文はこれにする（一字一句同じでなくてよいが、受け入れ基準の3つの文字列「同じ前提を持つ未着手（todo）のタスク票の「決定済み」にも同じ回答を追記する」「追記した票は手順6の git add に名前を指定して含める」「todo 以外の票には追記しない」はこのまま含める）：
  `回答が、解除する <id> 以外のタスクにも効く前提（手順・使うツール・確認コマンドの書き方など）を変える時は、計画票のタスク表を見て、同じ前提を持つ未着手（todo）のタスク票の「決定済み」にも同じ回答を追記する。追記した票は手順6の git add に名前を指定して含める。todo 以外の票には追記しない（done の票はフックが書き込みを拒否する。doing・review・blocked の票はそれぞれの流れで扱う）`
- `<id>` はスキル内の既存の書き方に合わせてバッククォートで囲んでよい（`` `<id>` ``）。ただし「todo 以外の票には追記しない」の部分には、バッククォートを入れない（grep の文字列と一致させるため）
- 手順6の文面は変えない（追記した票を add に含めることは C.3 の文の中で指示する）
- 「同じ前提を持つ」かどうかの判断基準を細かく定めない（オーケストレーターが回答とタスク票の「決定済み」・「受け入れ基準」を読んで判断する）
- 確認コマンドの基準 9ead5b8 は、このブランチを `main` から切った時のコミット（作業ツリーの未コミット分も比べる）。`git diff main` は使わない（`main` が進むと関係ない差分が出るため）
