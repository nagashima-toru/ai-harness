# T-01 run 手順7に PR の購読（手順7の8）を足し、完了報告に監視の結果を含める

## 目的
`/run` が PR を作った直後、実行環境に `subscribe_pr_activity` ツールがあれば作った PR を購読して監視を始めるようにし、その結果を完了報告に含める（GitHub Issue #222）。

## 入力
- `.claude/skills/run/SKILL.md`（`## 7. 次へ・完了` の小番号1〜8と、その後ろの2つの箇条（引数なしの `vcs_finish.sh`・`gh`/`glab` が無い時の MCP 代替））
- `docs/vision.md`（原則7：ハーネス本体はドメイン知識を持たない）

## 成果物
- `.claude/skills/run/SKILL.md`（1ファイル。`## 7. 次へ・完了` の小番号の8を新設し、今の8（完了報告）を9に繰り下げる）

## 受け入れ基準
- 手順7の小番号8が1つだけで、それが PR の監視である：`grep -c '^  8. ' .claude/skills/run/SKILL.md` が `1`、かつ `grep -c '^  8. PR の監視：手順7で GitHub の PR を作った時' .claude/skills/run/SKILL.md` が `1`
- 手順7の8に購読と解除の呼び出しが書かれている：`grep -c '^  8. PR の監視：.*subscribe_pr_activity. を1回呼んで購読する.*unsubscribe_pr_activity. で購読を解除する' .claude/skills/run/SKILL.md` が `1`
- 手順7の8に対象外の場合と、購読後の対応を実行環境の指示に任せることが書かれている：`grep -c '^  8. PR の監視：.*ホスティング無し（.none.）の時は対象外.*実行環境の指示（PR イベントの扱い）に従い、この手順では規則を足さない' .claude/skills/run/SKILL.md` が `1`

## 決定済み
- 変えるのは `## 7. 次へ・完了` の「全タスクが `done` になったら、次の順で PR を作る」の小番号リストだけ。今の `  8. 完了報告に ...` の行の直前に、新しい小番号8を次のコードブロックの中身どおり1行で入れる（行頭は他の小番号と同じ半角空白2つ。バッククォートもこのとおり書く。コードブロックの囲み（```）自体は書かない）：

```
  8. PR の監視：手順7で GitHub の PR を作った時（`scripts/vcs_finish.sh` が PR の URL を出した時と、下の MCP 代替で PR を作った時）だけ行う。GitLab の MR・ホスティング無し（`none`）の時は対象外で、何もしない。実行環境に `subscribe_pr_activity` ツール（クラウドセッションなど。名前に `mcp__github__` などの接頭辞が付くことがある）がある時は、作った PR の URL（`https://github.com/<owner>/<repo>/pull/<番号>`）から owner・repo・番号を取り、`subscribe_pr_activity` を1回呼んで購読する。成功したら完了報告に「PR の監視を始めた」と PR の URL を書く。ツールが無い時・呼び出しが失敗した時は何もせず（再試行しない。手順を止めない）、完了報告に「監視は始めていない」と理由（ツールが無い・失敗したエラーの内容）を書く。購読後の CI の失敗・レビューコメントへの対応は実行環境の指示（PR イベントの扱い）に従い、この手順では規則を足さない。PR がマージ・close されたら `unsubscribe_pr_activity` で購読を解除する
```

- 今の小番号8の行は、行頭の `  8. ` を `  9. ` に替え、行末に次の文を足す（ほかの文言は変えない）。今の行末は「も含める」で句点が無いので、句点を1つ挟んでから続ける。足す部分（先頭の句点を含む）：

```
。手順8の PR の監視の結果（「PR の監視を始めた」か「監視は始めていない」か、対象外）も含める
```

- 小番号8の新設に合わせて、ほかの箇所の番号は直さなくてよい。小番号4の「手順8と同じ `gh api ...`」は `## 8. ハーネス振り返り` を指しており、そのまま残す。`## 8. ハーネス振り返り` の見出しと本文も変えない
- 小番号7（`vcs_finish.sh` の実行）と、その後ろの2つの箇条（引数なしの `vcs_finish.sh`・MCP 代替）の文言は変えない。MCP 代替で PR を作った時も小番号8の対象になることは、新しい小番号8の文言（「下の MCP 代替で PR を作った時」）で表す
- `subscribe_pr_activity`・`unsubscribe_pr_activity` はこのリポジトリのスクリプトでもフックでもなく、実行環境（クラウドセッションの GitHub 連携など）が持つツール。スクリプトは新設せず、フック・`.claude/settings.json` も変えない。ツールの有無はオーケストレーターが自分の使えるツールの一覧で判断する
- 購読の失敗で PR 作成の手順や完了報告を止めない（PR は作成済みのため）。購読は1回だけ試みる
- 購読後の CI 失敗・レビューコメントへの対応方法（直すか・どう返信するか）は書かない。実行環境の指示に従う旨だけを書く（原則7。ドメイン知識を持ち込まない）
- smoke は約1分かかる。`(ref-1)` の検査対象に `.claude/skills/run/SKILL.md` が入っている。新しい小番号8でバッククォートで囲む語のうち `vault/`・`scripts/`・`docs/`・`.claude/` で始まるのは `scripts/vcs_finish.sh` だけで、実在する
