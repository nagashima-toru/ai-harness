# T-01 scripts/discard_worktree.sh を作る（対象検証つき worktree/ブランチ破棄スクリプト）

## 目的
`run` スキル手順6.3.2（FAIL 再試行時）が直接 `git branch -D` を実行すると `.claude/settings.json` の deny ルールに拒否され無人実行できない（issue #34）。対象を検証してから安全に worktree とブランチを破棄する専用スクリプトを新設する。

## 入力
- `vault/designs/D-006.md`（この計画の元設計文書。決定事項の根拠）
- `.claude/skills/run/SKILL.md` の59行目付近（現状の直接実行記述。呼び出し側への反映は T-03 で行うのでここでは読むだけ）
- `.claude/settings.json`（`permissions.deny` の `Bash(git branch -D *)`、`permissions.allow` の `Bash(bash scripts/*)`）
- `scripts/rules.sh`・`scripts/uninstall.sh`（既存スクリプトの書式：シェバン、先頭コメントでの使い方説明、`set -eu`、`usage` 変数と `exit 2`）

## 成果物
- `scripts/discard_worktree.sh`（新規ファイル1つ）

## 受け入れ基準
- 引数が2つでない場合は何も削除せず非0で終了し使い方を標準エラーに出す。確認：`bash scripts/discard_worktree.sh onlyonearg; echo $?` の終了コードが0以外
- ブランチ名が `worktree-agent-` で始まらない場合は削除せず非0で終わる。確認：一時リポジトリ（`git init` 後 `git commit --allow-empty` で初期コミット）で `git worktree add -q -b other-branch <path>` した上で `bash scripts/discard_worktree.sh <path> other-branch; echo $?` が0以外になり、直後の `git worktree list --porcelain` に `<path>` が残っている
- 指定パスが `git worktree list --porcelain` に登録されていない場合は削除せず非0で終わる。確認：存在しない絶対パス（例 `/tmp/discard-worktree-notexist-$$`）に対し `bash scripts/discard_worktree.sh /tmp/discard-worktree-notexist-$$ worktree-agent-x; echo $?` が0以外
- 指定パスに登録された worktree の実際のブランチが指定ブランチ名と一致しない場合は削除せず非0で終わる。確認：`git worktree add -q -b worktree-agent-real <path>` の後 `bash scripts/discard_worktree.sh <path> worktree-agent-fake; echo $?` が0以外で、`git worktree list --porcelain` に `<path>` が残っている
- 上記すべて（引数2つ・`worktree-agent-` 接頭辞・パス登録済み・ブランチ一致）を満たす場合は `git worktree remove --force` と `git branch -D` が実行され終了コード0で終わる。確認：`git worktree add -q -b worktree-agent-test <path>` の後 `bash scripts/discard_worktree.sh <path> worktree-agent-test; echo $?` が0で、`git worktree list --porcelain` に `<path>` が無く `git rev-parse --verify worktree-agent-test` が非0で終わる

## 決定済み
- 引数は位置引数2つ（`<worktree のパス> <ブランチ名>`）のみ。オプションは設けない
- ブランチ名接頭辞 `worktree-agent-` はスクリプト内の定数として持つ。環境変数での上書きは設けない
- worktree の照合は `git worktree list --porcelain` の `worktree <絶対パス>` 行と直後の `branch refs/heads/<名前>` 行のペアで行う
- 渡されたパスの絶対パス正規化には `python3 -c "import os,sys;print(os.path.abspath(sys.argv[1]))" "$1"` を使う（GNU/BSD で挙動が割れる `realpath -m` には依存しない。python3 は install.sh 等で既に前提にしている）。正規化はパスの存在有無を問わず動く
- 削除の順序は `git worktree remove --force <パス>` → `git branch -D <ブランチ名>`。前者が失敗したら後者は実行せず非0で終わる
- 終了コードの使い分け：引数個数の誤りは `exit 2`（`usage` を stderr に出す。`scripts/install.sh`・`scripts/uninstall.sh` と同じ慣習）、検証条件（接頭辞・未登録・ブランチ不一致）に落ちた場合は `exit 1` で理由を stderr に1行以上出す
- スクリプトは実行時のカレント作業ディレクトリの git リポジトリ（計画ブランチ側のメインの作業ツリー）で動く前提。`git -C` の指定は不要
- 書式は既存スクリプト（`scripts/rules.sh`・`scripts/uninstall.sh`）に合わせる：`#!/usr/bin/env bash` シェバン、先頭コメントで使い方を説明、`set -eu`、`USAGE` 変数と `exit 2`
- `bash scripts/discard_worktree.sh ...` という呼び出し文字列は `.claude/settings.json` の deny `Bash(git branch -D *)` の文字列照合に一致しない（permissions はエージェントの Bash ツール呼び出しのコマンド文字列にのみ適用され、スクリプト内部で実行する `git branch -D` は対象外）。そのため deny ルールは変更不要で、このスクリプトは拒否されない
- `.claude/hooks/agent_write_guard.py` は変更しない。このタスクの成果物はそれとは無関係
- `scripts/install.sh` の配布対象への追加は T-02、`SKILL.md` の呼び出し置き換えは T-03 で行う。このタスクでは触れない
- 一時リポジトリでのテストは `git init` 後 `git -c user.name=test -c user.email=test@example.com commit --allow-empty -m init` で初期コミットを作ってから `git worktree add` する（`scripts/smoke.sh` の既存 worktree ケースと同じ作法）
