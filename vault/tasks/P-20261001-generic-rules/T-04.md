# T-04 契約タスクの記述を agents/planner.md・vault-spec.md から README の拡張例へ移す

## 目的
「開発案件では契約タスクを先に切る」はドメイン（開発案件）固有の方式なので、配布するエージェント定義と仕様の粒度基準から外し、README の「拡張ポイント（ルール）」節に、導入先で `vault/rules/planner/` に積む拡張の例として移す（D-010 フェーズ10、#80）。

## 入力
- `.claude/agents/planner.md`（「粒度の基準（必ず守る）」節の24行目付近：「開発案件では、型・API・テスト雛形などの「契約」タスクを先に切り、…」）
- `docs/vault-spec.md`（8節「粒度の基準」の155行目付近：同趣旨の1項目）
- `README.md`（「## 拡張ポイント（ルール）」節）
- `vault/designs/D-010.md` のフェーズ10

## 成果物
- `.claude/agents/planner.md`・`docs/vault-spec.md`・`README.md` の3ファイルの変更（契約タスクの1項目を前2つから削除し、README に拡張の例として移す1組の変更）

## 受け入れ基準
- `.claude/agents/planner.md` と `docs/vault-spec.md` に「契約」の記述が無い（`grep -n '契約' .claude/agents/planner.md docs/vault-spec.md` が何も出力しない）
- `.claude/agents/planner.md` の「粒度の基準（必ず守る）」節の箇条が7から1つ減って6である（`awk '/^## 粒度の基準/{f=1;next} /^## /{f=0} f && /^- /{n++} END{print n}' .claude/agents/planner.md` が `6`）
- `docs/vault-spec.md` の8節の箇条が7から1つ減って6である（`awk '/^## 8\./{f=1;next} /^## 9\./{f=0} f && /^- /{n++} END{print n}' docs/vault-spec.md` が `6`）
- README の「拡張ポイント（ルール）」節に、契約タスクを `vault/rules/planner/` に置く拡張の例が書かれている（`awk '/^## 拡張ポイント/{f=1} /^## 仕組み/{f=0} f && /契約/ && /vault\/rules\/planner\//' README.md` が1行以上出力する）
- README の見出し（`## `）の数が変わっていない（`grep -c '^## ' README.md` が `7`）

## 決定済み
- 削除するのは、`.claude/agents/planner.md` と `docs/vault-spec.md` 8節の「契約」タスクの1項目だけ。他の項目の文言・順序は変えない（`.claude/agents/planner.md` の frontmatter の `model: opus` も変えない）
- README への追記は「## 拡張ポイント（ルール）」節の中に置き、新しい見出しは作らない。同じ1行（または1項目）の中に「契約」と `vault/rules/planner/` の両方の語を書く。文例：「- 導入先で積む拡張の例：開発案件なら、型・API・テスト雛形などの「契約」タスクを先に切り、実装タスクを `after` でそれに依存させる、というルールを `vault/rules/planner/` に置く」
- 「拡張の例」であり、ハーネスが同梱する標準ルールではないことが読み取れる書き方にする
- `docs/roadmap-rules-extension.md` の「契約」（別の意味で使っている見出し）、`docs/decisions.md`・過去の設計文書・過去の計画票の記述は変更しない
- `vault/rules/planner/planner.md` の契約タスクの項は、このタスクでは扱わない（T-01 の提案で外し、実体への反映は人が行う）
- smoke.sh はこのタスクの基準に含めない（T-06 で流す）
