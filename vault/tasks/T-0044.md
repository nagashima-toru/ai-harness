# T-0044 `docs/vault-spec.md` の11・12・13節（ルール／agent_write_guard／設計文書）を書き直し、全体の整合を確認する

## 目的
`docs/vault-spec.md` の「ルール」「agent_write_guard フックの改ざん防止判定」「設計文書」の3節を新
方式に合わせて書き直し、最後に文書全体から `vault/todo.md` への言及が消えていること・見出し番号が
1〜13の連番になっていることを確認する。このタスクが `docs/vault-spec.md` 改訂の最終タスク。

## 入力
- `docs/vault-spec.md`（T-0043 が終わった時点のもの。現行の「## 12. ルール」「## 13.
  agent_write_guard フックの改ざん防止判定」「## 14. 設計文書」に相当する範囲）
- `vault/designs/D-001.md`（「## 決定事項」「## フェーズ2」）
- `vault/tasks/T-0041.md`〜`T-0043.md`（先行タスクが固定した ID 体系・見出し構成）

## 成果物
- `docs/vault-spec.md` のうち、ルール／agent_write_guard フックの改ざん防止判定／設計文書の3節の書
  き直しと、文書全体の最終整合（見出し番号・`vault/todo.md` への言及の除去）

## 受け入れ基準
- `docs/vault-spec.md` 全体から `vault/todo.md` への言及が消えている。確認：`grep -c 'vault/todo.md'
  docs/vault-spec.md` が0
- agent_write_guard の節が、`vault/todo.md` の表解析ではなく計画票のタスク表の解析に言及してい
  る。確認：`grep -F '計画票のタスク表を簡易的に解析' docs/vault-spec.md` の出力が1行以上
- agent_write_guard の節が `.claude/hooks/todo_guard.py` ではなく `.claude/hooks/plan_guard.py` の
  `raw_rows` を参照している。確認：`grep -F 'plan_guard.py の raw_rows' docs/vault-spec.md` の出力
  が1行以上
- `HARNESS_ALLOW_RULES_WRITE` の使用例が計画スコープの ID 形式（`T-01`）になっている。確認：
  `grep -F 'HARNESS_ALLOW_RULES_WRITE=T-01' docs/vault-spec.md` の出力が1行以上
- 見出し番号（`## <数字>. `形式）が1から13までの連番で、重複・欠番が無い。確認：`grep -oE '^## [0-9]+\.'
  docs/vault-spec.md | tr -d '#. '` の出力が `1` から `13` までの13行
- T-0041 が冒頭に置いた未適用注記が残っている（このタスクでは消さない）。確認：
  `grep -F 'この仕様はフェーズ3〜4の実装が完了するまで未適用' docs/vault-spec.md` の出力が1行以上

## 決定済み
- 新しい章立て（全13節）は `vault/plans/P-020.md` の「分割方針」を正本とする。このタスクは新11節
  （ルール）・新12節（agent_write_guard フックの改ざん防止判定）・新13節（設計文書）を担当し、加え
  てこのタスクが最終タスクなので文書全体（1〜13節）の見出し番号の連番確認と `vault/todo.md` 全消し
  の確認を行う。ただし他の節の「内容」（見出し番号以外の文章）を書き直すのは行わない
- ルールの節（`vault/rules/` の置き場・振り分け・改ざん防止の概要）は内容を変えない。番号だけ新11
  節に振り直す
- agent_write_guard の節：「vault/todo.md の「## タスク」表を簡易的に解析し（.claude/hooks/
  todo_guard.py の raw_rows と同じ規則をこのファイル内にコピーして使う。import はしない）」を
  「（自分のブランチの）計画票のタスク表を簡易的に解析し（.claude/hooks/plan_guard.py の raw_rows
  と同じ規則をこのファイル内にコピーして使う。import はしない）」に差し替える。判定表（doing/
  review の行の有無・vault/rules/ 配下への書き込み判定・明示解除）の中身は変えない
- 明示解除の例（`HARNESS_ALLOW_RULES_WRITE=T-0019 claude`）を、計画スコープの ID 形式の例
  （`HARNESS_ALLOW_RULES_WRITE=T-01 claude`）に差し替える。「値は解除を許すタスク ID の列」「未設
  定・空・不一致では解除しない」等の説明文は変えない
- 設計文書の節（`vault/designs/` の ID 体系・形式・`/plan` との関係）は内容を変えない。番号だけ新
  13節に振り直す。設計文書 ID（`D-xxx`）自体の採番方式（既存最大値+1）は変更しない
- 見出し番号の確認コマンド `grep -oE '^## [0-9]+\.' docs/vault-spec.md | tr -d '#. '` は、`## タス
  ク`・`## 計画` のような数字を含まない見出し（今回の改訂で消えるはずの旧 todo.md 表由来の見出し）
  を拾わない。もし旧見出しの消し忘れで13行にならない場合は、それらの見出しも本タスクの範囲で消す
- T-0041 が冒頭に置いた未適用注記は**消さない**。削除するのは D-001 フェーズ4（フックとスキルが新方
  式に揃い、実装が仕様に追いついた時点）。このタスクでは残っていることだけを確認する
