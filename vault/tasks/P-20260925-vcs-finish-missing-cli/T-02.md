# T-02 run スキルに GitHub/GitLab MCP 代替手順を明記する

## 目的
`bash scripts/vcs_finish.sh` が `gh`/`glab` コマンド不在（exit 127、または T-01 で追加した明
示エラー）で失敗した場合に、オーケストレーターが GitHub MCP ツール等で同内容の PR を作成して
よいことを `run` スキルの手順として明文化し、毎回の独自判断をなくす。

## 入力
- `.claude/skills/run/SKILL.md`（変更対象。手順7に `bash scripts/vcs_finish.sh` の実行がある）
- `scripts/vcs_finish.sh`（T-01 完了後の版。`command not found` と、T-01 で追加した明示エラー
  の両方が対象になる）
- GitHub issue #37（`gh issue view 37`）：代替手順の提案文言の元ネタ

## 成果物
- `.claude/skills/run/SKILL.md`

## 受け入れ基準
- `scripts/vcs_finish.sh` が「コマンドが見つからない」旨のエラー（exit 127、または T-01 で追加
  した明示エラー）で失敗した場合に GitHub MCP ツールで代替してよい旨の記述がある。確認：
  `grep -n "MCP" .claude/skills/run/SKILL.md` がヒットする
- 具体的なツール名の例が書かれている。確認：`grep -n "mcp__github" .claude/skills/run/SKILL.md`
  がヒットする
- `gh pr create` に渡すはずだった情報（ブランチ名・PR タイトル・本文）を MCP ツール呼び出しに
  引き継ぐ旨が書かれている。確認：`grep -n "引き継" .claude/skills/run/SKILL.md` がヒットする
- GitLab（`glab`）についても、MCP 等の代替手段があれば使ってよい旨と、無ければ人に案内して止
  まる旨の両方が書かれている。確認：`grep -n "glab" .claude/skills/run/SKILL.md` がヒットし、
  かつ `grep -n "人" .claude/skills/run/SKILL.md` の該当追記箇所にも言及がある（目視で同じ節
  内にあることを確認する）
- `gh pr merge`/`glab mr merge` を**実行してよい**という記述が追加されていない。確認：
  `grep -n "gh pr merge\|glab mr merge" .claude/skills/run/SKILL.md` に実行を指示する記述が無
  いことを目視確認する（既存の「実行しない」という方針説明への言及は可）

## 決定済み
- 追記箇所は手順7（`bash scripts/vcs_finish.sh` を実行する行の直後）。既存の手順番号・見出し
  は変えず、その下に代替手順の段落を追加する形でよい
- 追記する内容の骨子（この通りの文面でなくてよいが、趣旨を含めること）：
  - `bash scripts/vcs_finish.sh` が `command not found`（exit 127 相当）、または新しく追加さ
    れた「`gh`/`glab` が見つからない」旨の明示エラーで失敗した場合、GitHub MCP ツール（例：
    `mcp__github__create_pull_request` 等、実行環境で使える GitHub MCP ツール）で同内容の PR
    を作成してよい
  - その際、`gh pr create "$@"` に渡すはずだったブランチ名・タイトル・本文などの情報を、MCP
    ツールの引数にそのまま引き継ぐ
  - GitLab（`glab`）が同様に失敗した場合も、GitLab MCP 等の代替手段があればそれを使ってよい。
    使える代替手段が無い環境では、人にブランチ名と状況を案内して止まる
  - この代替経路を使っても `gh pr merge`/`glab mr merge` は実行しない（マージは人が行うという
    既存方針は変わらない）
- 対象は「コマンド自体が無い」場合の代替であり、`gh`/`glab` が認証エラー・ネットワークエラー等
  で失敗するケースへの対応は今回のスコープ外（issue #37 の範囲に合わせる）
