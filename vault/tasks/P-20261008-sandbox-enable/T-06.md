# T-06 merge_settings_json.py が新規作成の時に sandbox キーを書かないようにする

## 目的
`scripts/merge_settings_json.py` は、dst が無い時（新規導入）に src をそのまま書く。ハーネス側の `.claude/settings.json` に `sandbox` を足した後も、導入先には既定でサンドボックスの設定を入れないよう、`create` の経路で `sandbox` キーを除いて書く（計画票の人への質問1の回答：案A）。

## 入力
- `vault/designs/D-013.md` の「フェーズ5 サンドボックスを有効にする」（決定済み：導入先には既定では入れず）
- `scripts/merge_settings_json.py`（docstring と `main()` の `if not dst.exists():`）

## 成果物
- `scripts/merge_settings_json.py`（1ファイル。`create` の経路と docstring の変更だけ）

## 受け入れ基準
- src に `sandbox` がある時、dst が無ければ作られた dst に `sandbox` キーが無い：一時ディレクトリで `{"hooks":{},"sandbox":{"enabled":true}}` の src を作り、`python3 scripts/merge_settings_json.py <src> <存在しない dst>` を実行して、`python3 -c "import json;print('sandbox' in json.load(open('<dst>')))"` の出力が `False`、標準出力が `create <dst>`
- `sandbox` 以外のキーは src のまま書かれる：同じ実行で、dst の `hooks` が src の `hooks` と等しい
- 既存の dst への merge・skip の動きが変わっていない：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- docstring の `dst が無い` の行に、`sandbox` は書かないことが書かれている（Read。`grep -n 'sandbox' scripts/merge_settings_json.py` の出力が docstring と `create` の経路の両方に1行以上）

## 決定済み
- 人の回答（/plan unblock）：案1で進める。`bash scripts/smoke.sh` は実行しない（サンドボックスが有効なセッションでは `mktemp -d` が失敗し、smoke が worktree と共有 `.git` を壊すため）。creator は「既存の smoke が全件通る」の基準を確認せず、進捗に「smoke は未実行（人がサンドボックスの外で確認する）」と書く。verifier もその基準を実行せず、その行は `ok: true` にせず note に「未実行。人がサンドボックスの外で確認する」と書く（verdict を PASS にするかは、ほかの基準が全部真かで決める）。ほかの基準（`merge_settings_json.py` を一時ディレクトリで直接実行する確認）は `$TMPDIR` 配下で行う
- `create` の経路で、`src_data` のコピーから最上位の `sandbox` キーだけを取り除いて `dump` する（`src_data` 自体は変えない。ほかのキーの順序・値は変えない）
- 標準出力は今までどおり `create <dst>` の1行。`sandbox` を除いたことの案内行は出さない
- docstring には「dst が無い → src から `sandbox` を除いた内容で作成」と、`sandbox` は導入先が手で足すもの（`docs/install.md` の「サンドボックスを有効にする（任意）」）であることを一言書く
- merge・skip の経路は変えない（`sandbox` を足さない、は今のままで満たされる）
- `scripts/install.sh`・`scripts/smoke.sh` は変えない。smoke のケースは T-02 が足す
- 既存の smoke で create の出力や中身を見ているケースが落ちたら、ケースを直さず blocked にして question に書く
