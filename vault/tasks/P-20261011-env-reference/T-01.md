# T-01 環境変数リファレンス docs/configuration.md を書く

## 目的
利用者が指定できる環境変数（`HARNESS_*`）を `docs/configuration.md` に、意味・既定値・読むもの・使う場面・詳しい説明へのリンクの表で一覧化する。

## 入力
- `vault/designs/D-20261011-user-guide.md`（「決定事項」とフェーズ1）
- 変数を読むコード：`scripts/vcs_finish.sh`・`scripts/purge_plan.sh`・`scripts/transition.py`・`scripts/run_unattended.py`・`.claude/hooks/stop_gate.py`・`.claude/hooks/agent_write_guard.py`・`.claude/skills/run/SKILL.md`・`.claude/skills/plan/SKILL.md`・`.claude/skills/design/SKILL.md`・`.claude/agents/creator.md`・`.claude/ai-harness.md`
- 既存の説明：`docs/runbook.md`（3節・8節・10節）・`docs/vault-spec.md`（1節・2節・7節・9節）・`docs/install.md`（「main 以外のブランチをベースにする（任意）」）

## 成果物
- `docs/configuration.md`（新規。1ファイル）

## 受け入れ基準
- 表の1列目の変数がちょうど11個で重複が無い：`python3 -c 'print(sorted(__import__("re").findall(r"^\| `(HARNESS_[A-Z_]+)` \|", open("docs/configuration.md").read(), 8)))'` の出力が `['HARNESS_BASE_BRANCH', 'HARNESS_CREATOR_MODEL', 'HARNESS_MAX_ATTEMPTS', 'HARNESS_MAX_PARALLEL', 'HARNESS_PR_BODY_FILE', 'HARNESS_PR_TITLE', 'HARNESS_PUSH_BRANCH', 'HARNESS_RUN_CMD', 'HARNESS_RUN_TIMEOUT', 'HARNESS_STRICT_STOP', 'HARNESS_VCS_HOST']`
- 6列の見出し行が2つ（2つの表）ある：`grep -cxF '| 変数 | 意味 | 既定値 | 読むもの | 使う場面 | 詳しく |' docs/configuration.md` が `2`
- 利用者が設定する9変数と内部用2変数が見出しで分かれている：`python3 -c 'print(open("docs/configuration.md").read().split("\n## run が内部で渡す変数\n")[0].count("| `HARNESS_"))'` が `9`、`python3 -c 'print(open("docs/configuration.md").read().split("\n## run が内部で渡す変数\n")[1].count("| `HARNESS_"))'` が `2`、後者の2行は `HARNESS_PR_BODY_FILE`・`HARNESS_PR_TITLE`
- 各行の「既定値」「読むもの」が決定済みの一覧と一致する：`python3 -c 'print("\n".join(c[1].strip()+" | "+c[3].strip()+" | "+c[4].strip() for c in (l.split("|") for l in open("docs/configuration.md")) if len(c)>7 and c[1].strip().startswith("`HARNESS_")))'` の出力の各行で、既定値の列が決定済みの「既定値」の記述（値と、経路で違う時はその旨）を含み、読むものの列が決定済みの「読むもの」のパスをすべて含む
- 表を含む本文のバッククォート内のパスがすべて実在する：`python3 -c 'print([p for p in __import__("re").findall(r"`((?:vault|scripts|docs|\.claude)/[^`\s<*{$]+)`", open("docs/configuration.md").read()) if not __import__("os").path.exists(p)])'` の出力が `[]`
- 「設定のしかた」の節に、決定済みの4つの語がある：`python3 -c 'print([w for w in ("export ", "env HARNESS_", "`.claude/settings.json`", "起動し直す") if w not in open("docs/configuration.md").read().split("## 設定のしかた")[1].split("\n## ")[0]])'` の出力が `[]`
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<数> fail=0` の形

## 決定済み
- 構成（見出しはこの文言のまま書く）：`# 環境変数リファレンス` → 短い導入（このファイルは ai-harness リポジトリで読むもので導入先には配らない、とは書かなくてよい）→ `## 設定のしかた` → `## 利用者が設定する変数`（表1：9行）→ `## run が内部で渡す変数`（表2：2行。「run が `scripts/vcs_finish.sh` に渡す内部用で、利用者は通常設定しない」と一言添える）。見出し行は前後を空行で区切る
- 2つの表の見出し行はどちらも `| 変数 | 意味 | 既定値 | 読むもの | 使う場面 | 詳しく |`、区切り行は `|---|---|---|---|---|---|`。データ行は `| `HARNESS_XXX` | … |` の形（1列目は変数名をバッククォートで囲んだだけにする。表2の行もこの形）。セルの中に `|` を書かない（区切りは「・」や「／」を使う）
- 表1の行の順：`HARNESS_BASE_BRANCH`・`HARNESS_PUSH_BRANCH`・`HARNESS_MAX_ATTEMPTS`・`HARNESS_MAX_PARALLEL`・`HARNESS_CREATOR_MODEL`・`HARNESS_STRICT_STOP`・`HARNESS_VCS_HOST`・`HARNESS_RUN_CMD`・`HARNESS_RUN_TIMEOUT`。表2：`HARNESS_PR_BODY_FILE`・`HARNESS_PR_TITLE`
- 既定値（コードで照合済み。作成時にもコードを読んで再確認し、食い違えばコードに合わせて進捗に書く）：
  - `HARNESS_BASE_BRANCH`：`main`（前後の空白を除いて空なら `main`）
  - `HARNESS_PUSH_BRANCH`：未設定（現在のブランチに push し、PR の head も現在のブランチ）
  - `HARNESS_MAX_ATTEMPTS`：`3`
  - `HARNESS_MAX_PARALLEL`：`3`（スクリプトは読まず、run スキル（オーケストレーター）が読む）
  - `HARNESS_CREATOR_MODEL`：未設定（`.claude/agents/creator.md` の frontmatter の `model` を使う）
  - `HARNESS_STRICT_STOP`：Stop フック単体では `0`。`scripts/run_unattended.py` 経由では、未設定（キーが無い）なら `1` を入れて子に渡す、と両方書く
  - `HARNESS_VCS_HOST`：`auto`（origin の URL から github / gitlab / none を判定）
  - `HARNESS_RUN_CMD`：`claude -p "/run"`
  - `HARNESS_RUN_TIMEOUT`：`3600`（秒）
  - `HARNESS_PR_BODY_FILE`：未設定（引数なしの `vcs_finish.sh` は「タスク履歴」表を本文にする）
  - `HARNESS_PR_TITLE`：未設定（`HARNESS_PR_BODY_FILE` の経路で、計画ID、無ければ現在のブランチ名）
- 読むもの（リポジトリ相対パスをバッククォートで書く。下のパスは全部含める）：
  - `HARNESS_BASE_BRANCH`：`scripts/vcs_finish.sh`・`scripts/purge_plan.sh`・`.claude/hooks/agent_write_guard.py`・`.claude/skills/plan/SKILL.md`・`.claude/skills/design/SKILL.md`
  - `HARNESS_PUSH_BRANCH`：`scripts/vcs_finish.sh`・`.claude/skills/plan/SKILL.md`・`.claude/skills/design/SKILL.md`
  - `HARNESS_MAX_ATTEMPTS`：`scripts/transition.py`・`.claude/hooks/stop_gate.py`
  - `HARNESS_MAX_PARALLEL`：`.claude/skills/run/SKILL.md`
  - `HARNESS_CREATOR_MODEL`：`.claude/skills/run/SKILL.md`・`scripts/transition.py`
  - `HARNESS_STRICT_STOP`：`.claude/hooks/stop_gate.py`・`scripts/run_unattended.py`
  - `HARNESS_VCS_HOST`：`scripts/vcs_finish.sh`
  - `HARNESS_RUN_CMD`・`HARNESS_RUN_TIMEOUT`：`scripts/run_unattended.py`
  - `HARNESS_PR_BODY_FILE`・`HARNESS_PR_TITLE`：`scripts/vcs_finish.sh`（`.claude/skills/run/SKILL.md` の手順7が渡す、と添える）
  - 上の他に、言及しているだけのファイル（例：`.claude/agents/creator.md`・`.claude/ai-harness.md`）は書かなくてよい
- 「使う場面」は1〜2文で自由に書く（例：`HARNESS_BASE_BRANCH` は develop などをベースにする導入先、`HARNESS_PUSH_BRANCH` は push 先が指定されるクラウドセッション）
- 「詳しく」は既存の説明へのリンク。アンカーは付けず、`[docs/runbook.md の 3節](runbook.md)` のようにファイルへのリンクと節の名前を書く。対応：
  - `HARNESS_BASE_BRANCH`：`docs/install.md` の「main 以外のブランチをベースにする（任意）」・`docs/vault-spec.md` の 1節
  - `HARNESS_PUSH_BRANCH`：`docs/runbook.md` の 10節・`docs/vault-spec.md` の 1節
  - `HARNESS_MAX_ATTEMPTS`：`docs/vault-spec.md` の 2節・`docs/runbook.md` の 3節
  - `HARNESS_MAX_PARALLEL`：`docs/vault-spec.md` の 2節
  - `HARNESS_CREATOR_MODEL`：`docs/runbook.md` の 8節・`docs/vault-spec.md` の 7節
  - `HARNESS_STRICT_STOP`：`docs/runbook.md` の 3節・`docs/vault-spec.md` の 9節
  - `HARNESS_VCS_HOST`：`docs/vault-spec.md` の 1節と `scripts/vcs_finish.sh` の冒頭のコメント（docs に専用の説明が無いため）
  - `HARNESS_RUN_CMD`・`HARNESS_RUN_TIMEOUT`：`docs/runbook.md` の 3節
  - `HARNESS_PR_BODY_FILE`・`HARNESS_PR_TITLE`：`docs/vault-spec.md` の 1節・`.claude/skills/run/SKILL.md` の手順7
- 「設定のしかた」の節には次を短く書く（この4つの語をそのまま含める）：シェルで `export HARNESS_…=…` する／1回だけなら `env HARNESS_…=値 <コマンド>`／恒久的には `.claude/settings.json` の `env`（`docs/install.md` の「main 以外のブランチをベースにする（任意）」に例がある）／セッションの起動後に変えても run の Bash に効かない場合があるので、変えたら起動し直す（`docs/runbook.md` 8節と同じ注意）
- 環境変数の追加・名前の変更・既定値の変更はしない（今の動作を書くだけ）
- 既存文書（`docs/runbook.md`・`docs/vault-spec.md`・`docs/install.md`）の説明は消さない・変えない（成果物ではない。重なりの整理はフェーズ3）
- このタスクでは `scripts/smoke.sh` と `README.md` を変えない（T-02・T-03 の成果物）。`docs/configuration.md` が smoke の `(ref-1)` の対象になるのは T-02 からなので、ここでは受け入れ基準5で同じ観点（パスの実在）を確かめる
