# T-0025 docs/install.md に「パターン2: 既存リポジトリ」と「インストール後の次の一歩」を追記する

## 目的
既存リポジトリへ組み込むユースケースの手順と、両パターン共通の「次の一歩」を `docs/install.md` に追記し、`scripts/install.sh` の実挙動と一致させる。

## 入力
- `docs/install.md`（T-0024 が作成した前半。前提＋パターン1がある状態）
- `scripts/install.sh`（複製ロジックの正本。CLAUDE.md は追記案内のみ、settings.json / todo.md 等は既存なら skip する挙動と、`copy_if_absent` の出力メッセージ `note`/`skip`）
- `docs/runbook.md`（インストール後、人が最初にやること）

## 成果物
- `docs/install.md`（T-0024 の続きに追記。新規ファイルは作らない）

## 受け入れ基準
- `## パターン2: 既存リポジトリに追加する` という見出しが1つある。確認コマンド: `grep -c '^## パターン2' docs/install.md`（結果が1）
- `## インストール後の次の一歩` という見出しが1つある。確認コマンド: `grep -c '^## インストール後の次の一歩' docs/install.md`（結果が1）
- `scripts/install.sh` の note 文言を引用している。確認コマンド: `grep -c 'CLAUDE.md は既にあります' docs/install.md`（結果が1以上）
- `vault/` を git 管理に入れる推奨（`git add vault/` を含むコマンド）が書かれている。確認コマンド: `grep -c 'git add vault/' docs/install.md`（結果が1以上）
- `docs/runbook.md` への参照がある。確認コマンド: `grep -c 'docs/runbook.md' docs/install.md`（結果が1以上）
- T-0024 が書いたパターン1の見出しが壊れずに残っている。確認コマンド: `grep -c '^## パターン1' docs/install.md`（結果が1）

## 決定済み
- 追記する見出しの順序は `## パターン2: 既存リポジトリに追加する` → `## インストール後の次の一歩`。
- `## パターン2` の手順に含める内容：
  - `bash /path/to/ai-harness/scripts/install.sh <既存リポジトリのパス>` の実行例
  - 出力される `note  CLAUDE.md は既にあります。...` と `skip  (exists) ...` の意味を説明する：`CLAUDE.md` は上書きされず追記が必要（`scripts/install.sh` の該当コメントのとおり）、`.claude/settings.json` や `vault/todo.md` 等は既存があれば複製せず既存のものを使う
  - `vault/` を git 管理に入れるかどうかの判断：ai-harness 自身が `vault/` 全体（`todo.md` / `tasks/` / `plans/` / `verdicts/` / `log/` / `archive/` / `rules/`）を git 管理している前例に合わせ、`git add vault/ .claude/ CLAUDE.md scripts/rules.sh scripts/smoke.sh docs/vault-spec.md && git commit` を推奨として明記する
  - 既存の開発ワークフロー（ビルド・CI・lint 等）との併存については「ハーネスはファイルを追加するだけで既存のビルド設定を変更しない」と1文で明記する
  - フォルダ信頼（`claude` を一度対話起動する）と `bash scripts/smoke.sh` による検証は、パターン1と同じ順序で行うと明記する
- `## インストール後の次の一歩` はパターン1・2共通の節として書く。`docs/runbook.md` を参照する1文と、最初に打つコマンドとして `/plan <ゴール>` を案内する1文を書く（詳細手順は runbook に譲り、ここでは繰り返さない）。
- 見出し・箇条書きの文体は T-0024 が書いた前半（パターン1）に合わせる。
