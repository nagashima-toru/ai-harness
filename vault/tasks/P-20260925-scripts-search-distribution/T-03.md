# T-03 docs/install.md の配布物説明を実態に合わせる

## 目的
`docs/install.md` の配布物の説明（34行目付近の列挙、116行目付近の `git add` 例）を、`scripts/` の検索方式配布に合わせて書き換える。

## 入力
- `docs/install.md`（34行目・116行目付近）
- `vault/designs/D-007.md` フェーズ1（決定事項）

## 成果物
- `docs/install.md`

## 受け入れ基準
- 配布物の説明に `scripts/vcs_finish.sh`、または「`scripts/` 配下」に類する検索方式を反映した表現がある。確認：`grep -n "vcs_finish\|scripts/ 配下" docs/install.md` がヒットする
- 116行目付近の `git add` 例が、個別列挙 `scripts/rules.sh scripts/smoke.sh` から `scripts/` へ置き換わっている。確認：`grep -c "scripts/rules.sh scripts/smoke.sh" docs/install.md` が `0`
- 置き換え後の `git add` 例に `scripts/` が含まれる。確認：`grep -c "scripts/ docs/vault-spec.md" docs/install.md` が `1`

## 決定済み
- 34行目付近の列挙は、`scripts/smoke.sh`・`scripts/rules.sh`・`scripts/merge_claude_md.py`・`scripts/merge_settings_json.py` の個別列挙をやめ、`scripts/vcs_finish.sh` を含む形にするか、「`scripts/` 配下のスクリプト一式（`*.sh`・`*.py`、除外リストの物を除く）」のように検索方式を反映した表現にする（どちらでもよい）
- 116行目付近の `git add` 例は、個別列挙 `scripts/rules.sh scripts/smoke.sh` を `scripts/` に置き換える。書き換え後は `git add vault/ .claude/ CLAUDE.md scripts/ docs/vault-spec.md && git commit -m "ai-harness を導入"` の形にする（`docs/vault-spec.md` は今回変更しないのでそのまま残す）
- T-01（install.sh の実装）の完了を待たなくても書ける内容なので `after` は付けない。ただし文言は「`scripts/` を検索方式で配布する」という前提で書く
- 109行目付近の「`.claude/settings.json` は自動マージされない」という記述はフェーズ2（`worktree.baseRef`）の対象。このタスクでは触れない
