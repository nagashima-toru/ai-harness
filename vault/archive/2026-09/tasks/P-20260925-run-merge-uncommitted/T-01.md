# T-01 run手順6: マージ前の未コミット差分回収と、新規コミット0件時のblocked化

## 目的
`.claude/skills/run/SKILL.md` の手順6「verdict に従う」の `PASS` 分岐に、(1) `git merge --no-ff` の直前に対象 worktree の未コミット差分をオーケストレーターがコミットする手順と、(2) それを経てもなお対象タスクの worktree に `PLAN_HEAD` からの新規コミットが無い場合を異常として検知し `blocked` にする手順の、2つの安全策をこの順で追加する（GitHub Issue #32）。

## 入力
- `.claude/skills/run/SKILL.md`（手順3.1・3.4・3.6 の `PLAN_HEAD` の定義と保持方法、手順6の現状の `PASS`/`FAIL` 分岐が対象）
- `vault/rules/common/git.md`（「コミットは受け入れ基準に含まれている場合だけ行う」という creator 側の既存方針。変更しないが、今回追加する手順が「オーケストレーターが行うコミット」であり creator の方針と矛盾しないことを明記するために読む）
- GitHub Issue #32（本文を計画票のゴールに転記済み。原文には対応案2つと「誤検知を避ける判定方法も考えること」という注意書きがある）
- `vault/log/P-20260924-vcs-finish.md`・`vault/plans/P-20260924-vcs-finish.md`（T-01〜T-05 で実際に発生した経緯。参考情報でありこのタスクでは変更しない）

## 成果物
- `.claude/skills/run/SKILL.md` の手順6 `PASS` 分岐の書き換え（1箇所にまとまった変更として扱う）

## 受け入れ基準
- マージ実行前に、対象 worktree の未コミット差分（staged/unstaged/untracked）を検知しオーケストレーターがコミットする手順が追加されている。確認: `grep -n "git status --porcelain" .claude/skills/run/SKILL.md` が1件以上ヒットする
- 上記コミットの実行者はオーケストレーターであり、creator 側のコミット方針（`vault/rules/common/git.md`）自体は変えない旨が明記されている。確認: `git diff --stat main -- vault/rules/common/git.md .claude/agents/creator.md vault/rules/creator` の出力が空
- 前項のコミット処理を経てもなお、対象タスクの worktree のブランチが `PLAN_HEAD` からの新規コミットを持たない場合を検知する手順が追加されている。確認: `grep -n "rev-list" .claude/skills/run/SKILL.md` が1件以上ヒットする
- 新規コミットが無い場合は `git merge --no-ff` を実行せず、status を `blocked` にし question に状況を書き、log に「新規コミット無し」等の理由が分かる形で追記する旨が明記されている。確認: `grep -n "新規コミット" .claude/skills/run/SKILL.md` が1件以上ヒットする
- 上記2つの安全策が「未コミット差分のコミット」→「新規コミット0件の判定」→「`git merge --no-ff`」の順に並んでいる。確認: `grep -n "git status --porcelain\|rev-list\|git merge --no-ff" .claude/skills/run/SKILL.md` の出力で、行番号が `git status --porcelain` < `rev-list` < `git merge --no-ff`（手順6 内の該当箇所）の順になっている
- `.claude/skills/run/SKILL.md` とタスク票自身（`vault/tasks/P-20260925-run-merge-uncommitted/T-01.md` の「進捗」欄更新）以外のファイルは変更されていない。確認: `git status --short` の出力から `vault/tasks/P-20260925-run-merge-uncommitted/T-01.md` の行を除いたときに `.claude/skills/run/SKILL.md` 以外の行が無い（例: `git status --short | grep -v 'vault/tasks/P-20260925-run-merge-uncommitted/T-01.md'`）

## 決定済み
- 追加位置は手順6の2.（`PASS` の場合）の先頭。既存の2.1（マージ実行）を後ろにずらし、新しい2つのステップを差し込む形にする。既存の「マージが衝突なく成功したら」「マージでコンフリクトが起きた場合」の記述はそのまま維持し、番号だけ振り直す
- 未コミット差分のコミット手順の文面イメージ：「対象タスクの worktree で `git -C <worktree のパス> status --porcelain` を実行し、出力が空でなければ（＝未コミットの変更が1件でもあれば）`git -C <worktree のパス> add -A` の後 `git -C <worktree のパス> commit -m "<計画ID>/<id>: creator 成果物の未コミット分をオーケストレーターが収集"` でコミットする」。コミットメッセージの文言はこの例に揃える（`grep` で拾う対象は「新規コミット」「rev-list」「git status --porcelain」の語であり、コミットメッセージ文言自体は受け入れ基準の grep 対象ではないため一言一句の一致は不要）
- 新規コミット判定の文面イメージ：「直前のコミット処理を経てもなお、対象タスクの worktree のブランチ先端が `PLAN_HEAD` からの新規コミットを持たない場合（`git rev-list <PLAN_HEAD>..<対象タスクの worktree のブランチ名> | wc -l` が `0`）、`git merge --no-ff` を実行せず異常として扱う。status を `blocked` にし、question に『worktree に新規コミットが無い（マージ対象の差分が無い）：<確認コマンドの出力>』のように状況を書く。`vault/log/<計画ID>.md` に `- <日時> <id> review→blocked attempt=<n> 新規コミット無し` を追記する。この worktree は削除せず残す（人が調査に使えるようにする）。他の対象タスクの処理は止めず、次のタスクへ進む」。既存のコンフリクト時・上限到達時の「worktree は削除しない」方針と揃える
- 「新規コミットが0件なら例外なく blocked にする」（差分ゼロで正しく完了したケースを区別する分岐を作らない）という判断は、計画票の「人への質問」に明記済み。人が承認時にこの方針に同意しない場合は、承認前に計画票側を修正してもらう想定。人からの指摘が無ければこの判断のまま実装してよい
- 新規コミット判定に使う `PLAN_HEAD` は手順3.1で既に控えている変数をそのまま使う（新たに取得し直さない）。対象タスクの worktree のブランチ名は手順3.4で「run のセッション内で保持する」とされている対応関係をそのまま使う
- コミットコマンドに `--no-verify` は付けない（フックのスキップは原則禁止のため。今回のコミット対象はコード変更ではなく成果物ファイルであり、hook 失敗時は通常のコミット失敗として扱われてよい）
- 手順6以外（手順3・手順5・「回帰確認」節など）の記述は変更しない。「回帰確認」節の成果物差分チェック（`git diff <PLAN_HEAD>..HEAD -- <成果物のパス>`）は、オーケストレーターによる自動コミットを経ても creator が作った変更内容と一致するため、そのままで矛盾しない
