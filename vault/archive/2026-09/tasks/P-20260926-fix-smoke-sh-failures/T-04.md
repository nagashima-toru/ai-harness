# T-04 smoke.sh の missing_referenced_scripts が .claude/worktrees/ 配下を誤検知しないようにする

## 目的
`scripts/smoke.sh` の `missing_referenced_scripts()` が `find "$target/.claude" -type f` で走査対象を取る際、`.claude/worktrees/` 配下（未削除の worktree の実体。中身はリポジトリ全体の入れ子コピーになりうる）まで含めてしまい、その中の例示テキスト（実在しないダミー名 `scripts/hello.sh` 等）を誤って「参照されているのに無い」と検知する問題を直す（issue #59 の提案2）。T-03（`install.sh` が `.claude/worktrees/` を複製対象から外す修正）と根本原因は共通だが、こちらは `missing_referenced_scripts()` 自身の走査範囲を絞ることで、`.claude/worktrees/` に何が残っていてもこの関数が誤検知しない頑健性を独立に持たせる。

## 入力
- `scripts/smoke.sh` の `missing_referenced_scripts()` 関数（397〜414行目付近。`find "$target/.claude" -type f` の行）
- T-03 のタスク票（同じ現象の別の根本原因。T-03 が先に完了していても、していなくても、この修正は独立に成立する）

## 成果物
- `scripts/smoke.sh` の修正（`missing_referenced_scripts()` 関数のみ。1ファイル）

## 受け入れ基準
- `missing_referenced_scripts()` 内の `.claude` 配下の `find` が `worktrees` 配下を除外している。確認コマンド: `grep -n "worktrees" scripts/smoke.sh` の出力が1行以上
- `missing_referenced_scripts()` 以外の関数・テストケースの行数・内容が変わっていない。確認コマンド: `git diff -- scripts/smoke.sh | grep -E '^[+-]expect'` の出力が空
- `bash scripts/smoke.sh` を実行した時、`新規インストール先で参照される scripts がすべて揃っている` の行が `ok` から始まる。確認コマンド: `bash scripts/smoke.sh`（`== 参照される scripts の存在チェック ==` セクションの行が `ok` で始まることを出力で確認する）
- 同じ実行の末尾 `smoke: pass=<N> fail=<M>` の `pass` が着手前HEAD時点の実行結果（152）より1件以上増えている（今回直した1ケース分。他タスクの完了状況によってはさらに増えていてもよい）。確認コマンド: 同じ実行結果の末尾行を読む

## 決定済み
- 除外方法は `find "$target/.claude" -type f` の対象から `.claude/worktrees` 配下を外せればよい（例：`find "$target/.claude" -path "$target/.claude/worktrees" -prune -o -type f -print`）。`vault/rules`・`vault/templates`・`docs/vault-spec.md`・`CLAUDE.md` を対象にした他の `find`/`echo` の行は変更しない
- T-03 と重複して同じ現象を直すことになるが、両方が独立に「該当ケースを ok にする」受け入れ基準を満たせばよい。どちらか一方が先に `done` になった時点でこの受け入れ基準（該当ケースが `ok`）は既に満たされている可能性があるが、それでも `scripts/smoke.sh` の該当関数を実際に直すこと自体がこのタスクの成果物
- 他タスク（T-01〜T-03・T-05）の成果物ファイルは変更しない（`scripts/smoke.sh` の `missing_referenced_scripts()` 関数以外は変更しない）
- コミットの指示は無いので、コミットするかどうかは任意（する場合は `vault/rules/common/git.md` の運用に従う）
