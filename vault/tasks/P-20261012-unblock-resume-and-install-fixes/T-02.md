# T-02 transition.py に todo→doing の --resume-worktree（blocked の worktree の引き継ぎ）を足す

## 目的
unblock で todo に戻したタスクを再着手する時に、blocked の時に残した worktree を破棄せず引き継げるよう、`scripts/transition.py` に todo→doing の `--resume-worktree` を足す。分岐元が計画ブランチの HEAD より古ければ、計画ブランチを worktree にマージしてから引き継ぐ（Issue #190）。

## 入力
- `scripts/transition.py`（`verify_worktree`・`collect_worktree`・`merge_branch`・`commit_files`・`worktree_record` の書式）
- `scripts/diff_gate.py`（base と branch の2点の差分で判定すること。base の版のタスク票を読むこと）
- `docs/vault-spec.md` 2節（transition.py の呼び出しの形・終了コード）・7節（記録行の書式）
- `scripts/smoke.sh` の `(transition-wt)` のテスト（`tw_setup`・`tw_run`・`tw_mod`・`tw_commit` などの部品）

## 成果物
- `scripts/transition.py`（主な成果物）
- `scripts/smoke.sh`（テストの追加）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-resume) 0[1-7] '` の出力が `7`（決定済みのテスト 01〜07 がすべて通る）
- `python3 scripts/transition.py --help` の終了コードが0で、出力に `--resume-worktree` が現れる
- `python3 scripts/transition.py P-X T-01 doing --resume-worktree --worktree /tmp/x --branch b` の終了コードが2（`--worktree` との併用は引数の誤り）
- `git diff --merge-base work/p-20261012-unblock-resume-and-install-fixes --name-only -- scripts/transition.py` の出力が `scripts/transition.py`

## 決定済み
- 呼び出しの形：`python3 scripts/transition.py <計画ID> <id> doing --resume-worktree [--note <補足>]`。id は1つだけ、遷移先は doing だけ。`--worktree`・`--branch`・`--plan-head`・`--question`・`--question-file` との併用、複数 id、doing 以外の遷移先は argparse のエラー（終了コード2）
- 前提の検査は今の todo→doing と同じ（計画票が approved・ブランチが `work/<計画IDの英小文字>`・その行が todo・`after` が全部 done・上限）。当たれば終了コード1で何も変えない。その行が todo でない時も終了コード1
- 引き継ぐ worktree は `vault/log/<計画ID>.md` のその id の最後の記録行（`- <日時> <id> worktree path=<パス> branch=<ブランチ名> plan_head=<sha>`）から取る。パスは空白を含みうるので `path=(.+) branch=(\S+) plan_head=([0-9a-f]{40})$` のように後ろから区切って読む
- 引き継げない時は終了コード5（新設）で、計画票・log・コミットを何も変えない。標準出力に `<計画ID>/<id>: 引き継げない（<理由>）` の1行を出す。引き継げない時とは：記録行が無い／ブランチ名が `worktree-agent-` で始まらない・`git worktree list --porcelain` にそのパスが無い・登録されたブランチが一致しない（`verify_worktree` と同じ条件だが、fail で終了コード1にせず5にする）／下のマージが衝突・失敗した。run は終了コード5を受けたら、その id を通常の todo→doing（新しい worktree）に回す
- 引き継げる時の順序：(1) worktree に未コミット分があれば今の `collect_worktree` と同じく `<計画ID>/<id>: creator 成果物をオーケストレーターが収集` でコミットする。(2) 計画ブランチの今の HEAD を H とする（この時点では状態のコミット前）。`git merge-base --is-ancestor H <ブランチ>` が偽なら、worktree の中で `git merge --no-ff H -m "<計画ID>/<id>: 計画ブランチを取り込み"` を行う。衝突・失敗したら衝突ファイルを取って worktree 側で `git merge --abort` し（マージ中の状態を残さない）、終了コード5（理由に衝突ファイル）。(1) の収集コミットは取り消さない（worktree の中の creator の作業を残すため）。(3) 計画票の行を doing・attempt=1 にし、log に `- <日時> <id> todo→doing attempt=1 worktree を引き継ぎ`（`--note` があれば後ろに空白を挟んで付ける。`creator=` などのモデルは付けない）を1行追記して、今と同じく計画票と log だけを `<計画ID>/<id>: todo→doing` でコミットする。記録行はこの時点では書かない（review・blocked の時に transition.py が書く）
- 成功は終了コード0。標準出力に `<計画ID>/<id>: todo→doing attempt=1 worktree を引き継いだ path=<realpath> branch=<ブランチ名> plan_head=<H の40桁>` の1行を出す。run はこの `plan_head`（状態のコミットの前の H）を、その id の `PLAN_HEAD`（review・blocked・done の `--plan-head`）として使う。H を使う理由：diff_gate は `git diff <base> <branch>` の2点比較なので、base は worktree に取り込み済みのコミットでなければならない（状態のコミットの後の HEAD を base にすると、worktree に無い計画票・log の差分が宣言外の変更として出る）。H には unblock で直したタスク票が入っているので、宣言の追加も差分ゲートに効く
- (3) の状態のコミットに失敗した時は今の `commit_files` と同じく計画票・log を元に戻して終了コード1。worktree 側のマージは取り消さない（その旨を標準エラーに出す）
- `--resume-worktree` 無しの呼び出しの動き・出力・終了コードは変えない。モジュール先頭の docstring に `--resume-worktree` の説明と終了コード5を足す
- smoke のテストは、`scripts/smoke.sh` の `# 25 pr_body の件名のパターン` の行の直前に、`# 26 --resume-worktree` の見出しコメントから始まる1つのブロックとして足す（ほかのタスクが別の場所にテストを足すので、この位置から動かさない）。フィクスチャは `tw_setup todo 0` などで作り、記録行は log に直接書いてよい。テスト名は `(transition-resume) 01 …`〜`(transition-resume) 07 …` とし、番号ごとに `expect_eq` を1つだけ書く（1つの expect_eq で複数の値を空白区切りで比べてよい）：
  - 01：todo の行と、残っている worktree を指す記録行がある → 終了コード0で、行が `| T-01 | doing | 1 |` で始まる
  - 02：01 の log の最後の行が `T-01 todo→doing attempt=1 worktree を引き継ぎ` で終わる（モデルの記録が無い）
  - 03：01 の標準出力が1行で、`path=<realpath> branch=<ブランチ> plan_head=<実行前の計画ブランチの HEAD>` を含む
  - 04：記録行を書いた後に計画ブランチでタスク票を変えてコミットし、worktree に未コミットの変更を置いてから引き継ぐ → worktree のブランチが実行前の計画ブランチの HEAD を祖先に持ち、未コミットだった変更がコミットされている
  - 05：04 の後、標準出力の `plan_head` を `--plan-head` に渡した `review --worktree ... --branch ...` の終了コードが0（差分ゲートの違反が無い）
  - 06：記録行が無い todo の行 → 終了コード5で、計画票・log・計画ブランチのコミット数が変わらない
  - 07：worktree と計画ブランチが同じファイル（例：`src/ok.txt`）を別々に変えてコミット済み → 終了コード5で、計画票が変わらず、worktree にマージ中の状態（`MERGE_HEAD`）が残っていない
