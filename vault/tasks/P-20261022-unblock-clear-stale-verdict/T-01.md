# T-01 再着手の todo→doing で transition.py が古い verdict をメイン側と worktree 側から除去し、smoke に回帰テストがある

## 目的
unblock（attempt を 0 に戻す）の後の再着手で、前回の blocked の時の verdict（attempt=1, PASS）が有効に見えないよう、`scripts/transition.py` の todo→doing がその id の古い verdict を機械的に除去する（Issue #227）。回帰テストを `scripts/smoke.sh` に足す。

## 入力
- `scripts/transition.py`（`main`・`resume_worktree`・`collect_worktree`・`import_plan_head`・`commit_files`・`done_with_worktree` の古い verdict を消す箇所（「古い PASS を先に消す」のコメント））
- `scripts/smoke.sh`（`tw_setup`・`tw_verdict`・`tw_rec`・`tw_run`・`tw_mod`、`# 26 --resume-worktree` の節）
- `docs/vault-spec.md` 2節（transition.py の仕様。この票では変えない）
- `.claude/skills/run/SKILL.md` 手順6の1（worktree→メインの verdict のコピー。この票では変えない）

## 成果物
- 主な成果物：`scripts/transition.py` の todo→doing での古い verdict の除去（1関数の追加と呼び出し）
- 付随：`scripts/smoke.sh`（回帰テストの追加）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<N> fail=0` の形（N は任意の整数）である
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-stale-verdict) '` の出力が `5` である（決定済みの5件のテストがすべて ok）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (transition-resume) '` の出力が `11` である（既存の引き継ぎのテストが壊れていない）
- `grep -c '）は何も変えず終了コード' scripts/transition.py` の出力が `0` で、`grep -c '古い verdict の除去のほかは何も変えず終了コード5' scripts/transition.py` の出力が `1` である
- `git diff --merge-base work/p-20261022-unblock-clear-stale-verdict --name-only` の出力に `scripts/transition.py` と `scripts/smoke.sh` が含まれる

## 決定済み
- 方式：`transition.py` に blocked→todo の遷移は足さない（解除は `/plan` の Edit のまま。`docs/vault-spec.md` 2節の「承認と blocked の解除は扱わず」は変えない）。同等の機械的な仕組みとして、todo→doing（通常の着手と `--resume-worktree` の両方）で、対象の id の古い verdict を除去する。todo の行は stop_gate の検査対象外で、古い verdict が害になるのは doing・review になってからなので、再着手の入口で消せば unblock の経路に関係なく効く。初めての着手では verdict が無いので何もしない
- 除去する位置：`main()` で、遷移表・`after`・attempt の上限・status のそろいなどの検査をすべて通った後、`if args.resume_worktree:` の分岐より前。遷移元が todo（`old_all == "todo"`）の時だけ行う。検査で終了コード1・2になる時は除去しない
- 対象：`args.id_list` の各 id の `vault/verdicts/<計画ID>/<id>.json`（transition.py を実行したリポジトリの root の側＝メイン側）
- 除去の方法（メイン側）：追跡済み（`git ls-files --error-unmatch -- <相対パス>` が終了コード0）なら `git rm -q -f -- <相対パス>` で index と作業ツリーから消す。その後もファイルが残っていれば `os.remove` で消す（rm -f 相当。無ければ何もしない）。未追跡なら `os.remove` だけ
- 追跡済みの除去が1件以上あった時は、状態のコミットの前に、除去したパスだけを `git commit -q -m "<計画ID>/<id,...>: 古い verdict を除去" -- <パス...>` で別のコミットにする（id は除去した id をカンマでつなぐ）。未追跡だけの時はコミットしない。状態のコミット（`commit_files`）の対象と件数は変えない（smoke の `(transition) 03` が「コミットが1つ増える」「コミットのファイルは計画票と log だけ」を見ている）
- 除去・コミットの失敗は `fail`（終了コード1）。計画票と log はまだ書き換えていない時点なので、それらは変わらない
- `--resume-worktree` の順序：メイン側の除去（上の位置）を `import_plan_head` より前に済ませる。追跡済みの除去のコミットが計画ブランチの HEAD（H）に入るので、取り込みで worktree からも消える（H に verdict が残ったまま取り込むと、worktree に追跡済みの古い verdict が入り、`/run` 手順6の1のコピーで古い PASS が復活する）
- worktree 側：`resume_worktree` の中で、`check_worktree` が通った後、`collect_worktree` の前に `<worktree>/vault/verdicts/<計画ID>/<id>.json` を消す。worktree で追跡済みなら `git -C <worktree> rm -q -f -- <相対パス>`、未追跡なら `os.remove`（無ければ何もしない）。worktree 側ではコミットしない（追跡済みの削除は `collect_worktree` の収集コミットが記録する）。記録行が無い・worktree の検証に通らない時は worktree 側に触れない
- 終了コード5（引き継げない）の時も、メイン側の除去は残る（run が次に呼ぶ通常の todo→doing でも同じ除去をするので冪等）。モジュールの docstring の「引き継げない時（記録行が無い・worktree の検証に通らない・マージの衝突）は何も変えず終了コード5で、」を「引き継げない時（記録行が無い・worktree の検証に通らない・マージの衝突）は、古い verdict の除去のほかは何も変えず終了コード5で、」に、終了コードの一覧の「5  --resume-worktree で worktree を引き継げなかった（何も変えていない）」を「5  --resume-worktree で worktree を引き継げなかった（古い verdict の除去のほかは何も変えていない）」にする。docstring の todo→doing・`--resume-worktree` の説明に、古い verdict の除去（メイン側・worktree 側・追跡済みの時の別コミット）を1〜3行で足す
- smoke のテストの置き場所：`scripts/smoke.sh` の `(transition-resume) 11` の expect_eq の後、`# 再検証（他タスクが先に done になってマージ済み）` のコメントの前。既存のヘルパー（`tw_setup`・`tw_verdict`・`tw_rec`・`tw_mod`・`tw_run`）を使う。`tw_verdict PASS 1` はメイン側に未追跡で verdict を置く。worktree 側に置く時は `mkdir -p "$TWW/vault/verdicts/P-TEST"` してから `cp` する（空のディレクトリは git が持たないため worktree に無い）
- smoke のテストは次の5件（名前の先頭はこのとおり。期待値の組み立て方は任せる）。各件は expect_eq 1回：
  - `(transition-stale-verdict) 01 通常の todo→doing で未追跡の古い PASS の verdict が消える`：`tw_setup todo 0`・`tw_verdict PASS 1`・`tw_run P-TEST T-01 doing` の後、終了コード0でメイン側の verdict が無い
  - `(transition-stale-verdict) 02 通常の todo→doing で追跡済みの古い verdict が消え HEAD にも残らない`：01 と同じ準備の後に verdict をメイン側でコミットしてから `tw_run P-TEST T-01 doing`。終了コード0・ファイルが無い・`git -C "$TWR" ls-tree --name-only HEAD -- vault/verdicts/P-TEST/T-01.json` が空
  - `(transition-stale-verdict) 03 --resume-worktree でメイン側と worktree 側の未追跡の古い verdict が消える`：`tw_setup todo 0`・`tw_rec`・`tw_mod`・`tw_verdict PASS 1`・worktree 側にも同じ verdict を未追跡で置き、`tw_run P-TEST T-01 doing --resume-worktree`。終了コード0・メイン側にも worktree 側にも verdict が無い
  - `(transition-stale-verdict) 04 03 の後の review は差分ゲートの違反が無く終了コード 0`：03 の標準出力の `plan_head=` の値で `tw_run P-TEST T-01 review --worktree "$TWW" --branch "$TWB" --plan-head <その値>` が終了コード0
  - `(transition-stale-verdict) 05 計画ブランチで追跡済みの古い verdict は引き継いだ worktree にも残らず review が終了コード 0`：`tw_setup todo 0`・`tw_mod`・`tw_verdict PASS 1`・メイン側で verdict をコミット・`tw_rec`・`tw_run P-TEST T-01 doing --resume-worktree`。引き継ぎの終了コード0・メイン側にも worktree 側にも verdict が無い・出力の `plan_head=` での review が終了コード0（worktree は verdict のコミットより前から分岐しているので、H を取り込んでも net の差分に verdict が出ない）
- smoke の中の後片付けは既存の `tw_setup` に任せる（新たに `rm -rf` を書かない）
- `.claude/hooks/stop_gate.py`・`.claude/hooks/_hooklib.py`・文書（`docs/vault-spec.md`・スキルの `SKILL.md`）はこのタスクでは変えない（文書は T-02・T-03）
- 確認コマンドの smoke は1回あたり約1分20秒かかる
