# T-05 smoke.sh に主な文書の参照切れの検査を足す

## 目的
主な文書の中でバッククォートに書かれたリポジトリ相対パスが、すべて存在することを `scripts/smoke.sh` で確かめる。文書を直した後に、パスの書き間違いや廃止したファイルへの言及が残れば smoke が落ちるようにする。

## 入力
- `scripts/smoke.sh`（足す対象。`expect_eq`（1145行目付近の定義）と、末尾の `echo "smoke: pass=$PASS_N fail=$FAIL_N"`）
- 検査の対象の文書：`.claude/ai-harness.md`・`.claude/skills/*/SKILL.md`・`.claude/agents/*.md`・`README.md`・`docs/vault-spec.md`・`docs/runbook.md`・`docs/install.md`
- 計画票の分割方針の「計画作成時の調査」（今ある、存在しないパスの一覧）
- `vault/designs/D-013.md` の「フェーズ7」

## 成果物
- `scripts/smoke.sh`（1ファイル）

## 受け入れ基準
- 構文が正しい：`bash -n scripts/smoke.sh` の終了コードが0
- 参照切れの検査の4ケースが通る（今の文書に参照切れが無い・存在しないパスを対象の文書の種類ごとに見つけ、対象外の文書は見ない・雛形と除外は数えない・導入先では検査しない）：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(ref-[1-4]\) '` の出力が `4`
- 既存の smoke が全件 PASS する：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- 廃止した `vault/todo.md` を除外にしていない：`grep -c 'vault/todo.md' scripts/smoke.sh` の出力が `2`（既存の238・239行目の planner の拒否のケースだけ。計画作成時も `2`）

## 決定済み
- 検査は smoke.sh の中の関数 `refcheck <ルート>` にする（`python3 - "$1" <<'PY' … PY` の形でよい）。ルートからの相対で次を行い、存在しないパスを1件1行 `<文書の相対パス>:<行番号>: <パス>` で標準出力に出す（無ければ何も出さない）。終了コードは常に0
  - 対象の文書と順序：`.claude/ai-harness.md` → `.claude/skills/*/SKILL.md`（パスの文字列順）→ `.claude/agents/*.md`（同）→ `README.md` → `docs/vault-spec.md` → `docs/runbook.md` → `docs/install.md`。無い文書は飛ばす。`docs/decisions.md`・`vault/` の下の文書は対象にしない
  - 各行で、バッククォートで囲まれた部分（正規表現 `` `([^`\n]+)` `` で左から順に取ったもの）のうち、`vault/`・`scripts/`・`docs/`・`.claude/` のどれかで始まるものを候補にする
  - 候補から除くもの：`<`・`*`・`{`・`$`・空白のどれかを含むもの（雛形）／`vault/rules/` で始まるもの（D-013 の決定済み：`vault/rules/` 配下は対象外）／除外リストに完全一致するもの
  - 除外リストは次の4つだけ：`vault/designs/D-xxx.md`（例）・`.claude/projects`（`~/.claude/projects/` の略記）・`.claude/harness-manifest.json`（導入先にできる）・`.claude/settings.local.json`（各人の環境にできる）。`vault/todo.md` は入れない
  - 存在の判定は `os.path.exists(<ルート>/<パス>)`（末尾の `/` はそのままでよい）
  - `<ルート>/.claude/harness-manifest.json` があれば（導入先）、何も検査せず何も出さない（導入先には `README.md`・`docs/runbook.md` などが無く、`docs/vault-spec.md` などが指すパスが切れるため）
- 足すケースは次の4つ。名前はこの文字列で始める。判定は既存の `expect_eq` を使う。置く場所は末尾の `echo` の直前。フィクスチャは smoke の一時ディレクトリ `$TMP` の下の `$TMP/refcheck/a`・`b`・`c` に `mkdir -p` と `printf` で作る
  - `(ref-1) 主な文書のバッククォート内のパスがすべて存在する`：`refcheck "$ROOT"` の出力が空
  - `(ref-2) 存在しないパスを対象の文書ごとに見つけ、対象外の文書は見ない`：`a` に次を置き、出力が下の5行と完全に一致する
    - `.claude/ai-harness.md`（1行目 `` `scripts/no-such-a.sh` ``）・`.claude/skills/x/SKILL.md`（1行目 `` `docs/no-such-b.md` ``）・`.claude/agents/y.md`（1行目 `` `vault/no-such-c.md` ``）・`README.md`（1行目 `なし`、2行目 `` `.claude/no-such-d.md` ``）・`docs/install.md`（1行目 `` `docs/no-such-e.md` ``、2行目 `` `docs/install.md` ``（存在するので出ない））・`docs/decisions.md`（1行目 `` `docs/no-such-f.md` ``（対象外なので出ない））
    - 期待する出力：`.claude/ai-harness.md:1: scripts/no-such-a.sh`、`.claude/skills/x/SKILL.md:1: docs/no-such-b.md`、`.claude/agents/y.md:1: vault/no-such-c.md`、`README.md:2: .claude/no-such-d.md`、`docs/install.md:1: docs/no-such-e.md` をこの順に改行でつないだもの
  - `(ref-3) 雛形・vault/rules/ 配下・除外リストは数えない`：`b` の `README.md` に `` `vault/<id>.md` ``・`` `scripts/*.sh` ``・`` `docs/{a,b}.md` ``・`` `vault/$X.md` ``・`` `docs/a b.md` ``・`` `vault/rules/x.md` ``・`` `vault/designs/D-xxx.md` ``・`` `.claude/projects` ``・`` `.claude/harness-manifest.json` ``・`` `.claude/settings.local.json` `` を1行ずつ書き、出力が空（`b` には `.claude/harness-manifest.json` のファイルは置かない）
  - `(ref-4) 導入先（.claude/harness-manifest.json がある）では検査しない`：`c` に `.claude/harness-manifest.json`（中身 `{}`）と、`README.md`（1行目 `` `scripts/no-such.sh` ``）を置き、出力が空
- `printf` でバッククォートや `$` を書く時は、シングルクォートの書式文字列にして展開させない
- 計画作成時の調査で、対象の文書の存在しないパスは除外リストの4つ・`vault/rules/` で始まるもの・`vault/todo.md`（T-01 で消える）だけだった。`(ref-1)` がそれ以外のパスで落ちた時は、除外リストに足したり他のファイルを直したりせず（このタスクの成果物は `scripts/smoke.sh` だけ）、出力をそのまま question に書いて `blocked` にする
- 既存のケースと関数は変えない。一時ファイルは `$TMP` の下だけに作り、消す処理は足さない（既存の `trap` に任せる）
- `bash scripts/smoke.sh` はサンドボックスの中で実行してよい（前の計画で `mktemp` を `$TMPDIR` の下にしてある）
