# T-07 タスク境界を git に明示し、宣言外ファイル検査の範囲をそのタスク分に限定する

## 目的
T-06 で指定した `git diff --name-only main...HEAD` はブランチ全体の差分を見るため、同じ計画の前のタスクが
作った成果物まで「宣言外」として拾ってしまう（2番目以降のタスクで必ず誤検知が出る）。creator がタスク着手
時の起点コミットを記録し、verifier がその起点から `HEAD` までに範囲を絞れるようにする。

## 入力
- `vault/rules/creator/git-workflow.md`（改訂対象。起点コミットの記録を手順に足す）
- `vault/rules/verifier/verifier.md`（改訂対象。T-06 で書いた範囲指定を起点コミット基準に直す）
- `.claude/agents/verifier.md`（改訂対象。手順9の範囲指定を同じに揃える）

## 成果物
- 上記3ファイル（範囲指定を「タスクの起点コミットから HEAD まで」に統一する改訂）

## 受け入れ基準
- `vault/rules/creator/git-workflow.md` に、タスクを `doing` にした直後の時点のコミットハッシュを
  タスク票の「進捗」に `起点コミット: <短縮ハッシュ>` の形で記録する手順がある。確認：
  `grep -cF '起点コミット' vault/rules/creator/git-workflow.md` が1以上
- `vault/rules/verifier/verifier.md` の宣言外ファイル検査が、タスク票の「進捗」の起点コミットを使う
  範囲指定になっている。確認：`grep -cF '起点コミット' vault/rules/verifier/verifier.md` が1以上、かつ
  `grep -c 'main\.\.\.HEAD' vault/rules/verifier/verifier.md` が0
- 起点コミットが「進捗」に無い場合の扱い（記録が無ければこの検査は行わず、その旨を `note` に書く）が
  `vault/rules/verifier/verifier.md` に明記されている。確認：
  `grep -cF '起点コミットの記録が無い場合' vault/rules/verifier/verifier.md` が1以上
- `.claude/agents/verifier.md` の手順9も同じ範囲指定になっている。確認：
  `grep -cF '起点コミット' .claude/agents/verifier.md` が1以上、かつ
  `grep -c 'main\.\.\.HEAD' .claude/agents/verifier.md` が0
- 3ファイルとも既存の「やらないこと」「## 禁止」節のブレット数が変わっていない。確認：
  `sed -n '/\*\*やらないこと\*\*/,/^## 確認方法/p' vault/rules/verifier/verifier.md | grep -c '^- '` が7、
  `sed -n '/^## 禁止/,/^## 出力/p' .claude/agents/verifier.md | grep -c '^- '` が4

## 決定済み
- **creator 側の手順**（`vault/rules/creator/git-workflow.md` の「ルール」に1ブレット追加）。文面はそのまま
  使ってよい：
  `- タスクを \`doing\` にしたら、その時点の \`git rev-parse --short HEAD\` を取り、タスク票の「進捗」の先頭に \`起点コミット: <短縮ハッシュ>\` の形で1行記録する。verifier はこの起点から \`HEAD\` までの差分を見て、そのタスクの変更範囲を判断する。`
- **verifier 側の範囲指定**（`vault/rules/verifier/verifier.md` の宣言外ファイル検査のブレットを差し替え）。
  `git diff --name-only <起点コミット>..HEAD` を使う形にし、`main...HEAD` の記述は消す。起点コミットの
  記録が無い場合はこの検査を行わず、その旨を `note` に書く（`reasons` には入れない。creator の記録漏れは
  基準違反ではないため）。除外リスト4項目（計画票・タスク票の「進捗」・`vault/log/<計画ID>.md`・
  `vault/verdicts/` 配下）はそのまま残す。
- **エージェント定義**（`.claude/agents/verifier.md` の手順9）も同じ範囲指定・同じ例外扱いに揃える。
- verifier はタスク票の「進捗」を**判定の根拠**にはしない（既存の「やらないこと」のとおり）が、起点コミット
  の読み取りは判定の根拠ではなく検査範囲の決定に使うだけなので矛盾しない。この点を verifier 側の文面に
  1文添えること（例：`「進捗」から読むのは起点コミットの値だけで、判定の根拠には使わない。`）。
- `vault/rules/` 配下2ファイルは `doing`/`review` 中は `agent_write_guard.py` に阻まれる。人が承認済みの
  回避策「`todo` のうちに内容を編集し、その後 `doing` にする」を使う。`.claude/agents/verifier.md` は
  対象外なのでいつ編集してもよい。
- このタスク自身の起点コミットは、新ルールがまだ無い状態で着手するため記録しなくてよい（T-05 の実地
  テストから運用を始める）。
