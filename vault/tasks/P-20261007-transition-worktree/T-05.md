## 決定済み
- 書く場所：2節の今の transition.py の箇条書き（`- 終了コード：0 遷移した／…` の行の前後）に、worktree 運用の段落と箇条書きを足す。新しい `## ` の節は作らない（節番号を変えない）
- 2節に書くこと（T-01〜T-03 の決定済みを要約する。字句は `scripts/transition.py` の実際の動きに合わせる）：
  - 呼び出しの形 `python3 scripts/transition.py <計画ID> <id> <review|done|doing|blocked> --worktree <パス> --branch <ブランチ> [--plan-head <sha>]`（`--plan-head` は review・done・blocked で必須、doing では使わない）。id は1つだけ。`--worktree` と `--branch` はそろって使う
  - worktree とブランチの検証は `scripts/discard_worktree.sh` と同じ条件（`worktree-agent-` で始まる・`git worktree list --porcelain` に登録済み・登録されたブランチが一致。パスは realpath で比べる）
  - review：収集コミット（`<計画ID>/<id>: creator 成果物をオーケストレーターが収集`）→ 新規コミットの判定（`git rev-list <plan-head>..<branch>` が0件なら doing→blocked）→ 差分ゲート（`diff_gate.check`。base は plan-head）→ 違反なしなら記録行と doing→review。違反ありなら差し戻し（タスク票の「進捗」に `- 差し戻し（attempt=<n>）: 宣言外の変更 <パス>, ...`、doing のまま attempt+1、worktree を破棄）、上限なら blocked にして worktree を残す
  - done：PASS の verdict の確認 → 収集はしない → 新規コミットの判定 → 差分ゲート（違反なら review→blocked）→ `git merge --no-ff <branch> -m "<計画ID>/<id>: マージ"` → done にしてコミット → `git worktree remove --force` → `git branch -d`。衝突したら `git diff --name-only --diff-filter=U` で衝突ファイルを取って `git merge --abort` し、review→blocked（question に衝突ファイル）、worktree は残す
  - doing（FAIL の再試行。review からだけ）：attempt+1 して worktree を破棄。log の補足は reasons の先頭を80文字で切ったもの。上限なら reasons を `／` でつないで200文字で切ったものを question にして review→blocked、worktree は残す
  - blocked（creator の blocked の報告。doing からだけ）：記録行を書いて doing→blocked、worktree は残す（収集・差分ゲートはしない）
  - 終了コード：`0 review/done にした／1 前提を満たさず何もしていない／2 引数の誤り／3 差し戻した（creator を呼び直す）／4 blocked にした`。この字句（`3 差し戻した`・`4 blocked にした` を含む）で書く。3・4 の時は何をしたかを標準出力に1行で出す（run が完了報告に写せるように）
  - `--worktree` を渡さない呼び出しは今の（フェーズ2の）動きのまま
- 2節の最後の行「今の `/run`（`.claude/skills/run/SKILL.md`）の手順はまだ `scripts/transition.py` を呼ばない」は残す（worktree 運用も含めてまだ呼ばない）
- 5節の最後の行「今の `/run` … はまだ `scripts/diff_gate.py` を呼ばない」は、「`scripts/transition.py` の worktree 運用（2節）が `check` を import して使う。今の `/run` … の手順はまだどちらも呼ばない」の趣旨に直す（`/run` と `まだ` を同じ行に残す）
- 7節：再開情報の記録行の段落の後ろに、transition.py の worktree 運用が書く行（記録行は review・blocked の時に遷移の行の直前に同じ日時で書くこと、差し戻しの行 `doing→doing attempt=<n+1> 宣言外の変更: <パス>, ...` はモデルを付けないこと、done 前の blocked の補足 `新規コミット無し`・`宣言外の変更: <パス>, ...`・`マージコンフリクト`）を足す
- 1節：`scripts/pr_body.py` の説明の段落（「引数なしの `scripts/vcs_finish.sh` は…」）の「`<計画ID>/<id>: done` コミットの短縮ハッシュ」を、`<計画ID>/<id>: done`（従来の run）か `<計画ID>/<id>: review→done`（transition.py。複数 id の `<計画ID>/T-01,T-02: review→done` も含む）のコミットの短縮ハッシュ、の趣旨に直す。字句 `<計画ID>/<id>: review→done` をこの段落に入れる。1節のほかの記述（証跡の段落など）は変えない（フェーズ5で run の流れが変わる時に直す）。9〜12節も変えない
- 実在しない `scripts/<名前>` を書かない（smoke の「参照される scripts の存在チェック」が fail する）
- `scripts/transition.py`・`scripts/pr_body.py`・`scripts/smoke.sh`・`.claude/skills/run/SKILL.md` は変えない
