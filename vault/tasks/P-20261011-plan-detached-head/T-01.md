# T-01 /plan 手順A-2・/design 手順1 に detached HEAD でベースと一致する時の checkout を加える

## 目的
クラウドセッションが detached HEAD（`git branch --show-current` が空）で始まった時、HEAD がローカルのベースブランチと同じコミットなら `git checkout <ベースブランチ>` してベース上とみなし、開始条件で止まらないようにする（GitHub Issue #178）。

## 入力
- `.claude/skills/plan/SKILL.md` の「## A. 計画を作る」の手順2（1行の段落）
- `.claude/skills/design/SKILL.md` の「## 手順」の手順1（1行の段落）
- `docs/decisions.md` の Issue #175 の行（直前に入った best-effort の fetch の経緯）

## 成果物
- `.claude/skills/plan/SKILL.md`（主な成果物。手順A-2 の段落への1文の挿入）
- `.claude/skills/design/SKILL.md`（手順1 の段落への同じ1文の挿入）

## 決定済み
- 挿入する文（2ファイルとも一字一句同じ。改行を入れず、既存の段落の「この fetch は best-effort で、…そのまま下の確認に進む。」の直後、「一致しなくても、`echo "${HARNESS_PUSH_BRANCH:-}"` …」の直前に入れる）：
  `` `git branch --show-current` の出力が空（detached HEAD）の時は、この fetch の後で `git rev-parse HEAD` の出力と `git rev-parse --verify <ベースブランチ>` の出力を比べ、同じなら `git checkout <ベースブランチ>` してベースブランチ上とみなす（`git checkout -f`・`git reset`・`git stash` は使わない非破壊の操作）。違う時、`git rev-parse --verify <ベースブランチ>` が失敗した時、`git checkout <ベースブランチ>` が失敗した時（未コミットの変更とぶつかる等）は、ブランチを切らず、下のどちらの条件も満たさない時と同じ案内を伝えて**止まる**。 ``
  （外側の二重バッククォートと前後の空白は票の書式で、挿入する文には含めない。文中のバッククォートと `**` は含める）
- 段落のほかの文は変えない。既存の fetch の文（「一致しない時は、下の確認の前に `git fetch origin …` を1回行う」）は detached の時も当てはまる（`git branch --show-current` が空なのでベースと一致せず fetch が先に走り、detached なのでベースはチェックアウト中でなく fetch は拒否されない）ので、fetch の順序のための書き換えは要らない
- checkout の後の続き：/plan は手順3の `git checkout -b work/<計画IDの英小文字>`、/design は同じ手順1の「ベースブランチ上なら `git checkout -b design/…`」でブランチを切る。これらの文も変えない
- 止まる時の案内は、各スキルの既存の案内（「ベースブランチ（`<値>`）に戻ってから `/plan`（または `/design`）を実行してください」）を指す。2ファイルの文言をそろえるため、挿入文ではスキル名を書かず「下のどちらの条件も満たさない時と同じ案内」と書く
- 既存の smoke・hooks・tests は開始条件の文言を検査していない（planner が確認済み）。smoke の変更は不要で、成果物にも含めない
- この変更は手順書（文章）だけで実行可能なコードを持たないため、受け入れ基準は文言の位置と一字一句の一致で確かめる（grep の対象は挿入文全体と前後の文で、部分語の出現数ではない）
- 2ファイルは `.claude/skills/` 配下なので、auto モードで Self-Modification として拒否されたら blocked にして question に書く
