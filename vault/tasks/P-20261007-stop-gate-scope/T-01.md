# T-01 stop_gate.py の判定順を変え、承認済みの計画票が0件なら未コミットの検査もせずに許可する

## 目的
`.claude/hooks/stop_gate.py` の `main()` の判定順を「`stop_hook_active` → approved な計画票の件数 → 未コミットの変更 → done の行 → doing/review の行」に変え、承認済みの計画票が無いリポジトリ（`main` など）では未コミットの変更があっても終了を止めないようにする。smoke にケースを足し、前提が変わる既存のケースを直す。

## 入力
- `vault/designs/D-013.md` の「フェーズ1 Stop フックの適用範囲と無人実行での厳格化」（決定済み）
- `.claude/hooks/stop_gate.py`（`main()` と先頭の docstring）
- `.claude/hooks/_hooklib.py`（`approved_plans`。読むだけ）
- `scripts/smoke.sh`（`== stop_gate.py ==` の節の (f)・(g)、`== _hooklib.py ==` の節の `(stop_gate worktree)` の2ケース）

## 成果物
- `.claude/hooks/stop_gate.py`（主な成果物）
- `scripts/smoke.sh`（ケースの追加と既存ケースの前提の直し）

## 受け入れ基準
- 承認済みの計画票が無い git リポジトリでは、未コミットの変更があっても許可する：`bash scripts/smoke.sh 2>&1 | grep -F 'ok   (stop-scope-1)'` の出力が1行
- 承認済みの計画票が2件ある git リポジトリでは、未コミットの変更があっても未コミットより先に件数でブロックする（reason に `approved な計画票が2件` を含む）：`bash scripts/smoke.sh 2>&1 | grep -F 'ok   (stop-scope-2)'` の出力が1行
- 承認済みの計画票が1件ある git リポジトリでは、今どおり未コミットの変更でブロックし、無ければ許可する（(f)・(g) と worktree の2ケースが通る）：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   (\((f|g)\) 未コミットの変更が|\(stop_gate worktree\) (未コミットのファイル|ファイルを消す))'` の出力が `4`
- `main()` の判定順が決定済みの順になっている（`approved_plans` の件数の判定が `has_uncommitted_changes` の呼び出しより前にあり、`stop_hook_active` の判定はその前のまま）。確認：`grep -nE 'if payload\.get\("stop_hook_active"\)|plans = H\.approved_plans\(root\)|if has_uncommitted_changes\(root\)' .claude/hooks/stop_gate.py` の出力が3行で、上から `stop_hook_active`・`approved_plans`・`has_uncommitted_changes` の順（計画作成時点は `stop_hook_active`・`has_uncommitted_changes`・`approved_plans` の順）
- 先頭の docstring に判定順（承認済みの計画票が0件なら未コミットの検査もせずに許可）が書かれている（Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 基準4の grep のため、`if payload.get("stop_hook_active")`・`plans = H.approved_plans(root)`・`if has_uncommitted_changes(root)` の3つの文の書き方は今のまま残し、`main()` の中で各1回だけ使う
- 判定の順序（D-013 の決定済みのとおり）：
  1. 委譲（`H.delegate_to_worktree`。今どおり最初）
  2. `stop_hook_active`（今どおり。`HARNESS_STRICT_STOP=1` なら無視して続ける）
  3. `root = project_dir(payload)` の後、`plans = H.approved_plans(root)`。0件なら `allow()`、2件以上なら今の文言のまま `block()`
  4. 1件の時だけ `has_uncommitted_changes(root)` で、今の文言（`未コミットの変更があります`）のまま `block()`
  5. done の行の検査、doing/review の行の検査（今どおり）
- ブランチ名は見ない（承認済みの計画票はその計画のブランチにしか無く、`main` では PR を作った時点で done になっているため）
- 既存のブロックの文言は変えない。`has_uncommitted_changes` の中身も変えない
- `_hooklib` の読み込みに失敗した時の処理（ファイル先頭の except 節）は変えない
- smoke の新しいケースは `== stop_gate.py ==` の節の (f)・(g) の近くに置き、名前を `(stop-scope-1)`・`(stop-scope-2)` で始める（基準の grep はこの接頭辞で見る）。増えるのはこの2件だけ
  - (stop-scope-1)：`git init` してコミットした一時リポジトリ（`vault/plans/` はあるが approved な計画票は無い）に未コミットのファイルを置く → `allow`
  - (stop-scope-2)：同じ形のリポジトリに approved な計画票を2つ置いてコミットし、未コミットのファイルを置く → `block`、期待する部分文字列は `approved な計画票が2件`
- 既存の (f)・(g) と `(stop_gate worktree)` の2ケースは、承認済みの計画票（`make_plan` と同じ形。タスク表は `| T-0001 | todo | 0 | - | A | |` の1行）を置いて `git add`・`git commit` してから検査する形に直す。ケース名と期待値（block/allow と部分文字列）は変えない。直したケース名はこのタスク票の「進捗」に列挙する（PR 本文に載せるため）
- 計画票を未コミットのまま置くと、それ自体が未コミットの変更になる。必ずコミットしてから dirty なファイルを置く
- 一時リポジトリは既存のケースと同じく `mktemp -d` で作り、`git -c user.email=t@example.com -c user.name=t commit` の形でコミットする（smoke の中の後片付けは既存どおりでよい）
- `(delegate stop_gate)` のケースは承認済みの計画票をコミット済みなので直さなくてよい（通ることだけ確認する）
- `.claude/hooks/_hooklib.py`・`docs/` は変えない（文書は T-03・T-04）
