# T-01 .claude/settings.json にサンドボックスの設定を足す

## 目的
このリポジトリの `.claude/settings.json` に Claude Code のサンドボックスの設定（`sandbox` キー）を足し、Bash とその子プロセスから `vault/rules/` と会話記録（`~/.claude/projects/`）への書き込みを OS で拒否し、通信先を GitHub だけにする。

## 入力
- `vault/designs/D-013.md` の「フェーズ5 サンドボックスを有効にする」（ゴール文・決定済み）
- `.claude/settings.json`

## 成果物
- `.claude/settings.json`（1ファイル。`sandbox` キーの追加だけ）

## 受け入れ基準
- `sandbox` の値が決定済みのとおりである：`python3 -c "import json; s=json.load(open('.claude/settings.json')).get('sandbox', {}); print(s.get('enabled'), s.get('allowUnsandboxedCommands'), sorted(s.get('filesystem', {}).get('denyWrite', [])), sorted(s.get('network', {}).get('allowedDomains', [])), 'failIfUnavailable' in s, 'excludedCommands' in s)"` の出力が `True False ['./vault/rules', '~/.claude/projects'] ['*.github.com', '*.githubusercontent.com', 'github.com'] False False`
- 最上位のキーが `sandbox` の1つだけ増えている：`python3 -c "import json; print(sorted(json.load(open('.claude/settings.json'))))"` の出力が `['hooks', 'permissions', 'sandbox', 'worktree']`
- `permissions`・`hooks`・`worktree` が main の版から変わっていない：`python3 -c "import json,subprocess; a=json.load(open('.claude/settings.json')); b=json.loads(subprocess.check_output(['git','show','main:.claude/settings.json'])); print(a['permissions']==b['permissions'], a['hooks']==b['hooks'], a['worktree']==b['worktree'])"` の出力が `True True True`
- `sandbox` の中のキーが決定済みの4つだけである：`python3 -c "import json; s=json.load(open('.claude/settings.json'))['sandbox']; print(sorted(s), sorted(s['filesystem']), sorted(s['network']))"` の出力が `['allowUnsandboxedCommands', 'enabled', 'filesystem', 'network'] ['denyWrite'] ['allowedDomains']`
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 足す内容は次のとおり（キーの順もこのとおり。`hooks` の後、ファイルの最後のキーとして足す。インデントは既存と同じ2スペース）

  ```json
  "sandbox": {
    "enabled": true,
    "allowUnsandboxedCommands": false,
    "filesystem": {
      "denyWrite": ["./vault/rules", "~/.claude/projects"]
    },
    "network": {
      "allowedDomains": ["github.com", "*.github.com", "*.githubusercontent.com"]
    }
  }
  ```

- `denyWrite` のパスの書き方は、公式ドキュメント（sandboxing のページ）で確認済みのもの：プロジェクトの設定（`.claude/settings.json`）では `.` で始まる相対パスがプロジェクトのルートに解決され、`~/` はホームからの相対、`/` で始まるパスは絶対パス（Read/Edit の許可ルールの `//path`・`/path` とは書き方が違う）。末尾の `/` は付けない。`./vault/rules` のように `.` で始まる書き方は、ドキュメントの例（`.` がプロジェクトのルートになる）と同じ系統だが、`./` 付きのサブディレクトリと末尾の扱いの細かい表は確認できていない。実際の解決先は、マージ後に人が新しいセッションの `/sandbox` の Config タブで確かめる（T-05 の手順）。creator はドキュメントを確かめに行かなくてよい
- `failIfUnavailable` は設定しない（サンドボックスが使えない環境でも Claude Code を起動できるようにするため。その環境では今の Bash の解析が守りになる）
- `excludedCommands` は入れない（`vcs_finish.sh` が動かないと分かった時だけ、別の計画で足す）
- `network.allowedDomains` に Anthropic の API のドメインは入れない（入れ子の claude を動かさないため）
- `permissions.allow`・`permissions.deny`・`hooks`・`worktree` は変えない
- `scripts/merge_settings_json.py`（T-06 が変える）・`agent_write_guard.py` は、このタスクでは変えない
- 設定はセッションの開始時に読まれるので、このセッションの中で効き目を確かめなくてよい（確かめようとして `vault/rules/` に書き込むコマンドを実行しない）
- 編集が Claude Code 本体（設定ファイルの保護・権限の確認）に拒否された時は、別の方法で書き込もうとせず、`blocked` にして question に「`.claude/settings.json` の編集が拒否された」と拒否の理由を書く。その後は人が上の JSON を手で足してコミットし、`/plan unblock` で T-01 を進める（計画票の人への質問2の回答）
