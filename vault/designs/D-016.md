# ゴール
タスク実行で溜まる計画一式（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）と設計文書を `main` に残さないようにし、リポジトリの肥大化と、影響調査で古い情報を読む悪影響を無くす。記録が要る情報は、除去の前に docs への追記か Issue 化で取り出す。

## 決定事項
人に聞いて確定した回答。以降のフェーズはこれを前提にする。1件1行。

| 決めたこと | なぜ |
|---|---|
| 方式は「PR 作成の直前に計画一式を除去する」。計画ブランチの中では従来どおり git で管理し、`main` には入れない | ブランチ内では worktree・`transition.py` のコミット・フックが、vault/ が git で管理されていることを前提にしている。`.gitignore` で管理外にすると大改修になる。PR の前に除去すれば、古い情報が `main` に溜まらない（人の選択） |

## フェーズ1 run の完了時に計画一式を取り出してから除去する

### ゴール文
run の完了手順（`.claude/skills/run/SKILL.md` の手順7）で、PR を作る直前に、計画の記録を PR 本文に写し、残すべき情報を docs への追記か Issue 化で取り出し、`scripts/purge_plan.sh` で計画一式4種（`vault/plans/<計画ID>.md`・`vault/tasks/<計画ID>/`・`vault/verdicts/<計画ID>/`・`vault/log/<計画ID>.md`）を `git rm` してコミットするようにする。計画の記録は新しいスクリプト `scripts/plan_record.py` が出す。仕様（`docs/vault-spec.md`）・`docs/runbook.md`・`.claude/ai-harness.md`・smoke を合わせて直す。

### 受け入れ基準の候補
- `bash scripts/purge_plan.sh <計画ID>` は、現在のブランチが `work/<計画IDの英小文字>`・計画票の frontmatter が `status: done`・タスク表が1行以上で全行 `done`・対象パスに未コミットの変更が無い、の全部を満たす時だけ4種を `git rm` し、終了コード0で終わる。どれかを外れたら何も消さずに理由を標準エラーに出して終了コード1で終わる（smoke で確認：`bash scripts/smoke.sh`）
- `bash scripts/purge_plan.sh --dry-run <計画ID>` は消す予定のパスを1行1件で出し、作業ツリーとインデックスを変えない（smoke で確認）
- `python3 scripts/plan_record.py <計画ID>` は、計画票の「ゴール」節・タスク表・`vault/log/<計画ID>.md` の全行を Markdown で標準出力に出し、ファイルに書き込まない（smoke で確認）
- `.claude/skills/run/SKILL.md` の手順7に、「計画票を done にする → pr_body.py・verdict_notes.py・plan_record.py を実行する → 取り出し（docs 追記・Issue 化）→ 本文ファイルを書く → purge_plan.sh とコミット → vcs_finish.sh」の順が書かれている（`grep -n 'purge_plan.sh\|plan_record.py' .claude/skills/run/SKILL.md` が手順7の中で一致する）
- `docs/vault-spec.md` の1節と7節に、計画一式が PR の直前に除去され `main` に入らないことと、証跡が PR に残ることが書かれている（`grep -n 'purge_plan.sh' docs/vault-spec.md` が一致する）
- 既存の `bash scripts/smoke.sh` が全部通る

### 決定済み
- `purge_plan.sh` はコミットしない。コミットはオーケストレーターが `<計画ID>: 計画一式を除去` のメッセージで行う
- `purge_plan.sh` の終了コードは 0（消した／dry-run で出した）・1（条件を満たさない。何も消さない）・2（引数の誤り・git リポジトリの外）。対象のうち存在しないパス（例：verdicts が無い）は飛ばす
- verdict が PASS かの検査は `purge_plan.sh` ではしない（done の判定は plan_guard と Stop フックが既にしている）
- `plan_record.py` の出力の見出しは `## 計画の記録` とし、その下に `### ゴール`・`### タスク表`・`### log` を置く。log は `<details>` で畳んでよい。計画票や log が無い時は標準エラーに出して終了コード1
- PR 本文の構成は、計画 ID の1行・`pr_body.py` の出力・`## verifier の指摘`（`verdict_notes.py` の出力）・`plan_record.py` の出力・`## 取り出した情報`（docs に追記した箇所と、作った Issue の一覧。無ければ「なし」）の順
- 取り出しの判断基準（オーケストレーターが手順7で行う）：
  - タスク票の「決定済み」の判断・`/plan unblock` の回答・blocked の question のうち、恒久的な仕様や判断で、まだ docs に無いもの → `docs/vault-spec.md` などの該当文書か `docs/decisions.md` に追記し、同じコミットに含める
  - 対応しなかった verifier の指摘・残課題 → run 手順8と同じ方法（`gh api` による起票）で Issue にする。失敗した時は PR 本文の `## 取り出した情報` に「Issue にできなかったもの」として書く
  - 仕様の変更そのものは各タスクで docs に反映済みのはずなので、二重に書かない
- 取り出しによる docs の編集は、オーケストレーターが成果物を作らない原則の例外として `.claude/ai-harness.md` の「役割」に明記する
- 手順8（ハーネス振り返り）は変えない。除去の後に実行する
- 新しいスクリプトは `scripts/` 直下に置くので、`install.sh` の配布対象に自動で入る（除外リストは触らない）
- フェーズ1の実行中の計画自身の一式は、更新後の手順7で除去されればそれでよい。残った場合はフェーズ2の一括削除で消える

## フェーズ2 main に残った計画一式と archive を一括で削除できるようにし、archive を廃止する

### ゴール文
`scripts/purge_plan.sh` に、`main` にマージ済みの計画一式と `vault/archive/` をまとめて削除する `--merged` モード（`--list`・`--report`・`--apply`）を足し、`scripts/archive_plans.sh` を廃止する。`--report` は削除の前に人が Issue 化すべき情報（最後の遷移が `blocked` のタスクとその question、verdict の `reasons`）を一覧で出す。`docs/runbook.md` 5節を「一括削除の手順」に書き換え、`docs/vault-spec.md`・`scripts/install.sh`・`scripts/uninstall.sh`・smoke から archive の記述を除く。実際の削除はこのフェーズのマージ後に人が runbook の手順で行う。

### 受け入れ基準の候補
- `bash scripts/purge_plan.sh --merged --list` は、`vault/plans/*.md` のうち現在のブランチの計画でなく、作業ツリーと `main` の版の両方で `status: done` の計画 ID を1行1件で出し、何も変えない（smoke で確認）
- `bash scripts/purge_plan.sh --merged --report` は、対象の計画について、最後の遷移が `→blocked` のタスクの id と question、空でない verdict の `reasons` を `<計画ID>/<id>: <内容>` の形で出し、何も変えない（smoke で確認）
- `bash scripts/purge_plan.sh --merged --apply` は、対象の計画の4種と `vault/archive/` を `git rm` し、コミットはしない。対象パスに未コミットの変更があれば何も消さずに終了コード1（smoke で確認）
- `scripts/archive_plans.sh` が無く、`grep -rn 'archive_plans' docs .claude scripts README.md` が何も出さない
- `docs/vault-spec.md` の1節の表に `vault/archive/` の行が無く、`scripts/install.sh` が `vault/archive/.gitkeep` を作らない
- `bash scripts/smoke.sh` が全部通る

### 決定済み
- `--merged --apply` は人だけが実行する。エージェントは `--list`・`--report` だけを使う（スクリプト冒頭のコメントと runbook に書く。`archive_plans.sh` と同じ扱い）
- `--keep` 相当（新しい N 件を残す）は持たない。マージ済みは全部消す
- 対象の条件は `archive_plans.sh` の条件1〜5（ID の形式・現在のブランチでない・`status: done`・タスク表が全行 done・`main` の版が done）を引き継ぐ。条件6（log の日時行）は使わない
- `vault/archive/` は中身の形式（旧形式の `todo.md` などを含む）を問わず丸ごと消す
- `model_stats.py` のコード（引数で渡したファイルを読む）は変えない。docs の `vault/archive/*/log/*.md` を渡す例だけを消す。smoke の (ms-2) のように archive をパスの例に使っているだけのテストは、そのままでよい
- `docs/decisions.md` の過去の行（archive に関する判断）は書き換えない。廃止の判断を新しい行として追記する
- runbook の新しい5節の手順：作業ブランチを切る → `--merged --report` を見て必要なものを人が Issue 化 → `--merged --apply` → `git commit` → PR
- `vault/harness-improvements/` は触らない
