# T-01 run/SKILL.md 手順3・5の Agent 呼び出しに run_in_background: false を明記する

## 目的
`/run` スキルの手順3（creator 呼び出し）・手順5（verifier 呼び出し）は、オーケストレーターが Agent ツールの完了を同期的に待つことを前提に後続手順（review 化・検証結果判定）を書いているが、`run_in_background` の指定がどちらの箇所にも書かれていない。既定（バックグラウンド実行）のまま呼ぶと、creator/verifier が完了する前にオーケストレーターの応答が終わろうとし、Stop フックにブロックされる往復が発生する（issue #63、実セッションで実際に再現）。両呼び出し箇所に `run_in_background: false` を明記する。

## 入力
- `.claude/skills/run/SKILL.md` の「## 3. 作る」節（特に2番目の項目、creator の Agent ツール呼び出し。現状21行目付近ではなく28行目）
- 同ファイルの「## 5. 検証する」節（特に1番目の項目、verifier の Agent ツール呼び出し。現状42行目）
- `vault/rules/common/roles.md`（planner→creator→verifier の受け渡し方針。呼び出し方自体は変えないことの確認用）

## 成果物

## 決定済み
- 追加方法は、既存の番号付きリスト項目（手順3の2番目「選んだタスクそれぞれについて、Agent ツールで creator サブエージェントを呼ぶ...」／手順5の1番目「review にした...Agent ツールで verifier サブエージェントを呼ぶ...」）の文中または文末に一文を追記する形にする。新しい番号付き項目を追加しない（他の記述が「手順3」「手順5」を項目番号込みで参照していないため番号ズレの実害は無いが、差分を最小にするため既存文への追記を優先する）
- 追記する文言の趣旨は「この Agent ツール呼び出しは `run_in_background: false` を指定し、同期的に完了を待つこと（`/run` の後続手順の判定が呼び出し結果に依存するため）」。文言の細部（語順・句読点）は自由でよいが、`run_in_background: false` という文字列と、結果への依存・同期を示す語（「結果に依存」または「同期的」のいずれか）の両方を含めること
- `isolation: "worktree"`（手順3）・`isolation` オプションを付けない（手順5）という既存の指定は変更しない。`run_in_background` の指定を追加するだけで、他のオプション・prompt の内容・呼び出し対象（creator/verifier）は変えない
- 「## ハング時の復旧」節（手順3・5の Agent 呼び出しが応答しない場合の節）は本タスクの対象外。`run_in_background: false` にしても Agent ツール呼び出し自体がハングする可能性は残るため、その節の記述は変更しなくてよい
- 確認コマンドの一時ファイルは `/tmp/P-20260926-run-creator-verifier-sync-T01-*.txt` の固定パスを使い、`mktemp` は使わない（`rm -rf` による後片付けを前提にしないため）
