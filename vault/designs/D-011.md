# ゴール

`.claude/hooks/` の3フック（`agent_write_guard.py`・`plan_guard.py`・`stop_gate.py`）に複製されている共通関数を共通モジュール `.claude/hooks/_hooklib.py` に切り出し、「フック間で import しない」方針を廃止する。あわせて、複製の間で食い違っている解析規則を1つに揃え、`agent_write_guard.py` の Bash 書き込み判定（解析不能時の従来判定が4通りある）を一本化し、`stop_gate.py` の `.git` 判定が worktree で無効になる不具合を直す。実戦投入前に、保守のたびに複製がずれていく構造を解消する。

## 決定事項

| 決めたこと | なぜ |
|---|---|
| 「フック間で import しない」方針を廃止し、共通関数を `.claude/hooks/_hooklib.py` に置く | 方針の起点は T-0005 の「`stop_gate.py` は変更禁止」という1タスクの範囲の制約で、技術的な理由は記録されていない。以降は前例として踏襲されただけ（D-008 でも根拠は「調査に基づく設計判断」）。既に複製間で受け入れ基準の数え方・frontmatter の読み方・表の行判定がずれている（人の回答） |
| モジュール名は `_hooklib.py`（`.claude/hooks/` 直下） | 先頭の `_` でフック本体ではないことが分かり、settings.json に誤登録されにくい（人の回答） |
| 各フックは自分のファイルと同じディレクトリを `sys.path` の先頭に入れてから `_hooklib` を import する | worktree 委譲（D-008）では委譲先の worktree のフックがその worktree の `_hooklib.py` を読む必要がある。`__file__` 起点なら委譲先・委譲元それぞれが自分の版を読む（調査に基づく設計判断） |
| `_hooklib` の import に失敗したら、そのフックは標準エラーに理由を書いて終了コード2で終わる（Stop フックだけは、stdin の `stop_hook_active` が真で `HARNESS_STRICT_STOP` が `1` でなければ exit 0） | 終了コード2は Claude Code では「ブロック」扱いになるので、直接実行された時は安全側に倒れる。一方、委譲先として実行された時は非0なので、`delegate_to_worktree` は委譲元（メインリポジトリ側の正常なコード）の判定にフォールバックする。worktree で `_hooklib.py` を編集中の creator が自分の構文エラーで全ツールを止められる事態を避けられる。終了コード1だと Claude Code は「ブロックしないエラー」として扱い、ガードが黙って無効になる。Stop の例外は、ブロックの無限ループを避けるため既存の `stop_hook_active` の扱いに合わせたもの（人の指示「読み込み失敗時は安全側に倒す」を受けた設計判断） |
| import 失敗時の処理は、標準ライブラリだけを使う数行の `try/except ImportError`（`SyntaxError` 等も含め `Exception` で捕まえる）として各フックの先頭に直接書く | この部分自体を共通化すると、共通モジュールが壊れた時に動かない（調査に基づく設計判断） |
| 各フックの先頭で `sys.dont_write_bytecode = True` にしてから import する | `.claude/hooks/__pycache__/` を作らせない。`install.sh` は `.claude/` 配下を `find` で丸ごと複製するため、キャッシュが複製先に紛れ込むのを防ぐ（調査に基づく設計判断） |
| 複製間でずれている規則は寛容な側に揃える：受け入れ基準は行頭 `- ` と `数字. ` の両方を数える／frontmatter の値は前後の `"`・`'` を外して読む／タスク表の行は行頭の空白を許す | 今のずれは「厳しい側のせいで正しい票が弾かれる」方向。寛容側に揃えても守りは弱くならない（人の回答） |
| `scripts/current_plan.sh`・`scripts/archive_plans.sh` の awk による frontmatter の読み方も、引用符を外す規則に揃える | 両スクリプトは「plan_guard.py の plan_id_and_status と同じ規則」と明記しており、フック側だけ変えると承認済み計画の検出が食い違う（人の回答「寛容な側に揃える」の帰結） |
| Bash 判定の一本化では、既存の smoke を全件 PASS のまま保つ。それ以外で挙動が変わる箇所は拒否する側に倒し、変わった点を PR に列挙する | 解析不能時の判定は fail-closed が既存の方針（issue #91）。一本化で見逃しを増やさないため（人の回答） |
| Bash の書き込み解析（`analyze_bash_writes` 等）は `_hooklib.py` に移さず `agent_write_guard.py` に残す | 使うのは `agent_write_guard.py` だけ。共通化の対象は「複数フックに複製されているもの」に限る（調査に基づく設計判断） |
| フェーズ1は「中身が完全に同じ複製」だけを移す。規則のずれの統一はフェーズ2で行う | 移すだけのフェーズと挙動を変えるフェーズを分け、それぞれを smoke で確かめやすくするため（調査に基づく設計判断） |

## フェーズ1 共通モジュール `_hooklib.py` の導入と .git 判定の修正

### ゴール文

`.claude/hooks/_hooklib.py` を新設し、3フック（`agent_write_guard.py`・`plan_guard.py`・`stop_gate.py`）に中身が同じまま複製されている関数（`existing_ancestor`・`git_toplevel`・`delegate_to_worktree`（委譲先のスクリプト名を引数にする）・`plan_id_and_status`・`approved_plans`・`raw_rows`（`agent_write_guard.py` の `plan_raw_rows` を含む）・`frontmatter_status`・`human_messages`・`is_approve_command`・`is_unblock_command`）をそこへ移して、各フックは import して使うようにする。`_hooklib` の import に失敗した時は、各フックが終了コード2で終わる（Stop フックは `stop_hook_active` の時だけ exit 0）。あわせて `stop_gate.py` の `has_uncommitted_changes` が `.git` がディレクトリかどうかで git リポジトリを判定しているのを `git rev-parse --is-inside-work-tree` に直し、worktree（`.git` がファイル）でも未コミット検査が効くようにする。「フック間で import しない」と書いている `docs/vault-spec.md` の記述と各フックの docstring を更新する。

### 受け入れ基準の候補
- `.claude/hooks/_hooklib.py` が存在し、移す対象の関数がそこにだけ定義されている。確認：`for f in existing_ancestor git_toplevel delegate_to_worktree plan_id_and_status approved_plans raw_rows frontmatter_status human_messages is_approve_command is_unblock_command; do grep -l "^def $f(" .claude/hooks/*.py; done | sort | uniq -c` が `_hooklib.py` の1行だけ（件数10）を出す
- 既存の smoke が全件 PASS する。確認：`bash scripts/smoke.sh | tail -1` が `fail=0` を含み、pass が486以上
- `_hooklib.py` を壊した一時コピー（3フック＋構文エラーを入れた `_hooklib.py` を一時ディレクトリの `.claude/hooks/` に置いたもの）で、`agent_write_guard.py`・`plan_guard.py` はそれぞれ終了コード2になる。`stop_gate.py` は `{"stop_hook_active":false}` で2、`{"stop_hook_active":true}` で0になる（smoke にケースとして追加する）
- `.git` がファイルの worktree をプロジェクトとして未コミットの変更を置いた時、`stop_gate.py` が「未コミットの変更があります」でブロックする（smoke にケースとして追加する）
- フックを実行した後に `.claude/hooks/__pycache__` が作られない。確認：smoke 実行前に `.claude/hooks/__pycache__` を削除してから smoke を実行し、`test ! -e .claude/hooks/__pycache__` が真
- `docs/vault-spec.md` に「import しない」という記述が残っていない。確認：`grep -c "import しない" docs/vault-spec.md` が `0`

### 決定済み
- 移すのは「中身が完全に同じ（またはスクリプト名だけが違う）」関数だけ。`stop_gate.py` の `parse_tasks`・`count_acceptance_criteria`、`plan_guard.py` の `parse_tasks`・`count_criteria`、各フックの `project_dir` は挙動が違うのでこのフェーズでは移さない（フェーズ2の対象）
- `delegate_to_worktree(payload, script_name)` のように委譲先のファイル名を引数で受ける。二重委譲防止（`_HOOK_DELEGATED`）・タイムアウト20秒・非0ならフォールバック、という既存の挙動は変えない
- import の書き方は各フック先頭で `sys.dont_write_bytecode = True` → `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` → `try: import _hooklib as H` / `except Exception as e:` で標準エラーに `[<フック名>] _hooklib の読み込みに失敗しました: <e>` を書いて `sys.exit(2)`。Stop フックだけは except 節で stdin を読み、`stop_hook_active` が真で環境変数 `HARNESS_STRICT_STOP` が `1` でなければ `sys.exit(0)`
- 失敗時の処理は共通化しない（各フックに直接書く）
- `.git` 判定の修正は `git -C <root> rev-parse --is-inside-work-tree` の出力が `true` かどうかで行う。取得できない時は従来どおり False（fail-open）
- `install.sh`・`uninstall.sh` は変更しない（`.claude/hooks/*.py` を自動で配布・マニフェスト記録する）。複製先で `_hooklib.py` が配られていることは、既存の install 系 smoke が通ることで確かめる
- smoke の worktree 委譲テストで差し替えている stub のフックは `_hooklib` を import しないままでよい
- `docs/decisions.md` に「フック間で import しない方針を廃止し `_hooklib.py` に共通化（人の判断、D-011）」の1行を追記する

## フェーズ2 複製間でずれていた解析規則の統一

### ゴール文

3フックと2スクリプトで食い違っている計画票・タスク票の解析規則を、寛容な側に揃えて `_hooklib.py` に1本化する。(1) 受け入れ基準の行数は、「## 受け入れ基準」節の行頭が `- ` か `数字. ` の行を数える（`plan_guard.py` の `count_criteria` の規則）。`stop_gate.py` の verdict 形式検査もこれを使う。(2) frontmatter の `id`・`status` の値は、前後の `"`・`'` を外して読む。`plan_id_and_status` と `frontmatter_status` を同じ規則にし、`scripts/current_plan.sh`・`scripts/archive_plans.sh` の awk も合わせる。(3) タスク表の行は行頭の空白を許す（`stop_gate.py` の `parse_tasks` を `plan_guard.py` の規則に揃える）。揃えた関数は `_hooklib.py` に置き、各フックの複製を消す。`docs/vault-spec.md` の該当節に規則を明記する。

### 受け入れ基準の候補
- 受け入れ基準を `1. ` 形式で4行書いたタスク票と、criteria 4件の PASS verdict の組で、`stop_gate.py` が verdict の形式不正としてブロックしない（smoke にケースとして追加する）
- frontmatter が `status: "approved"`（引用符付き）の計画票が、`plan_guard.py`・`stop_gate.py`・`bash scripts/current_plan.sh` のすべてで approved として扱われる（smoke にケースとして追加する）
- タスク表の行を半角空白でインデントした計画票で、`doing` かつ verdict の無い行を `stop_gate.py` がブロックする（smoke にケースとして追加する）
- `parse_tasks`・受け入れ基準を数える関数・frontmatter を読む関数が `_hooklib.py` にだけ定義されている。確認：`grep -l "^def \(parse_tasks\|count_criteria\|count_acceptance_criteria\)(" .claude/hooks/*.py` が `_hooklib.py` だけを出す
- 既存の smoke が全件 PASS する。確認：`bash scripts/smoke.sh | tail -1` が `fail=0` を含む

### 決定済み
- 寛容な側に揃える（人の回答）。厳しくする方向の変更は入れない
- 受け入れ基準を数える関数名は `count_criteria(text)` に統一し、ファイルパスではなく本文を受け取る（`stop_gate.py` 側はファイルを読んでから渡す）
- frontmatter の読み方は `frontmatter_status` の規則（1行目が `---`、次の `---` まで、値の前後の引用符を外す）に揃える。`plan_id_and_status` の「`\n---\n` を正規表現で探す」実装はこれに置き換える。`id` も同じ規則で読む
- awk 側は、値の先頭と末尾の `"` または `'` を1つずつ外す処理を足すだけでよい。frontmatter の他の読み方は変えない
- `project_dir` は各フックで役割が違う（`stop_gate.py` は `vault/plans` の存在を確かめる）ので統一しない
- 既存の smoke の期待値を変えないと通らないケースが出た場合は、寛容側に揃えた帰結であることを確かめた上で期待値を直してよい。直したケースは PR 本文に列挙する

## フェーズ3 agent_write_guard.py の Bash 書き込み判定の一本化

### ゴール文

`agent_write_guard.py` で、Bash コマンドの書き込み対象を求める処理を1つの関数（例：`bash_write_targets(cmd, root)`）にまとめ、1回のフック呼び出しで1度だけ計算するようにする。今は `targets_vault_rules`・`targets_transcript_dir`・`targets_creator_denied_paths`・`find_done_task_write`・ALLOWED 判定が、それぞれ `analyze_bash_writes` を呼び直している（最大5回）。解析できない時の従来判定も、わずかに違う正規表現で4通り書かれている。この関数は、解析できた時は `analyze_bash_writes` の結果を返す。解析できない時は、4通りの従来判定が拾っていた候補の和集合（リダイレクト先・`extract_bash_write_targets` の結果・保護対象パス（`vault/rules/`・`vault/plans/`・`vault/log/`・`vault/tasks/`・`vault/verdicts/`・`.claude/projects`）を含む path-like トークン）を返す。各判定はこの結果をパスで絞り込むだけにする。`BASH_WRITE_PATTERNS`・`OTHER_WRITE_PATTERNS`・`DESTRUCTIVE_BASH_PATTERN` の重複も、1つの定義から組み立てる形にまとめる。既存の smoke は全件 PASS のまま保ち、それ以外で挙動が変わる箇所は拒否する側に倒す。

### 受け入れ基準の候補
- 既存の smoke が全件 PASS する（期待値の変更なし）。確認：`git diff main -- scripts/smoke.sh` に既存ケースの削除・期待値の変更が無く、`bash scripts/smoke.sh | tail -1` が `fail=0` を含む
- 1回のフック呼び出しで `analyze_bash_writes` が高々1回しか実行されない。確認：smoke に、`analyze_bash_writes` の呼び出し回数を数える Python のテストケース（`agent_write_guard` を import して関数を包む）を追加し、`vault/rules/` を含む解析可能なコマンドと解析不能なコマンドの両方で回数が1以下
- 解析できない時の従来判定が1か所にまとまっている。確認：`grep -c "BASH_WRITE_PATTERNS" .claude/hooks/agent_write_guard.py` の出現が、定義と一本化した関数の中だけ（3以下）
- 一本化で挙動が変わったコマンドの例（変更前は許可、変更後は拒否）が、smoke のケースとして少なくとも1件追加されている。挙動が変わる例が無い場合は、その旨とどう確かめたかがタスク票の「進捗」に書かれている
- `docs/vault-spec.md` 12節の Bash 判定の記述が、一本化後の規則（解析できない時は候補の和集合で判定する）に合っている

### 決定済み
- smoke 全件 PASS、それ以外の差は拒否側に倒す（人の回答）
- `analyze_bash_writes`・`_strip_heredocs` などの Bash 解析は `_hooklib.py` に移さず `agent_write_guard.py` に残す
- `is_git_stage_or_commit_only`（done 判定で `git add`/`git commit` だけのコマンドを通すもの）の挙動は変えない。和集合化の対象は「候補パスの抽出」だけで、「git add/commit だけなら通す」「root 外だけなら通す」「ALLOWED 配下へのリダイレクトだけなら通す」などの許可条件は既存どおり各判定に残す
- 呼び出し回数を減らす方法は、`main()` で1度計算して各判定に渡す形でも、メモ化でもよい
- 挙動が変わった点は、PR 本文に「変更前→変更後」の形で列挙する

## 今回やらないこと

- `.claude/settings.json` の許可リスト（`Bash(bash *)`・`Bash(sh *)`・`Bash(python3 *)`・`Bash(env *)`・`Bash(xargs *)`・`Bash(find *)`）が拒否リストの抜け道になっている件。受け入れ基準の確認コマンドに `python3 -c` が多用されているため、絞ると verifier の確認が無人実行で拒否されやすくなる。当面は stop_gate のコミット強制で被害を直前のコミットまでに抑える現状維持とし、無人実行を本格化する段階で、サンドボックスでの実行か許可リストの縮小を別の設計で扱う
- `scripts/smoke.sh`（1641行）の分割・Python のテストへの置き換え
- Bash 解析（`analyze_bash_writes`）の精度向上・新しい書き込み動詞への対応
- 各フックの `project_dir` の統一
- `scripts/` 配下の Python（`model_stats.py` 等）から `_hooklib.py` を使うこと
