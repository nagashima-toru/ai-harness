# T-01 planner 定義に計画単位のレビュータスクを足す規則を書く

## 目的
コードを変更するタスクを含む計画では、planner が全タスクの後に計画全体の差分を `/code-review` で確かめるタスクを1件だけ足し、通常のタスクには `/code-review` の行を入れないようにする。`/plan` の粒度の確認でもその有無を見る。

## 入力
- `.claude/agents/planner.md`（全体。特に「粒度の基準」「『成果物』の書き方」「手順」「書き終えた後の確認」の節）
- `.claude/skills/plan/SKILL.md` の手順5（粒度の確認）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節（現行の扱いの参考。このタスクでは変えない）
- `docs/vault-spec.md` 5節（差分ゲートの宣言の読み方）・8節（粒度の基準）

## 成果物
- `.claude/agents/planner.md`（主な成果物。計画単位のレビュータスクの規則）
- `.claude/skills/plan/SKILL.md`（付随。手順5の粒度の確認に1文足す）

## 受け入れ基準
- planner 定義に計画単位のレビュータスクの見出しが1つある：`grep -c '^## 計画単位のレビュータスク' .claude/agents/planner.md` が `1`
- planner 定義に、コードを変更するタスクの判定基準が書かれている：`grep -c '配下でなく、拡張子が' .claude/agents/planner.md` が1以上
- planner 定義に、全タスクを `after` に持つ最後のタスクとして足すことが書かれている：`grep -c '全タスクを .after. に持つ最後のタスク' .claude/agents/planner.md` が1以上
- planner 定義に、計画単位のレビュータスクの受け入れ基準の行と、通常のタスクに `/code-review` の行を入れないことが書かれている：`grep -c 'で計画の差分に致命的な指摘が残っていない' .claude/agents/planner.md` が1以上、かつ `grep -c '通常のタスクの受け入れ基準には' .claude/agents/planner.md` が1以上
- planner 定義に、計画単位のレビュータスクを1計画7タスクの上限に含めることが書かれている：`grep -c '通常のタスクは6件まで' .claude/agents/planner.md` が1以上
- `/plan` の手順5に計画単位のレビュータスクの確認が書かれている：`grep -c '計画単位のレビュータスク' .claude/skills/plan/SKILL.md` が1以上
- smoke の `(ref-1)` が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- 用語は「計画単位のレビュータスク」に統一する（creator・verifier・vault-spec・run スキルも同じ語を使う）。title は「計画の差分が `/code-review` を通過する」とする
- `.claude/agents/planner.md` に `## 計画単位のレビュータスク` の見出しの節を、「## 『成果物』の書き方」の節の直後（「## 手順」の前）に新しく足す。節には次をすべて書く（文言は下の「」の部分をそのまま使い、それ以外は言い回しを整えてよい）
  - 判定：「コードを変更するタスク」は、「成果物」に「`vault/` 配下でなく、拡張子が `.md`・`.txt` でもないパス」が1つ以上あるタスクとする。末尾が `/` のディレクトリの宣言は、`vault/` 配下でなければコードを変更するとみなす（配下に何が入るか決まらないため）
  - 足す条件：計画にコードを変更するタスクが1件以上ある時だけ、「全タスクを `after` に持つ最後のタスク」として計画単位のレビュータスクを1件足す。0件の時は足さない。足さなかった時は計画票の「分割方針」にその判定を1行書く
  - タスク数：計画単位のレビュータスクは1計画7タスクの上限に含める。足す計画では「通常のタスクは6件まで」にする
  - 成果物：主な成果物は計画の差分への修正。直す対象は計画で変えたファイルなので、先行タスクの「成果物」に宣言したパスをすべてバッククォートで列挙する（差分ゲート `scripts/diff_gate.py` は宣言外の変更を違反にするため）
  - 受け入れ基準：1行目を「`/code-review` で計画の差分に致命的な指摘が残っていない」にする。残りの2〜6行には、先行タスクの受け入れ基準から計画全体の動作を確かめる確認コマンド（テスト・smoke・ビルドなど）を再掲し、修正で壊していないことを確かめる（合わせて3〜7行）
  - 決定済みに書くこと：レビューの範囲はベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）であること。計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしないこと。致命的な指摘が無ければ成果物を変えず「進捗」への記録だけでよいこと（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）。差分の外（既存コード）・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従うこと
  - 通常のタスク：「通常のタスクの受け入れ基準には `/code-review` の行を入れない」（計画単位のレビュータスク以外のタスクのこと）
- 「## 手順」に、タスク票を書いた後に計画単位のレビュータスクを足すかを判定する手順を1つ足す（番号の振り直しは自由）
- 「## 粒度の基準（必ず守る）」の「1計画は5〜7タスクまで」の箇条に、計画単位のレビュータスクも数に含めることを書き足す
- 「## 書き終えた後の確認」に、コードを変更するタスクの有無と計画単位のレビュータスクの有無が合っているか（ある時は全タスクを `after` に持ち、成果物に先行タスクの宣言をすべて列挙しているか）の箇条を1つ足す
- `.claude/skills/plan/SKILL.md` の手順5（粒度の確認）に、コードを変更するタスクがある計画では最後に計画単位のレビュータスクがあり全タスクを `after` に持つか、無い計画にはそれが無いかを確かめる旨を、「計画単位のレビュータスク」の語を使って1文足す（判定の正本は `.claude/agents/planner.md` の「計画単位のレビュータスク」節と書く）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md`・`docs/vault-spec.md`・`.claude/skills/run/SKILL.md`・`docs/decisions.md` は別のタスク（T-02〜T-05）で直すので、このタスクでは変えない
- 「やらないこと」節の既存の箇条は変えない。`vault/rules/planner/` は変えない
- バッククォートで書くパスは既存のファイルだけにする（新しいファイルは作らない。`(ref-1)` の対象文書のため）
