# T-03 docs/vault-spec.md 9節の判定表を新しい判定の順序に直す

## 目的
`docs/vault-spec.md` 9節（Stop フックの判定）の本文と判定表を、T-01 で変えた `stop_gate.py` の判定順（`stop_hook_active` → approved な計画票の件数 → 未コミットの変更 → done の行 → doing/review の行）に合わせる。

## 入力
- `vault/designs/D-013.md` の「フェーズ1 Stop フックの適用範囲と無人実行での厳格化」（決定済み）
- `.claude/hooks/stop_gate.py`（T-01 の後の版。`main()` と docstring）
- `docs/vault-spec.md` 9節

## 成果物
- `docs/vault-spec.md`（このファイルだけ。9節だけを変える）

## 受け入れ基準
- 判定表の先頭の4行が決定済みの順になっている：`grep -nE '^\| (.stop_hook_active. が真|approved な計画票が|未コミットの変更がある)' docs/vault-spec.md` の出力が4行で、上から `stop_hook_active` が真・`approved な計画票が0件`・`approved な計画票が2件以上`・`未コミットの変更がある` の順
- `approved な計画票が0件` の行の判定が許可で、未コミットの検査もしないことが書かれている：`grep -F '| approved な計画票が0件 | 許可（未コミットの変更の検査もしない' docs/vault-spec.md` の出力が1行
- 9節の本文に、ブランチ名を見ないこととその理由、無人実行（`scripts/run_unattended.py`）では `HARNESS_STRICT_STOP` が未設定なら `1` になることが書かれている：`sed -n '/^## 9\./,/^## 10\./p' docs/vault-spec.md | grep -cF 'run_unattended.py'` の出力が1以上（内容は Read で確認）
- 既存の smoke が全件通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 判定表の行（上から）。表の列（`| 状況 | 判定 |`）は変えない
  1. `` | `stop_hook_active` が真 | `` の行は今のまま
  2. 新設：`| approved な計画票が0件 | 許可（未コミットの変更の検査もしない。ブランチ名は見ない） |`
  3. 新設：`| approved な計画票が2件以上 | ブロック：1つだけ approved にする |`
  4. `| 未コミットの変更がある（…） |` の行は今のまま（状況の括弧書きの先頭に「approved な計画票が1件の時だけ検査する。」を足してよい。行頭の `| 未コミットの変更がある` は変えない）
  5. 以降（done の行・doing/review の行）は今のまま
- 本文（表の前の段落）の「approved な計画票を1件に特定した直後に」の流れを、判定の順序（1. 委譲 2. `stop_hook_active` 3. 件数 4. 未コミット 5. done の行 6. doing/review の行）が分かる書き方に直す
- ブランチ名を見ない理由：承認済みの計画票はその計画のブランチにしか無く、`main` では PR を作った時点で done になっているため。この理由を本文に1文で書く
- 無人実行について本文に1文書く：`scripts/run_unattended.py` は `HARNESS_STRICT_STOP` が未設定なら `1` を入れて子プロセスに渡す（`stop_hook_active` が真でも判定を続ける）。`HARNESS_STRICT_STOP=0` を明示すれば従来の動き
- 判定表の行頭が `| approved な計画票が` で始まる行は9節の2行だけにする（10節など他の節に作らない）
- 他の節（12節の `_hooklib.py` の段落を含む）は変えない
