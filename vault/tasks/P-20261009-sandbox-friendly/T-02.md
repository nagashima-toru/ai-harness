# T-02 settings.json の sandbox.excludedCommands に vcs_finish.sh と discard_worktree.sh を足す

## 目的
`.claude/settings.json` の `sandbox` に `excludedCommands` を足し、PR の作成（`scripts/vcs_finish.sh`）と worktree の後始末（`scripts/discard_worktree.sh`）だけをサンドボックスの外で実行させる。`git push -u` の `.git/config` への書き込み・`gh` の TLS の検証・`.git/worktrees/` への書き込みがサンドボックスの中で拒否され、人が手で行っている作業を無くす。

## 入力
- `.claude/settings.json`（今の `sandbox` は `enabled`・`allowUnsandboxedCommands`・`filesystem`・`network` の4キー）
- `.claude/skills/run/SKILL.md` の手順7の4（`env HARNESS_PR_BODY_FILE=<本文ファイル> HARNESS_PR_TITLE="<計画ID>: <ゴールの1行目>" bash scripts/vcs_finish.sh`）と、`bash scripts/discard_worktree.sh <パス> <ブランチ名>` の呼び出し（手順2の2・ハング時の復旧）
- `.claude/skills/design/SKILL.md` の手順8（引数なしの `bash scripts/vcs_finish.sh`）
- `vault/plans/P-20261009-sandbox-friendly.md` の分割方針（`excludedCommands` の仕様について分かったこと）

## 成果物
- `.claude/settings.json`（1ファイル）
- （リポジトリの外。差分ゲートの宣言ではない）上のファイルの編集が拒否された時だけ、決定済みの最後の項目のパッチ /tmp/claude/P-20261009-sandbox-friendly-T-02/settings.json.patch を残す

- `sandbox` のほかのキーは変わっていない：`python3 -c "import json; s=json.load(open('.claude/settings.json'))['sandbox']; print(sorted(s), s['enabled'], s['allowUnsandboxedCommands'], s['filesystem'], s['network'])"` の出力が `['allowUnsandboxedCommands', 'enabled', 'excludedCommands', 'filesystem', 'network'] True False {'denyWrite': ['./vault/rules', '~/.claude/projects']} {'allowedDomains': ['github.com', '*.github.com', '*.githubusercontent.com']}`
- 最上位のキーは変わっていない：`python3 -c "import json; print(sorted(json.load(open('.claude/settings.json'))))"` の出力が `['hooks', 'permissions', 'sandbox', 'worktree']`
- `permissions`・`hooks`・`worktree` は main の版と同じ：`python3 -c "import json,subprocess; a=json.load(open('.claude/settings.json')); b=json.loads(subprocess.run(['git','show','main:.claude/settings.json'],capture_output=True,text=True).stdout); print(all(a[k]==b[k] for k in ('permissions','hooks','worktree')))"` の出力が `True`

## 決定済み
- 人の回答（/plan unblock）：transition.py も excludedCommands に入れる（5パターン目）。人が .claude/settings.json に5パターンを足してコミット済み（eea9ba9）。この回答は下の「4つ」「4パターン」の記述と受け入れ基準1行目の期待値に優先する。期待値は `['bash scripts/vcs_finish.sh', 'bash scripts/vcs_finish.sh *', 'env HARNESS_PR_BODY_FILE=* bash scripts/vcs_finish.sh', 'bash scripts/discard_worktree.sh *', 'python3 scripts/transition.py *']`（5つ目は `python3 scripts/transition.py *`）。ほかの基準は変わらない
- 足すのは `sandbox` の中の `"excludedCommands"` の1キーだけ。値は次の4つをこの順で並べた配列
  1. `bash scripts/vcs_finish.sh`（`/design` などの引数なしの呼び出し）
  2. `bash scripts/vcs_finish.sh *`（引数付きの呼び出し）
  3. `env HARNESS_PR_BODY_FILE=* bash scripts/vcs_finish.sh`（run の手順7の4の呼び出し。`*` が本文ファイルのパスと `HARNESS_PR_TITLE="..."` を含む）
  4. `bash scripts/discard_worktree.sh *`（後始末。引数は worktree のパスとブランチ名）
- 置き場所は `"allowUnsandboxedCommands": false,` の次の行（`"filesystem"` の前）。インデントと書き方は今のファイルに合わせ、配列は1行で書く（例：`"excludedCommands": ["bash scripts/vcs_finish.sh", "bash scripts/vcs_finish.sh *", "env HARNESS_PR_BODY_FILE=* bash scripts/vcs_finish.sh", "bash scripts/discard_worktree.sh *"],`）
- 変えないもの：`allowUnsandboxedCommands: false`・`filesystem`（`allowWrite` は足さない。`.git` の保護を弱めないため。計画票の方針 B）・`network`（`enableWeakerNetworkIsolation` は足さない。計画票の方針 E）・`permissions`・`hooks`・`worktree`
- パターンの書き方は Bash の permission ルールの書き方（`excludedCommands` の説明：「Command patterns (Bash permission-rule syntax) that always run outside the sandbox」。Claude Code 2.1.294 の設定スキーマで確認。公式ドキュメントでは未確認）。`allowUnsandboxedCommands: false` をプロジェクトの設定にだけ置いている間は、プロジェクトの設定の `excludedCommands` は効く見込み。効き目はセッションの外でしか確かめられないので、受け入れ基準は設定の形までにし、効き目はマージ後に人が `/sandbox` で確かめる（計画票の「マージ後に人が行う作業」）
- `scripts/vcs_finish.sh`・`scripts/discard_worktree.sh`・`.claude/skills/` は変えない（run の手順は T-03、文書は T-04・T-05）
- `bash scripts/smoke.sh` は実行しない（このタスクの確認には要らない。全件は人がサンドボックスの外で確かめる）
- 編集が拒否された時（サンドボックスの書き込み保護や Claude Code 本体の設定ファイルの保護で `.claude/settings.json` を変えられない時）は、別の手段（`python3 -c` での書き込み・`cp` での上書きなど）で worktree のファイルを書き換えようとしない。代わりに次のとおりにして `blocked` にする（計画票の人への質問4）
