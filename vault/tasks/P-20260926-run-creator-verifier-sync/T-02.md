# T-02 run/SKILL.md 手順6（PASS 時の review→done 遷移）に verdict の git add・その場コミットを明記する

## 目的
`/run` スキルの手順6は、verifier が直接メインリポジトリへ書いた `vault/verdicts/<計画ID>/<id>.json` を、`review→done` の状態遷移（計画票・log の更新）と同じタイミングで `git add`・コミットする指示を持たない。過去の run 実行（issue #63 統合コメント／P-20260926-verifier-verdict-worktree-path）では、最後のタスクの done 遷移がこの明示的なコミットを経ないまま `bash scripts/vcs_finish.sh` まで進み、`gh pr create` の「Warning: 1 uncommitted change」で偶然気づいて追いコミットする事態が起きた。気づかなければ verdict がリモートに反映されないまま PR が作られていた。手順6の該当箇所に、verdict ファイルの `git add` とその場でのコミットを明記する。

## 決定済み
- 追加方法は、既存の項目4（「マージが衝突なく成功したら、status を review から done にし、...を追記する。続けて git worktree remove ...」）の文中・文末に一文または二文を追記する形にする。新しい番号付き項目（4.5 等）を追加しない。手順6の PASS ケースの他の項目（1〜3、5）の番号がずれると、手順3の他箇所からの参照（例：「手順3.4で保持したもの」）とは別系統だが、混乱を避けるため番号は増やさない方針とする
- 追記する文言の趣旨は「計画票のタスク表の更新・`vault/log/<計画ID>.md` への追記・`vault/verdicts/<計画ID>/<id>.json` を `git add` し、この時点でコミットする（次のタスクの doing 反映時のコミットに委ねない）」。文言の細部は自由だが、`git add`・「この時点でコミット」・`vault/log` の3つの文字列（またはそれに相当する表現のうち `git add` と「この時点でコミット」は原文のまま）を含めること
- 対象は `review→done` になる PASS ケースの項目4だけ。PASS の他の分岐（新規コミット無し＝blocked、コンフリクト＝blocked）や FAIL ケースの記述は変更しない（それらは verdict が生成されない、または既に別経路でコミット済みの状態のため対象外）
- `git worktree remove` ・`git branch -d` の順序・既存文言は変更しない。追記は「その前」に置いても「その後」に置いてもよいが、worktree 削除前にコミットが完了している（＝コミット対象のファイルが worktree 側ではなくメインリポジトリ側にある）ことが分かる書き方にする
- 確認コマンドの一時ファイルは `/tmp/P-20260926-run-creator-verifier-sync-T02-*.txt` の固定パスを使う
