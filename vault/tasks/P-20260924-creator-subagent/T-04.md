# T-04 run/SKILL.md を creator 呼び出し形に書き換える

## 目的
`.claude/skills/run/SKILL.md` を、オーケストレーターが状態を `doing` にしてログ追記した後に Agent ツールで `creator` を1回呼び、完了報告を受けたら `review` にしてログ追記する、という流れに書き換える。並行実行はまだ入れず、着手可能な `todo` を1件ずつ処理する現行の逐次フローを維持する。

## 入力
- `.claude/skills/run/SKILL.md`（現行の手順2「取り出す」〜手順7「次へ・完了」全体、特に手順3「作る」・手順4「review にする」）
- `.claude/agents/creator.md`（T-01 の成果物。creator の入出力仕様）
- `vault/designs/D-003.md`「フェーズ2」のゴール文

## 成果物
- `.claude/skills/run/SKILL.md`

## 受け入れ基準
- 手順2「取り出す」の末尾（status を `doing` にし log に `todo→doing` を追記する部分）がオーケストレーター自身の操作として残っている。確認コマンド: `grep -c 'todo→doing' .claude/skills/run/SKILL.md` の出力が1以上
- 手順3相当が「Agent ツールで `creator` をタスク ID だけ渡して1回呼ぶ」形に書き換わっている。確認コマンド: `grep -c 'creator' .claude/skills/run/SKILL.md` の出力が1以上、かつ `grep -c 'Agent ツール' .claude/skills/run/SKILL.md` の出力が1以上
- creator の完了報告を受けた後、オーケストレーターが status を `review` にし log に `doing→review` を追記する手順が明記されている。確認コマンド: `grep -c 'doing→review' .claude/skills/run/SKILL.md` の出力が1以上
- creator が「決定済みに無い判断が必要」と報告（blocked 報告）した場合、オーケストレーターが status を `blocked` にし question 列に質問を書き log に追記する手順が明記されている
- 手順5「検証する」・手順6「verdict に従う」の verifier 呼び出し方（タスク ID だけを渡す）は変更されていない。確認コマンド: `grep -c 'サブエージェントを呼ぶ' .claude/skills/run/SKILL.md` の出力が1以上

## 決定済み
- creator の呼び出しは verifier 呼び出しと同じ形式にする：Agent ツールの prompt はタスク ID だけ（例：`<計画ID>/<id> の成果物を作ってください`）。作業の経緯・言い訳は渡さない
- 並行実行（複数タスクを同時に doing にする、`HARNESS_MAX_PARALLEL` 等）はこのタスクの対象外。着手可能な `todo` を1件ずつ処理する現行の逐次フローをそのまま維持する
- creator が blocked を報告した場合、その質問文をそのまま計画票の question 列に書き写す（オーケストレーターが自分で言い換えない）
- 手順1「計画票を見つける」・手順5「検証する」・手順6「verdict に従う」・手順7「次へ・完了」は、このタスクでは内容を変更しない（変更するのは手順2の末尾の位置づけ・手順3「作る」・手順4「review にする」の3箇所のみ）
- 既存の1タスクずつの逐次フロー（着手可能な todo が1件のケース）で、最終的な状態遷移・ログ・成果物の結果が変更前と同じになることを、書き換え後に人がこのタスク票の「進捗」に確認結果として記録する（自動テストではなく目視の回帰確認でよい）
