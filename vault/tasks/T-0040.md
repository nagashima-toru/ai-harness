# T-0040 ドキュメント更新と全体の通し確認

## 目的

（`.claude/harness-manifest.json`）・`scripts/merge_settings_json.py` の挙動を反映し、通しで
`scripts/smoke.sh` が pass のみで終わることを確認する。

## 入力
- `docs/install.md`（パターン1・パターン2節、複製対象の説明）
- `README.md`（「## セットアップ」節）
- `docs/runbook.md`
- T-0036〜T-0039 で確定した `scripts/install.sh` の実際の挙動（`--update`・出力文言・
  `harness-manifest.json`・`merge_settings_json.py`）

## 成果物
- `docs/install.md`（変更）
- `README.md`（変更）
- `docs/runbook.md`（変更）

## 受け入れ基準
- `docs/install.md` に `--update`・`harness-manifest.json`・`skip (edited)`・
  `merge_settings_json.py` の4語すべてへの言及がある。確認コマンド:
  `grep -c -- '--update' docs/install.md`（1以上）、
  `grep -c 'harness-manifest.json' docs/install.md`（1以上）、
  `grep -c 'skip (edited)' docs/install.md`（1以上）、
  `grep -c 'merge_settings_json.py' docs/install.md`（1以上）
- `README.md` の「## セットアップ」節に `--update` の言及がある。確認コマンド:
  `grep -c -- '--update' README.md`（1以上）
- `docs/runbook.md` に `--update` の言及が1箇所以上ある。確認コマンド:
  `grep -c -- '--update' docs/runbook.md`（1以上）
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（T-0036〜T-0039 の全ケースを通しで実行）

## 決定済み
- `docs/install.md` のパターン1・パターン2の両方に、2回目以降は
  `bash /path/to/ai-harness/scripts/install.sh --update <dir>` で更新できる旨を追記する。内容は
  「未編集のハーネス本体ファイルは最新化される」「編集済みのファイルは `skip (edited)` として一覧
  報告され、上書きされない」「`.claude/settings.json` は `merge_settings_json.py` により hooks の
  欠落エントリと `permissions.deny` の不足分だけが足され、`permissions.allow` は変更されない」の3
  点を含める
- 34行目付近の複製対象の説明文（パターン1節）に `.claude/harness-manifest.json` と
  `scripts/merge_settings_json.py` を追加する
- `README.md` の「## セットアップ」節に、`--update` で2回目以降も最新化できる旨を1行加える
  （既存の CLAUDE.md マージの説明文の近くに置く）
- `docs/runbook.md` には新しい節を新設せず、既存の関連する節（ハーネス自体の更新・保守に触れてい
  る箇所。無ければ末尾に短い1項目）に `--update` の使いどころ（ハーネス側の変更を取り込みたい時に
  実行する）を追記する程度でよい
- `docs/decisions.md` の更新はこのタスクの範囲外（今回の決定は `vault/designs/D-001.md` に既に記
  録されているため、追加の1行は不要。書いても構わないが受け入れ基準には含めない）
- 出力文言（`create`/`update`/`copy`/`skip (edited)`/`skip  (exists)` 等）は T-0036〜T-0039 で実装
  した実際の文言に合わせて書く。ドキュメント側で文言を新たに作らない

## 進捗
- 読んだルール: roles.md, creator.md
- `docs/install.md`：新しい節「## ハーネスを更新する（2回目以降）」を「## インストール後の次の一歩」
  の直前に追加した。フラグ無しでは更新が届かない理由と、`update` / `skip (edited)` /
  `merge_settings_json.py`（allow は変更しない）/ マニフェスト無しの先の扱い / `.bak-<日時>` の
  4点＋補足を書いた。パターン1の手順8末尾とパターン2の手順1に、この節への導線を1行ずつ足した。
  パターン1の複製対象の説明に `scripts/merge_settings_json.py` を加え、`.claude/harness-manifest.json`
  が作られること・`settings.json` は複製でなくマージで用意されることを1段落で補った
- `README.md`：「## セットアップ」節の install.md への導線の行に、`--update` で取り込めること、
  未編集だけが最新化され編集済みは `skip (edited)` で上書きされないことを追記した
- `docs/runbook.md`：「## 7. ハーネス自体の更新を取り込む」を新設し（「## 困ったとき」の直前）、
  コマンドと挙動の要約、install.md への参照を書いた。決定済みは「既存節への追記程度でよい」だったが、
  6節までが人の日々の操作で構成されており、ハーネス保守に触れた既存節が無かったため短い節を足した
- 出力文言はすべて T-0036〜T-0039 の実装に合わせた（`update <path>` / `skip (edited) <path>` /
  `skip  (exists) <path>` / `create` / `merge`）。ドキュメント側で新しい文言を作っていない
