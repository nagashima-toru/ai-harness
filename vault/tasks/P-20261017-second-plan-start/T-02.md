# T-02 plan SKILL の承認・解除のログ追記で vault/log/ を作る

## 目的
`vault/log/` が無い導入先（Issue #205。計画一式の除去で `vault/log/` ごと消えた後など）でも、`/plan` の承認ログ（A 手順9）と blocked の解除ログ（B 手順8）の追記が失敗しないようにする。

## 入力
- `.claude/skills/plan/SKILL.md`（A 手順9：24行目、B 手順8：42行目）
- `docs/vault-spec.md` 7節（log の行の書式。変えない）

## 成果物
- `.claude/skills/plan/SKILL.md`（A 手順9 と B 手順8 の2行の書き換え）

## 受け入れ基準
- A 手順9の行に `mkdir -p vault/log` がある（確認：`grep -c '^9\. .*mkdir -p vault/log' .claude/skills/plan/SKILL.md` が `1`）
- B 手順8の行に `mkdir -p vault/log` がある（確認：`grep -c '^8\. .*mkdir -p vault/log' .claude/skills/plan/SKILL.md` が `1`）
- `mkdir -p vault/log` を書いた行は上の2行だけである（確認：`grep -c 'mkdir -p vault/log' .claude/skills/plan/SKILL.md` が `2`）
- 追記する log の行の書式は変わっていない（確認：`grep -c 'draft→approved /plan による自動承認' .claude/skills/plan/SKILL.md` が `1`、`grep -c 'blocked→todo 人の指示: /plan unblock' .claude/skills/plan/SKILL.md` が `1`）
- smoke の `(ref-1)` が通る（確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`）

## 決定済み
- A 手順9（`9. ` で始まる行）は、今の「`vault/log/<計画ID>.md` に次の1行を追記する（ファイルが無ければ作る）」を、「`vault/log/` が無ければ先に `mkdir -p vault/log` で作り、`vault/log/<計画ID>.md` に次の1行を追記する（ファイルが無ければ作る。`>>` はファイルを作るがディレクトリは作らないため。Issue #205）」の趣旨に直す。`mkdir -p vault/log` はバッククォートで囲み、この文字列のまま書く。追記する行（`- <日時> - draft→approved /plan による自動承認`）は変えない
- B 手順8（`## B.` 節の `8. ` で始まる行）も同じく「`vault/log/` が無ければ先に `mkdir -p vault/log` で作り、」を足す。追記する行（`- <日時> <id> blocked→todo 人の指示: /plan unblock <計画ID> <id>` と `--fresh` の時の末尾）は変えない
- `mkdir -p vault/log` は「無ければ作る」なので、`vault/log/` があっても失敗しない。存在の確認を別のコマンドにしなくてよい（`mkdir -p` を無条件に実行すると書いてもよい）
- 1行の手順を複数行に分けない（行頭の `9. `・`8. ` の行の中に書く。受け入れ基準1・2の確認がその行を見るため）
- ほかの手順（A 手順2・手順10、B 手順9 など）は変えない。A 手順2は T-03 が変える（同じファイルなので、このタスクでは触らない）
- `vault/log/` を作った時は、手順10（B は手順9）の `git add vault/log/<計画ID>.md` がそのファイルを stage するので、git add の手順は変えなくてよい
- `.claude/skills/run/SKILL.md` は変えない（run の log の追記は承認の後で、`vault/log/<計画ID>.md` が既にある時だけ `scripts/transition.py` が行うため）
