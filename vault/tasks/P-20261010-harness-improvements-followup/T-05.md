# T-05 creator・verifier の起点コミットの手順を削り、エージェント定義の vault/rules の記述を差分ゲートに合わせる

## 目的
宣言外の変更は `scripts/transition.py` の差分ゲートが機械的に止めるので、verifier の変更ファイル一覧の検査（起点コミットを使う手順）と creator の「起点コミットを記録する」手順は重複している。両方を削る。あわせて、T-03 で差分ゲートが `vault/rules/` を宣言すれば許すようになったので、エージェント定義の「`vault/rules/` は宣言があっても違反」の記述を実態に合わせる。

## 入力
- `.claude/agents/verifier.md`（「## 手順」の10）
- `.claude/agents/creator.md`（「## 手順」の3、「## 書き込まないもの」と「## やらないこと」の `vault/rules/` の行）
- `.claude/agents/planner.md`（「## 「成果物」の書き方」の `vault/rules/` の行、「## やらないこと」の「成果物は `<ファイル>` のみで…」の行）
- `scripts/diff_gate.py`（T-03 の後の版）
- `vault/harness-improvements/P-20261009-auto-approve.md` の2（提案の元）

## 成果物
- `.claude/agents/verifier.md`（主な成果物）
- `.claude/agents/creator.md`
- `.claude/agents/planner.md`
- `scripts/smoke.sh`（エージェント定義のケースを足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む。かつ `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (agents-1)'` の出力が `1`
- `.claude/` の下に起点コミットの記述が残っていない。確認：`grep -rn '起点コミット' .claude/` が何も出力しない
- verifier の手順が11段に詰めてある。確認：`awk '/^## 手順/{f=1;next} /^## /{f=0} f && /^[0-9]+\. /{print $1}' .claude/agents/verifier.md` の出力が `1.` から `11.` の11行（この順）
- creator の手順が6段に詰めてある。確認：`awk '/^## 手順/{f=1;next} /^## /{f=0} f && /^[0-9]+\. /{print $1}' .claude/agents/creator.md` の出力が `1.` から `6.` の6行（この順）
- エージェント定義に「`vault/rules/` は宣言があっても違反」の記述が残っていない。確認：`grep -rnF -e '宣言があっても差分ゲートが違反' -e 'vault/rules/` 配下は、宣言しても' .claude/agents/` が何も出力しない
- planner が `vault/rules/` を宣言すれば成果物にできると書いている。確認：`grep -cF '`vault/rules/` 配下は、宣言すれば成果物にできる' .claude/agents/planner.md` の出力が `1`

## 決定済み
- verifier.md：「## 手順」の10（「タスク票の「進捗」にある `起点コミット: …`」で始まる段）を丸ごと消し、今の11・12を10・11に繰り下げる。宣言外の変更を verdict の `reasons` に記録する決まりもこれで無くなる（差分ゲートが review・done への遷移で止める）。ほかの段・「## 受け渡し」以降は変えない
- creator.md：「## 手順」の3（`git rev-parse --short HEAD` を取って「進捗」の先頭に起点コミットを記録する段）を丸ごと消し、今の4〜7を3〜6に繰り下げる
- creator.md の「## 書き込まないもの」の `vault/rules/` の行は次の趣旨に直す：`vault/rules/` 配下は「成果物」に宣言されている時だけ変える（verifier の判定基準を自分で変えないため。宣言の無い変更は差分ゲートが差し戻す）。「## やらないこと」の `vault/rules/` の行も同じ趣旨（「成果物」に宣言されていない `vault/rules/` を編集しない）に直す。「宣言があっても差分ゲートが違反にする」の字面は書かない
- planner.md の「## 「成果物」の書き方」の `vault/rules/` を含む行は次の2文にする：「`vault/plans/`・`vault/log/`・`vault/verdicts/` 配下は、宣言しても違反になるので成果物にしない。」「`vault/rules/` 配下は、宣言すれば成果物にできる（変更は PR の差分で人が見る）。」。後の文は `` `vault/rules/` 配下は、宣言すれば成果物にできる `` の字面のまま書く
- planner.md の「## やらないこと」の「成果物は `<ファイル>` のみで他ファイルは変更していない」の行から「verifier の起点コミットの検査（`.claude/agents/verifier.md`）と」を消し、「`transition.py` の差分ゲートに任せてもよい」の形にする。ほかの文は変えない
- frontmatter（`name`・`description`・`tools`・`model`）は3ファイルとも変えない
- 足す smoke のケース（`scripts/smoke.sh` の末尾の「主な文書の参照切れの検査」の前に置く。名前は `(agents-1)`、1行の `ok`/`NG`）：`.claude/agents/creator.md`・`.claude/agents/verifier.md`・`.claude/agents/planner.md` のどれにも「起点コミット」の語が無い
- `docs/vault-spec.md` 6節（`reasons` の「宣言外ファイルの変更を検出した場合」）の更新は T-06 が行う
