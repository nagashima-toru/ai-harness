# T-04 smoke.sh に analyze_bash_writes の呼び出し回数と挙動が変わった例のケースを足す

## 目的
Bash 判定の一本化（T-01〜T-03）を smoke で守る。`analyze_bash_writes` が1回のフック呼び出しで高々1回しか実行されないことと、一本化で挙動が変わった例（変更前は許可、変更後は拒否）を、`scripts/smoke.sh` のケースとして足す。既存のケースは消さず、期待値も変えない。

## 入力
- `vault/designs/D-011.md`（フェーズ3の受け入れ基準の候補）
- `scripts/smoke.sh`（`run_guard`・`expect_guard`（403行目の4引数版）・`expect_eq`（1055行目）・末尾の `smoke: pass=... fail=...`）
- `.claude/hooks/agent_write_guard.py`（T-03 の成果物）
- T-03 の「進捗」（挙動が変わった例の一覧があれば）
- 参考：`vault/tasks/P-20261005-bash-write-unify/fixtures/bash_writes_check.py`（回数の数え方の例。smoke からは参照しない）

## 成果物
- `scripts/smoke.sh`（1ファイル）

## 受け入れ基準
- 既存のケースの行を消していない（期待値の変更は行の削除として現れる）：`git diff main -- scripts/smoke.sh | grep -cE '^-([^-]|$)'` の出力が `0`
- 足したケースが通り、ラベルが `(bash-write-unify)` で始まる：`bash scripts/smoke.sh 2>&1 | grep -c '  ok   (bash-write-unify)'` の出力が `3` 以上で、`bash scripts/smoke.sh 2>&1 | grep -c '  NG   (bash-write-unify)'` の出力が `0`
- smoke 全体が通り、件数が増えている：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含み、pass の値が `516` 以上
- smoke がこの計画のフィクスチャに依存していない：`grep -c 'P-20261005-bash-write-unify' scripts/smoke.sh` の出力が `0`
- smoke 実行でバイトコードを作らない：上の smoke を実行した後に `find .claude/hooks -name '*.pyc' -newer scripts/smoke.sh` の出力が空

## 決定済み
- 足すケース（ラベルは全て `(bash-write-unify)` で始める。新しい節として smoke.sh の末尾、最後の `echo` と `smoke: pass=` の行の手前にまとめて置く）
  - 呼び出し回数のケースを2件：`vault/rules/` へ書き込む解析できる形（例：`echo x > vault/rules/a.md`）と、解析できない形（例：`bash -c "echo x > vault/rules/a.md"`）のそれぞれで、`agent_write_guard` の `main()` を1回動かした時の `analyze_bash_writes` の実行回数が `1` であることを `expect_eq` で確かめる。2件とも判定が拒否であることもラベルか別のケースで確かめてよい
  - 挙動が変わった例を1件以上：verifier（`"agent_type":"verifier"`）の Bash で、解析できない形・repo の外だけへのリダイレクト・引用符の中に `vault/tasks/<計画ID>/<id>.md` を含むコマンド（例：`python3 -c "open('vault/tasks/P-X/T-01.md')" > /tmp/x.txt`）が拒否されること（`expect_guard ... deny`）。ラベルに「一本化で許可→拒否」の趣旨を書く。T-03 の「進捗」に他の例があれば、それもケースにしてよい
- 呼び出し回数の数え方
  - Python は `python3 -B` で、標準入力のヒアドキュメント（`python3 -B - <<'PY' … PY`）として書いてよい。`sys.dont_write_bytecode = True` にしてから `.claude/hooks` を `sys.path` に入れて `import agent_write_guard as G` する
  - `G.analyze_bash_writes` を、回数を数えて元の関数を呼ぶ関数に差し替える（`bash_write_targets` はグローバル名で呼ぶので差し替えが効く）。payload は `sys.stdin = io.StringIO(json.dumps(...))` で渡し、`G.main()` の `SystemExit` を捕まえ、標準出力は `contextlib.redirect_stdout` で捨てる。最後に回数だけを print して `expect_eq` で比べる
  - 環境は既存の `run_guard` と同じく `CLAUDE_PROJECT_DIR="$TMP"`。worktree への委譲を避けるため `_HOOK_DELEGATED=1` を付ける。payload に `cwd` は入れない
  - 2件のコマンドは別の文字列にする（`bash_write_targets` はコマンドでメモ化している）
- フィクスチャ（`vault/tasks/P-20261005-bash-write-unify/fixtures/`）は smoke から参照しない（計画の完了後にアーカイブされうるため）。必要な入力は smoke の中で組み立てる
- 既存のケースの削除・期待値の変更はしない。足したケースが通らない場合は、`agent_write_guard.py` を直さず blocked にして、ケースと出力を question に書く
- `.claude/hooks/agent_write_guard.py`・`docs/vault-spec.md`・他のファイルは変更しない
- コミットは受け入れ基準に無いので、creator はしない
