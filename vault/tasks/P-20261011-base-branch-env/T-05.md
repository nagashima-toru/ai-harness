## 決定済み
- vault-spec の定義の段落は、1節の `HARNESS_PR_BODY_FILE` の段落（`環境変数 `HARNESS_PR_BODY_FILE`（本文のファイルのパス）…` の行）の直後に、1行の段落として置く。次の文をそのまま使ってよい（語の順序を受け入れ基準の正規表現が見る）：
  `環境変数 `HARNESS_BASE_BRANCH` はベースブランチ（計画・設計のブランチを切る元で、PR/MR の取り込み先）の名前。前後の空白を除いて空（未設定を含む）なら `main` とする。値の形式は検査しない。影響する箇所は `scripts/vcs_finish.sh`（GitHub REST の `base`・ホスティング無しのマージ案内の取り込み先）、`/plan` 手順A-2・`/design` 手順1 の開始条件、`agent_write_guard.py` の (b)（ベースブランチと `main` の両方で `git commit` を拒否）、`scripts/purge_plan.sh --merged` のマージ済み判定、run 手順7の MCP 代替時の base。恒久的に変える時は導入先の `.claude/settings.json` の `env` に書く（`docs/install.md`）。`
- 1節の `HARNESS_PR_BODY_FILE` の段落は `-f base=main` を `-f base=<ベースブランチ>` に、`base は `main` 固定` を「base はベースブランチ（`HARNESS_BASE_BRANCH`、既定 `main`）」にする。GitLab はターゲットブランチを指定しない（glab の既定）ことを1文足してよい
- 1節の計画一式の段落の「`main` には入れない」、`--merged` の段落の「`main` にマージ済み」「`main` の版の計画票も `status: done`」、4節の「`main` にある done の計画票」「main へのマージは含まない」、9節の「`main` では PR を作った時点で done」、13節の「`main` から切る」「`main` にマージする」「`main` に要る」「`main` にマージ済み」「現在のブランチが `main` であることを確認してから」は、「ベースブランチ（既定 `main`）」に言い換える（同じ段落で2回目以降は「ベースブランチ」だけでよい）
- 12節の (b) の行は、判定名を `(b) ベースブランチと main への直接コミット` にし、対象の「現在のブランチが `main`」を「現在のブランチが `HARNESS_BASE_BRANCH` の値（前後の空白を除いて空なら `main`）か `main`」にする。結果の列に「理由にはそのブランチ名を入れる」を足す。表の列構成は変えない。12節冒頭の「(b) main への直接コミット」に触れる箇所があれば同じ名前にそろえる
- runbook は、3節の「main の履歴」「main の `git log`」「main にタスクごとのコミットが残る」、5節の「`main` にマージ済み」「`main` に残った分」「5. `main` の版の計画票も `status: done`」（受け入れ基準の字句にする）、コミット例 `一括削除: main にマージ済みの…` を、ベースブランチ（既定 `main`）に言い換える。トラブル表の「`main` では使わない」は「ベースブランチや `main` では使わない」にする
- install は `## サンドボックスを有効にする（任意）` の直前に `## main 以外のブランチをベースにする（任意）` の節を足す。内容：`develop` などをベースにする導入先は、導入先の `.claude/settings.json` の `env` に `"HARNESS_BASE_BRANCH": "develop"` を書く（JSON の例を1つ載せる。`env` キーが既にあればその中に足す）。未設定・空なら `main`。効く箇所の要約（PR の base・`/plan`・`/design` の開始条件・直接コミットの拒否（ベースと `main` の両方）・`purge_plan.sh --merged`）。詳細は `docs/vault-spec.md` を見る、と書く
- `README.md` の図の `orchestrator (main)` は「メインセッション」の意味なので変えない（成果物でもない）
- `HARNESS_PUSH_BRANCH`・クラウドセッションでの使い方はフェーズ2の範囲なので書かない。`docs/decisions.md` への追記もフェーズ2で行う
