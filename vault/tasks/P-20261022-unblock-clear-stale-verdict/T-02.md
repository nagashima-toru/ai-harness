## 決定済み
- 2節の箇条（`- 引き継ぎ（`--resume-worktree`。…）` の箇条の直前）に、次の書き出しで始まる箇条を1つ足す：`- 古い verdict の除去（todo→doing。Issue #227）：`。中身は T-01 の「決定済み」のとおり：todo→doing（通常の着手と `--resume-worktree` の両方）で、検査をすべて通った後、対象の id の `vault/verdicts/<計画ID>/<id>.json` を除去する。追跡済みなら `git rm` で、残ったファイルと未追跡のものは削除で消す。追跡済みの除去があれば状態のコミットの前に `<計画ID>/<id,...>: 古い verdict を除去` で別にコミットする（状態のコミットの対象は変えない）。理由（unblock は attempt を 0 に戻すので、再着手で attempt=1 になると前回の verdict の attempt と再び一致し、stop_gate が古い PASS を有効とみなすため。todo の行は stop_gate の検査対象外なので、再着手の入口で消せば unblock の経路に関係なく効く）も1文で書く。`transition.py` は blocked→todo を扱わない（解除は `/plan` の Edit のまま）ことは変えない
- 2節の `--resume-worktree` の箇条：引き継げる時の順序の先頭に、メイン側の古い verdict の除去（追跡済みの除去のコミットが H に入るので、取り込みで worktree からも消える）と、worktree 側の古い verdict の除去（`check_worktree` の後・収集の前。worktree で追跡済みなら `git rm`、未追跡なら削除。コミットは収集コミットに任せる）を足す。末尾の「引き継げない時（記録行が無い・worktree の検証に通らない・マージの衝突）は何も変えず終了コード 5 で、」を「引き継げない時（記録行が無い・worktree の検証に通らない・マージの衝突）は、古い verdict の除去のほかは何も変えず終了コード 5 で、」にする
- 2節の終了コードの箇条の「5 `--resume-worktree` で worktree を引き継げなかった（何も変えていない）」を「5 `--resume-worktree` で worktree を引き継げなかった（古い verdict の除去のほかは何も変えていない）」にする
- 7節の blocked の解除の段落（`blocked の解除（`/plan unblock`）はタスクに紐づくので` で始まる段落）の末尾に、次の文を足す：「`/plan unblock` は verdict に触れない（古い verdict は再着手の todo→doing で `scripts/transition.py` が消す。2節）。」
- 6節の「`attempt` は計画票のタスク表の attempt と一致させる。」の箇条の末尾に、unblock で attempt が 0 に戻ると再着手の attempt=1 が前回の verdict の attempt と再び一致しうるため、再着手の todo→doing で古い verdict を除去する（2節）ことを1文で足す
- 1節の証跡の段落（`証跡は3層で残る` で始まる段落）の git の履歴の列挙に、`<計画ID>/<id,...>: 古い verdict を除去`（追跡済みの古い verdict を再着手で除去した時だけ）を足す
- バッククォートで書くパスは既存のもの（`scripts/transition.py`・`vault/verdicts/<計画ID>/<id>.json` など）だけにする（新しいファイルは作らない。`(ref-1)` を壊さない）
- 他の節・他のファイルは変えない。`.claude/skills/` の文書は T-03 で直す
