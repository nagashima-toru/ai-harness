# T-03 run スキルに、残った worktree を discard_worktree.sh で消す後始末の節を足す

## 目的
サンドボックスの中では transition.py の後始末（`git worktree remove --force` と `git branch -D`）が `.git/worktrees/` への書き込みを拒否されて失敗し、worktree とブランチが残る。run が transition.py の後に残った worktree を `bash scripts/discard_worktree.sh`（T-02 でサンドボックスの外で動くようにする）で消すようにし、人がターミナルで消す作業を無くす。

## 入力
- `.claude/skills/run/SKILL.md`（早見表・手順4・手順6の3と4・手順7の4・ハング時の復旧）
- `scripts/transition.py` の `discard_worktree`（411行目付近。失敗は標準エラーに `[transition] worktree の破棄に失敗しました` などを出すだけで、終了コードは変えない。読むだけで変えない）
- `scripts/discard_worktree.sh`（検証してから `git worktree remove --force` と `git branch -D` を行う。読むだけで変えない）
- `vault/tasks/P-20261009-sandbox-friendly/T-02.md` の決定済み（`excludedCommands` の4つのパターン）

## 成果物

## 決定済み
- 新しい節は `## 6. verdict に従う（逐次処理）` の節の後、`## 7. 次へ・完了` の前に置き、見出しを `## worktree の後始末（サンドボックス）` とする。中身は次のとおり（語は変えてよいが、受け入れ基準2〜4行目の文字列はこのとおりに書く。下の3つの文字列は節の中に1回ずつだけ書く）
  - 1段落目：サンドボックスの中では transition.py の後始末（`git worktree remove --force` と `git branch -D`）が `.git/worktrees/` への書き込みを拒否されて失敗し、worktree とブランチが残る（transition.py は警告を標準エラーに出すだけで終了コードは変えない）。そこで run は、done（終了コード0）・FAIL の再試行（終了コード3）・差分ゲートの差し戻し（終了コード3）の後に、`git worktree list --porcelain` にその worktree のパス（`worktree <パス>` の行）がまだあれば、次を1回実行する
  - 呼び出し：`bash scripts/discard_worktree.sh <worktree> <branch>`（`<worktree>`・`<branch>` は transition.py に渡したものと同じ）
  - `discard_worktree.sh` と `vcs_finish.sh` は `.claude/settings.json` の `sandbox.excludedCommands` によりサンドボックスの外で実行される（だから `.git/worktrees/` や `.git/config` に書ける）。`bash scripts/discard_worktree.sh` の前に `cd` や `env` を付けない（パターン `bash scripts/discard_worktree.sh *` に一致させるため）
  - 終了コードが0以外の時は、別の手段（`git worktree prune`・`git update-ref -d`・`rm` など）で消そうとせず、標準エラーと `git worktree list --porcelain` の出力を完了報告に写して次へ進む（タスクの状態は変えない。人に知らせるだけ）
  - サンドボックスが無い環境では transition.py の後始末が成功するので、`git worktree list --porcelain` にパスが無く、何もしない
  - blocked（終了コード4）の時は worktree を残す（今までどおり。この節の対象外）
- 手順4の終了コード3の項目、手順6の3の終了コード0の項目、手順6の4の終了コード3の項目の3か所の末尾に、それぞれ `続けて「worktree の後始末（サンドボックス）」の節を行う。` を足す（受け入れ基準5行目で `「worktree の後始末（サンドボックス）」の節` を3と数えるので、ほかの場所にはこの文字列を書かない）
- 「回帰確認」の項目5（「PASS で `done` になれば transition.py の done が削除済み」）は、「transition.py の done か「worktree の後始末（サンドボックス）」の節の `discard_worktree.sh` が削除済み」のように直してよい。直す時は「」の中の文字列を `worktree の後始末（サンドボックス）の節`（鉤括弧なし）と書き、受け入れ基準5行目の数を変えない
