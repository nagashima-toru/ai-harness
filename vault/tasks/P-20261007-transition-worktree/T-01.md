# T-01 transition.py に --worktree の共通部品（引数・worktree の検証・収集コミット・新規コミット判定）と review を足す

## 目的
`scripts/transition.py` に `--worktree <パス> --branch <ブランチ> --plan-head <sha>` を足し、`review` で「worktree の未コミット分の収集 → 新規コミットの判定 → 差分ゲート → review／差し戻し／blocked」を1コマンドで行えるようにする（D-012 フェーズ4の (1)）。T-02（done）・T-03（doing・blocked）が使う共通部品もここで作る。`--worktree` を渡さない呼び出しはフェーズ2の動きのまま残す。

## 決定済み
- 引数：
  - `--worktree <パス>`・`--branch <ブランチ>`・`--plan-head <sha>` を足す。`--worktree` と `--branch` は両方そろって使う（片方だけは終了コード2）。`--plan-head` だけ・`--branch` だけを `--worktree` 無しで渡すのも2
  - `--worktree` を渡す時、id は1つだけ（`,` で複数を渡すと2）
  - このタスクの時点では `--worktree` を受け付ける遷移先は review だけ。done・doing・blocked に `--worktree` を付けたら終了コード2（理由は「まだ対応していない」旨。T-02 で done、T-03 で doing・blocked を受け付けるようにする）。review では `--plan-head` が必須（無ければ2）
  - 既存の `--note`・`--no-model` はそのまま使える。`--note` の値は、下で決める自動の補足の後ろに空白区切りで付ける
- 検査の順（どれかに当たったら、計画票・log・worktree のどれも変えずに終了コード1）：
  1. フェーズ2の検査（git リポジトリ・計画票が approved・ブランチが `work/<計画IDの英小文字>`・行がある・doing→review が遷移表にある＝今の status が doing・attempt が整数）
  2. worktree とブランチの検証（`scripts/discard_worktree.sh` と同じ条件）：ブランチ名が `worktree-agent-` で始まる／`git -C <root> worktree list --porcelain` にそのパスの worktree がある／その worktree の `branch refs/heads/<名前>` が `--branch` と一致する。パスは `os.path.realpath(<--worktree>)` と、一覧の `worktree <パス>` の `os.path.realpath` を比べる（macOS の一時ディレクトリでは `/var/...` と `/private/var/...` のように形が違う。フィクスチャの `@WT` は realpath でない形で渡る）
  3. `--plan-head` を `git rev-parse --verify --quiet <sha>^{commit}` で40桁の sha に解決できる
- 共通部品として関数に分けておく（T-02・T-03 が使う。名前は自由）：worktree の検証、収集コミット、新規コミットの件数、差分ゲートの呼び出し、worktree の破棄、計画票・log（・タスク票）を書き換えて1回でコミットする処理（フェーズ2の書き換え・コミット・失敗時の巻き戻しをこの形にまとめ直してよい。`--worktree` 無しの動きと出力は変えない）
- review の処理（検査がすべて通った後）：
  1. 収集：`git -C <worktree> status --porcelain` が空でなければ `git -C <worktree> add -A` → `git -C <worktree> commit -q -m "<計画ID>/<id>: creator 成果物をオーケストレーターが収集"`。空ならコミットしない。失敗したら `git -C <worktree> reset -q` で index を戻して終了コード1
  2. 新規コミットの判定：`git -C <root> rev-list --count <plan_head>..<branch>` が0なら doing→blocked（下の「新規コミット無し」）
  3. 差分ゲート：`scripts/` を `sys.path` に入れて `import diff_gate` し（`--worktree` を使う時だけ import する。失敗したら終了コード1）、`diff_gate.check(root, 計画ID, id, <plan_head の40桁>, <branch>)` を呼ぶ。`GateError` なら理由を標準エラーに出して終了コード1（計画票・log は変えない。収集コミットは worktree に残ったままでよい）
  4. 違反なし：log に再開情報の記録行と `doing→review` の行をこの順に書き、計画票と log をコミットして終了コード0
  5. 違反あり：下の「差し戻し」か「上限で blocked」
- 再開情報の記録行：`- <日時> <id> worktree path=<realpath> branch=<branch> plan_head=<40桁の sha>`（`docs/vault-spec.md` 7節の形）。遷移の行と同じ日時で、遷移の行の直前に書く。worktree を残す結果（review・blocked）の時だけ書き、差し戻しで破棄する時は書かない
- 差し戻し（違反あり・今の attempt を n として n+1 ≦ `HARNESS_MAX_ATTEMPTS`）：
  - 違反のパスは `check` の戻り値の順に `, ` でつなぐ（以下 `<パス一覧>`。理由は書かない）
  - メインの作業ツリーのタスク票 `vault/tasks/<計画ID>/<id>.md` の末尾（「## 進捗」節の最後）に `- 差し戻し（attempt=<n>）: 宣言外の変更 <パス一覧>` を1行追記する（末尾に改行が無ければ先に足す）
  - 計画票は doing のまま attempt を n+1 にし、log に `- <日時> <id> doing→doing attempt=<n+1> 宣言外の変更: <パス一覧>` を書く（モデルは付けない）
  - 計画票・log・タスク票を `git commit -m "<計画ID>/<id>: doing→doing" -- <3つのパス>` で1回でコミットし、その後で worktree を破棄する：`git worktree remove --force <realpath>` → `git branch -D <branch>`（`discard_worktree.sh` と同じ処理を Python で書く。subprocess からの git は `.claude/settings.json` の deny の対象外）
  - 終了コード3
- 上限で blocked（違反あり・n+1 が上限を超える）：タスク票の「進捗」に差し戻しと同じ1行を追記し、記録行と `doing→blocked attempt=<n>` の行（`creator=` はフェーズ2の規則どおり付く。補足は `宣言外の変更: <パス一覧>`）を書き、question は `宣言外の変更: <パス一覧>`。計画票・log・タスク票をコミットし、worktree は残す。終了コード4
- 新規コミット無し：記録行と `doing→blocked attempt=<n>` の行（`creator=` 付き。補足は `新規コミット無し`）を書き、question は `worktree に新規コミットが無い（マージ対象の差分が無い）`。計画票と log をコミットし、worktree は残す。終了コード4
- question と補足は、フェーズ2の `clean_text`（`|` を `／`、改行を空白）を通して書く
- コミットの件名はフェーズ2と同じ `<計画ID>/<id>: <旧>→<新>`。ほかの staged な変更を混ぜない（パスを指定してコミットする）。書き込み・コミットに失敗したら、フェーズ2と同じく書いたファイルを元に戻して終了コード1
- 状態のコミットの後の worktree の破棄に失敗した時は、標準エラーに `[transition] ` で始まる警告を出し、終了コードは3のままにする
- 標準出力：
  - 終了コード0：フェーズ2と同じ `<計画ID>/<id>: <旧>→<新> attempt=<n>` の1行
  - 終了コード3・4：何をしたかを1行だけ。形は `<計画ID>/<id>: <旧>→<新> attempt=<n> <内容>。worktree を破棄した` か `…。worktree を残した`。`<内容>` は、差し戻しは log の補足（`宣言外の変更: <パス一覧>`）、blocked は question
  - 1・2 の時の理由は標準エラー（フェーズ2どおり）
- 終了コードの意味（docstring に書く）：0 review/done にした／1 前提を満たさず何もしていない／2 引数の誤り／3 差し戻した（creator を呼び直す）／4 blocked にした
- 先頭の docstring に `--worktree` の使い方・review の動き・終了コード 0〜4 を書き足す。標準ライブラリだけ・Python 3.9 で動く書き方（`match` 文や `X | Y` の型注釈は使わない）
- `scripts/smoke.sh`（T-04）・`docs/vault-spec.md`（T-05）・`scripts/diff_gate.py`・`scripts/discard_worktree.sh`・`.claude/skills/run/SKILL.md`・`.claude/hooks/` は変えない。フィクスチャ `try.sh` は成果物ではないので変えない
