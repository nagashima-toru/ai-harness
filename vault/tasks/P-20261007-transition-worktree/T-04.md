## 決定済み
- 節は最後の節（`== diff_gate.py（D-012 フェーズ3） ==`）の後、最後の `echo` と `echo "smoke: pass=$PASS_N fail=$FAIL_N"` の前に足す。見出しは `echo "== transition.py worktree（D-012 フェーズ4） =="` の字句どおり。pr_body.py のケース（24・25）もこの節に入れる（既存の `vcs_finish-body` のケースは変えない）
- 判定は既存の `expect_eq`（名前・期待値・実際の値）を使う。ケース名はすべて `(transition-wt) NN ` で始め（`NN` は下の一覧の2桁の番号）、後ろに内容を書く。1つの番号に複数の `expect_eq` を書いてよい（その時は同じ番号で始まる名前を複数使う）
- 一時リポジトリは `$TMP/tw` の下に作る（`$TMP` は既存の `trap` で消える。worktree も `$TMP/tw` の下に置く）。ケースごとに作り直すヘルパー関数（例：`tw_setup <T-01 の status> <attempt> <verdict の種類> ...`）を節の中に定義する。形はフィクスチャ `try.sh` と同じでよい：
  - ブランチ `work/p-test`、承認済み計画票 `P-TEST`（T-01 と T-02 の2行）、タスク票 `vault/tasks/P-TEST/T-01.md`（6見出し。「成果物」は `src/ok.txt`）、`.claude/agents/creator.md`・`verifier.md`（model を smoke 用の値にする）をコミット → `PLAN_HEAD` を控える → `git worktree add -q -b worktree-agent-<名前> <パス> <PLAN_HEAD>` → ケースの変更を worktree に置く（必要ならコミットする）→ verdict は未追跡で置く
  - `transition.py` は `( cd <リポジトリ> && python3 "$ROOT/scripts/transition.py" P-TEST T-01 <遷移先> --worktree <パス> --branch <ブランチ> [--plan-head <sha>] )` の形で呼び、終了コードは `$?`、標準出力・標準エラーは `$TMP` の下のファイルに受けて見る
  - log の記録行のパスとの比較には、worktree のパスの realpath（`python3 -c 'import os,sys;print(os.path.realpath(sys.argv[1]))'`）を使う（macOS の一時ディレクトリは `/var/...` と `/private/var/...` で形が違う）
- 必須ケース（番号と内容。名前の後半の文言は自由）：
  - 01 review：未コミットの変更が worktree 側でコミットされ、その件名が `P-TEST/T-01: creator 成果物をオーケストレーターが収集`
  - 02 review：宣言どおりの変更で終了コード0、T-01 が review
  - 03 review：02 の log に `worktree path=<realpath> branch=<ブランチ> plan_head=<40桁>` の行と `doing→review attempt=1 creator=<model>` の行がこの順に追記される
  - 04 review：宣言外のファイルがあると終了コード3、T-01 が doing・attempt=2
  - 05 review：04 でタスク票の末尾の行が `- 差し戻し（attempt=1）: 宣言外の変更 <パス>`、log の最後の行が `doing→doing attempt=2 宣言外の変更: <パス>` で終わる（`creator=` が無い）
  - 06 review：04 で worktree（`git worktree list` の登録とディレクトリ）とブランチが消える
  - 07 review：attempt が上限（`HARNESS_MAX_ATTEMPTS` の既定3。表の attempt を3にする）で宣言外のファイルがあると終了コード4、T-01 が blocked で question に宣言外のパス、worktree が残る
  - 08 review：新規コミットが無い worktree で終了コード4、question が `worktree に新規コミットが無い（マージ対象の差分が無い）`
  - 09 review：worktree とブランチの検証に通らない（ブランチ名の不一致・未登録のパス・`worktree-agent-` で始まらないブランチ）時は終了コード1で、計画票・計画ブランチのコミット数・worktree 側のコミット数が変わらない
  - 10 done：終了コード0、計画ブランチに親が2つのマージコミット（件名 `P-TEST/T-01: マージ`）ができる
  - 11 done：10 で T-01 が done、最後のコミットに `vault/verdicts/P-TEST/T-01.json` が含まれる
  - 12 done：10 で worktree とブランチが消える

  - 14 done：計画ブランチ側と衝突する変更で終了コード4、マージ中の状態が残らない（`git rev-parse --git-path MERGE_HEAD` のファイルが無い）
