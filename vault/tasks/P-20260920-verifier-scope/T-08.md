# T-08 基準の妥当性判定の手順を具体化する（実地で働かなかったため）

## 目的
T-05 の1回目の実地テストで、宣言外ファイル検査は正しく働いたが、基準の妥当性判定は働かなかった。
わざと緩く作った基準（タスクの目的は「`vault/tmp/dummy-declared.md` を作る」なのに、確認コマンドは
`grep -c 'ハーネス' README.md` が1以上）に対し、verifier は「出力: 4（1以上なので基準を満たす）」と
判定しただけで緩さを指摘しなかった。現在の文面は「判定する」としか書いておらず、どう判定すれば
よいかの手順が無いのが原因。判定手順を具体化する。

  対象が一致しているかを見る観点が明記されている。確認：
  `grep -cF '目的」が指す対象と確認コマンドが見ている対象' vault/rules/verifier/verifier.md` が1以上
- 同ファイルに、基準を満たしたまま目的を達成していない状態があり得るかを考える観点が明記されている。
  確認：`grep -cF '基準を満たしたまま目的を達成していない状態' vault/rules/verifier/verifier.md` が1以上
- 同ファイルに、語数を数えるだけの確認コマンド（`grep -c` が1以上の形式）を緩い基準の典型として

  `grep -cF '目的」が指す対象と確認コマンドが見ている対象' .claude/agents/verifier.md`、
  `grep -cF '基準を満たしたまま目的を達成していない状態' .claude/agents/verifier.md`、

  `sed -n '/^## 禁止/,/^## 出力/p' .claude/agents/verifier.md | grep -c '^- '` が4

## 決定済み
- **判定手順として書く3つの観点**（この3つを満たす文面にする。言い回しの調整は可）：
  1. 「目的」が指す対象と確認コマンドが見ている対象が一致しているか（例：目的が「ファイル A を作る」
     なのに確認コマンドが別のファイル B を見ているなら緩い）
  2. 基準を満たしたまま目的を達成していない状態があり得るか（あり得るなら緩い）
  3. 語を数えるだけの確認コマンド（`grep -c '<語>'` が1以上の形式）は緩い基準の典型。その語が
     成果物のどこにあっても通るため、目的の達成を保証しない
- 記録の仕方（`ok: true` のまま `note` と `reasons` に書く、FAIL にはしない）は変更しない。
  変えるのは「どう判定するか」の手順だけ。
- `vault/rules/planner/planner.md` は変更しない（planner 側の「書かない」ルールは既にある。今回直すのは
  verifier 側の「見抜く」手順）。
- `vault/rules/verifier/verifier.md` は `doing`/`review` 中は `agent_write_guard.py` に阻まれる。人が
  承認済みの回避策「`todo` のうちに内容を編集し、その後 `doing` にする」を使う。
- このタスクの起点コミットは T-07 で追加した新ルールに従って「進捗」の先頭に記録する。
