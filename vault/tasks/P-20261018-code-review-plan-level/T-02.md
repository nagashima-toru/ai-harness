# T-02 creator 定義の先回りレビューを計画全体の差分に合わせる

## 目的
creator の「コードレビューを参照する基準がある時」の節を、計画単位のレビュータスクで計画全体の差分（ベースブランチとの分岐点から）をレビューする形に直す。先回りは「実行→直す→1回だけ再確認」のまま。

## 入力
- `.claude/agents/creator.md`（「## 手順」の6・「## コードレビューを参照する基準がある時」・「## 完了前の確認」）
- `docs/vault-spec.md` 1節の `HARNESS_BASE_BRANCH` の段落・11節の「コードレビューを参照する受け入れ基準」（現行の要約。このタスクでは変えない）

## 成果物
- `.claude/agents/creator.md`（1ファイル）

## 受け入れ基準
- 節の見出しが変わっていない：`grep -c '^## コードレビューを参照する基準がある時' .claude/agents/creator.md` が `1`
- レビューの範囲がベースブランチとの分岐点からの差分になっている：`grep -c 'diff --merge-base .ベースブランチ.' .claude/agents/creator.md` が1以上
- 対象の行の既定の書き方が計画の差分になっている：`grep -c 'で計画の差分に致命的な指摘が残っていない' .claude/agents/creator.md` が1以上、かつ `grep -c '計画単位のレビュータスク' .claude/agents/creator.md` が1以上
- 再確認を1回だけに抑える記述が残っている：`grep -c 'もう1回だけ' .claude/agents/creator.md` が1以上
- タスク単位の範囲と導入先任せの古い記述が残っていない：`grep -c -e 'そのタスクの差分' -e '導入先の planner ルール' -e 'で差分に致命的な指摘' .claude/agents/creator.md` が `0`
- smoke の `(ref-1)` が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- 見出し `## コードレビューを参照する基準がある時` は変えない（`docs/vault-spec.md` が節の名前で参照しているため）。番号付きの6項目の構成も保つ
- 1（対象の行）：既定の書き方を「`/code-review` で計画の差分に致命的な指摘が残っていない」にする。この行を持つのは planner が計画の最後に足す「計画単位のレビュータスク」（`.claude/agents/planner.md` の「計画単位のレビュータスク」節）で、通常のタスクの基準には入らない旨を書く。「導入先の planner ルールが決める」の記述は消す。説明・引用しているだけの行は対象にしないこと、基準に無ければ `/code-review` を呼ばないことは残す
- 2（範囲と呼び方）：対象は計画全体の差分で、`git -C <worktree のパス> diff --merge-base <ベースブランチ>` の差分（ベースブランチとの分岐点から作業ツリーまで。未コミットの変更も含む）と書く。ベースブランチは環境変数 `HARNESS_BASE_BRANCH`（前後の空白を除いて空なら `main`）。計画単位のレビュータスクの worktree は全タスクのマージ後の計画ブランチから分岐するので、この差分に計画の全タスクの変更が入る。ローカルにベースブランチの ref が無ければ `origin/<ベースブランチ>` を使い、どちらも無ければ「blocked: <質問文>」で返す。計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない（状態ファイルで、差分ゲートが変更を違反にするため）。Skill ツールで `code-review` を呼び、自分の worktree の絶対パスを明示して渡すこと・基準の行の引数（`effort`・`--max-findings` など）の扱いは現行どおり。呼び方の例は「対象は <worktree の絶対パス>。cd してから `git diff --merge-base <ベースブランチ>` の差分をレビューする（計画一式4種は除く）」にする
- 3（直すもの）：計画の差分で変えた行への致命的な指摘（クラッシュ・データ破損・誤った結果）を直し、直した後に同じ範囲で「もう1回だけ」実行して確かめ、それ以上は繰り返さない（現行の文言を保つ）。直すのは「成果物」に宣言されたファイル（計画で変えたファイル）だけ
- 4（直さないもの）：計画の差分の外（既存コード）への指摘と、致命的でない指摘は直さない（現行どおり）
- 5（人に渡すもの）・6（記録）：現行どおり。致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい旨を6に足す
- 「## 手順」の6と「## 完了前の確認」の該当箇条は、「差分」を「計画の差分」に読める程度に直してよい（意味は変えない）
- ほかの節（入力・受け渡し・git・禁止・やらないこと など）は変えない。frontmatter（tools・model）は変えない（smoke の `(agents-2)` が tools の Skill を検査している）
- `.claude/agents/verifier.md`・`.claude/agents/planner.md` などほかのファイルは別のタスクで直すので変えない
