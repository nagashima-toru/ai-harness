## 受け入れ基準
- 旧方式の理由付けが無い（`grep -c '作業ステップ' vault/tasks/P-20261001-git-rules-align/T-02-proposal.md` が `0`、かつ `grep -c '作業ツリーはクリーン' vault/tasks/P-20261001-git-rules-align/T-02-proposal.md` が `0`）
- 未コミットのファイルも検査対象になっている（`grep -n 'git status --porcelain' vault/tasks/P-20261001-git-rules-align/T-02-proposal.md` がヒットし、その行が `起点コミット` と `git diff --name-only <起点コミット>..HEAD` を含む宣言外ファイル検査の行であることを目視で確認する）
- 新しい理由が書かれている（`grep -n '受け入れ基準にある時だけ' vault/tasks/P-20261001-git-rules-align/T-02-proposal.md` と `grep -n 'オーケストレーター' vault/tasks/P-20261001-git-rules-align/T-02-proposal.md` がそれぞれヒットする）
- 変更が19行目の1行に限られている（`diff vault/rules/verifier/verifier.md vault/tasks/P-20261001-git-rules-align/T-02-proposal.md` の出力に現れる変更箇所の見出しが `19c19` の1つだけである）
- 既存の扱いが残っている（直した行に「`ok: false` にはしない」「FAIL にはしない」と除外対象の4つ（計画票・タスク票の「進捗」・`vault/log/<計画ID>.md`・`vault/verdicts/` 配下）がそのまま残っていることを目視で確認する）

## 決定済み
- 提案ファイルは全文で書く。現行の verifier.md をそのまま写し、19行目だけを書き換える。前置きや frontmatter は付けない
- 19行目のうち「creator は作業ステップごとにコミットするため、verifier が動く時点では作業ツリーはクリーンで、未コミット差分だけを見る方法では何も検出できない。」の文を置き換える。あわせて、検査対象の取得を「`git diff --name-only <起点コミット>..HEAD` の出力」と「`git status --porcelain` に出る未コミットのファイル」の両方にする（計画票の決定済み）。文案は次のとおり（語順の調整は可。ただし基準の語「受け入れ基準にある時だけ」「オーケストレーター」「git status --porcelain」は残す）
  - 「creator のコミットは受け入れ基準にある時だけで、未コミット分は PASS の後にオーケストレーターがまとめてコミットする。そのため verifier が動く時点の worktree には、コミット済みの変更と未コミットの変更の両方がありうる。`git diff --name-only <起点コミット>..HEAD` の出力と、`git status --porcelain` に出るファイルを合わせて変更ファイル一覧とする。」
- 「『進捗』から読むのは起点コミットの値だけ」・除外対象の4つ・`note`/`reasons` の扱い・「`ok: false` にはしない。FAIL にはしない」・起点コミットの記録が無い場合の扱いは変えない
- 「起点コミットの記録が無い場合はこの検査を行わない」は現行どおり残す（未コミット分だけを見る検査に切り替えない）
- T-03（`.claude/agents/verifier.md` 32行目）にも同じ趣旨の文案が書かれている。表現は揃えるが、このタスクでは `.claude/agents/verifier.md` を変更しない
- 実体 `vault/rules/verifier/verifier.md` は変更しない。フックで拒否され、反映は人が行う
- smoke.sh はこのタスクの基準に含めない（T-07 で流す）
- このタスクではコミットしない（受け入れ基準にコミットが無いため）
