## 決定済み
- このタスクは `docs/vault-spec.md` だけを変える。`docs/runbook.md` からの削除は T-02・T-03 が行うので、runbook には触れない。
- 14節は13節の後ろ（ファイルの末尾）に足す。見出しは `## 14. 無人実行ラッパー（`scripts/run_unattended.py`）` の文字どおりにする。1〜13節の番号・見出しは変えない。
- 14節に書く項目（`scripts/run_unattended.py` を読んで再確認し、実装と違えば実装に合わせて書き、違いを「進捗」に記録する）：
  - (1) 用途：cron・CI から無人で `/run` を回すためのタイムアウト付きラッパー。素の `claude -p "/run"` を直接呼ばずにこれを使う（ハングで居座らないため）
  - (2) 実行するコマンド：`HARNESS_RUN_CMD`（未設定か空なら `claude -p "/run"`）を shlex で分割し、シェルを経由せずに実行する。分割できない・空の時は標準エラーに理由を出して終了コード2
  - (3) 制限時間：`HARNESS_RUN_TIMEOUT`（秒。未設定か空なら3600）。正の整数でなければ標準エラーに理由を出して終了コード2
  - (4) タイムアウト時：標準エラーに `run_unattended: timeout <秒>s` を出し、子のプロセスグループ（子は新しいセッションで起動する）に SIGTERM を送り、10秒待っても終わらなければ SIGKILL を送って、終了コード124で終わる
  - (5) 時間内に終わった時は子の終了コードをそのまま返す（シグナルで死んだ子は 128+シグナル番号）。コマンドが見つからない時は127、Ctrl-C で止めた時は子に SIGTERM を送って130
  - (6) 環境変数は子にそのまま引き継ぐ。`HARNESS_STRICT_STOP` が未設定（キーが無い）の時だけ `1` を入れて渡し、設定済みなら値を変えない（`0` を明示すれば `stop_hook_active` が真の時に許可する従来の動き。判定は9節）
  - (7) ラッパーは vault のファイルに書かない。止めた後の復旧は、次回の `/run` が再開手順（`.claude/skills/run/SKILL.md` 手順2の2）で中断した地点から続ける。同じ地点で止まり続けても `HARNESS_MAX_ATTEMPTS` で blocked になる
- 12節の末尾（「### サンドボックス（使っていない）」の後、「## 13.」の前）に小見出し `### 作業ブランチの git の復旧` を足し、runbook の「困ったとき」の表の後の段落の内容を移す。書く項目：
  - (8) merge の途中（`git merge --abort`）・rebase の途中（`git rebase --abort`）・HEAD と作業ツリーの食い違い（`git reset --hard HEAD`）は、作業ブランチ（`work/<計画ID>` か creator の worktree のブランチ）の上でだけ、エージェント（オーケストレーター）が自分で直してよい。ベースブランチと `main` では使わない
  - (9) `.claude/settings.json` の `permissions.deny` に残っているのは `git push --force` 系・`rm -rf` 系・`sudo`・`gh pr merge`・`glab mr merge` だけで、作業ブランチの上の `git reset --hard`・`git clean`・`git branch -D` は止めない（D-015。壊れてもブランチを捨てて作り直せる）
  - (10) 半端な状態を見つける診断スクリプトは無い
  - (11) creator 自身は `.claude/agents/creator.md` の `## git` 節のとおり `git clean`・`git reset --hard` を使わない（worktree の中の自分の作業まで消すため）。この小見出しの復旧はオーケストレーターが行う
- 文書の書き方は既存の vault-spec に合わせる（です・ます調にしない、パスはバッククォート）。14節から `docs/configuration.md`・`docs/runbook.md` へのリンクは足さない（`docs/vault-spec.md` は導入先に配られ、両ファイルは配られないため）。
- runbook の他の内部の記述は、`docs/vault-spec.md` かスキルに同じ内容が既にあるので移さない（移し先は T-02・T-03 の「決定済み」にある）。
