# T-04 docs/runbook.md 4節の blocked 解除手順を /plan unblock を使う形に書き換える

## 目的
人向けの運用手順書の blocked の解除を、T-03 で作った `/plan unblock` に合わせる。人がエージェントに指示するだけで解除できる形にする（D-010 フェーズ5）。

## 入力
- `docs/runbook.md` 4節（`## 4. blocked に答えて戻す`）と冒頭の「人の仕事」の行
- `.claude/skills/plan/SKILL.md` の C 節（T-03 の成果物）
- `vault/designs/D-010.md` フェーズ5の決定済み

## 成果物
- `docs/runbook.md` の変更（1ファイル）

## 受け入れ基準
- 4節が `/plan unblock <計画ID> <id> [回答]` を打つ手順になっている。確認：`grep -n '/plan unblock' docs/runbook.md` が4節内の行にヒットする
- 4節が、エージェントが行う処理（回答の「決定済み」への追記・status を `todo`・attempt を `0`・question を空にする・log 追記・コミット）を説明し、回答を省略できる場合（ハングやマージコンフリクトなど答える質問が無い blocked）と、1回のコマンドで解除するのは1行だけである旨を書いている（目視で確認）
- 4節が、フックが会話記録の人の発言でコマンドの有無を確認するため、エージェントが独断で解除できない旨と、人がエディタで計画票を直接直す方法が代替手段であり、その場合フックは働かない旨を書いている（目視で確認）
- 4節の「`blocked→todo` は人だけが行う」の文が、`/plan unblock` で人が指示する旨に書き換わっている。確認：`grep -n 'blocked→todo` は人だけ' docs/runbook.md` がヒットしない
- 4節以外の節の手順の意味が変わっていない。確認：`git diff -- docs/runbook.md | grep -E '^@@'` の変更箇所が4節（と必要なら冒頭の行）に収まることを目視で確認する

## 決定済み
- 人の操作手順は「(1) `blocked` の行の `question` を読む（計画票のタスク表）、(2) `/plan unblock <計画ID> <id> <回答>` を打つ」の2段。回答が要らない時は回答を省く
- 人がエージェントを通さずエディタで計画票を直す運用は、runbook に代替手段として残す（この場合フックは働かない。変更後は自分で log に追記してコミットする）
- log の行の形は `- YYYY-MM-DD HH:MM <id> blocked→todo 人の指示: /plan unblock <計画ID> <id>`（`docs/vault-spec.md` 7節と揃える）
- 冒頭の「人の仕事」の「blocked に答える」の文言は変えなくてよい
- 「自由な文（「T-03 解除して」）や AskUserQuestion への回答では解除できない」旨は1行で足してよい（D-010 の「今回やらないこと」）
