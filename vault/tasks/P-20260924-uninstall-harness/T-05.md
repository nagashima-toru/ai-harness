# T-05 docs/install.md にアンインストール手順を追記する

## 目的
`docs/install.md` に「アンインストール」の節を追加し、`scripts/uninstall.sh` の使い方と、`install.sh` の `copy`/`skip (exists)`/`skip (edited)` と対称な3種類の報告（自動で消した／編集済みなので残した／利用者資産なので触れない）の意味を説明する。

## 入力
- `/home/user/ai-harness/docs/install.md`（既存の章立て、特に「ハーネスを更新する（2回目以降）」節の表形式）
- T-03 で実装済みの `scripts/uninstall.sh` の実際の出力文言（`remove` / `skip (edited)` / `note` 等）
- T-02 の「決定済み」にある `settings.json` 自動除去の限界（command/deny 文字列の完全一致でしか判定できない旨）

## 成果物
- `docs/install.md`（1ファイルの更新。新規ファイルは作らない）

## 受け入れ基準
- `## アンインストール` の見出しが追加され、`bash scripts/uninstall.sh <target-dir>` のコマンド例が書かれている。確認：`grep -n '^## アンインストール' docs/install.md`
- `install.sh` の `copy`/`skip (exists)`/`skip (edited)` と対称に、`uninstall.sh` の出力（`remove`・`skip (edited)`・`note`）の意味を表または箇条書きで説明している。確認：`grep -n 'remove\|skip (edited)' docs/install.md` がアンインストール節内にヒットする
- `settings.json` の自動除去が「command/deny 文字列の完全一致」でのみ判定するため、利用者が同一文字列を独自に追加していた場合は区別できず一緒に消える可能性がある旨を明記している。確認：`grep -n '完全一致' docs/install.md`
- `CLAUDE.md` のアンインストール（マーカーブロックのみ除去、ブロックだけの内容なら削除、他の本文は残る）を説明している。確認：`grep -n 'マーカー' docs/install.md` がアンインストール節内にヒットする
- `vault/` の利用者資産（`plans/tasks/verdicts/log/designs/archive`、標準4本以外の `vault/rules/`）には一切触れないことを明記している。確認：`grep -n 'plans/tasks/verdicts' docs/install.md` またはそれに相当する記述がアンインストール節内にある

## 決定済み
- 節の挿入位置は「ハーネスを更新する（2回目以降）」節の後、「インストール後の次の一歩」節の前とする
- 見出しレベルは既存の `## ハーネスを更新する（2回目以降）` と同じ `##`（トップレベルの節）にする
- 文体・表形式は既存の「| 出力 | 意味 | やること |」表の流儀に合わせてよい（新しい表を作ってよい）
- `settings.json` は自動化できているので「手動対応の手順」は必須ではないが、自動除去の限界（上記の完全一致の注記）に加え、`settings_src` キーが無い古いマニフェストの場合は自動処理がスキップされる旨と、その場合の手動確認手順（`.claude/settings.json` を開き、`hooks` と `permissions.deny` からハーネス由来のエントリを見比べて手で消す）も1段落で書く
