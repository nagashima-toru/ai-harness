# T-01 planner.md に確認コマンドの文字列へ禁止操作の語を直接書かない指針を足す

## 目的
Issue #224 の再発を防ぐため、planner が「禁止操作が含まれないこと」を調べる受け入れ基準を書く時に、禁止操作の語を確認コマンドの文字列へ直接書かないよう、`.claude/agents/planner.md` に指針と自己チェックの項目を1つずつ足す。

## 入力
- `.claude/agents/planner.md`（「## やらないこと」の Issue #187 の箇条（`確認コマンドを、` で始まり `python3 -c` の中の subprocess を扱う項目）と、「## 書き終えた後の確認」の `python3 -c` の中の subprocess を扱う項目）
- GitHub Issue #224 の内容（下の「決定済み」に要点を写してある）

## 成果物
- `.claude/agents/planner.md`（1ファイル）

## 受け入れ基準
- 「## やらないこと」節に、`- 禁止操作が含まれないことを調べる基準で` で始まる箇条が1つだけあり、節の箇条は18個になっている。確認：`sed -n '/^## やらないこと/,/^## 書き終えた後の確認/p' .claude/agents/planner.md | grep -c '^- 禁止操作が含まれないことを調べる基準で'` が `1`、`sed -n '/^## やらないこと/,/^## 書き終えた後の確認/p' .claude/agents/planner.md | grep -c '^- '` が `18`
- 「## 書き終えた後の確認」節に、`- 禁止操作が含まれないことを調べる確認コマンドの文字列に` で始まる項目が1つだけあり、節の項目は12個になっている。確認：`sed -n '/^## 書き終えた後の確認/,/^## 出力/p' .claude/agents/planner.md | grep -c '^- 禁止操作が含まれないことを調べる確認コマンドの文字列に'` が `1`、`sed -n '/^## 書き終えた後の確認/,/^## 出力/p' .claude/agents/planner.md | grep -c '^- '` が `12`
- 足した箇条に、語を直接書かないこと・2つの回避策・経緯が書かれている。確認：次の4つがいずれも `1`。`grep -c '確認コマンドの文字列に直接書かない' .claude/agents/planner.md`、`grep -c '語を分けて連結する（例：' .claude/agents/planner.md`、`grep -c '検査する語をリポジトリ内のファイルから読む形にする' .claude/agents/planner.md`、`grep -c 'Issue .224' .claude/agents/planner.md`
- smoke の `(ref-1)` が通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`
- 差分に `.claude/agents/planner.md` が含まれる。確認：worktree の中で `git diff --merge-base work/p-20261021-planner-forbidden-words --name-only` の出力に `.claude/agents/planner.md` の行がある

## 決定済み
- 「## やらないこと」の箇条は、Issue #187 の箇条（`- 確認コマンドを、` で始まり `python3 -c` の中の subprocess を扱う項目）の直後の行に1行で足す。文言は次のとおりにする（バッククォートも含めてそのまま書く）：
  - 禁止操作が含まれないことを調べる基準で、禁止操作の語（`git push`・`gh pr merge` など）を確認コマンドの文字列に直接書かない。導入先で、禁止ツールが含まれないことを調べる `python3 -c` の確認コマンドが、中に文字列リテラルの `'git push'`・`'gh pr merge'` を持つだけで拒否され、creator は同じ内容をスクリプトファイルに書いて実行して回避した（Issue #224）。拒否したのはこのリポジトリのフック（`.claude/hooks/`）でも `.claude/settings.json` の `permissions.deny` でもなく、Claude Code 側の権限判定かサンドボックスで、原因は確定していない。語を分けて連結する（例：`'git'+' push'`）か、検査する語をリポジトリ内のファイルから読む形にする。上の `python3 -c` の箇条と同じく、planner 自身が確認コマンドをガードを通る形で試走してから書く
  - 行頭は `- `（箇条）にする。上の文言の先頭の「禁止操作が…」が `- ` の直後に来る
- 「## 書き終えた後の確認」の項目は、`- ` に続けて `python3 -c` の中の subprocess を扱う既存の項目の直後の行に1行で足す。文言は次のとおりにする：
  - 禁止操作が含まれないことを調べる確認コマンドの文字列に、禁止操作の語（`git push`・`gh pr merge` など）を直接書いていないか。語を分けて連結するか、検査する語をリポジトリ内のファイルから読む形にしたか
- 既存の箇条・項目の文言や順序は変えない。足すのは上の2行だけ
- `docs/decisions.md` と `vault/rules/planner/ai-harness-lessons.md` は変えない（同種の Issue #187・#211 の指針が `docs/decisions.md` に書かれていないため。経緯集への追記は依頼の範囲外）。状態遷移・フック・`.claude/settings.json`・スクリプトも変えない
- 受け入れ基準の確認コマンドに禁止操作の語そのものを書かないのは、この指針自体に従うため。語が書かれていることは「確認コマンドの文字列に直接書かない」などの別の文言で確かめる
- `'git'+' push'` はパスとして扱われない（`vault/`・`scripts/`・`docs/`・`.claude/` で始まらない）ので、smoke の `(ref-1)` の対象にならない。`.claude/hooks/` と `.claude/settings.json` は既存のパスなので `(ref-1)` は通る
- planner がこの2行を入れた写しで受け入れ基準の確認コマンドを試走し、期待値（1・18・1・12・各1）を確かめてある。現行のファイルでは新しい箇条の grep はいずれも `0`、節の数は `17`・`11`
