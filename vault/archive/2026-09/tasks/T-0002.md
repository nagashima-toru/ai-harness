## 決定済み
- note の書式は自由文（文字列のまま）でよい。新しいJSONフィールド（例: `evidence`）は追加しない。推奨する書き方の例をverifier.mdに1つ書いておくとよい：`` "実行コマンド: `<command>` / 出力: <要点1〜2行>" ``のような形。数値・真偽の厳密なフォーマットは不要
- 出力の要点の長さの目安は1〜3行程度。コマンドの全出力をそのまま貼り付ける必要はなく、判定に使った部分だけ書けばよい
- コマンドが実行できなかった場合（権限拒否・ツール不足など）の書き方の例：「`<command>` は権限拒否で実行不可。代替として`<ファイルを目視確認/別コマンドで確認>`し、結果は`<要点>`」のように、失敗理由＋代替方法＋その結果をセットで書く
- 判定ロジック（`ok`/`result`/`reasons`の決め方、判定不能行の扱い）は今回変更しない。あくまで note の記述内容の要件追加のみ
- git commit はしない（人が確認してからコミットする）
- （人の回答 2026-09-17）受け入れ基準5は「todo.md の見出し行と列構成を変えていない」に差し替えた。run-queue による status 遷移の差分は許容する
- vault-spec.md のJSON例（`criteria` の1件目）に note の記入例を反映してもよいが、必須ではない（本文の説明文に要件があれば足りる）
