# T-0006 vault-spec.md に「ルール（vault/rules/）」節を追加し置き場を作る

## 目的
インストール先ごとのルール（コーディングルール・開発標準・方式設計・テスト標準・テスト観点など）を作成エージェント・verifier・planner に渡す拡張ポイント `vault/rules/` の仕様を `docs/vault-spec.md` に定め、空の置き場とテンプレートを用意する。

## 入力
- `docs/vault-spec.md`（正本。新節をここに追加する）
- `docs/roadmap-rules-extension.md`（全体設計。「## 0. 全体設計」と「## ① 仕様と置き場を決める（契約）」節を参照。受け入れ基準・決定済みの叩き台がある。そのまま使ってよいが、内容が矛盾しないかは自分で確認する）
- `vault/templates/task.md`、`vault/templates/plan.md`（既存テンプレートの書式の参考。見出し3つだけの `rule.md` は新規に作る）
- `vault/rules/`（現時点では存在しない。このタスクで新規作成する）

## 成果物
- `docs/vault-spec.md` に新節「ルール（`vault/rules/`）」を追加（既存の節番号を崩さないよう末尾に追加してよい）
- 付随して以下も作成する
  - `vault/rules/README.md`

## 受け入れ基準
- `docs/vault-spec.md` に `vault/rules/` の新節があり、`common` / `creator` / `verifier` / `planner` の4語をすべて含む（確認：`grep -c 'vault/rules/' docs/vault-spec.md` が1以上）
- `vault/rules/README.md` が存在し20行以内（確認：`wc -l < vault/rules/README.md` が20以下）
- `vault/rules/common/.gitkeep`・`vault/rules/creator/.gitkeep`・`vault/rules/verifier/.gitkeep`・`vault/rules/planner/.gitkeep` の4ファイルが存在する（確認：`ls vault/rules/common/.gitkeep vault/rules/creator/.gitkeep vault/rules/verifier/.gitkeep vault/rules/planner/.gitkeep`）
- `vault/templates/rule.md` が存在し、見出しが `目的` / `ルール` / `確認方法` の3つだけである（確認：`grep -E '^## ' vault/templates/rule.md` の出力が「目的」「ルール」「確認方法」の3行のみ）
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む（既存の検証が壊れていない）

## 決定済み
- ディレクトリ名は `common` / `creator` / `verifier` / `planner` の4つで固定。追加や改名はしない
- 振り分けはディレクトリのみで行う。frontmatter・索引ファイル（index.md 等）は作らない
- ファイルは `*.md`、小文字ケバブケース。読み込み順は `common/` → 役割ディレクトリ、各ディレクトリ内はファイル名順（仕様として明記するだけでよく、読み込みスクリプトの実装は別タスク（②）で行う）
- ルールは「受け入れ基準を増やすもの」ではなく「基準の判定方法を与えるもの」。verifier は受け入れ基準がルールを参照する時だけルールを根拠にする。この原則は仕様に明記するが、verifier エージェント定義側の変更は別タスク（④）で行う
- 1ファイル100行以内は目安として明記するだけで、機械的な強制（文字数チェック等）はこのタスクでは作らない
- ハーネス自体は `vault/rules/` の中身（ユーザーが書く実ルール）を同梱しない。今回作るのは `.gitkeep` のみの空ディレクトリとテンプレート・README
- 「doing/review 中は `vault/rules/` への書き込みをフックで拒否する」は仕様として1文書くだけでよい。`agent_write_guard.py` の実装・smoke.sh のケース追加はこのタスクの範囲外（別タスク⑥で行う）
- `vault/rules/README.md` の内容は20行以内で、書き方・4ディレクトリへの振り分け・受け入れ基準からルールを参照する例を含める（`docs/roadmap-rules-extension.md` の「### 置き場と振り分け」「### verifier とルールの関係」を要約してよい）
- このタスクでは `scripts/`・`.claude/skills/`・`.claude/agents/`・`.claude/hooks/`・`install.sh`・ルートの `README.md` は変更しない
- 新節を `docs/vault-spec.md` のどこに挿入するかは自由（既存の節番号「1〜11」を崩さないよう、末尾に新しい番号を付けて追加するのが最も安全）
