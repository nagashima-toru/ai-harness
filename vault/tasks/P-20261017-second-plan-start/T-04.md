# T-04 vault-spec と runbook に push 先ブランチの切り直しを書く

## 目的
T-03 で `/plan` A 手順2に足した push 先ブランチの切り直し（Issue #206）を、仕様の正本（`docs/vault-spec.md` 1節）と運用手順（`docs/runbook.md` 10節）に書き、スカッシュマージした時に人が行う作業（リモートの push 先ブランチの削除）を案内する。

## 入力
- `.claude/skills/plan/SKILL.md` の A 手順2（T-03 の後の版。書きぶりを合わせる）
- `docs/vault-spec.md` 1節の `HARNESS_PUSH_BRANCH` の段落（36行目）
- `docs/runbook.md` 10節「push 先が決められている環境（クラウドセッション）」（131〜144行目付近）と 3節のマージ方式（スカッシュマージを推奨）

## 成果物
- `docs/vault-spec.md`（主な成果物。1節の `HARNESS_PUSH_BRANCH` の段落への追記）
- `docs/runbook.md`（10節への箇条の追加）

## 受け入れ基準
- `docs/vault-spec.md` に切り直しの条件が書かれている（確認：`grep -c 'git checkout -B ' docs/vault-spec.md` が `1`、`grep -c 'git merge-tree --write-tree' docs/vault-spec.md` が `1`）
- `docs/vault-spec.md` に、切り直しが `/plan` だけで `/design` には加えないことが書かれている（確認：`grep -c '手順1 には加えない' docs/vault-spec.md` が `1`）
- `docs/runbook.md` の10節に、2つ目の `/plan` での切り直しと、スカッシュマージ後のリモートの push 先ブランチの削除が書かれている（確認：`awk '/^## 10\./,/^## 困ったとき/' docs/runbook.md | grep -c 'git checkout -B '` が `1`、`awk '/^## 10\./,/^## 困ったとき/' docs/runbook.md | grep -c 'リモートの push 先ブランチを削除'` が `1`）
- `docs/vault-spec.md` と `docs/runbook.md` の両方が変更されている（確認：`git diff --merge-base work/p-20261017-second-plan-start --name-only` の出力に `docs/vault-spec.md` と `docs/runbook.md` の行がある）
- smoke の `(ref-1)` が通る（確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`）

## 決定済み
- `docs/vault-spec.md`：1節の `HARNESS_PUSH_BRANCH` の段落（`環境変数 `HARNESS_PUSH_BRANCH` は push 先と…` で始まる行）の中、開始条件の説明（「`/plan` 手順A-2・`/design` 手順1 の開始条件には…が加わる（…）。」の文）の後に、次の趣旨の文を足す。新しい段落にはしない（同じ行に足す）：
  - 「`/plan` 手順A-2 では、上のどの条件も満たさない時、fetch の後で、`HARNESS_PUSH_BRANCH` が設定され、現在のブランチが `work/…` か push 先で、未コミットの変更が無く、`HEAD` とローカルの push 先の内容がベースブランチに取り込み済み（`git merge-tree --write-tree <ベースブランチ> <対象>` の結果がベースのツリーと同じ。スカッシュマージでも同じになる）で、リモートの push 先ブランチ（`git ls-remote --heads origin <push先>`）が無いかベースブランチの祖先なら、`git checkout -B <push先> <ベースブランチ>` で push 先ブランチを切り直してから上の条件で判定する（Issue #206）。リモートの push 先ブランチが残っていてベースの祖先でない時（スカッシュマージの後など）は止まる。この切り直しは `/plan` 手順A-2 だけで行い、`/design` 手順1 には加えない」
  - `git checkout -B ` と `git merge-tree --write-tree` は `docs/vault-spec.md` の中でこの1か所にだけ書く（受け入れ基準1で `1` を数えるため）。`手順1 には加えない` もこの1か所だけ
- `docs/runbook.md`：10節の箇条（`- ` で始まる行）の最後（「指定ブランチのリモートが先に進んでいて push が失敗した時…人が判断する。」の後、`## 困ったとき` の前）に、次の趣旨の箇条を1つ足す：
  - 「1つ目の計画の PR がマージされた後、同じセッションで2つ目の `/plan` を打つと、`/plan` は前の計画の内容がベースブランチに取り込まれていることを確かめて、push 先ブランチを `git checkout -B <push先> <ベースブランチ>` でベースブランチから切り直す（`.claude/skills/plan/SKILL.md` 手順A の2）。スカッシュマージした時は、リモートの push 先ブランチを削除してから `/plan` を打つ（残っていると切り直した後の push が non-fast-forward になるので、`/plan` は止まる）。GitHub ならリポジトリ設定の Automatically delete head branches でマージ後に自動で消せる（設定は人が行う）」
  - `git checkout -B ` と `リモートの push 先ブランチを削除` は10節の中でこの箇条の1か所にだけ書く（受け入れ基準3で `1` を数えるため）
- 文言は T-03 の後の `.claude/skills/plan/SKILL.md` A 手順2と食い違わないようにする。SKILL.md と食い違う時は SKILL.md に合わせる（SKILL.md は変えない）
- バッククォートで囲むパスは、存在するもの（`.claude/skills/plan/SKILL.md` など）だけにする（`(ref-1)` が見るため）。`<push先>`・`<ベースブランチ>` を含む文字列は `(ref-1)` の対象外
- `docs/guide.md`・`docs/configuration.md`・`docs/install.md`・`.claude/skills/design/SKILL.md` は変えない（guide.md と configuration.md は runbook 10節と vault-spec 1節へ案内しているので、そこを直せば足りる。`/design` は対象外）
- Issue #205（`vault/log/.gitkeep`）の記述は足さない（install.sh と smoke の変更で足り、仕様の段落に `.gitkeep` の記述は無いため）
