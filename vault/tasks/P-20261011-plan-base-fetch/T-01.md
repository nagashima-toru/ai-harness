# T-01 /plan 手順A-2・/design 手順1 の開始条件の前に best-effort の git fetch を入れる

## 目的
クラウドセッションでローカルの `<ベースブランチ>` が古いままでも開始条件で止まらないように、開始条件の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を best-effort で1回行う手順を、`/plan` 手順A-2 と `/design` 手順1 に同じ文言で入れる（GitHub Issue #175）。

## 受け入れ基準
- 2ファイルの両方で、決定済みの「挿入する文」の前半が「一致すればベースブランチ上とみなす。」の直後にちょうど1回ある。確認：`grep -cF '一致すればベースブランチ上とみなす。一致しない時は、下の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を1回行う（fast-forward できる時だけローカルのベースブランチの ref を進める非破壊の操作。' .claude/skills/plan/SKILL.md .claude/skills/design/SKILL.md` の出力が `.claude/skills/plan/SKILL.md:1` と `.claude/skills/design/SKILL.md:1` の2行
- 2ファイルの両方で、fetch の失敗時に止まらないことを書いた文が「一致しなくても、」の直前にちょうど1回ある。確認：`grep -cF 'この fetch は best-effort で、失敗しても（ネットワーク不可・リモートが無い・fast-forward できない等）止まらず、そのまま下の確認に進む。一致しなくても、' .claude/skills/plan/SKILL.md .claude/skills/design/SKILL.md` の出力が両ファイルとも `:1`
- 旧文言「`origin/<ベース>` との比較や fetch はしない」が `.claude/` 配下から消えている。確認：`grep -rnF '比較や fetch はしない' .claude/` の出力が空
- 置換後の文言が2ファイルにちょうど1回ずつある。確認：`grep -cF '（ローカルのベースブランチの ref とだけ比べる。`origin/<ベース>` とは比べない）' .claude/skills/plan/SKILL.md .claude/skills/design/SKILL.md` の出力が両ファイルとも `:1`
- 2ファイルに強制更新や破壊的な操作の手順が無い。確認：`grep -cE 'git reset --hard|git fetch.*--force|git fetch origin \+' .claude/skills/plan/SKILL.md .claude/skills/design/SKILL.md` の出力が両ファイルとも `:0`
- smoke の参照切れ検査が通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- smoke 全体が失敗0で終わる。確認：`bash scripts/smoke.sh 2>&1 | grep -c ' fail=0$'` の出力が `1`（smoke は1分以上かかる）

## 決定済み
- 方式は Issue の第1案（開始条件の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を1回行う）。代案（HEAD がベースの子孫かつ fetch した `origin/<ベース>` と一致すれば可）は採らない。比較は引き続きローカルのベースブランチの ref（`git rev-parse --verify <ベースブランチ>`）と行い、`origin/<ベース>` とは比べない
- 挿入する文（2ファイルとも一字一句同じ。`<ベースブランチ>` はプレースホルダのまま書く）：「一致しない時は、下の確認の前に `git fetch origin <ベースブランチ>:<ベースブランチ>` を1回行う（fast-forward できる時だけローカルのベースブランチの ref を進める非破壊の操作。現在のブランチがベースブランチ自身の時は git がチェックアウト中のブランチへの fetch を拒否するので、一致した時は行わない）。この fetch は best-effort で、失敗しても（ネットワーク不可・リモートが無い・fast-forward できない等）止まらず、そのまま下の確認に進む。」
- 挿入位置：各段落の「一致すればベースブランチ上とみなす。」の直後（その次の「一致しなくても、」の直前）。間に空白や改行を入れない（段落は1行のまま）
- 置換：各段落の「（ローカルのベースブランチの ref とだけ比べる。`origin/<ベース>` との比較や fetch はしない）」を「（ローカルのベースブランチの ref とだけ比べる。`origin/<ベース>` とは比べない）」に置き換える。この2か所以外の文言は変えない
- ベースブランチ上（一致した時）は fetch を行わない。fetch の成否で分岐する手順（失敗したらメッセージを出す等）は書かない
- `git fetch` は `.claude/settings.json` の許可リストの `Bash(git *)` で通り、deny に当たらないことを計画時に確認済み。`.claude/settings.json` は変えない
- `scripts/smoke.sh` と `tests/` に該当文言を検査するものは無い（計画時に確認済み）ので、smoke は変えない
- `docs/vault-spec.md`・`docs/decisions.md` の記述は T-02 で直す。このタスクでは触らない
- 実際に `git fetch` を実行して動作を試す必要は無い（ネットワークに依存するため、確認は文言で行う）
