# T-03 vault-spec.md の11〜12節を3つの判定に合わせ、提案ファイル方式・改ざん防止の記述を消す

## 目的
`docs/vault-spec.md` の 11節（ルール）と 12節（agent_write_guard）を、T-01 の後の `agent_write_guard.py`（3つの判定と worktree への委譲だけ）に合わせる（D-015 フェーズ3）。

## 入力
- `vault/designs/D-015.md` の「決定事項」の表と「フェーズ3」
- `.claude/hooks/agent_write_guard.py`（T-01 の後の版。実際の値・順序はコードを正とする）
- `vault/tasks/P-20261009-guard-three-checks/T-01.md` の「決定済み」（3つの判定と委譲の仕様）
- `docs/vault-spec.md` の 11節・12節（270〜372行目あたり）

## 成果物
- `docs/vault-spec.md`（1ファイル。11節と12節だけを変える）

## 受け入れ基準
- `docs/vault-spec.md` に「提案ファイル」と「改ざん防止」の語が無い。確認：`grep -c "提案ファイル" docs/vault-spec.md` が `0`、`grep -c "改ざん防止" docs/vault-spec.md` が `0`
- 12節の見出しが `## 12. agent_write_guard フックの判定` で、判定表に (a)(b)(c) の3行がある。確認：`grep -c '^## 12\. agent_write_guard フックの判定$' docs/vault-spec.md` が `1`、`sed -n '/^## 12\./,/^## 13\./p' docs/vault-spec.md | grep -cE '^\| \((a|b|c)\) '` が `3`
- 12節に削った判定の説明が残っていない。確認：`sed -n '/^## 12\./,/^## 13\./p' docs/vault-spec.md | grep -cE 'bash_write_targets|analyze_bash_writes|gh api|ALLOWED|transcript_path|DENIED_FOR_CREATOR'` が `0`
- 11節の小節が「ディレクトリと振り分け」「ルールと受け入れ基準の関係」の2つだけで、会話記録の人の発言の判定の説明が無い。確認：`sed -n '/^## 11\./,/^## 12\./p' docs/vault-spec.md | grep -c '^### '` が `2`、`grep -c "人の発言" docs/vault-spec.md` が `0`
- smoke 全体（参照切れの検査を含む）が通る。確認：`bash scripts/smoke.sh 2>&1 | tail -1` が `fail=0` を含む

## 決定済み
- 11節：「### 改ざん防止」の小節を消す。代わりに11節の冒頭の段落か「ディレクトリと振り分け」に、エージェントも `vault/rules/` に書き込めること、変更は PR の差分で人が見ること（D-015）を1〜2文で書く。`vault/rules/` のディレクトリと `scripts/rules.sh` は残る（導入先のルールの置き場）
- 12節の見出しを `## 12. agent_write_guard フックの判定` にする（この文字列を書くこと）。冒頭に、判定は3つだけで、agent_type は (c) だけが見ることを書く
- 12節の判定表は、行の先頭を `| (a) `・`| (b) `・`| (c) ` にする（この形を書くこと）。列は「判定 | 対象 | 結果」のような3列でよい。中身は T-01 の「決定済み」と実装に合わせる
  - (a)：Write・Edit・MultiEdit・NotebookEdit の書き込み先が `vault/tasks/<計画ID>/<id>.md` か `vault/verdicts/<計画ID>/<id>.json` で、計画票のタスク表でその id が done → 拒否。agent_type を問わない。計画票が無い・行が無い時は許可。Bash による書き換えは見ない（PR の差分と plan_guard・stop_gate の verdict の検査で見える）
  - (b)：Bash のコマンドを `&&`・`;`・改行で区切った各部分に `git commit`（`git -C . commit` のような前置オプション付きも含む）があり、現在のブランチが `main` → 拒否。正規表現の簡単な判定で、引用符の中などの誤検知は許容する。ブランチが取れない時（detached HEAD など）は素通り
  - (c)：`agent_type` が verifier の Write・Edit・MultiEdit・NotebookEdit で、書き込み先が `vault/verdicts/` の外 → 拒否。verifier の Bash は制限しない
- 12節から消す記述：`vault/rules/` 拒否の行、会話記録への書き込み拒否の行、blocked の解除（`/plan unblock` の会話記録による裏付け）の行と「blocked の解除の裏付けの判定に使う会話記録」の段落、「### 検知範囲：`gh api` / `curl` によるリモート直叩き」の小節、「### Bash の書き込み対象の解析」の小節、「### 提案ファイル方式」の小節、`ALLOWED` 判定（verifier／planner）・creator の拒否の説明
- 12節に、やめた判定を短い箇条書きで残す（なぜやめたかを各1行。D-015 の決定事項の表を要約する）。対象は `vault/rules/` の保護、会話記録への書き込みの拒否、GitHub の API を直接呼ぶリモート書き込みの検知、Bash の書き込み解析、creator・planner の書き込み先の制限、blocked の解除の裏付け。受け入れ基準1・3の grep に当たる語（「提案ファイル」「改ざん防止」「gh api」「ALLOWED」「bash_write_targets」など）はこの箇条書きでも書かない
- 「### worktree への委譲の範囲」の小節は残し、新しい規則に書き直す：Write 系は書き込み先（`file_path`）が worktree の中の時だけ委譲し、外なら委譲せずメインリポジトリの版が判定する。Bash とそのほかのツールは常に委譲する（Bash で残る判定は (b) だけで、`cwd` のブランチを見るため）。`plan_guard.py`・`stop_gate.py` の委譲は今どおり
- 「### サンドボックス（使っていない）」の小節は変えない（フェーズ1 の記述）
- 「フックの共通モジュール」の段落は残し、`_hooklib.py` の関数の説明から会話記録の人の発言とコマンドの一致判定を外す。Bash の書き込み解析を共通モジュールに置かない旨の文も消す（解析そのものが無くなった）
- 10節の「done のタスクの verdict への書き込みは agent_write_guard が拒否する（12節）」は (a) のとおりで正しいので変えない
- 11〜12節の外（2節の「（フックが会話記録で裏付ける）」など）は変えない。D-015 フェーズ5 で直す
- `.claude/hooks/`・`scripts/smoke.sh` は変えない（T-01・T-02 の成果物）
- 文書の中のバッククォートで囲んだパスは、smoke の参照切れの検査が存在を確かめる。存在しないパス（消した提案ファイルのパスなど）をバッククォートで書かない（`<計画ID>` のようなプレースホルダーを含むものは検査されない）
