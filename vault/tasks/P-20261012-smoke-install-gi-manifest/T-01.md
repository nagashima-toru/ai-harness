# T-01 install.sh が導入元の harness-manifest.json を複製しないようにし smoke に回帰テスト (install-gi) 07 を足す

## 目的
導入先で `bash scripts/smoke.sh` を実行すると、導入先自身の `.claude/harness-manifest.json`（`"gitignore": "appended"` を含む）が一時導入先へ複製されて gitignore キーが引き継がれ、(install-gi) 03 が NG になる（Issue #198）。install.sh が導入元の manifest を持ち込まないように直し、再現手順を smoke の回帰テストにする。

## 入力
- GitHub Issue #198（要旨は「決定済み」に写してある。Issue を読みに行かなくてよい）
- `scripts/install.sh` の「# .claude/（settings.json は専用マージャで扱うのでこのループから外す）」の for ループ（find で `settings.local.json`・`settings.json` だけを除外している）と、末尾の manifest 書き込み部の python（既存 manifest の `gitignore` を `prev_gi` として引き継ぐ）
- `scripts/smoke.sh` の「== install.sh の .gitignore ==」節（`gi_mf` 関数と (install-gi) 01〜06）

## 成果物
- `scripts/install.sh`（主な成果物。`.claude/` 複製ループの find に `harness-manifest.json` の除外を足す）
- `scripts/smoke.sh`（付随。回帰テスト (install-gi) 07 を足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | grep -c '^smoke: pass=[0-9]* fail=0'` の出力が `1`
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (install-gi) 07 '` の出力が `1`（導入元の manifest に gitignore キーがあり、`.claude/worktrees/` 行が既にある導入先へ導入した時、導入先の manifest に gitignore キーが無い）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (install-gi) 0[1-6] '` の出力が `6`（既存ケースが番号・期待値そのままで通る）
- `grep -c 'name .harness-manifest.json.' scripts/install.sh` の出力が `1`（`.claude/` 複製ループの find の除外にある）
- `git diff --merge-base work/p-20261012-smoke-install-gi-manifest --name-only -- scripts/install.sh scripts/smoke.sh | grep -c '^scripts/'` の出力が `2`

## 決定済み
- 方針は Issue の提案1で確定：install.sh の `.claude/` 複製ループの find の除外に `! -name 'harness-manifest.json'` を足す（既存の `! -name 'settings.local.json' ! -name 'settings.json'` と同じ書き方で、同じ find の中に並べる）。ループ直前のコメントにも manifest を外す旨（導入元の manifest を導入先へ持ち込まない。manifest は末尾で書く）を一言足してよい。manifest 書き込み部の python（`prev_gi` の引き継ぎ）は変えない。`--update`（導入先に既存 manifest がある）時の挙動は、もともと copy_if_absent で skip されていたので変わらない
- 原因の確認済みの再現手順：一時ディレクトリ S に `printf 'x/\n' > S/.gitignore` してから本体の install.sh で S へ導入（S の manifest に `"gitignore": "appended"` が入る）→ 別の一時ディレクトリ G に `.claude/worktrees/` 行を含む .gitignore を作り、`bash S/scripts/install.sh G` → 修正前は G の manifest に `"gitignore": "appended"` が入る（期待はキー無し）
- 回帰テストはこの再現手順をそのまま smoke で行う。番号は `(install-gi) 07`、置き場所は「== install.sh の .gitignore ==」節の (install-gi) 06 の直後（`rm -rf "$GI1" "$GI2" "$GI3"` の前後どちらでもよい）。一時ディレクトリは既存と同じ `smoke_tmpdir` で作り、値は既存の `gi_mf` 関数で取る。期待値は `"appended none"`（前半が S の manifest の gitignore＝フィクスチャが意図どおり、後半が G の manifest の gitignore）とし、`expect_eq` で書く。説明文は `(install-gi) 07 ` で始め、「gitignore キーのある manifest を持つ導入先を導入元にして、行が既にある導入先へ install → キー無し」の趣旨にする
- 後片付けは既存の節と同じ smoke 内の `rm -rf`（smoke 自身の一時ディレクトリの掃除）でよい。受け入れ基準の確認コマンドには `rm -rf` を使っていない
- 既存ケース (install-gi) 01〜06 の番号・期待値・説明文は変えない
- 修正前の install.sh で (install-gi) 07 が NG になることを、creator は手元で一度確かめる（例：install.sh の修正を入れる前にテストだけ足して smoke を流す）。確かめた結果を「進捗」に1行書く
- 文書（`docs/vault-spec.md`・`docs/install.md`）は変えない。vault-spec.md には manifest の記述が無く、install.md の manifest の説明は今回の修正と矛盾しないため
- 本体（ai-harness）には `.claude/harness-manifest.json` が無いので、本体の smoke では修正前でも 03 は通る。07 は S を一度導入してから S を導入元にするので本体でも再現する

## 進捗
- 読んだルール: vault/rules/common/vision.md
- smoke.sh に (install-gi) 07 を追加、修正前の install.sh で NG (got=appended appended) を確認
- install.sh の find に ! -name harness-manifest.json を追加とコメント追記。全受け入れ基準の確認コマンドが期待値どおり(1/1/6/1/2)
