# T-02 scripts/plan_record.py を作り smoke にケースを足す

## 目的
計画一式を除去する前に PR 本文へ写す「計画の記録」（計画票のゴール節・タスク表・`vault/log/<計画ID>.md` の全行）を Markdown で標準出力に出すスクリプト `scripts/plan_record.py` を作る。

## 入力
- `vault/designs/D-016.md` の「フェーズ1」（受け入れ基準の候補・決定済み）
- `scripts/verdict_notes.py`（`repo_root()` の書き方・argparse・docstring の書き方を参考にする）
- `vault/templates/plan.md`（計画票の見出し構成。ゴール節は `# ゴール`）
- `scripts/smoke.sh`（`== verdict_notes.py ==` 節のケースの書き方、T-01 で足した `== purge_plan.sh ==` 節）

## 成果物
- `scripts/plan_record.py`（主な成果物。新規）
- `scripts/smoke.sh`（`== plan_record.py ==` 節を足す）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む
- plan_record.py のケースが6つとも通る。確認：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (prec-[1-6])'` の出力が `6`
- このリポジトリの既存の計画で、出力の1行目が見出しになる。確認：`python3 scripts/plan_record.py P-20261010-harness-improvements-followup | head -1` の出力が `## 計画の記録`
- 同じ計画で、タスク表の7行がそのまま出る。確認：`python3 scripts/plan_record.py P-20261010-harness-improvements-followup | grep -c '^| T-0[1-7] | done | 1 |'` の出力が `7`
- 計画票の無い計画 ID では終了コード1で終わる。確認：`python3 scripts/plan_record.py P-20990101-no-such-plan` の終了コードが `1`、標準出力が空

## 決定済み
- 使い方：`python3 scripts/plan_record.py <計画ID>`。引数の誤り（計画 ID が無い等）は argparse の既定で終了コード2。読み込み先のルートは `scripts/verdict_notes.py` の `repo_root()` と同じ（カレントディレクトリの `git rev-parse --show-toplevel`、取れなければカレントディレクトリ）。ファイルには書き込まない
- 読むもの：`<ルート>/vault/plans/<計画ID>.md` と `<ルート>/vault/log/<計画ID>.md`。どちらかが無ければ、無いもの1つにつき `plan_record.py: 見つかりません: <パス>` を標準エラーに出し、標準出力には何も出さずに終了コード1
- 出力の形（この順・この見出し。見出しの前後の空行もこのとおり。末尾は改行1つ）：
  ```
  ## 計画の記録

  ### ゴール
  <ゴール節の本文>

  ### タスク表
  <タスク表の行>

  ### log
  <details>
  <summary>log の全行</summary>

  <log の全行>

  </details>
  ```
- ゴール節の本文：計画票で `# ゴール` か `## ゴール`（前後の空白は無視）の行の次の行から、次の見出し行（`#` が1〜6個と空白で始まる行）の前までを、前後の空行を除いてそのまま出す。見出しが無い・本文が空なら `（なし）` の1行
- タスク表の行：計画票で最初に現れる、行頭の空白を除いて `|` で始まり第1列が `id`・第2列が `status` の行（見出し行）から、行頭の空白を除いて `|` で始まる行が続く限りを、書き換えずにそのまま出す（見出し行と区切り行を含む）。見出し行が無ければ `（なし）` の1行
- log の全行：log ファイルの中身を書き換えずにそのまま出す（遷移行以外の記録行・空行も含む。末尾の改行は1つに揃えてよい）。log が空ファイルなら `<summary>` の後の空行と `</details>` の前の空行の間に何も無い形でよい
- 文字コードは UTF-8 で読み書きする
- docstring に、使い方・出力の形・終了コード（0 出力した／1 計画票か log が無い／2 引数の誤り）・「ファイルに書き込まない」を書く
- smoke のケース（名前は `(prec-<番号>)` で始め、どれも1ケース1行の `ok`/`NG` を `expect_eq` で出す）。一時ディレクトリは smoke の `$TMP` の下（または `smoke_tmpdir`）に作り、`vault/plans/P-20990101-pr.md`（ゴール節2行・`## 分割方針`・タスク表2行）と `vault/log/P-20990101-pr.md`（遷移行2行と `worktree path=...` の記録行1行）を置いて、そのディレクトリで実行する
  - `(prec-1)` 出力全体が上の形どおりの期待値と完全に一致する（ゴール2行・表の見出し行・区切り行・2行・log 3行）
  - `(prec-2)` ゴール節に `## 分割方針` 以降の行が混ざらない（`(prec-1)` と別に、分割方針の本文の語が出力に無いことを確かめる）
  - `(prec-3)` log の遷移行以外の行（`worktree path=...`）もそのまま出る
  - `(prec-4)` 計画票が無い計画 ID：終了コード1・標準出力が空・標準エラーに `plan_record.py: 見つかりません: ` を含む
  - `(prec-5)` log が無い：終了コード1・標準出力が空
  - `(prec-6)` 引数なし：終了コード2
  - 実行の後、一時ディレクトリの中のファイルが増えていない・変わっていないこと（書き込まないこと）を `(prec-1)` か別の確認に含めてよい（ケースの数は6つのまま）
- smoke の節は T-01 の `== purge_plan.sh ==` 節の後に `echo "== plan_record.py =="` で足す（`== archive_plans.sh ==` 節の中には混ぜない）
- `scripts/` 直下に置くので `install.sh` の配布対象に自動で入る（`SCRIPTS_EXCLUDE` は触らない）。`scripts/pr_body.py`・`scripts/verdict_notes.py` は変えない。文書（`docs/`・スキル）はこのタスクでは変えない（T-03・T-04 が行う）
