# T-02 vault-spec と run SKILL に引き継ぎの取り込みと新規コミットの判定を書く

## 目的
仕様の正本 `docs/vault-spec.md` と `.claude/skills/run/SKILL.md` に、`--resume-worktree` が worktree に計画ブランチを取り込むこと（マージコミットの件名、出力の `plan_head` が worktree の内容と一致すること）と、新規コミットの判定がマージコミットを数えないこと（T-01 で transition.py に入れる動き）を書く。

## 入力
- `docs/vault-spec.md`（1節の証跡の段落（22行目付近）、2節の review の項（69行目付近）・done の項（70行目付近）・引き継ぎ（`--resume-worktree`）の項（74行目付近））
- `.claude/skills/run/SKILL.md`（手順3の1（66行目付近））
- `scripts/transition.py` の `resume_worktree`・`count_new_commits`（読むだけ。T-01 で `count_new_commits` に `--no-merges` が入る）
- 計画票の「分割方針」（Issue #208 の要旨）

## 成果物
- `docs/vault-spec.md`（主な成果物）
- `.claude/skills/run/SKILL.md`

## 受け入れ基準
- `grep -c 'git rev-list --no-merges .plan-head....branch.' docs/vault-spec.md` の出力が `1` である（2節の review の (2) の判定の式）
- `grep -c 'マージコミットは数えない' docs/vault-spec.md` の出力が `1` である
- `git grep -n 'rev-list .plan-head' -- . ':!vault'` の出力が空である（`--no-merges` の無い旧い判定の式がリポジトリに残っていない）
- `grep -c '計画ブランチを取り込み' docs/vault-spec.md` の出力が `2` である（1節の証跡のコミットの種類と、2節の引き継ぎの項 (2) の件名）
- `grep -c '取り込んだ計画ブランチの HEAD' .claude/skills/run/SKILL.md` の出力が `1` である（手順3の1）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1` である
- `git diff --merge-base work/p-20261017-resume-worktree-sync --name-only` の出力に `docs/vault-spec.md` と `.claude/skills/run/SKILL.md` の両方の行がある

## 決定済み
- vault-spec 2節の review の項の (2) は、次の文に置き換える：「(2) 新規コミットの判定：`git rev-list --no-merges <plan-head>..<branch>` が0件なら doing→blocked にして worktree を残す（マージコミットは数えない。`--resume-worktree` の取り込みのマージコミットだけでは新規コミットにならない）」。(1)・(3)・(4) は変えない
- vault-spec 2節の done の項の「新規コミットの判定（0件なら review→blocked）」は「新規コミットの判定（review の (2) と同じ式。0件なら review→blocked）」にする。「マージコミットは数えない」の語は review の項の1か所だけに書く（受け入れ基準2が `1` を見るため）
- vault-spec 2節の引き継ぎの項の (2) は「H が worktree のブランチの祖先でなければ worktree の中で `git merge --no-ff H -m "<計画ID>/<id>: 計画ブランチを取り込み"` を行う」とし、その後ろに「取り込んだ後の worktree は H の内容を含むので、出力の `plan_head=<H>` からの差分は自タスクの変更だけになる（待機中に計画ブランチへ入った他タスクの変更が宣言外の変更に見えない）」の趣旨の1文を足す。衝突時に終了コード 5 で何も変えない、という今の記述は変えない
- vault-spec 1節の証跡の段落（22行目付近）の git の履歴の列挙に、worktree 側の収集コミットの後ろへ「worktree 側の取り込みのマージコミット（`--resume-worktree` が作る `<計画ID>/<id>: 計画ブランチを取り込み`）」を足す。`計画ブランチを取り込み` の語は vault-spec 全体でこの1か所と引き継ぎの項 (2) の1か所の計2か所にする
- run SKILL 手順3の1の「ただし手順2で引き継いだ id の `PLAN_HEAD` は、この HEAD ではなく `--resume-worktree` の標準出力の `plan_head` を使う」の `plan_head` の直後に「（transition.py が worktree に取り込んだ計画ブランチの HEAD。worktree の内容と一致する）」を足す。run SKILL のほかの箇所は変えない
- 受け入れ基準3で `vault/` を除くのは、この計画の計画票・タスク票が旧い式を説明の文字列として含むため（`vault/` は計画一式の除去で main に入らない）
- 通常の並行実行（同じ組の他タスクが先に done になる場合）の扱いは書かない（計画票の「次フェーズの候補」）
- 新しいファイルは作らない。バッククォートで書くパスは既存のものだけにする（`(ref-1)` のため）
- smoke 全体の実行には数分かかる（タイムアウトは10分を見込む）
