## 目的
1セッション1計画1ブランチの前提で、ブランチ・コミット・PR・破棄の運用を定める。

## ルール
- ブランチは `/plan` 実行時に計画ごとに1つだけ切る（`work/<計画IDの英小文字>`）。1ブランチ=1計画で、作業はそのブランチに閉じる
- コミットは作業ステップごとに小さく分けて行う（例：タスクの成果物ができた時、状態遷移を書いた時）。1タスクの作業を1コミットにまとめない
- `main` へ直接コミットしない。すべてのコミットは計画のブランチ上で行う（`agent_write_guard.py` がフックで強制する）
- 全タスクが `done` になったら `gh pr create` までを行う。マージは人が行い、エージェントは `gh pr merge` を実行しない
- 変更を破棄する時は `git restore` のみを使う。`git clean` / `git reset --hard` は使わない（`.claude/settings.json` の `permissions.deny` で拒否済み）
- コンフリクトが起きたら自己判断で解決せず、計画票のタスク表の該当タスクを `blocked` にして question に状況を書き、人の判断を仰ぐ

## 確認方法
- `bash scripts/rules.sh creator`（および `verifier`・`planner`）の出力に `vault/rules/common/git.md` が含まれるか
- 各行が真偽で判定できるか（ブランチが1計画1本か、コミットが作業ステップ単位に分かれているか、`main` に直接コミットしていないか）
