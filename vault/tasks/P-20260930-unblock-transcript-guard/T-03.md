# T-03 /plan スキルに C（/plan unblock による解除）の手順を追加する

## 目的
フック（T-01・T-02）が「人の `/plan unblock` の指示」を裏付けに blocked の解除を許可するので、スキルにその手順を用意する。解除の窓口を `/plan unblock` に一本化する（D-010 フェーズ5）。

## 入力
- `vault/designs/D-010.md` フェーズ5（ゴール文・決定済み）
- `.claude/skills/plan/SKILL.md`（frontmatter、A・B 節、注意節）。B 節の形式を手本にする
- `docs/runbook.md` 4節（現行の解除手順）

## 成果物
- `.claude/skills/plan/SKILL.md` の変更（1ファイル）

## 受け入れ基準
- `## C` の見出しで解除の節があり、引数が `unblock <計画ID> <id> [回答]` のコマンドで来たことの確認（自然文の解除は受け付けず、`/plan unblock <計画ID> <id> [回答]` を打つよう案内して止まる）が最初の手順にある。確認：`grep -n '^## C' .claude/skills/plan/SKILL.md` がヒットし、`grep -n '自然文' .claude/skills/plan/SKILL.md` が C 節内にもヒットする
- C 節が、対象行が `blocked` であることの確認（違えば解除せず状況を伝えて止まる）、回答があればタスク票の「決定済み」への追記、行の status を `todo`・attempt を `0`・question を空にする手順を書いている（目視で確認）
- C 節が `- <日時> <id> blocked→todo 人の指示: /plan unblock <計画ID> <id>` の log 追記（日時は `TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M'`）と、ファイルを名前で指定した `git add`・`git commit` の手順を書いている。確認：`grep -n 'blocked→todo 人の指示: /plan unblock' .claude/skills/plan/SKILL.md` がヒットする
- frontmatter の description に解除（unblock）でも使う旨があり、`argument-hint` が `[ゴール | approve <計画ID> | unblock <計画ID> <id> [回答]]` である。確認：`grep -n 'unblock' .claude/skills/plan/SKILL.md | head -3` に description と argument-hint の行が含まれる
- A・B 節と注意節の手順の意味が変わっていない。確認：`git diff -- .claude/skills/plan/SKILL.md | grep -E '^-[^-]'` の出力が、description・argument-hint・冒頭の説明文の行に収まることを目視で確認する

## 決定済み
- 手順の順序：(1) 引数が `unblock <計画ID> <id>` のコマンドで来たことを確認する（自然文は案内して止まる）。(2) 計画票のタスク表で対象行が `blocked` であることを確認する。(3) 回答があればタスク票 `vault/tasks/<計画ID>/<id>.md` の「決定済み」に追記する。回答が無い時は何も追記しない（ハングやマージコンフリクトなど、答える質問が無い blocked）。(4) 計画票の対象行の status を `todo`、attempt を `0`、question を空にする。(5) log に上記の1行を追記する。(6) `git add vault/plans/<計画ID>.md vault/tasks/<計画ID>/<id>.md vault/log/<計画ID>.md` と `git commit`（メッセージ例：`<計画ID>: <id> の blocked を解除する`）を行う（回答が無く、タスク票を変えなかった時は、タスク票を add に含めない）。(7) 解除したことを報告し、「`/run` で再開できます」と伝える
- 1回のコマンドで解除するのは1行だけ。複数行を解除する時は、人がコマンドを行の数だけ打つ旨をスキルに書く
- 回答の内容でタスク票の受け入れ基準を直す必要がある時は、回答に基づく追記までにとどめ、大きな書き換えは planner を呼ぶよう案内する（勝手に広げない）
- コミットは work ブランチ上で行う。`git add .`・`git add -A` は使わない
- 解除の log 行はタスク ID の位置に `<id>` を入れる（承認の行の `-` とは違う）
- description のトリガー語に「blocked を解除」などを足してよい。自然文でトリガーされた場合は、コマンドを打つよう案内する動きになる
- スキルの `name` は変えない。承認済み計画の差し戻しは扱わない
