# T-03 purge_plan.sh --merged のマージ済み判定をベースブランチの版で行う

## 目的
`scripts/purge_plan.sh --merged` の条件5（`main` の版の計画票も `status: done`）を、ベースブランチ（`HARNESS_BASE_BRANCH` の値、前後の空白を除いて空なら `main`）の版で判定するようにする。未設定なら今の動作を変えない。

## 入力
- `scripts/purge_plan.sh`
- `vault/designs/D-20261010-base-branch-config.md`（「決定事項」と「フェーズ1」の「決定済み」）
- `scripts/smoke.sh` の `== purge_plan.sh --merged ==` 節と `(hooklib-rules)` の purge_plan のケース（既存のケース。このタスクでは変えない）

## 成果物
- `scripts/purge_plan.sh`（1ファイル）

## 受け入れ基準
- マージ済み判定がベースブランチの版を読む：`grep -cF 'git show "$BASE_BRANCH:vault/plans/$pid.md"' scripts/purge_plan.sh` が `1`
- 固定の `main` が残っていない：`grep -cE '"main:vault|main にマージ済み|main の vault/plans|ブランチが main かどうか' scripts/purge_plan.sh` が `0`
- 値の読み方が前後の空白を除いて空なら `main`：`grep -cF '[ -n "$BASE_BRANCH" ] || BASE_BRANCH=main' scripts/purge_plan.sh` が `1`
- 別名のベースを指定しても既存の動作が壊れない：`env HARNESS_BASE_BRANCH=develop bash scripts/purge_plan.sh --merged --list` が終了コード0で終わる（このリポジトリに develop ブランチが無くてもエラーにしない）
- 既定のままの既存動作が変わらない（pm-1〜pm-6 と hooklib-rules を含む）：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 値の読み方は、`set -u`・`export LC_ALL=C` の後のトップレベルで次の4行をそのまま書く（変数名は `BASE_BRANCH`。値の形式は検査しない）：
  ```
  BASE_BRANCH="${HARNESS_BASE_BRANCH:-}"
  BASE_BRANCH="${BASE_BRANCH#"${BASE_BRANCH%%[![:space:]]*}"}"
  BASE_BRANCH="${BASE_BRANCH%"${BASE_BRANCH##*[![:space:]]}"}"
  [ -n "$BASE_BRANCH" ] || BASE_BRANCH=main
  ```
- 条件5の行は `mst="$(git show "$BASE_BRANCH:vault/plans/$pid.md" 2>/dev/null | fm_status)"` にする。ベースブランチが存在しない・その版が無い時は、今の main と同じく対象外（エラーにしない）
- 冒頭コメントの `--merged: main にマージ済みの…`・条件5の `main の vault/plans/<計画ID>.md …（main が無い・その版が無い時は対象外）`・`現在のブランチが main かどうかは検査しない` は、「ベースブランチ（HARNESS_BASE_BRANCH、前後の空白を除いて空なら main）」に言い換える（受け入れ基準の正規表現が当たる字句を残さない）
- `--merged` 以外（通常の除去・`--dry-run`）の条件と、`--apply` が現在のブランチを検査しないことは変えない
- `scripts/smoke.sh` はこのタスクでは変えない（develop の版で判定するケースは T-06 で足す）
- 確認コマンドの `--merged --list` は何も変えない（削除はしない）
