# T-01 状態遷移ルールの記述を ai-harness.md と vault-spec.md で書き換える

## 目的
「`doing` は計画内で常に1件だけ」という前提を、「`doing`/`review` は `after` 依存の無い集合（着手可能集合）に限り複数件になりうるが、計画票・ログへの書き込みは常にオーケストレーター1プロセスに集約する」という前提に、`.claude/ai-harness.md` と `docs/vault-spec.md` の両方で書き換える。

## 入力
- `.claude/ai-harness.md`（「状態遷移」節）
- `docs/vault-spec.md`（2節の状態表、9節 Stop フックの判定表、10節 plan_guard フックの判定）
- `vault/designs/D-003.md`（冒頭「決定事項」表の1行目、および「フェーズ1」の「ゴール文」「決定済み」）

## 成果物
- `.claude/ai-harness.md` の「状態遷移」節の書き換え
- `docs/vault-spec.md` の2節・9節・10節の書き換え
（コードは変更しない。1PR として扱う）

## 受け入れ基準
- `grep -c "常に1件" .claude/ai-harness.md docs/vault-spec.md` の合計が0（doing が常に1件という前提の文言が両ファイルから消えている）
- `.claude/ai-harness.md` に「着手可能集合」と「オーケストレーター1プロセス」の語句を含む行がそれぞれ1行以上ある。確認: `grep -c "着手可能集合" .claude/ai-harness.md` と `grep -c "オーケストレーター1プロセス" .claude/ai-harness.md` がいずれも1以上
- `docs/vault-spec.md` の2節（状態表）にも「着手可能集合」の語句がある。確認: `grep -c "着手可能集合" docs/vault-spec.md` が1以上
- `docs/vault-spec.md` の10節から「doing が2件以上」というブロック条件の記述が消え、`after` 依存関係を根拠にした判定の記述に置き換わっている。確認: `grep -c "doing が2件以上" docs/vault-spec.md` が0 かつ `grep -c "依存関係" docs/vault-spec.md` が1以上
- `docs/vault-spec.md` の9節（Stop フックの判定）に「doing/review の行それぞれ」という語句がある（1件だけでなく全行を検査する前提に更新されている）。確認: `grep -c "doing/review の行それぞれ" docs/vault-spec.md` が1以上

## 決定済み
- 反映すべき内容は D-003 フェーズ1の決定済み事項そのもの：「依存関係が張られている」の判定は、doing/review の行の `after` 列に、まだ `done` になっていない他の doing/review 行の id が含まれるかで見る（後方参照だけでなく doing 同士の相互依存も含む）。この判定方式の説明は T-02（plan_guard.py）の実装で使う語彙と揃える必要はなく、ドキュメント側は前提の説明に留めてよい
- ログ・計画票のフォーマット（列構成・見出し）には触れない。変えるのは状態遷移の許容範囲の文言と、それを検査するロジックの説明だけ
- `HARNESS_MAX_PARALLEL` 環境変数はこのタスクでは導入しない（言及もしない）。フェーズ3で導入する
- 文言は上記の受け入れ基準にある語句（「着手可能集合」「オーケストレーター1プロセス」「依存関係」「doing/review の行それぞれ」）を含めれば、前後の言い回しは自由に書いてよい
- `docs/vault-spec.md` の1節・3〜8節・11〜13節には手を入れない（状態遷移に関係しない節は変更対象外）
