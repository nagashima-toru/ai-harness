# T-02 docs/install.md の scripts/ の配布の説明を固定リストに合わせ、decisions.md に判断を記録する

## 目的
T-01 で `scripts/install.sh` の `scripts/` 直下の配布を固定リスト `SCRIPTS_FILES` に限ったので、導入手順の説明（`docs/install.md`）を実装に合わせ、判断を `docs/decisions.md` に1行で残す。古い記述（検索方式・除外リスト）がリポジトリに残っていないことを確かめる。

## 入力
- `scripts/install.sh`（T-01 の後の実ファイル。冒頭のコメント、`SCRIPTS_FILES` の定義とその直前のコメント）
- `scripts/smoke.sh` の `(inst-scr)` の節（T-01 で足したもの）
- `docs/install.md` の「### 3. ハーネスを複製する」の「複製されるものは」で始まる段落（34行目付近）と「## ハーネスを更新する（2回目以降）」節の箇条（147行目付近の「旧版の install で配布元の独自ファイルが…」）
- `docs/decisions.md` の最終行（#200 の判断。書式の手本）

## 成果物
- `docs/install.md`（主な成果物）
- `docs/decisions.md`（判断の行を末尾に1行足す）

## 受け入れ基準
- `docs/install.md` の「複製されるもの」の段落が scripts/ 直下を固定リストとして説明している（`grep -c '.SCRIPTS_FILES. の固定リスト' docs/install.md` が `1`）
- `docs/install.md` の「ハーネスを更新する」節の旧版の独自ファイルの箇条が独自スクリプトにも触れている（`grep -c '独自スクリプトを含む' docs/install.md` が `1`）
- `docs/decisions.md` に Issue #201 の判断の行がちょうど1行ある（`grep -c 'Issue #201' docs/decisions.md` が `1`）
- 古い記述がリポジトリに残っていない（`grep -rln -e SCRIPTS_EXCLUDE -e 検索方式 -e scripts_list --exclude-dir=.git --exclude-dir=vault --exclude-dir=worktrees .` の出力が空）
- smoke の文書の参照検査が ok（`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`）
- smoke 全体が失敗0件で終わる（`bash scripts/smoke.sh 2>&1 | grep -c '^smoke: pass=[0-9]* fail=0'` が `1`）
- 計画ブランチとの分岐点からの差分に `docs/install.md` と `docs/decisions.md` の両方が含まれる（worktree の中で `git diff --merge-base work/p-20261012-install-scripts-fixed-list --name-only` の出力に両方の行がある）

## 決定済み
- `docs/install.md` の「複製されるもの」の段落の scripts の部分（今の「`scripts/` 配下のスクリプト一式（`scripts/*.sh`・`scripts/*.py` を検索方式で配布する。`scripts/vcs_finish.sh` を含み、除外リストに載ったものだけを除く）」）を、「`scripts/` 直下は `scripts/install.sh` の `SCRIPTS_FILES` の固定リストのスクリプトだけ（`scripts/vcs_finish.sh` を含む。導入済みのリポジトリを配布元にしても、配布元が `scripts/` に独自に置いたスクリプトは配らず、マニフェストにも記録しない）」という趣旨に置き換える。語句「`SCRIPTS_FILES` の固定リスト」（バッククォート付き）をこの段落にちょうど1回書き、ファイルのほかの場所には書かない。21本の名前は列挙しない（install.sh が正本）
- 「ハーネスを更新する（2回目以降）」節の「旧版の install で配布元の独自ファイルが複製・記録されていた導入先では…」の箇条の「独自ファイル」の直後に「（`scripts/` 直下の独自スクリプトを含む）」を足す。語句「独自スクリプトを含む」はこの1か所だけに書く
- ハーネス本体にスクリプトを足す時の `SCRIPTS_FILES` の更新は、導入先の利用者向けの `docs/install.md` には書かない（install.sh のコメントと smoke の `(inst-scr) 06` が担う）
- `docs/decisions.md` は表の末尾に1行だけ足す。書式は既存の行と同じ `| 2026-10-12 | 何を | なぜ |`。「何を」は「`scripts/install.sh` が配る `scripts/` 直下は install.sh 内の固定リスト `SCRIPTS_FILES`（今ある21本）に限り、マニフェスト・`--update` の対象も同じリストにする。旧版で配られた配布元の独自スクリプトは `--update` で削除せず、マニフェストから外すだけにする。ハーネス本体にスクリプトを足し忘れたことは ai-harness 本体での smoke の `(inst-scr) 06` で検出する（Issue #201）（P-20261012-install-scripts-fixed-list）」の趣旨、「なぜ」は「`.claude/` を固定リストにした #200 と同じく、導入済みリポジトリを配布元にすると `find` による列挙が業務用の独自スクリプトまで配り、`--update`・`uninstall.sh` の管理対象にしていた。導入先では利用者が `scripts/` に独自スクリプトを置くので、足し忘れの検出はマニフェストの無いリポジトリ（本体）でだけ行う。導入先の既存資産は消さない（原則8）」の趣旨。語「Issue #201」はこの1行だけに書き、「検索方式」の語は書かない（古い記述の検査に当たるため）
- 古い記述の検査で `vault/` を除くのは、この計画の計画票・タスク票が古い記述（検索方式・`SCRIPTS_EXCLUDE`・`scripts_list`）を引用しているため（計画一式は PR の前に除去される）。`vault/rules/` には該当する記述が無いことを planner が確かめた。`.claude/worktrees/` は creator の作業用 worktree なので除く
- `docs/install.md` は smoke の `(ref-1)` の検査対象。バッククォートで書くパスは実在するもの（`scripts/install.sh`・`scripts/vcs_finish.sh` など）だけにする
- 受け入れ基準の smoke の実行には数分かかる。タイムアウトは長め（600000ms）にしてよい

- 人の回答（計画票「人への質問」）：scripts/ 直下は固定リスト `SCRIPTS_FILES` にする。リスト更新漏れは smoke で検出する（ai-harness 本体でだけ。導入先では省略）。今ある21本すべてを配る。
