# ゴール
`scripts/install.sh` で導入した先に、ハーネスの実行に必要なものが2つ届かない（issue #38）。①`run`/`design` が最終手順で呼ぶ `scripts/vcs_finish.sh` が配られない、②既に `.claude/settings.json` を持つ導入先に、`run` 手順3.6 が前提にしている `worktree.baseRef: "head"` がマージされない。この2件を直す。あわせて `scripts/` の配布を列挙方式から検索方式に変え、「スキル等に書かれた `scripts/<名前>` が導入先にすべてある」ことを smoke で確かめ、同じ種類の配布漏れを機械的に検出できるようにする。

## 決定事項

| 決めたこと | なぜ |
|---|---|
| `scripts/` の配布を、ファイル名の列挙から `scripts/*.sh`・`scripts/*.py` の検索に変える。配らないものは除外リストで明示する（当面は空） | 人の判断（推奨案採用）。hooks・agents・skills と同じ方式にそろえ、スクリプトを足した時に列挙を直し忘れる構造そのものをなくす |
| smoke に「導入先の `.claude/`・`vault/rules/`・`vault/templates/`・`docs/vault-spec.md`・`CLAUDE.md` に書かれた `scripts/<名前>.sh|py` が、すべて導入先に存在する」ことを調べるケースを足す | 配布漏れを、設計・計画・検証の範囲の外でも機械的に検出するため。検索方式にしても、除外リストの誤りや別ディレクトリへの参照は漏れうる |
| `worktree.baseRef` は、導入先の settings.json に無い時だけハーネス側の値（`"head"`）を足す。別の値が入っている時は上書きせず、`note` で「`run` が blocked になる」旨を案内する | 人の判断（推奨案採用）。利用者の設定を黙って変えない。既存の hooks・deny のマージと同じ「足すだけ・消さない」方針 |
| uninstall では `worktree.baseRef` を取り除かない。`docs/install.md` に「残る」旨を注記する | 人の判断（推奨案採用）。利用者が自分で設定した値と区別できない。残っても害は小さい |
| `vault/templates/design.md` に「導入先への影響」欄は足さない | 人の判断（推奨案採用）。smoke の参照チェックで機械的に検出できるので、ルールは増やさない |
| 2フェーズに分ける。フェーズ1＝scripts の配布（検索方式・参照チェック）、フェーズ2＝settings.json の `worktree.baseRef` マージ | 触るファイルが分かれており（install.sh 系と merge_settings_json.py 系）、どちらも単体で main にマージして動く |

## 依存関係
フェーズ1とフェーズ2は独立。どちらから着手してもよく、並行も可能（ただし両方が `scripts/smoke.sh` と `docs/install.md` を編集するので、後から着手する方は先の方が main にマージされてからブランチを切る）。

## フェーズ1 scripts の配布を検索方式にし、参照漏れを smoke で検出する

### ゴール文
`scripts/install.sh` の `scripts/` の配布を、ファイル名の列挙から `scripts/*.sh` と `scripts/*.py` の検索に変える。変更箇所は `manifest_paths()`（マニフェストと `--update` の対象）と、通常の複製（`copy_if_absent` の呼び出し）の両方。配らないスクリプトは install.sh 内の除外リスト（当面は空）で明示できるようにする。これで現在配られていない `scripts/vcs_finish.sh` も配られる。`scripts/smoke.sh` には、新規ディレクトリへ install した結果について、導入先の `.claude/`・`vault/rules/`・`vault/templates/`・`docs/vault-spec.md`・`CLAUDE.md` に書かれた `scripts/<名前>.sh` / `scripts/<名前>.py` がすべて導入先に存在することを調べるケースを足す。`scripts/install.sh` 冒頭の「複製するもの」コメントと、`docs/install.md` の配布物の説明（34行目付近の列挙、116行目付近の `git add` 例）も実態に合わせる。

### 受け入れ基準の候補
- 新規ディレクトリへ `bash scripts/install.sh <target>` を実行すると、リポジトリの `scripts/*.sh`・`scripts/*.py` がすべて `<target>/scripts/` に配置される。確認：`T=$(mktemp -d); bash scripts/install.sh "$T" >/dev/null; for f in scripts/*.sh scripts/*.py; do test -f "$T/$f" || echo "missing $f"; done` が何も出力しない
- 同じ実行で `<target>/.claude/harness-manifest.json` の `files` に `scripts/vcs_finish.sh` が sha256 付きで載る。確認：`python3 -c "import json,re;d=json.load(open('$T/.claude/harness-manifest.json'))['files'];print(bool(re.fullmatch('[0-9a-f]{64}',d.get('scripts/vcs_finish.sh',''))))"` が `True`
- `scripts/install.sh` から、スクリプト名を1つずつ書いた `copy_if_absent "$SRC/scripts/<名前>"` の行が無くなっている。確認：`grep -cE 'copy_if_absent "\$SRC/scripts/[a-z_]+\.(sh|py)"' scripts/install.sh` が `0`
- `scripts/smoke.sh` に参照チェックのケースがあり、配布漏れがあると NG になる。確認：`bash scripts/smoke.sh | grep -c '参照される scripts'` が1以上で ok になっており、install.sh の除外リストに一時的に `vcs_finish.sh` を入れて smoke を実行するとそのケースが NG になる（確認後に元へ戻す）
- `docs/install.md` の配布物の説明に `scripts/vcs_finish.sh` が含まれる（または「`scripts/` 配下のスクリプト一式」のように検索方式を反映した表現になっている）。確認：`grep -n "vcs_finish\|scripts/ 配下" docs/install.md` がヒットする
- `bash scripts/smoke.sh | tail -1` が `fail=0` で終わる

### 決定済み
- 検索の対象は `scripts/` 直下の `*.sh` と `*.py` だけ（サブディレクトリは見ない）。`manifest_paths()` では既存の hooks 等と同じく `find scripts -maxdepth 1 -type f \( -name '*.sh' -o -name '*.py' \)` の形でよい
- 除外リストは install.sh 内のシェル変数（例：`SCRIPTS_EXCLUDE=""`、スペース区切りのファイル名）として持つ。`manifest_paths()` と通常の複製の両方が同じ変数を見る。当面は空
- 通常の複製では、検索した各ファイルに対して既存の `copy_if_absent` を呼ぶ（上書きしない挙動は変えない）
- `docs/vault-spec.md` の配布は今までどおり（列挙のまま）。今回変えるのは `scripts/` だけ
- 参照チェックの検索パターンは `scripts/[A-Za-z0-9_.-]+\.(sh|py)`。対象は導入先の `.claude/`（`settings.json` を含む）・`vault/rules/`・`vault/templates/`・`docs/vault-spec.md`・`CLAUDE.md`。見つかった名前を重複除去し、それぞれ `<target>/scripts/<名前>` の存在を確かめる。1件でも欠けていれば NG にし、欠けた名前を出力する
- smoke のケース名には「参照される scripts」を含める（受け入れ基準の grep に合わせる）。書式は既存の `expect_eq` と同じ `  ok   <名前>` / `  NG   <名前> ...`
- 参照チェックは install.sh を実行する ai-harness 本体のリポジトリでも、導入先で smoke を実行した時でも動くようにする（`$ROOT/scripts/install.sh` を一時ディレクトリへ実行する既存ケースと同じ作法）
- `scripts/uninstall.sh` はマニフェスト駆動なので変更しない
- `docs/install.md` 116行目付近の `git add` 例は、`scripts/rules.sh scripts/smoke.sh` の列挙を `scripts/` に置き換える
- `.claude/settings.json` の `worktree.baseRef` はフェーズ2で扱う。このフェーズでは触れない

## フェーズ2 settings.json の worktree.baseRef をマージする

### ゴール文
`scripts/merge_settings_json.py` に、ハーネス側 settings.json の `worktree.baseRef` を導入先にマージする処理を足す。導入先に `worktree.baseRef` が無ければハーネス側の値（`"head"`）を足してマージ扱いにする。同じ値が既にあれば何もしない。別の値が入っていれば上書きせず、標準出力に `note` 行で「`worktree.baseRef` が `<値>` のため `run` の worktree が計画ブランチから分岐せず blocked になる。`"head"` にすること」という趣旨の案内を出す。`scripts/unmerge_settings_json.py` は変更しない（`worktree.baseRef` は uninstall で残す）。`scripts/smoke.sh` にこの3通りのケースを足し、`docs/install.md` の settings.json の説明（142行目付近のマージ内容、164行目付近の uninstall の説明）と `scripts/install.sh` 冒頭コメントを更新する。

### 受け入れ基準の候補
- `worktree` キーを持たない settings.json に対して `python3 scripts/merge_settings_json.py .claude/settings.json <dst>` を実行すると、`<dst>` の `worktree.baseRef` が `"head"` になり、出力が `merge <dst>` になる。確認：smoke の該当ケースが ok
- `worktree.baseRef` が `"fresh"` の settings.json に対して実行すると、値は `"fresh"` のまま変わらず、出力に `note` で始まり `worktree.baseRef` を含む行が出る。確認：smoke の該当ケースが ok
- `worktree.baseRef` が既に `"head"` で、hooks・deny も揃っている settings.json に対して実行すると、出力が `skip <dst>` になりファイルが書き換わらない。確認：smoke の該当ケースが ok
- 利用者が足した `permissions.allow` と `worktree` 配下の他のキーは、マージ後も残っている。確認：smoke の該当ケースが ok
- `scripts/unmerge_settings_json.py` に差分が無い。確認：`git diff main -- scripts/unmerge_settings_json.py` が空
- `docs/install.md` に、settings.json のマージ対象に `worktree.baseRef` が含まれることと、uninstall では残ることが書かれている。確認：`grep -c "worktree.baseRef" docs/install.md` が2以上
- `bash scripts/smoke.sh | tail -1` が `fail=0` で終わる

### 決定済み
- 対象はトップレベルの `worktree` 配下の `baseRef` だけ。ほかのトップレベルキーを汎用的にマージする仕組みは作らない
- ハーネス側（src）に `worktree.baseRef` が無ければ何もしない（今の src には `"head"` がある）
- 導入先の `worktree` がオブジェクトでない（配列・文字列など）場合は触らず、`note` で型が不正な旨を出す。終了コードは0のまま（hooks/deny の型不正は既存どおり非0で終わる。それとは扱いを分ける）
- 別の値が入っている時の `note` 行は変更の有無の判定に含めない（それだけなら `skip`）。`note` は `merge`/`skip`/`create` の行より前に出す
- dst が存在しない時は今までどおり src を丸ごと書く（`worktree.baseRef` も入る）。この経路は変えない
- `install.sh` は `merge_settings_json.py` の出力をそのまま表示しているので、`note` 行は install の出力にもそのまま出る。install.sh 側の変更はコメントだけ
- `docs/install.md` 109行目付近の「`.claude/settings.json` は自動マージされない」という記述は、現在の実装（自動マージする）と矛盾しているので、このフェーズで実態に合わせて直す
- smoke のケースは既存の「== merge_settings_json.py ==」節に足す。一時ファイルの作り方は既存ケース（`$STMP` 配下に python で settings.json を書く）と同じ
