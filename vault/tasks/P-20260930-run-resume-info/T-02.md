# T-02 run SKILL.md 手順3に worktree 記録行の追記手順を足し「永続化は不要」を削除する

## 目的
オーケストレーターが creator の完了時に受け取る worktree のパス・ブランチ名と `PLAN_HEAD` を log に記録し、セッションが途切れても再開に使えるようにする（D-010 フェーズ6、issue #78）。

## 入力
- `.claude/skills/run/SKILL.md` 手順3（特に3.1・3.4・3.7）
- `docs/vault-spec.md` 7節（T-01 で追記した記録行の書式）
- `vault/designs/D-010.md` フェーズ6のゴール文と決定済み

## 成果物
- `.claude/skills/run/SKILL.md` の変更（1ファイル。手順3の範囲）

## 受け入れ基準
- 手順3に、記録行 `- <日時> <id> worktree path=<パス> branch=<ブランチ名> plan_head=<sha>` を `vault/log/<計画ID>.md` へ追記する手順がある。確認：`grep -n 'plan_head=' .claude/skills/run/SKILL.md` がヒットする
- 手順3.4の「ファイルへの永続化は不要」という記述が削除されている。確認：`grep -n '永続化は不要' .claude/skills/run/SKILL.md` がヒットしない
- 追記の時点が「手順3.7で creator の完了報告を受けた直後」で、タスクごとに1行、複数タスクは手順3の中でまとめて追記すると書かれている。確認：`grep -n 'plan_head=' .claude/skills/run/SKILL.md` の行が手順3の範囲にあり、内容を目視で確認する
- 変更が手順3の範囲に収まっている。確認：`git diff -- .claude/skills/run/SKILL.md` の `@@` 行が手順3（`## 3.` から `## 4.` の手前）に収まることを目視で確認する
- `bash scripts/smoke.sh` の最終行が `fail=0` になる

## 決定済み
- 検査対象ファイルの範囲：変更してよいのは `.claude/skills/run/SKILL.md` と、このタスク票自身（`vault/tasks/P-20260930-run-resume-info/T-02.md` の「進捗」）だけ。宣言外ファイルの変更は verifier が `git status --porcelain` で検査する（`vault/log/`・`vault/verdicts/`・計画票は run が更新するので除外）。手順2.2（T-03 の担当）・「ハング時の復旧」節・`.claude/settings.json`・フック（`.claude/hooks/`）は変更しない
- 記録行の書式は T-01 で `docs/vault-spec.md` 7節に書いたものと一致させる。`plan_head=` の値は手順3.1で控えた `PLAN_HEAD` の完全な sha
- 追記は creator の完了報告の受領直後（手順3.7）。blocked 報告のタスクも worktree があれば記録してよいが、必須にしない。書くなら「blocked 以外のタスク」でなく「creator の完了報告を受けたタスク」と一般に書く（blocked の場合の worktree は温存されるため、記録があると人が調べやすい）
- 3.4 は「返る worktree のパス・ブランチ名をタスク ID に紐づけて保持する」までを残し、「永続化は不要」の括弧書きだけを消す。log に記録する旨を代わりに書く（3.4 か 3.7 のどちらに書くかは任せる）
- 手順3.5〜3.6（分岐元の確認）・手順3.8（blocked の書き込み）の内容は変えない
- log への書き込みはオーケストレーターだけ（creator は log に書かない）。この記録行の追記後のコミットは新たに要求しない（次の手順4の review 化のコミットに含まれる）
- stop_gate.py・plan_guard.py は log を読まないので変更しない
