# T-06 verifier.md の手順10を「worktree の変更は verifier の前にコミット済み」の前提に直す

## 目的
run が review の時に `scripts/transition.py` で worktree の未コミット分を収集コミットするようになった（T-02）ので、`.claude/agents/verifier.md` の手順10（宣言外ファイルの検査）の「未コミット分は PASS の後にオーケストレーターがまとめてコミットするため、worktree にはコミット済みと未コミットの変更が両方ありうる」という前提を、「worktree の変更は verifier を呼ぶ前にコミット済み」に直す。

## 決定済み
- 手順10の新しい前提の文は、次の文をこのまま入れる：「worktree の変更は、verifier を呼ぶ前にオーケストレーターが `scripts/transition.py` の review でコミット済みである（creator のコミットと、未コミット分の収集コミット）。」（基準2はこの文の `verifier を呼ぶ前にオーケストレーターが` を数える）
- 変更ファイルの一覧は `git diff --name-only <起点コミット>..HEAD`（worktree で実行する。`git -C <path> ...` の形でよい）だけで取る。`git status --porcelain` の未コミットのファイルは合わせない。理由を1文で書く：未コミット・未追跡のファイルは transition.py の done でマージされない（verifier が確認コマンドの実行で作ったファイルなど）ため、検査の対象にしない（計画票の「人への質問」5）
- 宣言外の検査そのもの・起点コミットの記録の扱い・除外するパス（計画票・タスク票の「進捗」・`vault/log/<計画ID>.md`・`vault/verdicts/` 配下）・`ok: false` にしないこと・起点コミットが無い時の扱いは変えない（廃止は D-012 の「今回やらないこと」。差分ゲートと役割は重なるが残す）
- 手順1（対象 worktree の読み方）は変えなくてよい。手順10以外を変える必要が出たら、変えずに blocked にして question に書く
- `vault/rules/verifier/verifier.md`・`vault/rules/common/git.md`・`vault/rules/creator/git-workflow.md` の「未コミット分は PASS の後にコミットする」の記述は直さない。提案ファイルも作らない（D-013 フェーズ4で直す。D-012 の決定済み）
- `.claude/agents/` 配下の変更はこのタスク票の「成果物」に宣言してあるので差分ゲートを通る
- `.claude/skills/run/SKILL.md`・`docs/vault-spec.md`・`scripts/` は変えない
