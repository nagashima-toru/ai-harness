# T-01 merge_settings_json.py に permissions.allow の不足を note 行で案内する処理を足す

## 目的
導入先の `.claude/settings.json` に既にファイルがある時、ハーネス側 `permissions.allow` のうち導入先に無いものを `note` 行で列挙し、利用者が手で足せるようにする。`permissions.allow` 自体は変更しない。

## 入力
- `scripts/merge_settings_json.py`（docstring、`merge_worktree_base_ref`・`worktree_base_ref_note`、`main` の note 出力位置）
- `.claude/settings.json`（ハーネス側の `permissions.allow`）
- `scripts/install.sh` 157行目（呼び出し側。変更しない）

## 成果物
- `scripts/merge_settings_json.py`（1ファイル。関数 `missing_allow`・`allow_missing_note` の追加と `main` からの呼び出し、docstring の更新）

## 受け入れ基準
- 構文が正しい：`python3 -m py_compile scripts/merge_settings_json.py` が終了コード0
- 不足を文字列の完全一致・src の順で返す：`python3 -c "import sys; sys.path.insert(0, 'scripts'); import merge_settings_json as m; print(m.missing_allow(['Read', 'Bash(git *)', 'Bash(jq *)'], ['Read', 'Bash(git:*)']))"` の出力が `['Bash(git *)', 'Bash(jq *)']`
- 不足が無ければ空、dst 側が None なら src 全部：`python3 -c "import sys; sys.path.insert(0, 'scripts'); import merge_settings_json as m; print(m.missing_allow(['Read'], ['Read', 'Write']), m.missing_allow(['Read', 'Write'], None))"` の出力が `[] ['Read', 'Write']`
- note 行の文言が決定済みの形になる：`python3 -c "import sys; sys.path.insert(0, 'scripts'); import merge_settings_json as m; print(m.allow_missing_note('x.json', ['Bash(git *)', 'Bash(jq *)']))" | grep -c '^note x\.json: permissions\.allow にハーネスが使う許可が 2 件足りない: Bash(git \*), Bash(jq \*)。対話実行では確認ダイアログが出て、無人実行（claude -p）では拒否される'` の出力が `1`
- 不足が無い dst では note を出さず書き換えない：`python3 scripts/merge_settings_json.py .claude/settings.json .claude/settings.json` の出力が `skip .claude/settings.json` の1行だけ
- `permissions.allow` を書き換えるコードが無い：`grep -nE '\[.allow.\] *=|allow[a-z_]*\.(append|extend|insert|remove)|setdefault\(.allow.' scripts/merge_settings_json.py` の出力が空

## 決定済み
- `permissions.allow` は読み取るだけで変更しない（既存方針の維持）。`dst_perms.setdefault("allow", ...)` のように allow キーを作ることもしない
- dst が無い（`create`）場合は src がそのまま書かれるので note は出さない。不足の判定は dst が既にある場合（merge/skip の経路）だけ行う
- 不足の判定は文字列の完全一致。パターンの包含関係は判定しない（例：dst に `Bash(git:*)` があっても `Bash(git *)` は不足扱い）
- 関数の形：
  - `missing_allow(src_allow, dst_allow)`：src の並び順で、dst に完全一致の文字列が無いものをリストで返す。src 内の重複は1回だけ数える。src の要素で文字列でないものは無視する。`src_allow` が None・リストでない時は `[]`。`dst_allow` が None の時は空リストとして扱う（src の文字列要素が全部不足）
  - `allow_missing_note(dst, missing)`：note 行の文字列を返す。形式は次の1行で固定する（`<N>` は件数、項目は `, `（カンマ＋空白）区切りで src の順）
    `note <dst>: permissions.allow にハーネスが使う許可が <N> 件足りない: <項目1>, <項目2>, ...。対話実行では確認ダイアログが出て、無人実行（claude -p）では拒否される。必要なら手で足すこと（このスクリプトは permissions.allow を変更しない）`
  - 不足が多くても1行にまとめる（改行で分けない）。省略もしない
- dst の `permissions.allow` がリストでない（文字列・オブジェクトなど）時は不足を判定せず、`note <dst>: permissions.allow の型が不正 (<型名>) なため不足を確認できない` の1行を出す（worktree の bad_type の note と同じ書き方）。終了コードは変えない（0）
- src は `src_data.get("permissions") or {}` の `allow` を使う。dst は `dst_data` の `permissions` の `allow` を読むだけ（既存の `dst_perms = dst_data.setdefault("permissions", {})` はそのままでよい）
- note を出す位置：`create`/`merge`/`skip` の行より前。worktree.baseRef の note がある時はその後に出す（順は worktree の note → allow の note → create/merge/skip）
- allow の不足は `added` に数えない。allow だけが不足している時は従来どおり `skip` で、dst を書き換えずバックアップも作らない
- 利用者の個人設定（`~/.claude/settings.json`）や `.claude/settings.local.json` はスクリプトから読まない
- docstring に、allow の不足を note 行で案内すること（変更はしない・完全一致で判定・create では出さない）を追記する。`permissions.allow は読み取るだけで一切変更しない` の段落は残す
- `scripts/install.sh` は変更しない（出力をそのまま流すので note 行はそのまま表示される）
- smoke.sh のテスト追加は T-02、docs/install.md は T-03 で行う。このタスクでは触らない
