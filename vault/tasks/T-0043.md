# T-0043 `docs/vault-spec.md` の8・9・10節（粒度／Stopフック／plan_guardフック）を書き直す

## 目的
`docs/vault-spec.md` の「粒度の基準」「Stop フックの判定」「todo_guard フックの判定」の3節を、計画
票を読む新方式に合わせて書き直す。判定ロジックの意味は変えず、参照先を `vault/todo.md` から計画票
に差し替え、`todo_guard` フックを `plan_guard` フックに改称する。

## 入力
- `docs/vault-spec.md`（T-0042 が終わった時点のもの。現行の「## 9. 粒度の基準」「## 10. Stop フッ
  クの判定」「## 11. todo_guard フックの判定」に相当する範囲）
- `vault/designs/D-001.md`（「## 決定事項」「## フェーズ2」「## フェーズ3」の `plan_guard.py` に関
  する記述。フェーズ3の実装詳細までは書き込まないこと。フェーズ2の範囲＝参照先の言い換えとフック名
  の改称に限る）
- `vault/tasks/T-0041.md`（ID・計画票の形式の契約）

## 成果物
- `docs/vault-spec.md` のうち、粒度の基準／Stop フックの判定／plan_guard フックの判定の3節の書き直
  し（新章立てで「8. 粒度の基準」「9. Stop フックの判定」「10. plan_guard フックの判定」に相当する
  範囲。他の節には触れない）

## 受け入れ基準
- 粒度の基準の節で、run（旧 run-queue）が必ず変えるファイルの例が `vault/todo.md` ではなく計画票
  になっている。確認：`grep -F 'vault/plans/<計画ID>.md' docs/vault-spec.md` の出力が1行以上
- Stop フックの節が、todo.md ではなく計画票のタスク表を読む記述になっている。確認：`grep -F
  '承認済み計画票のタスク表と verdict' docs/vault-spec.md` の出力が1行以上
- 見出しが「plan_guard フックの判定」に改称され、`plan_guard.py` への言及がある。確認：`grep -F
  'plan_guard フックの判定' docs/vault-spec.md` と `grep -F 'plan_guard.py' docs/vault-spec.md` の
  出力がそれぞれ1行以上
- plan_guard フックの節の5つの検査内容（doing が2件以上・blocked で question が空・status が5値以
  外・id の重複・データ行の列数が6でない）が残っている。確認：`grep -F 'データ行の列数が6でない'
  docs/vault-spec.md` の出力が1行以上

## 決定済み
- 新しい章立て（全13節）は `vault/plans/P-020.md` の「分割方針」を正本とする。このタスクは新8節
  （粒度の基準）・新9節（Stop フックの判定）・新10節（plan_guard フックの判定）を担当し、他の節に
  は触れない
- 粒度の基準の節：「run-queue が必ず変えるファイル（vault/todo.md、vault/log/queue.md、タスク票の
  「進捗」）を「変更していない」と差分で検査する受け入れ基準は書かない」という一文を、「run（旧
  run-queue）が必ず変えるファイル（計画票のタスク表、vault/log/<計画ID>.md、タスク票の「進捗」）」
  に差し替える。あわせて例のコマンドも `git diff -- vault/todo.md | ...` から `git diff --
  vault/plans/<計画ID>.md | grep -E '^[+-](## |\| id )'` に差し替える。それ以外（3〜7行、契約タス
  ク先出しなど）の記述は変えない
- Stop フックの節：`.claude/hooks/stop_gate.py` は「（自分のブランチの）承認済み計画票のタスク表と
  verdict を読んで判定だけを行い、状態は書き換えない」という一文に差し替える。判定表（6行の判定条
  件：stop_hook_active・doing/review 無し・verdict 無し/不一致・verdict 不正・FAIL と attempt 上
  限・PASS だが done でない・PASS かつ done）の中身は変えない。計画票が見つからない場合の fail-open
  など、フェーズ3の実装詳細は書き加えない（このタスクの範囲外）
- plan_guard フックの節：見出しを「10. plan_guard フックの判定」に改め、本文の `.claude/hooks/
  todo_guard.py` への言及と `vault/todo.md` への言及を、それぞれ `.claude/hooks/plan_guard.py` と
  「（自分のブランチの）計画票のタスク表」に差し替える。5つの検査内容自体は変えない
- 見出し番号は目安。このタスク終了時点で8・9・10節の番号・タイトルが最終形になっていればよく、11節
  以降（ルール／agent_write_guard／設計文書）がまだ旧番号のままでも構わない（次タスクが直す）
