# T-01 purge_plan.sh に --merged（--list・--report・--apply）を足し smoke で確かめる

## 目的
`main` にマージ済みの計画一式と `vault/archive/` を、人が一括で削除できるようにする。削除の前に Issue 化すべき情報を一覧で出せるようにする。

## 入力
- `vault/designs/D-016.md` の「フェーズ2」（受け入れ基準の候補・決定済み）
- `scripts/purge_plan.sh`（フェーズ1の単一計画モード。`fm_status`・`table_counts` を流用する）
- `scripts/archive_plans.sh` の候補の条件1〜5（`check_candidate`）
- `scripts/transition.py` の log 行の書式（`- <日時> <id> <旧>→<新> attempt=<n>[ creator=<model>|verifier=<model>][ <補足>]`）
- `scripts/smoke.sh` の `== purge_plan.sh ==` 節（`pp_make`・`pp_run` などの書き方）

## 成果物
- `scripts/purge_plan.sh`（主な成果物。`--merged` モードを足す）
- `scripts/smoke.sh`（`== purge_plan.sh --merged ==` 節を足す）

## 受け入れ基準
1. smoke に `(pm-1)`〜`(pm-6)` の6件があり、全部 ok になる（決定済みの各ケースを確かめる）。確認：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(pm-[1-6]\) '` が `6`
2. このリポジトリで `bash scripts/purge_plan.sh --merged --list` を実行すると、`main` で done の計画 `P-20261010-docs-align-guards` が1行で出て、旧形式の `P-019` と現在の計画 `P-20261010-purge-merged` は出ない。確認：`bash scripts/purge_plan.sh --merged --list | grep -c '^P-20261010-docs-align-guards$'` が `1`、`bash scripts/purge_plan.sh --merged --list | grep -cE '^(P-019|P-20261010-purge-merged)$'` が `0`
3. このリポジトリで `bash scripts/purge_plan.sh --merged --report` を実行すると、log の `→blocked` の行と verdict の空でない `reasons` が `<計画ID>/<id>: <種別> <内容>` の形で出る。確認：`bash scripts/purge_plan.sh --merged --report | grep -c '^P-20261004-hooklib-extract/T-01: blocked 基準4が決定済み(挙動を変えない)と両立しない$'` が `1`、`bash scripts/purge_plan.sh --merged --report | grep -c '^P-20261004-hooklib-extract/T-06: reasons 5行目の基準は'` が `1`
4. スクリプト冒頭のコメントに、`--merged --apply` は人だけが実行しエージェントは `--list`・`--report` だけを使うことが書かれている。確認：`grep -c '^# .*--merged --apply は人だけが実行する' scripts/purge_plan.sh` が `1`
5. 既存の単一計画モードの smoke（`(pp-1)`〜`(pp-8)`）が全部 ok のまま。確認：`bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(pp-[1-8]\) '` が `8`
6. smoke 全体が通る。確認：`bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<数> fail=0` の形

## 決定済み
- 使い方：`bash scripts/purge_plan.sh --merged (--list|--report|--apply)`。既存の `bash scripts/purge_plan.sh [--dry-run] <計画ID>` は挙動を変えない。usage の文字列は両方の形を出す
- 引数の誤り（終了コード2、何も変えない）：`--merged` だけ／`--list`・`--report`・`--apply` のうち2つ以上／`--merged` に計画 ID を付ける／`--merged` なしで `--list`・`--report`・`--apply` を使う／`--merged` と `--dry-run` を併用する／未知のオプション。git リポジトリの外も終了コード2
- 対象（`--list`・`--report`・`--apply` 共通）は、`vault/plans/*.md`（`LC_ALL=C` のファイル名順）のうち次の全部を満たす計画。archive_plans.sh の条件1〜5を引き継ぎ、条件6（log の日時行）と `--keep` は持たない
  1. 計画 ID が `^P-[0-9]{8}-[a-z0-9][a-z0-9-]*$` に一致する（`P-019` のような旧形式は対象外）
  2. 現在のブランチが `work/<計画IDの英小文字>` でない
  3. 作業ツリーの計画票の frontmatter の status が done（`fm_status` で読む。引用符付きの `"done"` も done）
  4. タスク表のデータ行が1行以上あり、全行の status 列が done（`table_counts`）
  5. `git show main:vault/plans/<計画ID>.md` の frontmatter の status が done。比較する ref は `main` に固定し、`--base` は持たない。`main` が無い・その版が無い時は対象外
- `--list`：対象の計画 ID を1行1件で標準出力に出す。対象が0件なら何も出さず終了コード0。作業ツリーとインデックスを変えない
- `--report`：対象の計画ごと（`--list` と同じ順）に次を標準出力に出す。何も変えない。対象や該当行が0件なら何も出さず終了コード0
  - `vault/log/<計画ID>.md` の遷移行のうち遷移先が `blocked` のもの（`<旧>→blocked`）を log の順に、`<計画ID>/<id>: blocked <補足>` の形で1行ずつ。`<補足>` は遷移行から `attempt=<n>` と、その直後の `creator=<model>`／`verifier=<model>` の語を除いた残り（前後の空白を除く）。空なら `(補足なし)`
  - 上の後に、`vault/verdicts/<計画ID>/*.json` をファイル名順に読み、`reasons` が空でない配列なら要素ごとに `<計画ID>/<id>: reasons <理由>` を1行ずつ。`<id>` はファイル名から `.json` を除いたもの。`<理由>` は改行を含む空白の連続を半角空白1つにし、前後の空白を除いたもの。JSON として読めない時は `<計画ID>/<id>: reasons verdict を JSON として読めない` を1行出す。`reasons` が無い・配列でない時は何も出さない
  - JSON の読み取りには `python3`（`-c` かヒアドキュメント）を使ってよい
  - 読み替えの理由：D-016 の候補は「最後の遷移が `→blocked` のタスク」だが、対象は全行 done の計画なので最後の遷移は必ず `→done` で、字句どおりでは常に0件になる。blocked の question は解除時に計画票から消え、log の補足にだけ残るので、log の `→blocked` の行を全部出す
  - `vault/archive/` の中身は報告しない（旧形式を含み形式がそろわないため。必要なら人が git の履歴で見る）
- `--apply`：対象の計画ごとに単一計画モードと同じ4種（存在するものだけ。`vault/plans/<ID>.md`・`vault/tasks/<ID>/`・`vault/verdicts/<ID>/`・`vault/log/<ID>.md` の順）を並べ、最後に `vault/archive/` が存在すれば `vault/archive/` を加え、`git rm -r -q` を1回呼ぶ。消したパスを1行1件で標準出力に出す。コミットはしない
  - 消す前に `git status --porcelain --untracked-files=all -- <全パス>` が空でなければ、`purge_plan.sh: 対象パスに未コミット・未追跡・stage 済みの変更がある` を標準エラーに出し、何も消さずに終了コード1
  - 対象の計画が0件で `vault/archive/` も無い時は、標準エラーに `purge_plan.sh: 削除するものがありません` を出し、標準出力は空で終了コード0
  - `vault/archive/` は中身の形式（旧形式の `todo.md` などを含む）を問わず丸ごと消す
  - `git rm` の失敗は単一計画モードと同じく終了コード1
  - 現在のブランチが `main` かどうかは検査しない（作業ブランチを切る手順は runbook に書く）
- スクリプト冒頭のコメントに、`--merged` の使い方・対象の条件・各モードの出力を書き足し、次の1行をそのまま入れる：`# --merged --apply は人だけが実行する。エージェントは --merged では --list・--report だけを使う。`
- smoke：`== purge_plan.sh ==` 節（`(pp-8)` の後、`== plan_record.py ==` の前）の直後に `echo "== purge_plan.sh --merged =="` の節を足す。一時リポジトリは smoke の `$TMP` の下に作り、`git init -q -b main` して計画を main にコミットした後、作業ブランチを切る（`pp_git` を流用してよい）。`== archive_plans.sh ==` 節には触らない（T-02 で消す）。テスト名と確かめる内容は次のとおり（名前は `(pm-<n>) ` で始める）
  - `(pm-1)` `--list`：対象（done・全行 done・main でも done）の1件だけを出し、次は出さない：main では approved の計画／タスク表に review がある計画／作業ブランチでだけ done にした（main の版が approved の）計画／現在のブランチの計画／ID が `P-019` の旧形式の計画。終了コード0で `git status --porcelain` が空のまま
  - `(pm-2)` `--report`：`→blocked` の行（`creator=` 付きで補足あり・補足なしの2種）と、`reasons` が2要素（1つは改行を含む）の verdict・`reasons` が空の verdict から、期待どおりの行だけをこの順に出す。`git status --porcelain` が空のまま
  - `(pm-3)` `--apply`：対象の4種と `vault/archive/` を `git rm` し（`git status --porcelain` に `D ` の行として出る）、対象外の計画は残り、HEAD は変わらない。標準出力に消したパスが出る
  - `(pm-4)` `--apply`：対象のタスク票に未コミットの変更がある時と、`vault/archive/` に未追跡ファイルがある時は、どちらも終了コード1で何も消さない
  - `(pm-5)` 決定済みの引数の誤りがどれも終了コード2
  - `(pm-6)` 対象が0件で `vault/archive/` も無い時の `--apply` は終了コード0・標準出力が空
- 受け入れ基準2・3は、このリポジトリの既存の計画（`vault/plans/`・`vault/log/`・`vault/verdicts/`）をそのまま読む。既存の計画一式と `vault/archive/` はこのタスクで消さない（`--apply` を実リポジトリで実行しない）
