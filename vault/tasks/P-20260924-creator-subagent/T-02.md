# T-02 agent_write_guard.py に creator 向け拒否ルールを追加

## 目的
`.claude/hooks/agent_write_guard.py` に、`agent_type == "creator"` の時は `vault/plans/` と `vault/log/` への書き込みを常に拒否するハード制限を追加する。成果物パスは repo 全体に及びうるため、既存の `ALLOWED` 辞書（許可リスト方式）には creator を追加せず、`vault/rules/` に対する既存の改ざん防止と同じ「拒否リスト方式」の関数を新設して実装する。

## 入力
- `.claude/hooks/agent_write_guard.py`（`ALLOWED` 辞書、`targets_vault_rules()`／`targets_vault_rules_remote()` のパターン、`BASH_WRITE_PATTERNS`）
- `vault/designs/D-003.md`「フェーズ2」の決定事項（creator の書き込み制限は拒否リスト方式、`vault/tasks/` と成果物パスは制限しない）
- `docs/vault-spec.md` 12節（agent_write_guard フックの改ざん防止判定。同じパターンを踏襲する）

## 成果物
- `.claude/hooks/agent_write_guard.py`

## 受け入れ基準
- `agent_type` が `creator` で書き込み先が `vault/plans/` 配下の Write は deny される。確認コマンド: `printf '{"agent_type":"creator","tool_name":"Write","tool_input":{"file_path":"vault/plans/P-X.md"}}' | python3 .claude/hooks/agent_write_guard.py` の出力に `"permissionDecision": "deny"` が含まれる
- `agent_type` が `creator` で書き込み先が `vault/log/` 配下の Write も同様に deny される。確認コマンド: `printf '{"agent_type":"creator","tool_name":"Write","tool_input":{"file_path":"vault/log/P-X.md"}}' | python3 .claude/hooks/agent_write_guard.py` の出力に `"permissionDecision": "deny"` が含まれる
- `agent_type` が `creator` で `vault/plans/`・`vault/log/` 以外（例：`README.md`、`vault/tasks/P-X/T-01.md`）への Write は許可される（拒否リストであり許可リストではない）。確認コマンド: `printf '{"agent_type":"creator","tool_name":"Write","tool_input":{"file_path":"README.md"}}' | python3 .claude/hooks/agent_write_guard.py` の出力に `"permissionDecision"` キー自体が含まれない
- Bash 経由（リダイレクト等）で `vault/plans/` を対象にした場合も deny される。確認コマンド: `printf '{"agent_type":"creator","tool_name":"Bash","tool_input":{"command":"echo x > vault/plans/P-X.md"}}' | python3 .claude/hooks/agent_write_guard.py` の出力に `"permissionDecision": "deny"` が含まれる
- 既存の verifier/planner 向け判定と `vault/rules/` 改ざん防止判定に回帰が無い。確認コマンド: `bash scripts/smoke.sh 2>&1 | grep '== agent_write_guard.py ==' -A 40 | grep -c '  NG'` の出力が0

## 決定済み
- 実装は `vault/rules/` 拒否（`targets_vault_rules()`）と同じパターンを踏襲する：`agent_type == "creator"` かつ対象パス（Write/Edit/MultiEdit/NotebookEdit の `file_path`、または Bash の `BASH_WRITE_PATTERNS` にマッチしたコマンドのリダイレクト先・パスらしき文字列）を正規化した結果が `vault/plans/` または `vault/log/` で始まる場合に deny する新しい判定関数を追加する
- この判定は既存の `ALLOWED` 辞書方式（許可リスト）には追加しない。`ALLOWED` は verifier/planner 用のまま変更しない
- deny の判定順序は、既存の `vault/rules/` 改ざん防止判定（`targets_vault_rules`）の直後、`ALLOWED` 辞書を使った既存判定より前に置く（`agent_type` が `creator` の場合はまず `vault/plans/`・`vault/log/` を見て、それ以外は `ALLOWED` に `creator` が無いのでそのまま許可される）
- deny メッセージには `vault/plans/` `vault/log/` のどちらに触れようとしたかが分かる文言を含める（既存の deny メッセージと同様の形式でよい）
- Bash のリダイレクト対象判定は、既存の `targets_vault_rules` 内のロジック（`re.findall(r">{1,2}\s*([^\s;&|]+)", cmd)` と `BASH_WRITE_PATTERNS` の組み合わせ）と同じ考え方を流用してよい
