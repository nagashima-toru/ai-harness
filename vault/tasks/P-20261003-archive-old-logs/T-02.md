# T-02 smoke.sh に archive_plans.sh の節を足す

## 目的
`scripts/archive_plans.sh` の対象の選び方（新しい `--keep` 件を残す）・移動・安全装置を、一時 git リポジトリで機械的に確かめられるようにする（`--apply` の動作は本物の vault では試せないため、ここで担保する）。

## 入力
- `scripts/archive_plans.sh`（T-01 の成果物）と、T-01 タスク票の「決定済み」（使い方・候補の条件・「新しい」の基準・安全装置・出力の形式）
- `scripts/smoke.sh`（`expect_eq` の書き方、`== discard_worktree.sh ==` 節・`== vcs_finish.sh ==` 節の一時リポジトリの作り方、`$TMP` の扱い）

## 成果物
- `scripts/smoke.sh`（`== archive_plans.sh ==` 節を追加する。1ファイル）

## 受け入れ基準
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- 節の見出しが1つある：`bash scripts/smoke.sh 2>&1 | grep -c '^== archive_plans.sh ==$'` の出力が `1`
- 節のテストが11件以上通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ar-'` の出力が `11` 以上
- 新しい件数を残すケース・件数以下のケース・同日の並びのケースがそれぞれ通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ar-\(9\|10\|11\))'` の出力が `3` 以上
- 節のテストに失敗が無い：`bash scripts/smoke.sh 2>&1 | grep -c '^  NG   (ar-'` の出力が `0`
- 追加した行に `/tmp/` の固定パスが無い：`git diff main -- scripts/smoke.sh | grep -c '^+.*/tmp/'` の出力が `0`

## 決定済み
- 節は `== vcs_finish.sh ==` 節の後（最後の `echo` と `smoke: pass=` の行の前）に置き、見出しは `echo "== archive_plans.sh =="` にする
- 一時リポジトリは smoke.sh 冒頭の `$TMP`（`mktemp -d`。終了時に trap で消える）の下に作る（例：`$TMP/ar_repo`）。`/tmp/` の固定パスは使わない（issue #95）。`$$` などで別に一意にする必要は無い。ケースごとに状態を作り直したい時は、`$TMP` の下に別名のリポジトリを作る（例：`$TMP/ar_repo2`）。`rm -rf` で作り直す前提にしない
- 一時リポジトリは `git init -q -b main` で作り、`git -c user.name=smoke -c user.email=smoke@example.com commit` でコミットする（`vcs_finish.sh` 節と同じ）。スクリプトは `bash "$ROOT/scripts/archive_plans.sh" ...` をサブシェルで `cd "$AR_REPO"` してから呼ぶ（スクリプトはカレントディレクトリの git ルートを使う）。main にコミットした後、`git checkout -q -b work/p-20260109-cur` のような作業ブランチに移ってからスクリプトを呼ぶ
- 計画 ID は日付部分のある形にする（例：`P-20260101-a`）。各計画には log（`- 2026-01-01 10:00 - draft→approved ...` のような日時行）を付ける
- テストのケース（名前は `(ar-1)` 〜 `(ar-11)` で始める。1ケースに `expect_eq` が複数あってよい）。(ar-1)〜(ar-8) は `--keep 0`（候補を全部移す対象にする）か、計画 ID を明示して呼んでよい
  - (ar-1) done・main にマージ済みの計画 A の `--dry-run`：終了コード0、`git mv ` で始まる行が4行、ファイルは動いていない
  - (ar-2) A の `--apply`：終了コード0、`vault/archive/2026-01/{plans,tasks,verdicts,log}/` に移り、元の場所から消え、`git status --porcelain` に `R ` の行（rename）が出る
  - (ar-3) done だが main に無い（作業ブランチにだけある）計画：ID を渡すと終了コード1、stderr に `archive_plans: NG <ID>: ` の行、何も動かない
  - (ar-4) approved の計画：ID を渡すと終了コード1、何も動かない
  - (ar-5) タスク表に review の行がある done の計画：ID を渡すと終了コード1、何も動かない
  - (ar-6) 移せる計画と NG の計画を一緒に渡す：終了コード1、移せる方も動かない（全部か無しか）
  - (ar-7) `--list`・`--dry-run`・`--apply` のどれも無い：終了コード2、stderr に `usage: ` の行
  - (ar-8) 移動先が既にある計画、または現在のブランチの計画（ブランチ名 `work/<ID の英小文字>`。main にも done である状態を作る）：終了コード1、何も動かない。現在のブランチの計画は `--keep 0 --list` の出力にも出ない
  - (ar-9) 新しい件数は残る：done・マージ済みの計画を3件（log の最初の日時が異なる）用意し、`--keep 2 --apply` で一番古い1件だけが移り、新しい2件は `vault/plans/` に残る
  - (ar-10) 候補が `--keep` 件以下なら何も移さない：候補2件で `--keep 2 --apply`（または既定の `--keep 5`）が終了コード0、stdout が空、何も動かない
  - (ar-11) 同日の並び：計画 ID の日付が同じ2件で、ID の文字列順と log の最初の日時の順が逆になるもの（例：`P-20260105-a` の log が 11:00、`P-20260105-b` の log が 10:00）を用意し、`--keep 1 --list` が `P-20260105-b` だけを出す（log の日時で新しい `-a` が残る）。あわせて log の最初の日時が同じ2件では、`--keep 1 --list` が ID の文字列順で前の方だけを出す
- 作業ブランチの切り替えは一時リポジトリの中でだけ行う（このリポジトリのブランチは触らない）
- `scripts/archive_plans.sh` にバグが見つかった時は、自分で直さず blocked にして question に書く（成果物は smoke.sh だけ）
- 確認コマンドの `git diff main -- scripts/smoke.sh` は、この計画で smoke.sh を変えるのがこのタスクだけなので使ってよい
