# T-02 起点を明示して worktree を作る scripts/add_worktree.sh を足す

## 目的
Issue #209。Agent ツールの worktree 隔離に頼らず、オーケストレーターが計画ブランチの HEAD（`PLAN_HEAD`）を起点に明示して creator 用の worktree を作れるスクリプトを用意し、smoke で確かめる。

## 入力
- `scripts/discard_worktree.sh`（同じ形のシェルスクリプト。ブランチ名の接頭辞 `worktree-agent-`・realpath の取り方・使い方の書き方を合わせる）
- `scripts/transition.py` の `check_worktree`（392行付近。作った worktree がこの検証を通る必要がある）と `resume_worktree` の標準出力の形（`path=… branch=… plan_head=…`）
- `scripts/smoke.sh` の `== discard_worktree.sh ==` の節（`smoke_tmpdir`・`expect_eq` の使い方）と `(inst-scr) 06`（`scripts/` 直下の `*.sh` が `SCRIPTS_FILES` に無いと落ちる）
- `scripts/install.sh` の `SCRIPTS_FILES=` の行
- `README.md` のスクリプトの表（`scripts/discard_worktree.sh` の行）

## 成果物
- `scripts/add_worktree.sh`（主な成果物。新規）
- `scripts/install.sh`（`SCRIPTS_FILES` に1つ足す）
- `scripts/smoke.sh`（`(add-wt-1)`〜`(add-wt-5)` の検査を足す）
- `README.md`（スクリプトの表に1行足す）

## 受け入れ基準
- smoke に足した5件の検査が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (add-wt-[1-5]) '` の出力が `5`
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<n> fail=0` の形（`<n>` は任意）
- 文書のバッククォートのパスがすべて存在する：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- install.sh が配るスクリプトの一覧に入っている：`grep -c '^SCRIPTS_FILES=.*scripts/add_worktree.sh' scripts/install.sh` の出力が `1`
- README のスクリプトの表に行がある：`grep -c 'add_worktree.sh. . worktree の作成' README.md` の出力が `1`

## 決定済み
- 使い方：`bash scripts/add_worktree.sh <PLAN_HEAD>`。引数は1つだけ（数が違えば使い方を標準エラーに出して終了コード2）。カレントディレクトリの git リポジトリ（run のメインの作業ツリー）で実行する前提で、`git rev-parse --show-toplevel` を対象のルートにする。`git -C` の指定は要らない（discard_worktree.sh と同じ）
- 起点：`<PLAN_HEAD>` を `git rev-parse --verify --quiet <PLAN_HEAD>^{commit}` で40桁の sha に解決する。解決できなければ何も作らず、理由を標準エラーに出して終了コード1。今の HEAD と同じかどうかは見ない（起点を明示することが目的で、`<PLAN_HEAD>` が HEAD より古いコミットでもそのコミットから切る）
- 名前：8桁の英小文字の16進の値 `<x>` を作り、パスを `<ルート>/.claude/worktrees/agent-<x>`、ブランチ名を `worktree-agent-<x>` にする（Agent ツールが作るものと同じ形。`scripts/discard_worktree.sh`・transition.py の `check_worktree` の検証をそのまま通る）。値の作り方（`python3` の `secrets`・`/dev/urandom` など）は任せる。パスかブランチが既にあれば値を作り直し、5回続けて当たれば終了コード1
- 作り方：`git worktree add -q -b worktree-agent-<x> <パス> <40桁の sha>`（親ディレクトリ `.claude/worktrees/` が無ければ先に `mkdir -p`）。`git worktree add` が失敗したら、その標準エラーを出して終了コード1。コミットはしない。`.claude/worktrees/` は `.gitignore` 済み（導入先は install.sh が足す）
- 標準出力：成功時だけ1行 `path=<パスの realpath> branch=<ブランチ名> plan_head=<40桁の sha>` を出して終了コード0。ほかの出力は標準エラーへ
- 終了コード：0（作った）・1（`<PLAN_HEAD>` を commit に解決できない・git リポジトリの外・名前が5回続けて当たった・`git worktree add` の失敗）・2（引数の誤り）
- ファイルの冒頭のコメントに、使い方・run が手順3で creator の worktree をこれで作ること（Agent ツールの worktree 隔離が計画ブランチ以外から切った Issue #209 の対策）・終了コードを書く
- `scripts/install.sh`：`SCRIPTS_FILES=` の値の、`scripts/amend_task.py` の直後に `scripts/add_worktree.sh` を足す（アルファベット順）。ほかの行は変えない
- `README.md`：スクリプトの表の `scripts/discard_worktree.sh` の行の直前に、次の1行をこのまま足す：
  - | `scripts/add_worktree.sh` | worktree の作成 |
- smoke の検査は `== discard_worktree.sh ==` の節の `(e)` の後ろ（`== install.sh --update ==` の前）に、`smoke_tmpdir` で作った一時リポジトリ（コミット2つ以上）を使って足す。ラベルと中身はこのとおり：
  - `(add-wt-1) add_worktree.sh 正常系: 終了コード0で1行を出し、パスが .claude/worktrees/agent- の下・ブランチが worktree-agent- で始まり・worktree の HEAD が指定の sha`
  - `(add-wt-2) add_worktree.sh で作った worktree を discard_worktree.sh が破棄できる`（出力の path・branch をそのまま渡して終了コード0、`git worktree list` から消える）
  - `(add-wt-3) add_worktree.sh は HEAD より古いコミットを渡すとそのコミットから切る`（`git -C <path> rev-parse HEAD` が渡した古い sha）
  - `(add-wt-4) add_worktree.sh 拒否系: commit に解決できない引数は終了コード1で worktree もブランチも増えない`
  - `(add-wt-5) add_worktree.sh 引数が無い時は終了コード2`
  - 後片付けは同じ節の既存の検査と同じく `git worktree remove --force`・`git branch -D`・`rm -rf`（smoke.sh の中の一時ディレクトリ）でよい（smoke.sh の中の処理で、確認コマンドではない）
- run/SKILL.md・creator.md・docs/vault-spec.md はこのタスクでは変えない（T-03〜T-05 で直す）
