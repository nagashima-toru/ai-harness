# T-02 smoke.sh に archive_plans.sh の節を足す

## 目的
`scripts/archive_plans.sh` の移動と安全装置を、一時 git リポジトリで機械的に確かめられるようにする（`--apply` の動作は本物の vault では試せないため、ここで担保する）。

## 入力
- `scripts/archive_plans.sh`（T-01 の成果物）と、T-01 タスク票の「決定済み」（使い方・安全装置・出力の形式）
- `scripts/smoke.sh`（`expect_eq` の書き方、`== discard_worktree.sh ==` 節・`== vcs_finish.sh ==` 節の一時リポジトリの作り方、`$TMP` の扱い）

## 成果物
- `scripts/smoke.sh`（`== archive_plans.sh ==` 節を追加する。1ファイル）

## 受け入れ基準
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる
- 節の見出しが1つある：`bash scripts/smoke.sh 2>&1 | grep -c '^== archive_plans.sh ==$'` の出力が `1`
- 節のテストが8件以上通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ar-'` の出力が `8` 以上
- 節のテストに失敗が無い：`bash scripts/smoke.sh 2>&1 | grep -c '^  NG   (ar-'` の出力が `0`
- 追加した行に `/tmp/` の固定パスが無い：`git diff main -- scripts/smoke.sh | grep -c '^+.*/tmp/'` の出力が `0`

## 決定済み
- 節は `== vcs_finish.sh ==` 節の後（最後の `echo` と `smoke: pass=` の行の前）に置き、見出しは `echo "== archive_plans.sh =="` にする
- 一時リポジトリは smoke.sh 冒頭の `$TMP`（`mktemp -d`。終了時に trap で消える）の下に作る（例：`$TMP/ar_repo`）。`/tmp/` の固定パスは使わない（issue #95）。`$$` などで別に一意にする必要は無い
- 一時リポジトリは `git init -q -b main` で作り、`git -c user.name=smoke -c user.email=smoke@example.com commit` でコミットする（`vcs_finish.sh` 節と同じ）。スクリプトは `bash "$ROOT/scripts/archive_plans.sh" ...` をサブシェルで `cd "$AR_REPO"` してから呼ぶ（スクリプトはカレントディレクトリの git ルートを使う）
- 用意する計画（計画 ID は日付部分のある形にする。例：`P-20260101-a`）
  - A：done・全行 done・main にコミット済み・tasks/verdicts/log あり（正常系）
  - B：done・全行 done だが main には無く、作業ブランチにだけある（マージ前）
  - C：approved
  - D：done だがタスク表に review の行がある
- テストのケース（名前は `(ar-1)` 〜 `(ar-8)` で始める。1ケースに `expect_eq` が複数あってよい）
  - (ar-1) A の `--dry-run`：終了コード0、`git mv ` で始まる行が4行、ファイルは動いていない
  - (ar-2) A の `--apply`：終了コード0、`vault/archive/2026-01/{plans,tasks,verdicts,log}/` に移り、元の場所から消え、`git status --porcelain` に `R ` の行（rename）が出る
  - (ar-3) B（main に無い）：終了コード1、stderr に `archive_plans: NG <B の ID>: ` の行、何も動かない
  - (ar-4) C（approved）：終了コード1、何も動かない
  - (ar-5) D（全行 done でない）：終了コード1、何も動かない
  - (ar-6) 正常な計画と NG の計画を一緒に渡す：終了コード1、正常な方も動かない（全部か無しか）
  - (ar-7) `--dry-run`・`--apply` のどちらも無い：終了コード2、stderr に `usage: ` の行
  - (ar-8) 移動先が既にある、または現在のブランチの計画（ブランチ名 `work/<ID の英小文字>`）：終了コード1、何も動かない
- 作業ブランチの切り替えは一時リポジトリの中でだけ行う（このリポジトリのブランチは触らない）
- `scripts/archive_plans.sh` にバグが見つかった時は、自分で直さず blocked にして question に書く（成果物は smoke.sh だけ）
- 確認コマンドの `git diff main -- scripts/smoke.sh` は、この計画で smoke.sh を変えるのがこのタスクだけなので使ってよい
