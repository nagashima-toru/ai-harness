# T-0050 `run-queue` を `run` に改名し `verifier.md` を新方式に直す

## 目的
`.claude/skills/run-queue/` を `.claude/skills/run/`（`/run`）に改名し、自分のブランチの承認済み
計画票（`vault/plans/` の `status: approved` な1件）のタスク表からタスクを取り、
`vault/log/<計画ID>.md` に状態遷移を追記する手順に書き換える。旧名のエイリアスは残さない。
`.claude/agents/verifier.md` の読み先・出力先を計画票／計画スコープのパスに直す。

## 決定済み
- 承認済み計画票が0件の場合は「承認済みの計画が見つかりません。`/plan approve <計画ID>` を実行し
  てください」と報告して終わる。2件以上見つかった場合は「approved な計画票が複数あります
  （異常）。人に確認してください」と報告して終わる（`plan_guard.py` が書き込み時に検出済みのはず
  だが、念のため `/run` 側でも異常系として扱う。修復はしない）
- タスクの取り方（doing継続／review継続／todoの先頭で after が全部done／`$ARGUMENTS` 指定）、
  verifier 呼び出し（タスク ID だけを渡す）、verdict に従う分岐（PASS→done／FAIL＋attempt<上限→
  doing／FAIL＋attempt≥上限→blocked）は `run-queue` の手順をそのまま踏襲する。変わるのはタスク票・
  verdict のパスが `vault/tasks/<計画ID>/<id>.md`・`vault/verdicts/<計画ID>/<id>.json` になる点と、
  ログの書き先が `vault/log/<計画ID>.md` になる点だけ
- 全タスクが `done` になったら、計画票 frontmatter の `status` を `done` にし、`gh pr create` を実
  行する。draft PR にするかどうかは規定しない（既定＝非 draft でよい）。`gh pr merge` は実行しない
- `verifier.md` の「読むもの」1番目（`vault/todo.md` の該当行）は「計画票（`vault/plans/<計画
  ID>.md`）のタスク表の該当行」に、`vault/verdicts/<id>.json` の例はすべて
  `vault/verdicts/<計画ID>/<id>.json`・`"task": "<計画ID>/<id>"` に直す。`criteria`／`note`／
  `reasons` の形式・禁止事項（成果物の修正禁止・状態変更禁止等）は変更しない
- Stop フックが verdict と状態を照合する点、`done` のタスク票は編集しない点、git のコミットは受け
  入れ基準に含まれる場合だけ行う点は `run-queue` の「注意」節からそのまま引き継ぐ
- `README.md`・`docs/runbook.md` など他ドキュメントの一括修正はこのタスクの範囲外（次フェーズで行
  う）
