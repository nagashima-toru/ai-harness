## 決定済み
- 提案ファイルの構成は、見出し `## 現行の該当箇所`・`## 直した文面`・`## 理由`・`## 他のロールのルール` をこの順で置く（先頭に `# T-06 修正案` などの h1 を置いてよい）。反映は人が手作業で行う。反映を前提にした他ファイルの変更はしない
- 「現行の該当箇所」：`vault/rules/planner/planner.md` の47行（「同じ形では、コマンドのどこかに `vault/rules/` を含む語があるだけで…」の段落全体）と49行（「避け方：…」の段落全体）を、行番号を添えてそのまま引用する（`~~~text` のコードブロックか `>` の引用。文字を変えない）。行番号は着手時に `grep -n` で確かめる
- 「直した文面」：47行と49行それぞれの置き換え後の全文を書く
  - 47行：「`vault/rules/` を含む語」を「保護対象パス（`vault/rules/`・`vault/plans/`・`vault/log/`・`vault/tasks/`・`vault/verdicts/`・`.claude/projects`）を含む語」に直す（この括弧書きの文字列をそのまま使う）。拒否が起こる条件（コマンドの別の場所にリダイレクトか書き込み動詞がある時）・引数・引用符の中・ヒアドキュメントの本文でも起こること・例外（`cat` のヒアドキュメントだけのコマンド置換、先頭の `cd <リポジトリのルート>`）・worktree の注記は残す
  - 47行には、verifier・planner では書き込み先が repo の外（`/tmp/...` など）だけでも、また自分の許可ディレクトリ（planner の `vault/plans/`・`vault/tasks/`）配下の語でも、その語が書き込み先の候補に入って拒否されうることを1文で足す（T-03 の「決定済み」の ALLOWED 判定：解析できない時は和集合の全候補が root の外か ALLOWED 配下のリダイレクトでないと許可しない）。例として `python3 -c "open('vault/tasks/P/T-01.md')" > /tmp/x.txt` を挙げてよい
  - 49行：最後の文「`vault/rules/` のパスを含むコマンドは、…分けて実行するか、Read で読む。」の主語を「保護対象パス（`vault/rules/`・`vault/plans/`・`vault/log/`・`vault/tasks/`・`vault/verdicts/`・`.claude/projects`）を含むコマンドは」に直す。49行の他の文は変えない
  - 46行（`>` の扱い）・48行（(3)）・41行（許可ディレクトリの説明）・50行・64行は直さない。T-03 の「進捗」に、これらの記述と食い違う挙動の変化が書かれていた場合だけ、「直した文面」に追加の案として書き、理由も添える
- 「理由」：一本化（D-011 フェーズ3）で、解析できない時の候補が4通りの従来判定の和集合になり、ALLOWED 判定（verifier・planner）もそれで判定するようになったこと、挙動が変わった例（少なくとも `python3 -c "open('vault/tasks/P-FX/T-02.md')" > /tmp/x.txt`：変更前は許可→変更後は拒否。T-03 の「進捗」に他の例があれば足す）、人の決定（元の質問1：ALLOWED も和集合、質問3：この計画で追随）を書く。書いた内容は `.claude/hooks/agent_write_guard.py` の実装と T-03 の「進捗」に合わせる（食い違えば実装を正とする）
- 「他のロールのルール」：`grep -n -e '解析できない' -e 'path-like' -e '含む語' vault/rules/creator/*.md vault/rules/verifier/*.md vault/rules/common/*.md` を実行した結果を書く。planner が着手前に確かめた時点（2026-10-05）では、`vault/rules/creator/creator.md`（12・17・23行）と `vault/rules/verifier/verifier.md` に、`vault/rules/` などへの直接書き込みが拒否される記述はあるが、解析できない形で語を含むだけで拒否される旨の記述は無い（直接書き込みの拒否は一本化で変わらないので直さない）。同じ結果なら、両ファイルのパスを挙げて「同種の記述なし、修正案なし」と書く。同種の記述が見つかった時だけ、そのファイルの引用と直した文面を同じ提案ファイルのこの節に足す
- `vault/rules/` 配下・`.claude/hooks/agent_write_guard.py`・`scripts/smoke.sh`・`docs/vault-spec.md`・他のタスク票・fixtures は変更しない
- 確認コマンドは grep だけで済むので、`vault/rules/` を含むコマンドを `python3 -c` などとつながない
- コミットは受け入れ基準に無いので、creator はしない
