# T-01 analyze_bash_writes を追加し vault/rules/ と会話記録の Bash 判定を精密化する

## 目的

## 決定済み
- **`analyze_bash_writes(cmd)` の返り値**：解析できた時は `[(verb, target), ...]`（書き込みが無ければ空リスト）を返し、解析できない時は `None` を返す。`verb` は次のどれか：`redirect`・`tee`・`sed-i`・`cp`・`mv`・`rm`・`mkdir`・`touch`・`chmod`・`chown`・`git-add`・`git-commit`・`git-write`。`git-write` は `git rm/mv/checkout/switch/reset/restore/clean/stash/merge/rebase/push`。`git-add`・`git-commit` を分けるのは、T-03 で「内容を変えない」扱いにするため
- **`None`（解析不能。呼び出し側は現行の判定をそのまま使う）にする条件**（どれか1つでも当たれば None）：
  1. ヒアドキュメント本文を除いた残りに `$(`・バッククォート・`<(`・`>(` がある
  2. shlex が例外を出す（引用符の閉じ忘れ等）
  3. 区切り以外の記号トークンとして `(`・`)` が出る（サブシェル）。または単語として `{`・`}`・`!` がコマンド位置に出る
  4. セグメントのコマンド語（先頭の `VAR=value` 形式の代入トークンを飛ばした最初のトークン）が `$` を含むか、次の集合に入る：`cd`・`pushd`・`popd`・`eval`・`exec`・`source`・`.`・`bash`・`sh`・`zsh`・`dash`・`env`・`sudo`・`nohup`・`time`・`timeout`・`nice`・`command`・`builtin`・`xargs`・`find`・`awk`・`gawk`・`perl`・`python`・`python3`・`ruby`・`node`・`git` の直後が `-` で始まる形（`git -C` 等）
  5. 書き込み対象のトークンに `$`・`*`・`?`・`[`・`{` が含まれる
  6. 引用符で囲まない区切り語のヒアドキュメント（`<<EOF`）の本文に `$(` かバッククォートがある
- **トークン化**：`shlex.shlex(..., posix=True, punctuation_chars=True)` に `whitespace_split = True`・`commenters = ''`（`#` をコメントとして捨てない。対象を多く拾う側＝安全側）を設定する
  - 引用符の外の改行は `;` と同じコマンド区切りとして扱う（`echo a` 改行 `rm x` の `rm` を `echo` の引数と見なさない）
  - 引用符内の改行（複数行の `-m "..."`）は区切りにしない
  - 区切りは `;`・`&&`・`||`・`|`・`|&`・`&`
- **ヒアドキュメント**：引用符の外の `<<`・`<<-` の直後の区切り語（`'EOF'`・`"EOF"`・`EOF`）を見つけ、次の行から区切り語だけの行までの本文を解析対象から取り除く。本文は書き込み対象にしない（データであり実行されない）。`<<` を含むコマンド行自体（例：`cat > out.md <<'EOF'` の `> out.md`）は通常どおり解析する。区切り語の行が見つからない時は None。`<<<`（here-string）は次の1語を読み取りの入力として扱う
- **リダイレクト**：`>`・`>>`・`>|`・`&>`・`&>>` の直後のトークンを `redirect` の対象にする（`2>`・`1>>` のような前置の数字は別トークンになるが同じ扱い）。`>&` の直後が数字か `-` なら fd の複製で、書き込みにしない（`2>&1`）。それ以外の語なら、その語を対象にする。`<`・`<<<` の直後は読み取りで、対象にしない
- **コマンド別の対象**（フラグ＝`-` で始まるトークンは除く。`--` の後はすべて引数）：
  - `tee`：全引数
  - `sed`：引数に `-i`・`-i<suffix>`・`--in-place` があれば全引数を `sed-i` の対象にする（スクリプト語を含めてよい）。無ければ書き込みなし
  - `cp`・`mv`：最後の引数。`-t <dir>`・`--target-directory=<dir>` があればその dir
  - `rm`・`mkdir`・`touch`・`chmod`・`chown`：全引数
  - `git add`：引数を `git-add` の対象にする
  - `git commit`：対象は無し。`git-commit` を target 空文字で1件記録する。`-m` のメッセージは対象にしない
  - `git rm/mv/checkout/switch/reset/restore/clean/stash/merge/rebase/push`：全引数を `git-write` の対象にする。引数が無ければ target 空文字で1件記録する
  - 上記以外のコマンド（`grep`・`cat`・`git show`・`git log`・`git diff`・`printf`・`echo`・`ls`・`head`・`wc` 等）：書き込みなし
- **`targets_vault_rules` の Bash 分岐**：`targets_vault_rules_remote(cmd)` の判定は今のまま先に行う
  - `analyze_bash_writes` が None なら、現行の判定（`BASH_WRITE_PATTERNS`＋リダイレクト先＋`vault/rules/` を含むパスらしいトークン）をそのまま使う。現行コードは関数に切り出して残してよい
  - リストが返れば、verb を問わずどれかの target が `normalize(target, root)` で `vault/rules/` 始まりの時だけ True にする（`git add vault/rules/x` も従来どおり拒否側）
- **`targets_transcript_dir` の Bash 分岐**：None なら現行の判定のまま。リストが返れば、どれかの target が `is_under_transcript_dir(target, root)` の時だけ True にする
- この2判定以外（`targets_creator_denied_paths`・`find_done_task_write`・`main()` の ALLOWED 判定・main 直接コミット拒否）は**このタスクでは変えない**（T-02〜T-04 で行う）。`BASH_WRITE_PATTERNS`・`extract_bash_write_targets`・`is_git_stage_or_commit_only` は、フォールバックと他の判定が使うので残す
- **smoke に足すケース**：既存の会話記録のブロック（`expect_tg "Bash で ~/.claude/settings.json へリダイレクト → 許可" ...` の行）の直後に置く
  - 名前は `(bash-parse) <説明> → 許可` / `(bash-parse) <説明> → 拒否` の形にする（受け入れ基準の grep がこの形に依存する）
  - 実行は `run_guard_home`（HOME=`$TG_HOME`）と 4引数版 `expect_guard` を使う。拒否ケースで reason の部分文字列を見る場合は、rules は `vault/rules/`、会話記録は `~/.claude/projects/` を4番目の引数に渡す
  - JSON 内の改行は `\n`、`"` は `\"` でエスケープする
  - 拒否ケースは、現行コードでも拒否されることを planner が確認済みの形にした。`cd vault/rules/ && ...`（末尾の `/` は normalize で落ちる）と `F=vault/rules/a.md; ... $F`（`F=` が前に付く）は、現行でも拒否されないため使わない（この既知の取りこぼしを直すのは今回の対象外）
  - 許可（5件。いずれも現行コードでは拒否される）：
    1. `grep -n "git commit" ~/.claude/projects/x/s.jsonl`
    2. `grep -c mkdir ~/.claude/projects/x/s.jsonl`
    3. `grep -n "doing->review" ~/.claude/projects/x/s.jsonl`
    4. `printf '%s' "echo x > vault/rules/a.md"`
    5. `cat > /tmp/P-20261002-write-guard-false-positive-note.md <<'EOF'`＋改行＋`see vault/rules/common/git.md and git commit`＋改行＋`EOF`
  - 拒否（10件）：
    1. `echo "x" > vault/rules/a.md`
    2. `cat > vault/rules/a.md <<'EOF'`＋改行＋`body`＋改行＋`EOF`
    3. `echo x; echo y > ~/.claude/projects/x/s.jsonl`
    4. `echo a`＋改行＋`rm ~/.claude/projects/x/s.jsonl`（改行区切り）
    5. `echo "$(echo x > vault/rules/a.md)"`（コマンド置換：従来判定）
    6. `cd vault/rules/common && echo x > a.md`（cd：従来判定）
    7. `echo x > vault/rules/$NAME`（変数を含む対象：従来判定）
    8. `bash -c "echo x > vault/rules/a.md"`（インタプリタ：従来判定）
    9. `cat <<EOF > /tmp/x`＋改行＋`$(echo x > vault/rules/a.md)`＋改行＋`EOF`（展開されるヒアドキュメント本文の `$(`：従来判定）
    10. `awk '{print > "vault/rules/a.md"}' README.md`（awk：従来判定）
