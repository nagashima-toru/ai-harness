# T-05 docs/runbook.md 9節を excludedCommands と後始末に合わせて直す

## 目的
`docs/runbook.md` の「## 9. サンドボックスを確かめる」の、「`vcs_finish.sh` が通らない時は別の計画で `excludedCommands` に足す。それまでは人がサンドボックスの外で実行する」などの記述を、T-02（`excludedCommands`）・T-03（run の後始末）と、T-01・T-07・T-08・T-09（smoke がサンドボックスの中でも通る）の後の運用に合わせて直す。人が確かめる手順に、`excludedCommands` が効いていることと、run の後に worktree が残っていないことの確認を足す。

## 入力
- `docs/runbook.md` の143〜172行目付近（「## 9. サンドボックスを確かめる」・「### うまくいかなかった時」・「### 使えない環境」）
- `.claude/settings.json` の `sandbox.excludedCommands`（T-02 の後の値。4つのパターン）
- `.claude/skills/run/SKILL.md` の「## worktree の後始末（サンドボックス）」（T-03）
- `scripts/smoke.sh`・`scripts/install.sh`・`scripts/uninstall.sh`・`scripts/archive_plans.sh` の一時ファイルの作り方（T-01・T-07・T-08・T-09 の後。`${TMPDIR:-/tmp}` の下に作り、作れない時は中断する）
- `vault/plans/P-20261009-sandbox-friendly.md` の分割方針（smoke をサンドボックスの中で実行した結果）

## 成果物

## 決定済み
- 手順2（`/sandbox` の確認）の Config タブの確認に、「`excludedCommands` に `.claude/settings.json` の4つのパターン（`bash scripts/vcs_finish.sh`・`bash scripts/vcs_finish.sh *`・`env HARNESS_PR_BODY_FILE=* bash scripts/vcs_finish.sh`・`bash scripts/discard_worktree.sh *`）が出ていること」を足す。受け入れ基準2行目の文字列はこのとおりに書く
- 手順4（smoke）は、コードブロックの `bash scripts/smoke.sh` を残し、本文を次の旨に直す
  - サンドボックスを有効にしたセッションの Bash で `bash scripts/smoke.sh` を実行し、`fail=0` を確かめる
  - smoke はサンドボックスの中でも通る（`scripts/smoke.sh`・`scripts/install.sh`・`scripts/uninstall.sh`・`scripts/archive_plans.sh` が一時ファイルを `${TMPDIR:-/tmp}` の下に作り、作れない時は中断するため）。人がサンドボックスの外で流す必要は無い。受け入れ基準3行目の1つ目の文字列（`人がサンドボックスの外で流す必要は無い`）はこのとおりに1回だけ書く
  - 「全件が通ることは未確認（計画 P-20261009-sandbox-friendly の run の後に、人がこの手順で1回確かめる）」の旨を書く。受け入れ基準3行目の2つ目の文字列（`全件が通ることは未確認`）はこのとおりに1回だけ書く
- 手順5（`vcs_finish.sh`）は、`vcs_finish.sh` は `excludedCommands` によりサンドボックスの外で実行されるので、run の最後に push と PR の作成が人の手を介さずに通ることを確かめる、という書き方に直す。コードブロックの `bash scripts/vcs_finish.sh` は残してよい
- 手順6を足す。行頭は `6. 計画の run が終わった後、` とし（受け入れ基準4行目）、`git worktree list` を実行して、done のタスクの worktree（`worktree-agent-` で始まるブランチ）が残っていないことを確かめる、と書く（blocked のタスクの worktree は残っていてよい）。コマンドはコードブロックで `git worktree list` と書く
- 「### うまくいかなかった時」：
  - 5 の項目は、「人がサンドボックスの外で実行する」「別の計画で `excludedCommands` に足す」の記述を消し、「`/sandbox` の Config タブで `excludedCommands` が出ているかを確かめる。出ていなければ、managed の設定か `--settings` で `allowUnsandboxedCommands: false` が設定されていないかを見る（その時はプロジェクトの設定の `excludedCommands` が無視される）。出ているのに通らない時は、run の呼び出しがパターンに一致していないので、呼び出しの形かパターンを直す計画を立てる」の旨に直す。受け入れ基準5行目の文字列はこのとおりに書く
  - 4 の項目（smoke）は、「どのケースが落ちたかを見て、サンドボックスの書き込み・通信の制限によるものかを確かめる」を残し、「直し方は別の計画で決める」を「`smoke: 一時ディレクトリを作れません` などの中断の文言が出た時は `$TMPDIR` を確かめる。ほかのケースが落ちた時の直し方は別の計画で決める」の旨に直す（中断の文言はスクリプトごとに `install:`・`uninstall:`・`archive_plans:` で始まり、smoke.sh 以外は「一時ファイルを作れません」）
  - 6 の項目を足す：done のタスクの worktree が残った時は、run の完了報告に写された `discard_worktree.sh` の標準エラーと `git worktree list --porcelain` の出力を見る。受け入れ基準6行目の文字列（`` `discard_worktree.sh` の標準エラー ``）はこのとおりに1回だけ書く
- 「### 使えない環境」の「`bash scripts/smoke.sh` は通る」は変えない（サンドボックスが無ければ通るため）
- 見出し（`## `・`### `）は足さない・消さない（受け入れ基準7行目）。番号付きの手順と箇条書きの中で直す
- 9節の外（1〜8節・困ったとき）は変えない。`docs/vault-spec.md`（T-04）・`docs/install.md` は変えない
- 文書だけの変更なので、確認は受け入れ基準の grep で行う。`bash scripts/smoke.sh` は実行しない（手順4は人がマージ後に行う手順で、creator・verifier はサンドボックスの中で全件を流さない）
