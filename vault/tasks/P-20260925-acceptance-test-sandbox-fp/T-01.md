# T-01 settings.json の rm -rf deny パターン見直しの提案を書く（issue #46）

## 目的
`.claude/settings.json` の `permissions.deny` にある `rm -rf` 系パターン（`Bash(rm -rf *)` 等）が、リポジトリ内の破壊的操作とリポジトリ外（`/tmp` 配下等）の使い捨てディレクトリの後片付けを区別せず一律ブロックしている問題について、元の防止意図を壊さない範囲の修正案を複数提示する。どの案を採用するかは人が決めるため、`.claude/settings.json` 自体は変更しない。

## 入力
- `.claude/settings.json`（60-63行目の `Bash(rm -rf *)` / `Bash(rm -fr *)` / `Bash(rm -r *)` / `Bash(rm -Rf *)`、および `permissions.allow` に同種の `/tmp` 用エントリが無いこと）
- `vault/plans/P-20260925-vcs-finish-push-and-diff-criteria.md` と `vault/tasks/P-20260925-vcs-finish-push-and-diff-criteria/T-01.md`（verifier が固定パスに書き換えて回避した実例）
- `vault/rules/common/git.md`（`git clean`/`git reset --hard` 等、他の破壊的操作を deny している既存方針。rm -rf 見直しもこの方針と矛盾しない範囲で行う）

## 成果物
- `vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-01-proposal.md`（`.claude/settings.json` 自体は変更しない）

## 受け入れ基準
- `T-01-proposal.md` に `## 案A`・`## 案B` の見出しがあり、それぞれ `.claude/settings.json` の変更前後を diff 形式のコードブロックで示している。確認コマンド：`grep -cE '^## 案[AB]$' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-01-proposal.md` の出力が `2`
- 各案の説明文が `rm -rf` という語を含み、`permissions.deny` の現行該当行に触れている。確認コマンド：`grep -c 'rm -rf' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-01-proposal.md` の出力が `2` 以上
- 各案について、リポジトリ内パス（`.`・`vault/`・`.claude/` 等の相対パス）への `rm -rf` は従来どおり拒否され続けることを1行以上で説明している（元の防止意図を壊さないことの根拠）
- Claude Code の `permissions.allow`/`permissions.deny` の優先順位（allow が deny に勝てるか等）を検証した結果、または「不明」と判断した根拠を `## 検証結果` に書いている。確認コマンド：`grep -c '^## 検証結果' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-01-proposal.md` の出力が `1`
- `.claude/settings.json` の実体は変更しない。確認コマンド：`git status --porcelain -- .claude/settings.json` の出力が空

## 決定済み
- 対象は `.claude/settings.json` の `permissions.deny` 内、`Bash(rm -rf *)` / `Bash(rm -fr *)` / `Bash(rm -r *)` / `Bash(rm -Rf *)` の4行。`permissions.allow` 側に `/tmp` 用の `rm -rf` エントリは現状無い
- 案の例（参考、そのまま採用しなくてよい。他の案でもよい）
  - 案A（deny を絞る）：`Bash(rm -rf *)` 系をリポジトリ内パスに限定するパターン群（例：`Bash(rm -rf .)` `Bash(rm -rf ./*)` `Bash(rm -rf vault/*)` `Bash(rm -rf .claude/*)` 等）に置き換える
  - 案B（allow を足す）：`permissions.allow` に `Bash(rm -rf /tmp/*)` 相当を追加し、`permissions.deny` は現状維持する
- どちらを採用するか、あるいは別の案にするかは人が決める。creator は両案を提示するところまでで止め、`.claude/settings.json` を実際に書き換えない
- Claude Code の allow/deny のマッチ規則（deny が allow より常に優先するか、パターンの具体性で結果が変わるか）を検証する場合、`.claude/settings.json` を一時的に書き換えて試してもよいが、確認後は必ず元に戻し、最終的に `git status --porcelain -- .claude/settings.json` が空になる状態で成果物を提出すること。検証しない（試せない）場合は「不明」と明記してよい
- `permissions.deny` の各パターンはプレフィックス一致（`Bash(<prefix> *)` 形式）とみなしてよく、正規表現ではない
- 提案ファイルの見出し以外の形式は自由。ただし受け入れ基準にある見出し・語は必ず含める
