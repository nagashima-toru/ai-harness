# T-0046 `todo_guard.py` を `plan_guard.py` に作り替え、計画票のタスク表を検査する

## 目的
`.claude/hooks/todo_guard.py` を `.claude/hooks/plan_guard.py` に作り替える。検査先を
`vault/todo.md` から「自分のブランチの計画票」（`vault/plans/*.md` のうち frontmatter の
`status` が `approved` の1件）のタスク表に変える。既存の5検査（doing2件以上／blocked で
question 空／status が5値以外／id 重複／データ行の列数が6でない）は意味を変えず移植する。加え
て、approved な計画票が2件以上見つかった異常（1ブランチ1計画の不変条件違反）を検出してブロック
する。

## 入力
- `.claude/hooks/todo_guard.py`（現行。5検査のロジックの移植元）
- `docs/vault-spec.md` 10節（plan_guard フックの判定）
- `vault/designs/D-001.md`「## 決定事項」「### 新しいディレクトリ構造」「## フェーズ3」
- `vault/templates/plan.md`（計画票の frontmatter とタスク表の形。見出しは `## タスク表（状態の
  正本）`、表の列は `id | status | attempt | after | title | question`）
- `.claude/settings.json`（PostToolUse フックのコマンドパスを直す）
- `scripts/smoke.sh`（`== todo_guard.py ==` セクションと共有ヘルパー `make_todo` の定義箇所）

## 成果物
- `.claude/hooks/plan_guard.py`（新規）。`.claude/hooks/todo_guard.py` は削除する
- `.claude/settings.json` の PostToolUse フックのコマンドパス更新
- `scripts/smoke.sh` の `== todo_guard.py ==` セクションを `== plan_guard.py ==` に書き換え、共通
  ヘルパー `make_plan` / `make_plan_task` を追加する

## 受け入れ基準
- `.claude/hooks/plan_guard.py` が存在し、`.claude/hooks/todo_guard.py` が存在しない。確認：
  `test -f .claude/hooks/plan_guard.py && test ! -e .claude/hooks/todo_guard.py && echo ok`
- `.claude/settings.json` の PostToolUse フックが `plan_guard.py` を指す。確認：
  `grep -c plan_guard.py .claude/settings.json` が1、`grep -c todo_guard.py .claude/settings.json` が0
- approved な計画票が0件なら何もしない（許可）、2件以上あるならブロックする（1ブランチ1計画の不変
  条件）。確認：`scripts/smoke.sh` に追加した該当ケース（allow 1件・block 1件）が通る
- 単一の approved 計画票のタスク表に対し、doing2件以上／blocked で question 空／status が5値以外
  ／id 重複／データ行の列数が6でない、の5パターンがそれぞれブロックし、正常な表とデータ行が無い
  表は許可される。確認：`scripts/smoke.sh` の `== plan_guard.py ==` セクションに該当ケースがあり通る
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

## 決定済み
- 計画票の走査：`vault/plans/*.md` を読み、各ファイルの frontmatter（先頭の `---` に挟まれた
  行）から `status:` の値を取る。`status: approved` のファイルだけを集める
- 0件（計画票が無い、またはどれも approved でない）→ 何もしない（許可）。2件以上 →
  ブロックし、該当する計画 ID（frontmatter の `id:`、無ければファイル名から `.md` を除いた値）を
  reason に列挙する（例：「approved な計画票が2件あります（P-a, P-b）。1ブランチにつき approved は
  1件にしてください」）
- 1件に絞れたら、そのファイルの本文で `## タスク表` で始まる行（`## タスク表（状態の正本）` の完全
  一致は求めない。前方一致でよい）を見出しとして探し、以降の `|` で始まる行をデータ行として集める
  （`todo_guard.py` の `raw_rows` と同じ規則：ヘッダ行・区切り行・空行は除く）。次の `## ` 見出しが
  出たら打ち切る
- 5検査のロジック・メッセージ文言は `todo_guard.py` をそのまま移植し、「todo.md」を「計画票」また
  は当該計画 ID に差し替えるだけでよい（判定の意味は変えない）
- `.claude/settings.json` は PostToolUse の `command` 文字列中の `todo_guard.py` を `plan_guard.py`
  に置換するだけ。`matcher`（`Write|Edit|MultiEdit|Bash`）や他の hooks エントリは変更しない
- `scripts/smoke.sh` の共通ヘルパー `make_todo`（`vault/todo.md` を作る）は削除しない。まだ
  `== stop_gate.py ==` と `== agent_write_guard.py ==` の両セクションが使っているため、このタスク
  で消すと他セクションが壊れる（T-0048 で全セクションの移行が終わってから削除する）
- 新設する共通ヘルパーの契約（T-0047・T-0048 がそのまま再利用するので、シグネチャを変えない）：
  - `make_plan <planID> <planStatus> <データ行...>` … `$TMP/vault/plans/<planID>.md` に
    frontmatter（`id: <planID>` / `status: <planStatus>`）と `## タスク表（状態の正本）` 見出し・
    ヘッダ行・区切り行・渡された各データ行を書く
  - `make_plan_task <id> <status> <attempt>` … `make_plan P-TEST approved "| <id> | <status> |
    <attempt> | - | テスト | |"` を呼ぶショートカット（旧 `make_todo` と同じ引数3つの形にして、
    他タスクでの置換を機械的にする）
  - 複数計画票を作る時は `mkdir -p "$TMP/vault/plans"` 済みの状態で `make_plan` を複数回呼べばよい
    （0件テストは `rm -rf "$TMP/vault/plans"`、2件テストは異なる planID で2回呼ぶ）
- `== plan_guard.py ==` セクションの実行方法は `run_todo_guard` 相当（`CLAUDE_PROJECT_DIR="$TMP"
  python3 "$PLAN_GUARD_HOOK"`、stdin は `{"hook_event_name":"PostToolUse","tool_name":"Edit"}` でよ
  い）を `run_plan_guard` として定義し直す

## 進捗
- 読んだルール: roles.md, creator.md
- `.claude/hooks/plan_guard.py` を新規作成し `.claude/hooks/todo_guard.py` を削除した。5検査ロジック
  と `raw_rows`/`parse_tasks` は todo_guard.py から移植（メッセージ文言を計画 ID 付きに差し替え）。
  approved 計画票の走査（`approved_plans`）・0件→許可／1件→検査／2件以上→ブロックを追加した
- `.claude/settings.json` の PostToolUse コマンドパスを `todo_guard.py` → `plan_guard.py` に変更した
- **ここで実害が発覚し停止した**：`vault/plans/*.md` を `grep -l '^status: approved$'` したところ
  20件（P-001〜P-017, P-019, P-020, P-021）が該当した。旧方式では計画の終端状態が `approved` のま
  まで（新方式で追加された `done` に相当する状態が無かった）、完了済みの計画も含めて全部
  `status: approved` を持ち続けている。plan_guard.py を settings.json に配線した瞬間、これを
  「1ブランチ1計画の不変条件違反（20件）」として検出し、以後のあらゆる Write/Edit/MultiEdit/Bash
  操作のたびに PostToolUse でブロック理由が出るようになった
- 根本原因：D-001 は「1セッション=1計画=1ブランチ」を git worktree による物理的な隔離が前提。この
  セッションは一度もブランチを切らず main に直接コミットしてきたため、過去の計画ファイルが同じ
  `vault/plans/` に全部残り続け、フックを配線した瞬間に不変条件違反が露呈した
- 「決定済み」に、旧計画ファイルの `status` をどう扱うか（今回のフェーズで `done` に一括移行する
  か、フェーズ4の凍結まで待つか、それまで plan_guard.py の配線自体を保留するか）の答えが無いため、
  自分で決めず blocked にした。すでに行った変更（plan_guard.py 作成・todo_guard.py 削除・
  settings.json 更新）は元に戻さず残した
- 人の判断：「今回のタスクで done に一括移行」「P-021 の残りも main 直コミットで続ける（worktree
  化はしない）」の2点。P-001〜P-017, P-019, P-020 の19ファイルの frontmatter を
  `status: approved` → `status: done` に書き換え、approved は P-021（作業中）のみ残した。
  `vault/designs/D-001.md` の「## 決定事項」にこの経緯を追記した。doing に戻して作業再開
- `grep -l '^status: approved$' vault/plans/*.md` で確認し、P-021 のみになったことを確かめた
- `scripts/smoke.sh` の `TODO_HOOK` を `PLAN_GUARD_HOOK`（`.claude/hooks/plan_guard.py`）に改名。
  `make_todo` の直後に共通ヘルパー `make_plan <planID> <planStatus> <データ行...>`（frontmatter +
  `## タスク表（状態の正本）` を書く）と `make_plan_task <id> <status> <attempt>`（`make_plan P-TEST
  approved "..."` のショートカット）を追加した。`make_todo` は削除していない（T-0048 まで残す。
  `stop_gate.py`/`agent_write_guard.py` の両セクションがまだ使っている）
- `== todo_guard.py ==` セクションを `== plan_guard.py ==` に書き換え、`make_plan`/`run_plan_guard`
  ベースの10ケース（既存5検査＋正常系2＋新規(f) 0件許可・2件以上ブロック＋vault/plans無し許可）にした
- 実行したところ、既存の T-0038/T-0039 が書いた `merge_settings_json.py`／`install.sh の
  settings.json 扱い` セクションの2ケースが NG になった。settings.json の実体が `todo_guard.py` から
  `plan_guard.py` に変わったため、`'todo_guard.py' in h['command']` という文字列一致チェックが成立
  しなくなったことが原因（テストの意図＝欠落 hooks の復元確認は変わらない）。該当2箇所の文字列を
  `plan_guard.py` に更新した。タスク票の範囲外だが、自分の変更が原因で smoke が壊れたため、
  `fail=0` の受け入れ基準を満たすために直した（判定ロジックや他の検証内容は変更していない）
- 受け入れ基準の確認コマンドを実行し、5件すべて通した
  - `test -f plan_guard.py && test ! -e todo_guard.py` → ok
  - `grep -c plan_guard.py settings.json`=1 / `grep -c todo_guard.py settings.json`=0
  - `== plan_guard.py ==` セクション全10ケース ok（0件許可・2件以上ブロックを含む）
  - 5検査（doing2件以上・blocked質問空・status不正・id重複・列数不一致）が全部ブロック、正常系と
    データ行無しは許可
  - `bash scripts/smoke.sh | tail -1` → `smoke: pass=91 fail=0`
