# T-02 planner ルールに「他ファイル不変」基準を git status --porcelain ベースにする提案を書く（issue #42）

## 目的
`vault/rules/planner/planner.md` に、「他タスクの成果物ファイルを変更していないこと」を確認する受
け入れ基準の確認コマンドは `git diff main -- <path>` ではなく `git status --porcelain` ベース（成
果物パス以外に変更が無いことを確認する形）で書くよう明記する。`vault/rules/` 配下は
`agent_write_guard.py` が常に書き込みを拒否するため、実体ではなく提案ファイルに下書きする。

## 受け入れ基準

  `grep -c "対象ファイル" vault/tasks/P-20260925-vcs-finish-push-and-diff-criteria/T-02-proposal.md`
  が1以上、かつ
  `grep -c "vault/rules/planner/planner.md" vault/tasks/P-20260925-vcs-finish-push-and-diff-criteria/T-02-proposal.md`
  が1以上
- 追記内容が、新方式として `git status --porcelain` を、置き換え対象の旧方式として
  `git diff main` をどちらも具体的に言及している。確認：
  `grep -c "git status --porcelain" vault/tasks/P-20260925-vcs-finish-push-and-diff-criteria/T-02-proposal.md`
  が1以上、かつ
  `grep -c "git diff main" vault/tasks/P-20260925-vcs-finish-push-and-diff-criteria/T-02-proposal.md`
  が1以上
- 見直しの理由として、`run`/`vault/rules/common/git.md` の運用（1計画=1ブランチに複数タスクを完
  了順に `git merge --no-ff` で逐次マージする）に触れている。確認：

  が1以上

  `vault/tasks/P-20260925-worktree-baseref-merge/` 配下のいずれも変更していない。確認：
  `git status --porcelain -- vault/rules/ vault/tasks/P-20260925-worktree-baseref-merge/` の出力
  が空

## 決定済み
- 提案ファイルのパスは `vault/tasks/P-20260925-vcs-finish-push-and-diff-criteria/T-02-proposal.md`
  に固定する。実体（`vault/rules/planner/planner.md`）への反映は人が手作業で行う。反映を自動化す
  るスクリプト・スキルは作らない
- 提案ファイルの構成は `vault/tasks/P-20260924-rules-guard/T-04-proposal.md` に倣い、「対象ファイ
  ル」「追記内容」「反映後の該当ファイル全文（参考）」の3構成にする
- 追記先は「やらないこと（このリポジトリで実際に起きた失敗から）」の箇条書きの末尾（既存4項目の
  後）に1項目追加する形でよい。既存4項目は「一般的な禁止 + 実際に起きた失敗の参照」という書き方
  をしているので、今回もその書式に合わせる
- 追記する内容の骨子（この通りの文面でなくてよいが、趣旨と受け入れ基準にある必須語句を含めるこ
  と）：他タスクの成果物ファイルを変更していないことを確認する受け入れ基準は、`git diff main --
  <path>` ではなく `git status --porcelain` ベース（成果物パス以外に変更が無いことを確認する形）
  で書く。理由：`run` は完了順にタスクを `git merge --no-ff` で計画ブランチへ逐次マージするため、
  後続タスクの検証時点では先行タスクの変更が既にブランチに含まれており、`main` との diff だと後
  続タスクが変更していないファイルまで非空になり誤検知する。実例として
  `P-20260925-worktree-baseref-merge` の T-01・T-03 で、過去2回 verifier が自力に `git status
  --porcelain` 等の代替確認で正しく PASS 判定した経緯を挙げてよい
- 既存の `vault/tasks/P-20260925-worktree-baseref-merge/T-01.md`・`T-03.md` は `done` 済みのため
  編集しない（参照のみ）
- `vault/rules/verifier/verifier.md`（issue #42 のもう一方の提案 (b)）への追記は必須ではない。今
  回のタスクの成果物には含めない（人の方針どおり、追記するかは今回のタスクの対象外とする）
- 「確認方法」節への追記（例：「他ファイル不変の基準が `git status --porcelain` ベースになってい
  るか」の1行）は任意。追加してもよいが、追加しない場合も受け入れ基準は満たせる
