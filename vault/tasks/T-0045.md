# T-0045 `vault/templates/plan.md` を新形式に更新する

## 目的
`vault/templates/plan.md` を、計画票が状態を持つ新方式（frontmatter に `status` の3値、本文にタス
ク表）に更新する。T-0041 が `docs/vault-spec.md` で固定した計画票の形式（frontmatter とタスク表の
列）をテンプレートに反映する。

## 入力
- `vault/templates/plan.md`（現行）
- `vault/tasks/T-0041.md`（計画票の形式の契約：frontmatter の `status` 3値、タスク表の列
  `id/status/attempt/after/title/question`）
- `docs/vault-spec.md`（T-0041 完了後の「計画票の形式」節）
- `vault/plans/P-019.md`（旧「タスク一覧（順序・依存・受け入れ基準の要約）」の書きぶりの参考。新方
  式ではこの表をタスク表に置き換えるため、そのまま真似しない）

## 成果物
- `vault/templates/plan.md`（1ファイル）

## 受け入れ基準
- frontmatter の `id` の例が計画 ID の新形式（`P-YYYYMMDD-<slug>`）になっている。確認：`grep -F
  'P-YYYYMMDD' vault/templates/plan.md` の出力が1行以上
- frontmatter の `status` の初期値が `draft` のままである。確認：`grep -F 'status: draft'
  vault/templates/plan.md` の出力が1行以上
- 本文にタスク表があり、列見出しが `id | status | attempt | after | title | question` である。確
  認：`grep -F '| id | status | attempt | after | title | question |' vault/templates/plan.md` の
  出力が1行以上
- `attempt` 列が含まれる。確認：`grep -c 'attempt' vault/templates/plan.md` が1以上
- 旧来の「タスク一覧（順序・依存・各タスクの受け入れ基準の要約）」という見出しが消えている。確認：
  `grep -c '順序・依存' vault/templates/plan.md` が0

## 決定済み
- frontmatter は `id` と `status` の2キーのまま（`docs/vault-spec.md` の計画票の節と一致させる）。
  `status` の例は `draft`（テンプレートなので draft のままでよい。`approved`/`done` は本文コメント
  で触れる必要はない）
- 本文の見出し構成は「# ゴール」「## 分割方針」「## タスク表（状態の正本）」「## 計画の受け入れ基
  準」の4つとする。旧テンプレートの「## タスク一覧（順序・依存・各タスクの受け入れ基準の要約）」
  は「## タスク表（状態の正本）」に置き換える（列を `id/status/attempt/after/title/question` に統
  一し、「順序」列と「受け入れ基準の要約」列は持たない。人向けの要約は「分割方針」に書く運用にする）
- タスク表のサンプル行は1行でよい（例：`| T-01 | todo | 0 | - | (title) | |`）
- 「## 計画の受け入れ基準」の3行（各タスクに成果物と受け入れ基準が1つずつある／依存に循環がない／1
  タスクが1コンテキストで終わる粒度である）は変更しない
- `docs/vault-spec.md` 側の節番号や見出し文言が T-0041 の想定と多少ずれていても、このタスクは
  `vault/tasks/T-0041.md`「決定済み」に書かれた列定義（`id/status/attempt/after/title/question`）
  を正として実装してよい（`docs/vault-spec.md` を読み直して不一致に気付いても、自分で仕様を変えず
  一致している方＝タスク票の決定済みに合わせる）

## 進捗
- 読んだルール: roles.md, creator.md
- `vault/templates/plan.md` を新形式に置き換えた
  - frontmatter：`id: P-YYYYMMDD-<slug>` / `status: draft`（2キーのまま）
  - 見出しを決定済みの4つに：`# ゴール` / `## 分割方針` / `## タスク表（状態の正本）` /
    `## 計画の受け入れ基準`
  - 旧「## タスク一覧（順序・依存・各タスクの受け入れ基準の要約）」を「## タスク表（状態の正本）」
    に置き換え、列を `id | status | attempt | after | title | question` に統一。「順序」列と
    「受け入れ基準の要約」列は持たせていない（人向けの要約は「分割方針」に書く運用）
  - サンプル行は決定済みのとおり1行（`| T-01 | todo | 0 | - | (title) | |`）
  - 「## 計画の受け入れ基準」の3行は無変更
- 受け入れ基準の確認コマンドを実行し、5件すべて通した
  - `P-YYYYMMDD`=1 / `status: draft`=1 / 6列のヘッダ行=1 / `attempt`=1 / `順序・依存`=0
- このタスクは `vault/templates/plan.md` の1ファイルだけを変更した。`docs/vault-spec.md` には
  触れていない（T-0041〜T-0044 の範囲）
