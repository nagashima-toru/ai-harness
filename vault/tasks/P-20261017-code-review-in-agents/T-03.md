# T-03 run の手順6で、人の判断を求める PASS の verdict を blocked に回す

## 目的
verifier がコードレビューで「直すのに設計・仕様の変更が要る」と判断した指摘（reasons の接頭辞 `人の判断が必要:`）を、done にせず blocked で人に渡せるようにする（GitHub Issue #214 の提案2の4点目）。verifier は状態を変えられないので、オーケストレーター（run）が verdict を見て遷移先を決める。

## 入力
- `.claude/skills/run/SKILL.md`（手順6「verdict に従う」と「transition.py の呼び出し（早見表）」）
- `.claude/agents/verifier.md`（T-01 で足した「## コードレビューを参照する基準の判定」節）
- `scripts/transition.py`（review→blocked の遷移は既存。`--worktree` を付けない呼び出しで行える）

## 成果物
- `.claude/skills/run/SKILL.md`（1ファイル）

## 受け入れ基準
- `grep -c 'ファイル. --note .人の判断が必要.' .claude/skills/run/SKILL.md` の出力が `2` である（早見表の1行と、手順6の3の1行）
- `grep -c '人の判断が必要:' .claude/skills/run/SKILL.md` の出力が `1` である
- 手順6の3（PASS の場合）が、done を呼ぶ前に verdict の `reasons` に接頭辞付きの要素があるかを確かめ、あれば その要素を言い換えずに質問ファイルに書いて blocked を呼び、done は呼ばずに次の対象タスクへ進むこと、接頭辞付きの要素が無ければ今までどおり done を呼ぶことを書いている（Read で確かめる）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1` である
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 手順6の3（`PASS` の場合）の冒頭に、次の趣旨を書く：「`reasons` に `人の判断が必要:` で始まる要素が1つでもあれば、done を呼ばない。その要素をすべて言い換えずに Write ツールで質問ファイル（例：`/tmp/<計画ID>-<id>-question.txt`）に書き、`python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --note "人の判断が必要"` を1回呼ぶ。終了コード0で blocked になり、worktree は残る（人が `/plan unblock` で答えた後、`--resume-worktree` で引き継いで再着手する）。次の対象タスクへ進む」。接頭辞の付かない要素（判定不能・緩い基準・`対象外（既存コード）:` など）だけなら今までどおり done を呼ぶ
- 接頭辞 `人の判断が必要:`（コロンは半角）はファイル中で1回だけ、手順6の3の上の文に書く。早見表の行や呼び出しの例には接頭辞を書かない（`--note "人の判断が必要"` はコロンを付けない）
- 呼び出しの形は `python3 scripts/transition.py <計画ID> <id> blocked --question-file <質問ファイル> --note "人の判断が必要"` に固定する。`--no-model` は付けない（verifier の判断による遷移なので、transition.py が log に `verifier=<モデル>` を付ける）。`--worktree` は付けない（`--worktree` 付きの blocked は doing からだけ）。この形はファイル中に2回（手順6の3の1回と早見表の1行）だけ書く
- 早見表には `| verifier が人の判断を求めた PASS（手順6。review→blocked） | <上の呼び出し> |` の形の行を、FAIL の行の後に1行足す
- 手順6の3の終了コードの説明には、blocked の呼び出しの終了コード0（blocked にした）と1（前提を満たさない。人に報告して止める）を足す
- 新しく作るファイルへのバッククォート参照は書かない（`(ref-1)` のため）
- `scripts/transition.py` は変えない（review→blocked は既存の遷移）。`docs/vault-spec.md` の log の補足の追記は T-05 で行う
