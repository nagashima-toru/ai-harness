# T-06 vault-spec の10節と関連する記述から承認の裏付けの検査を外し、自動承認に合わせる

## 目的
`docs/vault-spec.md` を、T-01〜T-03 の後の実際の状態（plan_guard は承認・unblock の裏付けを検査しない、agent_write_guard は承認を判定しない、`/plan` が自動で approved にする）に合わせる（D-015 フェーズ2）。

## 入力
- `vault/designs/D-015.md` の「決定事項」の表と「フェーズ2」の節
- `docs/vault-spec.md`（計画作成時の行番号で、2節の66行目・4節の97〜98行目・7節の180行目・10節の268行目と270行目・12節の306〜308行目と313〜317行目）
- T-01 後の `.claude/hooks/plan_guard.py`、T-02 後の `.claude/hooks/agent_write_guard.py`・`.claude/hooks/_hooklib.py`、T-03 後の `.claude/skills/plan/SKILL.md`

## 成果物
- `docs/vault-spec.md`（1ファイル）

## 受け入れ基準
- `/plan approve` が残っていない。確認：`grep -c "plan approve" docs/vault-spec.md` の出力が `0`
- 10節に会話記録の検査の記述が無い。確認：`sed -n '/^## 10\./,/^## 11\./p' docs/vault-spec.md | grep -c "会話記録"` の出力が `0`
- 7節に自動承認の log の形式がある。確認：`grep -c -F -- '- <日時> - draft→approved /plan による自動承認' docs/vault-spec.md` の出力が `1`
- 4節の status の表が自動承認になっている。確認：`grep -c -F '| `approved` | `/plan` が粒度の確認を通した後に自動で承認した。このブランチで進行中の計画 |' docs/vault-spec.md` の出力が `1`
- 12節の表から承認の行が消え、blocked の解除の行は残る。確認：`grep -c "（承認：draft→approved）" docs/vault-spec.md` の出力が `0`、`grep -c "（解除：blocked→他。" docs/vault-spec.md` の出力が `1`
- 見出しの数は変わらない。確認：`grep -c "^## \|^### " docs/vault-spec.md` の出力が `25`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む（参照切れの検査を含む）

## 決定済み
- 2節（transition.py の箇条書き）：「- 承認（draft→approved）と blocked の解除（`/plan approve`・`/plan unblock`）は扱わず、今の `/plan` の Edit のまま（10節の裏付けの検査が「HEAD と作業ツリーの比較」で働くため）」を「- 承認（draft→approved。`/plan` の自動承認）と blocked の解除（`/plan unblock`）は扱わず、`/plan` の Edit のまま」にする。2節の遷移の段落の「（フックが会話記録で裏付ける）」は変えない（`agent_write_guard.py` の unblock の判定が今も会話記録を見るため）
- 4節の status の表の2行を次にする
  - `| `draft` | planner が書いている間。粒度の検査（8節・10節）の対象で、まだ着手しない |`
  - `| `approved` | `/plan` が粒度の確認を通した後に自動で承認した。このブランチで進行中の計画 |`
- 7節：「`/plan approve` の承認は次の形で1行追記する（承認の根拠の記録）：`- <日時> - draft→approved 人の指示: /plan approve <計画ID>`」を「`/plan` の自動承認は次の形で1行追記する：`- <日時> - draft→approved /plan による自動承認`。D-015 フェーズ2 より前の承認の行（補足が `人の指示:` で始まるもの）は書き換えない」にする（この文に `plan approve` の語を書かない）
- 10節：「承認の裏付けの検査も plan_guard が行う（D-010 フェーズ4）。…」と「blocked の解除の裏付けの検査も plan_guard が行う（D-010 フェーズ5）。…」の2段落を消し、代わりに次の1段落を置く：「承認（draft→approved）と blocked の解除は、plan_guard では検査しない（D-015 フェーズ2 で廃止）。承認は `/plan` が粒度の確認を通した後に自動で行う。」（この段落に「会話記録」の語を書かない）。10節のほかの段落は変えない
- 12節の判定の表
  - 「対象が `vault/plans/<計画ID>.md` で、Write/Edit/MultiEdit により frontmatter の status を approved 以外…（承認：draft→approved）」の行を丸ごと消す
  - 会話記録（`~/.claude/projects/`）の行の「承認の裏付けが会話記録に依るため」を「blocked の解除の裏付けが会話記録に依るため」にする
  - blocked の解除の行の「（許可。警告は plan_guard が出す：10節）」を「（許可）」にする
- 12節の表の後ろの「**承認の裏付けの判定に使う会話記録**（agent_write_guard.py と plan_guard.py の両方が、…10節はここを参照する）：」の段落と箇条書き
  - 見出しの太字を「**blocked の解除の裏付けの判定に使う会話記録**」にし、括弧の中を「agent_write_guard.py が、フックに渡される `transcript_path` の会話記録（JSONL）を読む。解析は共通モジュール `.claude/hooks/_hooklib.py` の関数を使う」にする
  - 「- コマンドの一致：人の発言が `<command-name>/plan</command-name>` と、引数が `approve <計画ID>` の…」の箇条書きを消す
  - 「- 「読めない」：…この時はブロックせず許可し、警告に落とす。…」の「警告に落とす」を消し「この時はブロックせず許可する」にする
  - 「- `unblock` のコマンドの一致：承認と同じ形（スラッシュコマンドの `<command-args>`、または先頭が `/plan` の文）で、…」の「承認と同じ形」を外し、「人の発言が `<command-name>/plan</command-name>` を含みその `<command-args>` の、または先頭が `/plan` の文の、引数の先頭3トークンが `unblock <計画ID> <id>` であること」の趣旨に自己完結で書く。後ろの文は変えない
- 見出し（`## `・`### `）は追加も削除も名前の変更もしない
- 12節の `vault/rules/` の保護・提案ファイル方式・Bash の書き込み解析、9節など、上に挙げた以外の記述は変えない（D-015 フェーズ3〜5 で直す）
