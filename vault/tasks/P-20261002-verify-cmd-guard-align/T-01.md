# T-01 planner ルールに、ガードが拒否する確認コマンドの形とその避け方を追記する提案を書く

## 目的

- `docs/vault-spec.md` 12節「Bash の書き込み対象の解析（issue #91・#87）」

## 決定済み
- 成果物は提案ファイル1つ。`vault/rules/planner/planner.md` の実体は編集しない（ガードが常に拒否する）。中身は `planner.md` の変更後の全文にする（差分ではない）。現行の行は1文字も変えずに残し、追加だけを行う（既存の「複合コマンドにしない」項目の `/tmp` へのリダイレクトを勧める行もそのまま残す）
- 追加する場所：「やらないこと」の最後の項目（「コード変更を伴う受け入れ基準では、…」とその続き2行）の直後に新しい項目を足す。「確認方法」の最後の行の直後に確認項目を1行足す
- 新しい項目の先頭行はこの文字列にする（一字一句同じ）：`- 受け入れ基準の確認コマンドを、書き込みガード（agent_write_guard.py）が拒否する形で書かない。`
- 新しい項目の続きの行（2スペース字下げ。既存の項目と同じ書き方）には、次の事実を書く。どれも planner が現行のガードに verifier・planner のペイロードを渡して確かめたもの：
  - 対象：ガードは verifier・planner の Bash を、書き込み先が許可ディレクトリ（verifier は `vault/verdicts/`、planner は `vault/plans/`・`vault/tasks/`）か repo の外かで判定する。creator は `vault/plans/`・`vault/log/` への書き込みだけが拒否される
  - 拒否される形1：repo 内の、許可ディレクトリ以外へのリダイレクト。例 `echo x > README.md`（この文字列を書く）、`grep -c x README.md > count.txt`
  - 拒否される形2：インタプリタやコマンド置換を含む、解析できない形（`python3 -c`・`awk`・`bash -c`・`$(...)` など）の中にある `>`。解析できない形は従来の判定に落ち、引用符の中でも `>` をリダイレクトとみなし、直後の語を repo 内の書き込み先として扱う。例 `python3 -c "print(1 > 0)"`（この文字列を書く）、`awk -F: '$1>430'`。同じく解析できない形では、引用符の中の書き込み動詞の語（`git add`・`rm`・`cp` など）も書き込みとみなされうる
  - 拒否される形3：`git add`・`git commit` などの git の書き込み操作と、repo 内を対象にする `cp`・`mv`・`rm`・`tee`・`sed -i`（許可ディレクトリ内でも拒否される）
  - 避け方：比較は `>` を使わず、`grep -c` の出力を期待値と見比べる・`test <数> -gt <数>` を使う、構文の確認は `python3 -c` に `>` を含めずに書く（例：`ast.parse` を使う）、出力は標準出力で読む
  - 拒否されない形：`python3 -m py_compile`・repo の外（`/tmp/...` など）へのリダイレクト・`&&`／`;`／`|` の連結は、それだけではガードに拒否されない（この文字列「それだけではガードに拒否されない」を書く）。連結は区切りごとの書き込み先で判定される。拒否の理由に合わない代わりの手段を、受け入れ基準に書かない
  - 見分け方：ガードの拒否は reason が `[agent_write_guard]` で始まる（この文字列を書く）。そうでない拒否はガードの外（Claude Code の権限判定など）によるもので、この項目の対象ではない。ガードの外の判定については、既存の「複合コマンドにしない」項目に従う
- 「確認方法」に足す行は、文字列「書き込みガードの拒否する形」を含む1行にする。例：`- 確認コマンドが、書き込みガードの拒否する形（repo 内の許可外へのリダイレクト・解析できない形の中の \`>\`・git の書き込み操作など）を含んでいないか。`
- issue 番号・計画 ID・タスク ID（`#102`・`P-2026…` など）は書かない（`planner.md` は導入先に配布する汎用ルール。経緯は別の計画で `ai-harness-lessons.md` に書く）
- `python3 -m py_compile` を避けるようには書かない（ガードは拒否しない。`__pycache__/` は `.gitignore` 済みで `git status --porcelain` にも出ない）
- 文体：既存の `planner.md` に合わせる（である調・句点で終える）。1項目は先頭行と続きの行で7行以内を目安にする
- 確認コマンドを自分で実行する時、`>` や `git add` などの語を引用符の中に含むコマンドを `python3`・`bash -c`・ヒアドキュメントで包むと、ガードの従来の判定に当たって止められる。提案ファイルの検証は `grep`・`diff` を単体で実行する
