# T-04 plan の SKILL.md の手順4に planner の起動通知が返った時の待ち方を書く

## 目的
`run_in_background: false` を指定しても planner の Agent 呼び出しがバックグラウンドで起動して即座に戻る時に、/plan が完了通知を待ってから手順5以降に進み、出力ファイルの更新が10分止まればハングとして扱えるようにする。

- `.claude/skills/plan/SKILL.md`（「A. 計画を作る」の手順4）
- `.claude/skills/run/SKILL.md`（「ハング時の復旧」。参照するだけで変えない）

## 成果物

## 受け入れ基準

## 決定済み
- 手順4の「`run_in_background: false` を指定し、同期的に完了を待つこと」は消さない。その後ろに（同じ行か、手順4の下に字下げした項目として）、「それでも Agent ツールの結果が起動通知（バックグラウンド起動）だった時は、ターンを終えて完了通知を待ち、完了通知が来るまで手順5以降に進まない」旨を書く。「起動通知」「完了通知」「ターンを終え」の3語を同じ1行に書くこと
- 起動通知の見分け方は、Agent ツールの結果に「Async agent launched」「バックグラウンド」等の起動を表す文言があり、planner の完了の報告（計画 ID・タスク一覧）が無いこと、と書く。文言の完全一致に頼らない
- ハングの扱い：起動通知に含まれる出力ファイル（transcript）の最終更新時刻（`stat` などで見る）から10分進まなければハングとみなし、TaskStop で止める。止めた後は planner を自動で呼び直さず、計画票は draft のまま、ハングしたことを人に報告して止まる（planner にはタスクの状態遷移が無く、run の「ハング時の復旧」の transition.py の手順はそのまま当てはまらないため。人が `/plan` をやり直すか指示する）。出力ファイルのパスが分からない時はハングを判定せず、人に状況を報告して待つ。「10分」「出力ファイル」「TaskStop」の3語を同じ1行に書くこと
- 環境変数 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` を使う指示は書かない（語そのものを書かない）
- 手順4以外（手順5〜11、B 節、注意）は変えない
- バッククォートで囲むのは実在するパス・コマンド・書式の例にとどめる（smoke の (ref-1) がバッククォート内のパスの実在を検査するため）
