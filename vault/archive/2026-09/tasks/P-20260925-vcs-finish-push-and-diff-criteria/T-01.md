# T-01 vcs_finish.sh に PR/MR 作成前の自動 push を追加する（issue #44）

## 目的
`scripts/vcs_finish.sh` の `github`/`gitlab` 分岐が、現在のブランチに upstream（`origin` への push
済みの追跡ブランチ）が無いまま `gh pr create`/`glab mr create` を呼んで「まず push してください」
という趣旨のエラーで失敗するのを防ぐ。呼び出し前に upstream の有無を確認し、無ければ
`git push -u origin <現在のブランチ>` を実行してから本来のコマンドを呼ぶようにする。

## 入力
- `scripts/vcs_finish.sh`（変更対象。現状は `command -v gh`/`glab` の存在チェックの直後、無条件に
  `gh pr create "$@"`／`glab mr create "$@"` を呼んでいる）
- GitHub issue #44（`gh issue view 44`）：今回の動機・失敗の再現状況・人の提案（方針 (a) を採用済み）
- `vault/designs/D-005.md`（背景。`scripts/vcs_finish.sh` の既存設計。編集不要、参照のみ）
- `vault/tasks/P-20260925-vcs-finish-missing-cli/T-01.md`（`command -v` チェックを同スクリプトに
  追加した過去タスクの実例。テストの書き方の参考。編集不要、参照のみ）

## 成果物
- `scripts/vcs_finish.sh`

## 受け入れ基準
- upstream の無いブランチで `HARNESS_VCS_HOST=github` を指定して実行すると、`gh pr create` が呼ば
  れる前に `git push -u origin <ブランチ>` が実行され、テスト用のローカル bare リポジトリにその
  ブランチの ref ができる。確認：
  `SCRIPT="$(pwd)/scripts/vcs_finish.sh"; w=$(mktemp -d); git init --bare -q "$w/o.git"; git clone -q "$w/o.git" "$w/r"; git -C "$w/r" config user.email a@b.c; git -C "$w/r" config user.name t; git -C "$w/r" commit -q --allow-empty -m init; git -C "$w/r" push -q origin HEAD:main; git -C "$w/r" checkout -q -b work/test; mkdir -p "$w/bin"; printf '#!/bin/sh\necho called >> "$OUT"\n' > "$w/bin/gh"; chmod +x "$w/bin/gh"; (cd "$w/r" && OUT="$w/out" PATH="$w/bin:$PATH" HARNESS_VCS_HOST=github bash "$SCRIPT" >/tmp/vf1.log 2>&1); git ls-remote "$w/o.git" refs/heads/work/test | grep -q work/test && grep -q called "$w/out" && echo OK`
  の出力に `OK` が含まれる
- gitlab 側でも同様に、upstream の無いブランチで `HARNESS_VCS_HOST=gitlab` を指定すると push して
  から `glab mr create` を呼ぶ。確認：上記と同じ手順で `gh`/`github` を `glab`/`gitlab` に差し替
  えて実行し、出力に `OK` が含まれる（`SCRIPT="$(pwd)/scripts/vcs_finish.sh"; w=$(mktemp -d); git init --bare -q "$w/o.git"; git clone -q "$w/o.git" "$w/r"; git -C "$w/r" config user.email a@b.c; git -C "$w/r" config user.name t; git -C "$w/r" commit -q --allow-empty -m init; git -C "$w/r" push -q origin HEAD:main; git -C "$w/r" checkout -q -b work/test; mkdir -p "$w/bin"; printf '#!/bin/sh\necho called >> "$OUT"\n' > "$w/bin/glab"; chmod +x "$w/bin/glab"; (cd "$w/r" && OUT="$w/out" PATH="$w/bin:$PATH" HARNESS_VCS_HOST=gitlab bash "$SCRIPT" >/tmp/vf1b.log 2>&1); git ls-remote "$w/o.git" refs/heads/work/test | grep -q work/test && grep -q called "$w/out" && echo OK`）
- push 自体が失敗する場合（例：存在しないパスを `origin` に指定）、その失敗がそのままスクリプトの
  終了コードに伝播し、`gh`/`glab` は呼ばれない。確認：
  `SCRIPT="$(pwd)/scripts/vcs_finish.sh"; w=$(mktemp -d); git init -q "$w/r"; git -C "$w/r" config user.email a@b.c; git -C "$w/r" config user.name t; git -C "$w/r" commit -q --allow-empty -m init; git -C "$w/r" remote add origin "$w/does-not-exist.git"; git -C "$w/r" checkout -q -b work/test; mkdir -p "$w/bin"; printf '#!/bin/sh\necho called >> "$OUT"\n' > "$w/bin/gh"; chmod +x "$w/bin/gh"; (cd "$w/r" && OUT="$w/out" PATH="$w/bin:$PATH" HARNESS_VCS_HOST=github bash "$SCRIPT" >/tmp/vf2.log 2>&1); code=$?; [ "$code" -ne 0 ] && [ ! -f "$w/out" ] && echo OK`
  の出力に `OK` が含まれる
- upstream の確認と push の呼び出しは、`github`/`gitlab` 各分岐で `gh pr create`/`glab mr create`
  （既存の `command -v` チェックより後）を呼ぶ直前に置かれている。確認：`scripts/vcs_finish.sh` を
  読み、`gh pr create "$@"` および `glab mr create "$@"` それぞれの直前に upstream 確認・push の
  処理があることを目視で確認する
- `git status --porcelain -- scripts/` の出力が `scripts/vcs_finish.sh` の変更行以外を含まない（こ
  のタスクで変更するのは `scripts/vcs_finish.sh` だけ）。確認：`git status --porcelain -- scripts/`
  の出力が `?? `/` M` などの接頭辞を除き `scripts/vcs_finish.sh` 以外を含まない

## 決定済み
- upstream の有無は `git rev-parse --abbrev-ref --symbolic-full-name @{u}` （または同等の
  `@{upstream}` 記法）の終了コードで判定してよい。成功すれば push 済みとみなしそのまま
  `gh pr create`/`glab mr create` を呼ぶ
- 無い場合に実行する push は `git push -u origin "<現在のブランチ>"`。現在のブランチ名は
  `git rev-parse --abbrev-ref HEAD` で取得する
- push が失敗した場合の追加のエラーハンドリング（リトライ・メッセージの作り込みなど）は不要。
  push コマンドの終了コードが非0ならスクリプトもその時点で非0で終了してよい（`set -e` を新たに
  足す必要はなく、`if ! git push ...; then exit <非0>; fi` のような明示的な分岐でよい）
- 既にある `command -v gh`/`command -v glab` の存在チェック（無ければ exit 127 で案内）は変更しな
  い。upstream 確認・push はこのチェックの後、`gh pr create "$@"`／`glab mr create "$@"` を呼ぶ直
  前に追加する
- `none` 分岐・未知の `HARNESS_VCS_HOST` を扱う default 分岐は変更しない
- `.claude/skills/run/SKILL.md`・`.claude/skills/design/SKILL.md` 側の記述変更は不要（人の方針どお
  り、push はスクリプト側で自動化するため通常は不要。追記してもよいが、その場合も「push は自動化
  されている」という前提を崩さない範囲にとどめること。今回の成果物には含めない）
- テストで `gh`/`glab` を本物のコマンドとして呼ばないよう、PATH の先頭に置いたダミー実行可能ファ
  イル（呼ばれたら `$OUT` に1行書いて exit 0 する）で代替する。本物の GitHub/GitLab API は叩かない
- `gh pr merge`/`glab mr merge` の実行は追加しない（マージは人が行うという既存方針を維持する）

## 進捗
- 読んだルール: vault/rules/common/git.md, vault/rules/common/roles.md, vault/rules/creator/creator.md, vault/rules/creator/git-workflow.md
- `scripts/vcs_finish.sh` の github/gitlab 分岐に、`gh pr create`/`glab mr create` 呼び出し直前で
  `git rev-parse --abbrev-ref --symbolic-full-name @{u}` により upstream の有無を確認し、無ければ
  `git push -u origin "<現在のブランチ>"` を実行する処理を追加した
- 初回実装は `if ! git push ...; then exit $?; fi` の形にしたが、`! command` の直後の `$?` は
  否定演算後の値（成功なら0）になり push の実際の失敗コードを拾えないバグがあったため、
  `git push ...; push_status=$?; if [ "$push_status" -ne 0 ]; then exit "$push_status"; fi` の形に
  修正した（bash -c 'false; if ! false; then echo $?; fi' で0になることを確認して気づいた）
- 受け入れ基準の確認コマンドを3件とも実行し、いずれも `OK` が出力されることを確認した
  （github: push→gh呼び出し／gitlab: push→glab呼び出し／push失敗時にgh未呼び出しで非0終了）
- `git status --porcelain -- scripts/` の出力は `M scripts/vcs_finish.sh` のみで、他のファイルは
  含まれないことを確認した
- `bash -n scripts/vcs_finish.sh` で構文チェックOK
- `command -v gh`/`command -v glab` チェック、`none`/default 分岐は変更していない
