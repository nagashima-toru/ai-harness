# T-03 run スキルの verdict 読み取り手順に worktree 側フォールバックを追記する

## 目的
verifier が worktree 側に verdict を書いてしまった場合に備え、`.claude/skills/run/SKILL.md` 手順6「verdict に従う（逐次処理）」の verdict 読み取り箇所に、メインリポジトリ側に見つからない時は対象タスクの worktree 側の同じ相対パスを確認し、あればメインリポジトリ側へコピーして続行するフォールバックを追記する（issue #61 で人手で行った復旧を手順化する）。

## 入力
- `.claude/skills/run/SKILL.md` 手順6の冒頭（「全 verifier の完了を待った上で、対象タスクを1件ずつ…」から始まる節、既存のサブステップ「1. `vault/verdicts/<計画ID>/<id>.json` を読み、`result` と `attempt` を確認する。…」を含む）
- 手順3.4（対象タスクの worktree のパスをタスク ID に紐づけて run のセッション内で保持する、という既存記述。フォールバック時に参照する worktree のパスの出どころ）

## 成果物
- `.claude/skills/run/SKILL.md`（1ファイル、手順6のサブステップ追記のみ）

## 受け入れ基準
- `grep -n "配下の同じ相対パス" .claude/skills/run/SKILL.md` の出力が1行以上ある（worktree 側の同一相対パスを確認するフォールバックが追記されている）
- `grep -n "worktree側からコピー" .claude/skills/run/SKILL.md` の出力が1行以上ある（コピー後にログへ記録する手順が追記されている）
- `grep -n "vault/verdicts/<計画ID>/<id>.json.*が存在しない場合" .claude/skills/run/SKILL.md` の出力が1行以上ある（既存の手順6.1の直前または直後に、verdict 不在時の分岐が明記されている）
- `git status --porcelain -- . ':!.claude/skills/run/SKILL.md' ':!vault/tasks/P-20260926-verifier-verdict-worktree-path/T-03.md'` の出力が空（成果物とタスク票以外に変更が無い）

## 決定済み
- 挿入位置：手順6の各タスク処理の最初のサブステップ（既存の「1. `vault/verdicts/<計画ID>/<id>.json` を読み、`result` と `attempt` を確認する。…」の直前、または同じサブステップの冒頭）に新しい分岐を追加する。既存のサブステップ番号は振り直してよい
- 追記する内容の骨子（この趣旨を満たせば文言は自由。ただし受け入れ基準の grep 対象になる次のフレーズはそのまま含めること）：
  - 「`vault/verdicts/<計画ID>/<id>.json` が存在しない場合」という条件を明記する
  - 確認先として「対象タスクの worktree のパス（手順3.4で保持したもの）配下の同じ相対パス」を確認する旨を書く
  - 見つかった場合は `cp` でメインリポジトリ側のパスへコピーし、`vault/log/<計画ID>.md` に復旧した旨（「worktree側からコピー」という語を含む1行）を追記してから、コピーした verdict を通常どおり読む
  - worktree 側にも見つからない場合は、既存の「`attempt` が一致しない verdict」の扱いと同様に、検証未完了として次のタスクに進まず処理を止め、人に確認する
- `cp` は run のメインセッション（オーケストレーター）自身が実行する。`agent_write_guard.py` の書き込み制限はサブエージェント（verifier/planner/creator）向けであり、メインエージェントの `vault/verdicts/` への書き込みは制限されないため実行できる
- 手順6の PASS/FAIL 処理（マージ・done/blocked への遷移）のロジック自体は変更しない。今回はこのサブステップの直前に分岐を1つ足すだけ
