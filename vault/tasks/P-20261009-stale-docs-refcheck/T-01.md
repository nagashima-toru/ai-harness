# T-01 design/SKILL.md の vault/todo.md と第14節を、vault/plans/ と vault-spec.md 13節に直す

## 目的
`/design` スキルの本文から、廃止した `vault/todo.md` への言及と存在しない「第14節」を無くし、今の仕様（`docs/vault-spec.md` の13節・計画票の置き場 `vault/plans/`）を指すようにする。

## 入力
- `.claude/skills/design/SKILL.md`（直す対象。7行目・21行目・39行目）
- `docs/vault-spec.md` の13節「設計文書（`vault/designs/`）」と1節（ディレクトリ）
- `vault/designs/D-013.md` の「フェーズ7」

## 成果物
- `.claude/skills/design/SKILL.md`（1ファイル）

## 受け入れ基準
- 主な文書に `vault/todo.md` が残っていない：`grep -rn "vault/todo.md" .claude/skills .claude/agents .claude/ai-harness.md README.md docs/vault-spec.md docs/runbook.md docs/install.md` の出力が空
- 「第14節」が無い：`grep -c '第14節' .claude/skills/design/SKILL.md` の出力が `0`
- 仕様の参照先が13節になっている：`grep -c '仕様は `docs/vault-spec.md` の13節「設計文書（`vault/designs/`）」。' .claude/skills/design/SKILL.md` の出力が `1`。かつ参照先が実在する：`grep -c '^## 13\. 設計文書（`vault/designs/`）$' docs/vault-spec.md` の出力が `1`
- 調査の手順が計画票の置き場を指している：`grep -c '`vault/plans/`（既存の計画と重複しないか）' .claude/skills/design/SKILL.md` の出力が `1`
- 注意の節の書き込まない先が今の置き場になっている：`grep -c '^- `vault/plans/`・`vault/tasks/` には何も書かない。状態を変えない$' .claude/skills/design/SKILL.md` の出力が `1`
- 見出しの数が変わっていない：`grep -c '^## ' .claude/skills/design/SKILL.md` の出力が `3`

## 決定済み
- 直すのは次の3か所だけ。ほかの行（frontmatter・手順の番号・文言）は変えない
  1. 7行目の末尾「仕様は `docs/vault-spec.md` の第14節。」を「仕様は `docs/vault-spec.md` の13節「設計文書（`vault/designs/`）」。」にする（この文字列をそのまま書く。「節」の前に「第」を付けない）
  2. 21行目（手順2「調査する」）の「`vault/todo.md`（既存の計画・タスクと重複しないか）」を「`vault/plans/`（既存の計画と重複しないか）」にする（この文字列をそのまま書く）
  3. 39行目（注意の節）の「- `vault/todo.md` には何も登録しない。状態を変えない」を「- `vault/plans/`・`vault/tasks/` には何も書かない。状態を変えない」の1行にする（行末に句点を付けない）
- 13節を正とする理由：`docs/vault-spec.md` の設計文書の節は今「## 13. 設計文書（`vault/designs/`）」で、14節は無い。`docs/vault-spec.md` は変えない
- `docs/decisions.md` は判断の記録なので直さない（このタスクの対象外）
- 新たにバッククォートで書くパスは実在するものだけにする（T-05 の参照切れの検査の対象になる）。`vault/plans/`・`vault/tasks/` は実在する
- 文書だけの変更なので、確認は受け入れ基準の grep で行う。`bash scripts/smoke.sh` は実行しなくてよい
- このファイルの編集が拒否された時（サンドボックスの書き込み保護などで `.claude/skills/` の下を変えられない時）は、別の手段で書き換えようとせず、拒否の理由を question に書いて `blocked` にする
