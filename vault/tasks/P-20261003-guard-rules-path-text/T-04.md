# T-04 planner ルールの解析できない形の説明に vault/rules/ のパス文字列と例外を足す提案を書く

## 目的
T-02・T-03 で、本文が `cat` のヒアドキュメントだけのコマンド置換と、先頭の `cd <リポジトリのルート>` が解析できる形になった。`vault/rules/planner/planner.md` の「(2) 解析できない形」の説明に、`vault/rules/` のパス文字列があるだけで拒否されうることと2つの例外を足し、「避け方」に分けて実行するか Read で読む1文を足す提案を作る。

## 入力
- `vault/rules/planner/planner.md`（現行の実体。46行目の (2) と48行目の「避け方」が対象）
- `vault/tasks/P-20261003-planner-no-tmp-redirect/T-01-proposal.md`（提案ファイルの書き方の手本。変更後の全文だけを書く）
- `docs/vault-spec.md` 12節「提案ファイル方式」

## 成果物
- `vault/tasks/P-20261003-guard-rules-path-text/T-04-proposal.md`：`vault/rules/planner/planner.md` を変更した後の全文（`vault/rules/` には書けないため提案ファイル方式。実体への反映は人が行う）

## 受け入れ基準
- 提案ファイルが変えたのは、46行目の後への1行の追加と、48行目（追加後は49行目）の1行だけ。確認：`diff vault/rules/planner/planner.md vault/tasks/P-20261003-guard-rules-path-text/T-04-proposal.md` の出力がちょうど6行で、ハンク見出しが `46a47`・`48c49` の2つ
- 追加した行に、パス文字列だけで拒否されうることと cd の例外の限界が書かれている。確認：`grep -c -F 'を含む語があるだけで、それを書き込み先とみなして拒否されうる' vault/tasks/P-20261003-guard-rules-path-text/T-04-proposal.md` が `1`、`grep -c -F 'cd 先がルート以外（worktree など）の時は解析できない形のままになる。' vault/tasks/P-20261003-guard-rules-path-text/T-04-proposal.md` が `1`
- 「避け方」の行末に、分けて実行するか Read で読む1文が足されている。確認：`grep -c -F 'と同じコマンドにつながず分けて実行するか、Read で読む。' vault/tasks/P-20261003-guard-rules-path-text/T-04-proposal.md` が `1`
- 追加・変更した2行が「決定済み」の文と一字一句同じ。確認：提案ファイルの47・49行目を Read で読み、「決定済み」の文と見比べる
- 提案ファイルに、このリポジトリ固有の issue 番号・計画 ID が無い。確認：`grep -nE 'issue #|P-20[0-9]{6}' vault/tasks/P-20261003-guard-rules-path-text/T-04-proposal.md` の出力が空

## 決定済み
- 成果物は提案ファイル1つ。`vault/rules/planner/planner.md` の実体は編集しない（ガードが常に拒否する）。中身は変更後の全文（差分ではない。見出しや前置きも足さない）。`planner.md` を Read で読んで Write で書く（`cp` は使わない。引数に `vault/rules/` を含む `cp` はガードが拒否する）
- 変更は2か所だけ。他の行は1文字も変えない（「確認方法」も変えない）：
  - 46行目（`  (2) インタプリタやコマンド置換を含む…書き込みとみなされうる。`）の直後に、次の1行を新しく足す（行頭は半角空白2つ。一字一句同じ）：
    `` 同じ形では、コマンドのどこかに `vault/rules/` を含む語があるだけで、それを書き込み先とみなして拒否されうる（引数・引用符の中・ヒアドキュメントの本文でも。コマンドの別の場所にリダイレクトか書き込み動詞がある時）。例外として、本文が `cat` のヒアドキュメントだけのコマンド置換（`--body "$(cat <<'EOF' … EOF)"` の形）と、先頭の `cd <リポジトリのルート>`（`;` か `&&` で後ろに続くもの）は解析できる形として扱われる。cd 先がルート以外（worktree など）の時は解析できない形のままになる。 ``
  - 48行目（`  避け方：比較は…（上記の「複合コマンドにしない」項目の代替に従う）。`）は元の行を変えずに残し、行末（「…代替に従う）。」の直後、空白を挟まず）に次の1文を足す（一字一句同じ）：
    `` `vault/rules/` のパスを含むコマンドは、解析できない形（上の (2)）と同じコマンドにつながず分けて実行するか、Read で読む。 ``
  - 上の `` ... `` は表記のための囲みで、前後の `` `` `` と内側の半角空白1つずつは行に含めない。`…` は全角の三点リーダー1文字
- planner が事前に確かめたこと：上の2か所で現行の全文を組み立て（ファイルには書かず python の中で）、`diff` の出力が `46a47`（見出しと `>` の1行）と `48c49`（見出し、`<` の1行、`---`、`>` の1行）の6行になることを確認した。現行の `planner.md` には issue 番号・計画 ID が無い
- `vault/rules/planner/ai-harness-lessons.md` に経緯は足さない（成果物を1つに保つ）
- T-02・T-03 が blocked のまま人の手で適用された場合でも、この提案の文は変えない（適用後の挙動を書いた文のため）
- 確認コマンドを自分で試す時、`vault/rules/` のパスを含む `diff` は単一コマンドで実行する（`cd`・`$(`・インタプリタと同じコマンドにつながない）
- コミットは不要（受け入れ基準に無い）
