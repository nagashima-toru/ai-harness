# T-0014 ルール拡張ポイントの通し検証を行い docs/decisions.md に記録する

## 目的
`vault/rules/` 拡張ポイント（ディレクトリ振り分け・`scripts/rules.sh`・run-queue/verifier/planner の読み込み・`agent_write_guard.py` の改ざん防止）が一時インストール先で実際に機能することを、`claude -p` の子プロセスで確かめ、結果を `docs/decisions.md` に記録する。

## 入力
- `docs/roadmap-rules-extension.md` の「## ⑧ 通し検証」節（`/plan` 渡し文・受け入れ基準候補・決定済みの原案）
- `docs/vault-spec.md`（12節「ルール」、13節「agent_write_guard フックの改ざん防止判定」）
- `docs/decisions.md`（既存の書式：`| 日付 | 何を | なぜ |` の1行テーブル）
- `scripts/install.sh`、`scripts/rules.sh`、`.claude/hooks/agent_write_guard.py`、`.claude/skills/run-queue/SKILL.md`、`.claude/agents/verifier.md`、`.claude/agents/planner.md`

## 成果物
- `docs/decisions.md` への追記（通し検証で確認した結果・所要時間・気付いた既定値を1件1行で追加。既存行は変更しない）

## 受け入れ基準
- `docs/decisions.md` に通し検証に関する行が追記されている：確認コマンド `git diff -- docs/decisions.md | grep -c '^+|'` が1以上
- 追記行のいずれかに `vault/rules/` という文字列が含まれる：確認コマンド `grep -c 'vault/rules' docs/decisions.md`（実行前より増えていること）
- 一時ディレクトリでの `claude -p --model sonnet "/run-queue"` 実行で、作成エージェント・verifier がルールを読んだ記録（タスク票「進捗」の「読んだルール」行、verdict.json の該当 criteria の `note` に含まれるルールファイルのパス）が得られたか、得られなかった場合はその旨と手順を `docs/decisions.md` に記録している
- `agent_write_guard.py` を doing 中の `vault/todo.md` を用意して単体呼び出しし、`vault/rules/` 配下への Write が deny されたことを確認し、その結果が `docs/decisions.md` に記録されている
- ハーネス本体（このリポジトリ）の `vault/rules/{common,creator,verifier,planner}/` に `.gitkeep` 以外のファイルが増えていない：確認コマンド `find vault/rules/common vault/rules/creator vault/rules/verifier vault/rules/planner -type f ! -name '.gitkeep'` の出力が空
- `bash scripts/smoke.sh | tail -1` が `fail=0` を含む

## 決定済み
- 一時ディレクトリは `mktemp -d` で作り、`bash scripts/install.sh <tmpdir>` で複製後 `git init` する。検証終了後、一時ディレクトリは削除してよい（コミット対象にしない）。ハーネス本体側の変更は `docs/decisions.md` の追記のみ
- 仮ルールは一時ディレクトリの `vault/rules/common/naming.md`（例：シェルスクリプトの関数名は snake_case）と `vault/rules/verifier/check.md`（例：確認観点）に置く。ハーネス本体の `vault/rules/` には置かない
- 一時ディレクトリの `todo.md` に直接1件のタスク（例：`scripts/hello.sh` を作る。受け入れ基準に「`vault/rules/common/naming.md` に従っている」を含める）を登録してから `claude -p --model sonnet "/run-queue"` を子プロセスで実行する。対応するタスク票（例：`vault/tasks/T-0001.md`）も一時ディレクトリ側に手作業で用意する
- 一時インストール先は `claude -p` の前に一度対話起動してフォルダを信頼させる必要がある（`README.md`/`install.sh` の案内どおり）。信頼設定や環境制約により無人実行（`claude -p`）が通らない場合は、実行できなかった旨・試した手順・エラー内容を `docs/decisions.md` に1行で記録し、このタスクは `blocked` にしてよい。その場合も (5) の `agent_write_guard.py` 単体確認は独立して実行し、結果を記録する
- (5) の `agent_write_guard.py` 単体確認は、doing 中の行を含む `todo.md` をどこかの作業ディレクトリ（一時ディレクトリで可）に用意し、`echo '<PreToolUse用JSONペイロード>' | python3 .claude/hooks/agent_write_guard.py`（またはそれに準ずる直接呼び出し）で行う。子プロセスの `claude -p` を介さなくてよい
- `docs/decisions.md` への追記は既存の書式（`| 日付 | 何を | なぜ |` の1行、日付は `TZ=Asia/Tokyo date '+%Y-%m-%d'`）に合わせ、複数の確認事項がある場合は複数行に分けてよい
- git のコミットは受け入れ基準に含めていないため行わない（コミットするかは人の判断に委ねる）
