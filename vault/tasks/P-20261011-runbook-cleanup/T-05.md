# T-05 決定事項を docs/decisions.md に取り出し設計文書を削除する

## 目的
D-20261011-user-guide の最終フェーズとして、設計文書の「決定事項」を `docs/decisions.md` に取り出し、読まれなくなった設計文書 `vault/designs/D-20261011-user-guide.md` を削除する。

## 入力
- `vault/designs/D-20261011-user-guide.md` の「決定事項」の表（6行）
- `docs/decisions.md`（表の形と、設計文書由来の行の書き方。例：2026-10-11 の `（D-20261010-base-branch-config）` の行）
- `docs/vault-spec.md` 13節の「最終フェーズでの削除」

## 成果物
- `docs/decisions.md`（主な成果物。表の末尾に6行を足す）
- `vault/designs/D-20261011-user-guide.md`（削除）

## 受け入れ基準
- `test ! -e vault/designs/D-20261011-user-guide.md` が終了コード0で終わる
- `grep -c '^| 2026-10-11 | [^|]*（D-20261011-user-guide） |' docs/decisions.md` が `6`
- `grep -c '^| 20' docs/decisions.md` が `49`（既存の43行を残し、6行だけを足している）
- 足した6行が設計文書の「決定事項」の6行と1対1に対応し、各行の「なぜ」に設計文書の「なぜ」の内容（人の選択・人の要望である旨を含む）が書かれている（設計文書は削除済みなので、verifier はこのタスク票の「決定済み」の6項目と照らして確かめる）
- `grep -rn 'vault/designs/D-20261011-user-guide' README.md docs .claude/skills .claude/agents .claude/ai-harness.md scripts` の出力が空
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<数> fail=0`

## 決定済み
- 削除は `git rm vault/designs/D-20261011-user-guide.md` で行ってよい（`vault/designs/` は差分ゲートの禁止対象ではない。`docs/vault-spec.md` 13節）。`rm -rf` は使わない。
- 6つの決定事項はどれも `docs/decisions.md` に無いので、6つとも足す（「docs に無いもの」の判定はこれで確定。configuration.md・guide.md・runbook の本文に結果は反映済みだが、決めた理由は decisions.md に無いため）。
- 行の形：`| 2026-10-11 | <何を>（D-20261011-user-guide） | <なぜ> |`。日付は `2026-10-11`、「何を」の末尾に全角括弧で `（D-20261011-user-guide）` を付ける（既存の `（D-20261010-base-branch-config）` の行と同じ）。セルの中に `|` を書かない。既存の行は変えず、表の末尾に足す。
- 足す6行の中身（設計文書の「決定事項」の表の写し。言い換えは文の調子をそろえる程度にとどめ、意味を変えない）：
  1. 何を：環境変数リファレンス `docs/configuration.md` とやりたいこと別の入口 `docs/guide.md` の2ファイルを作り、`README.md` から両方へリンクする／なぜ：人の選択。一覧（引く場所）と入口（探す場所）を分け、既存の install・runbook の手順は重ねて書かずにリンクで辿らせる
  2. 何を：2ファイルは導入先に配らない（`scripts/install.sh` の配布対象に足さない）。ai-harness リポジトリで読む／なぜ：人の選択。`docs/install.md`・`docs/runbook.md` と同じ扱い。導入先の docs を増やさない（原則8）
  3. 何を：環境変数の一覧とコードのずれは `scripts/smoke.sh` で検査する。表は手で書き、`scripts/`・`.claude/` に出てくる `HARNESS_*` がすべて表にあること、表の変数がすべてコードに出てくることを確かめる／なぜ：人の選択。自動生成の仕組みを増やさず、変数を足した時の書き忘れだけを機械で止める（原則2）
  4. 何を：利用者向けガイドの範囲は、環境変数リファレンス・やりたいこと別の入口・runbook 全体の人向け整理まで。`settings.json` の権限やスキル引数のリファレンス化は含めない／なぜ：人の選択
  5. 何を：環境変数の既定値は「未設定の時に実際に使われる値」をコードから書き、経路で違うものはその旨を書く（例：`HARNESS_STRICT_STOP` は Stop フック単体では `0`、`scripts/run_unattended.py` 経由では `1` を入れて渡す）／なぜ：人の要望「各変数のデフォルト値も分かるようにする」。値が1つに決まらないものを1つに書くと誤る
  6. 何を：runbook はエージェントが内部でやること（transition.py が何を書くか等）を本文に持たない。仕様は `docs/vault-spec.md`、手順はスキル（`.claude/skills/*/SKILL.md`）が正本で、runbook はそこへリンクする。runbook にしか無い内部仕様は削らずに `docs/vault-spec.md` へ移す／なぜ：人の選択「runbook 全体の整理」。runbook を「人が日々やること」に絞り、仕様の二重持ちをやめる
- `docs/decisions.md` は smoke の `(ref-1)` の対象外だが、バッククォートで書くパスは実在するものにする（`HARNESS_*` や `.claude/skills/*/SKILL.md` のような `*` を含む形はそのままでよい）。
- 計画の前のタスク（T-01〜T-04）は `docs/decisions.md` を変えないので、着手時点の表の行数は43行（`grep -c '^| 20' docs/decisions.md` が `43`）。
