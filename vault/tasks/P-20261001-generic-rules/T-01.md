# T-01 planner.md 汎用版の提案を書く

## 目的
導入先に配る `vault/rules/planner/planner.md` を、ハーネスの仕組みに関わる汎用の規律だけに絞った全文を提案として書く。契約タスクの項と、このリポジトリ固有の経緯（T-xxxx・計画 ID・issue 番号）を外す（D-010 フェーズ10、#80）。

## 入力
- `vault/rules/planner/planner.md`（現行の実体。これを元に書く）
- `vault/templates/rule.md`（見出し構成：目的 / ルール / 確認方法）
- `vault/designs/D-010.md` のフェーズ10

## 成果物
- `vault/tasks/P-20261001-generic-rules/T-01-proposal.md`（汎用化した `vault/rules/planner/planner.md` の全文）

## 受け入れ基準
- 提案ファイルの見出しが `## 目的`・`## ルール`・`## 確認方法` の3つである（`grep -c -E '^## (目的|ルール|確認方法)$' vault/tasks/P-20261001-generic-rules/T-01-proposal.md` が `3`）
- 固有の経緯の文字列が無い（`grep -c -E 'T-00|P-2026|issue #|#[0-9]|このリポジトリ' vault/tasks/P-20261001-generic-rules/T-01-proposal.md` が `0`）
- 契約タスクの項が無い（`grep -c '契約' vault/tasks/P-20261001-generic-rules/T-01-proposal.md` が `0`）
- 「ルール」節の箇条（行頭 `- `）が、現行18から契約の1項目だけ減った17である（`awk '/^## ルール/{f=1;next} /^## /{f=0} f && /^- /{n++} END{print n}' vault/tasks/P-20261001-generic-rules/T-01-proposal.md` が `17`）
- 「確認方法」節の箇条が現行と同じ11である（`awk '/^## 確認方法/{f=1;next} /^## /{f=0} f && /^- /{n++} END{print n}' vault/tasks/P-20261001-generic-rules/T-01-proposal.md` が `11`）
- 汎用の教訓が残っている（`grep -c -F '複合コマンド'`・`grep -c -F 'git status --porcelain'`・`grep -c -F 'mkdir -p'`・`grep -c -F '起点コミット'`・`grep -c -F '出現回数'` を提案ファイルに対してそれぞれ実行し、いずれも1以上）

## 決定済み
- 提案ファイルは全文で書く（差分ではなく）。人がそのまま `vault/rules/planner/planner.md` へコピーできるようにする。ファイル冒頭に「これは提案です」などの前置きや frontmatter は付けない（中身はそのまま実体になる文面だけ）
- 外すのは2種類だけ：(a) 「責務」の「型・API・テスト雛形などの契約タスクを先に切り、実装タスクを `after` でそれに依存させる。」の1項目、(b) T-xxxx・計画 ID（`P-2026...`）・issue 番号（`issue #NN`・`#NN`）と、その経緯の説明文（「T-0002 が blocked になった」「verifier が固定パスに書き換えて回避した」など、何が起きたかを語る文）
- 失敗例の本文は、汎用の教訓として残す（例：「複合コマンドを確認コマンドにしない」）。各項目の「何をしない／代わりにどう書くか」の文はそのまま残し、経緯の説明だけを削る。経緯は T-02 で `ai-harness-lessons.md` に移す
- 「やらないこと（このリポジトリで実際に起きた失敗から）」の見出しは「やらないこと」にする（「このリポジトリ」の語を残さない）
- `.claude/settings.json` の `permissions.deny`・`vault/rules/verifier/verifier.md` の起点コミット・`docs/vault-spec.md` への参照など、ハーネスの仕組みに関わる記述は残す（固有の経緯ではない）
- 「ルール変更を成果物とするタスクは `vault/tasks/<計画ID>/<id>-proposal.md` にする」の項は残す（ハーネスの仕組み）
- 実体 `vault/rules/planner/planner.md` は変更しない（フックで拒否される。反映は人が行う）。この計画の受け入れ基準では実体が変わったことを検査しない
- `docs/decisions.md`・過去の設計文書・過去の計画票にある経緯の記述は変更しない
- smoke.sh はこのタスクの基準に含めない（T-06 で流す）
