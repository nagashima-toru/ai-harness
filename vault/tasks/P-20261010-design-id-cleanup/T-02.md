# T-02 /design スキルとテンプレートを新しい ID と最終フェーズの削除に合わせる

## 目的
`/design` が設計文書を `vault/designs/D-<YYYYMMDD>-<スラッグ>.md` に書いてブランチ `design/d-<YYYYMMDD>-<スラッグ>` を切り、最終フェーズの受け入れ基準の候補に設計文書の削除と `docs/decisions.md` への追記を必ず入れるようにする。

## 入力
- `.claude/skills/design/SKILL.md`（frontmatter の description、本文冒頭、手順1・5・6・7）
- `vault/templates/design.md`
- この票の「決定済み」（D-016 の決定事項を転記してある。`vault/designs/D-016.md` は T-06 で消えるので、ここだけを根拠にしてよい）

## 成果物
- `.claude/skills/design/SKILL.md`（主な成果物）
- `vault/templates/design.md`（付随：frontmatter の `id` の例と最終フェーズの候補の行）

## 受け入れ基準
- 手順1が `design/d-<YYYYMMDD>-<スラッグ>` のブランチを切ると書いている（`grep -nF 'git checkout -b design/d-<YYYYMMDD>-<スラッグ>' .claude/skills/design/SKILL.md` が1行以上出す）
- SKILL.md に最終フェーズの受け入れ基準の候補へ入れる文がある（`grep -nF '決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する' .claude/skills/design/SKILL.md` が1行以上出し、その行に `最終フェーズ` の語がある）
- テンプレートの frontmatter の `id` が新しい形式の例になっている（`grep -n '^id: D-<YYYYMMDD>-<スラッグ>$' vault/templates/design.md` が1行出す）
- テンプレートにも最終フェーズの候補の行がある（`grep -nF '決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する' vault/templates/design.md` が1行出す）
- 旧形式の記述が残っていない（`grep -nE 'D-xxx|d-xxx|vault/designs/D-[0-9]{3}|design/d-[0-9]{3}|最大値 ?\+1|\+ 3桁|^id: D-[0-9]{3}$' .claude/skills/design/SKILL.md vault/templates/design.md` が何も出さない）
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<N> fail=0` を出す（(run-skill-3) と参照切れ検査 (ref-1) を含む）

## 決定済み
- D-016 の決定事項（転記）：設計文書の ID は `D-<YYYYMMDD>-<スラッグ>`、ブランチは `design/d-<YYYYMMDD>-<スラッグ>`。削除すると「既存の最大値に1を足す」採番が崩れて過去の番号と衝突するため、計画 ID と同じ日付＋スラッグにする
- D-016 の決定事項（転記）：設計文書は最終フェーズで削除する。`/design` は最終フェーズの受け入れ基準に「決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する」を必ず入れる。設計文書は全フェーズを `/plan` に渡すまで `main` に要り、最後のフェーズが終われば読まれないため
- スラッグの規則は計画 ID と同じ `[a-z0-9][a-z0-9-]*`。日付は `/design` を実行した日（JST、`TZ=Asia/Tokyo date +%Y%m%d`）。採番は要らない。`vault/designs/` に同じ ID のファイルか、同名のローカルブランチが既にあればスラッグを変える
- 手順1：`git checkout -b design/d-<YYYYMMDD>-<スラッグ>` と書き、ブランチ名は ID を英小文字にして `design/` を付けたものと説明する（`xxx`・3桁の説明は消す）
- 手順5（フェーズに分ける）に1項目を足す：最終フェーズの「受け入れ基準の候補」に、必ず「決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する」を入れる。あわせてそのフェーズの「決定済み」に、削除は creator がタスクの成果物として行う（成果物に `vault/designs/` を宣言する。差分ゲートの禁止対象ではない）こと、設計文書を読む他のタスクの後に `after` で依存させて置くことを書く。この文は1行に収め、同じ行に「最終フェーズ」の語を入れる（受け入れ基準2・後続の smoke の検査が1行の固定文字列で読む）
- 手順6・7・description・本文冒頭の `vault/designs/D-xxx.md` は `vault/designs/D-<YYYYMMDD>-<スラッグ>.md` にする。手順6の「既存最大値 +1（`D-` + 3桁）」は新しい形式の説明（日付・スラッグ・衝突時の扱い）に置き換える
- テンプレート：frontmatter を `id: D-<YYYYMMDD>-<スラッグ>` にする。「フェーズ2」（テンプレートでの最後のフェーズ）の「受け入れ基準の候補」の `-` の行を `- （最終フェーズには必ず入れる）決定事項のうち docs に無いものを `docs/decisions.md` に追記し、設計文書を削除する` に置き換える。テンプレートの見出しの構成は変えない
- `gh api` の PR 作成に関する手順8の記述（smoke の (run-skill-3) が `` `gh api` の PR 作成に渡すはずだった `` を検査している）は変えない
- 参照切れ検査（smoke の refcheck）はバッククォート内の `vault/`・`.claude/` などで始まるパスが実在するかを見る。`<` を含むパスは対象外。実在しない具体的な設計文書のファイル名をバッククォートのパスで書かない
- `docs/vault-spec.md` は T-01 が直すので触らない

- SKILL.md（description・冒頭・手順1・5・6・7）と vault/templates/design.md（id・フェーズ2の候補行）を更新
- 受け入れ基準6行すべて確認済み（smoke: pass=478 fail=0、旧形式 grep は出力なし）
