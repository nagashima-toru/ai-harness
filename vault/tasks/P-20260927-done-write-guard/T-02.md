- `docs/vault-spec.md` 12節（181〜190行目付近。既存の判定表と、その直後の「この判定は既存の verifier/planner 向け `ALLOWED` 判定より前に実行される。」という段落）
- T-01 の成果物 `.claude/hooks/agent_write_guard.py`（対象パス2種類・fail-open条件・判定順序の一次情報）

## 成果物
- `docs/vault-spec.md`

## 受け入れ基準
- 12節に、対象パス2種類（`vault/tasks/` と `vault/verdicts/`）・`done`・fail-open条件（計画票が無い/読めない/該当行が無い場合は対象外）の3点に言及する行が追記されている。確認：`sed -n '/^## 12\./,/^## 13\./p' docs/vault-spec.md > /tmp/P-20260927-done-write-guard-T-02-sec12.txt` を実行した後、`grep -c 'vault/tasks/' /tmp/P-20260927-done-write-guard-T-02-sec12.txt` の出力が `1以上`、`grep -c 'vault/verdicts/' /tmp/P-20260927-done-write-guard-T-02-sec12.txt` の出力が `1以上`、`grep -c 'done' /tmp/P-20260927-done-write-guard-T-02-sec12.txt` の出力が `1以上`
- 追記した行に fail-open 条件（計画票が無い・読めない・該当行が無い場合は対象外）が書かれている。確認：`grep -c '対象外' /tmp/P-20260927-done-write-guard-T-02-sec12.txt` の出力が `1以上`
- 12節以外の節見出しは変更されていない。確認：`git diff -- docs/vault-spec.md > /tmp/P-20260927-done-write-guard-T-02-diff.txt` を実行した後、`grep -E '^[+-]## ' /tmp/P-20260927-done-write-guard-T-02-diff.txt` の出力が空
- 追記によって既存の「提案ファイル方式」の説明が消えていない。確認：`grep -c '提案ファイル方式' docs/vault-spec.md` の出力が `1以上`

## 決定済み
- 追記位置は12節の既存の判定表（`| 状況 | 判定 |` の表。改ざん防止＝`vault/rules/` 向けの1行だけがある表）に、新しい行を1行追加する形にする。既存の1行はそのまま残し、その直後に新しい行を足す
- 追記する行の例（そのまま使ってよいが、T-01 の実装と食い違わないよう文言は調整してよい）：
  `| 対象が \`vault/tasks/<計画ID>/<id>.md\` または \`vault/verdicts/<計画ID>/<id>.json\` で、該当 id の計画票上の status が \`done\`（計画票が無い・読めない・該当 id の行が無い場合はこの判定の対象外） | ブロック：\`done\` のタスク票・verdict は編集できません。解除口は無い |`
- 判定順序（「この判定は既存の verifier/planner 向け ALLOWED 判定より前に実行される」の段落）は変更しない。新しい行は表の中に追加するだけでよく、既存の説明文（表の前後の段落）は書き換えない
- 12節以外（`## 1.`〜`## 11.`・`## 13.`）の見出し・本文は変更しない
- T-01 が `done`（`.claude/hooks/agent_write_guard.py` の実装が確定した状態）になってから着手する。対象パスの正規表現・fail-open条件の文言を実装と正確に一致させるため
