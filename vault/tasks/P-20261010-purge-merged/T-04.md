# T-04 runbook 5節を一括削除の手順に書き換える

## 目的
`docs/runbook.md` の5節「月次で done を archive に移す」を、`purge_plan.sh --merged` を使った「一括削除の手順」に書き換え、runbook から archive_plans と archive 済みの log の記述を無くす。

## 入力
- `vault/designs/D-016.md` の「フェーズ2」（決定済みの「runbook の新しい5節の手順」）
- `docs/runbook.md`（5節と、8節の手順4の `archive 済みの計画は 5 節と同じく…` の行）
- T-01 で足した `scripts/purge_plan.sh` の `--merged`（冒頭のコメントに使い方・対象の条件・出力がある）

## 成果物
- `docs/runbook.md`（1ファイル）

## 受け入れ基準
1. 5節の見出しが `## 5. 一括削除の手順` になっている。確認：`grep -n '^## 5\. ' docs/runbook.md` の出力が `<行番号>:## 5. 一括削除の手順` の1行
2. 5節のコードブロックに、作業ブランチを切る → `--merged --list` → `--merged --report` → `--merged --apply` → `git commit` の順で手順がある。確認：`grep -nE '^(git switch -c purge/merged-<YYYYMMDD>|bash scripts/purge_plan.sh --merged --(list|report|apply)|git commit -m "一括削除: main にマージ済みの計画一式と vault/archive/ を削除")$' docs/runbook.md` が5行を出し、行番号がこの順に増えている
3. 5節に、`--merged --apply` は人だけが実行しエージェントは `--list`・`--report` だけを使うこと、`--report` の出力を見て必要なものを人が Issue 化してから `--apply` すること、`vault/archive/` も丸ごと消えること、が書かれている。確認：`grep -c -e '--merged --apply は人だけが実行する' docs/runbook.md`・`grep -c 'Issue 化してから' docs/runbook.md`・`grep -c 'vault/archive/` も丸ごと消える' docs/runbook.md` がどれも `1`
4. runbook に archive_plans・`<年-月>`・archive 済みの log の集計の記述が残っていない。確認：`grep -nE 'archive_plans|<年-月>|archive/\*/log|archive 済み' docs/runbook.md` の出力が空
5. 節の数が変わっていない。確認：`grep -c '^## ' docs/runbook.md` が `11`（書き換え前の main の版と同じ数）

## 決定済み
- 新しい5節の構成（この順）：
  1. 1〜2文の説明：`main` にマージ済みの計画一式（`vault/plans/<計画ID>.md`・`vault/tasks/<計画ID>/`・`vault/verdicts/<計画ID>/`・`vault/log/<計画ID>.md`）と `vault/archive/` を、人が `scripts/purge_plan.sh --merged` でまとめて削除する。新しい計画は run の手順7で PR の前に除去されるので、この手順は `main` に残った分を片づける時に使う
  2. 対象の条件（`purge_plan.sh` 冒頭のコメントと同じ条件1〜5を短く）：計画 ID が `P-YYYYMMDD-<slug>` の形・現在のブランチの計画でない・計画票が `status: done`・タスク表が全行 done・`main` の版も `status: done`。`--keep` は無く、マージ済みは全部消す
  3. 手順のコードブロック（受け入れ基準2の5行をこの順に、この文字列のまま。各行は行頭に空白を入れず、後ろに `# ...` のコメントを付けない。行の間に空行やコメント行を入れてもよい）：
     ```
     git switch -c purge/merged-<YYYYMMDD>
     bash scripts/purge_plan.sh --merged --list
     bash scripts/purge_plan.sh --merged --report
     bash scripts/purge_plan.sh --merged --apply
     git commit -m "一括削除: main にマージ済みの計画一式と vault/archive/ を削除"
     ```
     コードブロックの後に「PR を作り、人がマージする」と書く
  4. `--report` の説明：`<計画ID>/<id>: blocked <補足>`（log の `→blocked` の行の補足＝そのとき聞いた質問）と `<計画ID>/<id>: reasons <理由>`（verdict の `reasons`）を出す。この文言を入れる：「`--report` の出力を見て、未解決のもの・改善提案になるものを人が Issue 化してから `--apply` する」（受け入れ基準3の `Issue 化してから` を含む）
  5. `--apply` の説明：対象の4種に加えて「`vault/archive/` も丸ごと消える」（この文字列を入れる）。コミットはしない。対象パスに未コミット・未追跡の変更があれば何も消さずに終了コード1
  6. 実行者の制限：この文言をそのまま入れる：「--merged --apply は人だけが実行する。エージェントは --list・--report だけを使う」（`--merged --apply` をバッククォートで囲む場合も、`--merged --apply は人だけが実行する` の部分は途中に記号を挟まない連続した文字列にする）。理由として、他の計画の done のタスク票・verdict を消すのは、フック（`agent_write_guard.py`）と差分ゲート（`scripts/diff_gate.py`）を通らない経路になるため、と書く
  7. 対象外：計画 ID が `P-YYYYMMDD-<slug>` の形でない旧形式の計画（`P-019` など）と、旧形式のタスク票（`vault/tasks/T-0036.md` など）は対象にならない。消す時は人が `git rm` する。`vault/harness-improvements/` も対象外
- 受け入れ基準3の `--merged --apply は人だけが実行する` は runbook 全体で1回だけ書く（2回書くと基準の期待値 `1` に合わない）。`Issue 化してから`・`` `vault/archive/` も丸ごと消える `` も同じく1回だけ
- 8節の手順4の `- archive 済みの計画は 5 節と同じく、log や会話記録を引数で明示する（例：…vault/archive/*/log/*.md）。` の行は丸ごと消す（計画一式は PR の前に除去されるので、archive 済みの log は無くなる）。その前後の行は変えない
- 冒頭の「人の仕事は…「月次で片づける」の4つ」はそのまま残す（一括削除は人が折を見て行う片づけで、言い換えるほどの差が無い）
- 旧5節の `model_stats.py` の archive の例・`agent_write_guard.py` の done 判定の対象外の段落・旧形式の `vault/archive/2026-09/` の段落・「計画 ID は日付＋スラッグなので…」の段落は消す（新しい5節には要らない）
- 受け入れ基準5の `11` は、書き換え前の main の版で `git show main:docs/runbook.md | grep -c '^## '` が `11` だったことによる（節を足したり消したりしない）
- 5節の見出し番号と、ほかの節からの「5 節」への参照は変えない

## 進捗
- 読んだルール: なし（rules.sh creator は出力なし）
- docs/runbook.md の5節を書き換え、8節の archive 済みの行を削除。基準1〜5の確認コマンドを実行し全て通過
