# T-03 creator ルールへの提案ファイル方式の指示を提案ファイルとして用意する

## 目的
`vault/rules/creator/creator.md` に、「ルール変更を成果物とするタスクは
`vault/tasks/<計画ID>/<id>-proposal.md` に下書きし、`vault/rules/` へは直接書き込めない（フックが常
に拒否する）」旨の指示を追記する内容を、実体ファイルではなく提案ファイルとして下書きする。

## 入力
- `vault/rules/creator/creator.md`（現行。追記先）
- `vault/designs/D-002.md`「## 決定事項」「## フェーズ1」
- このタスク自身の `doing`/`review` 中は `vault/rules/` への書き込みが（旧ロジック・新ロジックいず
  れでも）フックで拒否されるため、実体を直接編集できない（この計画のゴールそのものが前提とする制
  約）

## 成果物
- `vault/tasks/P-20260924-rules-guard/T-03-proposal.md`（`vault/rules/creator/creator.md` に追記す
  る内容の提案。追記後のファイル全文、または追記する差分のどちらの形式でもよい）

## 受け入れ基準
- 提案ファイルが存在し、追記対象を明記している。確認：
  `grep -c 'vault/rules/creator/creator.md' vault/tasks/P-20260924-rules-guard/T-03-proposal.md` が1
  以上
- 提案内容に、ルール変更が成果物のタスクは `vault/tasks/<計画ID>/<id>-proposal.md` に下書きする旨の
  指示が含まれる。確認：`grep -c -- '-proposal.md' vault/tasks/P-20260924-rules-guard/T-03-proposal.md`
  が1以上
- 提案内容に、`vault/rules/` への直接書き込みは常に拒否される旨の記述が含まれる。確認：
  `grep -c 'vault/rules/' vault/tasks/P-20260924-rules-guard/T-03-proposal.md` が1以上かつ、その行の
  近傍に「常に」または「常時」の語がある（目視確認）
- `vault/rules/creator/creator.md` 自体には手を付けていない（提案のみで実体は変えない）。確認：
  `git status --porcelain -- vault/rules/creator/creator.md` の出力が空
- `bash scripts/smoke.sh | tail -1` に `fail=0` が含まれる

## 決定済み
- 提案ファイルの中身は、既存の `creator.md` の見出し構成（目的 / ルール / 確認方法）を崩さない追記
  案にする。追記位置は「## ルール」の「**責務**」箇条書きの末尾を想定する（`vault/rules/planner/
  planner.md` の同種の追記位置と揃える）
- 追記する文言の例（そのまま使ってよい）：「ルール変更（`vault/rules/` 配下のファイル）を成果物とす
  るタスクでは、実体パスに直接書き込めない（`agent_write_guard.py` が常に拒否する）。代わりに
  `vault/tasks/<計画ID>/<id>-proposal.md` に追記案を下書きし、それを成果物として `review` に回す。
  実体への反映は人が手作業で行う」
- 提案ファイルの反映（`vault/rules/creator/creator.md` への実際の追記）は人が手作業で行う。このタス
  ク自身で反映を試みない・自動化しない
- Write が `vault/rules/` 配下に対して deny された場合でも、status を `blocked` にせず、決定済みど
  おり提案ファイルに切り替えて進める（`blocked` にすべきなのは、決定済みに答えが無い判断が必要な時
  だけ）
