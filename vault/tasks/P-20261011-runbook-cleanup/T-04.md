# T-04 runbook の整理に合わせて他の文書からの参照を直す

## 目的
T-02・T-03 で runbook から詳しい説明が vault-spec へのリンクに置き換わったので、`docs/configuration.md` の「詳しく」列などの参照先を、説明が実際にある場所に合わせる。リポジトリ全体の「runbook の節」への参照と、runbook の冒頭と同じ古い記述を確かめて直す。

## 入力
- `docs/runbook.md`（T-02・T-03 で整理済み）
- `docs/vault-spec.md`（T-01 で足した14節）
- `docs/configuration.md`・`docs/guide.md`・`docs/install.md`・`README.md`
- 設計文書 `vault/designs/D-20261011-user-guide.md` の「決定事項」とフェーズ3

## 成果物
- `docs/configuration.md`（主な成果物。「詳しく」列の参照先を直す）
- 付随して、参照がずれていた時だけ直すファイル：`docs/guide.md`・`docs/install.md`・`README.md`・`docs/vault-spec.md`

## 受け入れ基準
- `grep -cE '^\| `HARNESS_(RUN_CMD|RUN_TIMEOUT|STRICT_STOP)` .*\[docs/vault-spec.md の 14節\]' docs/configuration.md` が `3`
- `grep -E '^\| `HARNESS_MAX_ATTEMPTS`' docs/configuration.md | grep -c 'runbook'` が `0`
- `grep -rnE 'runbook.{0,30}[0-9]+ ?節' README.md docs .claude/skills .claude/agents .claude/ai-harness.md` の各行について、指している runbook の節にその参照が期待する内容（説明・手順・注意）がある。行ごとの確認結果がタスク票の「進捗」に書かれ、verifier が runbook を読んで確かめる
- `grep -rn '月次で片づける' README.md docs .claude/skills .claude/agents .claude/ai-harness.md` の出力が空
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (guide-1) '` が `1`、`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (envref-1) '` が `1`
- `bash scripts/smoke.sh 2>&1 | tail -1` が `smoke: pass=<数> fail=0`、`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- `docs/configuration.md` の「詳しく」列の直し方：
  - `HARNESS_RUN_CMD`・`HARNESS_RUN_TIMEOUT`・`HARNESS_STRICT_STOP` の行に `[docs/vault-spec.md の 14節](vault-spec.md)` を足す（この文字列のとおりに書く。既存のリンクの形 `[docs/vault-spec.md の 9節](vault-spec.md)` と同じ）。`docs/runbook.md` の 3節へのリンクは、3節が無人実行の人の使い方を説明しているので残してよい。
  - `HARNESS_MAX_ATTEMPTS` の行から `docs/runbook.md` の 3節へのリンクを外す（runbook はもう上限の説明を持たず、`docs/configuration.md` へリンクするだけのため。`docs/vault-spec.md` の 2節へのリンクは残す）。
  - そのほかの行（`HARNESS_PUSH_BRANCH` の runbook 10節、`HARNESS_CREATOR_MODEL` の runbook 8節など）は、指す節に人の使い方が残っていればそのままにする。
  - 表の上の「設定のしかた」の「（`docs/runbook.md` 8節と同じ注意）」は、8節に起動し直す注意が残っていればそのままにする。
- 表の列（6列）・変数の行・既定値は変えない（設計の「今回やらないこと」：環境変数の追加・名前の変更・既定値の変更はしない）。
- `docs/guide.md` の「詳しく」の runbook の節は、T-02・T-03 で `## ` 見出しを変えていないので通常は直す必要が無い。smoke の `(guide-1)` が FAIL した時だけ直す。直す時は各項目の「すること：」「詳しく：」の形を崩さない。
- `docs/vault-spec.md` は、「手順は `docs/runbook.md` 5節」「マージ方式の運用は `docs/runbook.md` 3節」の参照が指す内容と合わない時だけ直す（T-02・T-03 はその内容を3節・5節に残す決定になっている）。ほかの節は変えない。
- `docs/install.md` は整理しない（設計の決定済み）。ただし末尾の「人が日々やること（ゴールを入れる・blocked に答える・PR をマージする・月次で片づける）」の1か所だけ、T-02 で直した runbook の冒頭の4つ（「マージ済みの計画を片づける」）とそろえる。ほかの行は変えない。
- `README.md` は、runbook への参照（「人が日々やることは `docs/runbook.md`」「手順は `docs/runbook.md`」）が今の runbook の内容と合っていればそのままにする。
- `.claude/` 配下の文書に「runbook の N節」という参照は今は無い（`grep -rnE 'runbook.{0,30}[0-9]+ ?節' .claude/skills .claude/agents .claude/ai-harness.md` が空）。`.claude/` は成果物にしない。
- `docs/configuration.md`・`docs/guide.md` を `scripts/install.sh` の配布対象に足さない（設計の決定事項）。

- docs/install.md 末尾の「月次で片づける」を「マージ済みの計画を片づける」に直した
