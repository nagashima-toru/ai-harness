# ゴール
`run`/`design` スキルの最終手順が `gh pr create` に直接依存しており、GitHub 以外のホスティング（GitLab）や、ホスティングサービスを使わないローカル git 運用ではハーネスを最後まで通せない（issue #19）。ホスティングの判定と PR/MR 作成コマンドの実行を共有スクリプト `scripts/vcs_finish.sh` に切り出し、GitHub（`gh`）・GitLab（`glab`）・ホスティング無し（人へのブランチ引き継ぎ案内）の3経路に対応させることで、この依存を解消する。

## 決定事項

| 決めたこと | なぜ |
|---|---|
| GitHub に加えて GitLab（`glab mr create`）も今回実装する。Bitbucket 等それ以外は対象外 | 人の判断。issue #19 の動機（GitLab も使う）にそのまま応える |
| ホスティングの判定は `git remote get-url origin` の値から自動判定するのを既定とし、環境変数 `HARNESS_VCS_HOST=github\|gitlab\|none` で上書きできるようにする | 人の判断（推奨案採用）。既存リポジトリは無設定のまま今までどおり動き、セルフホスト GitLab などドメインから判定できないケースだけ明示指定すればよい |
| ホスティング無し（`none`）の場合も、エージェントは main へのマージを一切行わない。用意できたブランチ名と `git merge --no-ff <branch>` 等の案内をスクリプトが出力し、それを人に伝えるところまでで止まる | 人の判断（既存方針を維持）。GitHub/GitLab 運用では「PR/MR は作るが `gh pr merge`/`glab mr merge` は実行せず、マージは常に人が行う」という安全境界を全箇所で徹底している。ホスティング無しの場合だけエージェントが直接 main へマージする例外を作ると、この安全境界が崩れる |

## 依存関係
単一フェーズ。並行実装の余地なし。

## フェーズ1 PR/MR 作成のホスティング非依存化

### ゴール文
`run` スキルの最終手順（全タスク `done` 後の PR 作成）と `design` スキルの最終手順（設計文書提示後の PR 作成案内）が直接呼んでいる `gh pr create` を、新しい共有スクリプト `scripts/vcs_finish.sh` の呼び出しに置き換える。このスクリプトは、環境変数 `HARNESS_VCS_HOST`（`github`/`gitlab`/`none`。未設定または `auto` なら自動判定）に従って動作を分岐する：`github` なら `gh pr create "$@"` を、`gitlab` なら `glab mr create "$@"` を実行してその終了コードをそのまま返す。自動判定は `git remote get-url origin` の値に `github.com` を含めば `github`、`gitlab` を含めば `gitlab`、リモートが無い・どちらにも一致しなければ `none` とする。`none` の場合は `gh`/`glab` を一切呼ばず、現在のブランチ名と、main への取り込みに使う `git merge --no-ff <branch>` コマンドを標準出力に案内として書き、終了コード0で終わる（エージェントはこのメッセージをそのまま人に伝える。自分でマージは実行しない）。`docs/vault-spec.md`（計画票 `status: done` の定義、設計文書のブランチと PR の節）と `docs/runbook.md` の該当箇所も、`gh pr create` 前提の記述からこのスクリプト経由の記述に更新する。

### 受け入れ基準の候補
- `scripts/vcs_finish.sh` が存在し、`HARNESS_VCS_HOST=none bash scripts/vcs_finish.sh` を実行すると `gh`/`glab` を呼ばずに終了コード0で終わり、標準出力に現在のブランチ名と `git merge --no-ff` を含む案内が出る。確認: 上記コマンドを実行し `echo $?` が0、出力に `git merge --no-ff` と現在のブランチ名の両方が含まれることを確認する
- `HARNESS_VCS_HOST=github` 指定時は `gh pr create` を、`HARNESS_VCS_HOST=gitlab` 指定時は `glab mr create` を呼ぶ分岐がスクリプト内にある。確認: `grep -n 'gh pr create\|glab mr create' scripts/vcs_finish.sh` の両方がヒットする
- 環境変数未指定（`auto`）時は `git remote get-url origin` の値から `github.com`→`github`、`gitlab`→`gitlab`、それ以外・リモート無し→`none` と判定するロジックがある。確認: `grep -n 'github.com\|gitlab' scripts/vcs_finish.sh` がヒットする
- `.claude/skills/run/SKILL.md` と `.claude/skills/design/SKILL.md` から `gh pr create` の直接記述が消え、`scripts/vcs_finish.sh` の実行に置き換わっている。確認: `grep -c "gh pr create" .claude/skills/run/SKILL.md .claude/skills/design/SKILL.md` がいずれも0
- `docs/vault-spec.md` の計画票 `status: done` の定義（2節・4節該当箇所）と、設計文書のブランチと PR の節（13節）、`docs/runbook.md` の該当箇所が、`scripts/vcs_finish.sh` 経由の表現に更新されている（`gh pr create` 前提の説明が残っていない）
- `gh pr merge` / `glab mr merge` の**実行**が、`scripts/vcs_finish.sh` にも `run`/`design` の両 SKILL.md にも無い（マージは人が行うという既存方針を壊さない）。確認: `grep -n "gh pr merge\|glab mr merge" scripts/vcs_finish.sh .claude/skills/run/SKILL.md .claude/skills/design/SKILL.md` に実行コマンドとしての記述が無いことを目視確認する（方針として「実行しない」と説明文で言及するのは可）

### 決定済み
- 環境変数名は `HARNESS_VCS_HOST`、値は `github`/`gitlab`/`none`（未設定または `auto` は自動判定）。既存の `HARNESS_MAX_PARALLEL`/`HARNESS_MAX_ATTEMPTS` と同じ「環境変数で調整できる既定値」パターンに合わせる
- スクリプトのパスは `scripts/vcs_finish.sh`。呼び出し時の引数はそのまま `gh pr create "$@"` / `glab mr create "$@"` に渡す（`--fill` などのフラグを付けるかはスキル側の判断に委ね、スクリプト自身はデフォルト引数を追加しない。現状 `run`/`design` スキルも `gh pr create` を引数無しで呼ぶ想定だったため、挙動は変えない）
- GitLab 判定は `git remote get-url origin` の値に部分文字列 `gitlab` が含まれるかどうかで行う簡易判定でよい（`gitlab.com` と、ホスト名に `gitlab` を含む大半のセルフホスト環境をカバーする）。ホスト名に `gitlab` を含まないセルフホスト環境は自動判定できないため `HARNESS_VCS_HOST=gitlab` を明示する運用にする
- `origin` という名前のリモートが存在しない（未設定）場合は `none` として扱う
- `gh`/`glab` コマンド自体が未インストール・未認証の場合のエラーハンドリング（分かりやすいメッセージ化など）はこのフェーズでは追加しない。現状の `gh pr create` 単体呼び出しと同様、コマンドが失敗すればそのエラーがそのまま出る
- `.claude/hooks/agent_write_guard.py` の `gh api`/`curl api.github.com` によるリモート改ざん検知（GitHub 固有、issue #6 対応）は今回変更しない。GitLab 相当の検知が要るかは別の懸念として扱う

## 今回やらないこと
- GitHub・GitLab 以外のホスティング（Bitbucket 等）への対応
- ホスト名に `gitlab` を含まないセルフホスト GitLab の自動判定精度の向上（環境変数で明示すれば対応できるため、自動判定の賢さを上げる作業は対象外）
- `gh`/`glab` の未インストール・未認証時に親切なガイダンスを出す UX 改善
- `agent_write_guard.py` の GitHub 固有のリモート改ざん検知を GitLab 等に拡張すること（issue 化するなら別issue）
- PR/MR のタイトル・本文を自動生成するロジックの追加（現状どおり、必要なら呼び出し側が引数で指定する）
