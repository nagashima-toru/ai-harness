## 決定済み
- **このタスクは「編集を先、状態遷移を後」の順で行う。** 人がリモートセッションで実行しており、
  起動時に `HARNESS_ALLOW_RULES_WRITE=T-0051` を渡せないため、通常の解除口が使えない（この制約は
  `vault/designs/D-001.md` の「今回やらないこと」に記録済み）。手順：
  1. T-0050 が `done` になり、このタスクがまだ `todo` の状態のまま、4ファイルを編集する
     （`agent_write_guard.py` の改ざん防止は `doing`/`review` のタスクがある時だけ発火するため、
     この時点では拒否されない）
  2. 編集を終えてから status を `doing` → `review` にし、verifier に確認させる
  3. `review` 中に追加の書き込みが必要になったら、そこで初めて deny される。その場合は
     status を `blocked` にし、question に事情を書いて人に依頼する（フックや設定を自分で変えない）
- この順序は解除口を**迂回している**。人が承認時に明示的に選んだ回避策であり、エージェントが
  勝手に取ってよい手段ではない。同じ状況が再発したら、また人に判断を仰ぐこと
- 迂回しても検証ゲート自体は残る（編集後に verifier が受け入れ基準を確認する）。またこのタスクの
  受け入れ基準は機械的な grep（`vault/todo.md` 言及が0・`vault/plans/` 言及あり・見出し数が3）
  なので、ルール文書を書き換えても基準を緩められない
- 言い換えの対応表：「`vault/todo.md` の status を…」→「計画票（`vault/plans/<計画ID>.md`）のタス
  ク表の status を…」、「`vault/log/queue.md` に…」→「`vault/log/<計画ID>.md` に…」、
  「`vault/todo.md` の該当行（`attempt` の値を取る）」→「計画票のタスク表の該当行（`attempt` の値
  を取る）」、「`vault/todo.md` の列順・見出しは変えない」→「計画票のタスク表の列順・見出しは変え
  ない」
- 各ファイルの「責務」「やらないこと」「確認方法」の項目数・順序・具体的な失敗例（T-0002 の
  `git diff --quiet` の話など）は変更しない。変えるのは `vault/todo.md` を指している文言だけ
- `roles.md` の「人 → planner」節にある「planner の出力が人の承認を受けて初めて `vault/todo.md` に
  載る」は「planner の出力が人の承認を受けて初めて計画票の `status` が `approved` になる」に直す
- `creator.md`（`vault/rules/creator/creator.md`）の確認方法にある
  「`git status` で、成果物・タスク票・todo.md・log 以外のファイルに差分が出ていないか」は
  「…成果物・タスク票・計画票・log 以外の…」に直す
- 4ファイルとも、書き込み先の制限（planner は `vault/plans/`・`vault/tasks/` のみ、verifier は
  `vault/verdicts/` のみ）は変更しない（`agent_write_guard.py` の `ALLOWED` は今回のフェーズで変え
  ていないため）

## 進捗
- 読んだルール: roles.md, creator.md, verifier.md, planner.md（4本とも成果物なので全部読んだ）
- 決定済みの手順どおり、todo のうちに4ファイルを編集した（`agent_write_guard.py` の改ざん防止は

  確認方法の「todo.md・log」→「計画票（`vault/plans/<計画ID>.md`）・log」
- `verifier.md`：`attempt` の説明2箇所を「計画票（`vault/plans/<計画ID>.md`）のタスク表の値」に、
  「成果物・タスク票・`vault/todo.md` を修正しない」→「…計画票のタスク表を修正しない」
- `planner.md`：採番の説明を「`P-YYYYMMDD-<slug>`（採番不要）・計画スコープの `T-01`〜」に全面差し
  替え、「`vault/todo.md` への登録は人の承認後に plan スキルが行う」→「承認（status を approved に
  すること）は人が行う」、T-0002 失敗例と確認コマンド例の `vault/todo.md` を計画票ベースに言い換え、
  「run-queue で必ず差分が出る」→「run で必ず差分が出る」
- `creator.md`・`verifier.md` は当初「計画票のタスク表」という言い方だけで `vault/plans/` の
  リテラル文字列を含んでおらず基準2（4ファイルとも `vault/plans/` への言及）を満たさなかった。
  自然な箇所（確認方法の該当行）に `vault/plans/<計画ID>.md` の具体パスを補って解消した
- **作業中に重大な発見**：このタスクとは無関係に、実際に配線済みの `.claude/hooks/plan_guard.py`・

  想定どおりの帰結だが、実際に確認できたのはここが初めて。T-0051 の範囲（ルール4ファイルの文言）
  には影響しないため作業は続けたが、タスク完了後に人へ報告する
