# T-05 /plan スキルの B（承認）を、人のコマンド確認・log への根拠追記・コミットの手順に改める

## 目的
フック（T-03・T-04）が「人の `/plan approve` の指示」を裏付けに承認を許可するので、スキルの B をそれに合う手順にする。承認の直後に log へ根拠を1行追記してコミットし、同じ承認に plan_guard が何度も当たらないようにする（D-010 フェーズ4）。

## 入力
- `vault/designs/D-010.md` フェーズ4（決定済みの `/plan approve` の log 行・コミット）
- `.claude/skills/plan/SKILL.md`（B 節、frontmatter の description、注意節）
- `vault/log/` の既存ファイルの行の形（`docs/vault-spec.md` 7節）

## 成果物
- `.claude/skills/plan/SKILL.md` の変更（1ファイル）

## 受け入れ基準
- B 節が、承認の指示が `/plan approve <計画ID>` のコマンドであること（人が自然文で承認を伝えた場合は、コマンドを打つよう案内して止まること）を書いている。確認：`grep -n '自然文' .claude/skills/plan/SKILL.md` がB節内の行にヒットし、目視で手順を確認する
- B 節が、status を approved にした後、`TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M'` で取った日時で `vault/log/<計画ID>.md` に `- <日時> - draft→approved 人の指示: /plan approve <計画ID>` を1行追記する手順を書いている。確認：`grep -n 'draft→approved 人の指示: /plan approve' .claude/skills/plan/SKILL.md` がヒットする
- B 節が、計画票と log を `git add`（ファイルを名前で指定）して `git commit` する手順を書いている。確認：`grep -n 'git commit' .claude/skills/plan/SKILL.md` がB節内の行にヒットする
- 「または人が承認を伝えた時」など、コマンド以外の承認の指示を認める記述が B 節の見出しに残っていない。確認：`grep -n '^## B' .claude/skills/plan/SKILL.md` の出力に `人が承認を伝えた` を含まない
- A 節・注意節・frontmatter の `name`・`argument-hint` の意味が変わっていない。確認：`git diff -- .claude/skills/plan/SKILL.md` の変更行が `## B` 節（と description の承認に関する文言）の範囲に収まることを目視で確認する

## 決定済み
- log 行の形は D-010 のとおり `- <日時> - draft→approved 人の指示: /plan approve <計画ID>`（タスク ID の位置は `-`）。この文字列を SKILL.md に書くこと
- 手順の順序：(1) 引数が `approve <計画ID>` のコマンドで来たことを確認する（自然文の承認は受け付けず、「`/plan approve <計画ID>` を打ってください」と案内して止まる）。(2) 計画票が `draft` であることを確認する。(3) frontmatter の status を `approved` にする。(4) log に上記の行を追記する（`vault/log/<計画ID>.md` が無ければ作る）。(5) `git add vault/plans/<計画ID>.md vault/log/<計画ID>.md` と `git commit` を行う（コミットメッセージ例：`<計画ID>: 計画を承認する`）。(6) 承認したことを報告し、「`/run` で処理を開始できます」と伝える
- コミットは work ブランチ上で行う（main 上では `agent_write_guard.py` が拒否するが、`/plan` は A 節で work ブランチを切っているので通常は問題ない）。`git add .` や `git add -A` は使わない
- frontmatter の description の「計画を承認」「P-... を承認」の記述は、コマンド `/plan approve <計画ID>` で承認する旨に合わせて直してよい。トリガー語（「計画を承認」など）は残す。自然文でトリガーされた場合は、コマンドを打つよう案内する動きになる
- 承認済みの計画票を差し戻す運用や `/plan unblock` は扱わない（D-010 フェーズ5）
- スキルの手順が使う `TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M'` は `docs/vault-spec.md` 3節の取得例と同じ
