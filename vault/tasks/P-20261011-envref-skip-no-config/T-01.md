# T-01 smoke.sh の envcheck を docs/configuration.md が無い時にスキップし (envref-3) を足す

## 目的
導入先（`docs/configuration.md` が配布されないルート）で `bash scripts/smoke.sh` の `(envref-1)` が必ず NG になる問題（GitHub Issue #176）を、`envcheck()` が `docs/configuration.md` の無いルートでは何も出さずに終わる形にして直す。

## 入力
- `scripts/smoke.sh` の `envcheck()`（「scripts/・.claude/ の HARNESS_* と docs/configuration.md の表の一致検査」の節、2730 行付近）と、`(envref-1)`・`(envref-2)` の検査（2833〜2847 行付近）
- 前例：同じファイルの `guidecheck()`（`docs/guide.md` が無ければ `sys.exit(0)`）と `refcheck()`（`.claude/harness-manifest.json` があれば `sys.exit(0)`）
- `scripts/install.sh`（docs は `docs/vault-spec.md` だけを配る。読むだけで変えない）

## 成果物
- `scripts/smoke.sh`（1ファイル。`envcheck()` の早期終了の追加と `(envref-3)` 検査の追加）

## 受け入れ基準
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (envref-3) '` の出力が `1`（導入先相当のルートで envcheck が空を返す新しい検査が pass する）
- `bash scripts/smoke.sh 2>&1 | grep -cE '^  ok   \(envref-[12]\) '` の出力が `2`（ハーネス本体での一致検査と、偽ツリーでのずれ検出が従来どおり pass する）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  NG   '` の出力が `0`
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `smoke: pass=<数> fail=0` の形で、`fail=0` で終わる
- `scripts/smoke.sh` の `(envref-3)` の検査が使うフィクスチャのルートは、`scripts/` 配下に `HARNESS_` で始まる変数名を含むファイルがあり、`docs/configuration.md` が無い（`scripts/smoke.sh` の該当箇所を読んで確認する。修正前の `envcheck` ならこのルートで「表に無い:」の行が出る構成であること）

## 決定済み
- 直し方は対応案 A。`envcheck()` の python 部で、`root` を得た直後（`scripts/`・`.claude/` の走査より前）に `os.path.join(root, "docs/configuration.md")` が無ければ `sys.exit(0)` で何も出さずに終わる。`guidecheck()` の書き方にそろえる。既存の `if os.path.isfile(cf):` の分岐は残しても消してもよい（早期終了の後では常に真になる）
- `(envref-1)`・`(envref-2)` の検査名・期待値・フィクスチャは変えない（ハーネス本体には `docs/configuration.md` があるので従来どおり検査される）
- 新しい検査の名前は `(envref-3)` にし、`expect_eq "(envref-3) <説明>" "" "$(envcheck "<フィクスチャのルート>")"` の形で `(envref-2)` の直後に置く。説明文は例：「docs/configuration.md が無いルート（導入先）では検査しない」
- `(envref-3)` のフィクスチャは `$TMP` 配下の新しいディレクトリ（例 `$TMP/envref-noconf`）に `mkdir -p` で作り、`scripts/` に `HARNESS_` で始まる変数名を含むファイル（例 `printf 'HARNESS_NOCONF\n' > .../scripts/a.sh`）を置き、`docs/configuration.md` は作らない。既存の `$EV`（`$TMP/envref`）は `docs/configuration.md` を持つので流用しない。後片付けの `rm -rf` は書かない（`$TMP` の既存の扱いに任せる）
- `scripts/install.sh`・`docs/install.md`・`docs/configuration.md`・その他の docs は変えない（対応案 B は採らない）
- smoke の実行は1回あたり約1分かかる。確認コマンドは基準ごとに個別に実行してよい
