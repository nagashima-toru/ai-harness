# T-06 docs/vault-spec.md の9節・10節に done の行の verdict の検査を書く

## 目的
仕様の正本 `docs/vault-spec.md` の9節（Stop フックの判定）と10節（plan_guard フックの判定）を、T-03・T-04 で足した done の行の verdict の検査に合わせる（D-012 フェーズ1）。

## 入力
- `vault/designs/D-012.md` の「フェーズ1」（ゴール文・決定済み）
- `docs/vault-spec.md` の9節・10節（12節の done の verdict への書き込み拒否も参照）
- `.claude/hooks/stop_gate.py`・`.claude/hooks/plan_guard.py`・`.claude/hooks/_hooklib.py`（T-01・T-03・T-04 の後の版）

## 成果物
- `docs/vault-spec.md`（9節・10節だけを直す。このファイルだけ）

## 受け入れ基準
- 9節の判定表に done の行の検査の行がある：`sed -n '/^## 9\./,/^## 10\./p' docs/vault-spec.md | grep -c -F '| done の行に attempt が一致する正しい PASS の verdict が無い'` の出力が `1`
- 9節の判定表から「PASS かつ done → 許可」の行が消えている：`sed -n '/^## 9\./,/^## 10\./p' docs/vault-spec.md | grep -c -F '| PASS かつ done | 許可 |'` の出力が `0`
- 9節の本文に検査の位置が書かれている：`sed -n '/^## 9\./,/^## 10\./p' docs/vault-spec.md | grep -c -F 'status が done の行それぞれについて'` の出力が `1`
- 10節に done の行の検査の段落がある：`sed -n '/^## 10\./,/^## 11\./p' docs/vault-spec.md | grep -c -F 'done の行の verdict の検査も plan_guard が行う（D-012 フェーズ1）。'` の出力が `1`
- 節の構成は変わらない：`grep -c '^## ' docs/vault-spec.md` の出力が `13`
- smoke が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 9節の冒頭の段落を次の文面に置き換える（`status が done の行それぞれについて` は字句どおりに書く。基準3が数える）
  `.claude/hooks/stop_gate.py` は、自分のブランチの承認済み計画票のタスク表と verdict を読んで判定だけを行い、状態は書き換えない。approved な計画票を1件に特定した直後に、status が done の行それぞれについて、attempt が一致する正しい PASS の verdict があるかを検査する（doing/review の行の検査より前。条件と理由の順は10節の done の行の verdict の検査と同じ）。続いて、doing/review が複数件になりうる前提（2節）のため、doing/review の行それぞれについて下表の判定を行い、いずれか1行でもブロック対象なら停止をブロックする。
- 9節の判定表：
  - 「未コミットの変更がある」の行の直後（「doing / review のタスクが無い」の行の前）に次の1行を足す
    `| done の行に attempt が一致する正しい PASS の verdict が無い（verdict が無い・JSON として読めない・task / attempt が不一致・result が PASS でない・形式が不正） | ブロック：表の上から最初のその行について、status を review に戻し verifier を実行するよう指示する |`
  - 最後の行 `| PASS かつ done | 許可 |` を消す（stop_gate.py の done の分岐を T-03 で消したため。done の行は上の行で検査する）
  - ほかの行は変えない
- 10節：「承認の裏付けの検査も plan_guard が行う（D-010 フェーズ4）。」で始まる段落の直前に、次の段落を足す
  `done の行の verdict の検査も plan_guard が行う（D-012 フェーズ1）。自分のブランチの approved な計画票のタスク表で status が done の行それぞれについて、vault/verdicts/<計画ID>/<id>.json があり、JSON として読め、task が <計画ID>/<id>、attempt がタスク表の値と一致し、result が PASS で、形式が正しい（9節の「verdict が不正」の条件に当たらない）ことを、この順に確かめる。満たさない行があれば、表の上から最初の1行についてブロックし、その行の status を review に戻して verifier を実行するよう指示する。この検査は上の段落の検査（列数・status・依存・blocked の question・id の重複）の後に行い、それらのブロック理由が先に出る。検査の本体は .claude/hooks/_hooklib.py の done_rows_without_pass で、Stop フック（9節）と共通。done のタスクの verdict への書き込みは agent_write_guard が拒否する（12節）ため、直す手順は review に戻してから verifier を実行する順になる。draft・done の計画票と vault/archive/ は検査しない。`
  - パス・関数名・status の値は、まわりの段落に合わせてバッククォートで囲んでよい。ただし基準4の文 `done の行の verdict の検査も plan_guard が行う（D-012 フェーズ1）。` は字句どおりに書く
- 10節の冒頭の段落（壊れ方の列挙）は変えない（done の行の検査は上の新しい段落で書く）
- 9節・10節以外（6節の verdict の形式、12節など）は変えない
- フック・smoke は変更しない
