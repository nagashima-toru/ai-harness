## 受け入れ基準

## 決定済み
- `docs/decisions.md` の表の末尾に1行だけ足す。既存の行は変えない
- 行の形：`| 2026-10-17 | creator・verifier の tools に Skill を足し、受け入れ基準が /code-review を参照する時の判定（差分内の致命的な指摘だけで FAIL、差分の外は対象外、設計・仕様の変更が要る指摘は人の判断として PASS から blocked）を定める（Issue #214）（P-20261017-code-review-in-agents） | <なぜ> |`
- 「なぜ」の列に書く4点：(1) 導入先で `/code-review` が規約のチェックリストで拾えない不具合を検出した (2) 差分の外の指摘で FAIL が続くと、タスクで直せないまま attempt を使い切る (3) verifier は状態を変えられないので、run が verdict を見て blocked にする (4) どのタスクにレビューを求めるかは導入先の planner ルールで決め、ハーネスはレビューを強制しない（原則7）
- 行の中に `|` を表の区切り以外で使わない（列がずれるため）
