# T-03 planner ルールに rm -rf 前提にしない機能テスト指針を追記する提案を書く（issue #46）

## 目的
`vault/rules/planner/planner.md` に、`mktemp -d` を使った機能テスト（一時ディレクトリ・ダミーコマンドを用意して確認する形）のような、後片付けが必要になりうる受け入れ基準の確認コマンドを書く際は、`rm -rf` による後片付けを前提にしない（固定パスへの上書き運用にするか、後片付け不要な設計にする）よう指針を追記する提案を書く。

## 入力
- `vault/rules/planner/planner.md`（「やらないこと（このリポジトリで実際に起きた失敗から）」節。既存項目18〜31行目と同じ書式：1行の見出し＋具体例つきの説明2〜3行）
- `docs/vault-spec.md` 12節（提案ファイル方式。`vault/rules/` は `agent_write_guard.py` が常に書き込みを拒否する）
- `vault/plans/P-20260925-vcs-finish-push-and-diff-criteria.md` と `vault/tasks/P-20260925-vcs-finish-push-and-diff-criteria/T-01.md`（実際にこの問題が起きた受け入れ基準の実例：固定パス `/tmp/vftest_a` 等に書き換えて後片付けをしない形で回避した）
- `.claude/settings.json` の `permissions.deny`（`Bash(rm -rf *)` 系。この計画の T-01 で見直しを提案中だが、T-03 は T-01 の結論を待たず、現状の制約を前提に指針を書く）

## 成果物
- `vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-03-proposal.md`（`vault/rules/planner/planner.md` の実体は変更しない）

## 受け入れ基準
- `T-03-proposal.md` に、`planner.md` の「やらないこと」節へ追記する形の文面（見出し1行＋説明2〜3行、既存項目と同じ体裁）を1件含む。確認コマンド：`grep -c '^- ' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-03-proposal.md` の出力が `1` 以上
- 追記文面が、後片付けに `rm -rf` を使わずに済む具体的な回避策として「固定パス」への言及を含む。確認コマンド：`grep -c '固定パス' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-03-proposal.md` の出力が `1` 以上
- 追記文面が、`rm -rf` を後片付けの前提にしない理由として `.claude/settings.json` の `permissions.deny` に触れている。確認コマンド：`grep -c 'permissions.deny' vault/tasks/P-20260925-acceptance-test-sandbox-fp/T-03-proposal.md` の出力が `1` 以上
- `vault/rules/planner/planner.md` の実体は変更しない。確認コマンド：`git status --porcelain -- vault/rules/planner/planner.md` の出力が空

## 決定済み
- 提案ファイル方式に従う（`docs/vault-spec.md` 12節）。実体（`vault/rules/planner/planner.md`）は `agent_write_guard.py` が常に拒否するため直接編集しない
- 追記対象は「やらないこと（このリポジトリで実際に起きた失敗から）」節。既存項目と同じ書式（1行の見出し＋具体例つきの説明2〜3行）にする
- 内容の方向性の例（参考、文言は creator に委ねる）：`/tmp/<計画ID>-<タスクID>` のように計画・タスク ID を含む固定パスにし、テスト開始時に `mkdir -p` で作り直す（既存内容を無条件に使う前提にしない）ことで、後片付け無しでも安全に運用できる、という方向性
- rm -rf の deny パターン自体をどう変えるか（T-01）とは独立したタスク。T-01 の結論を待たず、現状の制約（`.claude/settings.json` に `rm -rf` deny がある）を前提に指針を書いてよい
- grep 誤検知（T-02）の議論はこの提案に含めない（別問題として扱う）
